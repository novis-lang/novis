What a program's own records look like, and who is told when one of its requests fails.

The block gathers the shape of the record and the rungs the runtime climbs when something goes
wrong. Two of its keys are the ordinary sort a program changes for itself: the rendering, JSON
unless somebody asks for text, and the level, below which a record is not written at all. A job that
wants its own run traced turns its level down and gets the detail for that one request, while the
requests beside it keep what the deployment wrote.

The rest is the operator's, and each of those keys says so on its own page: the script run when a
request fails, the memory and time held back for it, and the destination the floor writes to. Where
the record of a failure goes is not the failing program's decision.

The example prints what this checkout starts with, turns one movable key down, and asks for the ones
that will not move.
