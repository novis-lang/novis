# Handoff

## State

**Side goal `restart-free`: a running server takes every code change without a restart, and every
config change it can.** ADR 0218 covers source revalidation (Stages 2 to 4) and ADR 0219
configuration apply (Stages 5 and 6). Both are on disk, and 0219 is the last record number this goal
takes. Stages 2 to 5 are complete.

**Stage 6.** The configuration check is on disk (`crate::control::check` in
`crates/nvs-cli/src/control.rs`). `[server]` is a `Reload` block row with `Boot` rows `listen`,
`socket_mode` and `workers`. Every other `[server]` key reloads, and so do `root`, `[[server.mount]]`,
`[session]`, `[control] socket` and now all of `[queue]`. The queue workers belong to a
`worker::Crew` (`crates/nvs-cli/src/worker.rs`): one stop switch per worker, armed at boot by
`arm_queue_workers`, and a task on the ticking core that compares `Current::load` pointers every
`SCHEDULE_POLL` and starts workers (`nvs_host::spawn_child`) or stops the newest ones. A new
connection or block stops them all and starts the count there. The reload asks a new connection's
storage before it publishes (`serve::queue_storage_refusal`, called from `Process::published`).
Proved by `a_changed_queue_worker_count_starts_and_stops_workers_after_their_current_job`. Still
`Boot`: `http.client.tls`, `cache.shared`, `io.temp_root`, `opcache.file_cache_dir`. The fragment
`reloadability-is-its-own-field` names exactly these in its **What is on disk** paragraph. Shrink it
as each one lands.

My calls, not confirmed with the user: a reload whose queue workers would move to storage that is
behind the queue's schema, or that cannot be opened, is **refused whole**, as the boot is. It is not
applied with the key kept, because the key carry cannot hold back a changed `[db.<name>]` block under
the same name. The crew prints `note: N queue workers started on …` and `… stop after the current
job` on standard error. The crew task wakes once per second, so a drain can take up to one second
longer. Earlier calls: a reload whose `[control] socket` names a network address is refused whole
with `E0629`. A control socket that could not be moved is listed by `nvs ctl status` as a restart
pending. After boot, nothing checks again that a named file is one of the mount table's entries. A
reload that removes the last `[[server.mount]]` block serves the named file alone. A changed root is
expanded at once, without waiting for `settle`. Older calls are in ADR 0218, ADR 0219 and `git log`.

`verify.py`'s `extension` leg fails on `tsc` not found (missing `editors/vscode/node_modules`),
which nothing here touches. `tests/db/ca.crt` is a git-ignored fixture copied in from the main
checkout. `docs/novis.md`'s directive table (generated by `tools/reference.py`) still says the queue
keys apply `at boot only` until it is regenerated.
