# Handoff

## State

**Goal `webcrypto` — Novis reads what a browser encrypts and what an issuer signs — has just started; nothing of it has landed yet.** Goal `template-format`'s whole list is this goal's Stage 1 floor.

**The design is settled with the user and is written into the goal's § *Standing decisions*; the record
that states it is not written yet.** Stage 2 writes it — one new record, the goal names no number — and
it transcribes those decisions rather than re-deriving them. The two things not to re-decide: **one
streamlined API** — `seal` and `open` take a required `Cipher` enum, a member exists per job and never
per algorithm — and **no algorithm argument has a default**, for a cipher, a digest or a curve.
`generateKey()` keeps no parameter, because its key serves every cipher and every roster protocol.

**The goal was widened before it ran to carry JWS, and that design is settled with the user too.** Four
more things not to re-decide: `ring`, already TLS's provider, signs and verifies RS256, PS256, ES256 and
EdDSA, and nothing else moves onto it; an RSA key's scheme is fixed when it is read, and a key set
refuses an RSA key with no `alg` unless the caller names the scheme; `Jwt::verifyIssued<T>` answers its
claims as a `tainted` shape through the decode-site check `Core\Request::jsonAs` already has; and
`leeway` is `60s` by default and never above `5m`. The frozen set already carries its `jws` section,
regenerated by hand, so stage 7 has everything it replays. JWS is stage 6, and the old stages 6 and 7
are now 7 and 8. Two more were added the same way and are not to be re-decided either: raw
`Crypto::sign`/`verify` over the same kinds, landing in stage 4, and structured claims under a key pair
in `Jwt::sign`, landing in stage 6. The set's `signatures` section is their vectors.
