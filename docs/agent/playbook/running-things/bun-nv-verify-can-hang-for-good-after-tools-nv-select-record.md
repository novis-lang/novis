- **`bun nv verify` can hang for good after `tools/nv/select/record.ts` logs "its record could not be read ... Out of memory".** When the machine is short of memory, Bun fails to read the select records, and the run then sits at 0 CPU on one step. Check that `.agent-tmp/verify-progress.json`'s `at` stops moving and that its `pid` uses no CPU. If both hold, stop your own run with TaskStop and start it again with `run_in_background`; ask the user about another session's. `until: gone tools/nv/select/record.ts:could not be read`
