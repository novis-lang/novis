- **A test that writes a long message to a peer thread fails under Miri on the peer's read timeout, and it reads as a lost message.** Miri runs every thread on one interpreter, so masking 200 kB on the writer's side took longer than the peer's 5 s wait, and the peer stopped reading before the message arrived. Shrink the message under `cfg!(miri)` before you lengthen a wait, as `crates/nvs-stdlib/src/http/socket.rs` does.
