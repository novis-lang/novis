- **A perf record made in a tree another session is editing hashes that session's uncommitted file, and CI then finds it stale.** `bun nv proofs --record-perf` reads each feature's impl files from the working tree, so a `Core\Router` record made while the main loop held an edit to `router.rs` carries a hash that no commit has. Before you record, compare each stale cause's file with `git status --short`, and pass `--only` the features whose files are clean. A `grep -v` that filters ids with a backslash in them can match nothing and leave every id in, so check the count before the run. `tools/nv/proofs/perf.ts` computes the hash. `until: gone tools/nv/cmd/proofs.ts:--record-perf`
