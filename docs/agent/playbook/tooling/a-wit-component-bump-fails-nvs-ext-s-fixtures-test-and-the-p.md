- **A `wit-component` bump fails `nvs-ext`'s `fixtures` test, and the pins it rewrites are also named in `nvs.toml` files it does not touch.** The packer's bytes move with the encoder, so every committed `.nvsx` gets a new pin, and the `[[extension]]` entries under `docs/examples/` and `tests/hostile/` still name the old one. Run `NVS_WRITE_FIXTURES=1 cargo test --test fixtures`, then grep the tree for each old pin from the `.sha256` diff and replace it, as `crates/nvs-ext/tests/fixtures.rs` says. `until: gone crates/nvs-ext/tests/fixtures.rs:NVS_WRITE_FIXTURES`
