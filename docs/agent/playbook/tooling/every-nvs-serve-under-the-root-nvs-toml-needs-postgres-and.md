- **Every `nvs serve` under the root `nvs.toml` needs the compose `postgres` with the queue's tables in it, so a check that serves can go red in every program at once for a reason no program has.** The root file's `[queue]` arms on `[db.main]`, and the boot refuses when that database cannot be opened or lacks `nvs_jobs`, while `nvs run` only warns. The service keeps no volume, so a new container needs `nvs queue migrate` again. `bun nv site` does both before its first served snippet (`rootConfigReady`); a new tool that serves under the root file needs the same. `until: gone tools/nv/cmd/site.ts:rootConfigReady`
