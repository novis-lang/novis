# M5 — Concurrency and script isolates (~5 weeks)

**Carried by goal `concurrency` — the parity program's keystone.** Nothing above it in the program has a socket, a timer or a
task without this milestone: the four database drivers, the outbound HTTP client and the listener all
reach the network through the one stream this builds. [Goal `concurrency`](../agent/goals/concurrency.md) is the
loop goal that lands it.

**The runtime is ours and it is not `async`.** `corosensei` stackful coroutines on a thread-per-core
scheduler, and no second scheduler in the binary — `tokio` is compiled with `sync` alone where it
appears at all (`rule:concurrency/one-scheduler`). What makes every synchronous Rust
crate usable on top of it is that **`nvs-host`'s socket implements plain `std::io::Read` and `Write` and
parks its coroutine instead of blocking the core** — `rustls` streams over it unmodified, and so do the
wire codecs the drivers use. `docs/plan/design.md` § *Thread-per-core, shared-nothing runtime* is the one
home for that rule; earlier text here and in `rule:http-server/a-core-is-never-blocked-on-a-syscall` said "Tokio" and was stale.

Per-core runtimes, coroutine scheduler, `spawn` / `await` and `Core\Task\Channel` with backpressure,
cross-core worker dispatch with deep-copy-or-move, structured concurrency (a task tree dies with its parent
— no orphans), async-native file I/O, sockets, timers and HTTP client. The earlier `all`/`race`/`timeout`/
`parallel_map` verb list is now `rule:concurrency/one-scheduler`'s `Core\Task`
roster — `::all` over a shape literal of `fn` literals binding each field's own type, `::map` (what
`parallel_map` becomes, subject-first), `{limit, deadline}` as the one options shape in place of a
`timeout` wrapper, and **no** `race`: `rule:concurrency/limit-and-deadline-are-the-only-bounds` refuses one
and reserves the hedging name, and no goal on the chain builds it. That ADR also fixes what cancellation
does: no user code runs, native teardown does, and no call returns with a child still running. The isolate
this milestone builds is also what makes `nvs test` parallel: from here every `#[Test]` runs in its own
isolate sharing nothing but compiled code, the runner owns the test's task tree, and `#[Test(at:, seed:)]`
puts the clock and the generator under the test's control
(`rule:testing/isolate-per-test`, `rule:testing/determinism-declared-on-the-test` and `rule:testing/task-tree-and-virtual-clock`).
`serialize()`/`unserialize()` share this milestone's deep-copy-or-move graph walk, externalized to Novis's own
closed byte format (`rule:classes/two-copy-depths`); `unserialize()` refuses
anything not in that format, with no `__serialize`/`__unserialize`/`__sleep`/`__wakeup` hook. That same graph
walk — both as `serialize()` and as the `spawn worker`/`spawn script` value-crossing operation below — refuses
a `secret`-qualified value outright unless it was first passed through `Core\Secret::reveal()`
(`rule:security/secret-qualifier`).

**Also in this milestone: `spawn script`** (`rule:security/isolate-shares-nothing`) — the
`Isolate` type in `nvs-host` with its own arena, `Core` accessor backing state and config overlay; the
request tree and its shared budget; `Core\Script::args()` (`rule:statements/no-host-populated-variables`) and the
top-level `return` contract; the `ScriptResult` shape; the value-crossing
rules shared with worker dispatch (graph copy, refusal of closures, references and resources, refusal of an
unresolvable class); `output: capture|inherit`; `on: worker`; cancellation of a child at its next safepoint.
It belongs here rather than later because it is a task with a heap boundary, which is exactly what this
milestone builds — and doing it now means the HTTP server in M7 is written against the same `Isolate`
instead of growing a second isolation path that has to be unified afterwards. Enforcement of its *limits*
and of the `script.spawn` capability lands with the rest of the config work in M6; until then it runs under
compiled-in defaults. The three spawn-construct routines built here also each gain a `spawn`-kind trace
event with a parent/child overhead split under `rule:testing/debug-probes`'s `TRACE`/`PROFILE` bits
(`rule:observability/trace-events-carry-a-kind`); [goal `m5-proofs`](../agent/goals/m5-proofs.md) is
where that event is recorded.

**Verify:** stress tests with 100k concurrent tasks; a deliberate deadlock test proves cancellation
works; CPU-bound children placed `on: "worker"` show near-linear speedup across cores, since
`Core\Task::map` is concurrency on one core (`rule:concurrency/on-worker-runs-the-child-on-another-core`); ThreadSanitizer
clean. `rule:concurrency/one-scheduler`'s own *Verification* section is the one home
for what `Core\Task` owes, including the one that is easy to skip: a cancelled task's `catch` and cleanup
blocks do not execute while its arena is still released. A `Task::all` field holding a callable-typed
variable binds exactly as an `fn` literal does —
`rule:concurrency/an-all-field-answers-what-its-callable-declares` replaced the restriction that made it a
compile error, and `task_all_binds_its_result_shape_from_callable_typed_variables` in `crates/nvs-types/tests/core_members.rs` pins the binding. For isolates: a child cannot read or write a parent
variable, global, static, or output buffer, and
a `Core\Request`/`Core\Server`/`Core\Session` call inside it throws rather than seeing the parent's request
(`rule:statements/no-host-populated-variables`); a closure, reference or resource is refused at the boundary; a
cyclic argument crosses without
hanging; a child's uncaught throw, its limit breach and a contained panic inside it all leave the parent
running with `ok = false`; a cancelled parent leaves no orphan and no leaked arena; spawn-to-result for a
trivial child on a warm cache is single-digit microseconds, committed to `benches/abi-probe/benches/isolation.rs` next to the
process baseline it replaces, with a guard test alongside
`an_os_process_costs_orders_of_magnitude_more_than_a_task`. `serialize()`/`unserialize()` round-trip a cyclic
value using the same graph-copy fixtures as the isolate-boundary tests; bytes that are not Novis's own format,
or that name a class whose declared properties no longer match, are refused rather than partially accepted
(`rule:classes/two-copy-depths`).
