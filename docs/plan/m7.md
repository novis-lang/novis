# M7 — Built-in HTTP server (~4 weeks)

**Carried by [goal `server`](../agent/goals/server.md) — the last milestone of the parity program — and
by the goals behind it**, which the index's `Carried by` cell lists because it is derived from the chain
and this paragraph is not. Goal `server` shipped the single-core server and closed;
[goal `per-core`](../agent/goals/per-core.md) took the fan-out this milestone's own scope had been
carrying unclaimed, so *per-core accept and dispatch* — § 1 below — is what `nvs serve` starts today, one
worker per core (`crates/nvs-cli/src/serve.rs:427`). The milestone was moved ahead of the editor because
the request-facing half of `Core` (`Request`, `Response`, `Session`, `Router::match`, the `Metrics`
exporter) has no meaning without it, and leaving those behind would have made "PHP core parity" a claim
with a hole in it. What it still owes an operator is
[goal `m7-server-surface`](../agent/goals/m7-server-surface.md)'s.

**How hyper runs in a workspace with no async runtime.** `hyper` with `default-features = false, features
= ["http1", "server"]` depends on `http`, `http-body`, `bytes`, `futures-core` and `pin-project-lite`, and
on no `tokio`. h1 requires no `Executor` and `serve_connection` spawns nothing, so the connection future is
driven by a **`block_on` on the coroutine that owns the connection** — a waker that marks the coroutine
ready, poll, park on `Pending` — over the `hyper::rt::Read`/`Write` adapters wrapping M5's parking stream.
That is one polled future per connection, not a second scheduler, so `rule:concurrency/one-scheduler`'s rejection of tokio's task
primitives is untouched. Hand-rolling h1 instead was weighed and refused for the reason `docs/plan/design.md`
already gives about FCGI: framing is where request smuggling lives, and it is not a parser to own.

`nvs serve`: **hyper h1 only** — no TLS listener and no h2c, both dropped by
`rule:http-server/two-deployments-and-nothing-a-proxy-owns` — per-core accept and dispatch,
request → the root isolate of a request tree (the same `Isolate` M5 built, not a second isolation path),
the `Core\Request`/`Core\Server` accessor classes populated from it
(`Core\Request::query()`/`::post()`/`::cookie()`/`::file()`, `Core\Server::meta()`/`::header()` — replacing
`$_GET`/`$_POST`/`$_SERVER`/`$_COOKIE`/`$_FILES`, see `rule:statements/no-host-populated-variables`), returning
`tainted string`/`tainted bytes` per `rule:security/tainted-qualifier`,
multipart and urlencoded body parsing with limits, streaming responses, graceful shutdown and zero-downtime
reload. **An uploaded file is a stream and `Core\Request::files(): Iterable<Part>` is the only way to
receive one** — `rule:http-server/an-upload-is-received-only-through-files`
holds the only copy of the part shape, the three ways to consume one, `Core\IO::writeStream`, and the two
caps `[limits] request_body` (bytes parsed into memory) and `[limits] upload_total` (a streamed multipart
body, enforced on the wire and refused pre-dispatch when `Content-Length` already exceeds it), both landing
here as new rows in M6's `[limits]`/`[limits.hard]` pair. **`Core\Response`'s body surface is the five typed members**
`html`/`json`/`text`/`bytes`/`sendFile` rather than a single `write`, each setting its own `Content-Type`,
with `echo` the HTML-only sixth path and mixing the two a compile error
(`rule:security/response-body-is-one-typed-member`) — which is also where a JSON
body stops being an `echo` the auto-escape sink would corrupt. The **`echo` binding table** (§ 3 of that
ADR) is enforced from here: the HTML sink is attached by a request and by nothing else, so a scheduled
script's and an isolate's `echo` take the terminal sink's neutralization instead.

**What the server is, and is not, is `rule:http-server/two-deployments-and-nothing-a-proxy-owns`** —
the only copy of the scope, the `[server]` block and every rule below. Two deployments and no third: a
development server serving static files beside `.nvs`, and a proxied production origin that replaces
FastCGI. Its governing rule is that **a filesystem path is never derived from a URL at request time**, so a
request selects a **mount** from a table that globs expanded against disk at boot — which is what makes
several entry points under one document root, and vhost-per-module, cost one line each. Also landing here
from that ADR: prefix stripping and the relocatable module it buys, static-file serving as one policy in
both modes, the trusted-proxy walk behind `Core\Request::clientIp` and `X-Forwarded-Proto`, four finite idle
timeouts, `max_in_flight` with its pre-allocation `503`, the optional health path and
`Core\Server::isDraining()`, `Core\Request::bodyStream()`, and `[log] access`.

**Also here: the control socket and `nvs ctl`** — a local unix socket (named pipe on Windows), created
`0600` and refused if its directory is world-writable, speaking HTTP so that a network listener would later
be a second `bind` rather than a second protocol, with `nvs ctl reload` as its only operation and no control
port in either direction of configuration (`rule:config/one-local-control-socket` and `rule:config/no-network-control-surface`).

**Also here: `nvs service`**, which makes this binary installable under the platform's own service manager
rather than under a third-party shim. On Windows that is SCM registration with the hosted argv encoded into
a quoted, absolute `ImagePath`, a per-service virtual account, `STOP_PENDING` driven by the graceful drain
above and `PARAMCHANGE` driven into the reload beside it; on Linux it is a printed, hardened systemd unit
with `Type=notify` and an `ExecReload` pointing at that same socket, written to disk only on an explicit
`--install`. The installer is an `rule:security/sink-predicate`
sink and fails closed — a closed `serve`/`run` subcommand allowlist, no relative path, no password on a
command line, and a refusal to install from an
`rule:packaging/nvs-build-compile-appends-the-program-to-a-copy-of-the-host` bundle. Scope, every refusal, the argv-encoding
rule and the verification list are
`rule:packaging/a-service-is-one-stored-argv`, the only copy.

**Four subsystems land on top of that server, each with its own ADR holding the only copy of its rules.**
The **response policy** — secure headers, closed CORS and `Secure; HttpOnly; SameSite=Lax` cookies applying
with nothing configured, every directive `Runtime` so a request may change it for itself
(`rule:http-server/secure-headers-with-nothing-written`, `rule:http-server/cors-is-closed-until-origins-are-named`, `rule:http-server/cookies-are-secure-httponly-and-lax` and `rule:http-server/policy-headers-are-runtime-class-and-setheader-wins`). The **`[[schedule]]` ticker**, firing each
entry as a **root** isolate through the same `Isolate` M5 built, with the fleet lease over the shared store
(`rule:config/scheduled-work-is-a-config-block`). **`Core\Task::afterResponse`**, whose tree stays alive
past the connection and is bounded by `[deferred] max_concurrent`
(`rule:concurrency/after-response-outlives-the-connection` and `rule:concurrency/deferred-is-bounded-by-two-directives`). And the **observability export** —
`Core\Metrics`, the default series, W3C `traceparent` inbound with a trace id generated for every request
whether sampled or not, and spans derived from
`rule:observability/trace-events-carry-a-kind`'s existing event kinds with no probe
added to `rule:testing/debug-probes`'s measured path (`rule:observability/the-runtime-exports-what-it-already-measures`). **`Core\Router::match`**
lands here too, over the table M4S compiled, with the three conventions
`rule:routing/matching-is-not-dispatching` deferred decided above it — and with
`rule:routing/the-servers-match-dispatches-nothing`'s
once-per-request match behind `Core\Request::route()`, which is what this milestone's CSRF check and `route`
metric label both read rather than matching again. `methodsFor`, `urlAbsolute`, `Core\Request::mount()` and
the per-mount `origin` boot check land with it. **Not named here:**
raw/unparsed body access for an arbitrary content-type — a gap
`rule:security/tainted-qualifier`'s *Revisiting* flags, narrowed to what `body()` and `bodyStream()` do not
already answer and settled by [goal `m7-server-surface`](../agent/goals/m7-server-surface.md), which
takes `Core\Request`'s full body surface.

**Also in this milestone: hot-reload of the compiled-unit cache**, which is what makes "no restart to see an
edit" true of a running server rather than only of `nvs run`. `rule:config/an-edit-reaches-the-next-request-without-a-restart`
holds the only copy of the mechanism — a per-path pointer over the content-addressed cache M5/M6 already
built, revalidated lazily and rate-capped, swapped without ever blocking a request-serving core, with
`validate`'s startup default selected by the run mode. Every request stays as isolated as a fresh
subprocess regardless: compiled code is the only thing this milestone ever lets one request share with
another, and that sharing is exactly what M5's `Isolate` and M6's `[limits]`/`[limits.hard]` already bound
per request tree, not per file.

**Verify:** the core requirement demonstrated under load — 10k concurrent cold requests for the same file
compile it **exactly once** (assert via a compile counter) with no stalled requests; a state-bleed test
suite proves nothing leaks between requests, and the same suite runs across an isolate boundary, which the
shared `Isolate` makes a parameterisation rather than a second suite; a request whose isolates are still
running when the client disconnects leaves none of them behind; path traversal, header injection and
request-smuggling suites pass; throughput compared against PHP 8.5 with opcache and recorded in
`benches/serve.json`, which `bun nv bench --serve-vs-fpm` writes. Neither `wrk`/`oha` nor an FPM pool
exists on the boxes this repository is developed on, and `tools/nv/cmd/bench.ts`'s § *The serve-versus-FPM
leg* is the one
home for what stands in for each — a generator written into the tool, and `php-cgi -b` over FastCGI, which
is FPM's own SAPI without the process manager — for why the substitution biases the figure towards PHP, and
for why concurrency defaults to 1. The containerised leg that really does put nginx in front of FPM is
`bun nv bench-proxied`, whose design is `benches/proxied/README.md`; it is not comparable with this one
and is not what this paragraph asks for.
`rule:http-server/two-deployments-and-nothing-a-proxy-owns`'s own *Verification* is the
fixture list for the mount table, resolution order, the `[server]` waits and ceiling, the forwarded-header
walk, the three conventions and the body paths — including the assertion that the set of paths the server
can execute after boot equals the expanded mount table, which is that ADR's governing rule stated as a test.
`rule:http-server/an-upload-is-received-only-through-files`'s *Verification*
is the fixture list for uploads, whose load-bearing case is that a multipart body far larger than any
in-memory bound is received in full at **bounded resident memory**, asserted against a high-water mark
rather than against the request merely succeeding.
For hot-reload specifically (`rule:config/an-edit-reaches-the-next-request-without-a-restart`): a request
makes no filesystem call to revalidate, because one background check per `revalidate_freq` notices an edit,
so no request rate can raise the `stat` count; a storm of requests against a broken file costs one compile;
a request that resolved the old version runs it to completion while a newer version is already being served
to new requests; a revalidation that fails to compile fails only requests resolving it afterwards.

**Also here: persistent connections** (`rule:concurrency/a-connection-is-a-root-isolate`).
`Core\Socket::upgrade` and `Core\Sse::upgrade` reuse `rule:security/isolate-shares-nothing`'s
`with(...)` clause whole and hand the socket to a **root isolate** — the same `Isolate` M5 built, so this
milestone adds a lifetime, not an isolation path. The upgrade is h1-only, where it is native. `Core\Topic`
is the cross-core publish/subscribe bus, with a bounded per-subscriber queue that closes a slow subscriber
rather than blocking a publisher. That ADR's *Verification* is the fixture list; the state-bleed suite above
gains connections as a third parameterisation rather than a second suite.
