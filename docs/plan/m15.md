# M15 — Packages, the registry and the supply chain (~8 weeks)

**Backlog 4.** Capabilities exist, so a package can be granted them, and nothing this milestone needs
is missing. **It is not optional**: `rule:programs/slice-ranking` ranks this above new `Core`
breadth, because it is the thing a new user meets before any language feature.

`rule:packaging/a-package-is-its-digest` is the whole design. The client half:
`package.toml`/`package.lock`, `nvs add`/`fetch`/`update`/`outdated`/`vendor`/`audit`/`publish`, minimal
version selection, the root-only git source, digest verification, transparency-log inclusion and consistency
checks, and the generated `vendor/packages.nvs` that reaches a fetched package through an ordinary
`rule:programs/no-runtime-autoload` `autoload` declaration — the piece that
keeps this out of the language. A name is `vendor/name`, lowercase and compared exactly, with the vendor
`nvs` reserved (`rule:packaging/a-package-name-is-vendor-slash-name`); a breaking release is a new name
carrying `supersedes` (`rule:packaging/a-breaking-release-is-a-new-name`); a known-bad version is
retracted with a reason and a fixed-in version, never deleted, and `nvs audit` reads the advisory feed
(`rule:packaging/a-known-bad-version-is-retracted-not-deleted`); and an archive that carries an
`nvs.toml` is refused (`rule:packaging/a-package-cannot-reach-its-host`). The compiler half is smaller than it looks: a file → package map, and a
capability check at every `Core` call site against the grants of the namespace that call site is in
(`rule:security/authority-is-the-enclosing-namespace`, which owns the key, the
longest-prefix lookup, the required/optional split and `Core\Cap::has`; its codes are the band's next free numbers — `E0604`–`E0607` have since gone to configuration diagnostics — and they
land here). **There is no name-resolution work at all**, which is the design's own assertion and the first
thing to verify.

The registry half is a service rather than a milestone deliverable: a static index, an artifact store, an
append-only Merkle log with signed checkpoints, an advisory feed, accounts with a second factor. It is
specified here and operated outside the repository.

**`nvs/rest` is one of the first packages the registry carries**: the REST and OAuth client, about seven
types over OAuth grants, discovery and DPoP. Everything it needs from `Core` has landed — JWS signing and
verification, the HTTP client, the memory cache tier and sealed secrets, the forward proxy and the
outbound WebSocket — and
`rule:core-api/tier-placement` keeps the OAuth flows themselves out of `Core`, so the package is what is
left. A user's refresh token goes in the session (`Core\Session::setSecret`), because a cache tier may evict
it. Encrypted ID tokens and generating a client from an OpenAPI document are out of its scope.

**A program gains a declared version here, and the generated API document is its first reader.**
`package.toml` is the first place anything in the tree says what a program is published as, so
`crates/nvs-cli/src/openapi.rs`'s `info.version` — which 3.1 requires and which the emitter therefore
carries as a fixed `0.0.0` while nothing declares one — is read off that manifest with the rest of the
document unchanged. A deployment key would be the emitter quoting a fact back at whoever wrote it in
`nvs.toml`, which is not what the version of a published artifact is. The same manifest is where an
`nvs build --compile` bundle gets its own Windows version information and icon: a bundle is a copy of the
host, so today it carries Novis's (`crates/nvs-cli/src/bundle.rs`'s known gap).

**Verify:** a test per packaging rule this milestone owns, each named in that rule's `guardedBy`. The
ones that matter most: a package calling a `Core` member without a matching grant line fails to compile
naming the package, the capability and the fix; a package containing a top-level statement with an
observable effect produces no effect from `fetch`, `build` or `vendor`; `fetch` writes a grant line for
every package, an empty one included (`rule:security/package-authority-is-granted-one-line-at-a-time`);
and `nvs audit` warns on an autoload root that no grant line mentions
(`rule:security/an-unmatched-namespace-holds-the-application`).
