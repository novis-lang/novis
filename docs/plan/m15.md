# M15 — Packages, the registry and the supply chain (~8 weeks)

**Carried by goals `namespace-grants`, `api-compat`, `package-client`, `registry-log`, `core-passkey`,
`core-web-push`, `registry-service`, `registry-website`, `package-audit` and `first-packages`**, in
that order at the end of the chain. Each goal holds its stages, its standing decisions and its acceptance; this file
holds the design they share. `rule:programs/slice-ranking` ranks this above new `Core` breadth,
because a package system is the thing a new user meets before any language feature.

**A package is its namespace, and its identity is its digest.** A package's root namespace has exactly
two segments, `Vendor\Package`, and every file in it declares that namespace or one under it
(`rule:packaging/a-package-name-is-vendor-slash-name`). The name a command line or a URL uses is
derived mechanically: lowercase, with `\` replaced by `/`. The first publish of `Acme\Http` takes the
name and makes the account the owner of the vendor `Acme`; a name that ever had a published version is
never reassigned. `Core\` and `Novis\` belong to the project's own account, and `Novis\` holds the
built-in components and the first-party packages. A package is an immutable source archive whose
BLAKE3 digest is its identity (`rule:packaging/a-package-is-its-digest`).

**Authority is the namespace that encloses the code** (`rule:security/authority-is-the-enclosing-namespace`).
The application's grant table is keyed on namespace prefixes, the longest match wins, and a `Core` call
site compiles only where its namespace was granted the capability, intersected with the operator's
configuration (`rule:security/grants-are-keyed-on-a-namespace`). A required capability not granted is a
compile error and an optional one a guarded throw (`rule:security/optional-capability-degrades`). For a
registry package the grant table and the package graph are the same thing; the table also protects
code no package manager fetched. Goal `namespace-grants` builds this first, independent of the
registry.

**Only a major may break the API.** Versions are `MAJOR.MINOR.PATCH` read literally: `0.0.x` is
experimental, and from `0.1.0` on a minor or patch never breaks the public API of the release before it.
`nvs` checks that statically at publish, and the registry refuses a break
(`rule:packaging/only-a-major-may-break-the-api`). Resolution still takes the highest minimum, across
majors too, so a graph is never unsolvable (`rule:packaging/resolution-takes-the-highest-minimum`).

**The client** is `package.toml`, `package.lock` and `nvs pkg add`, `fetch`, `update`, `outdated`, `vendor`
and `audit`. Each vendor resolves from exactly one registry
(`rule:packaging/a-vendor-resolves-from-one-registry`), every digest is locked
(`rule:packaging/the-lockfile-holds-every-digest`), only the root may name a git dependency
(`rule:packaging/a-git-dependency-is-root-only`), and a fetched package is an ordinary `autoload` line
in the generated `vendor/packages.nvs` plus a grant line, an empty one included
(`rule:packaging/a-fetched-package-is-an-autoload-line`). **There is no name-resolution work at all**,
and nothing in a package runs before the program (`rule:packaging/nothing-runs-before-the-program`).
The grant lines are `[grants]` in the application's own `package.toml`, which `nvs pkg add` and `fetch`
write and a person reviews; the compiler reads that table and nothing else of the file, and only the
table folds into every compiled unit's cache key, as the extension set does
(`rule:packaging/package-toml-is-a-tool-input`, `rule:config/the-extension-set-is-in-every-unit-key`).

**The registry is a Novis program in this repository** (`rule:packaging/the-registry-is-a-novis-program`),
`apps/registry/`, and the byte work it needs (clone, deterministic pack, digest, manifest and API
checks, log append) is Rust in the `nvs` subcommands the client runs too. It builds every archive
itself from a git commit (`rule:packaging/the-registry-builds-the-archive-from-git`) and never
overwrites (`rule:packaging/publishing-never-overwrites`). An account is passkeys and recovery codes,
with no email and no forge binding (`rule:packaging/a-registry-account-is-a-passkey`), and owners are
notified through channels they verified (`rule:packaging/an-owner-is-notified-without-email`). A
token is scoped and expires (`rule:packaging/a-publish-token-is-scoped-and-expires`), and token use
never keeps an account active (`rule:packaging/an-account-stays-active-by-proof-not-by-token`). A
release by token alone waits seven days unless an owner confirms it with a passkey
(`rule:packaging/a-release-waits-seven-days-unless-an-owner-confirms`). An owner may unlist
(`rule:packaging/an-owner-may-unlist`), and the operator may only withhold
(`rule:packaging/the-operator-only-withholds`). Every such event is an entry in an append-only log in
the C2SP formats, and a client refuses a log that does not extend the one it saw
(`rule:packaging/the-registry-keeps-an-append-only-log`). `Core\Passkey` is the `Core` class the
registry signs in with, and every Novis web application gains it
(`rule:core-classes/passkey-verifies-a-webauthn-ceremony`). Owners' push notifications go through
`Core\WebPush`, which encrypts with an AES-128-GCM it keeps internal and a nonce it derives itself,
signs a VAPID token and sends under `net.connect`
(`rule:core-classes/web-push-sends-an-encrypted-message`).

**A program gains a declared version here.** `package.toml`'s version becomes the generated API
document's `info.version`, which is a fixed `0.0.0` while nothing declares one, and an
`nvs build --compile` bundle's own Windows version information and icon. **`Novis\Rest`**, the REST and
OAuth client that `rule:core-api/tier-placement` keeps out of `Core`, is the first package the registry
carries.

**Verify:** a test per rule this milestone owns, each named in that rule's `guardedBy`, and every goal
above reached. The ones that matter most: a package calling a `Core` member without a matching grant
line fails to compile naming the namespace, the capability and the fix; a package containing a
top-level statement with an observable effect produces no effect from `fetch`, `build` or `vendor`;
`fetch` writes a grant line for every package, an empty one included
(`rule:security/package-authority-is-granted-one-line-at-a-time`); a minor that breaks the previous
release's API is refused at publish; a client refuses a forked log; and `nvs pkg audit` warns on an
autoload root that no grant line mentions (`rule:security/an-unmatched-namespace-holds-the-application`).
