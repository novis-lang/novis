# M12 — Optimising JIT tier (ongoing)

Profiling counters, inline caches for property and method access (monomorphic → polymorphic →
megamorphic), unboxed int/uint/float fast paths, inlining, refcount elision, escape analysis, deopt and OSR
at existing safepoints. Narrower than originally scoped: the declared types of
`rule:types/declaration` mean the baseline tier is already typed, so speculation only
has to cover `mixed`, unions and dynamic calls.

**The library's own allocation economy is this milestone's other half**, and is where a `Core`
member's deferred allocation count lands. Escape analysis and refcount elision reach the allocations
the compiler can see, and a native member's are not among them: a key copied onto the heap to be
looked up, a callback argument nobody declared, an argument list built in a heap vector per call, a
result array grown one entry at a time with the entry count already in hand. Each of those is a
decision about a convention every member shares rather than about one member, each moves rows of
`docs/perf/members.ndjson` under `rule:testing/member-perf-ledger`, and
the individual ones are written in the `# Known gaps` section of the crate that owes them.

**Verify:** macro benchmarks show a multiple over the baseline tier and over PHP 8.5 with JIT — measured per
`rule:testing/perf-two-mechanisms`'s same-host PHP-oracle ratio, not a raw
cross-machine wall-clock claim; no correctness regressions in the full conformance suite when the
optimising tier is forced on. The allocation counts deferred here are re-measured in that same
ledger, member by member.
