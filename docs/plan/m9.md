# M9 — Extension system, and the `nvs:ext@1.0.0` world it freezes (not yet sized)

**Carried by eight goals at the end of the chain**, in this order: `ext-design`, `ext-host`,
`ext-compiler`, `ext-grants`, `ext-tooling`, `ext-image`, `ext-image-analysis`, `ext-intl`. PHP's
optional extensions are not on the parity program's path, so the milestone runs behind it and behind the
editor rather than beside M8 ([implementation-plan.md](../implementation-plan.md)).

**The design is decided before any code.** [0003](../decisions/0003.md) chose the sandbox;
[0246](../decisions/0246.md) settles everything it left open — a value crosses as the WIT type
`rule:packaging/a-value-crosses-as-its-wit-type` gives it, a `.nvsx` carries a JSON manifest and its
Novis source in two sections under one required pin (`rule:packaging/an-nvsx-is-one-file-carrying-its-manifest`),
a guest call is an async call polled on its request's core that yields every epoch tick
(`rule:packaging/a-guest-call-yields-on-its-core`) and spends that request's CPU and memory, a trap
throws `ExtensionError` (`rule:packaging/a-guest-crash-throws`), and a guest holds an empty WASI plus the
files and outbound HTTP its entry, its manifest and its caller all grant
(`rule:security/extension-grants-are-an-intersection`). [0247](../decisions/0247.md) builds the two
first-party components into every binary, always present under `Novis\`
(`rule:packaging/the-first-party-components-are-built-in`). Signatures are M15's.

**Goal `ext-design` writes the world first.** The `nvs:ext@1.0.0` WIT text is derived from a finished
`Core`: its first slice walks every `Core` value class against the draft world, so a shape that cannot
cross is found in a design session rather than in a port, and the parametric array signatures M8 wrote
are reused, `uint` as `u64`. The image component's eight entry points
(`rule:core-classes/image-pipeline`) are written against the same world. Before either, the goal proves
in `benches/abi-probe` the one mechanism 0246 could not take on trust: a wasmtime async call polled from
a Novis coroutine, parked on a host import, yielding at an epoch tick while a second coroutine enters wasm
on the same thread.

**`nvs-ext` is goals `ext-host` and `ext-grants`:** loading and the load refusals, the packer, per-request
instances on the pooling allocator, the call bridge, the CPU deadline and the memory charge, failures,
reload over the `env_hash` M6 put in both cache keys (`rule:config/the-extension-set-is-in-every-unit-key`),
compiled modules in the artifact cache; then the empty WASI, the `grants` key, preopens and the
`wasi:http` handler over `Core\Http\Client`. **Goal `ext-compiler`** registers a manifest's class into
the signature table so a call is type-checked and its qualifiers are checked by the same code as a
`Core` call's (`rule:security/extension-manifest-only-tightens`), emits the direct trampoline call, and
makes the source section resolvable. **Goal `ext-tooling`** is `nvs ext new|build|inspect|test|verify|pin`
with Rust and C templates (`rule:packaging/nvs-ext-is-the-authoring-tool`), and a bundle carrying a
`.nvsx`.

**Goals `ext-image`, `ext-image-analysis` and `ext-intl` build the two components**
`rule:core-api/tier-roster` places at Tier 1 and this milestone builds; the PDF renderer and the
spreadsheet component are M17's. The image component is one Rust component linking libwebp compiled to
wasm, prebuilt and checked in CI (`rule:packaging/a-prebuilt-wasm-library-is-rebuilt-in-ci`), and it
carries `exif`; its first wave is [0120](../decisions/0120.md)'s roster without SVG and PDF, which are
M17's second wave. The intl component is ICU4X with every CLDR locale, covering 0247 § 5's set, and its
API is the one record goal `ext-intl` opens.

**Verify:** the two first-party components answer from a binary with no `nvs.toml`. The **image
component** makes the security claim legible — decoding an attacker-supplied file in a sandbox under the
request's memory cap and an epoch deadline — and `rule:core-classes/image-pipeline`'s *Verification* is
its fixture list: the pixel cap refusing a bomb before allocation, auto-orientation, ICC-to-sRGB,
metadata stripped by default, `variants` costing one call, `compare` on identical and one-pixel-different
inputs, a malformed IFD thrown inside the guest rather than a trap. Its C leg builds on all three
platforms from one binary. The **intl component** proves the embedded-data and batch shapes: sorting
10,000 strings costs one boundary crossing, counted. Adversarial suite: an extension reading a file or
calling a host it was not granted fails, each of the three grant parties narrowing in turn; a runaway
extension is stopped by the request's CPU cap rather than hanging a core; a memory-hungry one hits the
request's memory cap; a crashing one throws `ExtensionError` and the next call succeeds; state stored in
a global is not seen by the next request. Reload, per `rule:config/the-config-is-an-immutable-snapshot`'s
own list: an artifact compiled under one extension set is never reused under another; an extension added
by a reload is callable from requests arriving after it with no restart; a reload whose pin does not
match the file on disk is refused whole, leaving the previous set live. Both templates build, load and
pass `nvs ext test` on Linux, Windows and macOS. Benchmark in-guest compute against the same crates
built native — the image component's resize and JPEG decode — and **commit the numbers**: it is the one
figure in `rule:packaging/the-boundary-is-the-cost` that is still asserted rather than measured.
