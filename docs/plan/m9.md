# M9 — Extension system, and the `nvs:ext@1.0.0` world it freezes (~6 weeks)

**Backlog 1 — the first milestone behind the chain.** PHP's optional extensions are not on the parity
program's path, so this milestone runs behind
it and behind the editor rather than beside M8 — the schedule adopted 2026-08-28
([implementation-plan.md](../implementation-plan.md)).

**Authoring the `nvs:ext@1.0.0` WIT world is this milestone's first slice**, moved here from M8 by the
same decision. M8's argument for authoring it early was that the Tier 0 internal interface and the Tier 1
guest interface should be one design rather than two that drift; that argument survives the move and its
conclusion reverses, because with M9 four milestones behind M8 the world would otherwise be frozen against
a `Core` that did not exist yet. Written here, it is derived from a finished `Core` instead of predicting
one. What does not move is the obligation M8 kept: the parametric array signatures are written once for
the built-ins there and reused verbatim by the world, where `uint` maps to `u64` with no conversion. **The
world must carry a qualifier axis** — a parameter that refuses `tainted`, a return that is always
`tainted` — per [ADR 0055](../adr/0055-extension-qualifier-declarations.md), which this milestone then
freezes; adding it afterwards would be a breaking change to a published ABI, and without it any `.nvsx`
launders untrusted data merely by being called. The residual risk the move accepts is named rather than
hidden: if authoring the world reveals a `Core` shape that cannot be expressed across the boundary, the
fix is a `Core` change five milestones after that member shipped. The first slice therefore walks the
whole `Core` roster against a draft world **before** any host implementation is written, so that discovery
lands in a design session rather than in a port. The image component's entry points
(`rule:core-classes/image-pipeline`) are
walked in the same slice: eight whole-input-in, whole-output-out exports are the coarse shape the world
must be able to express, and the builder above them is Novis source that the ABI never sees.

`nvs-ext`: `.nvsx` loading (wasm component + `nvs.manifest` custom section), manifest parsing and
registration into the compiler symbol table so extension calls are statically type-checked — including the
`tainted`/`secret` qualifier axis, applied at an extension call site by the same code path as a `Core` one,
with a manifest attempting the laundering form ADR 0055 § 3 says does not exist failing validation at load
time — the WIT host
implementation, per-call handle tables for value access, lazy per-request instantiation on the pooling
allocator, epoch-interruption wiring to the per-request CPU cap, `StoreLimits` wiring to the memory cap,
the capability bridge (no ambient authority; optional WASI world with preopens derived from `nvs.toml`
grants), hash pinning and signature verification, and compiled-module caching in the existing
content-addressed artifact cache. The set is **reloadable rather than boot-only**: `nvs ctl reload`
re-verifies every pin, refuses the swap whole if one does not match, and rides the `env_hash` M6 put in both
cache keys, so a changed set recompiles lazily through ADR 0017's existing machinery with no invalidation
pass ([ADR 0078](../adr/0078-config-reload-and-control-socket.md) § 4). Duplicate class names across extensions
are refused at load, which is what makes that hash order-independent. An extension package may carry
Novis source beside its component ([ADR 0081](../adr/0081-packages-are-digests-resolution-is-a-maximum.md)
§ 1, as ADR 0120 § 1 amended it), and `nvs/image` is the first that does.

Tooling: `nvs ext new --lang rust|c|zig|go`, `nvs ext build` (one portable `.nvsx`), `nvs ext inspect`
(manifest and requested capabilities), `nvs ext test`, `nvs ext verify`. `nvs ext build` must link a C
library compiled with `wasi-sdk` into a Rust component, because the image component needs it (below).

**Verify:** the two scheduled first-party extensions [ADR 0051](../adr/0051-standard-library-tiers.md) § 3
places at Tier 1, end to end — the roster's other entries are deliberately unscheduled, and this milestone
builds exactly two. The
**image component** is the one that makes the security claim legible — decoding an attacker-supplied file in a
sandbox with a memory cap and an epoch deadline — and its shape is
`rule:core-classes/image-pipeline`: a Novis
builder over eight coarse entry points, one crossing per terminal. It is built as **one Rust component
linking libwebp compiled to wasm** for lossy WebP encoding, and that C leg is the second-language
toolchain proof, running unmodified on all three platforms from one binary. It **carries `exif`**
rather than leaving it a second component: the decoder already holds the file, so orientation and the rest
of the tag set cost no extra boundary crossing, and a fixture asserts a malformed IFD is a thrown error
inside the guest rather than a trap. `rule:core-classes/image-pipeline`'s *Verification* is the fixture list — the pixel cap refusing
a bomb before allocation, auto-orientation, ICC-to-sRGB, metadata stripped by default, `variants` costing
one call, `compare` on identical and one-pixel-different inputs, an SVG's external reference left
unresolved. The **intl component** proves the two shapes that ADR's Ext placement depends on: CLDR data
carried in the component's own wasm data section, and a batch-shaped API where sorting 10,000 strings costs
one boundary crossing rather than one per comparison. Adversarial suite: an extension attempting filesystem or network access it was not granted fails;
a runaway extension is trapped by the request's CPU cap rather than hanging a core; a deliberately
memory-hungry extension hits the cap; an extension that stores state in a global cannot observe it on the
next request. Reload, per [ADR 0078](../adr/0078-config-reload-and-control-socket.md)'s own list: an artifact
compiled under one extension set is never reused under another; an extension added by a reload is callable
from requests arriving after it with no restart; a reload whose pin does not match the file on disk is
refused whole, leaving the previous set live. Benchmark in-guest compute throughput against the equivalent native Tier 2 implementation and
**commit the numbers** — this is the one figure in ADR 0003 that is currently asserted rather than
measured, and the image component's resize and JPEG decode are the workload, against the same crates
built native.
