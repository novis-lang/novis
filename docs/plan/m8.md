# M8 — Stdlib and databases (~16 weeks)

**The milestone is cut in two, by file set**: everything but the databases, and
`rule:core-classes/db-one-api` whole. `nvs-db` shares nothing with `Core\Cli`. `Core\Test::request` is
at `crates/nvs-stdlib/src/test.rs:437`.

**The Tier 0 roster `rule:core-api/tier-roster` names is built**, including `Core\Net`, `Core\Os`,
`Core\Signal`, `Core\Compress`, `Core\Mime`, `Core\Zip`, `Core\Xml`, `Core\Html::sanitize` and
`rule:core-classes/html-parsing`'s WHATWG parser. `crates/nvs-stdlib/tests/spec-classes-part-two-outstanding.txt`
holds one key — `§16 Core\Metrics`, marked `unowned` because no goal on the chain registers that class.
Spec §§ 16–17 is registered whole when that line is struck.

**Where the drivers get their I/O.** There is no async runtime, so a driver is written against M5's
synchronous parking stream: wire-protocol crates (`mysql_common`, `postgres-protocol`, our own TDS) over a
`Read + Write` that suspends the coroutine, with `rustls` layered on the same stream for TLS, and
`rusqlite` for SQLite under [ADR 0051 § 4](../decisions/0051.md)'s audited C exception.
`sqlx` and `tokio-postgres` are not usable here and the reason is structural rather than a preference:
they need a runtime that spawns.

**The roster this milestone builds is `rule:core-api/tier-roster`** — which class is
Core, which is a capability-gated native subsystem, which is an extension, and which of PHP's extensions
has no equivalent at all. That ADR is the one home for the list; this paragraph covers only what M8 must
decide beyond it. The capability-bearing half of testing lands with the capabilities it needs:
`#[Test(db:)]`'s rolled-back transaction, `Core\Test::request`'s in-process dispatch through the compiled
route table, `#[Test(server: true)]`'s ephemeral listener, and inline snapshots with their source updater
(`rule:testing/inline-snapshots`, `rule:testing/db-transaction` and `rule:testing/in-process-request`).

**`Core\Cli` lands here in full** (`rule:tooling/terminal-output-is-a-sink`): the terminal
output sink and its visible-substitution table, the `Cli\Text`/`Style`/`Color` value types, the once-per-
process tty/colour-depth/width resolution over `anstream`, the five prompts reading the controlling
terminal rather than stdin, the scoped `live`/`progress` regions, and `Core\Command::run` plus its
generated `--help` and shell completions over M4S's table. Two dependencies arrive with it — `crossterm`
for raw mode, key events and resize, `unicode-width` for UAX #11 columns — both pure Rust, both owing a
notice regeneration. The `rule:errors/engine-floor` terminal-restoration
obligation is part of this slice, not a follow-up: a live region that survives a panic is the defect the
whole scoped shape exists to prevent.

Regex is two-tier, and the tiering is a rule rather than an implementation detail: a linear-time engine by
default, backtracking only for patterns it cannot express and only under a throwing step budget, with a
literal pattern's tier settled at compile time and the *pattern* argument refusing `tainted`
(`rule:core-classes/regex-two-tiers`). The compile-time half of that rides on
`rule:expressions/intrinsic-literals`'s closed intrinsic list, which also lands here and
covers `Core\Uri`, the date-format strings and `Core\Str::format`'s placeholder checking.
`Core\Decimal`/`Core\BigInt` supply the method surface around the `decimal` scalar M2–M4
already built (`rule:types/decimal`) — including `divExact`, `divRound` and
`allocate`, since division is the one place a decimal result may be inexact. `Core\Cache`'s two tiers, the
copy-in/copy-out rule and the per-core memory cap are `rule:concurrency/cross-request-state-is-explicit`;
`Core\Http\Client`'s `tainted`-refusing URL parameter, the `Core\Http::allowUrl` launderer and the
`net.connect` address policy are `rule:http-server/allow-url-pins-the-address`, and its finiteness half —
no spelling for an unbounded wait, jittered opt-in retry under one covering deadline, and a `post` retried
without an `idempotencyKey` being a compile error — is
`rule:http-server/no-spelling-for-an-unbounded-wait`, `rule:http-server/retry-is-opt-in-jittered-and-closed` and `rule:http-server/a-non-idempotent-retry-needs-an-idempotency-key`; the closed
signed-cookie/CSRF/TOTP/JWT roster and its correct-by-construction constraints are
`rule:security/protocol-roster`. **`Core\RateLimit`** lands here too — GCRA over the
shared store as `consume`, per-core and approximate as `shed`, no configuration at all, and an unreachable
store throwing rather than deciding *allowed*
(`rule:core-classes/ratelimit-two-members`); the shared tier's atomic script is ours, since no distributed
rate limiter exists as a crate. `Core\Http\Client` also gains outbound `traceparent` propagation
(`rule:observability/an-outbound-call-propagates-traceparent`), which is the point at which a trace crosses a service
boundary at all.

Also: JSON; hashing and crypto (RustCrypto: sha2, blake3, argon2,
bcrypt, aes-gcm), AEAD-only per `rule:core-api/tier-roster`; date/time with PHP-compatible formatting; filesystem and
stream abstractions — with no scheme dispatch anywhere in them
(`rule:security/a-path-is-not-a-url`); process
execution behind the `process.exec` capability gate — `Core\Process::run()`/`::spawn()`, argv-only with no
shell-string form at all, a Windows batch/PowerShell-target refusal, and coroutine-suspending waits, per
`rule:core-classes/process-is-argv-only` (which supersedes `rule:security/sink-predicate`'s original
placeholder bullet); sessions, which may not be backed by `Core\Cache`'s local tier; and
`Core\Html::escape`/`Markup` plus the `Core\Taint` launderers, per
`rule:security/tainted-qualifier`.

**The database half of this milestone is `rule:core-classes/db-one-api`**, with its signatures in
[docs/spec/01-core-library.md](../spec/01-core-library.md) § 18: one API replacing `PDO`, `mysqli`, `pgsql` and
`sqlite3`, over pure-Rust MySQL, MariaDB, PostgreSQL and MS SQL Server drivers plus SQLite (whose C
dependency is [ADR 0051 § 4](../decisions/0051.md)'s audited exception). Connections are named
in root-owned config under a new `db.connect`/`db.open` capability pair, every statement is prepared, and a
transaction is a closure. Two things it needs from elsewhere in this milestone: `Core\Time`'s types for the
date columns, and `Core\Json` for the JSON ones, which are not auto-decoded. Also here: **`Core\Reflect` and `Core\Ast`**, built-in — not
extension-provided — structural reflection and a runtime door onto `nvs-syntax`'s own lexer/parser, per
`rule:tooling/reflection-and-source-parsing-are-core-features`; reflective access enforces the same
visibility/hook checks ordinary code does, and a parsed AST is typed, inert data with no path back into
execution. Also here: **`Core\Attributes`**, the narrow, statically-resolved `get<T>`/`all<T>` accessor onto
attribute literals attached in M4 — deliberately not part of `Core\Reflect`'s general-purpose walk, per
`rule:attributes/inert-metadata`. Also here: **`Core\Fatal` and `Core\Log`**, plus the operator-configured `.nvs` error-handler
script and the engine-native logging floor beneath it, per
`rule:errors/escalation-ladder`; `Core\Log`'s JSON-Lines writer is the same native
serialiser the engine floor calls directly, so the two never disagree on log shape. `nvs check` refuses a
`secret`-qualified operand at a `Core\Log::write()` call site's `fields` argument despite that parameter's
open `array<string, mixed>` type, and `Core\Secret::reveal()` plus the password-hashing helpers from this
milestone's crypto line item above are the two ways a value legitimately loses `secret` before reaching it
(`rule:security/secret-qualifier`).

**The `nvs:ext@1.0.0` WIT world is no longer authored here.** It moved to M9 with the schedule that put
M9 four milestones behind this one; [m9.md](m9.md) is now its only home and states why.
What this milestone still owes it is the thing that made the original placement worth arguing: **the
parametric array signatures** (`rule:types/declaration` — `array_map(callable,
array<T>): array<U>` and friends) are written once for the built-ins here and reused by the world later,
where `uint` maps to `u64` with no conversion. Type variables stay available only to declarations the
compiler owns; user-defined generics are not part of this milestone.

**Also in this milestone: the framework's privileged half** (`rule:programs/framework-core-half`), each entry placed by `rule:core-api/tier-placement`'s own six tests rather than by a
new rule — `Core\Validate` (the launderer, and the one entry that could never be a package),
`Core\Session`, `Core\Password`, `Core\Mail` transport against an operator-named SMTP endpoint,
`Core\Storage` over local disk, and `Core\Cldr::pluralCategory`. **`Core\Queue` lands here too**
(`rule:concurrency/enqueue-commits-with-your-write`): the jobs and dead-letter tables, `nvs queue migrate`,
per-backend `SKIP LOCKED`-shaped claiming, the visibility timeout, bounded retries with jittered backoff,
and the transactional-enqueue property that is the reason for the whole design. **And the connection pool**
(`rule:security/db-pool-reset-is-a-boundary`) — per core, keyed as `connect`/`open` already key, with a per-backend
reset that is a security boundary: PostgreSQL's targeted reset that preserves the statement cache, MySQL's
and SQL Server's protocol resets that do not, and a failed reset destroying the connection rather than
returning it.

**Verify:** ADRs 0051 and 0054–0060 each list what M8 had to prove, and the tree holds those items as
tests. CI's attribution job runs `bun nv gen-attribution --check-c-deps`, which fails on a C dependency
of the default binary not recorded against `rule:packaging/a-c-dependency-answers-two-questions`, and
`namespace Core` in user code is `E0217` (`crates/nvs-syntax/src/parser/tests/decl.rs`).
`Core\Decimal::divExact`, `divRound` and `allocate` have conformance cases, a PostgreSQL `NUMERIC(30,10)`
column throws on read (`crates/nvs-stdlib/tests/db_stream.rs`), and `Core\Json::decodeAs` round-trips a
25-digit `decimal` exactly. `benches/abi-probe/tests/perf_guards.rs` guards the typed `decimal` loop and
the two regex tiers on one corpus, and `tests/conformance/core/regex-literal-tiers.txt` records each
literal pattern's tier. Every intrinsic literal is checked against its runtime twin
(`crates/nvs-stdlib/src/lib.rs`), a folded call still counts as covered
(`crates/nvs-codegen/tests/probes.rs`), and a unit another toolchain compiled is a cache miss. The HTTP
client refuses a `tainted` URL, connects to the address `Core\Http::allowUrl` pinned, and judges every
redirect again (`crates/nvs-stdlib/src/http/transport.rs`). The local cache tier is per core and evicts at
its cap, `put` refuses a `secret`, a closure and a generator, and `Core\Session` on the local tier is
`E0626`. A JWT with `alg: none`, without `exp` or past it fails, so does one whose algorithm the issuer's
key did not choose, and verified claims are `tainted`. A signed cookie opens under a retired key and seals
under the newest. ADR 0055's list is extension work, owned by M9's goal `ext-compiler`. Two items are gap
records owned by `goal-closeout`: a literal URL at the HTTP client is not read while checking, and the
`tainted`-URL diagnostic does not name `allowUrl`. Beyond that: per-subsystem conformance suites, and
for the database half, the five-driver CI-container matrix `rule:core-classes/db-one-api`'s own
*Verification* section specifies. `Core\Reflect`/`Core\Ast`
verified per `rule:tooling/reflection-and-source-parsing-are-core-features`'s own M8 verification
list — a reflective call to a `private` method from outside its class fails like the equivalent ordinary
call; `Core\Ast::parse()` fuzzed with the same corpus as M1's lexer/parser target. `Core\Attributes` verified per
`rule:attributes/inert-metadata` — `get<T>` on a site with zero matching attributes
compiles to a constant `null`, one match compiles to that constant value with no runtime lookup, and more
than one match is a compile-time diagnostic naming `all<T>`; a literal property/parameter name that names no
real member is a compile-time diagnostic, and a non-literal one is a runtime empty result instead.
`Core\Fatal`/`Core\Log`
verified per `rule:errors/escalation-ladder`'s own M7/M8 list — `onUncaughtThrow` receives
the real `Throwable`; the configured handler script runs charged to the engine's own reserve and still
fires when the reporting request is at its own memory ceiling; application code and the engine floor
produce schema-identical log records for the same error. `Core\Process` verified per
`rule:core-classes/process-is-argv-only`'s own M8 list — a tainted `$path`/`$argv` element is
a compile-time diagnostic, a Windows batch/PowerShell target is refused, the `process.exec` capability is
deny-by-default, and a concurrent-spawn scheduler guard sits alongside `benches/abi-probe`'s existing
coroutine-suspension tests.
