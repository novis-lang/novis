# M17 — Document components: the image second wave, `nvs/pdf` and `nvs/spreadsheet` (not yet sized)

**Backlog 6, and unscheduled on purpose.** No goal carries it. Its one precondition is M9: all three
parts are Tier 1 `.nvsx` packages loaded, capped and pinned by the extension system M9 builds, and the
first part extends `nvs/image`, which M9 builds. It does not wait on M15 — a first-party extension package
reaches a program the way `nvs/image` does in M9.

**The line against M9.** M9 builds the image component's first wave as the extension system's proof, and
keeps it. This milestone is everything [0120](../decisions/0120.md), [0121](../decisions/0121.md),
[0123](../decisions/0123.md) and [0128](../decisions/0128.md) placed and contracted but left unscheduled:
three parts, independent of each other once M9 is done, each large enough to be one or more goals of its
own when it is scheduled.

**Part 1 — the image component's second wave.** SVG and PDF join
`rule:core-classes/image-format-roster` decode only, through `resvg` and `hayro`, with `Format` gaining
its cases and no new entry point (`rule:packaging/pdf-decoding-ships-in-the-image-package`).
`rule:core-classes/pdf-page-is-an-image-source` and `rule:core-classes/pdf-decode-refusals` are the PDF
contract. Two prerequisites gate linking `hayro`, per 0128 § 4: it builds for the component's `wasm32`
target, and its dependency tree passes `deny.toml`. If either fails, the fallback is pdfium compiled to
wasm, never a host dependency. Complex text shaping (`rustybuzz`) for `text(...)`, which the first wave
leaves at Latin script, lands here too.

**Part 2 — `nvs/pdf`.** HTML plus a CSS subset plus inline SVG to PDF, under `Novis\Pdf`, with no I/O
(`rule:core-classes/pdf-render-has-no-io` through `rule:core-classes/pdf-output-is-inert`). There is no
engine to link: the work is a **pagination layer** — page boxes, fragmentation, page breaks, running
headers and footers, page counters — over the pure-Rust crates 0121's *Context* lists, with `html5ever`
shared with `Core\Html` (`rule:core-classes/html-parsing`). That layer is this milestone's largest item.
It also owes what 0121 left to the building milestone: the builder's API and the component's entry
points, the exact CSS subset, and the embedded default font set. The opt-in fidelity backend behind
`rule:core-classes/pdf-one-engine`'s interface is not part of the acceptance; it can follow once the
interface is fixed.

**Part 3 — `nvs/spreadsheet`.** Reading and writing under one registered class, with formula injection
closed by type (`rule:core-classes/spreadsheet-has-no-io` through
`rule:core-classes/spreadsheet-output-is-inert`). The roster is
`rule:core-classes/spreadsheet-evaluation-and-roster`'s first wave: xlsx reads and writes at parity,
xlsm reads data only, the binary and legacy formats read, ods reads, and template fill is named. The write
path offers the bounded-memory streaming mode `rule:core-classes/spreadsheet-bulk-boundary` requires. Owed
here per 0123: the builder's API, the cell cap's knob, default and config block, and the PhpSpreadsheet
concept-mapping table. Writing ods and the explicit evaluate call are that rule's second wave; the
evaluate call waits on IronCalc 1.0 (0123 *Revisiting*) and is outside this acceptance.

**Verify:** the *Verification* lists of [0128](../decisions/0128.md), [0121](../decisions/0121.md) and
[0123](../decisions/0123.md) are the fixture lists, one per part, each fixture asserting inside the guest.
Beyond those: each component builds on all three platforms and runs from one binary, and each package's
manifest requests no capability. A render benchmark — one invoice, one long report — is committed beside
M9's figures, and a million-row streaming export is measured with peak memory proportional to rows in
flight rather than rows total.
