# M6 — Config, limits, capabilities, disk cache (~3 weeks)

**Carried by goal `governance`.** Every capability-bearing `Core` member goal `core-part-ii` lands is gated on what this milestone
builds, so it runs before them rather than after, and [goal `governance`](../agent/goals/governance.md) is the loop
goal that lands it. The control socket is
[goal `m7-server-surface`](../agent/goals/m7-server-surface.md)'s, over the listener goal `server`
shipped — see § *Also here: the config snapshot* below, which already said so.

Directive registry with changeability classes, boot config parsing (TOML via `serde`, with duplicate and
unknown keys refused — `rule:config/the-file-is-nvs-toml-and-it-is-toml`; § 2a there is the block list and
names the ADR that argues each block's directives, including this milestone's new `[deferred]`,
`[[schedule]]`, `[http.*]`, `[metrics]` and `[trace]`), per-request overlay,
`Core\Config::set` semantics, capability enforcement at every syscall-touching stdlib entry point, safepoint-driven limit
enforcement, content-addressed artifact cache with integrity verification and a refusal to use a
world-writable cache directory — the exact file layout, header format, mmap-verify-then-execute read path
and probabilistic eviction sweep are already decided in `rule:packaging/an-artifact-is-one-immutable-content-addressed-file`;
this milestone builds exactly what that ADR specifies, not a fresh design. Isolates get their governance here: the `script.spawn` capability with
canonicalise-then-prefix path resolution, `max_script_depth`, per-tree accounting of every `[limits]` value,
spawn-site sub-caps, and derivation of a child's overlay from its parent's effective config. **Also here:**
the `fatal_reserve_memory`/`fatal_reserve_time` directives and `Core\Fatal::onLimit` registration
(`rule:errors/escalation-ladder`) — the reserved slice a resource-limit `FATAL`'s handler
runs with is carved out of the request's own budget at the same point these limits are set up.

**Also here: `nvs build --compile`**, a CLI-only "one portable executable" bundler — appends an entry file's
statically-resolved `require` graph to the host `nvs` binary as plain source, read back through this same
artifact cache with no new mechanism. Scope, the source-not-precompiled-artifacts trade, and why bundling a
web-serving deployment is explicitly out of scope are all in
`rule:packaging/nvs-build-compile-appends-the-program-to-a-copy-of-the-host`, the only copy of the reasoning.

**Also here: the boot-time validation the four new blocks owe**, each ADR's own *Verification* section
being the one home for its list — a `[[schedule]]` entry with no `scope`, a malformed `cron`, a `script`
outside `script.spawn`'s roots or `scope = "fleet"` with no shared store all refuse to boot
(`rule:config/scheduled-work-is-a-config-block`); `origins = ["*"]` with `credentials = true`, and
`same_site = "None"` with `secure = false`, are refused at boot and by `Core\Config::set` alike
(`rule:http-server/an-unsafe-or-unbounded-default-is-a-defect`).

**Also here: the config snapshot and the registry's reloadability field.** The registry becomes an immutable
`Arc<Config>` a request clones at start and reads for its whole life, and every directive gains a
`Reload`/`Boot` field beside its changeability class — orthogonal to it, and now the only thing that makes a
directive boot-only (`rule:config/the-config-is-an-immutable-snapshot` and `rule:config/reloadability-is-its-own-field`). `env_hash` lands here
too, carried by both compiled-unit cache keys, which is what stops an artifact compiled against one
extension set from ever being reused against another. No socket here: the client that drives a reload needs
a long-running server, so it is [goal `m7-server-surface`](../agent/goals/m7-server-surface.md)'s, over
M7's listener.

**Also here: the configuration is a tree, and per-application blocks exist.** The boot path resolves a root
named by repeatable `--config` or found as `./nvs.toml`, walks `[[include]]` by `path` and by `dir`, merges
the result as one ordered stream where later wins, and refuses any file in it that another account can
write — the ownership check being what makes an `optional` include safe, and what makes every file in the
tree equally trusted (`rule:config/the-root-is-config-else-nvs-toml-else-the-shipped-defaults`, the only copy of the
resolution order, the merge rules, the `password_file` indirection, the closed flag list and the
`nvs config check`/`dump` verbs; `nvs ctl config` is goal `m7-server-surface`'s, over M7's socket).
`rule:config/an-application-is-its-entry-file-path` lands with it: `[[app]]` keyed on a
canonicalized entry-file path, which is what finally gives `nvs run` the per-application limits, grants and
mode that `rule:config/three-changeability-classes` has assumed since it was written.

**Verify:** adversarial suite — a script attempting to widen a capability or set a `System` directive
fails; `Core\Config::set('memory', '512M')` above the `[limits]` default succeeds and takes effect, above the
`[limits.hard]` ceiling returns `false` with the previous value intact, and is invisible to the next request
on the same core; memory/CPU caps terminate runaway scripts as a `FATAL`, reported to `Core\Fatal::onLimit`
if registered and never to an ordinary `catch` (`rule:errors/escalation-ladder`); warm-cache
CLI startup under 10 ms; a tampered cache artifact is rejected. For isolates: `spawn script` without `script.spawn`
fails; a path outside the granted roots fails, including one reaching it through `..` or a symlink; a child
cannot widen a capability its parent narrowed; N concurrent isolates cannot together exceed the tree's
memory, CPU or output budget; a recursive spawn is stopped by `max_script_depth` and reported as that rather
than as an out-of-memory. For the bundler: a bundled executable runs identically to `nvs run` against the
same source, on all three platforms, per `rule:packaging/nvs-build-compile-appends-the-program-to-a-copy-of-the-host`'s own verification list. For the config snapshot: a request
that started before a swap reads the old value to completion while one started after reads the new; a
malformed file leaves the previous snapshot serving and names the offending line; a changed `Boot` key is
reported in the result and does not take effect. For the config tree and the per-app block, each ADR's own
*Verification* section is the list — a group-writable file or directory refuses the boot, an `[[include]]`
cycle is refused with the chain named, `optional` covers absence and not unreadability, a key set in two
files resolves to the later one with both origins reported while a key set twice in one file still refuses,
a value array replaces where a `[[table]]` appends, `password_file` yields the file's content with one
trailing newline stripped, and an entry path reaching an `[[app]]` root through `..` or a symlink does not
match it.
