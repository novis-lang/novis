# M2 — HIR, types, IR (~4 weeks)

Name resolution: namespace/`use` scoping, class hierarchy resolution — no trait flattening, since traits do
not exist; instead, default-method/private-method visibility and `by`-delegation type-matching
(`rule:classes/no-traits`; this replaces
`crates/nvs-hir`'s already-written `hierarchy.rs` trait-use/`insteadof` resolution, per that ADR's
*Consequences*) — statically resolved `require` with a dynamic fallback
(`rule:statements/require-is-the-only-inclusion-construct`), `autoload`-declared name-to-file resolution as a
fixpoint over that same require-graph worklist
(`rule:programs/no-runtime-autoload`), every callable/constant resolved as a class
member with no bare-name fallback (`rule:classes/no-free-functions-or-constants`),
`type`-alias substitution (`rule:statements/nothing-gets-a-second-name`), and property-access resolution with
no `__get`/`__set` fallback (`rule:classes/property-observer`).

Type checker (`rule:types/declaration`): declared types enforced, definite assignment
(locals, and per `rule:classes/definite-property-initialization` every constructor-declared
property), flow-sensitive union narrowing, array element types checked at every depth, the arithmetic
result-type table. No inference engine and no `Unknown` type — that's the simplification the mandatory
declarations buy. Also enforced here: `Comparable`-gated object ordering
(`rule:classes/comparable`); `tainted` poisoning/laundering
(`rule:security/tainted-qualifier`) and, independently, `secret`
(`rule:security/secret-qualifier`); `callable` accepted only from
a method reference or an anonymous function, no `__invoke`
(`rule:types/callable-values`, `rule:types/anonymous-function`);
`Stringable`-gated string conversion and `unset()` refused on a declared property
(`rule:classes/no-magic-methods`); identifier casing
(`rule:core-api/identifier-casing`/[0030](../decisions/0030.md),
lands in `nvs-syntax` directly since it needs no name resolution); `object` subtyping and shape-type
structural checking (`rule:types/object-top`); `foreach` accepted over exactly an
`array<T>`, an `Iterable<T>` or an `Iterator<T>`, with `$obj[$k]` on a non-array refused
(`rule:iteration/two-interfaces`); and `decimal`'s conversion and arithmetic rows,
including `decimal + float` refused on the same grounds as `int + uint`
(`rule:types/decimal`, whose literals are target-typed with no suffix, so `as T`
must place one); and the nullable target form `as ?T`, which needs no parser work and reuses § 6's `?T`
narrowing, refusing the conversions that cannot fail or do not exist
(`rule:expressions/nullable-conversion`).

**Re-opened here by `rule:expressions/one-equality-operator`:** an
equality whose two operand types are **disjoint** is a compile error (`E0466`), over that rule § 2's table
and including § 6's `switch` labels and `match` arms, which reach the same check through
`reject_disjoint_equality` (`crates/nvs-types/src/locals.rs:1230`). Its § 3 also moves § 6's null-test
narrowing from `=== null`/`!== null` to the one remaining spelling. The lowering half — the null tag test and a helper each for the string, array and object rows —
is M3/M4's, and `nvs-ir`'s own gap list owns it.

Lowering to a CFG/SSA IR carrying explicit safepoints, refcount operations and runtime-helper calls, with a
stable per-statement/per-edge id reserved for
`rule:testing/debug-probes`'s probes — cheap now,
expensive to retrofit once M3 builds on the IR without it. The IR must also be able to represent a
**suspension point inside a loop body**, which is what `rule:iteration/two-interfaces`'s
state-machine lowering of a generator was added on top of without reshaping it — that transform is
`crates/nvs-ir/src/lower/generator.rs`, and it cost the shape here nothing, exactly as with the probe ids.

**Verify:** every diagnostic the rules above name is raised by a test. The corpus is
`tests/conformance/reject/`, one `.nvst` case per refused behaviour with the full rendered error, plus
the checker's own Rust tests, which name a code by its `code::E_*` constant. It includes
`rule:types/declaration`'s core entries (undeclared/redeclared local, read-before-definite-assignment,
`int + uint`, array element-type violations at depth, a missing vs. present narrowing). Plus IR snapshot
tests in `crates/nvs-ir/src/lower/tests.rs`; no program produces an `Unknown` type, since the IR has
none.
