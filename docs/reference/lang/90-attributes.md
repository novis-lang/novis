# An attribute is an anonymous object attached to a declaration

An attribute is an anonymous object attached to a declaration. You write it as `#[...]` in front of
the declaration. A class, an interface, an enum, a method, a property, a class constant and a
parameter can each carry one.

Inside the brackets you write named values, as in `#[Route(path: "/users")]`. The name in front of the
brackets must be a `type` alias for a shape, and Novis checks your values against that shape. An
alias declared inside a class, an interface or an enum is written with its owner, as in
`#[Job::Meta(...)]`, the same way as in a type. An attribute is not a class. Novis creates nothing
for it, and none of your code runs for it.

Every value must be known while the program is compiled: a number, a string, `true`, `null`, a list, a
class constant or an enum case. A variable or a function call there does not compile.

**Good to know:** `#` on its own starts a comment. Only `#[` starts an attribute.

The name in front of the brackets is checked first. A name that nothing declares is `E0303`. A class,
or a `type` alias for something that is not a shape, such as `type Id = int;`, is `E0726`.

Your values are then checked against the shape. A missing field or a value of the wrong type is
`E0401`, and the help line names the missing field. Fields the shape does not have are allowed.
`#[Name]` with no brackets has no fields, so it is `E0401` for a shape that has any.

Each value needs its field name. `#[Tag(5)]` is a syntax error, and the same field written twice is
`E0494`.

A value may be a number (also a negative one), a string, `true`, `false` or `null`. It may also be an
anonymous object, an array, a class constant, an enum case or `Foo::class`. A variable, a call, `new`, arithmetic such as
`1 + 2` and a string with `{$name}` in it are each `E0725`. A class constant that is `secret` is
`E0727`.

An array in an attribute has the type `array<mixed>`. A field typed `array<mixed>` takes it. A field
typed `array<int>` or `array<string>` does not, and the attribute is `E0401`.

An attribute may also stand in front of an enum case and a property hook. In front of a statement or
a local variable, it is `E0101`.

You can write an attribute on an enum, an enum case or a class constant, and the program compiles.
`Core\Attributes` cannot read it back, because only a class, an interface, a method, a property and a
parameter have a way to name them.

An attribute may have no name, as in `#[{ inject: "repo" }]`. Nothing checks its fields.

Several attributes can share one bracket, with commas between them: `#[A(n: 1), B(s: "x")]`. This is
the same as writing each one in its own bracket.

You can write the same attribute any number of times on one declaration. Novis keeps every copy, in
the order you wrote them.

## Example 01: label a class and read it back

```nvs
<?nvs
// Shows how to attach information to a class and read it back. The name in
// front of the brackets is a `type` alias for a shape, and your values are
// checked against that shape.

type Table = { name: string };

#[Table(name: 'users')]
class User
{
    public string $email = '';
}

// `Core\Attributes::get` returns the values attached to the class, or `null`
// when the class carries none. `User::constructor(...)` names the class itself.
?Table $table = Core\Attributes::get<Table>(User::constructor(...));
if ($table != null) {
    // This prints `users`.
    echo $table->name, "\n";
}

// A class with no attribute on it. The result is `null`.
class Session
{}

?Table $none = Core\Attributes::get<Table>(Session::constructor(...));
echo $none == null ? "no table name\n" : "a table name\n";
```

```output
users
no table name
```

## Example 02: several attributes on one declaration

```nvs
<?nvs
// Shows several attributes on one declaration, and the two ways to write one.
// `#[Name(...)]` checks your values against the shape `Name`. `#[{...}]` has no
// name in front of it, so there is nothing to check it against.

type Tag = { label: string };

#[Tag(label: 'billing')]
#[Tag(label: 'nightly')]
class Invoice
{
    #[Tag(label: 'money')]
    public int $cents = 0;

    public function send(#[{ from: 'config' }] string $to): string
    {
        return $to;
    }
}

// `Core\Attributes::all` returns every attached value that fits the shape, in
// the order you wrote them. This prints 2, `billing` and `nightly`.
array<Tag> $tags = Core\Attributes::all<Tag>(Invoice::constructor(...));
echo Core\Arr::count($tags), "\n";
foreach ($tags as Tag $tag) {
    echo $tag->label, "\n";
}

// A property and a parameter can carry an attribute too. The second argument is
// the name of the property or the parameter. This prints `money`.
?Tag $onProperty = Core\Attributes::get<Tag>(Invoice::constructor(...), 'cents');
if ($onProperty != null) {
    echo $onProperty->label, "\n";
}

// The attribute on the parameter `$to` was written without a name. You read it
// back by writing the shape you expect. This prints `config`.
?{ from: string } $onParameter = Core\Attributes::get<{ from: string }>(Invoice::send(...), 'to');
if ($onParameter != null) {
    echo $onParameter->from, "\n";
}
```

```output
2
billing
nightly
money
config
```

## Example 03: a schedule read from the job classes

```nvs
<?nvs
// A nightly schedule that reads itself from the job classes. Each class says
// how often it runs, so adding a job means writing one class. There is no
// second list to keep up to date.

class Every
{
    public const int HOUR = 60;
    public const int QUARTER_HOUR = 15;
}

// The enum and the shape are declared inside the interface every job implements.
// Outside the interface, you write them as `Job::Level` and `Job::Meta`.
interface Job
{
    enum Level: int
    {
        Normal = 1,
        Urgent = 2,
    }

    type Meta = { name: string, everyMinutes: int, level: Level };
}

// A class constant and an enum case are both allowed in an attribute, because
// their values are known while the program is compiled.
#[Job::Meta(name: 'send invoices', everyMinutes: Every::HOUR, level: Job::Level::Normal)]
class SendInvoices implements Job
{
    public static function run(): string
    {
        return '12 invoices sent';
    }
}

#[Job::Meta(name: 'clean sessions', everyMinutes: Every::QUARTER_HOUR, level: Job::Level::Normal)]
class CleanSessions implements Job
{
    public static function run(): string
    {
        return '84 sessions removed';
    }
}

#[Job::Meta(name: 'charge cards', everyMinutes: Every::HOUR, level: Job::Level::Urgent)]
class ChargeCards implements Job
{
    public static function run(): string
    {
        return '3 cards charged';
    }
}

array<Job::Meta> $schedule = [];
$schedule[] = Core\Attributes::get<Job::Meta>(SendInvoices::constructor(...)) ?? throw new RuntimeError('no job');
$schedule[] = Core\Attributes::get<Job::Meta>(CleanSessions::constructor(...)) ?? throw new RuntimeError('no job');
$schedule[] = Core\Attributes::get<Job::Meta>(ChargeCards::constructor(...)) ?? throw new RuntimeError('no job');

foreach ($schedule as Job::Meta $job) {
    string $mark = $job->level == Job::Level::Urgent ? ' (urgent)' : '';
    echo $job->name, ': every ', $job->everyMinutes as string, ' minutes', $mark, "\n";
}
```

```output
send invoices: every 60 minutes
clean sessions: every 15 minutes
charge cards: every 60 minutes (urgent)
```

# Reading attributes back: `Core\Attributes::get` and `all`

`Core\Attributes::get` and `Core\Attributes::all` read the attributes attached to a declaration. `get`
returns the one attribute that matches the shape you write, or `null` when nothing matches. `all`
returns every match, in the order the attributes are written, and an empty list when nothing matches.

You name the declaration with a method reference: `Users::show(...)` for a method, and
`Users::constructor(...)` for the class itself. A second argument names one property or one parameter of
that declaration, and you then get the attributes on that one. This name must be written out. If you
write a variable there, the result is `null` or an empty list.

Matching is by shape and not by name. An attribute with more fields than the shape you write still
matches, so `{ name: string }` matches `#[Tag(name: "alpha", weight: 3)]`.

Novis does all of this while it compiles your program. The call is replaced by the value it found, so
there is no lookup while the program runs.

`get` with two matching attributes is `E0728`. `all` has no such limit.

The type between `<` and `>` must be a shape, written out as `{ label: string }` or as a `type` alias
for one. `get<int>` is `E0729`, and `get` with no type is `E0442`.

Every class has a constructor, even when you do not write one. So `Users::constructor(...)` always
names the class.

The first argument must be a method reference written in the call. A variable that contains one is
`E0730`. A method that is `private` is `E0471` outside its class. A static method is named the same
way, as `Orders::show(...)`.

A property or parameter name written in quotes is checked. A name that the class or the method does
not have is `E0798`. For the parameters of the constructor, use `Users::constructor(...)` and the
parameter's name. For a promoted constructor parameter, you get the attributes on the parameter and
on the property together.

A subclass does not get its parent's attributes. `B::constructor(...)` finds nothing when only the
parent class `A` has the attribute. `B::show(...)` also finds nothing when `show` is declared in `A`,
even if `B` does not override it. An interface method's attributes are read with `I::m(...)`.

`all<{}>` returns every attribute on the declaration, also the attributes Novis reads itself, such as
`#[Core\Json\Derive]`.

A class constant, an enum case or `Foo::class` in an attribute is read back as its value. The value
comes from the place where the attribute is written. In a file with `namespace Shop;`, `K::class` is
read back as `"Shop\K"`. A class constant whose own value is another class's constant is `E0792` in
an attribute. When `get` or `all` matches that attribute, the call is `E0731` too.

Each call gives a new copy of the value. A change to the copy does not change what the next call
returns.

## Example 01: read every attribute with all

```nvs
<?nvs
// Shows how to read every attribute attached to one declaration.
// `Core\Attributes::all` returns them in the order they are written.

type Tag = { name: string };

class Article
{
    #[Tag(name: 'news')]
    #[Tag(name: 'sport')]
    #[Tag(name: 'local')]
    public function publish(): int
    {
        return 1;
    }

    public function archive(): int
    {
        return 2;
    }
}

// This prints `news`, `sport` and `local`, one per line, in that order.
array<Tag> $tags = Core\Attributes::all<Tag>(Article::publish(...));
foreach ($tags as Tag $tag) {
    echo $tag->name, "\n";
}

// `archive` carries no attribute. The result is an empty list, so this prints 0.
array<Tag> $none = Core\Attributes::all<Tag>(Article::archive(...));
echo Core\Arr::count($none), "\n";
```

```output
news
sport
local
0
```

## Example 02: read an attribute on a property or a parameter

```nvs
<?nvs
// Shows the second argument of `Core\Attributes::get`. It names one property
// or one parameter, and you then get the attributes on that one.

type Column = { name: string };
type Range = { min: int, max: int };

class Product
{
    #[Column(name: 'product_title')]
    public string $title = '';

    public function discount(#[Range(min: 0, max: 90)] int $percent): int
    {
        return $percent;
    }
}

// A property of a class. `Product::constructor(...)` names the class, and
// `"title"` names the property. This prints `product_title`.
?Column $column = Core\Attributes::get<Column>(Product::constructor(...), 'title');
if ($column != null) {
    echo $column->name, "\n";
}

// A parameter of a method. `Product::discount(...)` names the method, and
// `"percent"` names the parameter. This prints `0 to 90`.
?Range $range = Core\Attributes::get<Range>(Product::discount(...), 'percent');
if ($range != null) {
    echo $range->min, ' to ', $range->max, "\n";
}

// The name must be written out, as it is above. If you write a variable there,
// the result is `null`.
string $field = 'title';
?Column $computed = Core\Attributes::get<Column>(Product::constructor(...), $field);
echo $computed == null ? "null\n" : "a column name\n";
```

```output
0 to 90
null
```

## Example 03: a permission check built from the methods

```nvs
<?nvs
// A permission check that reads itself from the methods. Each method says
// which permission it needs, so adding a method means writing one attribute.
// There is no second list to keep up to date.

type Requires = { permission: string };

class Orders
{
    // This attribute has one field more than `Requires`. Matching is by shape,
    // so it still matches.
    #[{ permission: 'orders.read', audit: true }]
    public static function show(): string
    {
        return 'order 1042';
    }

    #[Requires(permission: 'orders.write')]
    public static function cancel(): string
    {
        return 'order 1042 cancelled';
    }

    public static function ping(): string
    {
        return 'ok';
    }
}

class Access
{
    public static function check(string $action, ?Requires $needs, array<string> $granted): string
    {
        if ($needs == null) {
            return $action . ': open to everyone';
        }
        if (Core\Arr::contains($granted, $needs->permission)) {
            return $action . ': allowed';
        }
        return $action . ': needs ' . $needs->permission;
    }
}

array<string> $granted = ['orders.read'];

// This prints one line per action: `show` is allowed, `cancel` needs a
// permission this user does not have, and `ping` needs none at all.
echo Access::check('show', Core\Attributes::get<Requires>(Orders::show(...)), $granted), "\n";
echo Access::check('cancel', Core\Attributes::get<Requires>(Orders::cancel(...)), $granted), "\n";
echo Access::check('ping', Core\Attributes::get<Requires>(Orders::ping(...)), $granted), "\n";
```

```output
show: allowed
cancel: needs orders.write
ping: open to everyone
```

# The names the compiler acts on

Most attributes are metadata. Novis stores what you attach and your program reads it back, and nothing
else happens. A small set of names is different. Novis owns those names, and when an attribute points
to one of them the compiler acts on it: it writes a JSON codec for the class, adds a row to the route
table, adds a row to the command table, or registers a test.

Novis decides by the declaration a name points to, not by the way the name is written. `#[Core\Command]`
and an imported `#[Command]` are one attribute. A type of your own called `Command` is a different
declaration, so it stays ordinary metadata however it is spelled. An import binds one whole name, so
`use Core\Json;` followed by `#[Json\Derive]` points at nothing and does not compile.

Each name Novis owns has a fixed list of options. An option it does not know, an option of the wrong
type, and an option given twice are each an error while your program compiles.

The examples show one attribute written both ways, an attribute of your own that shares a name with one
of these, and a class that carries both kinds at once.

An option the attribute does not have is `E0454`, and the help line lists every option with its
type. An option of the wrong type is `E0401`, and an option given twice is `E0304`. A value that is
not known while compiling is `E0725`, as in any attribute. A missing option that the attribute needs
has an error of its own, such as `E0767` for a `#[Core\Command]` with no `name`.

A name under `Core\` that Novis does not read, such as `#[Core\Nope]`, is `E0726`. These names are
never written with `::`, so `#[Core\Json::Derive]` is `E0405`. An import cannot be renamed, so
`use Core\Command as Cmd;` is `E0212`.

Novis does not read an attribute without a name. `#[{ name: "deploy", about: "…" }]` is ordinary
metadata, even when its fields are the same as a `Core\Command`.

Your code can still read these attributes with `Core\Attributes`. For example,
`Core\Attributes::get<{ path: string }>(Home::show(...))` returns the `path` of a `#[Core\Route]`.

Each of these attributes belongs on one kind of declaration. A `#[Core\Command]` belongs on a
`static` method, and on a method that is not `static` it is `E0789`.

## Example 01: one attribute written two ways

```nvs
<?nvs
// Shows the two ways to write one of the attributes Novis owns. Novis reads the
// name after it works out which declaration it points to. `#[Core\Command]` and
// an imported `#[Command]` point to the same declaration, so both methods below
// are commands.

use Core\Command;

type Row = { name: string, about: string };

class Jobs
{
    #[Core\Command(name: 'import', about: 'Read rows from a file')]
    public static function import(): void
    {}

    // The `use Core\Command;` above makes this short spelling the same attribute.
    #[Command(name: 'export', about: 'Write rows to a file')]
    public static function export(): void
    {}
}

class Help
{
    public static function line(?Row $row): string
    {
        if ($row == null) {
            return '(no command here)';
        }
        return $row->name . ': ' . $row->about;
    }
}

// This prints one line per command.
echo Help::line(Core\Attributes::get<Row>(Jobs::import(...))), "\n";
echo Help::line(Core\Attributes::get<Row>(Jobs::export(...))), "\n";
```

```output
import: Read rows from a file
export: Write rows to a file
```

# `#[Core\Json\Derive]` and `#[Core\Json\Field]`: a class with a JSON codec

`#[Core\Json\Derive]` on a class gives it a JSON encoder and a JSON decoder. `Core\Json::encode` then
accepts instances of that class, and `Core\Json::decodeAs` builds one from JSON text. A class without
the attribute is not allowed at either call.

The fields of the document are the class's declared properties, in the order they are written. Each
of these properties is also a constructor parameter of the same name and type, because a decode calls your
constructor. `#[Core\Json\Field]` changes one property. `name:` writes it under a different key, and
`skip: true` leaves it out of the document.

A decode checks the whole document before it builds anything. If a field is missing, has the wrong
type, or is `null` where that is not allowed, the decode throws a `ParseError`. The error lists every
bad field at once.

The examples show a class encoded as JSON, a renamed key and a skipped property, and a request body
read into an object. Then they show each check of a decode, a property with no constructor parameter,
and an enum and an array in a decode.

The document has one key for each instance property that the class itself declares. A `private` or
`protected` property has a key too. A property promoted in the `constructor` has its key in the place
where it is written. A `static` property has no key, and neither does a property the class inherits.
A `readonly` property has a key. A class with no such property is `E0758`.

A property may be a number, a `string`, a `bool`, an enum, an inline shape, an `array<T>` of these, or
`?T` of these. It may also be another class with `#[Core\Json\Derive]`. A class without the attribute
is `E0756`. An enum case is written in JSON as its number. A `float` is written with a fraction, so
`2` in a `float` property encodes as `2.0`.

A `secret` property is decoded like any other property. Encoding its class does not compile, and is
`E0462`. A `lateinit` property is `E0463`. `#[Core\Json\Field(skip: true)]` leaves either one out. A property with no constructor parameter of the same name is
`E0460`. A parameter of another type is `E0461`. `#[Core\Json\Field]` has the options `name` and
`skip` only, and any other option is `E0464`. `skip: false` is the same as no `skip`.

A constructor parameter that does not match a property in the document is `E0820` at the `Core\Json::decodeAs` call. This is
true even when the parameter has a default value. `Core\Json::decodeAs` on a class without the
attribute does not compile, and is `E0821`. `Core\Json::encode` of such an object throws a
`LogicError` when it runs.

A `?T` property that is `null` is written as `null`. It is never left out of the document. A `?T`
property is always required in a decode too. A missing key is the issue `required field missing`, as
for any other property. Only its value may be `null`.

A key in the document that the class does not have is ignored.

The `ParseError` has every problem in its `issues`. Each issue has a `path` and a `message`.

A decode checks each value's type and does not convert it. `1.5` and `2.0` in an `int` property are
issues, and so is `-1` in a `uint` property. A number in a `string` or `bool` property is an issue,
and so is a string in a `float` property. An `int` in a `float` property is accepted. An enum
property takes the
number of a case. Any other number, or a string, is the issue `expected a declared enum case`.

The path of an issue joins the keys with `.`. A field of a nested object is `address.city`, and an
array element ends with its index, as `tags.1`. `Core\Json::decodeAs<array<User>>` decodes a list,
and its paths start with the index, as `1.address.city`.

Text that is not valid JSON gives one issue with an empty path. Its message names the line and the
column. A document that is a number, a string or `null` also gives one issue with an empty path.
Its message says that the class decodes from a JSON object.

The decode calls your constructor after the checks pass. An error the constructor throws reaches
your code unchanged.

## Example 01: give a class a json codec

```nvs
<?nvs
// Shows how to turn an object into JSON text. `#[Core\Json\Derive]` on a class
// gives it an encoder, so `Core\Json::encode` accepts its instances.

use Core\Json;

#[Core\Json\Derive]
class Point
{
    public int $x;
    public int $y;

    // Every property is a constructor parameter of the same name and type.
    public function constructor(int $x, int $y)
    {
        $this->x = $x;
        $this->y = $y;
    }
}

// The keys are the declared properties, in the order they are written.
// This prints {"x":3,"y":4}.
echo Json::encode(new Point(3, 4)), "\n";

#[Core\Json\Derive]
class Line
{
    public Point $from;
    public Point $to;

    public function constructor(Point $from, Point $to)
    {
        $this->from = $from;
        $this->to = $to;
    }
}

// A property whose type is another class with the attribute is encoded inside the
// same document. This prints {"from":{"x":0,"y":0},"to":{"x":3,"y":4}}.
echo Json::encode(new Line(new Point(0, 0), new Point(3, 4))), "\n";
```

```output
{"x":3,"y":4}
{"from":{"x":0,"y":0},"to":{"x":3,"y":4}}
```

```nvs
<?nvs

use Core\Json\Field;

#[Core\Json\Derive]

    // in the document.
```

```nvs
<?nvs

// checks the whole document and then calls the class constructor. A bad document
// throws a `ParseError` that lists every bad field at once.

use Core\Json;
use Core\Json\Field;

#[Core\Json\Derive]
class Address
{
    public string $city;

    public function constructor(string $city)
    {
        $this->city = $city;
    }
}

#[Core\Json\Derive]
class Signup
{
    public string $email;
    public uint $age;
    #[Field(name: 'accepts_mail')]
    public bool $acceptsMail;
    public Address $address;

    public function constructor(string $email, uint $age, bool $acceptsMail, Address $address)
    {
        $this->email = $email;
        $this->age = $age;
        $this->acceptsMail = $acceptsMail;
        $this->address = $address;
    }
}

string $body = "{\"email\":\"ada@example.com\",\"age\":36,\"accepts_mail\":true,"
    . "\"address\":{\"city\":\"london\"},\"sent_at\":\"today\"}";

// This prints `ada@example.com lives in london`.

}
```

# `#[Core\Route]` and `#[Core\Access]`: the route table

`#[Core\Route]` on a method gives it a path and an HTTP method. `#[Core\Access]` says who may
use it. A route needs both.

A path has fixed segments and captures. `{id}` matches one segment. `{id?}` matches one segment or
none, and must come last. `{path...}` matches all remaining segments. Each capture goes to
the parameter with the same name, converted to its type.

Novis collects every route into one table at compile time. `Core\Router::url` builds a
link from the name of a route. An unknown route name or a missing capture is a compile error.

The server matches each request to a route before your program runs. Your entry file calls
`Core\Router::dispatch`, which calls that route's method. A program can also read the match with
`Core\Request::route()`.

A parameter with `#[Core\Query]` gets its value from the query string, converted to its type. A
parameter with a default value makes its key optional. If the key is missing, the parameter has the
default value. A value that does not convert, a missing key with no default and a key sent twice are
each a `400`. The route method does not run.

**The examples below** show a route and its link, the three captures, product list links, routes in
another file, calling a route method yourself, a route with no `#[Core\Access]`, which does not
compile, and a query parameter with a bad value.

A path must start with `/`, or it is `E0750`. A `{name?}` or `{name...}` capture that is not the last
segment is `E0750` too. A route with no `method:` is `E0747`, and a `method:` that is not a case of
`Core\Http\Method` is `E0401`. A route with no `name:` still matches a request. Its `name()` is
`null`, and `Core\Router::url` cannot build a link to it.

Two routes with the same path and the same HTTP method are `E0748`. This is true when they are in two
classes, and when their captures only have different names, such as `/users/{id}` and
`/users/{key}`. Two routes with one name are `E0749`. One method with several `#[Core\Route]` lines
may give them all the same name when they all have the same path.

A capture parameter may be a `string`, `int`, `uint`, `decimal`, `bool` or an enum. It may also be a
set of allowed values such as `"en"|"de"`, or a class that implements `Parses`.

A capture with no parameter of the same name is `E0751`. A `float` parameter is `E0752`, and so is a
`{name...}` parameter that is not a `string`. A `{name?}` parameter with no default value is `E0753`.
A `#[Core\Query]` parameter takes the same types as a capture, so a `?string` one is `E0752`.
`#[Core\Query]` on a method with no route is `E0765`.

`Core\Router::dispatch` reads the query string key with the same name as the parameter. A key with
brackets, such as `page[]=1`, is a `400` too. For each `400`, `refused` gets
`Core\Router\Refusal::BadCapture` and the match. A path capture that does not convert is a `404`,
because then no route matches the request.

A route with no `#[Core\Access]` is `E0762`. `#[Core\Access]` on a method with no route is `E0788`.
Two `#[Core\Access]` lines on one method are `E0763`, and one with no `allow:` is `E0760`. The
`allow:` value must be an enum case or a class constant. A number is `E0761`. `csrf: false` on a
method whose routes are all `Head` or `Options` is `E0764`. It is allowed on `Get`, because a
WebSocket upgrade arrives as a `Get`.

A fixed segment is tried before a capture, so `/users/new` matches the route `/users/new` and not
`/users/{id}`. The order of the two routes in the code does not matter.

A fixed segment is compared exactly, so `/U` does not match `/u`. A path with an extra `/` at the
end, such as `/u/`, does not match the route `/u`. An `int` capture matches `-4`, `+4` and `04`. It
does not match a number too large for an `int`. A `uint` capture does not match a negative number.
A `decimal` capture matches `1.50` and not `x`. A `{name...}` capture needs at least one segment, so
`/files` does not match `/files/{path...}`.

An enum capture matches the name of a case exactly, such as `De`, and not `de` or `1`. When every case
of the enum has a written value, the capture matches that value instead. For `enum Lang { En = 3,
De = 7 }`, `/7` matches and `/De` does not.

A capture of a class that implements `Parses` matches any segment. The class's `parse` method runs
when `Core\Router::match` returns the result. If `parse` throws an error, that error comes out of
`Core\Router::match`.

`$match->param("id")` returns `uint|int|null|decimal|tainted string|Core\Uuid|Parses`, so you convert
it with `as`. A `string` capture gives a `tainted string`. A name that is not a capture gives `null`.
`access()` returns the full name of the `allow:` value, such as `Role::Staff` or `Users::ADMIN`.
`accessAs<Core\Audience>()` on a route with `allow: Role::Staff` returns `null`.

`Core\Router::url` with an unknown name is `E0754`. A params array that leaves out a capture is
`E0755`. A key that is neither a capture nor a `#[Core\Query]` parameter is `E0759`. A value outside a
closed set, such as `"fr"` for `"en"|"de"`, is `E0772`. These checks need the name and the array
written directly in the code. A name in a variable throws a `RuntimeError`. A params array in a
variable that leaves out a capture throws a `RuntimeError` too.

The compiler does not check the type of a value. `"x"` for a `uint` capture gives the link `/x`, and
that link does not match the route. A value of a class that implements `Parses` is given as text,
such as `"cup-01"`. An object throws a `RuntimeError`.

A capture value is encoded for one segment, so `x/y?z#` becomes `x%2Fy%3Fz%23`. An empty string gives
an empty segment. A space is `%20` in the path and `+` in the query string, and `&` in a query value is
`%26`. A `{name?}` key that you leave out drops its segment, so the link is `/u`. A `null` value for it
gives `/u/`, and the route matches that link too. A `null` value for a `#[Core\Query]` key leaves
that key out of the query string.

`Core\Router::urlAbsolute` with no `origin` setting throws a `RuntimeError`. An `origin` that ends in
`/` does not give two `/` characters in the link.

## Example 01: declare a route and build a link

```toml file=nvs.toml
# `Core\Router::urlAbsolute` puts this origin in front of a path.
[[app]]
root = "."
origin = "https://example.test"
```

```nvs
<?nvs
// Shows how to declare a route and build a link to it. `#[Core\Route]` gives a
// method a path, and `#[Core\Access]` says who may reach it. Every route needs
// both. `Core\Router::url` builds the link for a route from its name.

class Users
{
    #[Core\Route(path: '/users', method: Core\Http\Method::Get, name: 'Users::index')]
    #[Core\Access(allow: Core\Audience::Public)]
    public function index(): string
    {
        return 'all users';
    }

    // `{id}` is a capture. It fills one segment of the path, and the parameter
    // `$id` says the value there is a whole number.
    #[Core\Route(path: '/users/{id}', method: Core\Http\Method::Get, name: 'Users::show')]
    #[Core\Access(allow: Core\Audience::Public)]
    public function show(uint $id): string
    {
        return 'user ' . $id;
    }
}

// This prints `/users` and then `/users/7`.
echo Core\Router::url('Users::index', []), "\n";
echo Core\Router::url('Users::show', ['id' => 7]), "\n";

// A route method is an ordinary method. You can call it yourself.
echo (new Users())->show(7), "\n";
```

```output
/users
/users/7
user 7
```

```nvs
<?nvs
// Shows the three kinds of capture, and a parameter that comes from the query
// string. The type you declare for a parameter is what its part of the path
// converts to.

class Docs
{
    enum Lang { En, De }

    // `{page?}` matches one segment or none, so `$page` needs a default value.
    // `#[Core\Query]` fills `$q` from the query string instead of the path.
    #[Core\Route(path: '/{lang}/docs/{page?}', method: Core\Http\Method::Get, name: 'docs')]
    #[Core\Access(allow: Core\Audience::Public)]
    public function page(Lang $lang, uint $page = 1, #[Core\Query] string $q = ''): string
    {
        return 'docs';
    }

    // `{path...}` matches everything that is left, the `/` characters included.
    #[Core\Route(path: '/files/{path...}', method: Core\Http\Method::Get, name: 'file')]
    #[Core\Access(allow: Core\Audience::Public)]
    public function file(string $path): string
    {
        return 'file';
    }
}

// A value you leave out drops its segment. This prints `/De/docs`.
echo Core\Router::url('docs', ['lang' => Docs::Lang::De]), "\n";

// A key that is not a capture becomes the query string, and the space in `a b`
// is encoded. This prints `/En/docs/3?q=a+b`.
echo Core\Router::url('docs', ['lang' => Docs::Lang::En, 'page' => 3, 'q' => 'a b']), "\n";

// This prints `/files/a/b%20c.txt`.
echo Core\Router::url('file', ['path' => 'a/b c.txt']), "\n";
```

```output
/En/docs/3?q=a+b
```

## Example 05: call the route method yourself

```toml file=nvs.toml
# `Core\Router::urlAbsolute` puts this origin in front of a path.
[[app]]
root = "."
origin = "https://example.test"
```

```nvs
<?nvs
// Shows how a program finds the route for a request and calls its method
// itself. `Core\Router::match` finds the route for an HTTP method and a path,
// so this example runs without a server.

class Users
{
    #[Core\Route(path: '/users/{id}', method: Core\Http\Method::Get, name: 'Users::show')]
    #[Core\Access(allow: Core\Audience::Public)]
    public function show(uint $id): string
    {
        return 'user ' . $id;
    }

    #[Core\Route(path: '/users', method: Core\Http\Method::Post, name: 'Users::create')]
    #[Core\Access(allow: Core\Audience::Public)]
    public function create(): string
    {
        return 'created';
    }
}

class App
{
    public static function answer(Core\Http\Method $method, string $path): string
    {
        var $match = Core\Router::match($method, $path);

        // `match` returns `null` when no route has this method and path. An empty
        // array from `methodsFor` means the path does not exist.
        if ($match == null) {
            return Core\Router::methodsFor($path) == [] ? '404' : '405';
        }

        // The server does not check the `allow:` value. Your program checks it.
        if ($match->accessAs<Core\Audience>() != Core\Audience::Public) {
            return '403';
        }

        var $users = new Users();
        switch ($match->name()) {
            case 'Users::show':
                return $users->show($match->param('id') as uint);
            case 'Users::create':
                return $users->create();
        }
        return '404';
    }
}

// This prints `user 7`, `created`, `405` and `404`.
echo App::answer(Core\Http\Method::Get, '/users/7'), "\n";
echo App::answer(Core\Http\Method::Post, '/users'), "\n";
echo App::answer(Core\Http\Method::Delete, '/users'), "\n";
echo App::answer(Core\Http\Method::Get, '/nothing'), "\n";
```

```output
user 7
created
405
404
```

# `#[Core\Api]` and the OpenAPI document

`#[Core\Api]` describes a route in the API document that `nvs build --openapi` writes. It goes on a
method that has a `#[Core\Route]`.

Most of the document comes from the code. The path, the parameters, their types and the return type
are read from the route and the method, and the `///` comment above the method gives the summary
and the description. `#[Core\Api]` adds the rest: `tags:` groups the operation, `security:` names
the scheme a client must use, `errors:` lists the error responses, and `example:` shows one answer.

Novis checks each of those against the code when it compiles. A class in `errors:` must exist, and
every key in `example:` must be a property of the return type.

Each name in `security:` must be declared by a `#[Core\Api\Scheme]` on a class of your program. Its
`name:` is the name that `security:` uses, and its `type:` is a case of `Core\Api\SchemeType`, such as
`Http` or `ApiKey`. A name that no scheme declares does not compile.

**The examples below** add one tag, then errors and a security scheme, then a small API with
everything a client generator needs. The last one shows an `example:` that does not compile.

`nvs build --openapi main.nvs` writes the document to standard output and runs nothing. The document's
`info.title` is the file name without `.nvs`, and `info.version` is always `0.0.0`. A program with no
`#[Core\Route]` writes no document. The command prints a message to standard error that says so, and
exits with status 0. A program that does not compile writes no document either.
The command prints the compile errors and exits with status 1.

The paths are sorted by their text, and the operations of one path by their HTTP method. Two builds of
the same file give the same bytes. Each operation's `operationId` is the route's `name:`. When several
routes share one name, each `operationId` gets the method after a dot, such as `hook.post` and
`hook.put`.

The first sentence of the `///` comment is the `summary`. The rest of the comment is the
`description`, and a blank `///` line in it stays a blank line. A comment with no full stop is all
`summary`. A method with no `///` comment has neither.

Each capture is a parameter with `"in": "path"`, and it is always required. Each `#[Core\Query]`
parameter is a parameter with `"in": "query"`. It is required when it has no default value. Each type
has its own schema. An `int` is `integer`, and a `uint` is `integer` with a `minimum` of `0`. A
`decimal` is a `string` with the format `decimal`. An enum lists the names of its cases, and a set of
allowed values such as `'x'|'y'` lists those values.

The `200` response has the schema of the return type when it is `string`, `int`, `uint`, `float`,
`bool` or `decimal`. Every other return type has the empty schema `{}`. This includes a class, an
array, an enum and a `?int`. A `void` method has a `200` response with no content.

`#[Core\Api]` has four fields: `tags`, `security`, `errors` and `example`. Every field is optional,
and `#[Core\Api]` with no list is allowed. Any other field is `E0454`. Each value must be written
directly in the code, so `"a" . "b"` in `tags` is `E0725`. You can write `#[Api(...)]` after `use
Core\Api;`. A `static` route method takes `#[Core\Api]` too.

Each check below gives `E0771` when it fails. `#[Core\Api]` on a method with no `#[Core\Route]` is
not allowed. `tags` and `security` must be arrays, even for one entry, and each entry must be a
string. An `errors` entry needs both `status` and `type`, and `status` must be a number from 100 to
599. `example` must be an anonymous object. When the return type is a class, each key of `example`
must be a property of that class.

A class in `errors` that does not exist is `E0303`. A built-in class such as `RuntimeError` works
too. Each `errors` entry becomes a response under its status, and the response's `description` is the
class name. An empty `tags` array writes no `tags`. Each name in `security` becomes its own entry in
the operation's `security` list, with an empty list of scopes. Each name in `security` must be the
`name` of an `#[Core\Api\Scheme]` on a class of the program. Any other name is `E0886`. Each scheme
`type` needs its own fields: `Http` needs `scheme`, and `ApiKey` needs `in` and `parameter`. The
`example` value is written into the `200` response beside its schema.

# `#[Core\Command]` and `#[Core\Option]`: the command table

`#[Core\Command]` marks a static method as a command for the command line, and `#[Core\Option]` marks
one of its parameters as an option. The compiler collects every command in the program into one table
and checks it.

A command needs a `name:`, which is the word that selects it, and the name is unique across the
program. A parameter is a positional argument unless it carries `#[Core\Option]`, and a `bool` option
is a flag. Every option or positional parameter needs a type that text converts to: `string`, `int`,
`uint`, `decimal`, `bool`, an enum, or a class that implements `Parses`. The method is `static` and
returns `void` or the exit status as a `uint`.

`Core\Command::run()` reads the program's command line and calls the command that the first word
names. You can also read the table yourself with `Core\Attributes::get` and
`Core\Program::implementing`, as the examples below do. The last example shows an option that does
not compile.

`#[Core\Command]` has two fields, `name` and `about`. A command with no `name` is `E0767`, and a
`name` that is not a string is `E0401`. `about` is optional. `#[Core\Option]` has three fields,
`short`, `long` and `about`, and each is optional. Any other field is `E0454`. You can write
`#[Command(...)]` and `#[Option(...)]` after `use Core\Command;` and `use Core\Option;`.

Two commands with one name are `E0768`. This is true when they are in two classes, and when one method
has two `#[Core\Command]` lines with the same name. Two lines with different names on one method give
one command two names, and `Core\Attributes::all` returns both lines.

A method that is not `static` is `E0789`. A return type other than `void` or `uint` is `E0789` too,
and that includes `int`. `#[Core\Option]` on a parameter of a method with no `#[Core\Command]` is
`E0766`.

Each option has a long spelling. It is `--` and the `long` value, or `--` and the parameter's name when
there is no `long`. With `short: "v"`, the option also has the spelling `-v`. Two options of one command
with the same spelling are `E0745`. So `long: "name"` on one parameter and a second parameter called
`$name` are `E0745`. `short: "v"` and `short: "V"` are two different spellings.

An option of a type that text does not convert to is `E0746`. A `?string` option is `E0746` too. A
positional parameter is not checked this way. A positional `float` compiles, and `Core\Command::run`
throws `LogicError` when it reaches that command.

`Core\Command::run` fills the parameters from the words after the command's name. An option may come
before, between or after the positional words. An option with a value is written `--retries 7`. The
form `--retries=7` is not an option. A `bool` option is `true` when it is written and `false` when it
is not, even with the default value `true`. An option with a default value may be left out. An enum
parameter takes the name of a case, written exactly, so `Fast` works and `fast` does not.
`--help` is not an option of its own, so `deploy --help` is a usage error.

# `Core\Program::implementing<I>()`: every class that is an `I`

`Core\Program::implementing<I>()` gives you one object for every class in your program that
implements the interface `I`. Novis works that list out while it compiles your program, so nothing is
registered while it runs and no list of classes is written anywhere. A class joins the list by
implementing the interface.

The array is sorted by the full class name. The order is the same on every machine and never depends
on the file system. An `abstract` class is not in the list, because `new` cannot create one. Every
class in the list needs a constructor that takes no arguments, and what a class needs arrives through
the interface's own methods instead. An interface that no class implements gives an empty array.

The objects are created where the call is, each time it runs, like any other `new`. Two calls give
you two separate sets of objects.

The examples show a list of checks, which classes end up in the list, and one table written in every
format a program knows. The last example is a class whose constructor needs an argument, which does
not compile.

`I` can also be a class. Then the list has every class that extends it, and `I` itself when it is
not `abstract`. An `abstract` base class is a good `I` when the classes share code. A class that
implements an interface which extends `I` is in the list too. The test for each class is the same
as `$object is I`.

`I` must be an interface or a class that your program declares. An enum, a shape, a scalar,
`mixed` and `object` are `E0743`. A built-in interface or class, such as `Stringable` or
`RuntimeError`, is `E0743` as well. A name that nothing declares is `E0303`.

The call takes exactly one type argument, so `implementing()` and `implementing<I, J>()` are
`E0442`. It takes no value argument, so `implementing<I>(1)` is `E0402`.

A class whose constructor has a parameter without a default is `E0744`, and the message names the
class. A constructor whose parameters all have defaults is allowed, and each parameter gets its
default. To pass arguments to the constructors, use `Core\Program::constructors` instead.

The result is an `array<I>`. Storing it in an `array<J>` of another type is `E0401`, and `var`
gives the variable the type `array<I>`.

Each call runs every constructor again. Two calls return two different objects for each class, so
`==` between them is `false`.

The full class name includes the namespace, so `Alpha\Zebra` comes before `Middle`, and `Middle`
before `Zed\Apple`. The list has the classes of every file in the program. It also has the classes
under each `autoload` folder, even when no code names those classes or their files.

```nvs
interface Check

}
```

```nvs
    public function name(): string

    }

}
```

```nvs
// Writing one table in every format a program knows. Adding a format means
// adding a class. There is no list of formats to keep up to date, and nothing

{
    public function format(): string;

    }

    public function render(array<string> $rows): string
    {

    }

{
    public function format(): string
    {
        return 'json';
    }

    {

    }
}

class TextExporter implements Exporter
{
    public function format(): string
    {
        return 'text';
    }

    public function render(array<string> $rows): string
    {
        string $out = '';
        foreach ($rows as string $row) {
            $out = $out . '- ' . $row . ' ';
        }
        return Core\Str::trim($out);
    }
}

array<string> $rows = ['cup', 'plate', 'bowl'];
```

# `Core\Program::implementingWith<I, T>($member)`: every implementor with one attribute

`Core\Program::implementingWith<I, T>($member)` gives you one row for every class in your program
that implements the interface `I`, with one of that class's attributes beside it.

Each row has two fields. `instance` is the object, and `attribute` is the one attribute on that
class's `$member` whose fields match the shape `T`. Without such an attribute, it is `null`. `$member` is the name of a method or a property, or an empty string for the attributes written
on the class itself. Rows are sorted by full class name.

Novis finds the classes and their attributes while it compiles your program. A framework uses this
to read the settings of the classes it found.

**Good to know:** two attributes on one class that both match `T` are an error. Use a narrower
shape, or read that class with `Core\Attributes::all<T>`.

The examples show a report label, class attributes, an admin menu, each page's route path, and a
missing member, which does not compile.

`I` follows the same rules as for `Core\Program::implementing`. The list has the same classes in
the same order, and `E0743`, `E0744` and `E0442` are given for the same mistakes. The call takes two
type arguments.

`$member` is a `string`, and an `int` is `E0401`. Without an argument, `$member` is the empty
string, so the rows have the attributes on each class itself. A second argument is `E0402`.

Write `$member` as a string in quotes. Novis reads it while it compiles. A variable, a class
constant or a joined string such as `"m" . "m"` also compiles, but every row's `attribute` is
then `null`.

A method name finds the method in each class, also a `static` or a `private` one. `"constructor"`
finds the attributes on the constructor. A property is written without the `$`, as `"total"`. In
double quotes, `"$total"` is a variable in the string, so it is `E0301` when no such variable
exists. A promoted constructor parameter is a property, and its name gives the attributes written
on that parameter. A constructor parameter that is not promoted is not found. To read its
attributes, use `Core\Attributes::get` with `Report::constructor(...)` and the parameter's name.

A name that one of the classes does not have is `E0798`, and the message names that class. A
method that a class inherits counts as one it has. Its attributes are not read, so that row's
`attribute` is `null`. A class that overrides a method has only the attributes on its own version.
An attribute on the interface's method is not read either.

The attribute matches `T` when it has every field of `T` with the right type. It may have more
fields. Two attributes that both match on one class are `E0728`, and the message names the class and
the member. A shape with a field that only one of them has picks that one. A `T` that is not a shape,
such as `int` or a class, is `E0729`.

Each row has the type `{ instance: I, attribute: ?T }`. Storing the result in an
`array<{ instance: I, attribute: T }>` is `E0401`, because `attribute` may be `null`.

The attributes Novis reads itself can be read this way too. `{ path: string }` reads the path of each
class's `#[Core\Route]`.

When no class implements `I`, the result is `[]`, whatever `$member` is.

## Example 01: every class with the attribute it declares

```nvs
<?nvs
// Shows how to read one attribute from every class that implements an
// interface. Each row holds the object and the attribute found on it.

type Label = { text: string };

interface Report
{
    public function rows(): int;
}

class SalesReport implements Report
{
    #[Label(text: 'Sales')]
    public function rows(): int
    {
        return 12;
    }
}

class StockReport implements Report
{
    #[Label(text: 'Stock')]
    public function rows(): int
    {
        return 7;
    }
}

// The rows are sorted by class name, so `SalesReport` comes first.
// This prints `Sales: 12` and then `Stock: 7`.
foreach (Core\Program::implementingWith<Report, Label>('rows') as { instance: Report, attribute: ?Label } $row) {
    echo $row->attribute?->text ?? '(none)', ': ', $row->instance->rows(), "\n";
}
```

```output
Sales: 12
Stock: 7
```

## Example 03: build an admin menu from the pages

```nvs
<?nvs
// Shows what a framework does with this: every page in the program, beside the
// menu entry that page declares for itself.

type Menu = { title: string, order: int };

interface AdminPage
{
    public function path(): string;
}

class Dashboard implements AdminPage
{
    #[Menu(title: 'Dashboard', order: 1)]
    public function path(): string
    {
        return '/admin';
    }
}

class Users implements AdminPage
{
    #[Menu(title: 'Users', order: 2)]
    public function path(): string
    {
        return '/admin/users';
    }
}

class Health implements AdminPage
{
    // This page is reachable and stays out of the menu, because it declares
    // no `#[Menu]`.
    public function path(): string
    {
        return '/admin/health';
    }
}

// Adding a page to the menu is adding the attribute to the page, and no list
// of pages can go out of date. This prints `1. Dashboard -> /admin` first.
foreach (Core\Program::implementingWith<AdminPage, Menu>('path') as { instance: AdminPage, attribute: ?Menu } $row) {
    ?Menu $entry = $row->attribute;
    if ($entry != null) {
        echo $entry->order, '. ', $entry->title, ' -> ', $row->instance->path(), "\n";
    }
}
```

```output
1. Dashboard -> /admin
2. Users -> /admin/users
```

## Example 05: each page beside its route

```nvs
<?nvs
// Shows how to read the path of each page's `#[Core\Route]`, so each path is
// written only once.

interface Page
{
    public function render(): string;
}

class Index implements Page
{
    #[Core\Route(path: '/', method: Core\Http\Method::Get, name: 'index')]
    #[Core\Access(allow: Core\Audience::Public)]
    public function render(): string
    {
        return 'home';
    }
}

class Contact implements Page
{
    #[Core\Route(path: '/contact', method: Core\Http\Method::Get, name: 'contact')]
    #[Core\Access(allow: Core\Audience::Public)]
    public function render(): string
    {
        return 'contact us';
    }
}

class Draft implements Page
{
    public function render(): string
    {
        return 'not routed';
    }
}

// `Draft` has no route, so its `attribute` is `null`.
// This prints `/contact -> contact us` first, because `Contact` comes first.
foreach (Core\Program::implementingWith<Page, { path: string }>('render') as { instance: Page, attribute: ?{ path: string } } $row) {
    echo $row->attribute?->path ?? '(no route)', ' -> ', $row->instance->render(), "\n";
}
```

```output
/contact -> contact us
(no route) -> not routed
/ -> home
```
