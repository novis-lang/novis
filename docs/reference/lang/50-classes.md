# Declaring a class

A class is a type you write yourself. It holds some data and the functions that work on that data. You
create one with `new`.

Every member of a class writes `public`, `protected` or `private`. A `public` member is reachable from
anywhere. A `protected` member is reachable from the class and from the classes that extend it. A
`private` member is reachable only from the class that declares it. There is no default, so a member
written without one of those three words does not compile.

The constructor is a method named `constructor`. It runs once, when `new` creates the object. It must
give a value to every property that has no default. A class where every property already has a default
needs no constructor.

**Good to know:** a visibility keyword in front of a constructor parameter declares a property of that
name and fills it with the argument.

**The examples below** show a class with data and methods, a constructor that declares its
properties, and a class that keeps its data private. The last two show a property with no visibility,
which does not compile, and a class with no constructor.

A property, a method or a constant written without `public`, `protected` or `private` does not
compile (`E0122`). A method named `__construct` does not compile either (`E0114`). The error tells you
to name it `constructor`. A class name is PascalCase, so `class point` is the error `E0110`.

Reading a property or calling a method where its visibility does not allow it is the error `E0471`.
That includes a `private` property read in a class that extends the declaring class. A `private`
constructor works the same way. `new A()` outside `A` is `E0471`, and a `static` method of `A` may
still call `new A()`.

A class is declared at the top level of a file. A class or an interface inside a class body is the
error `E0233`. Only an `enum` or a `type` alias may be declared there. A class inside a method or an
`if` block is `E0233` too.

A wrong number of arguments is the error `E0402`. An unknown method or property is `E0405`, for a
read and for a write. A class with no `constructor` takes no arguments, so `new Counter(1)` is
`E0402`. A class that extends another and declares no constructor uses its parent's: with
`class B extends A {}`, `new B(4)` calls `A`'s constructor.

A visibility keyword is allowed only on a parameter of `constructor`. On any other method it is the
error `E0722`. A promoted parameter may also be `readonly`: `public readonly int $x`.

`new A` without parentheses is the same as `new A()`. A constructor may declare the return type
`void`, and it may have no return type at all.

## Example 01: a class with data and methods

```nvs
<?nvs
// Shows how to declare a class, create an object with `new`, and use it.
// Every member writes `public`, `protected` or `private`.

class User
{
    public string $name;
    public string $email;
    private string $role = 'member';

    public function constructor(string $name, string $email)
    {
        $this->name = $name;
        $this->email = $email;
    }

    public function label(): string
    {
        return $this->name . ' <' . $this->email . '>';
    }

    public function roleName(): string
    {
        return $this->role;
    }
}

var $user = new User('Ada Lovelace', 'ada@example.com');

// A `public` property is read and written from anywhere with `->`.
$user->email = 'ada@example.org';

// This prints `Ada Lovelace <ada@example.org>`.
echo $user->label(), "\n";

// `$role` is `private`. Only `User`'s own methods read it, so this class gives
// you a method for it. This prints `member`.
echo $user->roleName(), "\n";
```

```output
Ada Lovelace <ada@example.org>
member
```

## Example 02: a constructor that declares the properties

```nvs
<?nvs
// Shows constructor promotion. A visibility keyword on a constructor parameter
// declares a property of that name and type, and assigns the argument to it.

class Product
{
    // These three lines declare three properties and fill them. There is no
    // second place where `$name`, `$priceCents` and `$currency` are written.
    public function constructor(
        public string $name,
        public int $priceCents,
        private string $currency = 'EUR',

    {
        return $this->priceCents . ' ' . $this->currency;

var $mug = new Product('Coffee mug', 1250, 'CHF');

// This prints `The Art of Computer Programming: 8990 EUR`.

// This prints `Coffee mug: 1250 CHF`.
echo $mug->name, ': ', $mug->price(), "\n";
```

## Example 03: a class that collects and sums its own data

```nvs
<?nvs
// Shows the shape most classes in a program have: private data, and public
// methods that are the only way to reach it.

class Cart
{
    private array<int> $prices = [];

    public function constructor(private string $currency)
    {}

    public function add(int $priceCents): void
    {
        $this->prices[] = $priceCents;
    }

    public function total(): int
    {
        int $sum = 0;
        foreach ($this->prices as int $price) {
            $sum = $sum + $price;
        }
        return $sum;
    }

    public function summary(): string
    {
        return Core\Arr::count($this->prices) . ' items, ' . $this->total() . ' ' . $this->currency;
    }
}

var $cart = new Cart('EUR');
$cart->add(1250);
$cart->add(399);
$cart->add(8000);

// Nothing outside `Cart` can change the prices, so `total` is always the sum of
// what `add` was given. This prints `3 items, 9649 EUR`.
echo $cart->summary(), "\n";
```

```output
3 items, 9649 EUR
```

# Properties

A property is a named value that each object of a class has.

Every property declares its type and its visibility. A property without a default value must be
assigned in the constructor, on every path out of it. A default value must
be a constant: a number, a string, a `bool`, an enum case, a class constant, `[]` or `null`.

Three keywords change when a property gets its value. `readonly` means the constructor sets it once
and no later code can change it. `lateinit` means another part of the program sets it after `new`
returns. Reading it before that first write throws an error. `static` means there is one value for
the whole class, and it starts every request at the value you declared.

**The examples below** show defaults, a constructor, `readonly`, `static` and `lateinit`. Others
show a constructor that does not compile, a `lateinit` read that throws, `isinit`, a `readonly`
write and `static::` on a property.

Only a plain `=` assigns a property in the constructor. `$this->n += 1;` reads the property first, so
a constructor with only that line is the error `E0409`. A `?T` property with no default and no
assignment starts as `null`.

A `return` in a constructor has no value. `return 1;` is the error `E0248`. A bare `return;` leaves
the constructor early, and every property must already have its value on that path. If one does
not, it is `E0409`.

A `lateinit` property may have any type, and a default too. If a method reads it before any write on
the same path, the read does not compile (`E0428`). Any other read with no value first throws a
`LogicError` when it runs. Example 06 prints its message. `isinit` works only on a `lateinit` property. On any other property it is the error
`E0853`. A property cannot be both `lateinit` and `readonly` (`E0427`).

A `readonly` property has no default, and that includes a `static readonly` one (`E0249`). Every
write after the constructor is the error `E0782`: `=`, a compound operator such as `+=`, and an
append with `[]`. A write in another method of the class is `E0782` too, and so is a write in a
subclass constructor after `parent::constructor()`. A second write on the same path through the
constructor is `E0782` as well. `unset($a->v)` is the error `E0413` for every declared property.

A `static` property with no default and a type that is not nullable is the error `E0409`. A
subclass shares the same value with its parent: `B::$n = 5;` also changes `A::$n`. `static::$n`
is the error `E0499`. Write `self::$n` or the class name. `++`, `--` and every compound operator
work on a `static` property. An unknown one is the error `E0309`, and a `private` one read outside
its class is `E0471`.

## Example 01: defaults and a constructor

```nvs
<?nvs
// Shows the two ways a property gets its first value: a default written in the
// class, or an assignment in the constructor.

class Invoice
{
    // These three have a default, so the constructor does not touch them.
    public string $currency = 'EUR';
    public int $total = 0;
    public array<string> $lines = [];

    // This one has no default. The constructor must give it a value.
    public string $customer;

    public function constructor(string $customer)
    {
        $this->customer = $customer;
    }

    public function add(string $line, int $amount): void
    {
        $this->lines[] = $line;
        $this->total = $this->total + $amount;
    }
}

var $invoice = new Invoice('Ada Lovelace');
$invoice->add('Keyboard', 4900);
$invoice->add('Cable', 900);

// This prints: Ada Lovelace owes 5800 EUR for 2 lines.
echo $invoice->customer, ' owes ', $invoice->total, ' ', $invoice->currency;
echo ' for ', Core\Arr::count($invoice->lines), " lines.\n";
```

```nvs
final class Money
```

## Example 03: a shared counter and a logger attached later

```nvs
<?nvs
// Shows a `static` property, which belongs to the class itself, and a `lateinit`
// property, which is written after the object is created.

class Printer
{
    public function write(int $number, string $subject): void
    {
        echo '#', $number, ' ', $subject, "\n";
    }
}

class Ticket
{
    // One value for the whole class. Every request starts it again at 0.
    public static int $issued = 0;

    // The printer is chosen elsewhere, so it arrives after `new` returns.
    public lateinit Printer $printer;

    public readonly int $number;

    public function constructor(public string $subject)
    {
        self::$issued = self::$issued + 1;
        $this->number = self::$issued;
    }

    // A class may read its own `lateinit` property once a write came first on
    // the same path. This method does both.
    public function printWith(Printer $printer): void
    {
        $this->printer = $printer;
        $this->printer->write($this->number, $this->subject);
    }
}

var $printer = new Printer();

var $first = new Ticket('The printer is out of paper');
$first->printWith($printer);

var $second = new Ticket('A new keyboard');
$second->printWith($printer);

// This prints 2. The counter belongs to the class, so both tickets added to it.
echo 'tickets so far: ', Ticket::$issued, "\n";
```

```output
#1 The printer is out of paper
#2 A new keyboard
tickets so far: 2
```

# Methods, `self`, `static` and `parent`

A method is a function that belongs to a class.

An instance method runs on one object, and `$this` is that object. A `static` method belongs to the
class itself. It has no `$this`, and you call it as `Class::method()`.

Three keywords call a method without writing the class name. `self` is the
class the code is written in. `static` is the class the call was made on, which may be a subclass.
`parent` is the class this one extends, so `parent::format()` calls the parent's version.

**Good to know:** a method that says it returns `static` must return the object it was called on, or
a new object of the same class.

**The examples below** show the two kinds of method, `self` beside `static` in a subclass, and a
subclass that calls its parent's version. The last two show a chain of calls with an anonymous
function that keeps `$this`, and a return type `static` that does not compile.

An anonymous function written inside a method keeps that method's `$this`. It may read the class's
`private` properties and call its `private` methods.

A `static` method may also be called on an object: `$a->s()` calls `A::s()`. `$a::s()` is the error
`E0496`, because the left side of `::` must be a class name. An instance method called through the
class, such as `A::i()`, is the error `E0778`. `$this` inside a `static` method is the error `E0779`.

`self`, `static` and `parent` work only inside a class. Outside one, `self::class` and
`static::class` are the error `E0702`. `parent::` in a class that extends no class is the error
`E0303`. When the parent declares a constructor, the child's constructor must call
`parent::constructor(...)` on every path. A path without the call is the error `E0410`.

A method that returns `self` returns the class the method is written in. On a subclass object, the
result has the parent's type, so a method only the subclass has is the error `E0405`. Declare the
return type `static` to keep the subclass. `self` also works as a parameter type.

A method that returns `static` may return `$this`, `new static(...)` or the result of a `static::`
call. `new self()` or `new A()` there is the error `E0741`. `new self()` in a `static` method
always creates the class the code is written in, even when the call was made on a subclass.
`static::method()` reaches an `abstract static` method that a subclass writes.

`static::` inside an anonymous function is the error `E0834`. `self::m()` and `parent::m()` inside
one call the class the function is written in.

## Example 01: an instance method and a static method

```nvs
<?nvs
// Shows the two kinds of method. An instance method works on one object through
// `$this`. A static method belongs to the class and needs no object.

class Temperature
{
    public function constructor(public readonly int $celsius)
    {}

    // An instance method. `$this` is the object the method was called on.
    public function isFreezing(): bool
    {
        return $this->celsius <= 0;
    }

    // A static method. It has no `$this`, so everything it needs is a parameter.
    public static function warmer(Temperature $a, Temperature $b): Temperature
    {
        if ($a->celsius > $b->celsius) {
            return $a;
        }
        return $b;
    }
}

var $morning = new Temperature(-4);
var $noon = new Temperature(11);

// Only the first of these two prints a line.
if ($morning->isFreezing()) {
    echo "the morning is freezing\n";
}
if ($noon->isFreezing()) {
    echo "the noon is freezing\n";
}

// This prints 11, which is the warmer of the two.
echo 'warmer: ', Temperature::warmer($morning, $noon)->celsius, "\n";
```

```output
the morning is freezing
warmer: 11
```

# Constants and `::class`

A class can hold named values that never change, and every class knows its own name.

A constant is written `public const int MAX = 3;`, with its type. Code inside the
class reads it as `self::MAX`, and code anywhere else as `Limits::MAX`. The value must be written
directly in the code, as one value or a list.

A subclass can give a constant a new value. In a method, `static::MAX` reads the value of the class
the call was made on. `self::MAX` reads the value of the class the code is written in. `static::`
works only for a single value, not inside an anonymous function.

`Limits::class` gives the name of a class as a string. `$order::class` gives the class a value
really is.

A constant list gives you a new list on every read.

**The examples below** show `self::` and `static::`, class names as text, a constant list, and
`static::` with a list, which does not compile.

A constant name is SCREAMING_SNAKE_CASE, so `const int max` is the error `E0113`. `static` on a
constant is the error `E0106`. An unknown constant is `E0309`. A constant cannot be assigned:
`A::N = 2;` is the error `E0105`, and `A::L[] = 2;` is `E0700`. A constant is read through the class
name, so `$a::N` is the error `E0496` and `$a->N` is `E0405`.

A subclass that declares the same constant again keeps its type, or a narrower one. An `int|string`
constant may become `int`. A `string` in place of an `int` is the error `E0833`. An interface may
declare a constant, and a class that implements it may declare it again. In a default method,
`static::NAME` reads the value of the class, or the interface's value when the class has none.

`static::NAME` works for `string`, `int`, `uint`, `bool` and `float` constants. For an `array` or a
`?int` constant it is the error `E0832`. A parameter default cannot use `static::` (`E0831`), and
`self::NAME` works there.

`Class::class`, `self::class` and `parent::class` are fixed when the program compiles.
`static::class` and `$obj::class` are read when the program runs. The result is a `string`, so
`int $n = A::class;` is the error `E0401`. `$v::class` on a `mixed`, a `?A` or an anonymous object is
the error `E0702`. Check the value with `is` first. On a `class<A>` value it is `E0702` too. Write
`$c as string` to get the name.

`foreach` works on an array constant like on any other array.

## Example 01: values that never change

```nvs
<?nvs
// Shows a class holding values that never change. Every constant writes its
// type, and code inside the class reads it with `self::` or `static::`.

class Upload
{
    public const uint MAX_BYTES = 1048576;
    public const string FOLDER = 'uploads';
    // The element type is `float`, so this constant holds 1.0 and 2.5.
    public const array<float> STEP_SECONDS = [1, 2.5];

    // Returns true when a file of this size may be stored. `static::MAX_BYTES`
    // reads the constant of the class the call was made on.
    public static function fits(uint $bytes): bool
    {
        return $bytes <= static::MAX_BYTES;
    }

    // `self::MAX_BYTES` always reads the value written in this class.
    public static function describe(): string
    {
        return static::MAX_BYTES as string . ' of ' . self::MAX_BYTES as string . ' bytes';
    }
}

// A subclass gives the constant a smaller value.
class AvatarUpload extends Upload
{
    public const uint MAX_BYTES = 65536;
}

// From outside the class, the name of the class comes first. This prints
// 1048576 and then uploads.
echo Upload::MAX_BYTES, "\n";
echo Upload::FOLDER, "\n";

// `fits` uses `static::`, so each class checks against its own limit.
if (Upload::fits(500000)) {
    echo "500000 bytes fit an upload\n";
}
if (!AvatarUpload::fits(500000)) {
    echo "500000 bytes do not fit an avatar\n";
}

// This prints `65536 of 1048576 bytes`. The first number comes from
// `static::`, the second from `self::`.
echo AvatarUpload::describe(), "\n";

// The first value is written as a whole number. The declared type makes it a
// float, so this division prints 0.5.
echo Upload::STEP_SECONDS[0] / 2, "\n";
```

# Inheritance

A class can build on another class. `extends` names the parent, and the new class starts with
everything the parent has.

The subclass keeps every property and method of the parent, and may write its own version of a
method. `parent::` reaches the version the parent wrote. When the parent has a constructor, the
subclass constructor must call `parent::constructor(...)`.

An `abstract` class is not finished. You cannot create an object of it, and a subclass must write
each method it declares without a body. A `final` class cannot be extended, and a `final` method
cannot be replaced. `$x is T` tests whether an object is a `T`.

**Good to know:** a class extends one parent only. To share behaviour between classes that are not
related, use an interface.

**The examples below** show a subclass that adds to its parent, then an abstract class every
subclass fills in, then a class the program picks while it runs. Examples 06, 09 and 10 show an
`abstract static` method, `is` and a static call through a class value. The others show what does
not compile.

`extends` names one class. `extends A, B` is a syntax error. A class that is not declared is the
error `E0303`, and so is an interface after `extends`. A class that extends itself, directly or
through another class, is the error `E0305`.

When the parent has a constructor, every path through the subclass constructor must call
`parent::constructor(...)`. A call inside one `if` branch only is the error `E0410`. Code may run
before the call, and a second call runs the parent's constructor again. When the parent has no
constructor, the subclass does not call one, and `parent::constructor()` is the error `E0309`. A
subclass with no constructor uses the parent's constructor.

A subclass reaches the parent's `public` and `protected` members. A `private` member is the error
`E0471` in the subclass. `parent::` in a class with no parent is `E0303`. `parent::f()` runs the
nearest version above the class, so it reaches a grandparent when the parent does not declare `f`.
A default parameter value comes from the declared type of the variable. Say `A::f(int $x = 1)` is
replaced by `B::f(int $x = 2)`. A call on an `A` variable uses `1`, even when it contains a `B`.

A class that does not write every `abstract` method of its parent is the error `E0449`. An
`abstract` class that extends another one does not need to write them. `new` on an `abstract` class
or on an interface is the error `E0785`. `new static()` inside an `abstract` class compiles, because
it makes an object of the subclass the call was made on. A method without a body in a class that is
not `abstract` is the error `E0786`, and so is an `abstract` method there. A method cannot be both
`abstract` and `final`: that is the error `E0106`.

An `abstract static` method has no body, so a call to it must reach a subclass. `self::title()` and
`static::title()` in a static method call the class the method was called on. `Page::title()` on the
`abstract` class is the error `E0835`. `self::title()` inside an anonymous function is `E0835` too,
because it calls the class the function is written in.

A class that extends a `final` class is the error `E0783`. A method that replaces a `final` method
is the error `E0784`, also in a grandchild class. Other methods of the same class can be replaced as
usual.

`$x is T` is true for the object's own class, every parent class, and every interface they
implement. It is false for any other class, and false when `$x` is `null`. Inside the `if`, the
variable has the type `T`. The right side of `is` is a class name or a `class<T>` value. A `string`
there is the error `E0496`.

A `class<T>` value works in three places: `new $cls(...)`, `$cls::f(...)` and `$x is $cls`. A
`string` in any of them is the error `E0496`. `$obj->$name` with a string is the error `E0235`. A
static call through a `class<T>` value runs the subclass's method, and `static::` in it is that
subclass. `new $cls(...)` checks the arguments against the constructor of `T`. When a subclass of `T`
has a constructor that cannot take those arguments, the `new` is the error `E0794`. Convert to the
subclass, as in `as class<Strict>`, or give the subclass a constructor that fits. A class name
written in the code that is not a subclass of `T` is the error `E0708` at `as class<T>`.

## Example 01: a subclass adds to what its parent does

```nvs
<?nvs
// Shows `extends`. A subclass starts with everything its parent has, and
// `parent::` runs the version the parent wrote.

class Invoice
{
    public function constructor(public string $customer, public int $cents)
    {}

    public function line(): string
    {
        return $this->customer . ': ' . $this->cents . ' cents';
    }
}

class OverdueInvoice extends Invoice
{
    public function constructor(string $customer, int $cents, public int $days)
    {
        // The parent's constructor assigns the properties the parent declares.
        parent::constructor($customer, $cents);
    }

    public function line(): string
    {
        // `parent::line()` is the version above this one, so this method adds
        // to that text instead of writing it again.
        return parent::line() . ', ' . $this->days . ' days late';
    }
}

// A subclass fits everywhere its parent fits, so both objects go in the
// same array.
array<Invoice> $book = [
    new Invoice('Ada', 1200),
    new OverdueInvoice('Bo', 3400, 12),
];

// Each object runs its own version of `line`.
foreach ($book as Invoice $invoice) {
    echo $invoice->line(), "\n";
}
```

```output
Bo: 3400 cents, 12 days late
```

# `covariant`

`covariant` lets a subclass give a method parameter or a property a narrower type than its parent
gives it. The parent takes any `Animal`, and the subclass takes only a `Dog`.

You write `covariant` before the type: `public function feed(covariant Dog $a)` for a parameter, and
`public covariant Dog $pet;` for a property. Code that uses the parent's type can still pass any
`Animal`. So Novis checks each value when it enters. A parameter is checked before the method body
runs. A property is checked each time it is written. A value of the wrong type throws a
`LogicError` that names both types.

**Good to know:** a narrower type without `covariant` does not compile. The error message tells you
to add it.

**The examples below** show a narrower parameter, the error a wrong value throws, a narrower
property and `compareTo` in a subclass. The last one does not compile.

`covariant` is allowed on a parameter of a method that replaces a parent's method or implements an
interface's method. Static methods and `compareTo` are included. It is also allowed on an instance
property that the parent class already declares. Anywhere else it is the error `E0882`. That
includes a method that replaces nothing and a constructor parameter that is not promoted. It also
includes an anonymous function, a static property, a constant and a `readonly` property.

The type must be one that `is` can test quickly: a class, an interface, an enum, a scalar, or a
nullable type or union of those. An array, a shape, a callable, a `class<T>` and a `property<T>` are
the error `E0883`. For those, take the wider type and test the value inside the method.

The new type must be narrower than the type in the first class that declares the parameter or the
property. The same type or a wider type with `covariant` is `E0882`, because the check would test
nothing. A grandchild class that repeats its parent's narrower type writes `covariant` too. A
`tainted` or `secret` type keeps that word. If the first class gives the parameter a default value,
the narrower type must accept that value, or the method is the error `E0884`.

An `inout` parameter is checked when the method is entered. A variadic parameter checks each value,
and the error names the first one that fails. A property is checked on every write. That includes a
write through `object` or `mixed`, a `property<T>` key, `Core\Reflect` and the parent's
constructor. A property with a `set` hook is checked before the hook runs. Reading a value is never
checked.

## Example 01: a method that takes a narrower type

```nvs
<?nvs

{

    {}
}

class Dog extends Animal
{
    public function bark(): string
    {
        return $this->name . ' barks';
```

# Interfaces

An interface is a list of methods a class promises to provide. A class writes `implements` and then
writes those methods.

A class may implement many interfaces, and an interface may extend another one. A variable typed as
an interface accepts any class that implements it. A class that leaves out a required method does
not compile.

An interface may also have a method with a body. Every class that implements the interface gets
that method and may replace it. An interface may also have constants and `static` methods.

Two interfaces may both give a class a method with the same name. Then the class must declare that
method itself, or it does not compile.

**Good to know:** Novis has no `trait`. To share methods, write them in an interface. To pass the
work to another object, write `implements Greets by $voice`. Every method of `Greets` then calls the
same method on the object in `$voice`.

**The examples below** show a class that implements an interface, an interface with its own method,
and a class that passes its work to another object. Examples 04 and 05 show more of an interface,
and the others do not compile.

An interface has no properties. `public string $path;` in an interface is the error `E0254`. A
constant in an interface needs a type, as in any class: `public const MAX = 3;` is the error
`E0246`. A class may declare the constant again with its own value. A default method reads the
value of the class with `static::MAX`, and the interface's value when the class has none.

A `private` method with a body is a helper. Only the interface's own methods can call it. A call
from anywhere else is the error `E0435`. A class that replaces a default method can still call the
interface's version with `Greets::greet()`. A subclass calls its parent's version with `parent::`.
A default method cannot read a property, because the interface has none: `$this->name` there is the
error `E0313`. It calls a method instead.

A `static` method with a body is called as `Greets::kind()` or `Person::kind()`, and a class may
replace it. A `static` method without a body must be written by every class, like any other
method.

A class that does not write a required method is the error `E0449`. The message names the method
and the interface. A name after `implements` that is a class is the error `E0303`. A name after an
interface's `extends` that is a class is `E0303` too. An interface may extend several interfaces,
separated by commas. Two interfaces that extend each other are the error `E0305`. When a class
extends a parent class and also gets a default method of the same name from an interface, the
parent's method is used.

When two interfaces give a class default methods with the same name, the class must declare that
method itself. Otherwise it is the error `E0859`. Its body can call `A::h()` and `B::h()`.

`implements Greets by $voice` needs a property named `$voice`. A missing property is the error
`E0720`. The property's type must be the interface, or a class that implements it. A `?Greets`
property, an `int` property and a class that only has the same methods are all the error `E0720`.
The forward covers the methods without a body. A default method of the interface still runs its own
body, and calls the class's methods. The forward reads the property on every call, so assigning a
new object to it changes where later calls go. A `lateinit` property that is not set yet throws
`LogicError` on the first forwarded call. A `static` method, a method with a `...` parameter and a
method with an `inout` parameter cannot be forwarded. Each is the error `E0721`, and the class must
write that method itself. One `implements` list may mix interfaces with `by` and without it.

`trait`, `use T;` in a class body and `insteadof` are all the error `E0227`.

# Property hooks

A property hook is a small piece of code that runs every time a property is read or written.

You write `get` to decide what a read gives back, and `set` to decide what a write stores. Either one
may stand alone. A property with only a `get` hook is a computed property: it works out its value
from the other properties, and only its own class writes it.

The hooks run for every read and every write, including the ones the constructor makes, the ones
inside a string, and the ones a subclass makes. Inside the hooks, `$this->name` is the stored value
itself, so a `set` hook stores with `$this->name = ...` and does not call itself. A `set` hook that
throws an error stops the write, and the property keeps the value it had.

**The examples below** show a `set` hook that checks a value, a `get` hook that works one out, and a
class that keeps a name and a display form in step. Example 04 does not compile.

A `get` hook can also have a body: `get { return $this->a * 3; }`. A `set` hook may leave out its
parameter. The new value is then `$value`, as in `set { $this->a = $value; }`. A `get` hook that
returns another type than the property is the error `E0401`.

A hooked property has no default value. `public int $a = 3 { … }` is a syntax error (`E0101`).
A hook on a promoted constructor parameter is a syntax error too. A `readonly` property cannot have
a hook, which is the error `E0843`. An interface declares no property, so a hook there is `E0254`.

A write from outside the class to a property with only a `get` hook is the error `E0787`. The
class's own methods may write it. The `get` hook then reads the stored value. A write of one array
element through a hooked property is the error `E0478`, in the class's own methods too. This
includes `$this->xs[] = 1` in the constructor.

Inside the property's own hooks, `$this->name` is the stored value. In every other method of the
class, `$this->name` runs the hooks. So `$this->a = $this->a + 1` in another method runs `get` and
then `set`. A compound assignment such as `$c->a += 5` and an increment such as `$c->a++` run both
hooks too. `unset($c->a)` is the error `E0413`, as for every property.

A subclass inherits the hooks. A write in a subclass method runs the parent's `set` hook. A
subclass may declare the property again with its own hooks, and a read then runs the subclass's
`get` hook. `isset($c->a)` runs the `get` hook, and is `false` when it returns `null`.

Two `get` hooks may read each other, such as `get => $this->b` on `$a` and `get => $this->a` on
`$b`. They then call each other until the program stops with a `RecursionError`.

## Example 01: a set hook checks every write

```nvs
<?nvs
// Shows a `set` hook. It runs on every write, including the one the
// constructor makes, so the property can never hold a value outside its range.

class Volume
{
    public int $level {
        set(int $v) {
            if ($v < 0) {
                throw new LogicError('a volume is never below 0');
            }
            // Inside the hook, `$this->level` is the stored value. This line
            // stores it, and does not call the hook again.
            if ($v > 10) {
                $this->level = 10;
            } else {
                $this->level = $v;
            }
        }
    }

    public function constructor(int $start)
    {
        $this->level = $start;
    }
}

// 30 is above the ceiling, so the hook stores 10.
var $radio = new Volume(30);
echo $radio->level, "\n";

$radio->level = 7;
echo $radio->level, "\n";

// A hook that throws stops the write. The property keeps the value it had.
try {
    $radio->level = -1;
} catch (LogicError $e) {
    echo 'refused: ', $e->message, "\n";
}
echo $radio->level, "\n";
```

# `LateInit`

A `lateinit` property can get its value the first time a program reads it. The class implements the
interface `LateInit` and writes one method, `initProperty`.

When a read finds a `lateinit` property with no value, Novis calls `initProperty` with the name of the
property. The method sets the property, and then the read returns the new value. A later read does not
call the method again. A write to one element, such as `$post->tags[] = "news"`, calls the method first
too.

If `initProperty` returns and the property still has no value, the read throws a `LogicError`. If the
method throws an error, the property still has no value, and the next read calls the method again.

**Good to know:** the write that gives the property its first value inside `initProperty` does not run
a `set` hook, `PropertyGuard` or `PropertyObserver`. A second task that reads the property while the
method runs waits until it returns.

**The examples below** show a property set on the first read, one method for several properties, a
second try after an error, and the error when a property stays empty.

In a class that implements `LateInit`, a method may read a `lateinit` property before any write.
This compiles, even in the constructor, because the read calls `initProperty`. In a class without
`LateInit`, the same read in the constructor is the error `E0428`. A class that implements
`LateInit` and has no `initProperty` method is the error `E0449`.

`initProperty` runs only for a `lateinit` property with no value. A read of a plain property never
calls it. A write before the first read gives the property its value, so a later read does not call
`initProperty`. `isinit($p->views)` tests the property and calls nothing. A compound assignment such
as `$p->views += 1` reads first, so it calls `initProperty` and then adds `1`.

`initProperty` may set more properties than the one it was called for. A later read of another
property it set does not call it again. A `lateinit` property that a subclass declares calls the
parent's `initProperty` too, with the subclass property's name.

Example 04 shows the message of the `LogicError` when `initProperty` returns and the property still
has no value. A read of a property `$v` inside its own `initProperty` call throws a `LogicError`
too. Its message is `` `$v` is read while `initProperty` initializes it. ``

Inside `initProperty`, only the first write of a property is plain. A second write of the same
property in the method runs `PropertyGuard`, a `set` hook and `PropertyObserver`, as every other
write does.

# `PropertyGuard`

A class can check every write of its own properties before the value is stored. It implements the
interface `PropertyGuard`.

You write two methods. Novis calls `beforePropertySet` before every write of a property the class
declares, in the constructor too. It gets the name of the property, the new value and a list of keys,
`$keys`. A write of the whole property gives `[]`. A write to one element gives the keys of that
element, for example `["0", "1"]` for `$sheet->cells[0][1] = $v`. Novis calls `beforePropertyUnset`
before `unset` removes an element.

If one of these methods throws an error, nothing changes. The property keeps its old value, and no
`PropertyObserver` method runs.

**Good to know:** on a property with a `set` hook, the guard runs before the hook. It gets the value the
caller wrote.

A default value is not a write, so it does not call `beforePropertySet`. A write of a property the
class declares calls it, and so does a write of a property a subclass declares. A write through a
`mixed` variable calls it too. A `static` property calls no guard.

`$value` has the type `mixed`. To use it as an `int`, test it first with `$value is int`. A plain
`int $n = $value;` is the error `E0401`.

For a nested element, `$keys` lists every key from the property down to the element. So
`$a->cells["r"][0] = 9` gives `["r", "0"]`. A compound assignment and an increment give the new
value in `$value`. When `$a->x` is `1`, `$a->x += 4` gives `5`, and then `$a->x++` gives `6`.

A guard may write another property of its own class. That write calls the guard again, with the
other property's name. Test `$name` first, or the program calls the guard until the call stack is
too deep.

When `beforePropertyUnset` throws an error, `unset` removes nothing, and the error goes to the
caller.

## Example 01: stopping a bad value

```nvs
<?nvs
// Shows a guard that stops a bad write. `Account` throws an error when a
// program writes a negative balance, so the old balance stays.

class Account implements PropertyGuard
{
    public int $balance;

    public function constructor(int $balance)
    {
        // The guard also checks this write.
        $this->balance = $balance;
    }

    // `$value` is the new value. It is not stored yet.
    public function beforePropertySet(string $name, mixed $value, array<string> $keys): void
    {
        if ($name == 'balance' && $value is int && $value < 0) {
            throw new LogicError('the balance cannot be negative');
        }
    }

    public function beforePropertyUnset(string $name, array<string> $keys): void
    {
    }
}

var $account = new Account(100);
$account->balance = 40;
echo $account->balance, "\n";

try {
    $account->balance = -10;
} catch (LogicError $e) {
    echo 'error: ', $e->message, "\n";
}

// The write did not happen, so this prints 40.
echo $account->balance, "\n";
```

```output

error: the balance cannot be negative
40
```

# `PropertyObserver`

A class can watch every read and every write of its own properties by implementing the interface
`PropertyObserver`.

You write two methods, `onPropertyGet` and `onPropertySet`. Novis calls them for every property the
class declares: public or private, with hooks or without, written in the constructor or later, and
declared by a subclass too. Each call gives you the property name and the value after it has settled,
so `onPropertySet` sees what was really stored. A write to one element, such as
`$account->history[] = 5`, calls `onPropertySet` once with the whole array after the change.

An observer reports, and it does not decide. Both methods return nothing, so they cannot change the
value a read gives back. If a method throws an error, the read or the write throws it. The value
of a write is already stored then.

**Good to know:** writing a property inside one of these two methods calls the method again. Test the
name first, or the program runs until the call stack is too deep.

**The examples below** show the two methods on a small class, how far one observer reaches, and a
record that knows when it needs saving.

A default value is not a write, so it does not call `onPropertySet`. A `static` property calls
neither method.

`onPropertySet` runs after the value is stored. If it throws an error, the write throws that error,
and the property already has the new value. `onPropertyGet` runs after the value is read, and an
error it throws comes out of the read.

A read inside a string, such as `"v=$o->x"`, calls `onPropertyGet`. So does `isset($o->x)`. A write
of one element, such as `$a->rows[] = 1`, calls `onPropertySet` once with the whole array.
`unset($a->rows[0])` does the same. Neither one calls `onPropertyGet`.

For a property with a `get` hook, `onPropertyGet` gets the value the hook returned. A property the
hook reads calls `onPropertyGet` too, before it. A read inside `onPropertyGet` of another property
calls `onPropertyGet` again, for that property.

`$value` has the type `mixed`. Text you build from it, such as `$value as string`, is a
`tainted string`, so `string $s = $value as string;` is the error `E0401`.

## Example 01: watching every read and write

```nvs
<?nvs
// Shows the two methods an observer writes. `Account` prints one line for every
// read and every write of its own properties.

class Account implements PropertyObserver
{
    public string $owner;
    public int $balance;

    public function constructor(string $owner)
    {
        // The constructor writes both properties, so `onPropertySet` runs twice here.
        $this->owner = $owner;
        $this->balance = 0;
    }

    // `$name` is the property, and `$value` is the value it now has.
    public function onPropertyGet(string $name, mixed $value): void
    {
        echo 'read ', $name, ' = ', $value, "\n";
    }

    public function onPropertySet(string $name, mixed $value): void
    {
        echo 'wrote ', $name, ' = ', $value, "\n";
    }
}

var $account = new Account('Ada');
$account->balance = 120;

// A read calls `onPropertyGet` first, then gives you the value. This prints
// the line from the observer and then 120.
echo $account->balance, "\n";
```

```output

wrote balance = 0
wrote balance = 120
read balance = 120
120
```

## Example 03: a record that knows it changed

```nvs
<?nvs
// Shows what an observer is most often used for: a record that knows whether
// it still matches the database, so a program saves it only after a change.

final class Contact implements PropertyObserver
{
    public string $name;
    public string $email;
    public bool $unsaved = false;

    public function constructor(string $name, string $email)
    {
        $this->name = $name;
        $this->email = $email;
        // The two writes above set the flag. This row comes from the database,
        // so it starts as saved.
        $this->unsaved = false;
    }

    public function onPropertyGet(string $name, mixed $value): void
    {
    }

    public function onPropertySet(string $name, mixed $value): void
    {
        // Writing a property in this method calls the method again. Test the
        // name first. Without this test the program never stops.
        if ($name != 'unsaved') {
            $this->unsaved = true;
        }
    }

    public function save(): void
    {
        if (!$this->unsaved) {
            echo "nothing to save\n";

        echo 'saving ', $this->name, "\n";
        $this->unsaved = false;
    }
}

// One write anywhere in the program is enough. No method has to remember to
// report it.

$contact->save();
$contact->save();
```

```output
nothing to save
```

# `Stringable`

An object becomes text through the interface `Stringable`, whose one method is `toString`.

A class that implements it can be written out in four places: `echo`, the `.` operator that joins two
texts, a value inside a string like `"{$price}"`, and the cast `as string`. Novis calls `toString` at
each of them and uses the text it returns. An object whose class does not implement the interface is
not allowed in any of the four, so no program prints something like `Object#3`.

Everywhere else an object stays an object. Passing one to a method that wants a `string` does not
compile. Write `as string` there yourself.

**Good to know:** the method is called on the real class of the object, so a subclass that writes its
own `toString` is the one that runs.

**The examples below** show a price with its own text form, the four places that text appears, a
receipt built out of several such classes, and a class without `Stringable` that does not compile.

An object of a class that does not implement `Stringable` is the error `E0412` in each of the four
places. A method named `toString` is not enough. The class must also say `implements Stringable`.
A class that implements `Stringable` and has no `toString` method is the error `E0449`.

The method name `__toString` is the error `E0111`, because a method name is written in camelCase.

An object passed to a `string` parameter is the error `E0401`. An object compared with a string
using `==` is the error `E0466`.

`Stringable` is also a type. A parameter or a variable of type `Stringable` accepts an object of any
class that implements it. You can use that value in the same four places.

A variable of a type such as `?Money` can be `null`. A `null` value gives the empty string in each of
the four places.

If `toString` throws an error, the `echo`, the `.` or the conversion throws that error.

## Example 01: giving a class its own text

```nvs
<?nvs
// Shows a class that can be printed. `Money` stores whole cents, and `toString`
// gives the amount people read.

final class Money implements Stringable
{
    public function constructor(private int $cents)
    {}

    public function toString(): string
    {
        return ($this->cents / 100) . ' EUR';
    }
}

var $price = new Money(1250);

// `echo` calls `toString`. This prints 12.5 EUR.
echo $price, "\n";

// `toString` is an ordinary method, so you can also call it by name.
string $text = $price->toString();
echo $text, ' has ', Core\Str::length($text), " characters\n";
```

```output
12.5 EUR
12.5 EUR has 8 characters
```

# `Comparable`

Compares two objects of your own class with `<`, `>`, `<=`, `>=` and `<=>`.

Those operators work on objects when the class implements `Comparable`. That interface has one
method, `compareTo`, which takes another value of the same class and returns a number: negative when
this value comes first, zero when neither comes first, positive when the other one does. The four
ordering operators read only the sign of that number, and `<=>` returns the number itself. You write
the order once, in one method, and all five operators follow it.

**Good to know:** a class that does not implement `Comparable` cannot be ordered. The comparison
does not compile, and the message names `Comparable` as the fix. `==` is a separate question and is
not affected: two objects are equal only when they are the same object. To test whether two values
have the same contents, check that `compareTo` returns zero.

Each of the five operators on objects of a class that does not implement `Comparable` is the error
`E0411`. A class that implements `Comparable` and has no `compareTo` method is the error `E0449`.

Both sides must have the same class. Two objects of different classes are the error `E0411`, even
when both classes implement `Comparable`. This includes a subclass and its parent class. An object
compared with a number is `E0411` too. So is a value of a type such as `?Version`, which can be
`null`.

Each operator calls `compareTo` once. If `compareTo` throws an error, the comparison throws that
error.

`==` does not call `compareTo`. `$a == $b` is `true` only when both variables are the same object.

## Example 01: comparing two values with the usual operators

```nvs
<?nvs
// Shows the comparison operators working on two objects. They work because the
// class implements `Comparable` and writes the one method that interface needs.

final class FileSize implements Comparable
{
    public function constructor(public uint $bytes)
    {}

    // Returns a negative number when this size is the smaller one. Two sizes
    // that are the same give zero. A larger size gives a positive number.
    public function compareTo(self $other): int
    {
        return $this->bytes <=> $other->bytes;
    }
}

var $upload = new FileSize(2400000);
var $limit = new FileSize(1048576);
var $sameLimit = new FileSize(1048576);

// `>` reads the sign of `compareTo`. This prints `the upload is over the limit`.
if ($upload > $limit) {
    echo "the upload is over the limit\n";
}

// `<=` is true when `compareTo` returns zero or a negative number, so two
// sizes that are the same pass it.
if ($limit <= $sameLimit) {
    echo "the limit is within itself\n";
}

// `<=>` returns the number itself. Below zero means the value on the left
// comes first. This prints `1` and then `-1`.
echo $upload <=> $limit, "\n";
echo $limit <=> $upload, "\n";
```

```output
the upload is over the limit
the limit is within itself
1
-1
```

## Example 02: an order built from two properties

```nvs
<?nvs
// Shows an order that reads two properties, and how a program branches on the
// number `<=>` returns.

final class Release implements Comparable
{
    public function constructor(public uint $major, public uint $minor)
    {}

    // The major number decides first. Two releases with the same major number
    // are ordered by their minor number.
    public function compareTo(self $other): int
    {
        int $byMajor = $this->major <=> $other->major;
        if ($byMajor != 0) {
            return $byMajor;
        }
        return $this->minor <=> $other->minor;
    }
}

final class Report
{
    // Prints which of the two releases is the newer one.
    public static function say(Release $installed, Release $available): void
    {
        int $order = $installed <=> $available;
        if ($order < 0) {
            echo "an update is available\n";
        } elseif ($order > 0) {
            echo "your release is newer than the one on the server\n";
        } else {
            echo "you are up to date\n";
        }
    }
}

Report::say(new Release(2, 4), new Release(3, 0));
Report::say(new Release(2, 4), new Release(2, 4));
Report::say(new Release(2, 9), new Release(2, 4));

// The operators read the same method, so the minor number orders these two.
if (new Release(2, 4) < new Release(2, 9)) {
    echo "2.4 comes before 2.9\n";
}
```

```output
you are up to date
your release is newer than the one on the server
2.4 comes before 2.9
```

```nvs

    public function constructor(public uint $number)
    {}

    public function compareTo(self $other): int
    {

    }
}

    {
        return new ApiVersion(7);

    // one outside the range above.
    public static function accept(ApiVersion $wanted): ?ApiVersion
    {
        if ($wanted < Api::oldest()) {
            return null;
        }
        if ($wanted > Api::newest()) {
            return null;
        }
        return $wanted;
    }
}

    var $answer = Api::accept(new ApiVersion($number));
    if ($answer == null) {

    } else {
        echo 'version ', $answer->number, " accepted\n";
    }
}
```

# `Parses`

`Parses` is the interface for a class that is built out of a piece of text.

A class that implements it writes one method,
`public static function parse(tainted string $s): static`. The method returns an object of the class,
or throws an error when the text is not valid. `tainted` says the text came from outside your
program, such as a web request or a command line.

Novis needs this interface everywhere text from outside becomes a value: a piece of a route path, a
`#[Core\Query]` parameter, a command argument and a command option. You declare the parameter at your
own class, and Novis calls `parse` for you. A parameter typed at a class that does not implement
`Parses` does not compile, and the error says so.

**Good to know:** the return type `static` means the class the call named, so a subclass that
inherits `parse` gets an object of the subclass back.

**The examples below** show a product code built from text, what a subclass gets back, a list of
values from a form checked one by one, a class used in a route, and a route that does not compile.

A class that implements `Parses` and has no `parse` method is the error `E0449`. A `parse` method
with a return type other than `static`, such as the class name, is the error `E0404`.

`parse` is an ordinary static method, so your code can call it too: `Slug::parse("hello")`. It may
throw any error. `ParseError` is the usual one.

The text keeps its `tainted` qualifier. A property that stores it must have the type
`tainted string`. A `string` property is the error `E0401`. The object that `parse` returns is not
tainted.

A route capture or a `#[Core\Query]` parameter accepts these types: `string`, `int`, `uint`,
`decimal`, an enum, a set of allowed values such as `'a'|'b'`, and a class that implements `Parses`.
Any other class is the error `E0752`.

A path capture fails in two ways. The router converts some types itself while it matches the path:
`int`, `uint`, `decimal`, `Core\Uuid` and a set of allowed values. A segment that does not convert is
no match. If no other route matches, the response is `404`. For any other `Parses` class, the router matches the path first.
Then it calls `parse`. If `parse` throws, the response is `400`, and the method does not run.

## Example 01: building a value from text

```nvs
<?nvs
// Shows a class built out of text. A product code is eight characters in upper
// case, and `parse` is the only way to make one.

final class Sku implements Parses
{
    public function constructor(public tainted string $code)
    {}

    public static function parse(tainted string $s): static
    {
        // The text comes from outside the program, so every rule is checked here.
        if (Core\Str::length($s) != 8) {
            throw new ParseError('a product code has 8 characters');
        }
        if ($s != Core\Str::upper($s)) {
            throw new ParseError('a product code is written in upper case');
        }
        return new static($s);
    }
}

echo Sku::parse('ABC-1234')->code, "\n";

// Text the class does not accept throws a `ParseError`.
try {
    echo Sku::parse('abc-1234')->code, "\n";
} catch (ParseError $e) {
    echo $e->message, "\n";
}
```

# Objects are handles

An object is never copied when your program passes it from one place to another. A variable, a
property, an array element and a parameter all hold a reference to the object. Assigning it to a
second variable gives that variable the same object. Passing it to a function gives the function the
same object. A write through any one of them is seen through all of them.

`==` on two objects tests whether they are the same object. Two separate objects are never equal,
even when every property in them has the same value.

`clone` makes a new object of the same class and copies every property into it. The copy is one
level deep. An array property is copied, so the two objects have two arrays. An object property is
shared, so both objects point at the same inner object. No method runs during a clone.

**The examples below** show two variables naming one object, a function that changes the object it
is given, and a copy that is edited without changing the original.

`clone` keeps the class of the object. If a variable of type `Animal` has a `Dog`, its clone is a
`Dog` too. A `private` constructor does not stop `clone`, because no constructor runs.

An array property is copied, but an object inside the array is not. After a clone, both arrays
contain the same objects. A write to `$copy->items[0]->price` is seen through the original too.

`!=` on two objects is `true` when they are different objects. `==` on objects of two classes that
are not related is the error `E0466`. `==` with `null` tests whether a `?Note` variable has an
object.

## Example 01: two names for one object

```nvs
<?nvs
// Shows what happens when you assign an object to a second variable. Both
// variables name the same object, so a write through one is read through the other.

class Counter
{
    public int $value = 0;
}

var $counter = new Counter();
var $alias = $counter;

// The write goes through `$alias`. Both variables name one object, so this prints `5|5`.
$alias->value = 5;
echo $counter->value, '|', $alias->value, "\n";

// `==` on two objects is true when they are the same object. This prints `1`.
echo ($counter == $alias) as string, "\n";

// A second `new` makes a second object. It has the same value and is still a
// different object, so `==` is false and `as string` prints an empty string.
var $other = new Counter();
$other->value = 5;
echo ($counter == $other) as string, "|done\n";
```

```output
5|5
1
|done
```

# Nullable objects and `?->`

`?Box` is a type that holds a `Box` or `null`. A plain `Box` never holds `null`, so a value of that
type is always there.

`->` on a value that may be `null` does not compile. Novis needs you to say what should happen when
the value is missing, and there are two ways to say it.

Write `?->`. On a `null` value the whole access returns `null`. The method is not called and its
arguments are not evaluated. Put `?? "something"` after it to give the missing case a value.

Test the value first. Inside `if ($box != null)` the value is no longer nullable, so plain `->`
works there. This is the better choice when the branch does several things with the value.

**The examples below** show reading a setting that may be missing, testing a value before using it,
a chain of accesses where any step may be absent, and a `->` that does not compile.

`->` on a value that may be `null` is the error `E0459`. This is true for a property and for a
method call.

The result of `?->` can be `null`. `$box?->count` on an `int` property is a `?int`. Assigning it to
an `int` variable is the error `E0401`. Write `$box?->count ?? 0` to get an `int`.

Each `?->` covers one step of a chain. In `$box?->inner()->label`, the result of `?->inner()` can be
`null`, so the `->` after it is `E0459`. This is true even when `inner()` returns a `Box`. Write
`?->` for every step after the first one: `$box?->inner()?->label`.

`$box?->save();` can call a `void` method as a statement. When `$box` is `null`, nothing runs.
`isset($box?->count)` is `false` when `$box` is `null`.

## Example 01: reading a value that may be missing

```nvs

// the value is missing, and `??` gives you something to use instead.

{

    {}

// This prints `default`.

// Without `??` the result is `null` itself. `as string` prints an empty text for it.
```

# `object`: the top of every class type

`object` is a type that contains an object of any class. It names no class itself. The compiler only
checks that the value is an object. Use it where a value may come from several unrelated classes,
such as a plugin a program loaded.

A property read through an `object` compiles. The name is looked up while the program runs. The read
throws an error when the object has no property with that name.

A method call through an `object` does not compile. Name the class first. Inside `if ($value is
Tag)`, you can call the methods of `Tag`. `$value as Tag` gives you a `Tag` to use anywhere.

**The examples below** show a value of unknown class, a check before calling a method on it, a list
of mixed objects sorted by class, and a method call that does not compile.

A method call through `object` is the error `E0477`. This is true for `?->` on a `?object` too.

An `object` variable contains only an object of a class. An `int`, `null` or an anonymous function
at an `object` is the error `E0401`. Write `?object` for a value that can be `null`.

An `object` value at a parameter or a variable of a class type is the error `E0401`. Convert it with
`as` first.

A property read through `object` gives `mixed`. So `int $n = $o->count;` is the error `E0401`. Write
`$o->count as int`.

A write through `object` compiles, and the value is checked while the program runs. A property the
object does not have throws a `RuntimeError`. A value of another type than the property's throws a
`RuntimeError` too, and so does a write to a `readonly` property.

# What a class cannot declare

Novis classes do not have magic methods, anonymous classes or nested classes. Each one is a compile
error, and the message names what to write instead.

No method name may start with `_`, so `__get`, `__set`, `__call`, `__invoke`, `__clone`,
`__destruct`, `__toString` and the rest cannot be written. A property hook does the work of `__get`
and `__set`. `PropertyObserver` sees every read and write of a class. `Stringable` gives a class
its text form. A `callable` comes from `fn` or from a method reference such as `Core\Str::length`,
so there are no callable objects. There is no destructor.

`new class { … }` does not exist. A `class` or an `interface` inside a class body does not
compile. Every class is declared at the top level of a file, with a name. An `enum` and a `type`
alias are the only types a class body can declare.

**The examples below** show a hook in place of `__get`, `PropertyObserver` in place of `__set`, a
named class in place of an anonymous one, and two classes that do not compile.

A method whose name starts with `__` is the error `E0111`. Its help names the method without the
underscores, such as `get` for `__get`. `__construct` is the error `E0114`, and its help names
`constructor`. A property whose name starts with `_` is the error `E0112`.

`new class { … }` is the error `E0244`.

An object cannot be called like a function. `$obj()` is the error `E0420`. Call a method by its
name, or use a method reference such as `$obj->run(...)`.

A method called `destructor` is an ordinary method. It runs only when your code calls it.

## Example 01: a hook in place of a get method

```nvs
<?nvs
// Shows a property hook where PHP would write `__get`. The hook runs when the
// property is read, so the class works the value out instead of storing it.

class Person
{
    public function constructor(public string $first, public string $last)
    {}

    // `get => expr;` runs on every read of `$fullName`.
    public string $fullName {
        get => $this->first . ' ' . $this->last;
    }
}

var $ada = new Person('Ada', 'Byron');

// This prints "Ada Byron".
echo $ada->fullName, "\n";

// The value follows the properties it is worked out from. This prints
// "Ada Lovelace".
$ada->last = 'Lovelace';
echo $ada->fullName, "\n";

// A hook belongs to one property, with a name and a type the compiler checks.
// Your editor completes `$ada->fullName` as it does any other property.
```

```output
Ada Byron
Ada Lovelace
```

## Example 02: propertyobserver in place of a set method

```nvs
<?nvs
// Shows `PropertyObserver` where PHP would write `__set`. One method sees every
// write to every property the class declares. A program can keep a trail of what
// changed without writing a setter for each property.

final class Profile implements PropertyObserver
{
    public string $displayName;
    public string $email;
    public string $changed = '';

    public function constructor(string $displayName, string $email)
    {
        $this->displayName = $displayName;
        $this->email = $email;
        // The two writes above are already in the trail. This row comes from
        // the database, so the trail starts empty.
        $this->changed = '';
    }

    public function onPropertyGet(string $name, mixed $value): void
    {
    }

    public function onPropertySet(string $name, mixed $value): void
    {
        // Writing a property in this method calls the method again. Test the
        // name first, or the program never stops.
        if ($name != 'changed') {
            $this->changed = $this->changed . $name . ' ';
        }
    }
}

var $profile = new Profile('ada', 'ada@example.com');

$profile->displayName = 'Ada Lovelace';
$profile->email = 'ada.lovelace@example.com';

// This prints "displayName email", the two properties that changed, in the
// order they were written.
echo $profile->changed, "\n";
```

```output
displayName email
```

## Example 03: a named class in place of an anonymous one

```nvs
<?nvs
// Shows a named class where PHP would write `new class { … }`. Novis has no
// anonymous classes, so a one-off implementation of an interface gets a name.

interface Notifier
{
    public function notify(string $text): string;
}

// This class is declared at the top level of the file, like every other class.
class ConsoleNotifier implements Notifier
{
    public function notify(string $text): string
    {
        return 'console: ' . $text;
    }
}

// A second one. A test uses this in place of the real notifier and then reads
// what it collected.
class RecordingNotifier implements Notifier
{
    public string $last = '';

    public function notify(string $text): string
    {
        $this->last = $text;
        return 'recorded: ' . $text;
    }
}

class Job
{
    public function constructor(private Notifier $notifier)
    {}

    public function run(): string
    {
        return $this->notifier->notify('job finished');
    }
}

// This prints "console: job finished".
echo (new Job(new ConsoleNotifier()))->run(), "\n";

// The same job, with a different notifier. This prints
// "recorded: job finished" and then "job finished".
var $recorder = new RecordingNotifier();
echo (new Job($recorder))->run(), "\n";
echo $recorder->last, "\n";
```

```output
console: job finished
recorded: job finished
job finished
```
