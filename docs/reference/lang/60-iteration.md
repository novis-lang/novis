# What `foreach` walks

`foreach` is the loop that walks a collection of values and gives you one value at a time.

It accepts three kinds of subject: an array, an object whose class implements `Iterable`, and an
object whose class implements `Iterator`. A method that contains `yield` returns an `Iterator`, so it
is a subject too. Write `var` for the loop variable, and it gets the type of the subject's values. Or
write the type, and the compiler checks it. Over an array the loop may get the key as well as the
value. The other two subjects have no keys, so a loop over one gets the value alone.

**Good to know:** a method that takes `Iterable<T>` as a parameter type works with every class that
can be walked. One function can then read a list, a cart or a database result the same way.

**The examples below** show an array with and without its keys, then an object and a generator, then
a checkout that adds up a shopping cart. Each one uses `var` first and a written type after it.
Example 04 shows a second loop over the same iterator.

The key of an array is always a `string`, also when the array was written as a list. `var $k` is a
`string`, and `int $k` is the error `E0723`. Convert the key in the loop body if you need a number.

A written value type is checked against the element type. `string $v` over an `array<int>` is the
error `E0401`. This is the same over an `Iterable<int>` and an `Iterator<int>`.

Any other subject is the error `E0443`. That covers an object whose class implements neither
interface, an `int`, a `string` and a `?array<int>`. Check a nullable array for `null` before the
loop.

A loop over an `Iterator` walks the iterator itself. A second loop over the same iterator starts
where the first one stopped. After a complete loop, the second loop gets no values. After a
`break`, the second loop gets the values that are left.

## Example 01: walking an array with and without its keys

```nvs
<?nvs
// Shows the two ways a `foreach` loop walks an array: the values alone, and the keys
// together with the values.

var $scores = ['ada' => 31, 'bob' => 27, 'cleo' => 44];

// The loop gives one value per step. `var $score` gets the type of the values, `int`.
var $total = 0;
foreach ($scores as var $score) {
    $total = $total + $score;
}
// This prints 102.
echo $total, "\n";

// An array also has keys. `string $name => int $score` gets both, and writes their types.
foreach ($scores as string $name => int $score) {
    echo $name, ' scored ', $score, "\n";
}
```

```output
102
ada scored 31
bob scored 27
cleo scored 44
```

## Example 02: walking an object and an iterator

```nvs
<?nvs
// Shows the other two subjects a `foreach` loop accepts: an object whose class
// implements `Iterable`, and an `Iterator` returned by a method that contains `yield`.

class Weekdays implements Iterable<string>
{
    // `foreach` calls `iterate()` once and walks the iterator it returns.
    public function iterate(): Iterator<string>
    {
        yield 'Monday';
        yield 'Tuesday';
        yield 'Wednesday';
    }
}

class Steps
{
    // A method with `yield` returns an `Iterator`, which `foreach` walks directly.
    public static function upTo(int $last): Iterator<int>
    {
        int $i = 1;
        while ($i <= $last) {
            yield $i;
            $i = $i + 1;
        }
    }
}

// The subject is an object. `Weekdays` is an `Iterable<string>`, so `$day` is a
// `string`. This prints the three names.
foreach (new Weekdays() as var $day) {
    echo $day, "\n";
}

// The subject is an iterator. This loop writes the type `int` in place of `var`.
// This prints 1, 2 and 3.
foreach (Steps::upTo(3) as int $n) {
    echo $n, "\n";
}
```

```output
Monday
Tuesday
Wednesday
1
2
3
```

## Example 03: adding up a shopping cart

```nvs
<?nvs
// Shows one method that adds up a shopping cart. Its parameter type is `Iterable<Item>`,
// so it walks any class that can be walked and never needs to know how the cart stores
// its items.

class Item
{
    public function constructor(
        public string $name,
        public int $cents,
        public int $quantity,
    )
    {}
}

class Cart implements Iterable<Item>
{
    private array<Item> $items = [];

    public function add(Item $item): void
    {
        $this->items[] = $item;
    }

    public function iterate(): Iterator<Item>
    {
        // `var $item` is an `Item`, because `$this->items` is an `array<Item>`.
        foreach ($this->items as var $item) {
            yield $item;
        }
    }
}

class Checkout
{
    public static function total(Iterable<Item> $items): int
    {
        int $cents = 0;
        foreach ($items as Item $item) {
            $cents = $cents + $item->cents * $item->quantity;
        }
        return $cents;
    }
}

var $cart = new Cart();
$cart->add(new Item('Coffee', 749, 2));
$cart->add(new Item('Filter', 399, 1));

// This prints 1897, the price of the whole cart in cents.
echo Checkout::total($cart), "\n";
```

```output
1897
```

## Example 04: an iterator continues where it stopped

```nvs
<?nvs
// Shows that a second loop over the same `Iterator` starts where the first
// loop stopped. A loop over an `Iterable` starts again from the first value.

class Queue implements Iterable<string>
{
    public function iterate(): Iterator<string>
    {
        yield 'first';
        yield 'second';
        yield 'third';
    }
}

Iterator<string> $jobs = $queue->iterate();

// The first loop stops after one value. This prints `first`.

    echo $job, "\n";
    break;
}

// The same iterator gives the values that are left. This prints `second` and `third`.
foreach ($jobs as string $job) {
    echo $job, "\n";
}

// The object calls `iterate()` again for a new loop. This prints `first`.
foreach ($queue as string $job) {
    echo $job, "\n";
    break;
}
```

second
third
first

# The two interfaces

Two interfaces make a class walkable by a `foreach` loop: `Iterator<T>` and `Iterable<T>`. There are
no others.

`Iterator<T>` is the cursor. `advance()` moves it to the next element and returns `false` once there
are none left. `current()` returns the element the last `advance()` moved to. `Iterable<T>` has one
method, `iterate()`, which returns a fresh `Iterator<T>`. A class declares one of the two at a
concrete type, such as `Iterator<int>`. Both names also work as a parameter type or a variable type.

**Good to know:** `foreach` calls `iterate()` once per loop, so one `Iterable<T>` object can be
walked twice, or nested inside a loop over itself. A cursor has no keys, so a loop over one cannot
bind a key.

**The examples below** show a cursor written by hand, then a class that gives out a fresh cursor per
loop, then a search result read page by page. Example 04 shows that a loop over a cursor cannot get
a key.

`implements Iterator` with no type argument is the error `E0442`. Write the element type, such as
`Iterator<int>`. A class of your own cannot declare a type argument. `class Box<T>` and
`interface Pair<T>` do not compile.

A class that implements `Iterator<T>` without `advance()` or `current()` is the error `E0449`. The
same is true for `Iterable<T>` without `iterate()`.

A class may implement both interfaces. `iterate()` may then return `$this`.

The three types are separate. An `array<int>` and an `Iterator<int>` are not an `Iterable<int>`, and
an `Iterable<int>` object is not an `Iterator<int>`. Passing one where another is needed is the error
`E0401`. The element type must match too: an `Iterable<int>` object is not an
`Iterable<int|string>`.

`current()` called before the first `advance()`, or after `advance()` returned `false`, throws a
`LogicError`. The message is `current() outside the iteration protocol: it answers only after
advance() returned true`.

## Example 01: a cursor written by hand

```nvs
<?nvs
// Shows the `Iterator<T>` interface. A class that has `advance()` and `current()` can be
// walked by a `foreach` loop, and by a `while` loop that calls the two methods itself.

class Letters implements Iterator<string>
{
    // The cursor starts before the first element, so the first `advance()` reaches it.
    private int $at = -1;

    public function constructor(private array<string> $items)
    {}

    // Moves to the next element. The result is `false` once there are none left.
    public function advance(): bool
    {
        $this->at = $this->at + 1;
        return $this->at < (Core\Arr::count($this->items) as int);
    }

    // Returns the element the last `advance()` moved to.
    public function current(): string
    {
        return $this->items[$this->at];
    }
}

array<string> $abc = ['a', 'b', 'c'];

// The two methods are the whole protocol, so this loop does what a `foreach` does.
var $byHand = new Letters($abc);
while ($byHand->advance()) {
    echo $byHand->current();
}
echo "\n";

// The same three letters, with the loop calling the two methods for you.
foreach (new Letters($abc) as string $letter) {
    echo $letter;
}
echo "\n";
```

```output
abc
abc
```

## Example 02: a fresh cursor for every loop

```nvs
<?nvs
// Shows the `Iterable<T>` interface. Its one method `iterate()` returns a cursor, and
// `foreach` calls it once per loop. Every loop therefore starts at the beginning.

class Countdown implements Iterable<int>
{
    public function constructor(private int $from)
    {}

    // A method with `yield` returns an `Iterator<int>`, which is what this must give.
    public function iterate(): Iterator<int>
    {
        int $i = $this->from;
        while ($i > 0) {
            yield $i;
            $i = $i - 1;
        }
    }
}

var $three = new Countdown(3);

// The same object is walked twice, and the second loop starts at 3 again.
foreach ($three as int $n) {
    echo $n;
}
echo "\n";
foreach ($three as int $n) {
    echo $n;
}
echo "\n";

// One loop inside another over the same object. Each loop has its own cursor, so this
// prints all nine pairs.
foreach ($three as int $outer) {
    foreach ($three as int $inner) {
        echo $outer, $inner, ' ';
    }
}
echo "\n";
```

```output
321
321
33 32 31 23 22 21 13 12 11
```

# Generators

A generator is a method that gives out its values one at a time, as a loop asks for them.

Write `yield` in the body and declare `Iterator<T>` as the return type. Calling the method runs none
of the body. It returns a cursor, and each step of a `foreach` loop runs the body as far as the next
`yield`. When the loop ends, the body stops where it is. This makes a generator cheap. It has one
value at a time, and it can give a sequence that goes on forever.

**Good to know:** a generator is walked once. A second `foreach` over the same cursor sees nothing,
and calling the method again gives you a new cursor that starts at the beginning.

You cannot `clone` a generator. `clone Gen::count(3)` does not compile. If the generator is in a
`mixed` or `Iterator<T>` variable, `clone` throws a `LogicError`. To start again, call the method
again.

**The examples below** show a small generator first, then a sequence with no end, then two
generators reading one report together. Then they show separate cursors and `return;`, a `finally`
block, an error thrown in a generator, and two code examples that do not compile.

A method with `yield` in its body must return `Iterator<T>`. Any other return type is the error
`E0446`. This is true for `Iterable<T>`, `array<T>` and `void`. `Generator` is not declared, so it is
the error `E0303`. A method that returns `Iterator<T>` but has no `yield` is an ordinary method. It
must return a value, or it is the error `E0739`.

`yield` works only in the body of the generator itself. A `yield` at the top level of a file, or in
an anonymous function, is the error `E0445`. This is also true for an anonymous function inside a
generator.

A static method, an instance method and `iterate()` may each be a generator. An `iterate()` that
yields gives a new generator for each loop, so the object can be walked many times.

`yield` is a statement and has no value. These forms are the error `E0448`:

- `int $x = yield 2;`, since nothing is sent back into a generator.
- `yield "a" => 1;`, since an `Iterator<T>` has no keys.
- `yield;` with no value.
- `yield from G::inner();`. Write `foreach (G::inner() as int $v) { yield $v; }` instead.

The value of a `yield` must have the type `T`. `yield "a";` in an `Iterator<int>` is the error
`E0401`.

`return;` ends the sequence early. `return 5;` is the error `E0447`, because a generator has no
return value.

A generator cannot take an `inout` parameter. That is the error `E0492`. The arguments are copied
when the method is called. A change to the caller's array after the call is not seen by the
generator.

`current()` called before the first `advance()`, or after `advance()` returned `false`, throws a
`LogicError`. Once the sequence has ended, every later `advance()` returns `false`.

A loop over a generator cannot have a key. `foreach (G::g() as string $k => int $v)` is the error
`E0444`.

`clone G::g()` is the error `E0858`. `clone` of a generator in a variable throws a `LogicError` with
the message `clone(): a generator is a suspended frame, so it has no meaning on the other side of a
copy boundary`.

A `finally` block around a `yield` runs when the body reaches its end. It also runs when the loop
stops early with `break`, before the code after the loop. A generator that was advanced and then
freed runs its `finally` too. This happens when its last variable gets a new value. A generator that
was never advanced runs nothing.

A `throw` in the body reaches the `foreach` loop or the `advance()` call that resumed the generator.
The values yielded before it have already been given to the loop. A `try` and `catch` inside the body
can catch the error, and the body can then go on yielding.

A generator can read another generator with `foreach`, and a generator can call itself in the same
way. A generator stored in a `mixed` variable is an `Iterator<T>` for `is`. A `foreach` over the
`mixed` variable is the error `E0443`.

## Example 01: a method that yields its values

```nvs
<?nvs
// Shows how to write a generator: a method whose body contains `yield`. It gives
// out one value at a time, and the body runs only as far as the loop asks.

class Countdown
{
    // A generator declares `Iterator<T>` as its return type. Each `yield` gives one `T`.
    public static function from(int $start): Iterator<int>
    {
        echo "the body starts\n";
        int $n = $start;
        while ($n > 0) {
            yield $n;
            $n = $n - 1;
        }
        echo "the body ends\n";
    }
}

// Calling the method runs none of the body. It returns a cursor, and prints nothing.
Iterator<int> $numbers = Countdown::from(3);
echo "the cursor exists\n";

// The loop is what runs the body. This prints 3, 2 and 1.
foreach ($numbers as int $n) {
    echo $n, "\n";
}
```

```output
the cursor exists
the body starts
3
2
1
the body ends
```

## Example 02: a sequence with no end

```nvs
<?nvs
// Shows a generator whose loop has no end. The body runs one step per value, so a
// sequence without an end is safe to write and safe to walk.

class Backoff
{
    // Every wait is twice the one before it: 1, 2, 4, 8, and so on.
    public static function delays(int $first): Iterator<int>
    {
        int $wait = $first;
        while (true) {
            yield $wait;
            $wait = $wait * 2;
        }
    }
}

int $attempt = 0;
foreach (Backoff::delays(1) as int $seconds) {
    $attempt = $attempt + 1;
    echo "attempt {$attempt} waits {$seconds}s\n";
    // `break` leaves the generator where it stopped. The body runs no further,
    // so the loop above ends after four values.
    if ($attempt == 4) {
        break;
    }
}
```

attempt 1 waits 1s
attempt 2 waits 2s
attempt 3 waits 4s
attempt 4 waits 8s

// Shows two generators working together: one reads the lines of a report, the other
// keeps the lines that matter. A program uses this shape to scan a long report while

class Report
{
    // Gives out the lines of the text, one per `yield`.
    public static function lines(string $text): Iterator<string>
    {
        foreach (Core\Str::lines($text) as string $line) {

        }

    public static function failures(Iterator<string> $lines): Iterator<string>

                yield $line;
            }
        }
    }
}

// This prints the two `ERROR` lines. The report is walked once, and neither
// generator builds a list of its own.
foreach (Report::failures(Report::lines($log)) as string $failure) {
    echo $failure, "\n";
}

// Shows that each call gives a new cursor, that `return;` ends the values early,
// and that a cursor is walked once.

class Numbers
{
    public static function count(int $n): Iterator<int>
    {
        int $i = 0;
        while ($i < $n) {
            yield $i;
            $i = $i + 1;
        }

    {
        yield 1;
        if ($stop) {
            return;
        }

# `Core` collections are `Iterable`

A `foreach` loop walks a `Core` collection the same way it walks an array.

Four classes work this way. `Core\ObjectSet` gives you its members and `Core\ObjectMap` gives you its
keys, both in the order you added them. `Core\Heap` gives you its elements smallest first, and leaves
the heap full. `Core\Task\Channel` gives you each value another task sent, and the loop ends when that
task calls `close`.

A set, a map and a heap take a copy of their contents when the loop starts. The loop walks that copy,
so your code may add or remove inside the loop body. The loop still visits what was there at the
start, and your changes are in the collection when it ends.

**The examples below** show a set and a map first, then a heap, then a channel between two tasks.

`Core\ObjectSet<T>`, `Core\Heap<T>` and `Core\Task\Channel<T>` are each an `Iterable<T>`.
`Core\ObjectMap<K, V>` is an `Iterable<K>`. You can pass each one to a parameter of that type.

A loop over a map gives the keys, never the values. `int $v` over an `ObjectMap<string, int>` is the
error `E0401`. A key variable is not allowed: `foreach ($map as string $k => int $v)` is the error
`E0444`. The written type of the loop variable must be the element type, or the error is `E0401`.
`var $v` takes the element type.

A heap made with a compare function gives its elements in the order that function sets. A heap of
`Comparable` objects gives them in the order of `compareTo`.

A set, a map and a heap can be walked many times, and each loop gives every element again.

A loop over a channel takes each value out of it. A second loop over the same closed channel gets no
values. Values sent before `close` are still given to the loop.

## Example 01: walking a set and a map

```nvs
<?nvs
// Shows how to walk a `Core\ObjectSet` and a `Core\ObjectMap` with `foreach`.

var $tags = new Core\ObjectSet<string>();
$tags->add('blue');
$tags->add('green');
$tags->add('blue');

// A set holds each value once, so "blue" is in it once. The loop gives you the
// members in the order you added them. This prints blue and then green.
foreach ($tags as string $tag) {
    echo $tag, "\n";
}

var $stock = new Core\ObjectMap<string, int>();
$stock->set('apples', 12);
$stock->set('pears', 4);

// A loop over a map gives you the keys. Use `get` to read the value for a key.
foreach ($stock as string $name) {
    echo $name, ' ', $stock->get($name), "\n";
}
```

```output
blue
green
apples 12
pears 4
```

## Example 02: reading a heap without emptying it

```nvs
<?nvs
// Shows how to read every element of a `Core\Heap` in priority order.

var $costs = new Core\Heap<int>();
$costs->push(30);
$costs->push(5);
$costs->push(17);

// The loop gives you the elements smallest first. This prints 5, 17 and 30.
foreach ($costs as int $cost) {
    echo $cost, "\n";
}

// The loop takes nothing out of the heap. All three elements are still there,
// so this prints 3.
echo $costs->count(), "\n";

// `pop` is what removes one. This prints 5, the same element the loop saw first.
echo $costs->pop(), "\n";
```

```output
5
17
30
3
5
```

## Example 03: a worker task reading its jobs

```nvs
<?nvs
// Shows a worker task taking its jobs from a `Core\Task\Channel` with `foreach`.

class Report
{
    public static string $done = '';
}

// The channel holds 2 jobs at a time. A sender waits while it is full, so a fast
// sender cannot fill up the memory of a slow worker.
var $jobs = new Core\Task\Channel<string>(2);

Core\Task::all({
    fill: fn(): int => {
        array<string> $queue = ['resize-logo', 'resize-banner', 'resize-icon'];
        foreach ($queue as string $job) {
            $jobs->send($job);
        }
        // `close` ends the loop in the other task. Without it, that loop waits forever.
        $jobs->close();
        return 0;
    },
    work: fn(): int => {
        // The loop gives you each job that was sent, in the order it was sent.
        foreach ($jobs as string $job) {
            Report::$done = Report::$done . $job . ' ';
        }
        return 0;
    },
});

// Both tasks have finished here, so this prints all three job names.
echo Report::$done, "\n";
```

```output
resize-logo resize-banner resize-icon
```

# Materialising a sequence: `Core\Arr::from`

`Core\Arr::from` turns a sequence into a plain array.

It takes whatever a `foreach` loop takes: an array, a generator, an object you can walk, or a `Core`
collection. The result is an `array<T>` numbered from `0`, holding the values in the order the
sequence gave them. Use it when you need the whole sequence at once, to count it, to sort it, or to
read it more than once. A generator is walked once and is then spent, so keep the array you get
back.

**Good to know:** the `limit` option stops the walk after the number of values you name. A sequence
with no end needs it, or the call never returns.

**The examples below** show a generator collected into an array, then `limit` on a sequence with no
end, then a `Core` collection sorted.

The element type of the result is the element type of the sequence. A generator of `int` gives an
`array<int>`, and a `Core\ObjectMap<string, int>` gives an `array<string>`. Assigning the result to
another array type is the error `E0401`.

An array literal written in the call gives an `array<mixed>`. `array<int> $b =
Core\Arr::from([1, 2, 3]);` is the error `E0401`. Put the array in a typed variable first.

The keys of an array are not kept. An array with the keys `"x"` and `"y"` gives an array with the
keys `0` and `1`.

The argument must be an array, an `Iterable<T>`, an `Iterator<T>` or a `Core` collection. Any other
type is the error `E0401`, and this is true for `mixed` too.

`limit` is a `uint`. A negative number or a string is the error `E0401`. `limit: 0` gives an empty
array, and the body of a generator does not run. A limit larger than the sequence gives the whole
sequence. Any other option name is the error `E0454`.

With `limit`, a generator stops where the limit is reached. A later loop or a later
`Core\Arr::from` over the same generator continues with the next value.

A heap is not emptied. `Core\Arr::from` gives its elements in priority order, and the heap still has
them all.

An error thrown by a generator reaches the code that called `Core\Arr::from`.

## Example 01: a generator as an array

```nvs
<?nvs
// Shows how to collect the values of a generator into a plain array.

class Fibonacci
{
    public static function first(int $many): Iterator<int>
    {
        int $a = 1;
        int $b = 1;
        int $n = 0;
        while ($n < $many) {
            yield $a;
            int $next = $a + $b;
            $a = $b;
            $b = $next;
            $n = $n + 1;
        }
    }
}

// `Core\Arr::from` walks the generator to its end and keeps every value.
array<int> $numbers = Core\Arr::from(Fibonacci::first(7));

// The keys start at 0. This prints 7, then 13.
echo Core\Arr::count($numbers), "\n";
echo $numbers[6], "\n";

// The values are in an array now, so you can read them as often as you like.
// This prints 33.
echo Core\Arr::sum($numbers), "\n";
```

```output
7
13
33
```

## Example 02: taking the first few values

```nvs
<?nvs
// Shows the `limit` option, which stops the walk after the number of values you name.

class Ids
{
    // This generator has no end.
    public static function forever(string $prefix): Iterator<string>
    {
        int $n = 1;
        while (true) {
            yield "{$prefix}-{$n}";
            $n = $n + 1;
        }
    }
}

// `limit` is what makes this call return. It stops the walk after three values.
array<string> $batch = Core\Arr::from(Ids::forever('order'), { limit: 3 });

// This prints order-1, order-2 and order-3.
foreach ($batch as string $id) {
    echo $id, "\n";
}
```

```output
order-1
order-2
order-3
```

## Example 03: sorting what a collection holds

```nvs
<?nvs
// Shows how to take a `Core` collection into an array and sort it. A program does this
// when it gathers values while it works and puts them in order at the end.

var $seen = new Core\ObjectSet<string>();
$seen->add('marta');
$seen->add('ada');
$seen->add('kofi');
$seen->add('ada');

// A set gives its members in the order you added them, and keeps each one once.
// This prints 3.
array<string> $names = Core\Arr::from($seen);
echo Core\Arr::count($names), "\n";

// `Core\Arr::sort` needs every value at once, which is why the array above is made
// first. This prints ada, kofi and marta.
foreach (Core\Arr::sort($names) as string $name) {
    echo $name, "\n";
}
```

```output
3
ada
kofi
marta
```

# What does not exist

PHP's iteration helpers do not exist in Novis. Naming one is a compile error.

There is no `ArrayAccess`, `Countable`, `IteratorAggregate`, `Traversable` or `Generator`, and no
`iterator_to_array`, `count`, `current`, `next` or `reset`. Each one has a replacement. A class
becomes walkable by implementing `Iterable<T>` or `Iterator<T>`. A generator returns an
`Iterator<T>`, so it needs no class of its own. `Core\Arr` holds what the free functions did:
`Core\Arr::count` counts, and `Core\Arr::from` reads a sequence into an array. Reading an element of
an object, `$basket[0]`, has no interface behind it. Give the class a method and name it yourself.

**Good to know:** you meet all of these when you compile, never while the program is running.

**The examples below** show the three replacements: `Iterable<T>` for `IteratorAggregate`, `Core\Arr`
for the free functions, and methods of your own for `ArrayAccess` and `Countable`. The last two
examples show `Countable` and `iterator_to_array` as compile errors.

`Countable`, `ArrayAccess`, `IteratorAggregate`, `Traversable` and `Generator` are not declared. A
class that implements one, or a parameter of one of these types, is the error `E0303`. The message
names no replacement.

`iterator_to_array`, `iterator_count`, `count`, `current`, `next`, `reset` and `array_walk` are not
functions. A call to one is the error `E0320`.

`$obj[0]` on an object is the error `E0482`, for a read and for a write. Only an array can be read
with `[ ]`.

A `foreach` loop over an object that implements neither `Iterable<T>` nor `Iterator<T>` is the error
`E0443`. A method named `getIterator` does not change this. A loop never reads an object's
properties.

## Example 01: iterable in place of iteratoraggregate

```nvs
<?nvs
// Shows the replacement for PHP's `IteratorAggregate` and `Traversable`. A class becomes
// walkable by implementing `Iterable<T>` and writing one method, `iterate()`.

class Playlist implements Iterable<string>
{
    private array<string> $tracks = [];

    public function add(string $title): void
    {
        $this->tracks[] = $title;
    }

    // This replaces `getIterator()`. The return type names what the loop reads.
    public function iterate(): Iterator<string>
    {
        foreach ($this->tracks as string $title) {
            yield $title;
        }
    }
}

var $playlist = new Playlist();
$playlist->add('Blue in Green');
$playlist->add('So What');

// The object is now a subject a `foreach` loop accepts.
foreach ($playlist as string $title) {
    echo $title, "\n";
}
```

```output
Blue in Green
So What
```

## Example 02: core arr in place of the free functions

```nvs
<?nvs
// Shows the replacements for PHP's `iterator_to_array` and `count`. Both live on `Core\Arr`,
// so there is no free function to call.

class Series
{
    public static function squares(int $upTo): Iterator<int>
    {
        int $i = 1;
        while ($i <= $upTo) {
            yield $i * $i;
            $i = $i + 1;
        }
    }
}

// `Core\Arr::from` reads a sequence into an array. This replaces `iterator_to_array`.
array<int> $squares = Core\Arr::from(Series::squares(5));
echo $squares[0], ',', $squares[4], "\n";

// `Core\Arr::count` returns the number of elements. This replaces `count`.
echo Core\Arr::count($squares), "\n";
```

```output
1,25
5
```

## Example 03: methods of your own in place of arrayaccess

```nvs
<?nvs
// Shows a real use: a basket that PHP would give `ArrayAccess` and `Countable`. Novis has
// neither interface, so the class names its own methods. A reader of this code sees what
// each one does without looking the interface up.

class Line
{
    public function constructor(public string $sku, public int $quantity)
    {}
}

class Basket implements Iterable<Line>
{
    private array<Line> $lines = [];

    public function put(string $sku, int $quantity): void
    {
        $this->lines[] = new Line($sku, $quantity);
    }

    // This replaces `offsetGet`, and the name says which line it returns.
    public function lineAt(int $position): Line
    {
        return $this->lines[$position];
    }

    // This replaces `count`, and it returns the number of lines.
    public function size(): int
    {
        return Core\Arr::count($this->lines) as int;
    }

    public function iterate(): Iterator<Line>
    {
        foreach ($this->lines as Line $line) {
            yield $line;
        }
    }
}

var $basket = new Basket();
$basket->put('COFFEE-1KG', 2);
$basket->put('FILTER-100', 1);

// This prints 2 lines, then COFFEE-1KG.
echo $basket->size(), " lines\n";
echo $basket->lineAt(0)->sku, "\n";

foreach ($basket as Line $line) {
    echo $line->sku, ' x', $line->quantity, "\n";
}
```

```output
2 lines
COFFEE-1KG
COFFEE-1KG x2
FILTER-100 x1
```
