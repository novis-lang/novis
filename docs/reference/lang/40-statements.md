# Expression statements, blocks and declarations

A statement is one step of a program. Most statements are an expression followed by `;`: a call, an
assignment, an `echo`. The value is thrown away, and the work still happens. A `;` on its own is an
empty statement.

A declaration is a statement too. Write the type, or write `var` and the type comes from the value.
A variable belongs to the whole function, so each name is declared once.

Braces `{ … }` group statements into a block. A block does not open a new scope. You may read a
variable only where every path has given it a value. A variable assigned in one branch of an `if`
is readable after the `if` when every branch assigns it.

**The examples below** show the statements, a variable declared before its value is
known, and a program that prices an order. The last one reads a variable that only one branch
declares, and does not compile.

A variable is declared once in a function. A second declaration of the same name does not compile: it
is the error `E0406`. This is also true inside a block, and for the variable of a second `for` loop.

A declaration inside a loop body is one statement. It runs on every round of the loop, and it gives the
variable its first value again each time.

A variable declared inside one branch of an `if` has no value on the other paths. Reading it after the
`if` does not compile: it is the error `E0301`.

## Example 01: the statements a program is made of

```nvs
<?nvs
// Shows the kinds of statement a program is made of: a declaration, an
// assignment, a call written for what it does, and an empty statement.

class Report
{
    // Prints one line and returns how many characters it printed.
    public static function line(string $text): uint
    {
        echo $text, "\n";
        return Core\Str::length($text);
    }
}

// A declaration is a statement. It gives `$total` a type and a first value.
int $total = 0;

// An assignment followed by `;` is a statement.
$total = $total + 7;

// This call is a statement. The program runs it for what it prints, and the
// number it returns is thrown away.
Report::line('counted');

// A `;` on its own is an empty statement. It does nothing.
;

// This prints 7.
echo $total, "\n";
```

```output
counted
7
```

## Example 02: declaring a variable before its value is known

```nvs
<?nvs
// Shows the two ways to declare a variable, and how to declare one before you
// know its value.

// A declaration names the type. `$attempts` is a whole number from here on.
int $attempts = 3;

// `var` takes the type from the value on the right, so `$service` is a string.
var $service = 'payments';

// You can declare a variable without a value. You may read it only after every
// path has given it one, so both branches below assign it.
string $plan;
if ($attempts > 1) {
    $plan = 'retry';
} else {
    $plan = 'give up';
}

// Braces group statements into a block. A block does not open a new scope, so
// `$wait` is still there after the closing brace.
{
    int $wait = $attempts * 2;
}

// This prints: payments: retry after 6 seconds
echo $service, ': ', $plan, ' after ', $wait, " seconds\n";
```

```output
payments: retry after 6 seconds
```

## Example 03: pricing an order step by step

```nvs
<?nvs
// Shows these statements in a program that prices an order: a variable
// declared before its price is known, a call written for what it records, and
// a block that groups one step.

class Audit
{
    // Writes one line about a decision and returns whether it was written.
    public static function note(string $text): bool
    {
        echo 'audit: ', $text, "\n";
        return true;
    }
}

array<int> $order = ['items' => 4, 'weight' => 1200];

// The shipping price is not known yet. Every branch below gives it a value, so
// it can be read after the `if`.
int $shipping;
if ($order['weight'] > 1000) {
    $shipping = 900;
    // The result of this call is thrown away. The line is still written.
    Audit::note('heavy parcel');
} elseif ($order['items'] > 3) {
    $shipping = 400;
    Audit::note('more than three items');
} else {
    $shipping = 250;
}

// The block groups the discount step. `$discount` can be read after it,
// because a block does not open a new scope.
{
    int $discount = 0;
    if ($shipping > 500) {
        $discount = 100;
    }
}

// This prints 800.
echo $shipping - $discount, "\n";
```

```output
800
```

# `if`, `elseif`, `else`

`if` runs a block of code when its condition is true. `else` gives the block that runs when it is
not. `elseif` adds a further condition to test in between. You may write `else if` instead, and the
two are the same.

The arms are tested from top to bottom, and only the first one whose condition is true runs. `else`
comes last and takes everything the arms above it did not.

The condition is any expression, and it does not have to be a `bool`. The value is read as a
condition: `0`, `0.0`, `""`, `"0"`, `[]`, `null` and `false` count as false, and every other value
counts as true.

A body of one statement needs no braces. `if ($n > 1) echo "big\n";` is allowed. Braces around every
body are still the safer habit.

**The examples below** show a chain that picks one arm, then conditions that are not `bool` values,
then a shipping price worked out from several rules in order.

## Example 01: picking one arm of a chain

```nvs
<?nvs
// Shows an `if`/`elseif`/`else` chain. The arms are tested from top to bottom,
// and only the first one whose condition is true runs.

class Band
{
    public static function of(int $score): string
    {
        if ($score >= 90) {
            return 'excellent';
        } elseif ($score >= 75) {
            return 'good';
        } elseif ($score >= 50) {
            return 'pass';
        } else {
            return 'fail';
        }
    }
}

array<int> $scores = [95, 80, 60, 20];

foreach ($scores as int $score) {
    // This prints one line per score: 95 excellent, 80 good, 60 pass, 20 fail.
    echo $score, ' ', Band::of($score), "\n";
}
```

```output
95 excellent
80 good
60 pass
20 fail
```

## Example 02: a condition that is not a bool

```nvs
<?nvs
// Shows conditions that are not `bool` values. The value is read as a
// condition, so an empty array, an empty string and the number 0 are false.

array<string> $names = [];
if ($names) {
    echo "there are names\n";
} else {
    // This line runs. An empty array counts as false.
    echo "no names yet\n";
}

int $unread = 0;
if ($unread) {
    echo "you have unread messages\n";
} else {
    // This line runs. The number 0 counts as false.
    echo "your inbox is empty\n";
}

// The text "0" counts as false as well. Test the length when you mean
// "this text is not empty".
string $answer = '0';
if ($answer) {
    echo "the answer counts as true\n";
} elseif (Core\Str::length($answer) > 0) {
    // This line runs.
    echo "the answer is not empty, and it still counts as false\n";
}
```

```output
no names yet
your inbox is empty
the answer is not empty, and it still counts as false
```

## Example 03: working out a shipping price

```nvs
<?nvs
// Shows several rules tested in order, the way a program works out a price.
// The first rule that fits decides, so the order of the arms is part of the
// rules. Prices here are in cents.

class Shipping
{
    public static function priceFor(string $country, int $grams, bool $isMember): int
    {
        if ($isMember && $grams <= 2000) {
            return 0;
        } elseif ($country != 'DE') {
            return 1490;
        } elseif ($grams > 10000) {
            return 990;
        } elseif ($grams > 2000) {
            return 590;
        }
        return 390;
    }
}

// This prints 0. The member rule is first, so it wins over every rule below it.
echo Shipping::priceFor('DE', 800, true), "\n";
// This prints 1490. A parcel outside Germany takes the same price at any weight.
echo Shipping::priceFor('FR', 800, false), "\n";
// This prints 990.
echo Shipping::priceFor('DE', 12000, false), "\n";
// This prints 390. No arm matched, so the line after the chain decides.
echo Shipping::priceFor('DE', 800, false), "\n";
```

```output
0
1490
990
390
```

# `while` and `do … while`

`while (condition) { … }` runs its body again and again for as long as the condition is true. The
condition is tested first, so a condition that is false at the start means the body never runs.

`do { … } while (condition);` runs the body first and tests the condition afterwards. The body
therefore always runs at least once. Note the semicolon after the closing bracket.

`break` leaves the loop. `continue` skips the rest of the body and goes to the next test. In a
`do … while` loop, `continue` goes to the test at the bottom, and does not restart the body.

The condition is read the same way an `if` condition is. It does not have to be a `bool`.

Use `while` when you do not know how many rounds you need, such as reading until nothing is left.
Use a `for` or a `foreach` loop when you are counting or walking a collection.

**The examples below** show a `while` loop that drains a queue of work, then a `do … while` loop
that always runs once, then a retry that stops on success or after a limit.

## Example 01: working through a list until it is empty

```nvs
<?nvs
// Shows a `while` loop. The condition is tested before every round, including
// the first one, so a list that is already empty means no round at all.

class Queue
{
    public static function drain(array<string> $jobs): int
    {
        int $done = 0;
        int $at = 0;
        while ($at < Core\Arr::count($jobs)) {
            echo 'running ', $jobs[$at as string], "\n";
            $done = $done + 1;
            $at = $at + 1;
        }
        return $done;
    }
}

array<string> $jobs = ['backup', 'send mail', 'clean up'];
// This prints one line per job, then 3.
echo Queue::drain($jobs), "\n";

array<string> $none = [];
// This prints 0. The condition was false at the start, so the body never ran.
echo Queue::drain($none), "\n";
```

```output
running backup
running send mail
running clean up
3
0
```

## Example 02: asking once before testing anything

```nvs
<?nvs
// Shows `do … while`. The body runs before the condition is tested, so it
// always runs at least once. Note the semicolon after the closing bracket.

// A page of results is fetched, and another page only while a full one came
// back. The first page is always fetched.
class Pages
{
    public static function sizeOf(int $page): int
    {
        if ($page < 3) {
            return 100;
        }
        return 12;
    }
}

int $page = 1;
int $rows = 0;
int $size = 0;
do {
    $size = Pages::sizeOf($page);
    $rows = $rows + $size;
    echo 'page ', $page, ' gave ', $size, " rows\n";
    $page = $page + 1;
} while ($size == 100);

// This prints 212.
echo $rows, "\n";

// The same loop written with `while` would fetch nothing here, because the
// condition is false from the start.
int $count = 0;
do {
    $count = $count + 1;
} while (false);
// This prints 1.
echo $count, "\n";
```

```output
page 1 gave 100 rows
page 2 gave 100 rows
page 3 gave 12 rows
212
1
```

## Example 03: trying again until it works or the limit is reached

```nvs
<?nvs
// Shows a `while` loop with two ways to end: the work succeeded, or the limit
// was reached. A program does this around a call that sometimes fails.

class Upload
{
    // Fails on the first two attempts and succeeds on the third.
    public static function send(int $attempt): bool
    {
        return $attempt >= 3;
    }
}

int $attempt = 0;
bool $sent = false;

while ($sent == false && $attempt < 5) {
    $attempt = $attempt + 1;
    $sent = Upload::send($attempt);
    if ($sent) {
        echo 'sent on attempt ', $attempt, "\n";
    } else {
        echo 'attempt ', $attempt, " failed\n";
    }
}

if ($sent == false) {
    echo 'gave up after ', $attempt, " attempts\n";
}

// This prints 3.
echo $attempt, "\n";
```

```output
attempt 1 failed
attempt 2 failed
sent on attempt 3
3
```

# `for`

A `for` loop counts. Its header has three parts, separated by semicolons: where the counter starts,
how long the loop runs, and how the counter changes after every round. `for (var $i = 0; $i < 10;
$i++)` runs the body while `$i` is below 10.

The first part is either one new variable, or assignments to variables declared above the loop. The
second and third parts may each be a list separated by commas. Any part may be empty, and `for (;;)`
runs until a `break`.

The counter belongs to the function, not to the loop. After the loop, it has the value that ended
it. A second loop in the same function needs a different name. `continue` runs the third part before
the next test.

**The examples below** show a `var` counter, two counters that meet in the middle, `uint` counters,
a `for (;;)` loop, and a header that does not compile.

The first part of the header declares one variable at most. `for (int $a = 0, int $b = 0; …)` is
the error `E0125`. Declare the second variable above the loop.

The first part is either one declaration or a list of expressions. It cannot have both. `for (var $i
= 0, $j = 1; …)` is the error `E0124`.

The second part can be a list separated by commas. Before each test, the loop runs every expression
in the list. The last expression decides if the loop runs again. The expressions before it also run
on the test that ends the loop.

Two loops in one function cannot declare the same counter. The second declaration is the error
`E0406`.

## Example 01: numbering every line of a list

```nvs
<?nvs
// Shows the three parts of a `for` header: where the counter starts, how long
// the loop runs, and how the counter changes after every round.

var $steps = ['unpack the archive', 'check the files', 'install'];

// `var $i = 0` declares the counter. It is an `int`, the type of `0`.
for (var $i = 0; $i < Core\Arr::count($steps); $i++) {
    // The counter is also the position in the array.
    echo $i + 1, '. ', $steps[$i], "\n";
}

// You can read the counter after the loop. It holds the value that ended the
// loop, so this prints 3.
echo $i, "\n";
```

```output
1. unpack the archive
2. check the files
3. install
3
```

## Example 02: walking a list from both ends

```nvs
<?nvs
// Shows a loop with two counters. The first and the third part of the header
// are lists separated by commas, so both counters start and move together.

array<string> $names = ['Ada', 'Grace', 'Alan', 'Edsger'];

uint $front = 0;
uint $back = 0;

for ($front = 0, $back = Core\Arr::count($names) - 1; $front < $back; $front++, $back--) {
    string $keep = $names[$front];
    $names[$front] = $names[$back];
    $names[$back] = $keep;
}

// The counters meet in the middle, and every pair has changed places. This
// prints ["Edsger","Alan","Grace","Ada"].
```


## Example 03: sending rows in batches

```nvs
<?nvs
// Shows a counter that moves by more than one. A program does this to send a
// long list in batches, because one request per row would be too many requests.

class Store
{
    // Writes one batch and returns how many rows it held.
    public static function write(array<int> $rows): uint
    {
        echo 'writing ', Core\Json::encode($rows), "\n";
        return Core\Arr::count($rows);
    }
}

array<int> $ids = [11, 12, 13, 14, 15, 16, 17];
uint $total = Core\Arr::count($ids);
uint $written = 0;

// The counters write their type, `uint`, in place of `var`. A `uint` is never
// negative, and neither is a position in a list.
for (uint $start = 0; $start < $total; $start = $start + 3) {
    array<int> $batch = [];
    // The inner loop stops at the end of the batch or at the end of the list,
    // whichever comes first.
    for (uint $at = $start; $at < $start + 3 && $at < $total; $at++) {
        $batch[] = $ids[$at];
    }
    $written = $written + Store::write($batch);
}

// Seven rows do not divide into batches of three, so the last batch is
// shorter. This prints 7.
echo $written, "\n";
```

```output
writing [11,12,13]
writing [14,15,16]
writing [17]
7
```

# `foreach`

`foreach` visits every element of an array, a generator or any object you can iterate. Write
`foreach ($subject as var $value)`, and the body runs once for each element.

`var` gives the variable the type of the subject's values. Over an array you may get the key too,
with `var $key => var $value`. The key is always a `string`. You can write the type in place of
`var`, as in `string $key => int $value`, and the compiler checks it. A variable with neither does
not compile.

The value variable is a copy. With `inout`, as in `foreach ($rows as inout var $row)`, each element
goes back into the array when the body ends. The syntax `&$value` does not compile. A plain
loop walks a copy of the array, so adding or removing elements in the body does not change what
it visits.

**The examples below** show values, then keys with values, then `inout`, each with `var` first and
a written type after. Then come a loop over what a function returns, a generator, a wider type, and
two loops that do not compile.

One header can use `var` for one variable and a written type for the other. A variable without
either is the error `E0101`.

`var` on the value keeps every qualifier of the element type. Over an `array<tainted string>`, the
value variable is a `tainted string`.

A written type can be wider than the element type. Write `int|float $v` over an `array<int>` if the
body stores a `float` in `$v`. The compiler checks that each element fits the written type.

A generator, an `Iterator<T>` and an `Iterable<T>` give values of type `T` and have no key. A key
variable over one of them is the error `E0444`.

The word `as` in the header belongs to `foreach`. To convert the subject, put the conversion in
parentheses: `foreach (($m as array<int>) as var $v)`. A `mixed` subject without a conversion is the
error `E0443`.

An array literal can be the subject when the value variable uses `var`. All its elements need the
same type. Elements of different types are the error `E0414`, and so is an empty array `[]`. With a
written type, an array literal does not compile. Put it in a typed variable first.

An `inout` loop walks the array itself. An element that the body adds at the end is visited too.

A later `foreach` in the same function can declare the same variable again with the same type. With
another type, the second declaration is the error `E0406`.

## Example 01: adding up the values of an array

```nvs
<?nvs
// Shows the simplest `foreach`. The body runs once for each element of the array.

var $lineTotals = ['shirt' => 1990, 'socks' => 450, 'belt' => 2500];
var $sum = 0;

// `var $cents` gets the type of the array's values, so `$cents` is an `int`.
foreach ($lineTotals as var $cents) {
    $sum = $sum + $cents;
}

// This prints 4940. Prices here are in cents.
echo $sum, "\n";

// The array can also be written in the loop header. All its values are strings,
// so `$tag` is a `string`.
foreach (['new', 'sale', 'last one'] as var $tag) {
    echo '[', $tag, '] ';
}
echo "\n";

// You can write the type in place of `var`. The compiler checks that the array
// contains that type, and the reader sees the type in the loop header.
int $largest = 0;
foreach ($lineTotals as int $cents) {
    if ($cents > $largest) {
        $largest = $cents;
    }
}

// This prints 2500.
echo $largest, "\n";
```

```output
4940
[new] [sale] [last one]
2500
```

## Example 05: walking a generator

```nvs
<?nvs
// Shows `foreach` over a generator. The function returns an `Iterator<int>`,

class Pages
```

## Example 06: a wider type and a converted subject

# `switch`

`switch (value) { … }` compares one value with a list of labels and runs the body of the first label
that is equal to it. Each label is written as `case something:`, and `default:` is what runs when no
label matched. Nothing happens when no label matched and there is no `default`.

A body runs on into the next body until a `break` stops it. That is called falling through, and it
lets several labels share one body: write them one under the other, with nothing in between. A body
that ends with `return` also leaves the `switch`.

The labels are tried in the order you wrote them, and `default` is tried last wherever you put it.
`switch (true)` compares against `true`, so every label is a condition, and the first condition that
is true is the one that runs.

**The examples below** show a choice between three answers, then labels that share a body, then
`switch (true)` sorting a number into bands, then a `default` between two labels.

`switch` compares the value with each label using `==`. A label whose type can never be equal to the
value is the error `E0466`. An `int` value with the label `"5"` is one such case.

A body falls through into the body written after it, even when that is `default`. `default` is
still tried last, after every `case`. When it matches, the bodies after it run too, until a
`break`.

## Example 01: choosing one answer out of several

```nvs
<?nvs
// Shows a `switch` that picks one answer out of several. The subject is
// compared with each `case` in order, and `default` runs when none matched.

array<string> $statuses = ['new', 'sent', 'lost'];

foreach ($statuses as string $status) {
    string $text = '';
    switch ($status) {
        case 'new':
            $text = 'waiting to be packed';
            break;
        case 'sent':
            $text = 'on its way';
            break;
        default:
            $text = 'we do not know';
    }
    echo $status, ': ', $text, "\n";
}
```

```output
new: waiting to be packed
sent: on its way
lost: we do not know
```

## Example 02: two labels that share one body

```nvs
<?nvs
// Shows labels that share a body, and a body without `break`. A body without
// `break` runs on into the next body, which is called falling through.

array<string> $keys = ['a', 's', 'q'];

foreach ($keys as string $key) {
    echo $key, ': ';
    switch ($key) {
        case 'a':
        case 's':
            echo 'saving';
            break;
        case 'q':
            echo 'saving, ';
        // There is no `break` here, so the next body runs as well.
        default:
            echo 'leaving';
    }
    echo "\n";
}
```

```output

q: saving, leaving
```

# `break` and `continue`

`break` stops a loop immediately. `continue` skips the rest of the current iteration and starts the
next one.

Both act on the loop closest to them. Inside a `switch`, `break` leaves the `switch`, and a plain
`continue` starts the next iteration of the loop around it, because a `switch` has no iterations of
its own.

Write a number after either word to leave more than one level at once. `break 2` leaves the loop
around the loop you are in. Levels count from 1 at the closest statement, and every loop and every
`switch` is one level. The number has to be written directly in the code, so a variable is not
allowed there.

**Good to know:** a level with no matching loop or `switch` does not compile. A wrong number is an
error you see before the program runs.

**The examples below** take these in turn: a search that stops at the first match, a loop that skips
the rows it does not want, and an order check that leaves two loops at once. The last two show a
`switch` inside a loop, and a `continue` that does not compile.

Inside a `switch` that is inside a loop, `continue`, `continue 1` and `continue 2` do the same thing.
Each one starts the next iteration of the loop.

`break 1` is the same as `break`, and `continue 1` is the same as `continue`. The smallest level is 1,
so `break 0` does not compile.

These programs do not compile, because no statement matches the level:

- `break` or `continue` outside any loop or `switch`.
- `continue` inside a `switch` with no loop around it.
- `break 3` inside only one loop.

## Example 01: stopping a search at the first match

```nvs
<?nvs
// Shows how `break` stops a loop as soon as the work is done. This loop looks
// for the first reading above 100 and stops there.

int $found = 0;
foreach ($readings as int $reading) {
    if ($reading > 100) {
        $found = $reading;
        break;
    }
    echo 'checked ', $reading, "\n";
}

// The loop stopped at 140 and never read the two values after it.
// This prints 140.
echo 'first above 100: ', $found, "\n";
```

```output

checked 40
checked 96
first above 100: 140
```


# `return`

`return $value;` leaves the method it is in and gives the value to whoever called the method. The
lines after it do not run, and neither does the rest of any loop it is inside. A method may have as
many `return` statements as you need, and the first one that runs ends the method.

The value has to fit the return type the method declares. A method declared `void` gives nothing
back, so its `return` carries no value and is written `return;` alone. Writing a value there does
not compile.

`return` also works outside any method, at the top level of a file. There it ends the file. In the
file you started, that ends the program.

**The examples below** show a method that returns as soon as it has found what it was looking for,
then a `void` method that ends early, then a program that stops because it has nothing to do. The
last one shows a `void` method with a value in its `return`, which does not compile.

A method with a return type other than `void` needs a value in every `return`. In such a method,
`return;` alone does not compile.

Every way through such a method has to end with a `return` or a `throw`. If one way reaches the end of
the method body, the program does not compile.

A file that another file loads with `require` can end with `return $value;` at its top level. The
`require` expression then gives that value.

## Example 01: giving a value back to the caller

```nvs
<?nvs
// Shows `return`, which leaves a method and gives a value back to the caller.
// The first `return` that runs ends the method, so the loop stops there.

class Basket
{
    // Gives the first price over the limit, or 0 when there is none.
    public static function firstOver(array<int> $prices, int $limit): int
    {
        foreach ($prices as int $price) {
            if ($price > $limit) {
                return $price;
            }
        }
        return 0;
    }
}

array<int> $prices = [300, 1200, 4500];

// This prints 1200. The method ends at the first price over 1000, so 4500 is
// never looked at.
echo Basket::firstOver($prices, 1000), "\n";

// This prints 0. No price is over 9000, so the last line of the method runs.
echo Basket::firstOver($prices, 9000), "\n";
```

```output
1200
0
```

# `catch` as an expression

`catch` written after an expression gives that expression a value to fall back on when it throws an
error. It saves writing a whole `try` block for one value.

Write the expression, then `catch (SomeError $e) => fallback`. If the expression runs normally, its
own value is the result. If it throws an error the arm matches, the arm's value is the result. You
may write several arms after one expression; they are tried in order, and the first class that
matches wins. An error no arm matches keeps travelling, as it would without the `catch`. An arm
holds an expression, so `throw` is allowed there and `return` is not.

**Good to know:** `catch (Throwable) => value` with no variable and no `throw` gives a warning. It
hides every error, including the ones you never thought about.

**The examples below** show a fallback for a row that is missing, then several arms tried in order,
then a report line whose division is guarded and a low-level error replaced by a clear one. The last
two show the type of the result, and a `return` in an arm that does not compile.

Every arm checks the error that the expression on the left threw. In `f() catch (LogicError $a) => x
catch (IOError $b) => y`, the `IOError` arm does not check `x`.

An arm for a parent class that is written before an arm for its subclass matches first. The later
arm never runs. This compiles without a warning.

`catch` covers everything to its left up to an assignment. In `$x = $a / $b catch (ArithmeticError
$e) => 0`, it covers the whole division. It also covers a whole `?:` and a whole `??` chain.

The variable is optional: `catch (IOError) => 0` is allowed. An arm names one class.
`catch (IOError | LogicError $e)` does not compile: it is the error `E0245`.

An arm's variable can only be used inside that arm. After the arm, you may declare the same name
again. The name must not already be a variable of the function when the arm starts: that is the
error `E0406`.

The type of the result includes the type of the expression and the type of every arm. If `get`
returns `int` and an arm gives `null`, the result is `?int`. Writing that result into an `int`
variable does not compile: it is the error `E0401`. An arm that throws adds nothing to the type.

`return`, `break` and `continue` in an arm do not compile: that is the error `E0126`.

This form has no `finally`. When the error leaves the expression, the `finally` block of the `try`
around it runs as usual.

The warning for `catch (Throwable) => value` is `W1006`. An arm with a variable does not get it.

## Example 01: a fallback when a row is missing

```nvs
<?nvs
// Shows how a `catch` arm after an expression supplies a fallback value.
// `Repo::price` throws when it has no row for a product.

class Repo
{
    public static function price(string $sku): int
    {
        if ($sku == 'lamp') {
            return 1200;
        }
        throw new IOError('no row for ' . $sku);
    }
}

// The lookup worked, so the result is the call's own value. This prints 1200.
echo Repo::price('lamp') catch (IOError $missing) => 0, "\n";

// The lookup threw, so the result is the arm's value. This prints 0.
echo Repo::price('ring') catch (IOError $missing) => 0, "\n";

// The arm can read the error it caught. This prints `no row for ring`.
echo Repo::price('ring') catch (IOError $e) => $e->message, "\n";
```

```output
1200
0
no row for ring
```

```nvs

// the first class that matches wins. The arms belong to the expression on the
// left, not to each other.

class Field

    {

            throw new LogicError('the field is empty');
        }

            throw new IOError('the field is unreadable');
        }
        return 42;

}

    echo Field::toAmount('') catch (IOError $io) => -2, "\n";
} catch (LogicError $left) {
    echo 'left the expression: ', $left->message, "\n";
```

# `echo`, `print`, `unset`, `exit`, `yield`

`echo`, `print`, `unset`, `exit` and `yield` are five short statements: they write output, remove an
array entry, end the program, and produce values one at a time.

`echo a, b, c;` writes several values in order with nothing between them. `print $value;` writes one
value, and its result is `1`. Both turn a value into text the same way `.` does: `true` writes `1`,
and `false` and `null` write nothing.

`unset($a["k"]);` removes that entry from the array `$a`, and nothing else. Every variable and every
property in Novis always has a value, so `unset($x)` and `unset($o->p)` do not compile. Assign `null`
instead, where the type allows it.

`exit;` ends the program with status 0. `exit(3);` ends it with status 3, and `exit("bye")` writes the
text and then ends with status 0.

`yield $value;` goes inside a method that returns `Iterator<T>`. It sends one value to the loop that
reads it. A `yield` is a statement, so `$x = yield 1;` does not compile.

**The examples below** show `echo` and `print`, then `unset` on array entries, then a check that
reads rows with `yield` and stops with `exit`. The last one is an `unset` that does not compile.

One `unset` can remove several entries: `unset($a["k"], $a["j"]);`. Removing a key that is not in
the array does nothing. The entries after a removed one keep their keys.

`unset($x)` on a variable does not compile: it is the error `E0234`. `unset($o->p)` on a property
does not compile either: that is the error `E0413`.

`exit("bye")` writes the text to standard output. `exit` is also an expression, so
`int $n = $value ?? exit(4);` ends the program with status 4 when `$value` is `null`.

`yield` outside a generator does not compile: it is the error `E0445`. A method that contains `yield`
must return `Iterator<T>`, or it is the error `E0446`.

`yield from` does not exist: it is the error `E0448`. Write a `foreach` loop that yields each value
instead.

## Example 01: writing values with echo and print

```nvs
<?nvs
// Shows how `echo` and `print` write values. `echo` takes several values at
// once and writes them in order with nothing between them.

string $name = 'Ada';
int $orders = 3;

// This prints: Ada has 3 orders
echo $name, ' has ', $orders, ' orders', "\n";

// `print` writes one value.
print "report finished\n";

// A value becomes text the same way `.` does. `true` writes `1`, and `false`
// and `null` write nothing, so this line prints 1|||
echo true, '|', false, '|', null, '|', "\n";
```

```output
Ada has 3 orders
report finished
1|||
```

## Example 02: removing the entries you are done with

```nvs
<?nvs
// Shows how `unset` removes entries from an array. Only an array entry can be
// removed. A variable always has a value in Novis, so `unset($x)` does not
// compile.

array<int> $stock = ['apple' => 4, 'pear' => 0, 'plum' => 7, 'fig' => 0];

// One call removes several entries. This prints {"apple":4,"plum":7}
unset($stock['pear'], $stock['fig']);
echo Core\Json::encode($stock), "\n";

array<int> $counts = [10, 20, 30];

// Removing an entry in the middle leaves a gap. The entries after it keep the
// keys they had, so this prints {"0":10,"2":30}
unset($counts[1]);
echo Core\Json::encode($counts), "\n";

// Removing a key that is not in the array does nothing, and is not an error.
// There are still 2 entries.
unset($counts[99]);
echo Core\Arr::count($counts), "\n";
```

```output
{"apple":4,"plum":7}
{"0":10,"2":30}
2
```

## Example 03: ending a check at the first bad row

```nvs
<?nvs
// Shows a small check program. It reads rows one at a time with `yield`,
// writes a line for each good row, and ends with `exit` at the first bad one.

class Rows
{
    // Each `yield` sends one row to the loop below.
    public static function all(): Iterator<string>
    {
        yield 'ada,42';
        yield 'grace,17';
        yield 'broken row';
        yield 'alan,9';
    }
}

foreach (Rows::all() as string $row) {
    if (Core\Str::contains($row, ',') == false) {
        // `exit` with a text writes it and ends the program with status 0.
        // The rows after this one are never read.
        exit('stopped at a bad row: ' . $row . "\n");
    }
    echo 'ok: ', $row, "\n";
}

echo "every row is good\n";
```

```output
ok: ada,42
ok: grace,17
stopped at a bad row: broken row
```

# Statement forms that do not parse

Novis reads PHP syntax, but not all of it. A few PHP statement forms do not parse. For most of them, the
compiler error names what to write instead.

`goto` and its labels are gone: use a loop, an early `return`, or a flag. `declare(strict_types=1)`
is not needed, because every Novis file is strict already. The alternative syntax `if (…): … endif;`
is not accepted: write braces. Instead of `global $x;`, pass the value as a parameter, or keep it in
a `private static` property. That property is also what replaces a `static` variable inside a
function. Write `[int $a, int $b] = …` instead of `list($a, $b) = …`, and `require` instead of `include` or
`require_once`. A `class`, `interface`, `enum`, `type`, `namespace`, `use` or `autoload` statement
goes at the top of a file, never inside a body.

**The examples below** show what to write instead of `goto`, instead of `global` and a `static`
variable, and instead of `list()` and the alternative syntax. The last two are a `goto` and an
`if (…): … endif;` that do not compile.

Each form has its own error code:

- `goto` is the error `E0203`.
- `global $x;` is the error `E0204`.
- `static $n = 0;` inside a method is the error `E0209`.
- `list($a, $b) = …` is the error `E0230`.
- `include` and `require_once` are the error `E0221`.
- A `class`, `interface`, `enum`, `type`, `namespace` or `use` statement inside a body is the error
  `E0233`.

A label, `declare(…)` and the alternative syntax give a general syntax error. That error does not
name what to write instead. The alternative syntax is the colon form of `if`, `while`, `for`,
`foreach` and `switch`, with `endif`, `endwhile`, `endfor`, `endforeach` and `endswitch`.

In `[int $a, int $b] = …`, each variable needs its type. `[$a, $b] = …` does not compile, even when
`$a` and `$b` are already declared.

## Example 01: what to write instead of goto

```nvs
<?nvs
// `goto` and its labels do not parse. Shows the three ways to leave a piece of
// work early instead: an early `return`, a `break`, and a flag.

class Orders
{
    // Returns the first total above the limit, or 0 when there is none.
    public static function firstOver(array<int> $totals, int $limit): int
    {
        foreach ($totals as int $total) {
            // An early `return` leaves the method at once.
            if ($total > $limit) {
                return $total;
            }
        }
        return 0;
    }
}

array<int> $totals = [400, 1200, 250, 3000];

// This prints 1200.
echo Orders::firstOver($totals, 1000), "\n";

// `break` leaves a loop. This one stops at the first total below 300.
int $small = 0;
foreach ($totals as int $total) {
    if ($total < 300) {
        $small = $total;
        break;
    }
}

// This prints 250.
echo $small, "\n";

// A flag carries the decision to the statements after the loop.
bool $found = $small > 0;
if ($found) {
    echo "one small order\n";
}
```

```output
1200
250
one small order
```

## Example 02: what to write instead of global and a static variable

```nvs
<?nvs
// `global $x;` and a `static` variable inside a function do not parse. Shows
// what to write instead: a parameter, and a `private static` property.

class Retry
{
    // The count belongs to the class, so it is still there on the next call.
    private static int $attempts = 0;

    // The limit arrives as a parameter. Nothing is read from outside.
    public static function attempt(int $limit): bool
    {
        self::$attempts = self::$attempts + 1;
        return self::$attempts <= $limit;
    }

    public static function attempts(): int
    {
        return self::$attempts;
    }
}

int $round = 0;
while ($round < 3) {
    // The first two calls are allowed, the third is not.
    if (Retry::attempt(2)) {
        echo 'attempt ', Retry::attempts(), ": allowed\n";
    } else {
        echo 'attempt ', Retry::attempts(), ": too many\n";
    }
    $round = $round + 1;
}
```

```output
attempt 1: allowed
attempt 2: allowed
attempt 3: too many
```

## Example 03: what to write instead of list and the alternative syntax

```nvs
<?nvs
// `list($a, $b) = …` and the alternative syntax `if (…): … endif;` do not
// parse. Shows the two replacements in a program that reads contact lines.

array<string> $lines = ['Ada Lovelace|ada@example.com', 'Grace Hopper|'];

foreach ($lines as string $line) {
    // Brackets replace `list()`. Each name is written with its type, as
    // everywhere else.
    [string $name, string $mail] = Core\Str::split($line, '|');

    // Braces replace `if (…): … endif;`.
    if ($mail == '') {
        echo $name, " has no address\n";
    } else {
        echo $name, ' <', $mail, ">\n";
    }
}
```

```output
Ada Lovelace <ada@example.com>
Grace Hopper has no address
```
