# No colouring: I/O just waits

Novis has no `async`, no `await` on a promise, no `Fiber` and no callback style. A function that
waits is an ordinary function. When it reads a file, sleeps or takes a value from a channel, it
stops the task that called it and returns when the answer is there. The result is the value itself,
with nothing to unwrap, and the lines around the call run in their own order.

The same function works when you call it on its own line and when you call it inside a group of
tasks.

You get concurrency by running several tasks, not by marking functions. While one task waits,
another runs. A task belongs to the call that started it, and that call does not return while any
of its tasks is still running.

**The examples below** show an ordinary function that waits, two tasks taking turns, and a page
that asks for two slow answers at once.

`async`, `await` and `Fiber` are not keywords or classes. `async function` and `await $x` do not
compile, and `new Fiber(…)` is `E0303`.

A task runs until it waits. Two tasks that never wait run one after the other, each from its first
line to its last.

A task may start its own group of tasks. The inner `Core\Task::all` or `Core\Task::map` returns
before the outer task goes on.

What a task prints with `echo` is kept until the group is done. Then each task's output is printed
in the order the tasks were written, not in the order they finished. For `Core\Task::map`, that is
the order of the array. The output of a task that was stopped or that threw is printed too.

A static property has one value, and every task of the program reads and writes that same value.

## Example 01: a function that waits is an ordinary function

```nvs
<?nvs
// Shows that waiting needs no special syntax. `Core\Time::sleep` stops this task
// until the time has passed. The lines around it run one after another, in order.

class Report
{
    public static function rows(): array<string>
    {
        // A real program reads a file or asks a database here. Both of those wait.
        Core\Time::sleep(10ms);
        return ['north', 'south'];
    }
}

echo "asking for the rows\n";

// The result is the array itself. There is nothing to unwrap.
array<string> $rows = Report::rows();

echo 'got ', Core\Arr::count($rows), " rows\n";

foreach ($rows as string $row) {
    echo $row, "\n";
}
```

```output
asking for the rows
got 2 rows
north
south
```

## Example 02: while one task waits another runs

```nvs
<?nvs
// Shows what a wait does inside a group of tasks. `slow` waits 40 milliseconds and
// `quick` waits 5. While `slow` waits, `quick` runs and finishes first. The steps are
// kept in a variable, because a task collects what it prints until the group is done.

class Trace
{
    public static string $steps = '';

    public static function note(string $what): void
    {
        Trace::$steps = Trace::$steps . $what . "\n";
    }
}

Core\Task::all({
    slow: fn(): void => {
        Trace::note('slow starts');
        Core\Time::sleep(40ms);
        Trace::note('slow is done');
    },
    quick: fn(): void => {
        Trace::note('quick starts');
        Core\Time::sleep(5ms);
        Trace::note('quick is done');
    },
});

// Both tasks start, and `quick` is done long before `slow`.
echo Trace::$steps;
```

```output
quick starts
slow starts
quick is done
slow is done
```

```nvs
// Shows a real use: a page needs a customer and their orders, and both answers come
```

# `Core\Task::all`: a fixed set of tasks

`Core\Task::all` runs a fixed set of jobs at the same time and gives you all their results together.

You give it a shape: a value with named fields, written `{rows: …, label: …}`. Each field holds a
function that takes no arguments. `Core\Task::all` returns a shape with the same field names, and
each field has the type that job's function returns. You read `$page->rows` straight away, with no
conversion. A variable of type `callable`, with no signature, gives you `mixed` for that field alone.

`Core\Task::all` returns only when every job has finished, so nothing from the group is still
running afterwards. The subject has to be a shape of functions. An array of functions does not
compile.

**The examples below** show three jobs read by name, the three ways to write a job, a product
page that loads its parts at the same time, and an array of functions that does not compile.

The type of a field in the result is the return type of its function. For `fn(): int => …` it is
`int`. A `fn` with an expression body and no return type gives the type of that expression. A
variable of type `callable`, with no signature, gives `mixed`. A variable of type `callable(): int`
gives `int`.

A field of type `mixed` converted with `as string` is a `tainted string`.

A function that returns `void` gives a `void` field. `echo $r->a` on it is `E0707`.

Reading a field that the shape does not have compiles and throws `RuntimeError` when it runs.

`Core\Task::all({})` has no tasks and returns at once.

Each field must be a function. A field with another value, such as `{a: 1}`, is `E0401`. An array
of functions is `E0401` too.

## Example 01: three jobs read by name

```nvs
<?nvs
// Shows how to run three jobs at the same time. `Core\Task::all` takes one field per
// job and returns one field per result, under the same names.

var $page = Core\Task::all({
    rows:  fn(): array<int> => [10, 20, 30],
    label: fn(): string     => 'orders',
    total: fn(): int        => 60,
});

// Each field already has the type its own function returns, so nothing needs converting.
// This prints orders: 3 rows, 60 in total.
echo $page->label, ': ', Core\Arr::count($page->rows), ' rows, ', $page->total, " in total\n";
```

```output
orders: 3 rows, 60 in total
```


```output
from a variable
```

# `Core\Task::map`: one task per element

`Core\Task::map` calls one function once per element of an array, each call at the same time as the
others, and gives you the results as an array.

The results come back under the input's own keys and in the input's own order. The order the jobs
finished in does not change anything you see. The function receives the value and the key, in that
order, and you may write only the value if the key is not needed. The result is an array of the
type the function returns.

`Core\Task::map` returns only when every element has been handled, so nothing from the group is
still running afterwards. If one job throws, the rest are stopped and the error reaches you at the
call.

**The examples below** show one job per element, a function that reads the key as well, and an
import that checks every row of a file at the same time.

The function may take no parameters, the value, or the value and the key. A third parameter is
`E0401`. The key is always a `string`, so `fn(int $v, int $k)` is `E0401`. The value parameter
must have the type of the array's elements.

The result is an array of the function's return type. `Core\Task::map([1, 2], fn(int $v): int => …)`
returns an `array<int>`.

The function can be written in place, or be a method reference such as `Prices::of(...)`. A
variable of type `callable(int): int` works too. A variable of type `callable`, with no signature,
is `E0401`.

The first argument must be an array. An `Iterator` or a `mixed` value is `E0401`.

An empty array starts no tasks, and the result is an empty array.

## Example 01: one job for every element

```nvs
<?nvs
// Shows how to run one job for every element of an array. `Core\Task::map` calls the
// function once per element, all at the same time, and returns the results as an array.

array<int> $prices = ['apple' => 3, 'pear' => 4, 'plum' => 5];

var $cents = Core\Task::map($prices, fn(int $euros): int => $euros * 100);

// The results keep the input's keys and the input's order.
// This prints apple=300, then pear=400, then plum=500.
foreach ($cents as string $fruit => int $amount) {
    echo $fruit, '=', $amount, "\n";
}
```

```output
apple=300
pear=400
plum=500
```

## Example 02: the function can read the key too

```nvs
<?nvs
// Shows the two parameters the function may take. The first is the element's value.
// The second is its key. You write the second one only when you need it.

array<int> $stock = ['Hamburg' => 12, 'Munchen' => 0, 'Koln' => 7];

// Only the value. This prints 24, 0 and 14.
var $doubled = Core\Task::map($stock, fn(int $count): int => $count * 2);
foreach ($doubled as int $count) {
    echo $count, "\n";
}

// The value and the key. This prints Hamburg has 12, and so on for the other two.
var $lines = Core\Task::map($stock, fn(int $count, string $city): string => $city . ' has ' . $count);
foreach ($lines as string $line) {
    echo $line, "\n";
}
```

```output
24
0
14
Hamburg has 12
Munchen has 0
Koln has 7
```

## Example 03: an import checks every row at once

```nvs
<?nvs
// Shows a real use: an uploaded file has one order per row, and every row has to be
// checked before any of them is saved. No row needs another row, so all of them are
// checked at the same time. The answers come back in the file's own order.

class Row
{
    public static function check(string $line): string
    {
        array<string> $parts = Core\Str::split($line, ',');
        if (Core\Arr::count($parts) != 2) {
            return 'needs two columns';
        }

        if (Core\Str::length($parts[1]) == 0) {
            return 'the amount is empty';
        }

        return 'ok';
    }
}

array<string> $upload = [
    'COFFEE-1KG,2',
    'FILTER-100',
    'MUG-BLUE,',
    'CUP-RED,4',
];

var $verdicts = Core\Task::map($upload, fn(string $line): string => Row::check($line));

// An array's key is always a `string`, so the row number is converted before it is used.
foreach ($verdicts as string $key => string $verdict) {
    echo 'row ', ($key as int) + 1, ': ', $verdict, "\n";
}
```

```output

row 2: needs two columns
row 3: the amount is empty
row 4: ok
```

# `limit` and `deadline`

`Core\Task::all` and `Core\Task::map` both take a second argument with two fields, `limit` and
`deadline`. Both fields are optional, and they are the only two bounds a group of tasks has.

`limit` says how many tasks may run at the same time. The others wait for a free place, and none of
them is refused. Without a `limit`, every task starts at once. A `limit` of `0` throws `LogicError`.

`deadline` is a time limit for the whole call, not for each task. When it passes, every task still
running is stopped. The call waits for those tasks to stop, and then throws `TimeoutError`. A
stopped task runs no more of its own code: not its `catch`, and not the line after the one it was
waiting on.

**The examples below** show a deadline for a whole call, two tasks running at a time, and a price
list that is polite to a slow service.

The options must be written at the call as `{…}`. Options kept in a variable are `E0453`. A field
that is not `limit` or `deadline` is `E0454`, and its help lists the two.

`limit` is a `uint`. `limit: -1` and an `int` variable are `E0401`. A `limit` larger than the
number of tasks is allowed. The waiting tasks start in the order they were written.

`deadline` is a `Core\Time\Duration`, such as `20ms`. A number such as `20` is `E0401`.

The `TimeoutError` message is `Core\Task::map: the deadline expired before every child returned`,
with `Core\Task::all` for that call. `TimeoutError` is a `RuntimeError`. The `LogicError` message
for `limit: 0` starts with `Core\Task::map:` or `Core\Task::all:` too.

`deadline: 0ms` throws `TimeoutError`, even when no task waits.

A stopped task does not run its `finally` blocks either.

A task can start its own group with a shorter deadline, and catch that group's `TimeoutError`. The
outer group then goes on. When the outer deadline passes first, it stops the inner groups too, and
the outer call throws its own `TimeoutError`.

## Example 01: a deadline for the whole call

```nvs
<?nvs
// Shows how to give a group of tasks a time limit. The deadline covers the whole
// call. When it passes, every task still running is stopped and the call throws
// `TimeoutError`.

try {
    Core\Task::all({
        quick: fn(): int => 1,
        slow: fn(): int => {
            Core\Time::sleep(500ms);
            return 2;
        },
    }, { deadline: 20ms });
    echo "both tasks finished\n";
} catch (TimeoutError $late) {
    // This is the line that prints. `slow` needs half a second, and the group has
    // 20 milliseconds.
    echo "the group ran out of time\n";
}
```

```output
the group ran out of time
```

## Example 02: no more than two tasks at a time

```nvs
<?nvs
// Shows how to say how many tasks may run at the same time. There are six tasks
// here, and `limit` lets two of them run at once. The other four wait for a free
// place. None of them is refused.

class Gauge
{
    public static int $running = 0;
    public static int $most = 0;
}

var $results = Core\Task::map(Core\Arr::range(1, 6), fn(int $n): int => {
    Gauge::$running += 1;
    if (Gauge::$running > Gauge::$most) {
        Gauge::$most = Gauge::$running;
    }
    Core\Time::sleep(5ms);
    Gauge::$running -= 1;
    return $n * 10;
}, { limit: 2 });

// This prints 2. Two tasks ran at the same time, and never three.
echo 'most at once: ', Gauge::$most, "\n";
// All six tasks ran, so the last result is 60.
echo 'last result: ', $results[5], "\n";
```

```output
most at once: 2
last result: 60
```


# A child's throw

`Core\Task::all` and `Core\Task::map` run several tasks at the same time. When one task throws an
error, the whole group stops.

The first error wins. The other tasks are cancelled, and none of them is still running when your
`catch` runs. The error you catch is the one the task threw. It has the same class, the same message,
and your own properties if you wrote your own error class. Nothing wraps it.

A cancelled task runs nothing more. Its own `catch` does not run, and neither do the lines after it.

**The examples below** show a group where one task fails, an error class of your own crossing out of a
task, a page that loads three things and reports the one that was missing, and two tasks that throw
before they wait.

A task runs until it waits, for example in `Core\Time::sleep` or a `send` on a full channel. The other
tasks are stopped at the place where they wait. A task that throws before it waits for anything is
not stopped in time. When two tasks throw that way, your `catch` gets the first error. The second
error is printed on standard error as `uncaught in a cancelled sibling: second`, and the program goes
on. With `Core\Task::map`, the first error is the one of the first element.

A stopped task runs none of its own `catch` and `finally` blocks. What it printed before it stopped is
still printed.

The error you catch is the same object the task threw. `==` with a copy the task saved is `true`. A
`catch (Throwable $e)` gets it too, and `$e is LogicError` is still `true` for a `LogicError`.

The `backtrace` of the error has one entry: the task's function, at the line of the `throw`.

A task can start its own group. An error in the inner group passes through the outer group to your
`catch`, and the other tasks of the outer group are stopped too.

When nothing catches the error, the program ends with exit status 1 and the usual error report.

When a `deadline` passes before any task throws, the call throws `TimeoutError`, and the later error
is not thrown.

## Example 01: one task fails and the group stops

```nvs
<?nvs
// Shows what happens when one task in a group throws an error. The group stops
// and your `catch` gets the error that task threw.

class Trace
{
    public static int $finished = 0;
}

try {
    Core\Task::all({
        // This task waits, so the other one throws first.
        slow: fn(): int => {
            Core\Time::sleep(2s);
            Trace::$finished = Trace::$finished + 1;
            return 1;
        },
        quick: fn(): int => {
            throw new RuntimeError('the price list is empty');
        },
    });
    echo "the group finished\n";
} catch (RuntimeError $e) {
    echo 'caught: ', $e->message, "\n";
}

// The slow task was cancelled, so it never reached its last line.
echo Trace::$finished, " tasks finished\n";
```

```output
caught: the price list is empty
0 tasks finished
```

# `Core\Task\Channel<T>`: a bounded queue between tasks

A `Core\Task\Channel<T>` is a queue that one task fills and another empties. You give it a capacity
when you make it, and it holds that many values. `send` puts one value in. If the channel is full,
`send` waits until there is room, so the queue never grows.

You read a channel with a `foreach` loop. It takes the values out one at a time, in the order they
were sent. The loop waits while the channel is empty, and ends once it is empty and closed.

`close` says that no more values are coming. Values already in the queue are still delivered, and
closing twice does nothing. A task that never closes leaves the reading task waiting forever.
Sending into a closed channel stops the program with an error, and so does a capacity of `0`.

**The examples below** show two tasks passing values, what the capacity does, and orders billed
while they are still being read.

The capacity is a `uint`. `-1` and an `int` variable are `E0401`. A capacity of `0` stops the program
with `FATAL: Core\Task\Channel's constructor expected a capacity of at least 1, got 0` and exit
status 1.

You must write the value type. `new Core\Task\Channel(1)` is `E0442`. A `send` of another type is
`E0401`, and so is a `foreach` variable of another type. `foreach ($chan as var $v)` gives `$v` the
channel's value type. A key, as in `foreach ($chan as $k => int $v)`, is `E0444`.

A channel has the methods `send` and `close`. There is no `receive` method (`E0405`). A `foreach` loop
is the way to take values out.

A `send` on a closed channel stops the program with `FATAL: Core\Task\Channel::send was called on a
closed channel` and exit status 1. No `catch` block and no `finally` block runs.

Nothing checks that another task will read or send. A `send` on a full channel with no reader waits
forever. So does a `foreach` on an empty channel that nobody closes. This is true inside a task group
and outside one. A `deadline` on the group stops that wait.

A second `foreach` over a channel that is closed and empty runs nothing.

An object you send is the same object in the reading task. A change the reader makes to it is seen by
the sender.

You can pass a channel to a method. The parameter type is `Core\Task\Channel<int>`, with the value
type.

## Example 01: two tasks pass values through a queue

```nvs
<?nvs
```

```nvs
<?nvs
// Shows a real use: one task reads orders and another writes a receipt for each one.
// The channel holds 2 orders, so the reading task waits for the writer. A list of a

class Order
{
    public function constructor(public string $id, public int $cents)
    {}
}

class Shop
{
    public static function orders(): array<Order>
    {
        return [
            new Order('A-1001', 1250),
            new Order('A-1002', 900),
            new Order('A-1003', 4300),
        ];
    }
}

var $queue = new Core\Task\Channel<Order>(2);

var $till = Core\Task::all({
    read: fn(): int => {
        int $count = 0;
        foreach (Shop::orders() as Order $order) {
            $queue->send($order);
            $count = $count + 1;
        }
        $queue->close();
        return $count;

    bill: fn(): int => {
        int $cents = 0;
        foreach ($queue as Order $order) {
            echo 'receipt ', $order->id, ': ', $order->cents, " cents\n";
            $cents = $cents + $order->cents;
        }
        return $cents;
    },
});

// This prints 3 and 6450.
echo $till->read, ' orders, ', $till->bill, " cents in total\n";
```

# Isolates: `spawn script` and `await`

`spawn script "file.nvs"` runs another file while your program keeps going. It gives you a handle.
`await $handle` waits for that file and returns its result.

The result has four fields. `ok` is true when the file finished without an error. `value` is what the
file returned, and you convert it with `as`. `output` is what the file printed, when you wrote
`output: "capture"`. `error` has the class name and the message when the file stopped with an error.

A path in quotes starts at the folder of the file that contains it. A path you build at run time
must be a full path, or `spawn script` throws `RuntimeError`. Build one with `Core\Path::join`. You
can also start a static method, written `Class::method(...)`.

A static method and a file inside your application folder need no capability. A file outside that
folder needs the `script.spawn` capability. You can await one handle once. A second `await` of the
same handle throws `LogicError`.

`spawn script` gives a `Core\Script\Handle`. The handle has no properties, so `$h->ok` is `E0405`.
`await` needs a handle. `await $n` on an `int` is `E0401`.

The entry is a path or a static method. An anonymous function is `E0802`.

`with(…)` takes the options `args`, `limits`, `grants`, `output` and `on`. Another name is `E0101`, and
its help lists the five.

`on:` must be the word `"worker"` or `"here"`, written at the spawn. Another word is `E0818`, and so is
a variable. To choose the core while the program runs, write two spawns in an `if`.

`output:` may be a variable. A value that is not `"capture"` or `"inherit"` throws `LogicError` with
the message ``` `spawn script`'s `output:` is `'capture'` or `'inherit'`, got `'keep'` ```.

The type of `output` in the result is `Core\Html\Markup|Core\Cli\Text`, not `string`. So `string $s =
$r->output;` is `E0401`. `echo $r->output` works, and `$r->output as string` gives the text.

With `output: "inherit"`, the child's output is printed when you `await` its handle. It comes after
everything the parent printed before that `await`. The `output` field is then empty.

A handle that is never awaited prints nothing. The program ends when the parent ends, even while the
child still runs.

`value` is `mixed`, so `int $v = $r->value;` is `E0401`. `$r->value as string` gives a `tainted
string`. A child with no `return` gives `null`. A child that calls `exit` also gives `null`, and `ok`
is `true`.

A child cannot return an object. When it does, `ok` is `false`, and the class in `error` is `Error`.
This is true for an anonymous object too, and for a class the parent also declares.

`args:` copies its value at the spawn. A change the parent makes later is not seen by the child.
Without `args:`, `Core\Script::args()` returns `null`. A file cannot receive an object in `args:`. The
spawn then throws `LogicError` in the parent.

A static method gets each entry of `args:` as the argument with the same name. Write `args:` as an
array with string keys, such as `["n" => 5]`. Here an object can be passed. A method with parameters
and no `args:` is `E0402`, and a key that names no parameter is `E0486`. When an entry is missing
while the program runs, the spawn throws `LogicError`. When an entry has the wrong type, the child
fails with a `LogicError`, and `ok` is `false`.

A path built while the program runs must be absolute. For a relative one, the message is ``
`spawn script` needs an absolute path, and `child.nvs` is relative ``. A second line names
`Core\Path::join` and `Core\Path::fromCwd`.

`limits: {memory: "1M"}` gives the child a memory limit. A child that goes over it ends with `ok`
`false` and a `RuntimeError`. `grants: []` gives the child no capabilities, so a `spawn script` inside
it throws `RuntimeError`.

A child can start its own child. A task in `Core\Task::all` can start a child and `await` it.

# A child shares nothing

A script you start with `spawn script` runs on its own. It shares nothing with the program that started
it.

Every class static in the started script begins at its declared value, whatever your program wrote in its
own copy. A write inside the script stays there. Your own values are the same after the script has
finished as they were before it began. Two scripts started one after another share nothing either.

Printing works the same way. With `output: "capture"` the text the script prints comes back to you in the
`output` field of the result, and nothing reaches the screen. With `output: "inherit"` the script prints
to your screen, and `output` is then empty.

**The examples below** show a script that cannot change your numbers, the two ways to handle what a
script prints, and a health check made of three scripts that cannot disturb each other.

A static property with an array value starts at its declared value in the child too. An entry the
parent added is not there, and an entry the child adds does not reach the parent.

A child started with `on: "here"` runs on the same core as the parent. It shares nothing with the
parent either.

A task in `Core\Task::all` can start a child. All tasks of the program share one value of each static
property, but the child still gets its own copy.

The child is a separate program. It does not need the classes the parent declares, and it cannot read
the parent's variables. A child that uses `$x` without declaring it does not compile. The error is
`E0301`, and `spawn script` throws `RuntimeError` in the parent.

```nvs
// check cannot change what another check counted. This program adds the three
// numbers up itself.

final class Report
{
    public static int $problems = 0;
}

// `#[Core\Path]` says that a parameter is a file path. A relative path in
// quotes passed to it starts at the folder of this file.
class Here
{
    public static function path(#[Core\Path] string $path): string
    {
        return $path;
    }
}

// `$dir` is a full path, so a path built from it works from any folder.
string $dir = Here::path('checks');
array<string> $checks = ['disk-space', 'mail-queue', 'old-sessions'];

foreach ($checks as string $name) {
    string $path = Core\Path::join($dir, $name . '.nvs');
    var $handle = spawn script $path with(output: 'capture');
    var $result = await $handle;

    // All three scripts declare `Report::$problems` and start it at 0. The
    // number each one returns is its own count.
    int $problems = $result->value as int;
    Report::$problems = Report::$problems + $problems;

    echo $name, ': ', $problems, " problem(s)\n";
    echo '  ', $result->output;
}
```

# A child's failure is a value

A script you start with `spawn script` runs on its own. When it fails, the failure comes back to you as
a value.

`await` returns a result. `ok` is false when the script ended with an error it did not catch. `error` has
the class name and the message of that error. `output` still has everything the script printed before it
failed. Your program keeps running.

A mistake in your own program is different. A file name that points to nothing throws an error in your
program. So does a file that does not compile, or a misspelled `output:` setting. Those errors happen at
the line that starts the script, and you catch them with `try`.

**The examples below** show a failed script read as a result, your own mistake told apart from the
script's failure, and a group of jobs where one fails and the other two still finish. The last one
shows the error when your program may not start scripts.

The type of `error` is `null|{class: string, message: string}`. It is `null` when `ok` is `true`. So
`$r->error->message` is `E0459`. Read it with `?->`, or test `$r->error != null` first.

`error` has two fields, `class` and `message`. It has no `backtrace` and no `line`. `$r->error?->line`
compiles, and throws a `RuntimeError` when it runs: `` `$shape{class,message}` has no field `line` ``.

`class` is the name of the class the child threw. For a class the child declares itself, such as
`ImportFailed`, the result has that name. A `RecursionError` in the child gives the class
`RecursionError` and the message `the call stack is too deep`. A division by zero gives
`ArithmeticError`.

A failure in the child never throws in the parent. A `try` around `await` catches nothing, and `ok`
is `false`. With `output: "inherit"`, what the child printed is printed at `await`, and then `ok` is
`false` too.

A child that calls `exit(3)` gives `ok` `true` and `error` `null`. The result has no status number.

A missing file and a file that does not compile give the same message in the parent:
`` `spawn script '<path>'`: `<path>` could not be compiled; see the errors above ``. The compiler's
errors are printed to standard error. For a missing file, that is a `could not read` line with the
message of the operating system.

Without the grant, the message is `` `spawn script` needs the capability `script.spawn` for <path>,
which is not granted ``. A second line starts with `help:` and names `[capabilities.script]` in
`nvs.toml`.

```nvs
<?nvs
// Shows a program that runs three jobs and reports each one. The first job
// fails, and the other two still run. This is what a nightly job runner does.

// `#[Core\Path]` says that a parameter is a file path. A relative path in
// quotes passed to it starts at the folder of this file.
class Here
{
    public static function path(#[Core\Path] string $path): string
    {
        return $path;
    }
}

// `$jobs` is a full path, so a path built from it works from any folder.
string $jobs = Here::path('jobs');
array<string> $names = ['import-orders', 'build-invoices', 'send-receipts'];

int $failed = 0;
foreach ($names as string $name) {
    string $path = Core\Path::join($jobs, $name . '.nvs');
    var $handle = spawn script $path with(output: 'capture');
    var $result = await $handle;
    // A failed job is a result you can read, so the loop goes on to the next.
    if ($result->ok) {
        echo $name, ": done\n";
    } else {
        echo $name, ': failed, ', $result->error?->message, "\n";
        $failed = $failed + 1;
    }
}

echo $failed, " of 3 jobs failed\n";
```

```output
build-invoices: done
send-receipts: done
1 of 3 jobs failed
```

# What does not exist

PHP's concurrency tools do not exist in Novis. Naming one is a compile error.

There is no `async` keyword, no `await` on a promise, no `Fiber`, and no `pcntl_fork`, `pthreads`,
`parallel` or `curl_multi_init`. A method that waits just waits, and the code around it is ordinary
code. Run several jobs at the same time with `Core\Task::all`, or one job per element with
`Core\Task::map`. Run a whole file or a static method beside your program with `spawn script`, and
read its result with `await`. There is no `spawn worker`, and an anonymous function is not allowed
as the entry.

Nothing is shared between requests, or between a spawned file and your program. `global`,
`$GLOBALS` and a `static` variable inside a function are compile errors. Values cross at `await`.

**The examples below** show `Core\Task::all` in place of promises, `spawn script` in place of
`pcntl_fork`, and a page that gets a price from three shops at the same time. The last one shows that
`new Fiber` does not compile.

`Thread`, `Promise` and `parallel\Runtime` are not classes. `new Thread()` is `E0303`, and the
message names no replacement.

`pcntl_fork()` and `curl_multi_init()` are `E0320`, because Novis has no functions outside a class.

`spawn worker "x.nvs"` is a general syntax error. The first error is `E0319` for `spawn`, and it names
no replacement.

`global $x;` is `E0204`, `$GLOBALS` is `E0211`, and `static int $n = 0;` inside a method is `E0209`.
Their help names a `static` property, a constant or a parameter.

## Example 01: core task in place of async and promises

```nvs
<?nvs
// Shows the replacement for `async` and a promise. `Core\Task::all` takes a set of
// functions, runs them at the same time, and returns all their results together.

class Orders
{
    public static function total(): int
    {
        return 3 + 4;
    }

    public static function title(): string
    {
        return 'Orders';
    }
}

// No function here is marked `async`, and none of them returns a promise.
// Each field is a function that takes no arguments.
var $page = Core\Task::all({
    total: Orders::total(...),
    title: Orders::title(...),
    note:  fn(): string => 'ready',
});

// The results are ready on this line. `Core\Task::all` returns only when every
// function has finished. This prints Orders: 7 (ready).
echo $page->title, ': ', $page->total, ' (', $page->note, ")\n";
```

```output
Orders: 7 (ready)
```

## Example 02: spawn script in place of fork and threads

```nvs file=scripts/count-orders.nvs
<?nvs
// The examples in the folder above start this file with `spawn script`. It counts
// the orders it was given and returns the number.

echo "counted the orders\n";
return 1200;
```

```nvs
<?nvs
// Shows the replacement for `pcntl_fork` and threads. `spawn script` runs a whole
// file, or a static method, beside your program. Both kinds of entry have a name.

class Report
{
    public static function build(int $days): string
    {
        return 'sales for ' . $days . ' days';
    }
}

// The first kind of entry is a file. The path starts at the folder of this file.
var $file = spawn script 'scripts/count-orders.nvs' with(output: 'capture');

// The second kind is a static method, written `Class::method(...)`. `args:` gives it
// the values its parameters need.
var $method = spawn script Report::build(...) with(args: ['days' => 7]);

// An anonymous function is not allowed as the entry, because it captures variables.
// A spawned file shares nothing with your program except compiled code.

// `await` waits for one entry and gives you its result.
var $counted = await $file;
var $built = await $method;

int $orders = $counted->value as int;
tainted string $text = $built->value as string;
echo 'orders: ', $orders, "\n";
echo 'report: ', $text, "\n";
```

```output
report: sales for 7 days
```

## Example 03: three shops priced at the same time

```nvs
<?nvs
// Shows a real use: a product page needs a price from three shops before it can be
// drawn. `Core\Task::map` runs one job per element and returns the answers under the
// same keys, in the same order, whatever order the jobs finished in.

class Shop
{
    // A real program would ask the shop over the network here. Each call returns its
    // own answer, so no job writes into storage another job can read.
    public static function priceIn(string $city): int
    {
        array<int> $board = ['Hamburg' => 700, 'Munchen' => 750, 'Koln' => 680];

array<string> $shops = ['north' => 'Hamburg', 'south' => 'Munchen', 'west' => 'Koln'];

// This prints north: 700, then south: 750, then west: 680.
foreach ($prices as string $region => int $cents) {
    echo $region, ': ', $cents, "\n";
}
```
