# Precedence and associativity

Precedence decides which operator runs first. Associativity decides the order when two operators of
the same strength meet.

Novis uses the order most languages use: `*` and `/` before `+` and `-`, then the comparisons, then
`&&`, then `||`, and the assignment last. `**` runs before a minus sign in front of it, and a chain
of them is read from the right. So `-2 ** 2` is `-4` and `2 ** 3 ** 2` is `512`. A conversion with
`as` binds tighter than every operator around it.

**Good to know:** the compiler gives warning `W1022`
for two mixes that are easy to misread. In `$n ?? 0 + 10`, the `+` runs first, so the default is
`10`.

**The examples below** show the arithmetic order, `**` with a minus sign, and `as` and `.` in a line
of text. The last one shows `!` with `is`, the pipeline `|>` and a method call on `new`.

The full order, from the operators that run first to the ones that run last:

- `->`, `?->`, `::`, `[…]`, a call `(…)`, `$x++`, `$x--` and `as T`, left to right
- `new` and `clone`
- `**`, right to left
- a prefix `-`, `+`, `~`, `++` and `--`
- `|>`, left to right
- `is`, left to right
- `!`
- `*`, `/` and `%`, left to right
- `+` and `-`, left to right
- `<<` and `>>`, left to right
- `.`, left to right
- `<`, `<=`, `>` and `>=`, left to right
- `==`, `!=` and `<=>`, left to right
- `&`, then `^`, then `|`, each left to right
- `&&`, then `||`, each left to right
- `??`, right to left
- `? :`, right to left
- `catch (T $e) => …` in an expression
- `=` and every other assignment, such as `+=` and `??=`, right to left
- `print`, `throw` and `yield`, which take everything to their right

`as` runs before every prefix and binary operator. `-$s as int` is `-($s as int)`, and
`$s as int ** 2` is `($s as int) ** 2`. To convert a result, write `($a / $b) as int`.

`!` runs after `is`. `!$o is User` is `!($o is User)`.

`|>` runs before every binary operator and after a prefix operator. `-$a |> Core\Math::abs($_)` is
`Core\Math::abs(-$a)`. In `"x=" . $a |> Core\Str::upper($_)`, only `$a` goes into the pipeline. In
`$x = $a |> Core\Str::trim($_)`, `$x` gets the result of the whole pipeline.

`new User()->name()` calls the method on the new object, with no parentheses around `new`.
`clone $a->b` copies the object in the property `$a->b`.

The compiler gives warning `W1022` in three cases:

- a `??` whose default is an arithmetic or `.` expression without parentheses, such as `$n ?? 0 + 10`
- a `? :` whose condition is an arithmetic or `.` expression without parentheses, such as
  `"n=" . $ok ? "x" : "y"`
- a `?:` or `? :` whose condition is a `??` without parentheses, such as `$m ?? 1 ?: 2`

The warning shows two ways to add the parentheses. The first keeps what the line does now. The
second is the order the line most likely meant. A warning does not stop the program.

A `catch` in an expression runs after the ternary and before the assignment. So in
`$x = $a / $b catch (ArithmeticError) => 0`, the `catch` covers the whole division, and `$x` gets
the result. A second `catch` after it is another case of the same `catch` expression.

## Example 01: multiplication before addition

```nvs
<?nvs
// Shows the order Novis uses when you write several operators in one
// expression: multiplication before addition, and the comparison after both.

int $price = 20;
int $quantity = 3;
int $shipping = 5;

// `*` runs before `+`, so this is `20 * 3 + 5`. It prints 65.
echo $price * $quantity + $shipping, "\n";

// Parentheses change the order, and cost nothing when the program runs.
// This prints 160.
echo $price * ($quantity + $shipping), "\n";

// The arithmetic and the comparison run before `&&`, and `&&` runs before
// `||`. This prints `free shipping`.
bool $isMember = false;
bool $hasCoupon = true;
echo $isMember || $hasCoupon && $price * $quantity > 50 ? 'free shipping' : 'pay shipping', "\n";
```

```output
65
160
free shipping
```

## Example 02: the power operator and a minus sign

```nvs
<?nvs
// Shows the two rules for `**`: it runs before a minus sign written in front
// of it, and a chain of them is read from the right.

// `2 ** 2` runs first, and the minus sign is applied to the result.
// This prints -4.
echo -2 ** 2, "\n";

// Parentheses make the minus sign part of the number. This prints 4.
echo (-2) ** 2, "\n";

// A chain is read from the right: `3 ** 2` is 9, and `2 ** 9` is 512.
echo 2 ** 3 ** 2, "\n";

// The same chain read from the left would be 64. Write the parentheses when
// you mean that. This prints 64.
echo (2 ** 3) ** 2, "\n";
```

```output
-4
4
512
64
```

## Example 03: building a total line from a form field

```nvs
<?nvs
// Shows the two rules you meet when you build a line of text out of numbers:
// `as` binds tighter than every operator around it, and the dot that joins
// two strings binds looser than the arithmetic.

// The quantity arrived from a form, so it is text.
string $typed = '3';
int $unitPrice = 20;
int $shipping = 5;

// `as int` converts before the multiplication, so no parentheses are needed
// here. This prints 60.
echo $typed as int * $unitPrice, "\n";

// The whole sum is worked out first and then joined to the label, because `.`
// binds looser than `*` and `+`. This prints `total: 65`.
echo 'total: ' . $typed as int * $unitPrice + $shipping, "\n";

// A division needs its own parentheses, because `as` would otherwise convert
// only the number on its right. This prints 21.
int $cents = 4200;
echo ($cents / 200) as int, "\n";
```

```output
60
total: 65
21
```

## Example 04: is the pipeline and a method call on new

```nvs
<?nvs
// Shows the order of `!` with `is`, of `|>` with other operators, and of a method call on `new`.

class Coupon
{
    public function constructor(public int $percent)
    {}

    public function label(): string
    {
        return $this->percent . '% off';
    }
}

// `is` runs before `!`, so this tests "not a `Coupon`". This prints `false`.
mixed $value = new Coupon(10);
echo !$value is Coupon ? 'true' : 'false', "\n";

// The minus sign runs before `|>`, so the pipeline gets -5. This prints 5.
int $change = 5;
echo -$change |> Core\Math::abs($_), "\n";

// `|>` runs before `.`, so only `$code` goes into the pipeline. This prints `code: SPRING`.
string $code = 'spring';
echo 'code: ' . $code |> Core\Str::upper($_), "\n";

// `<<` runs before `.`, so `1 << 2` is 4 and is then joined to "x". This prints `4x`.
echo 1 << 2 . 'x', "\n";

// A method call on `new` needs no parentheses. This prints `25% off`.
echo new Coupon(25)->label(), "\n";

// A ternary inside another one groups to the right. This prints `small`.
int $total = 40;
echo $total > 100 ? 'large' : $total > 20 ? 'small' : 'tiny', "\n";
```

```output
false
5
code: SPRING
4x
25% off
small
```

# Operators that do not parse

Some operators do not exist in Novis. Writing one is a compile error, and most of these errors name
what to write instead.

`&&` and `||` are the only two logical operators that join conditions. `and` and `or` do not exist,
and `xor` is `!=` between two `bool` values. `==` and `!=` never convert either side, so `===`,
`!==` and `<>` do not compile. A cast such as `(int)$x` is written `$x as int`. `@` does not exist,
because a failure is thrown and you catch it. There are no references (`&$x`), no variable variables
(`$$name`) and no backticks. To add two arrays, use `Core\Arr::underlay`. To read one character, use
`Core\Str::at`. A string has no `++`.

**Good to know:** every one of these errors appears when you compile, never while the program runs.

**The examples below** show the replacements you need most often: `&&` and `||` in a condition,
`==` for equality, and `Core\Arr::underlay` and `Core\Str::at`. The last one shows the error for
`===`.

Each form has its own error code:

- `and`, `or` and `xor` are the error `E0226`.
- `===` and `!==` are the error `E0232`, and `<>` is the error `E0241`.
- A cast such as `(int)$x` or `(string)$x` is the error `E0225`.
- `@` before an expression is the error `E0236`. Catch the error with `try` and `catch` instead.
- `$a = &$b` is the error `E0701`.
- `$$name` and `${$name}` are the error `E0202`.
- `$a + $b` on two arrays is the error `E0467`.
- `$s[0]` on a string is the error `E0482`.
- `$s++` on a string is the error `E0474`.
- `eval(…)` is the error `E0201`. Put the code in a file and `require` it.

A backtick and `&$x` in an expression give a general syntax error. That error does not name what
to write instead. To run another program, use `Core\Process`. To let a method change a variable,
use an `inout` parameter.

After `===`, `!==` or `<>`, the compiler reads the line as if `==` or `!=` were written. So it also
reports every other error in the file in the same run.

## Example 01: and or and xor written with symbols

```nvs
<?nvs
// Shows how to write "and", "or" and "xor" between two conditions. Use `&&` for
// "and" and `||` for "or". For "xor" on two `bool` values, use `!=`.

bool $paid = true;
bool $inStock = true;
bool $expressRequested = false;
bool $customerIsPremium = true;

// `&&` is true when both sides are true. This prints `ship now`.
echo $paid && $inStock ? 'ship now' : 'hold', "\n";

// `||` is true when at least one side is true. This prints `express`.
echo $expressRequested || $customerIsPremium ? 'express' : 'standard', "\n";

// `!=` between two `bool` values is true when exactly one of them is true.
// This prints `exactly one`.
echo $expressRequested != $customerIsPremium ? 'exactly one' : 'both or neither', "\n";
```

```output
ship now
express
exactly one
```

## Example 02: one equality operator

```nvs
<?nvs
// Shows the one equality operator. `==` never converts its operands.
// `===`, `!==` and `<>` do not exist, and none of them compiles.

// A quantity that arrived as text, and the quantity already stored.
string $typed = '7';
int $stored = 7;

// Convert the text with `as int` first, then compare. This prints `same`.
echo ($typed as int) == $stored ? 'same' : 'different', "\n";

// Two strings compare character by character, so `"07"` and `"7"` are two
// different strings. This prints `no match`.
string $fromUrl = '07';
echo $fromUrl == $typed ? 'match' : 'no match', "\n";

// `!=` is the only inequality operator, and it is exactly the opposite of
// `==`. This prints `changed`.
string $saved = 'draft';
string $current = 'published';
echo $saved != $current ? 'changed' : 'unchanged', "\n";
```

```output

no match
changed
```

## Example 03: user settings over defaults

```nvs
<?nvs
// Shows how to combine two arrays with `Core\Arr::underlay` and read one
// character with `Core\Str::at`. The program reads settings and an order code.

// What this user saved, and the defaults for everything else.
array<string> $saved = ['theme' => 'dark', 'pageSize' => '50'];
array<string> $defaults = ['theme' => 'light', 'pageSize' => '25', 'language' => 'en'];

// `Core\Arr::underlay` keeps the first array's value at each shared key and
// adds the keys only the second array has. This prints `dark 50 en`.
array<string> $settings = Core\Arr::underlay($saved, $defaults);
echo $settings['theme'], ' ', $settings['pageSize'], ' ', $settings['language'], "\n";

// `Core\Str::at` reads the character at one position, and `Core\Str::slice`
// reads several from a position. This prints `A AT`.
string $orderCode = 'AT-1042';
echo Core\Str::at($orderCode, 0), ' ', Core\Str::slice($orderCode, 0, 2), "\n";
```

```output
dark 50 en
A AT
```

# Arithmetic

The arithmetic operators `+ - * / % **` work on the four number types: `int`, `uint`, `float` and
`decimal`.

Both sides must be numbers. `"3" * 2` does not compile, so you write `($s as int) * 2`. A whole
number and a `float` give a `float`, so `3 + 0.5` is `3.5`. An `int` and a `uint` do not mix, and a
`decimal` and a `float` do not mix either. Dividing two whole numbers gives a whole number when the
result is exact. Otherwise it gives a `float`, so `7 / 2` is `3.5`. A result too large for a whole
number throws an `ArithmeticError`. A division by zero, `%` by zero and a negative power of a whole
number throw it too.

**Good to know:** use `decimal` for money. A `float` cannot store `0.1` exactly, so ten additions of
`0.1` do not give `1.0`. A `decimal` stores digits, and the total is exact.

**The examples below** show everyday arithmetic, the errors arithmetic throws and a basket priced in
`decimal`. Then they show an `int` and a `uint` in one expression, the operators `++` and `--`, and
the bitwise operators.

Each type that is not a number gives a compile error with an arithmetic operator:

- `"3" * 2` and `true + 1` are the error `E0716`. A `bool` becomes a number with `$b ? 1 : 0`.
- A value that can be `null`, such as a `?float`, is the error `E0716` too. Test it first with
  `if ($a != null)`, or give it a default with `??`: `($a ?? 0.0) + 1.5`.
- `+"3"` and `-"3"` are the error `E0705`.
- Two arrays with `+` are the error `E0467`.

A `mixed` value is checked when the program runs. A `mixed` that is `"3"` in `$m + 1` throws a
`RuntimeError`.

`int / int` has the type `int|float`. So `float $avg = 7 / 2;` compiles, and `int $n = 7 / 2;` is
the error `E0401`. `6 / 3` is the `int` `2` when the program runs. `Core\Math::intDiv(7, 2)` is
integer division, and it gives `3`.

`%` works on `int`, `uint` and `decimal`. On a `float` it is the error `E0717`, and
`Core\Math::mod(5.5, 2.0)` gives the remainder `1.5`. The result has the sign of the number on the
left: `(-7) % 3` is `-1`, and `7 % -3` is `1`.

`int` with `uint` is the error `E0407`, and so is a shift or a bitwise operator between them. An
integer literal next to a `uint` is a `uint`, so `$u + 3` compiles.

`decimal` with `float` is the error `E0455`, also for a `float` literal. Write
`$d + (0.2 as decimal)`. `decimal` with `int` or `uint` gives a `decimal`. `**` on a `decimal` is the
error `E0455` too, and `Core\Decimal::pow` is the power. A `decimal` division keeps up to 28 digits
after the point: `1.0 / 3.0` is `0.3333333333333333333333333333`.

`**` with whole numbers gives a whole number. A negative exponent throws, except with the base `1`
or `-1`: `(-1) ** -3` is `-1`. `2 ** 0.5` is a `float`.

Each overflow of a whole number throws an `ArithmeticError` with its own message: `Integer addition
overflowed`, `Integer subtraction overflowed`, `Integer multiplication overflowed`, `Integer
exponentiation overflowed` and `Integer negation overflowed`. `0 - 1` on a `uint` overflows too. A
`float` that is too large becomes `INF` and does not throw.

A division by zero throws an `ArithmeticError` with the message `Division by zero`. This is also
true for a `float`, such as `1.0 / 0`. For a `decimal`, the error has another message, the same one
as a result that is too large. `%` by zero gives `Modulo by zero`, and `Core\Math::intDiv(1, 0)`
throws as well.

`++` and `--` work on an `int`, `uint`, `float` or `decimal` variable, property or array element.
On a string they are the error `E0474`, and on a value such as `3++` the error `E0105`.

The bitwise operators `& | ^ ~ << >>` work on `int` and `uint`, and give the same type. On a `float`
they are the error `E0706`. A shift does not check for overflow, so `1 << 63` is
`-9223372036854775808`.

## Example 01: everyday arithmetic on numbers

```nvs
<?nvs
// Shows the arithmetic operators on whole numbers and on fractions, and what
// dividing two whole numbers gives.

int $apples = 7;
int $baskets = 2;

// Dividing two whole numbers gives a whole number when it comes out even and
// a fraction when it does not. This prints 3.5 and 2.
echo $apples / $baskets, ' ', 6 / 3, "\n";

// For a whole number use `Core\Math::intDiv`, which drops the remainder, and
// `%` for the remainder itself. This prints 3 and 1.
echo Core\Math::intDiv($apples, $baskets), ' ', $apples % $baskets, "\n";

// `**` raises a number to a power. This prints 1024.
echo 2 ** 10, "\n";

// A fraction on either side makes the result a fraction. This prints 3.75
// and 3.5.
echo 1.5 + 2.25, ' ', 3 + 0.5, "\n";
```

```output

3 1
1024
3.75 3.5
```

```nvs
// Shows the errors arithmetic throws instead of giving you a wrong number.

int $largest = 9223372036854775807;
```

## Example 03: a basket priced in decimal

```nvs
<?nvs
// Shows why money is added up in `decimal`. Ten additions of 0.1 as a `float`
// look right and are not, and the same ten in `decimal` are exact.

float $floatTotal = 0.0;
decimal $step = 0.1;
decimal $decimalTotal = 0.0;
int $item = 0;

while ($item < 10) {
    $floatTotal = $floatTotal + 0.1;
    $decimalTotal = $decimalTotal + $step;
    $item = $item + 1;
}

// The `float` total prints as 1 and is still not equal to 1.0, so this prints
// "1 no". The `decimal` total is equal, so the next line prints "1.0 yes".
echo $floatTotal, ' ', $floatTotal == 1.0 ? 'yes' : 'no', "\n";
echo $decimalTotal, ' ', $decimalTotal == (1.0 as decimal) ? 'yes' : 'no', "\n";

decimal $price = 19.99;
decimal $rate = 0.2;
decimal $goods = $price * 3;
decimal $tax = $goods * $rate;

// Every digit of this is exact. It prints "59.97 + 11.994 = 71.964".
echo $goods, ' + ', $tax, ' = ', $goods + $tax, "\n";
```

```output
1.0 yes
59.97 + 11.994 = 71.964
```

## Example 05: signs and counting up and down

```nvs
<?nvs
// Shows the operators written before one number, and `++` and `--`.

int $n = 3;

    $largest++;
} catch (ArithmeticError $overflow) {

}
```

```nvs
<?nvs
// Shows the bitwise operators `& | ^ ~` and the shifts `<<` and `>>`.

// This prints `2 7 5 -6`.
```

# Comparison and equality

`==` tests whether two values are equal, and `!=` tests whether they are different. These are the
only two equality operators.

Neither operator converts a value. `1 == "1"` does not compile, and the error tells you to convert
one side first. Numbers of different types do compare, so `1 == 1.0` is true. Two strings are equal
when they have the same characters. Two arrays are equal when they have the same keys and values in
the same order. Two objects are equal only when they are the same object, so a copy is not equal to
the original.

`<`, `<=`, `>`, `>=` and `<=>` put two values in order. They work on numbers, on two `bool` values,
and on two objects of a class that implements `Comparable`. They do not work on strings. Use
`Core\Str::compare` to order two strings. On numbers, `<=>` returns `-1`, `0` or `1`.

**The examples below** show a number that arrived as text, then arrays, objects and a missing value,
then two delivery offers put in order by price. The last two show the errors for an `int` compared
with a string and for `<` on two strings.

Two values whose types can never be equal are the error `E0466`:

- an `int` and a string, such as `1 == "1"`
- an enum case and an `int`. Compare `$e as int` with the number instead.
- a type that cannot be `null` and `null`, such as `$n == null` for an `int`
- a string and `bytes`
- objects of two classes that are not related

A class and an interface compile, even when the class does not implement the interface. A child
class could implement it.

`int` and `uint` compare exactly, with no conversion: `-1 == 18446744073709551615` is false, and
`-1 < 18446744073709551615` is true. `decimal` ignores trailing zeros: `1.10 == 1.1` is true.
`float` keeps its rounding, so `0.1 + 0.2 == 0.3` is false.

Two strings are equal when they have the same code points (the numbers that make up the text). So
`"é"` written as one code point is not equal to `"e"` followed by a combining accent.

An `array<int>` and an `array<float>` compare element by element, so `[1] == [1.0]` is true.
`["x" => 1, "y" => 2]` is not equal to `["y" => 2, "x" => 1]`, because the keys are in another order.
Two anonymous functions are equal only when they are the same function.

A `?T` value compared with `null` tests whether there is a value. In the branch where `$u != null`
is true, `$u` is a `T`.

Two `mixed` values are compared when the program runs. Values of different types are not equal, so
a `mixed` `1` is not equal to a `mixed` `"1"`. Numbers of different types are equal when the numbers
are the same: a `mixed` `1` is equal to a `mixed` `1.0`.

`<`, `<=`, `>`, `>=` and `<=>` give a compile error on any other pair:

- two strings, two enum cases, two arrays or `null` are the error `E0715`. Order an enum by its
  number with `($a as int) < ($b as int)`.
- two objects of a class that does not implement `Comparable` are the error `E0411`.
- objects of two different classes are the error `E0411`, even when both implement `Comparable`.

A `?int` compiles with `<`. When the value is `null`, the comparison throws a `RuntimeError`, such
as "no ordering for a `null` against a `int`". Two `mixed` strings throw a `RuntimeError` too.

On two objects, `<` calls `compareTo` and compares its result with `0`. `<=>` returns the result of
`compareTo` unchanged. So when `compareTo` returns `-40`, `$a <=> $b` is `-40`. `false <=> true` is
`-1`.

```nvs
<?nvs
// Shows how to order values: numbers compare directly, text uses
// `Core\Str::compare`, and a class states its own order by implementing
// `Comparable`. This is the shape a checkout page uses to pick an offer.

class Offer implements Comparable
{
    public function constructor(public string $carrier, public int $cents, public int $days)
    {}

    // `compareTo` returns a negative number when this offer comes first, and
    // a positive one when it comes last. The cheaper offer wins.
    public function compareTo(self $other): int
    {
        if ($this->cents != $other->cents) {
            return $this->cents <=> $other->cents;
        }
        return Core\Str::compare($this->carrier, $other->carrier);
    }
}

// A delivery promise is worth paying for when it is at least two days sooner.
// This prints "worth it".
if ($express->days <= $standard->days - 2) {
    echo "worth it\n";
} else {
    echo "not worth it\n";
}
```

# Logical operators and truth

`&&` means "both", `||` means "either" and `!` means "not". Each one tests its operands as
conditions and returns `true` or `false`. The result is always a `bool`.

Every value counts as true except these: `false`, `null`, zero, an empty string, the string `"0"`
and an empty array. A `bytes` value is false only when it is empty. An object, a callable and an
enum case are always true.

`&&` and `||` stop when the result is known. In `$count != 0 && $total / $count > 10.0`, the
division runs only when `$count` is not zero.

**Good to know:** `and`, `or` and `xor` are not part of the language.

A value that can be `null`, such as an `?int`, is false for `null` and also for `0`. The compiler
gives warning `W1023` when you test such a value directly. Write `!= null` to check whether there is
a value.

**The examples below** show a check that reads a value only when the value exists, the values of a
form field that count as empty, and the checks a request must pass.

`and`, `or` and `xor` are the error `E0226`. Write `&&` for `and` and `||` for `or`. For `xor` on two
`bool` values, write `$a != $b`.

`&&`, `||` and `!` always return a `bool`. `5 && 3` is `true`, and `!!$x` gives the truth value of
`$x` as a `bool`. A call that returns `void` is not an operand: `Log::write() && $ok` is the error
`E0718`.

A few values are easy to get wrong. The string `"0.0"` and a string with one space are true. `NAN`
(the float that is not a number) is true. `-0.0`, a `decimal` `0.00` and a `uint` `0` are false.

The right side of `&&` and `||` is narrowed like the branches of an `if`. The narrowing feature
explains the rules. After the whole expression, nothing it tested is kept. So
`bool $ok = $u != null && $u->active;` compiles, but a `$u->active` on the next line is the error
`E0459`.

Warning `W1023` is given when the whole condition of an `if`, a `while`, a `? :` or a `?:` can be
`null`. It is also given for a `?User`, which is false only for `null`. It is not given for an
operand of `&&`, `||` or `!`. So `if ($n && $ok)` with an `?int` `$n` gives no warning, and `null`
and `0` are both false there.

## Example 01: a guard that runs the second check only when it is safe

```nvs
<?nvs
// Shows why `&&` and `||` stop early. The right side runs only when the left

// code on the right.

    public static function averageIsHigh(int $total, int $count): bool
    {

        // When the count is zero, the division never runs.

// `||` is the other way round: it stops as soon as one side is true. The
// second check runs only when the first one failed.
array<string> $chosen = [];
array<string> $suggested = ['novis'];

    echo "something to show\n";
```

# String operators

`.` joins two strings into one, and `.=` adds a string to the end of a variable. Both convert each
side to a string first, so `"Order " . 1042` gives `Order 1042` without a cast.

Every number can be converted this way. `true` gives `1`, and `false` and `null` give an empty
string. An object can be joined when its class implements `Stringable`, and the result of that
method is used.

Four things cannot be converted to a string, and joining one does not compile: a `bytes` value, an
array, an enum case, and a call that returns nothing. For the first three, the error message says
what to write instead. For example, you choose the encoding of a `bytes` value or the fields of an
array yourself.

A string in double quotes inserts values in the same way: `"Hello $name"` and `"{$order->total}"`.

**The examples below** show strings and numbers joined into one message, a line built piece by
piece with `.=`, and the confirmation text for an order.

Each value that cannot be joined has its own error:

- a `bytes` value, an array, an enum case or a call that returns `void` is the error `E0707`.
  Write `$data as string` for `bytes`, `Core\Json::encode($list)` for an array and `$case as int`
  for an enum case.
- an object whose class does not implement `Stringable` is the error `E0412`.
- a `Core\Html\Markup` value is the error `E0710`. Join two of them with `+`, which gives a new
  `Markup`.

A `mixed` value is converted when the program runs. A `mixed` number joins like a number. A `mixed`
array throws a `RuntimeError` with the message "cannot convert an array to `string`".

`+` on two strings is the error `E0716`. `+`, `-`, `*` and `/` run before `.`, so `"n=" . $n + 1`
with `$n` equal to `2` gives `n=3`.

A `float` loses its `.0` when it is joined: `10.0` gives `10`. A `decimal` keeps every digit it has,
so `4.50` gives `4.50`. A `uint` gives all its digits, up to `18446744073709551615`.

`.=` writes a `string`, so the variable must be able to contain one. `$n .= "x"` on an `int` is the
error `E0401`. On a `?string` that is `null`, `.=` starts from an empty string.

When one side is `tainted` or `secret`, the result is `tainted` or `secret` too. `$s .= $input` on a
plain `string` `$s` is the error `E0401` when `$input` is `tainted`. `echo` of a joined `secret`
value is the error `E0790`.

## Example 01: joining text and numbers into one message

```nvs
<?nvs
// Shows how to join text and numbers with `.`. Every value gets its text form

// `true` joins as 1, while `false` and `null` join as nothing at all. This
// prints: [1] [] []

?string $note = null;
```

## Example 02: growing a line a piece at a time

```nvs
<?nvs
// Shows how to build up text one piece at a time with `.=`. It adds to the
// end of the text already in the variable. That is what a loop needs when
// the number of pieces is only known while the program runs.

array<string> $tags = ['urgent', 'billing', 'eu'];

string $line = '';
foreach ($tags as string $tag) {
    // The separator goes in front of every piece but the first. An empty
    // `$line` is how you know this is the first one.
    if ($line != '') {
        $line .= ', ';
    }
    $line .= $tag;
}
// This prints: urgent, billing, eu

// The piece added does not have to be text. A number, a `bool` and `null` all

string $status = 'retries=';
$status .= 3;
$status .= ' done=';
$status .= true;
// This prints: retries=3 done=1
echo $status, "\n";

// `Core\Str::join` does the whole loop above in one call when all the pieces
// are already in an array. This prints: urgent, billing, eu
echo Core\Str::join($tags, ', '), "\n";
```

## Example 03: rendering the confirmation an order sends out

```nvs
<?nvs
// Shows the job `.` and `.=` do most often at work: turning records into the
// text a customer reads. A class that implements `Stringable` joins in as
// whatever its `toString` returns. An amount is then formatted in one place,
// and every line that mentions it comes out the same.

class Money implements Stringable
{
    public function constructor(public decimal $amount, public string $currency)
    {}

    public function toString(): string
    {
        return $this->amount . ' ' . $this->currency;
    }
}

class Line
{
    public function constructor(
        public string $item,
        public uint $quantity,
        public Money $price,
    )
    {}
}

class Confirmation
{
    public function constructor(public string $customer, public array<Line> $lines)
    {}

    // The subject is one join. Nothing here is cast: the number and the
    // object both have a text form already.
    public function subject(): string
    {
        return 'Your order, ' . $this->customer . ' (' . Core\Arr::count($this->lines) . ' items)';
    }

    // The body grows a piece at a time, because how many lines there are is
    // only known while this runs.
    public function body(): string
    {
        string $body = "Hello $this->customer,\n\n";
        foreach ($this->lines as Line $line) {
            $body .= '  ' . $line->quantity . ' x ' . $line->item . ' at ' . $line->price . "\n";
```

# `??`, `?:`, `?->` and the ternary

Five short operators for values that may be missing, and for choosing between two values.

`$a ?? $b` gives `$a`, or `$b` when `$a` is `null` or the array key is not there. `$a ??= $b` writes
`$b` into `$a` only when `$a` is `null` or missing. `$a ?: $b` gives `$b` when `$a` counts as
nothing, such as an empty string or a zero. `$o?->name` gives `null` when `$o` is `null`.
`$c ? $a : $b` gives `$a` when `$c` is true and `$b` when it is not.

**Good to know:** only the side you end up with is run. In `$o != null ? $o->name : "none"`, the
first side runs only when `$o` is not `null`. `&&` works the same way.

**The examples below** show a missing value, a choice between two values and a settings
file with its gaps filled in. The last two show `??-=` and `??.=`, and the error for a write through
`?->`.

`??` runs its right side only when the left side is `null` or a missing key. The right side may be
`throw`: `$id ?? throw new LogicError("no id")`. A missing key at any level gives the right side, so
`$t["a"]["b"] ?? 7` is `7` when `$t` has no key `"a"`. `??` on a value that can never be `null`
compiles, and the result is the left side.

The type of `$a ?? $b` is the type of `$a` without `null`, joined with the type of `$b`. So an `?int`
`$a` with `"x"` on the right gives `string|int`. An empty array `[]` on the right takes the type the
result needs. Under `var`, it takes the type of the left side. So `$names ?? [1]` with an
`?array<string>` `$names` is the error `E0401`.

`??` runs after `+`. `$n ?? 0 + 10` is `$n ?? (0 + 10)`, and the compiler gives warning `W1022`.
Write `($n ?? 0) + 10`.

`$a ??= $b` runs `$b` only when it writes. Its value is the value of `$a` afterwards, so
`($a ??= 5) + 1` is `6` when `$a` was `null`. The type of `$a` does not need to include `null`.

`??+=`, `??-=` and `??.=` are the only three of their kind. `??*=` is the error `E0105`, and so is
`($a ?? 100) -= 1`. Write `$a = ($a ?? 100) - 1` instead. A missing key starts at the zero of the
array's element type: `0`, `0.0`, a `decimal` zero or `""`. On a `uint`, `??-= 1` from a missing key
throws an `ArithmeticError`, because `0 - 1` does not fit.

`$a ?: $b` runs `$a` once. The type of the result is the type of `$a` joined with the type of `$b`.

`$o?->m($x)` does not run the arguments when `$o` is `null`. In a chain such as `$q?->next?->value`,
the first `null` makes the whole result `null`. A `?->` on a value that can never be `null` works
like `->`. Writing through `?->`, such as `$p?->x = 2`, is the error `E0479`.

`$c ? $a : $b` runs only the arm it picks. The type of the result is the types of both arms joined,
and it is widened when it is stored: `float $x = $c ? 1 : 2.5` is `1.0` or `2.5`. A ternary in the
last arm of another ternary needs no parentheses. `$n > 9 ? "huge" : $n > 3 ? "big" : "small"` tests
from left to right.

## Example 01: a value that may be missing

```nvs
<?nvs
// Shows how to give a value a fallback with `??`. The left side is used
// unless it is `null`, or unless the array key is not there.

array<string> $row = ['name' => 'Ada'];

// The key "name" is there, so this prints "Ada".
echo $row['name'] ?? 'unknown', "\n";

// Reading a key that is not there stops the program with an error. `??` is
// the one read that gives a value instead, so this prints "unknown".
echo $row['city'] ?? 'unknown', "\n";

?string $nickname = null;

// `??` looks only for `null`, and this variable is `null`, so the right side
// is used. This prints "Ada".

?string $shortName = null;

// You can write several fallbacks in a row. The first one that is not `null`
// is the result, so this prints "no nickname".
echo $shortName ?? $nickname ?? 'no nickname', "\n";

array<array<string>> $tagsByPost = ['first' => ['news']];

// An empty list `[]` after `??` gets the type of the left side. So `$tags`
// is an `array<string>`, and you can add a string to it. This prints 1.
var $tags = $tagsByPost['second'] ?? [];
$tags[] = 'draft';
echo Core\Arr::count($tags), "\n";
```

```output
1
```

# Assignment

`=` writes a value into a local variable, a property, a static property or an array element. It is
also an expression. Its value is what was just written, so `$a = $b = 3` sets both.

Every compound form, such as `+=` or `.=`, is a short way to write `$x = $x op e`. The target is
worked out once, so `$totals[next()] += 1` runs `next()` once. A compound form cannot change the
type of its target, so `$n /= 2` on an `int` does not compile.

`??+=`, `??-=` and `??.=` update a value that may not exist yet. `$count["paid"] ??+= 1` starts
from `0` when the key is missing or the value is `null`. A string starts from `""`.

**The examples below** write and update values, update arrays and objects, and tally a report with
`??+=`. The last two show every compound operator, and the error for `/=` on an `int`.

The compound forms are `+=`, `-=`, `*=`, `/=`, `%=`, `**=`, `.=`, `<<=`, `>>=`, `&=`, `|=` and `^=`.
There is no `<=>=` and no `|>=`.

A compound form needs a value that fits the type of the target. Each of these is the error `E0401`:

- `$n /= 2` on an `int`, because `/` gives `int|float`
- `$n += 1.5` on an `int`
- `$n .= "x"` on an `int`

`$f += 1` on a `float` works, because the `int` is widened. A bitwise form on a `float`, such as
`$f |= 1`, is the error `E0706`. On an `?int`, `$a += 1` is the error `E0716`, even when the value is
not `null`. Use `??+=` or test the value first.

A compound form throws the errors of its operator. On an `int` or a `uint`, a result out of range
throws an `ArithmeticError`, and so does `$n %= 0`. `$n **= -1` on an `int` throws too.

A compound form on an array element reads the element first. `$a["k"] += 1` throws a `RuntimeError`
when the key `"k"` is missing. `??+=` starts a missing key at `0`.

The left side must be a place to store a value. Writing to a constant or to a call, such as `P::X =
2`, is the error `E0105`. Writing a `readonly` property after the constructor is the error `E0782`.
A write to a variable that was never declared is the error `E0301`. A parameter is a variable, so a
method may write to it.

`if ($a = 0)` compiles. It writes `0` and tests the value written, so the `else` block runs.

```nvs
// updating a few running values once per row. Nothing is collected first and
// added up at the end.

{
    public function constructor(
        public string $status,
        public decimal $amount,
        public uint $items,
    )
    {}
}

    new Order('paid', 19.99, 2),
    new Order('refunded', 4.50, 1),
    new Order('paid', 120.00, 7),
    new Order('paid', 8.25, 1),
];

    // `??+=` adds to a count that may not exist yet. The first row for a

    if ($order->items > 5) {
        $large .= $order->status . ' ';
    }

// This prints: paid 3, refunded 1

// This prints: large orders: paid
echo 'large orders: ', Core\Str::trim($large), "\n";
```

# `match`

`match` chooses one value out of several by comparing a subject with a list of values.

You write the subject in brackets, then one arm per line. Each arm has one or more values on the
left and a result on the right. The first arm with a value equal to the subject gives the result of
the whole `match`. `default` is used when none of the other arms matched. It is tried last, wherever
you put it in the list. A `match` is an expression, so you can assign it to a variable, pass it to a
function or join it to a string.

**Good to know:** if no arm matches and there is no `default`, `match` throws a `LogicError`. The
comparison is `==`. An arm value of a type the subject can never be equal to does not compile. Text
against a number is one example.

**The examples below** take these in turn: choosing a label for a value, choosing by a range with
`match (true)`, and writing the line a customer reads for each order status. The last two show a
`match` inside an `echo` and a string, and an arm value that does not compile.

The subject goes in brackets after `match`. Without the brackets, the code does not compile.
The subject runs once, before any arm.

The arms are tested in the order they are written. An arm's values run one by one, and the test
stops at the first match. The arms after it do not run. When two arms have the same value, the first
one gives the result.

An arm may have several values, separated by commas. This works in `match (true)` too:
`$n > 5, $n < 0 => "far"` matches when one of the two conditions is true. A comma after the last
arm is allowed.

Each value is compared with the subject by `==`. A `mixed` subject that contains the string `"5"`
does not match the arm `5`. A value whose type can never be equal to the subject is the error `E0466`.
A string against an `int` is one such case. `null` against an `int` subject is another: the subject
must be a `?int` for that arm. In `match (true)`, each condition must be a `bool`, and an `int`
condition is `E0466` too.

In `match (true)`, a condition such as `$m is int` narrows the variable in that arm's result.
`match (true) { $m is int => $m + 1, default => 0 }` gives `6` when `$m` is `5`.

The type of a `match` is the union of its results. With the results `"a"` and `2`, the type is
`string|int`. Assigning that to a `string` variable is the error `E0401`.

A result is one expression. A block of statements in braces does not compile. A result may be a
`throw`, such as `default => throw new RuntimeError("bad")`.

A `match` with no arms is the error `E0476`. When no arm matches and there is no `default`, the
`LogicError` has the message ``no `match` arm matched the subject``. This also happens for an enum
case that has no arm, because the compiler does not check that the arms list every case.

## Example 01: choosing a label for a value

# `is`, `new`, `clone`, `throw`, `print`, `exit`, `isset`, `empty`

Eight small expressions that test a value, build one, copy one or stop the program.

`$x is T` is true when the value in `$x` is a `T`. Where the test is true, `$x` has the type
`T`. `$x is $cls` tests against a `class<T>` variable. `new C(...)` builds an object.

`clone $o` makes a shallow copy. An object in a property is
shared with the original. `isset($x)` is true when `$x` is there and is not `null`. `empty($x)` is
true when `$x` is false by the truth table. Both work on a variable, a property or an array element.

**Good to know:** `throw`, `print` and `exit` are expressions too, so each can be the right side of
`??`. `print` writes one value and gives `1`.

**The examples below** show a type test, an object and its copy, and settings that may be missing.
The last two show all of these, and a `string` after `is`, which does not compile.

`is` works with every type a value can have: a class, an interface, `int`, `?int`, `null`, a union
such as `int|string` and an array type such as `array<int>`. When the declared type of the variable
already gives the answer, the test is fixed while compiling. For an `int` variable, `$n is int` is
always `true` and `$n is string` is always `false`.

The right side of `is` is a type. The only variable allowed there is a `class<T>` variable, as in
`$v is $cls`. A `string` variable is the error `E0496`. Convert the name first with `as class<T>`.

`new P` without brackets is the same as `new P()`. The arguments work as in a method call, and named
arguments work too. You can call a method on the new object directly: `new P()->hi()`. Inside a class,
`new self()` builds the class itself, and `new static()` builds the class the method was called on.

These forms of `new` do not compile:

- `new` with an interface or an `abstract` class is the error `E0785`.
- `new $c()` with a `string` variable is the error `E0496`. The class must be written in the code.
- `new P(...)` is the error `E0740`. A constructor is not a method, so use an anonymous function.

`clone` copies every property, and a `readonly` property too. The copy is a new object, so
`$p == $q` is `false` after `$q = clone $p`. A class cannot change what `clone` does. A method named
`clone` is an ordinary method, and `clone` does not call it. `clone` on an `int` or another type that
is not an object is the error `E0781`. On a `mixed` value that is not an object, it throws a
`LogicError` when it runs. On a `?Point` value that is `null`, it compiles and throws a
`LogicError` too.

`throw` takes a `Throwable`. `throw "oops"` is the error `E0780`. A `throw` can be the right side of
`??`, `?:`, `||` and `&&`, or one result of a ternary.

`print` takes one value. `print "a", "b"` does not compile, and `print [1]` is the error `E0707`.
`print` gives `1`, so `$n + print "x"` prints `x` and gives `$n + 1`.

`isset` takes one or more operands, and is `true` only when every one has a value that is not `null`.
Each operand is a variable, a property or an array element. A call or a literal is the error `E0498`.
To test a call, write `A::f() != null`. A variable that was never declared is the error `E0301`, for
`empty` too. An operand of a type without `null`, such as `int`, is always `true`.

A missing key at any level gives `false`: `isset($a["q"]["y"])` is `false` when `"q"` is missing. A
nullable object on the way needs `?->`. `isset($p->next->v)` is the error `E0459` when `next` is a
`?P`, and `isset($p->next?->v)` is `false` when `next` is `null`.

`empty` takes one operand, and that operand may be any expression, a call included. `"0"` and an empty
array are empty, as the truth table says.

## Example 01: checking what kind of value you have

```nvs
<?nvs
// Shows how `$x is T` checks what kind of value you have right now. Inside
// the branch where the check is true, the compiler knows the type. You can
// read the value there without converting it first.

interface Reading
{}

class Temperature implements Reading
{
    public function constructor(public float $celsius)
    {}
}

class Humidity implements Reading
{
    public function constructor(public int $percent)
    {}
}

class Report
{
    public static function line(mixed $reading): tainted string
    {
        if ($reading is Temperature) {
            // Here `$reading` is a `Temperature`, so its property is readable.
            return 'temperature ' . $reading->celsius;
        }
        if ($reading is int) {
            return 'count ' . $reading;
        }
        if ($reading is string) {
            return 'note ' . $reading;
        }
        return 'unknown reading';
    }

    // When the class is only known while the program runs, put it in a
    // `class<Reading>` variable. `$reading is $kind` then checks against it.
    public static function count(array<mixed> $readings, class<Reading> $kind): int
    {
        int $found = 0;
        foreach ($readings as mixed $reading) {
            if ($reading is $kind) {
                $found += 1;
            }
        }
        return $found;
    }
}

// This prints: temperature 21.5
echo Report::line(new Temperature(21.5)), "\n";

// This prints: count 3
echo Report::line(3), "\n";

// This prints: note warm
echo Report::line('warm'), "\n";
```

# Calls

A call runs a method and returns the method's result.

You write the class or the object, the name of the method, and the arguments in brackets. You can
call a method on the result of a call directly. Arguments go in the order of the parameters. You can
also write them by name, in any order. A name also lets you leave out a parameter in the middle that
has a default. A variadic parameter, written `...$rest`, takes any number of arguments. `...$list`
at the call passes each value of an array as an argument. An `inout` parameter writes its new value
back to the variable you passed. You write `inout` at the call as well.

**Good to know:** you call a `callable` through the variable, the array element or the property
that contains it. Its arguments are checked when the program runs.

**The examples below** take these in turn: calling and chaining, naming the arguments you pass, and
pricing an order with the handler the customer chose. The last one shows each way to write a call in
one program.

The arguments run in the order they are written, also when they are named. In
`A::f(b: A::v(2), a: A::v(5))`, `A::v(2)` runs first.

A static method may also be called on an object: `$p->s()` calls the static method `s`. An
instance method called on the class, such as `P::i()`, is the error `E0778`. A method the class does
not have is the error `E0405`. On a nullable object, such as a `?P`, `$p->hi()` is the error `E0459`.
Use `$p?->hi()`, which gives `null` when `$p` is `null`.

`...$list` only fills a variadic parameter. Before a method with only fixed parameters, it is the
error `E0489`. Arguments may come before it, and several `...` arguments may follow each other:
`A::f(3, ...$xs)` and `A::f(...$xs, ...$xs)` both work. The type of the array must match the
variadic parameter, so an `array<string>` for `int ...$a` is the error `E0401`. The keys of the
array are kept: `["x" => 1, "y" => 2]` arrives with the keys `"x"` and `"y"`.

A call through a `callable` gives `mixed`. `int $r = $f(1)` is the error `E0401`, so write
`$f(1) as int`. The arguments are checked when the call runs. An argument of the wrong type throws a
`LogicError`: ``argument 1 to a `callable` must be of type int, string given``. Too few arguments
throw a `LogicError` too, and extra arguments are ignored.

A `callable` in a property needs brackets around it: `($this->cb)(1)`. Without them,
`$this->cb(1)` calls a method named `cb`, and is the error `E0405` when the class has none.

A call that returns `void` has no value. At an `int` variable it is the error `E0401`, and after
`echo` it is the error `E0707`.

## Example 01: calling a method and chaining the result

```nvs
<?nvs

// on the class and an instance method on an object. You can call a method on
// the object that a call returns directly.
```

# The pipeline operator

Passes a value through several steps, written from left to right in the order they run.

You write the value, then `|>`, then the step. Inside the step, `$_` is the place where the
value goes. Each step takes the result of the step before it. To trim a string and then convert it
to lower case, you write two steps.

Without `|>` you write one call inside another, and you read the steps from the inside to the
outside. Both forms do the same work, and `|>` adds no cost when the program runs.

**Good to know:** each step needs exactly one `$_`. A step with none, or with two, does not
compile. The right side of `|>` is the call itself, with `$_` in it.

**The examples below** clean up a form field in two steps, build a URL slug in five steps and
tidy a list of tags. Example 04 uses `|>` with other operators. Examples 05 and 06 do not compile.

The compiler replaces `$_` with the value on the left. So a pipeline has the same type, the same
errors and the same result as the nested calls it replaces. A `tainted string` stays tainted, and a
`?string` value on the left is the error `E0401` at a step that needs a `string`. The value on the
left runs once.

A step is a call, an array index, a property, a method call or an expression in brackets.
`$xs |> $_[1]`, `$p |> $_->name`, `4 |> $p->add($_)`, `2 |> self::f($_)` and `3 |> new Point($_)`
all work. For any other expression, write brackets around it: `$n |> ($_ * 2)`.

The step ends where the call, index or brackets end. In `$n |> $_ * 2`, the step is only `$_`, and
then the result is multiplied by 2. The result is the same here, but `$n |> 10 - $_` does not
compile: the step is `10`, which has no `$_`.

`$_` may be deep inside the step. `$s |> Core\Str::lower(Core\Str::trim($_))` works. So does a
second pipeline in an argument, or an anonymous function in an argument that uses `$_`.

These are the three errors:

- A step without `$_` is the error `E0129`. A method reference such as `Core\Str::upper` and an
  anonymous function are steps without `$_` too.
- A step with `$_` twice is the error `E0130`. Store the value in a variable first.
- `$_` anywhere else is the error `E0131`. This includes `$_` as a parameter name, and the second
  `$_` in `$n |> $_ * $_`.

`|>` runs after a prefix `-` and before every operator with two sides. `"a" . "b" |> Core\Str::upper($_)`
prints `aB`, and `$s ?? "d" |> Core\Str::upper($_)` is `$s ?? Core\Str::upper("d")`. `!` runs after
`|>`, so `!$a |> f($_)` is `!f($a)`.

# Anonymous functions

An anonymous function is a small function you write where you need it. You can keep it in a
variable, pass it to another call or store it in a list.

`fn` is the only way to write one. After the arrow comes one expression, whose value the function
returns, or a block in braces. Every parameter has a type. A block declares its return type.
The function copies each outside variable it uses when the function is written.

`$fn->bindTo($obj)` and `$fn->bind($obj)` return a copy that uses `$obj` as `$this`.
`$fn->call($obj, ...)` makes that copy and calls it. The object must be of the class the function
was written in, or a subclass. Any other object, or `null`, throws a `LogicError`.

**Good to know:** there is no `use (...)` list. A call through a `callable` returns `mixed`.

**The examples below** write functions, show captures and check a form.
Example 04 reads `$this`, 05 calls itself, and 06 does not compile.

These forms do not compile:

- `function (int $x) { … }` is the error `E0222`.
- `fn(int $x) use ($k) => …` is the error `E0223`.
- `static fn(…) => …` is the error `E0210`.
- An `inout` parameter is the error `E0493`, and `int &$x` is the error `E0237`.
- A parameter without a type is the error `E0808`.
- A block body without a return type is the error `E0450`.

With an expression body, the return type may be left out. The function then returns the type of the
expression. A value of the wrong type is the error `E0401` in an expression body, and the error
`E0403` after `return` in a block.

A captured variable is a copy. The function may change its copy, and the outside variable keeps its
value. Each call starts again from the value that was captured: a function that adds 1 to its copy
of `$k = 1` returns `2` on every call. An object is not copied. A function that captured `$b` reads
a property of `$b` that changed after the function was written.

A function cannot use the variable it is stored in. In `callable $f = fn(…) => … $f(…) …`, the inner
`$f` is the error `E0301`, because `$f` has no value yet. Give the function a name instead:
`fn fact(int $n): int => …` can call `fact(…)`. The call is checked against the function's
parameters and return type. Outside the function, `fact` is the error `E0320`.

`$this` outside a method, or inside a `static` method, is the error `E0779`.

A method reference names a method without calling it. `Core\Str::length`, `self::f` and
`static::f` each give a callable. On an object, write `(...)` in place of the arguments:
`$p->add(...)`. A method that does not exist is the error `E0405`.

`bindTo`, `bind` and `call` can throw a `LogicError` for the wrong object. Its message starts
``this callable uses `$this`, so it can only be bound to an object of class `A` ``. A function that does not use `$this` is returned unchanged, so any object works. A second
argument is the error `E0402`.

An anonymous function can be called where it is written: `(fn(int $x): int => $x * 10)(4)` gives
`40`.

```nvs

// array. Each rule is an anonymous function that returns the message for a bad
// value. The same loop then checks any form, so adding a field is adding a line.

class Form
{
    // Each rule gets the value of its field. It returns an empty string when
    // the value is fine.
    public static function check(array<string> $values, array<callable> $rules): array<tainted string>
    {
        array<tainted string> $problems = [];

        foreach ($rules as string $field => callable $rule) {
            tainted string $message = $rule($values[$field] ?? '') as string;

            if ($message != '') {
                $problems = Core\Arr::append($problems, $field . ': ' . $message);
            }
        }

        return $problems;
    }

    'name' => fn(string $value): string => $value == '' ? 'please give a name' : '',
    'email' => fn(string $value): string => Core\Str::contains($value, '@') ? '' : 'needs an @',
    'password' => fn(string $value): string =>
        Core\Str::length($value) < $shortest ? 'needs ' . $shortest . ' characters' : '',
];

array<string> $filled = [
    'name' => 'Ada',
    'email' => 'ada@example.com',
    'password' => 'correct horse',
];

// Nothing is wrong with this one, so the list of problems is empty.

array<string> $empty = [
    'name' => '',
    'email' => 'ada.example.com',
    'password' => 'short',
];

// This prints one line per field that failed its rule.
foreach (Form::check($empty, $rules) as tainted string $problem) {
    echo $problem, "\n";
}
```

# Arrays in expressions

An array is a list of values, or a table where every value has a name.

You write an array as `[10, 20]` or `["city" => "Graz"]`. `var $prices = [10, 20]` takes the type
from the values, so `$prices` is an `array<int>`. An empty array, or one whose values have different
types, needs the type written: `array<int> $prices = []`. `$prices[] = 30` adds a value at the end.
Every key is text, so `$prices[8]` and `$prices["8"]` are one entry. Reading a key that is not there
throws a `RuntimeError`. Write `$prices["milk"] ?? 0` where a missing key is normal.

**Good to know:** an array is a value. Assigning, passing or returning it gives a copy, so a change
on one side is never seen on the other.

**The examples below** build a list and a price table, read missing keys and group rows.
Example 04 shows keys, spread and nested arrays, 05 destructuring, and 06 does
not compile.

`var $a = [];` is the error `E0414`, because an empty array has no values to take a type from.
`var $a = [1, "x"];` is `E0414` too. Its help names the type to write: `array<int|string>`.

A key is an `int`, a `uint` or a `string`. A `float`, `bool` or `null` key is the error `E0434`.
`"08"` and `"8"` are two different keys.

`$a[] = 1` uses the largest whole-number key plus one, and a negative key counts too. In an empty
array, after `$a[-5] = 1;` the next key is `-4`. `unset` does not number the keys again, so after
`[10, 20, 30]` loses key `1`, the next `$a[]` gets key `3`. `$a[]` can only be written to. Reading
it is the error `E0481`.

`[...$a, 30]` copies the entries of `$a` into the new array. A whole-number key, such as `"5"` or
`"-3"`, gets the next number of the new array. Every other key is kept. When two entries have the same key, the later
one wins: `["k" => 5, ...$a, "k" => 7]` has one `k`, and it is `7`. The values of `$a` must fit the
new array's type. An `array<int>` spread into an `array<string>` is the error `E0401`.

A write into a key that is not there creates every inner array on the way:
`$g["a"]["b"]["c"] = 1;` works on an empty `$g`. A read does not. `$g["a"]["b"]` throws a
`RuntimeError` for the first key that is missing: `undefined array key `a``. `??` and `isset` test
every level, so `isset($g["a"]["b"])` is `false`. `isset` is also `false` for a key whose value is
`null`.

`unset($a["k"])` does nothing when the key is not there. It also works on an inner array:
`unset($g["r"]["0"])`.

A function result is not stored anywhere, so `A::f()["k"] = 1;` is the error `E0700`. Assign the
result to a variable first.

Destructuring reads by key, not by order. `[int $a] = $p;` reads key `"0"`, wherever it is in `$p`.
Entries that no variable names are skipped, and a missing key throws `undefined array key`. A
positional variable and a `"key" =>` variable can be mixed, and a key can be a variable:
`[$k => int $v] = $row;`.

Each variable in a destructuring needs its type. `[$a, $b] = $p;` is the error `E0101`, and
`[var $a] = $p;` is the error `E0102`. Each type must match the array's value type, or it is the
error `E0401`. The right side must be an `array<T>`. A `mixed` or a `?array<int>` value is the error
`E0482`. A `foreach` variable cannot be a destructuring pattern, which is the error `E0101`.
`list($a, $b) = $p;` is the error `E0230`.

# Anonymous objects

An anonymous object is an object with exactly the fields you write. You do not declare a class for
it.

You write it as `{ x: 1, y: 2 }` and read or change a field with `$point->x`. Its type is the shape
`{ x: int, y: int }`, and a `type` alias gives that shape a short name. Any object with at least those
fields fits where the shape is needed. So two parts of a program work together when they name the
same fields.
A field that may be missing is written `label?: string`, and `??` gives a value for the times it is
not there.

**Good to know:** an object is a handle and not a value. Two variables can name one object, and `==`
checks whether they do. It does not compare the fields, so two anonymous objects with equal values are
never equal.

**The examples below** build a point and change it, then pass shapes into a method and back out,
then return the result of a check as an object. Example 04 returns an object from an anonymous
function, and example 05 does not compile.

A field name is a plain name with no quotes. `{"x": 1}` is the error `E0101`, and so is
`{...$p, y: 2}`, because there is no spread for an object. A comma after the last field is allowed,
and `{}` is an object with no fields. A field name written twice is the error `E0494`.

At the start of a statement and directly after the `=>` of an anonymous function, `{` starts a
block. An anonymous object there is the error `E0117`. Write it in parentheses: `({ x: 1 });` and
`fn(int $x): Point => ({ x: $x, y: 0 })`.

The type of a field does not change. `$p->x = "a";` on `{ x: 1 }` is the error `E0401`. A
field with another anonymous object in it, or a function, is allowed. Call that function as
`($p->f)(1)`. `$p->f(1)` is the error `E0477`, because an anonymous object has no methods.

Reading a field the object does not have compiles, and throws a `RuntimeError` when it runs:
`` `$shape{x}` has no field `y` ``. A field written `b?: int` is optional. Reading it when it is not
there throws the same error, so read it with `$r->b ?? 0`. `isset($r->b)` is `false` when it is not
there.

An object of a class fits a shape when it has public properties with those names and types.
`$v is Point` checks every field and its type when the program runs.
`$v as Point` runs the same check. If the check fails, it throws a `RuntimeError`.

`clone $p` gives a new object with the same fields, so `$p == clone $p` is `false`.
`Core\Json::encode($p)` writes the fields sorted by name. `echo $p` compiles, and throws a
`RuntimeError` when it runs, because an anonymous object has no string form.

## Example 01: a point and what holds it

```nvs

    echo $result->message, ' (', $result->code ?? 200, ")\n";
    echo Core\Json::encode($result), "\n";
}
```

```output
that is not an email address (422)
```


# Refused in expression position

Some ways of writing code that PHP allows do not exist in Novis. Writing one is a compile error.

The list is `eval`, `extract`, `settype`, `compact` and the other free functions, variable variables
such as `$$name` and `${$expr}`, `list(...)`, casts such as `(int)$x`, the `@` sign, `=&`,
backticks, `die`, `include` and `require_once`, `yield` used as a value, and `self`, `static` or
`parent` written outside a class. Each error but the backtick's names what to write instead: a
method under `Core` for a free function, `as` for a conversion, `[...]` for taking a list apart,
`require` for reading another file, and `exit` for ending a program.

**Good to know:** you meet all of these when you compile, never while the program is running.

**The examples below** show the three replacements you need most often: a `Core` method in place of
a free function, `as` in place of a cast, and `[...]` in place of `list(...)`. The last example shows
the error for a variable variable.

Each form below is a compile error with its own code. The help line of the error names what to
write instead.

- `eval(…)` is `E0201`. Put the code in a file and `require` it, or run it with `spawn script`.
- `extract($a)` is `E0205`. Use destructuring, or read each key.
- `settype($x, "int")` is `E0208`. Convert into a new variable with `as`.
- `compact(…)`, `strlen(…)` and every other free function is `E0320`. Use a `Core` method such as
  `Core\Str::length($s)`.
- `$$name` and `${$expr}` are `E0202`. Use an `array<T>` with a key for each name.
- `list($a, $b) = $p;` is `E0230`. Write `[int $a, int $b] = $p;`.
- `(int)$x` and the other casts are `E0225`. Write `$x as int`.
- `@$a["k"]` is `E0236`. Catch the error with `try` and `catch`.
- `$b =& $a;` is `E0701`. Write `$b = $a;`, which copies the value.
- `die` is `E0228`. Write `exit`.
- `include` and `require_once` are `E0221`. Write `require`.
- In a generator, a `yield` whose value is used, such as `mixed $x = yield 1;`, is `E0448`. Write `yield 1;` as a
  statement of its own.
- `self`, `static` and `parent` outside a class are `E0303`. This is the same for `self::X`,
  `static::$x`, `parent::f()` and `new self()`. Write the class name.

A backtick is the one form with no replacement. `` echo `ls`; `` is the error `E0001`, an unexpected
character, and its message names nothing else. To run another program, use `Core\Process::run` with
the path and an array of arguments.

## Example 01: a core method in place of a php function

```nvs
<?nvs
// Shows the `Core` methods that replace PHP's free functions. In Novis
// every built-in is a method on a class, so `strtoupper($s)` is written
// `Core\Str::upper($s)`.

use Core\Str;

array<string> $names = ['ada lovelace', 'grace hopper'];

foreach ($names as string $name) {
    // `Str::upper` returns the text in capitals, and `Str::length` returns the
    // number of characters. The first line prints `ADA LOVELACE (12)`.
    echo Str::upper($name), ' (', Str::length($name), ")\n";
}

// `Str::replace` puts one text in place of another. This prints
// `grace-hopper`.
echo Str::replace('grace hopper', ' ', '-'), "\n";
```

```output
ADA LOVELACE (12)
GRACE HOPPER (12)
grace-hopper
```

## Example 02: as in place of a cast

```nvs
<?nvs
// Shows `as`, the one way to convert a value in Novis. PHP writes `(int)$x`
// or `settype($x, "int")`; neither exists here, and both are replaced by this
// one syntax.

string $typed = '42';

// `as int` converts the text to a whole number, and the result goes into a new
// variable. This prints `44`.
int $age = $typed as int;
echo $age + 2, "\n";

// A conversion that cannot work throws an error. `as ?int` returns `null`
// instead, so you can test the result. This prints `not a number`.
?int $maybe = "twelve o'clock" as ?int;
echo $maybe ?? 'not a number', "\n";

// `as` never changes the variable it reads. `$typed` is still the text it was
// given, so this prints `42`.
echo $typed, "\n";
```

```output
44
not a number
42
```

## Example 03: reading a row into variables

```nvs
<?nvs
// Shows how to read the parts of a row into variables, the way a program does
// when it imports a file. PHP offers `list(...)`, `extract` and `$$name` for
// this; Novis has `[...]` for a list and an array you index by name.

array<string> $line = ['2026-09-19', 'ada@example.com', '19.99'];

// `[...]` on the left takes the elements in order, one variable each. This
// prints the three values on one line.
[string $date, string $email, string $amount] = $line;
echo $date, ' ', $email, ' ', $amount, "\n";

array<string> $form = ['email' => 'grace@example.com', 'country' => 'US'];

// A row whose parts have names is an array with string keys. You read the key
// you want, and `??` gives a value for a key that is not there.
echo $form['email'], "\n";
echo $form['phone'] ?? 'no phone given', "\n";

// The key can come from a variable. This replaces a variable variable such as
// `$$name`, and the result still has a type: here it is a `string`.
string $wanted = 'country';
echo $form[$wanted], "\n";
```

```output
2026-09-19 ada@example.com 19.99
grace@example.com
no phone given
US
```
