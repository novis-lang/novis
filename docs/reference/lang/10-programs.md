# A program is a file of top-level statements

A Novis program is one file you run, and the lines written in it are the program.

There is no build step and no starting function to write. You save the file, you run it, and the
statements in it happen from the top downwards, in the order you wrote them. `echo` writes values
out, one after another, and puts nothing between them; `print` does the same for a single value.
Classes are different: one can be written anywhere in the file, above or below the lines that use
it, because declaring a class is not a step that happens at a moment.

**Good to know:** nothing is added to what you write out — not even a line break. A program that
should end its line says so, by writing the newline itself.

## Example 01: the smallest program

```nvs
<?nvs
// The whole program. Save it as `hello.nvs` and run `nvs run hello.nvs`.
// There is nothing else to write: no starting function, no build step.

echo 'Hello, World!', "\n";
```

```output
Hello, World!
```

## Example 02: write a line piece by piece

```nvs
<?nvs
// Putting a line together out of several pieces.
// `echo` takes as many values as you like and writes them one after another,
// with nothing in between. Spaces and line breaks are yours to write.

string $name = 'Ada';
int $messages = 3;

echo 'Hi ', $name, ', you have ', $messages, ' new messages.', "\n";

// `print` writes a single value, and is handy when there is only one.
print "That is all for now.\n";
```

```output
Hi Ada, you have 3 new messages.
That is all for now.
```

## Example 03: print a short report

```nvs
<?nvs
// A small script of the kind you run from a terminal: it prints a short
// report and stops. The lines run from the top down, and the class they lean
// on is written underneath them, which is allowed.

array<int> $minutes = [35, 12, 90, 5];

echo "Today\n";
echo "-----\n";

foreach ($minutes as int $spent) {
    echo Report::line($spent), "\n";
}

echo "-----\n";
echo Report::line(Core\Arr::sum($minutes) as int), " in total\n";

class Report
{
    public static function line(int $minutes): string
    {
        return '- ' . ($minutes as string) . ' min';
    }
}
```

```output
Today
-----
- 35 min
- 12 min
- 90 min
- 5 min
-----
- 142 min in total
```

# A complete program, annotated

A short tour of what almost every Novis program has in its first ten lines.

A program is a file of statements that run from top to bottom. Every variable has a type. You write
the type once, where you create the variable, and the variable keeps that type. A `foreach` loop
also names the type of each value it reads from a list.

To convert a value to another type, you use `as`. For example, a form sends text, and `as` converts
that text to a number you can add. If the value cannot be converted, the program stops with an
error.

Every built-in function is a method of a class, such as `Core\Str::length`. A program cannot read a
file, call another server or start another program until the person who runs it allows that.

**The examples below** show this one task at a time: adding the numbers a form sent, sorting a list
with the one option that `sort` accepts, and building a JSON reply.

## Example 01: add up what a form sent

```nvs
<?nvs
// A first program: three quantities arrive as text, and it adds them up.
// Every name says its type once, where it is created. `as` is how a piece of
// text becomes a number.

array<string> $quantities = ['3', '11', '7'];

int $total = 0;
foreach ($quantities as string $quantity) {
    $total = $total + ($quantity as int);
}

echo 'items ordered: ', $total, "\n";
```

```output
items ordered: 21
```

## Example 02: show the best scores first

```nvs
<?nvs
// A short leaderboard, best score first.
// The second thing given to `sort` is one anonymous object with its optional
// settings. There are no flags to remember, and the loop says what it takes
// out of the list.

array<int> $scores = [1420, 880, 2310, 1105];
array<int> $ranked = Core\Arr::sort($scores, { order: Core\Arr::Order::Desc });

int $place = 1;
foreach ($ranked as int $score) {
    echo $place, '. ', $score, "\n";
    $place = $place + 1;
}
```

```output
1. 2310
2. 1420
3. 1105
4. 880
```

## Example 03: answer a form with json

```nvs
<?nvs
// Turning what a form sent into the JSON answer a browser reads back.
// The quantities arrive as text and are counted as numbers. Building the
// answer is a call on `Core\Json`: everything Novis gives you is a class
// member, so there is no loose `json_encode` to remember.

array<string> $lineItems = ['2', '10', '1'];

int $units = 0;
foreach ($lineItems as string $quantity) {
    $units = $units + ($quantity as int);
}

echo Core\Json::encode({ lines: Core\Arr::count($lineItems), units: $units }), "\n";
```

```output
{"lines":3,"units":13}
```

# Code mode and HTML mode

A `.nvs` file can be a page and a program at once. Text outside the tags is written to the output
unchanged, and code between the tags runs.

A file starts in text mode, where every byte is written to the output. `<?nvs` starts code mode and
`?>` ends it. Most files start with `<?nvs` and never close it, so the whole file is code.

`<?= $name ?>` writes one value at the place where the tag is. A template uses it for most values
in a page. You can change mode as often as you like. A `{ … }` block can start in one code section
and end in a later one, so a loop or an `if` can repeat or skip plain HTML.

**Good to know:** a newline directly after `?>` is not written to the output, so a line that ends
with a closing tag leaves no empty line. `<?php` does not compile, and the error message names
`<?nvs`. There is no short `<?` tag, so a `<?xml` line in a page stays text.

`<?= $value ?>` is short for `<?nvs echo $value; ?>`. It writes one expression at the place where the
tag is. Inside `<?= ?>`, a `;` before `?>` is allowed and not needed. Inside `<?nvs ?>`, each statement
needs its `;`, also the last one before `?>`.

A file whose first line starts with `#!` is in code mode from its second line. The first line is not
written to the output. A `<?nvs` tag before the first `?>` in such a file does not compile (`E0009`).

In an HTTP request, the output escapes every `string` you write, so `<?= $title ?>` cannot add a tag to
the page. A `Core\Html\Markup` value is written as it is. You build one with an html template, and
`<?= $value ?>` inside that template escapes the value in the same way.

## Example 01: put one value into a page

```nvs
<html><body>
<?nvs
// Everything outside the tags is written out exactly as it stands. This part
// is code, and it runs.
string $who = 'world';
?>
<p>Hello, <?= $who ?>!</p>
</body></html>
```

```output
<html><body>
<p>Hello, world!</p>
</body></html>
```

## Example 02: wrap plain html in a loop

```nvs
<?nvs
// Shows a loop that starts and ends in code, with plain HTML in between.
// The HTML is not written as strings inside the program.
array<string> $products = ['pen', 'ink', 'paper'];
?>
<ul>
<?nvs foreach ($products as string $name) { ?>
  <li><?= $name ?></li>
<?nvs } ?>
</ul>
```

```output
<ul>
  <li>pen</li>
  <li>ink</li>
  <li>paper</li>
</ul>
```

## Example 03: an order confirmation page

```nvs
<?nvs
// A real page: a heading, one row per item, a total, and a different message
// when there is nothing to show. The page text stays page text throughout.
array<string> $items = ['Fountain pen', 'Ink, blue', 'Paper, 100 sheets'];
array<int> $cents = [4900, 1250, 899];

int $total = 0;
foreach ($cents as int $price) {
    $total = $total + $price;
}
?>
<h1>Thank you for your order</h1>
<?nvs if (Core\Arr::count($items) == 0) { ?>
<p>Your basket was empty.</p>
<?nvs } else { ?>
<table>
<?nvs
    int $row = 0;
    foreach ($items as string $name) {
        ?>
  <tr><td><?= $name ?></td><td><?= $cents[$row] ?></td></tr>
<?nvs
        $row = $row + 1;
    }
    ?>
</table>
<p>Total: <?= $total ?> cents</p>
<?nvs } ?>
```

```output
<h1>Thank you for your order</h1>
<table>
  <tr><td>Fountain pen</td><td>4900</td></tr>
  <tr><td>Ink, blue</td><td>1250</td></tr>
  <tr><td>Paper, 100 sheets</td><td>899</td></tr>
</table>
<p>Total: 7049 cents</p>
```

# Comments

A comment is a note for whoever reads the file next, and the program takes no notice of it.

There are three ways to write one. `//` and `#` each start a note that runs to the end of the line,
so either can sit on a line of its own or follow code you want to explain. `/* … */` covers any
span, from the middle of one line to a whole paragraph. A note meant for the people who *call* your
code gets a third slash instead: `///` written above a class or a method is a doc comment, and your
editor shows it to whoever types that name.

**Good to know:** `#[` is not a comment. It opens an attribute, so a note that starts with a square
bracket has to use `//`. And a block comment ends at the first `*/`, which means one cannot hold
another.

## Example 01: the three ways to write a note

```nvs
<?nvs
// A note for a reader. The program runs exactly as it would without it.
// `//` and `#` both run to the end of the line. `/* */` covers any span.

# Either spelling works on a line of its own.
string $city = 'Vienna'; // ... or after code, to explain that line.

/* A block comment is the one to reach for when the note is longer
   than a line, and it can stop in the middle of one. */
echo 'Weather for ', $city, "\n";

echo /* even here, between two values */ 'sunny', "\n";

// The markers only count outside text. Inside a string they are characters
// like any other.
echo 'the // and the /* stay put', "\n";
```

```output
Weather for Vienna
sunny
the // and the /* stay put
```

## Example 02: document a class for whoever calls it

```nvs
<?nvs
// Three slashes write a doc comment. It belongs to the declaration on the
// line under it, and your editor shows it to whoever types that name.

/// One greeting, written the same way everywhere in the program.
class Greeting
{
    /// Greets `$name` by name.
    /// The name is used as it arrives, so capitalise it before you pass it in.
    public static function forName(string $name): string
    {
        //// Four or more slashes make an ordinary comment.
        //// Your editor does not show it as documentation.
        return 'Hello, ' . $name . '!';
    }
}

echo Greeting::forName('Ada'), "\n";
```

```output
Hello, Ada!
```

## Example 03: say why a line is the way it is

```nvs
<?nvs
// Shows two common uses of a comment. One says why a line is written this way.
// The other turns off a line for a while without deleting it.

array<int> $basketCents = [1299, 450, 9900];

int $total = 0;
foreach ($basketCents as int $price) {
    $total = $total + $price;
}

// Baskets of 100 euro or more ship for free.
// The shipping contract sets this limit.
int $shippingCents = 495;
if ($total >= 10000) {
    $shippingCents = 0;
}

// This line is turned off until finance checks the new rate.
// $shippingCents = $shippingCents * 2;

echo 'Items:    ', $total, "\n";
echo 'Shipping: ', $shippingCents, "\n";
echo 'Total:    ', $total + $shippingCents, "\n";
```

```output
Items:    11649
Shipping: 0
Total:    11649
```

# Doc comments: `///`

A doc comment is a note for whoever uses your code, and the toolchain reads it.

Write it with three slashes, `///`, on the lines directly above a class, a constant, a property, a
method or an enum case. The whole run of `///` lines is one comment. Your editor shows it to whoever
types that name, and `nvs doc` puts it on the page it builds.

Two tags may be written, each at the start of a line. `@see` names another class
or member, and `@example` names a file that shows the code in use. Both are checked when the program
compiles, so a link that goes nowhere stops the build. Any other `@tag` is an error. Explain a
parameter in a sentence instead: its type is already in the signature.

**Good to know:** a `///` run with a blank line under it documents nothing, and that is an error.
Four slashes or more is an ordinary comment, so a divider line of slashes is not documentation.
The last example shows a `@param` tag, which does not compile.

The body of a doc comment is Markdown. `nvs meta --json` includes it, `nvs doc` shows it on a page,
and the editor shows it when you hover over the name.

`@see` and `@example` are tags only at the start of a line. `@see` must name a class or member that
exists, or the program does not compile (`E0323`). `@example` must name a file under `examples/` or
`tests/` (`E0325`). Any other tag, such as `@param` or `@return`, does not compile (`E0128`).

A `///` comment must be directly above a class, a constant, a property, a method or an enum case. If it
is above a statement, above a blank line or at the end of the file, the program does not compile
(`E0127`). Write `//` for a note to the reader.

`/** … */` is an ordinary comment. Directly above a declaration it documents nothing, and the compiler
prints the warning `W1011`. A line of four or more slashes is an ordinary comment too.

## Example 01: document a class and its members

```nvs
<?nvs
// Shows how to document a class. Three slashes write a doc comment, and it
// belongs to the declaration on the line under it.

/// A price in cents. A whole number of cents never needs rounding.
final class Price
{
    /// The lowest price a shop may set.
    public const int MIN = 0;

    /// Doubles a price.
    /// Several `///` lines in a row make one doc comment.
    public static function double(int $cents): int
    {
        return $cents * 2;
    }
}

// This prints 0.
echo Price::MIN, "\n";

// This prints 250.
echo Price::double(125), "\n";
```

```output
0
250
```

## Example 02: document the cases of an enum

```nvs
<?nvs
// Shows how to document the cases of an enum. Each case carries its own doc
// comment, which is where the meaning of a status belongs.

/// How far an order has got.
enum Status
{
    /// The customer has ordered and has not paid yet.
    Pending,
    /// The money has arrived.
    Paid,
    /// The goods have left the building.
    Shipped,
}

Status $order = Status::Paid;

// A case is a whole number, counted from the first case. This prints 1.
echo $order as int, "\n";
```

```output
1
```

## Example 03: point at related code with see

```nvs
<?nvs
// Shows how a doc comment points at related code. `@see` names a class, a method
// or a property, and the compiler checks that the name exists.

/// One customer invoice. Every amount in it is in cents.
/// @see Invoice::total
final class Invoice
{
    /// The amount of each line of the invoice, in cents.
    public array<int> $lines;

    /// Builds an invoice from its lines.
    public function constructor(array<int> $lines)
    {
        $this->lines = $lines;
    }

    /// Adds up the lines and returns the total in cents.
    /// @see Invoice::$lines
    public function total(): int
    {
        int $sum = 0;
        foreach ($this->lines as int $line) {
            $sum = $sum + $line;
        }
        return $sum;
    }
}

array<int> $lines = [1250, 399, 80];
var $invoice = new Invoice($lines);

// This prints 1729.
echo $invoice->total(), "\n";
```

```output
1729
```

# Names and casing

Novis checks the spelling of every name you write, so the spelling alone tells a reader what kind of
thing the name is.

Classes, interfaces, enums, enum cases, type aliases and the parts of a namespace start with a
capital letter. Methods, properties, parameters and variables start with a small one. A class
constant is written in capitals with an underscore between the words. In every other name, the
compiler checks the first letter and that there is no underscore. An abbreviation inside a name keeps
its capitals, so `HTTPClient` and `HttpClient` are equally fine.

A name spelled the wrong way is an error, not a warning, and there is no setting that turns it off.
The message names the spelling to use instead.

**Good to know:** no name may start with `_`, and a constructor is spelled `constructor`. Names
are case-sensitive everywhere, so `Core\Str` and `Core\STR` are two different names.
The last example shows a class name in snake case, which does not compile.

Each kind of name has its own error code. `E0110` is for a class, an interface, an enum, an enum
case, a type alias or a part of a namespace. Each of these must start with a capital letter. A method name is
`E0111`. A property, a parameter or a variable is `E0112`. A class constant that is not all capitals
and underscores, such as `MaxLines` or `MAX_lines`, is `E0113`. The message shows the name written
the right way.

A class constant may contain an underscore. No other name may: `$line_count` is `E0112`, and an enum
case `GOLD_RANK` is `E0110`. An enum case `GOLD` compiles, because it starts with a capital letter and
has no underscore.

A constructor written `__construct` is `E0114`.

Every property, method and class constant must say `public`, `protected` or `private`. Without one,
the program does not compile (`E0122`).

## Example 01: one spelling for each kind of name

```nvs
<?nvs
// One small class using every kind of name there is, each spelled the way
// its kind is spelled.

class OrderLine
{
    public const int MAX_QUANTITY = 10;

    public int $quantity = 0;

    public function constructor(int $quantity)
    {
        $this->quantity = $quantity;
    }

    public function isTooLarge(): bool
    {
        return $this->quantity > OrderLine::MAX_QUANTITY;
    }
}

OrderLine $line = new OrderLine(12);

echo 'quantity: ', $line->quantity, "\n";
if ($line->isTooLarge()) {
    echo 'over the limit of ', OrderLine::MAX_QUANTITY, "\n";
}
```

```output
quantity: 12
over the limit of 10
```

## Example 02: an abbreviation keeps its capitals

```nvs
<?nvs
// The compiler checks the first letter of a name and that it has no underscore.
// An abbreviation can keep the capitals people write it with.

class HTTPClient
{
    public static function parseXMLPayload(string $body): uint

{
    public static function forName(string $name): string

```


## Example 03: a shipping quote in its own namespace

```nvs
<?nvs

// the two constants and the variables each use the casing for their kind.
// A reader can see what each name is from the way it is written.

}
```


# Namespaces and `use`

A namespace is a prefix on every name a file declares, so two classes called `Greeter` in two parts
of a program never get in each other's way.

A file may open with one `namespace` declaration, and any number of `use` imports after it. Both
belong at the top of the file and never inside a class or a function. A name you write with a `\` in
it is read from the very beginning: `Core\Str` means `Core\Str` wherever you write it. A name with
no `\` is looked for in the file's imports first, then in the file's own namespace, and nowhere
else.

**Good to know:** there is no falling back to the outermost level, so inside `namespace App;` a
plain `Helper` means `App\Helper` and never a `Helper` declared outside any namespace. An import
cannot be renamed and cannot name a group of names, so write one `use` per name. `Core` is reserved
for the classes Novis ships, and nothing you write may live under it.

The `namespace` declaration must come before every class, interface, enum and type alias in the
file. A second `namespace`, or one below a declaration, does not compile (`E0243`). A `use` import
covers the code below it. A class above the `use` cannot use the short name, so put every `use` at
the top. A `use` inside a method body does not compile (`E0233`).

A name that starts with `\`, such as `\Core\Str`, does not compile (`E0240`). A name with a `\` in it
already starts from the top namespace. `use Core\Str as S;` does not compile (`E0212`), and neither
does `use Core\{Str, Json};` (`E0238`). `namespace Core;` does not compile (`E0217`). A class of your
own may still be called `Str`, outside any namespace or inside one.

A class or an interface is declared at the top level of a file. A class inside an `if` or inside
another class does not compile (`E0233`). An enum or a type alias may also be declared inside a class
or an interface body. It has no `public` or other modifier in front of it (`E0133`).

## Example 01: put a file in a namespace

```nvs
<?nvs
// One `namespace` declaration at the top of the file puts everything the file
// declares under that prefix. Inside the file you still write the short name.

namespace App;

class Greeter
{
    public static function greet(string $name): string
    {
        return 'Hello, ' . $name . '!';
    }
}

// The short name is looked for in the file's own namespace, so this is
// `App\Greeter`. Writing the name out in full means exactly the same class.
echo Greeter::greet('Ada'), "\n";
echo App\Greeter::greet('Bo'), "\n";
```

```output
Hello, Ada!
Hello, Bo!
```

## Example 02: import the names you type a lot

```nvs
<?nvs
// A `use` import lets you write a long name short. It covers the code below it
// and introduces one name, under the last part of the path.

namespace App;

use Core\Arr;
use Core\Str;

array<string> $words = ['order', 'invoice', 'receipt'];

// `Str` and `Arr` are the imports above.
echo Str::upper($words[0]), "\n";
echo Arr::count($words), "\n";

// You never have to import anything. A name written out in full works the
// same, imported or not.
echo Core\Str::lower('QUIET'), "\n";
```

```output
ORDER
3
quiet
```

## Example 03: name a class after a built in and keep both

```nvs
<?nvs
// Your program can have its own class called `Json`. A name that contains a `\`
// starts from the top namespace. So `Core\Json` is the built-in class, and
// `Json` is yours.

namespace App\Billing;

class Json
{
    public static function forInvoice(int $number, int $totalCents): string
    {
        return Core\Json::encode({ invoice: $number, total: $totalCents });
    }
}

echo Json::forInvoice(1042, 5990), "\n";
echo Core\Json::encode({ ok: 1 }), "\n";
```

```output
{"invoice":1042,"total":5990}
{"ok":1}
```

# `require`: run another file in this frame

`require` runs another file right where you write it, as part of the program that is already running.

The other file's own lines run in order at that point, every time your program reaches the `require`.
There is no once-only version. A `require` is also a value: whatever the other file hands back with
`return` at its top level is what you get, and you convert it with `as` to the type you expect. A
file that returns nothing hands back `1`. The path is written relative to the folder holding the file
you wrote the `require` in.

**Good to know:** one kind of name crosses between the two files and one does not. Every class,
interface, enum and type alias the other file declares is yours to use, as if you had typed it in.
Variables are not shared, so the other file's `$name` is its own and yours stays yours. To hand
something across, put it in a class.

The path is read while the program compiles. If no file is at that path, the program does not compile
(`E0311`). The path may be text in quotes, a class constant, or several of these joined with `.`.

A path built from a variable is not read while compiling. When the program reaches that `require`,
it throws a `RuntimeError`, even if the file exists.

The other file's top-level code is checked on its own. Its variables are new variables, even when a
name is the same as one of yours: after the `require`, your `$x` still has its old value.

`include`, `include_once` and `require_once` do not compile (`E0221`). The message names `require`.
A file of declarations that must be read once is found through `autoload`, which never reads a file
twice.

# `autoload`: find a class by its namespace

`autoload` tells Novis which folder your classes are in, so your program uses a class by its name
and never loads a file.

One declaration connects the start of a namespace to a folder. With `autoload 'App' from './src';`,
the class `App\Text\Greeter` is read from `./src/Text/Greeter.nvs`. `App` is removed, the middle
parts are folders, and the last part is the file name. One prefix can have several folders, and
they are searched in the order you wrote them.

`autoload discover` takes a folder pattern with a `*`. Every folder that matches is used for the
namespace named by the part that `*` matched.

A prefix can also contain `{..}`. In `autoload 'Site\{..}' from '../src';`, `{..}` is replaced by
the name of the folder that `..` points to from this file. If the file is in `Blog/public`, the
prefix is `Site\Blog`.

**Good to know:** every `autoload` declaration is read when the program is compiled. A class that
cannot be found stops the compile with an error. `nvs check --autoload-map` shows which folders
each prefix uses.

Every path in an `autoload` declaration is text in quotes, relative to the folder of the file that
contains the declaration. A path in a variable does not compile (`E0123`). An `autoload` declaration
is written at the top level of a file, and inside an `if` or a method it does not compile (`E0233`).
It covers the whole file, so it may come after the code that uses its classes.

Every part of a prefix starts with a capital letter. A prefix such as `'app'` or `'App\*'` does not
compile (`E0327`). One part may be `{.}`, `{..}` or `{../..}`. That part is replaced by the name of
the folder the path points to from the declaring file.

A file found through `autoload` declares one class, interface, enum or type alias. Its full name,
namespace included, must be the name the file was found by. Otherwise the program does not compile
(`E0317`). Folder and file names are case-sensitive, so `App\text\Greeter` does not find
`Text/Greeter.nvs`.

A class that no folder has is `E0303`, the same error as any name that is not declared. A folder that
does not exist is allowed. `nvs check --autoload-map` prints every prefix with its folders, and lists
a folder that does not exist under `missing`.

The map comes from every `autoload` in every file the program reads. `Core\Program::implementing<I>()`
uses it too: it finds each class that implements the interface `I`, even when no code names the class.

## Example 01: find a class by its name

```nvs file=app/Text/Greeter.nvs
<?nvs
// `App\Text\Greeter` lives here because of where the file is: the `App` prefix
// points at `app/`, and `Text\Greeter` is the rest of the way.

namespace App\Text;

class Greeter
{
    public static function hello(string $who): string
    {
        return 'Hello, ' . $who . '!';
    }
}
```

```nvs
<?nvs
// One line says where your classes live, and after that you name a class and
// never a file. `App\Text\Greeter` is read from `app/Text/Greeter.nvs`: the
// `App` prefix is dropped, and what is left becomes folders and a file name.

autoload 'App' from './app';

use App\Text\Greeter;

echo Greeter::hello('Alice'), "\n";
echo App\Text\Greeter::hello('Bo'), "\n";
```

```output
Hello, Alice!
Hello, Bo!
```

# File paths: a relative path starts at the folder of its file

A relative file path written in quotes starts at the folder of the file that contains it.

`Core\IO::read("data/prices.txt")` reads the `data` folder next to your program. It reads the same
file when you start the program from another folder, under `nvs serve` and as a service. A full
path, such as `/srv/shop/prices.txt`, is used as you wrote it. Add `#[Core\Path]` to a `string`
parameter of your own method, and a path in quotes passed to it works the same way.

**Good to know:** this works only for a path written in quotes in the call itself. A path such as
`'data/' . $name` starts with a relative path, so it does not compile. Start it with the folder of your file:
`Core\Path::thisDir('data') . '/' . $name`. `Core\Path::join` also adds a name to a full folder path.
A relative path in a variable throws a `RuntimeError` when a file method gets it.

**The examples below** read a file next to the program, pass a path to a method of your own, and
build a path from a name that is only known while the program runs.

Every `Core` parameter that names a file works this way. Examples are the path methods of `Core\IO`,
`Core\Process::run`, `Core\Response::sendFile`, the script of `spawn script`, `Core\Socket::upgrade`
and `Core\Sse::upgrade`. The methods of `Core\Path` work on text, and their parameters are not file
paths.

`#[Core\Path]` is allowed on a `string` or `?string` parameter. On a parameter of any other type, the
program does not compile (`E0836`). A default value of such a parameter, such as `string $path =
'rates.json'`, starts at the folder of the file that declares the method.

A class constant is not joined to the folder, just like a variable. If it is a relative path, the
file method throws a `RuntimeError`. The error for `'data/' . $name` is `E0840`, and its message
shows how to start the path with the folder of the file.

## Example 01: read a file next to the program

```text file=data/prices.txt
coffee 3.50
tea 2.80
```

```nvs
<?nvs
// Shows how to read a file that is stored next to the program.

// The path starts at the folder of this file. `nvs run` gives the same result
// from any folder. This prints the two lines of `data/prices.txt`.
echo Core\IO::read('data/prices.txt');
```

```output
coffee 3.50
tea 2.80
```

## Example 02: your own method takes a path

```text file=templates/welcome.txt
Hello, {name}! Your order is on its way.
```

```nvs
<?nvs
// Shows how to make a parameter of your own method a file path.

class Mail
{
    // `#[Core\Path]` says that `$template` is a file path. A path in quotes
    // passed here starts at the folder of the file that calls the method.
    public static function render(#[Core\Path] string $template, string $name): string
    {
        return Core\Str::replace(Core\IO::read($template), '{name}', $name);
    }
}

// This prints "Hello, Ada! Your order is on its way.".
echo Mail::render('templates/welcome.txt', 'Ada');
```

```output
Hello, Ada! Your order is on its way.
```

## Example 03: a file name known only at run time

```text file=data/prices.txt
coffee 3.50
tea 2.80
```

```nvs
<?nvs
// Shows how to build a path for a file name that the program only knows while
// it runs.

string $name = 'prices.txt';

// `Core\Path::thisDir('data')` returns the full path of the `data` folder next
// to this file. The name is added to it, so this read works.
echo Core\IO::read(Core\Path::thisDir('data') . '/' . $name);

// `Core\Path::join` adds the name to a full folder path. This prints the same file.
string $folder = Core\Path::thisDir('data');
echo Core\IO::read(Core\Path::join($folder, $name));
```

```output
coffee 3.50
tea 2.80
coffee 3.50
tea 2.80
```

# Ending a program

A program ends when its last line has run. Its exit status is then `0`, which tells the shell that
all went well.

`exit` ends the program early. `exit;` ends it with status `0`. `exit(3);` ends it with status `3`,
and the shell can read that number. A status is a number from 0 to 255. A program that checks or
imports something can use it to report how many problems it found. `exit("Nothing to do.");`
prints the text and ends with status `0`.

**Good to know:** `exit` is not an error. A `catch` does not stop it, and a `finally` block does not
run. `die` does not exist in Novis. If an error is thrown and nothing catches it, the program ends
with status `1` and prints where the error came from.
The last example shows that a line after `exit` does not run.

The status is one byte. A number outside 0 to 255 keeps only its lowest eight bits, so `exit(300)`
ends with status `44` and `exit(-1)` ends with status `255`. This is the same on every system.

`exit("bye")` prints `bye` to standard output and adds no newline. Put `"\n"` at the end of the text
if you want one.

`die` does not compile (`E0228`). The message names `exit`, which takes the same argument.

A thrown error that nothing catches ends the program with status `1`. The error and the lines it
passed through are printed to standard error.

## Example 01: stop early when there is nothing to do

```nvs
<?nvs
// A program does not have to run to its last line. This one prints today's
// orders; when there are none, there is nothing left to do, so it says so
// and stops right there. On its own, `exit` ends the program as a success.

array<string> $orders = [];

echo "Nightly order report\n";

if (Core\Arr::count($orders) == 0) {
    echo "No orders came in today.\n";
    exit;
}

foreach ($orders as string $order) {
    echo '- ', $order, "\n";
}

echo "That is every order.\n";
```

```output
Nightly order report
No orders came in today.
```

## Example 02: say why you are stopping

```nvs
<?nvs
// `exit` can be handed a line of text. The text is written out first, and
// then the program ends as a success. It is the short way to stop and tell
// whoever reads the output why you stopped.

string $importFolder = '';

echo "Customer import\n";

    exit("No import folder was set, so there is nothing to read.\n");
```


## Example 03: tell the shell whether the check passed

```nvs
<?nvs
// The number you pass to `exit` is the exit status that the shell reads.
// This program checks some addresses and exits with the number of problems.
// Every address below has an `@`, so the exit status is `0`.

array<string> $addresses = ['ada@example.com', 'grace@example.com'];

int $problems = 0;
foreach ($addresses as string $address) {
    if (Core\Str::contains($address, '@')) {
        echo 'ok   ', $address, "\n";
    } else {
        echo 'bad  ', $address, "\n";
        $problems = $problems + 1;
    }
}

echo 'checked ', Core\Arr::count($addresses), ', problems ', $problems, "\n";
exit($problems);
```

```output
ok   ada@example.com
ok   grace@example.com
checked 2, problems 0
```
