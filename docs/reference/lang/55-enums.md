# Declaring an enum

Declares a new type whose values are a fixed set of named numbers.

Write the cases between `{` and `}`, separated by commas. Every case has a whole number behind it.
You can write that number with `=`, or leave it out. The first case with no number written is `0`,
and every later case with no number written is one more than the case before it. A number may be
negative or zero, and two cases may carry the same number.

`enum Level: int` and `enum Level: uint` name the type of number behind the cases. With nothing
written it is `int`. No other type backs an enum. An enum body holds cases and nothing else: a
method, a constant or an `implements` clause does not compile. Put the behaviour in a class that
takes the enum.

**The examples below** show an enum with no numbers written, then an enum whose numbers you choose,
then a set of permissions where each case is one bit of a number. Example 04 shows numbers that count
on from a number you write. Examples 05 to 07 show three enums that do not compile.

A case value is a whole number written in the code. It may be negative, and it may be written in hex
(`0x10`), in binary (`0b11`) or with underscores (`1_000`). Anything else is the error `E0436`. That
covers a calculation such as `1 << 3`, another case, a class constant, a `float` and a string.

A value that does not fit the backing type is the error `E0437`. `enum M: uint { A = -1 }` is one
example. A case with no value after the largest possible number is `E0437` too, because no number is
left to count on to.

A comma after the last case is allowed. An enum with no cases compiles.

Two cases with the same value are equal: `Suit::A == Suit::B` is `true` when both are `1`.

The enum name and every case name are PascalCase. A name that starts with a lowercase letter or has
an underscore, such as `hearts` or `Big_One`, is the error `E0110`. The help gives the fixed name.

These forms do not compile:

- `case` before a case name is the error `E0239`.
- A constant, a method, or a `;` between cases is the error `E0220`.
- `implements` on an enum is the error `E0218`.
- `enum Suit: string` is the error `E0219`. Any other backing type except `int` and `uint` is
  `E0438`.
- An enum with the same name as another enum or a class in the file is the error `E0304`.
- An enum declared inside a method is the error `E0233`. Declare it at the top level of the file,
  or in a class body.

A case that the enum does not have, such as `Suit::Clubs`, is the error `E0309`.

## Example 01: the steps of an order

```nvs
<?nvs
// Shows an enum written without any numbers. The first case is 0, and every
// case after it is one more than the case before it.

enum Step { Ordered, Packed, Shipped, Delivered }

// `as int` gives the number behind a case. This prints 0, 1, 2 and 3.
echo Step::Ordered as int, "\n";
echo Step::Packed as int, "\n";
echo Step::Shipped as int, "\n";
echo Step::Delivered as int, "\n";

// A variable of type `Step` holds one of these four cases and nothing else.
Step $current = Step::Packed;

// This prints `packed`.
echo $current == Step::Packed ? 'packed' : 'somewhere else', "\n";
```

```output
2
3
```


## Example 03: what a role may do

```nvs
<?nvs
// Shows why you choose the numbers yourself. Each permission gets a number with
// a single bit set, so one `uint` can hold several permissions at once.

class Role
{
    enum Permission: uint { Read = 1, Write = 2, Delete = 4, Invite = 8 }

    // Adds one permission to a set of permissions.
    public static function add(uint $set, Permission $p): uint
    {
        return $set | ($p as uint);
    }

    // Returns `true` when the set contains the permission.
    public static function has(uint $set, Permission $p): bool
    {
        return ($set & ($p as uint)) != 0;
    }
}

uint $editor = Role::add(Role::add(0, Role::Permission::Read), Role::Permission::Write);

// An editor may read and write, and may not delete.
// This prints `read: yes`, `write: yes` and `delete: no`.
echo Role::has($editor, Role::Permission::Read) ? 'read: yes' : 'read: no', "\n";
echo Role::has($editor, Role::Permission::Write) ? 'write: yes' : 'write: no', "\n";
echo Role::has($editor, Role::Permission::Delete) ? 'delete: yes' : 'delete: no', "\n";
```

```output
read: yes
write: yes
delete: no
```

# A case is its integer

Turns an enum case into the whole number behind it.

Every case of an enum has a number, and `as int` gives you that number. This is the only way to get a
number from a case. A case has no text form, so `echo` on a case, a case inside a `"..."` string, and
`as string` do not compile. To show a case to a person, convert it to its number first, or write
your own function that returns a name for each case.

An enum declared as `enum E: uint` converts with `as uint` instead, and only with `as uint`.

**Good to know:** the number is the value of the case, which is not always its position in the list.
The first case is `0`, and each later case counts on from the one before it. A case may also set its
own value.

**The examples below** show reading the number, printing a name for a case, and saving a choice as a
number. Example 04 shows that `as string` on a case does not compile.

`echo` on a case, a case in a `"..."` string and a case joined with `.` are the error `E0707`. A case
as an array key is the error `E0434`. Write `$case as int` for the key.

`as float`, `as decimal` and `as string` on a case are the error `E0708`. So is `as int` on a `uint`
enum, and `as uint` on an `int` enum. Convert to the backing type first, then to the type you want:
`(Level::High as int) as string`.

`as bool` on a case compiles, and the result is always `true`. Every case is `true` in a condition,
also a case whose number is `0`.

A case of one enum does not convert to another enum. `Mode::Read as Access` is the error `E0416`, also
when both enums have a case with the same number. Write a `match` that names every case.

`+`, `-` and the other arithmetic operators on a case are the error `E0415`. Convert the case with
`as int` first. This also applies to `-1 as Level`: `as` runs before the `-`, so write `(-1) as Level`.

`Core\Json::encode` and `Core\Debug::dump` write a case as its number.

In a `mixed` variable, a case knows that it is an enum case, but not which enum. `$value is int` is
`false` for it. `$value is Level` is `true` when its number belongs to a case of `Level`, also when it
came from another enum.

## Example 02: printing a name for a case

```nvs
<?nvs
// Shows how to print an enum case. A case has no text form, so this program
// writes a function that returns a name, and prints the number beside it.

class Levels
{
    enum Level { Low, Mid, High }

    // Returns a name a person can read for one case.
    public static function name(Level $level): string
    {
        return match ($level) {
            Level::Low => 'low',
            Level::Mid => 'mid',
            Level::High => 'high',
        };
    }
}

array<Levels::Level> $seen = [Levels::Level::High, Levels::Level::Low, Levels::Level::Mid];
// This prints `high 2`, then `low 0`, then `mid 1`.
foreach ($seen as Levels::Level $level) {
    echo Levels::name($level), ' ', $level as int, "\n";
}
```

```output
high 2
low 0
mid 1
```

# From an integer back to a case

Turns a number into the case of an enum that carries it.

`$n as Level` gives the case whose number is `$n`. When no case of `Level` carries that number, it
throws a `RuntimeError` whose message names every case of the enum. Write `$n as ?Level` where the
number comes from outside your program: the result is then `null` instead of an error, and your
program chooses what to do about it.

The value on the left is converted to the enum's backing type first, so text and a `float` reach a
case too. `"10" as Level` converts the text to `10` and then looks for the case. Text that is not a
number gives `null` under `as ?Level`, and throws under `as Level`.

**The examples below** convert a number that names a case, then show what happens when no case
carries the number, then read a setting that arrives as text.

The value is first converted to the backing type, with the rules of `as int` or `as uint`. Then the
enum is searched for a case with that number. Each step can fail:

- A number that no case has throws a `RuntimeError`. The message lists every case of the enum.
- Text that is not a whole number throws a `RuntimeError`. Text with a space, such as `" 1"`, and text
  with a fraction, such as `"2.0"`, are not whole numbers.
- A `float` with a fraction, such as `1.5`, throws an `ArithmeticError`. A `float` without one, such
  as `2.0`, finds the case with the number `2`.
- A negative number for a `uint` enum throws an `ArithmeticError`.
- `null` throws a `RuntimeError`.

`as ?Level` gives `null` in each of these cases, and throws nothing.

`ArithmeticError` is not a kind of `RuntimeError`. A `catch (RuntimeError $e)` does not catch it.

When two cases have the same number, the result is equal to both of them.

A `mixed` value and a `tainted string` convert the same way. `as Level` does not convert a `bool`:
`true as Level` is the error `E0708`.

An enum has no `from` or `tryFrom` method. `Level::from(1)` is the error `E0309`. Write `1 as Level` or
`1 as ?Level`.

## Example 01: a number that names a case

```nvs
<?nvs
// Shows how a number becomes a case of an enum. `as Level` looks for the case
// that carries the number.

enum Level: int { Debug = 0, Info = 1, Warn = 2, Error = 3 }

int $stored = 2;
Level $level = $stored as Level;

// This prints `warn`.
echo $level == Level::Warn ? 'warn' : 'something else', "\n";

// The number comes back out with `as int`. This prints 2.
echo $level as int, "\n";

// Text is converted to the number first, so this also finds `Level::Error`.
Level $fromText = '3' as Level;

// This prints 3.
echo $fromText as int, "\n";
```

```output
warn
2
3
```

## Example 02: a number that names no case

```nvs
<?nvs
// Shows the two ways to convert a number that no case carries. `as Level`
// throws an error. `as ?Level` returns `null`.

enum Level: int { Debug = 0, Info = 1, Warn = 2, Error = 3 }

// The message names every case of the enum, so you can see what was expected.

    Level $level = 9 as Level;
    echo "this line is never reached\n";
} catch (RuntimeError $e) {
    echo $e->message, "\n";
}

// `as ?Level` gives `null` for the same number, and throws nothing.

// This prints `no such level`.
echo $maybe == null ? 'no such level' : 'found one', "\n";

// Text that is not a number gives `null` as well.
?Level $fromText = 'loud' as ?Level;

// This prints `no such level`.
echo $fromText == null ? 'no such level' : 'found one', "\n";
```

```output
no such level
```

## Example 03: a setting that arrives as text

```nvs
<?nvs
// Shows how a program reads a setting written by somebody else. The text may
// name no case, so the program uses `as ?Level` and keeps its own default.

class Settings
{
    enum Level: int { Debug = 0, Info = 1, Warn = 2, Error = 3 }

    // Returns the level the text names. Returns `Level::Info` when the text
    // names no level.
    public static function level(string $text): Level
    {
        ?Level $found = $text as ?Level;
        if ($found == null) {
            return Level::Info;
        }
        return $found;
    }

    // Returns `true` when a message at this level should be written.
    public static function writes(Level $configured, Level $message): bool
    {
        return ($message as int) >= ($configured as int);
    }
}

array<string> $lines = ['2', '0', 'verbose', ''];

// The first two lines name a level. The last two do not, so both become
// `Settings::Level::Info`. This prints 2, 0, 1 and 1.
foreach ($lines as string $line) {
    echo Settings::level($line) as int, "\n";
}

Settings::Level $configured = Settings::level('2');

// A warning is written and a debug message is not. This prints `yes` and `no`.
echo Settings::writes($configured, Settings::Level::Warn) ? 'yes' : 'no', "\n";
echo Settings::writes($configured, Settings::Level::Debug) ? 'yes' : 'no', "\n";
```

```output
2
0
1
1
yes
no
```

# Comparing cases

Compares two cases of one enum.

`==` is true when both sides are the same case, and `!=` is true when they are different. Both sides
must belong to the same enum. A case compared against a plain number, or against a case of another
enum, does not compile: the two types have no value in common, so the comparison could only ever be
false.

There is no `<` or `>` between cases. Write `$case as int` on both sides and compare the numbers,
which is also how you subtract or add them. That keeps the order you get explicit, because the order
of the cases is the order of the numbers you gave them.

**The examples below** show `==` and `!=` between cases, then the number comparison that puts two
cases in order, then a page that decides what a visitor may do from a role. Example 04 shows that a case compared with
a number does not compile.

A case compared with `==` or `!=` to a number, a string or a case of another enum is the error `E0466`.
A case compared to `null` is `E0466` too, unless the variable has a type such as `?Level` that allows
`null`. A `?Level` variable that contains a case compares with that case as usual.

`<`, `>`, `<=`, `>=` and `<=>` on two cases are the error `E0715`. Convert both sides with `as int`.

`==` compares numbers. When both sides have the type `Level`, only cases of `Level` are compared. In
a `mixed` variable, a case does not keep which enum it belongs to. There, `==` is `true` between a case
and a plain number with the same value, and between cases of two enums with the same number.
`Core\Arr::contains` compares the same way.

## Example 01: testing which case a value is

```nvs
<?nvs
// Shows how to compare two cases of one enum. `==` is true when both sides are
// the same case. `!=` is true when they are different cases.

enum Rank { Bronze, Silver, Gold }

Rank $held = Rank::Silver;

// This prints `the same`.
if ($held == Rank::Silver) {
    echo "the same\n";
}

// This prints `not gold`.
if ($held != Rank::Gold) {
    echo "not gold\n";
}

Rank $other = Rank::Gold;

// This prints `different`. Two variables compare the same way as a variable and
// a case.
if ($held != $other) {
    echo "different\n";
}
```

```output
the same
not gold
different
```

## Example 02: putting two cases in order

```nvs
<?nvs
// Shows how to test whether one case is higher than another. `<` and `>` do not
// work on cases. Convert both sides with `as int` and compare the numbers.

enum Rank { Bronze = 1, Silver = 2, Gold = 3 }

Rank $held = Rank::Silver;

// This prints `below gold`. `Silver` is 2 and `Gold` is 3.
if (($held as int) < (Rank::Gold as int)) {
    echo "below gold\n";
}

// This prints `at least bronze`. `Bronze` is 1.
if (($held as int) >= (Rank::Bronze as int)) {
    echo "at least bronze\n";
}

// The numbers work in arithmetic as well. This prints 1.
echo (Rank::Gold as int) - ($held as int), "\n";
```

```output
below gold
at least bronze
1
```

## Example 03: what a visitor may do on a page

```nvs
<?nvs
// Shows a page that decides what a visitor may do. The role arrives as an enum.
// `==` tests for one role, and `as int` compares two roles by their number.

class Page
{
    enum Role { Guest = 0, Member = 10, Editor = 20, Owner = 30 }

    public static function actions(Role $role): string
    {
        // A guest is a single case, so `==` is the test for it.
        if ($role == Role::Guest) {
            return 'read';
        }
        // Everybody from `Editor` upwards may publish, so the numbers decide.
        if (($role as int) >= (Role::Editor as int)) {
            return 'read, comment, publish';
        }
        return 'read, comment';
    }
}

array<Page::Role> $visitors = [Page::Role::Guest, Page::Role::Member, Page::Role::Owner];

// This prints `read`, then `read, comment`, then `read, comment, publish`.
foreach ($visitors as Page::Role $role) {
    echo Page::actions($role), "\n";
}
```

```output
read
read, comment
read, comment, publish
```

# `match` and `switch` over an enum

Chooses what to do for each case of an enum.

`match` and `switch` both compare the subject with each case label, from the first one written to
the last. `match` is an expression: it returns the value of the arm that fits, and nothing runs after
that arm. When no arm fits and there is no `default`, `match` throws an error, so a `default` arm is
how you cover the cases you did not name.

`switch` runs statements instead of returning a value. An arm ends at its `break`. An arm without a
`break` runs on into the arm written below it, which is useful when one case needs everything a
later case does and a little more.

**The examples below** show a `match` with a `default` arm, then the error a `match` throws without
one, then a `switch` whose first arm runs on into the second.

A `match` that has an arm for every case needs no `default`. The compiler does not check that every
case has an arm. A case with no arm throws the `LogicError` when it reaches the `match`.

A label must be a case of the subject's enum. A case of another enum is the error `E0466`, and so is
a number such as `1`. This is the same in a `match` arm and in a `switch` `case`. A `null` label is
`E0466` too, unless the subject has a type such as `?Mode` that allows `null`.

An arm for `Mode::Read` does not narrow the subject. Inside that arm, `$m` still has the type `Mode`.
Passing it to a parameter of the type `Mode::Read` is the error `E0401`. The same is true inside a
`switch` `case`. Write `match (true)` with the arm `$m == Mode::Read` to narrow `$m` in that arm.

A `switch` with no matching `case` and no `default` runs none of its code. It does not throw.

When the subject has a smaller type such as `Mode::Read|Mode::Write`, an arm for `Mode::Exec` still
compiles. That arm never runs.

In a `mixed` subject, a label is compared by its number. A `mixed` variable that contains the
number `1` matches the arm `Mode::Write` when `Write` is the case with the number `1`.

## Example 01: choosing a text for each case

```nvs
<?nvs
// Shows a `match` that gives one text for each case of an enum. `match` tries
// the arms from top to bottom and returns the first one that fits.

class Name
{
    enum Mode { Read, Write, Exec }

    public static function of(Mode $mode): string
    {
        return match ($mode) {
            Mode::Read => 'read',
            Mode::Write => 'write',
            // `default` is used for every case that no arm above names.
            default => 'other',
        };
    }
}

// This prints `write`.
echo Name::of(Name::Mode::Write), "\n";

// This prints `other`. No arm names `Exec`, so the `default` arm is used.
echo Name::of(Name::Mode::Exec), "\n";
```

```output
write
other
```

## Example 02: a match without a default throws

```nvs
<?nvs
// Shows what happens when no arm fits and there is no `default`. The `match`
// throws an error, which you can catch. Add a `default` arm to avoid it.

enum Mode { Read, Write, Exec }

Mode $mode = Mode::Exec;

try {
    string $name = match ($mode) {
        Mode::Read => 'read',
        Mode::Write => 'write',
    };
    echo $name, "\n";
} catch (Throwable $error) {
    // This prints the message: no `match` arm matched the subject.
    echo $error->message, "\n";
}

// The same `match` with a `default` arm returns a value for every case. This
// prints `other`.
echo match ($mode) { Mode::Read => 'read', default => 'other' }, "\n";
```

```output
no `match` arm matched the subject
other
```

## Example 03: the next step for each order

```nvs
<?nvs
// Shows the next step to take for each order in a list. A `switch` runs
// statements instead of returning a value, and `break` ends an arm. An arm
// without `break` runs on into the arm below it.

class Work
{
    enum Stage { Placed, Paid, Shipped }

    public static function next(Stage $stage): string
    {
        string $todo = '';
        switch ($stage) {
            case Stage::Placed:
                $todo = $todo . 'take the payment; ';
            // No `break` here, so a new order is also packed.
            case Stage::Paid:
                $todo = $todo . 'pack the box';
                break;
            case Stage::Shipped:
                $todo = $todo . 'send the tracking number';
                break;
        }
        return $todo;
    }
}

array<Work::Stage> $orders = [Work::Stage::Placed, Work::Stage::Paid, Work::Stage::Shipped];

// This prints `take the payment; pack the box`, then `pack the box`, then
// `send the tracking number`.
foreach ($orders as Work::Stage $stage) {
    echo Work::next($stage), "\n";
}
```

```output
take the payment; pack the box
pack the box
send the tracking number
```

# An enum as a type

Uses an enum's name as a type.

An enum is a type like `int` or `string`, and you can write its name anywhere a type is written: a
property, a parameter, a return type, the element type of an `array<Suit>`, the variable of a
`foreach` loop, and the type a generator gives with `Iterator<Suit>`. Everything declared that way
accepts the cases of that enum and no other value. A number or a string there does not compile.

A case is not an array key. Write `$case as int` to get the number behind the case, and use that
number as the key. The array then works as any array with whole-number keys does.

**The examples below** show the type on a property, a parameter and a return value, then an array of
cases and two loops over one, then a list of orders that reads a text label from a table.

A variable of the type `Suit` accepts only the cases of `Suit`. A number, a case of another enum and
an `array<Suit>` element of another type are the error `E0401`. A `foreach` variable declared with
another enum is `E0401` too. A method that declares `Suit` and returns a number is the error `E0403`.

`var $s = Suit::Hearts;` gives `$s` the type `Suit`. Assigning `1` to it later is `E0401`.

A property of an enum type has no default value. Give it one, such as `public Suit $suit =
Suit::Hearts;`, or assign it in the constructor. Without either, the class does not compile
(`E0409`). A parameter may have a case as its default value: `Suit $suit = Suit::Hearts`.

`?Suit` accepts a case or `null`.

`Core\Json::encode` writes an `array<Suit>` as an array of numbers: `[0,1]`.

## Example 01: a type for a property and a method

```nvs
<?nvs
// Shows an enum used as a type. The name `Level` is the type of a property, of
// a parameter and of a return value. Each of them accepts the three cases of
// `Level` and no other value.

class Gate
{
    enum Level { Low = 1, Mid = 5, High = 9 }

    // This property stores one case of `Level`.
    public Level $level;

    public function constructor(Level $level)
    {
        $this->level = $level;
    }

    // The parameter and the return type are both `Level`.
    public function raise(Level $to): Level
    {
        if (($to as int) > ($this->level as int)) {
            $this->level = $to;
        }
        return $this->level;
    }
}

var $gate = new Gate(Gate::Level::Low);

// This prints 5. `Mid` is higher than `Low`, so the gate moves up to `Mid`.
echo $gate->raise(Gate::Level::Mid) as int, "\n";

// This prints 5 again. `Low` is lower, so the gate stays at `Mid`.
echo $gate->raise(Gate::Level::Low) as int, "\n";
```

```output
5
5
```

## Example 02: a type for an array and a loop

```nvs
<?nvs
// Shows an enum as the element type of an array and as the type of a loop
// variable. `array<Deck::Suit>` is an array where every element is one case of
// `Deck::Suit`.

class Deck
{
    enum Suit { Clubs, Hearts, Spades }

    // A generator declared `Iterator<Suit>` gives one case at a time.
    public static function red(): Iterator<Suit>
    {
        yield Suit::Hearts;
    }
}

array<Deck::Suit> $hand = [Deck::Suit::Spades, Deck::Suit::Clubs];

// This prints 2 and then 0. The loop variable is declared `Deck::Suit`.
foreach ($hand as Deck::Suit $card) {
    echo $card as int, "\n";
}

// This prints 1. The generator gives cases of `Deck::Suit`, so the loop
// variable is a `Deck::Suit` here too.
foreach (Deck::red() as Deck::Suit $card) {
    echo $card as int, "\n";
}
```

```output
2
0
1
```


# A union of cases is a narrower type

Writes a type that accepts only some of an enum's cases.

Where a type is written you can name two or more cases of one enum with `|` between them, as in
`Mode::Read|Mode::Write`. A variable, a parameter, a property or a return type declared that way
accepts those cases and nothing else. A value typed as the whole enum does not fit, even when it is
one of the named cases while the program runs.

Such a value enters the smaller type with `as Mode::Read|Mode::Write`, which throws an error when
the value is not one of the named cases. `as ?Mode::Read|Mode::Write` returns `null` instead of
throwing.

**Good to know:** the smaller type fits everywhere the whole enum is wanted, so you never need a
conversion in that direction.

**The examples below** show the type on a parameter, the two conversions into it, a web handler that
takes only the two requests it is written for, and a case outside the type that does not compile.

When the parameter is `Mode::Read|Mode::Write`, `Open::file(Mode::Exec)` and `Open::file($m)` with
a `Mode` variable give the same error: `E0401`, ``expected `Mode::Read|Mode::Write`, found `Mode` ``. A method that declares the smaller type and
returns another case is the error `E0403`. An array literal of the type `array<Mode::Read|Mode::Write>`
with another case in it is `E0401`.

A type may name one case alone, such as `Mode::Read`. It may also name cases of two enums, or
name the same case twice.

`if ($m == Mode::Read)` narrows `$m` to the type `Mode::Read` inside the block. This works on a
variable of the whole enum and on a variable of a smaller type. Nothing else narrows to a smaller
type:

- `$m == Mode::Read || $m == Mode::Write` does not narrow `$m` to `Mode::Read|Mode::Write`.
- The `else` block of `$m == Mode::Read`, and the block of `$m != Mode::Read`, keep the whole type.
- An arm of `match ($m)` keeps the whole type.

Write `$m as Mode::Read|Mode::Write` for a set of two or more cases.

`$m is Mode::Read|Mode::Write` is `true` when `$m` is one of the two cases.

`as` also converts a number. `1 as Mode::Read|Mode::Write` gives `Mode::Write`. A number written in
the code that is not one of the cases is the error `E0470`. A number in a `mixed` variable is checked
while the program runs. When it is not one of the cases, the `RuntimeError` message names the cases
the type accepts.

`?Mode::Read|Mode::Write` and `Mode::Read|Mode::Write|null` both accept `null` as well.

A `type` alias may name a set of cases: `type Rw = Mode::Read|Mode::Write;`.

`$m == Mode::Exec` compiles when `$m` has the type `Mode::Read|Mode::Write`. The result is always
`false`.

## Example 01: a type that accepts only some cases

```nvs
<?nvs
// Shows a parameter that accepts two of an enum's four cases. Writing the cases
// with `|` between them makes a type of its own.

// `Mode` stays outside the classes, because `File` and `Log` both use it.
enum Mode { Read, Write, Append, Exec }

class File
{
    // This parameter accepts `Mode::Read` and `Mode::Write`. No other case of
    // `Mode` compiles here.
    public static function open(Mode::Read|Mode::Write $mode): string
    {
        return 'opened in mode ' . (($mode as int) as string);
    }
}

// This prints `opened in mode 0` and `opened in mode 1`.
echo File::open(Mode::Read), "\n";
echo File::open(Mode::Write), "\n";

// A value of the smaller type fits everywhere the whole enum is wanted.
class Log
{
    public static function line(Mode $mode): string
    {
        return 'mode=' . (($mode as int) as string);
    }
}

Mode::Read|Mode::Write $chosen = Mode::Write;
// This prints `mode=1`.
echo Log::line($chosen), "\n";
```

```output
opened in mode 0
opened in mode 1
mode=1
```

# An enum inside a class

Declares an enum in the body of the class or interface that uses it.

Write the enum in the body, next to the properties and methods. Inside the body, the enum is
`Status` and a case is `Status::Paid`. Everywhere else, the enum is `Order::Status` and a case is
`Order::Status::Paid`. A case is a whole number, the same as in an enum outside a class.

The enum takes no `public` or `private`. A subclass does not inherit it, and a class that
implements an interface does not inherit the interface's enum. Write `Status` inside the owner and
`Order::Status` everywhere else. `self::Status` and `use Shop\Order::Status;` do not compile. An
enum that several classes use is declared outside the classes.

**The examples below** show an order that keeps its status, a command line program with its own exit
codes, and an interface whose enum every class that implements it returns. Then three programs that
do not compile: an enum with `private`, a subclass that names its parent's enum, and a `use` of an
enum.

`public`, `private` or `protected` before the enum is the error `E0133`. The cases leave the class in
every value it returns, so a visibility could only hide the name.

A subclass does not inherit the enum. `Refund::Status`, where `Refund` extends `Order`, is the error
`E0309`, and its help names `Order::Status`. Inside `Refund`, the name `Status` alone is the error
`E0303`. The same is true in a class that implements an interface with an enum. Write
`Order::Status` or `Job::Result` there.

`self::Status` and `static::Status` are the error `E0135`. Inside the class that declares the enum,
write `Status`.

`use Shop\Order::Status;` is the error `E0212`. Write `use Shop\Order;` and then `Order::Status`.

An enum, a class constant and a `type` alias in one class must have different names. Two of them
with the same name are the error `E0304`. Two enums with the same name in one class are `E0304` too.

An enum body does not declare an enum (`E0220`). An `if` block does not declare one either
(`E0233`). A class body declares an enum or a `type` alias, but not a class or an interface
(`E0233`).

An enum in a class may have the same name as an enum outside the classes. Inside the class, the
name means the class's own enum.

`Order::Status::class` gives the full name of the enum. In the namespace `Shop`, that is
`Shop\Order::Status`. The enum `Status` in the class `Shop\Order` and a class `Status` in the
namespace `Shop\Order` are two different types. `Shop\Order::Status` names the enum, and
`Shop\Order\Status` names the class.

Two classes may each declare an enum with the same name. They are two different enums.
`A::Kind::X == B::Kind::X` is the error `E0466`.

## Example 01: an order and its status

```nvs
<?nvs

{
    enum Status { Open, Paid, Shipped, Cancelled }

    // Inside the class, the enum is `Status`.
    public Status $status = Status::Open;

    public function pay(): void
    {
        $this->status = Status::Paid;
    }

    public function ship(): void
    {
        if ($this->status == Status::Paid) {
            $this->status = Status::Shipped;
        }
    }
}

Order $order = new Order();
$order->ship();

// The order was not paid, so it is still open. This prints 0.
echo $order->status as int, "\n";

$order->pay();
$order->ship();

// Outside the class, the enum is `Order::Status`. This prints `shipped`.
echo $order->status == Order::Status::Shipped ? 'shipped' : 'not shipped', "\n";
```


# What an enum does not have

Says what an enum does not have, and what to write instead.

A case is a number with a name, not an object. It has no `->name` and no `->value`, and an enum has
no `cases()`, `from()` or `tryFrom()`. An enum body has cases and nothing else, so a method, a
constant and an `implements` clause do not compile either.

You write these things outside the enum. `$case as int` gives the number of a case. `$n as Level`
and `$n as ?Level` turn a number back into a case. For the name of a case, for a list of every case,
or for any behaviour at all, write a class that takes the enum and put a `match` in it. The compiler
does not check that the `match` names every case. A case with no arm throws a `LogicError` when it
reaches the `match`.

**The examples below** show the name of a case, then the list of every case with a lookup by name,
then a class that carries the behaviour of an order. Examples 04 and 05 show that `->name` and
`cases()` do not compile.

These forms do not compile:

- `->name`, `->value` or any other property on a case is the error `E0405`. A write such as
  `$level->value = 1` is `E0405` too.
- A method call on a case, such as `Level::Info->label()`, is the error `E0405`.
- `Level::from($n)`, `Level::tryFrom($n)` and `Level::cases()` are the error `E0309`. So is a
  constant or a static property read on the enum, such as `Level::COUNT` or `Level::$x`.
- `extends` after an enum name is the error `E0220`.
- `abstract` or `final` before `enum` is a syntax error (`E0101`).
- `clone` on a case is the error `E0781`.

A case is not an object. Putting a case in an `object` variable is the error `E0401`, and
`$case is object` is `false`.

`Level::class` gives the full name of the enum. `Level::Info::class` is the error `E0702`.

## Example 01: the name of a case

```nvs
<?nvs
// Shows how to get the name of a case. A case has no `->name`, so the names
// live in a `match` inside a class of your own.

class Levels
{
    enum Level { Debug, Info, Warn }

    // Returns the name of a level. The `match` has an arm for every case of
    // `Level`. Add an arm here when you add a case to the enum.
    public static function name(Level $l): string
    {
        return match ($l) {
            Level::Debug => 'debug',
            Level::Info => 'info',
            Level::Warn => 'warn',
        };
    }
}

// This prints `info` and `warn`.
echo Levels::name(Levels::Level::Info), "\n";
echo Levels::name(Levels::Level::Warn), "\n";

// The number behind a case needs no class. This prints 2.
echo Levels::Level::Warn as int, "\n";
```

```output
info
warn
2
```

## Example 02: a list of every case

```nvs
<?nvs
// Shows the list of every case. An enum has no `cases()`, so the list is an
// ordinary static method that returns `array<Level>`.

class Levels
{
    enum Level { Debug, Info, Warn }

    public static function all(): array<Level>
    {
        return [Level::Debug, Level::Info, Level::Warn];
    }

    public static function name(Level $l): string
    {
        return match ($l) {
            Level::Debug => 'debug',
            Level::Info => 'info',
            Level::Warn => 'warn',
        };
    }

    // Returns the level with this name, or `null` when there is none.
    public static function byName(string $wanted): ?Level
    {
        foreach (Levels::all() as Level $l) {
            if (Levels::name($l) == $wanted) {
                return $l;
            }
        }
        return null;
    }
}

// This prints `debug`, `info` and `warn`, one per line.
foreach (Levels::all() as Levels::Level $l) {
    echo Levels::name($l), "\n";
}

// This prints 3.
echo Core\Arr::count(Levels::all()), "\n";

// A name nobody wrote gives `null`, so the program picks its own level.
// This prints 1.
echo (Levels::byName('loud') ?? Levels::Level::Info) as int, "\n";
```

```output
debug
info
warn
3
1
```

## Example 03: a class that carries the behaviour

```nvs
<?nvs
// Shows where the behaviour of an enum goes. The enum holds the states of an
// order, and a class of your own holds everything the order can do.

class Orders
{
    enum Status { Placed, Paid, Shipped, Cancelled }

    // Returns the text shown to a customer for this status.
    public static function label(Status $s): string
    {
        return match ($s) {
            Status::Placed => 'waiting for payment',
            Status::Paid => 'ready to ship',
            Status::Shipped => 'on its way',
            Status::Cancelled => 'cancelled',
        };
    }

    // Returns `true` when nothing more happens to an order in this status.
    public static function isFinal(Status $s): bool
    {
        return match ($s) {
            Status::Shipped => true,
            Status::Cancelled => true,
            Status::Placed => false,
            Status::Paid => false,
        };
    }

    // Returns the status after this one, or `null` when there is none.
    public static function next(Status $s): ?Status
    {
        return match ($s) {
            Status::Placed => Status::Paid,
            Status::Paid => Status::Shipped,
            Status::Shipped => null,
            Status::Cancelled => null,
        };
    }
}

Orders::Status $order = Orders::Status::Paid;

// This prints `ready to ship` and `no`.
echo Orders::label($order), "\n";
echo Orders::isFinal($order) ? 'yes' : 'no', "\n";

// The order walks to its last status. This prints `on its way` and `yes`.
?Orders::Status $after = Orders::next($order);
if ($after != null) {
    echo Orders::label($after), "\n";
    echo Orders::isFinal($after) ? 'yes' : 'no', "\n";
}
```

```output
ready to ship
no
on its way
yes
```

# `Core` enums

The enums that come with Novis. They work exactly like the ones you write yourself.

`Core\Arr::Order` chooses the direction of a sort. It is declared in the class `Core\Arr`, whose
methods use it. `Core\RoundMode` chooses how a number is rounded. Part B of the reference lists the
rest.

A case is written `Core\Arr::Order::Desc`. You pass it to a method that needs it. You can keep it in a
variable of type `Core\Arr::Order`, compare it with `==`, use it in a `match`, and convert it to its
number with `as int`.

Nothing about these enums is special. They have no methods and no `->value`, the same as your own.
`as Core\Arr::Order` or `as ?Core\Arr::Order` converts a number back into a case. A method that takes
one of these enums accepts only its cases. A wrong value is an error when the program is compiled.

**The examples below** sort with `Core\Arr::Order`, round a bill with `Core\RoundMode`, then turn the
text a visitor sent into a sort order. Example 04 shows that a number in place of a case does not
compile.

A number where a member needs a `Core` enum is the error `E0401`, such as `{ order: 1 }` for
`Core\Arr::sort`. A case of another enum is `E0401` too. `Core\Arr::Order::Desc` passed to
`Core\Decimal::divRound` needs a `Core\RoundMode`, so it does not compile.

A case the enum does not have, such as `Core\Arr::Order::Random`, is the error `E0405`.

`7 as Core\Arr::Order` throws a `RuntimeError` when no case has the number `7`. The message names
every case: `` `7` is not one of `Core\Arr::Order::Asc`, `Core\Arr::Order::Desc` ``.
`7 as ?Core\Arr::Order` gives `null`.

A case of one `Core` enum compared with a case of another is the error `E0466`.

`use Core\Arr;` lets you write `Arr::Order::Desc`. `use Core\Arr::Order;` is the error `E0212`,
because an import names a class and not the enum inside it.

You may declare your own enum named `Order`. It is a different enum from `Core\Arr::Order`.

`Core\Json::encode` and `Core\Debug::dump` write a case of a `Core` enum as its number.

## Example 01: sorting the largest first

```nvs
<?nvs
// Shows the enum that chooses the direction of a sort. `Core\Arr::Order` is an
// ordinary enum. You pass one of its cases to a method that needs it.

array<int> $scores = [3, 1, 2];

// This prints 3, 2 and 1, the largest first.
foreach (Core\Arr::sort($scores, { order: Core\Arr::Order::Desc }) as int $s) {
    echo $s, "\n";
}

// Leaving the option out sorts the other way. This prints 1, 2 and 3.
foreach (Core\Arr::sort($scores) as int $s) {
    echo $s, "\n";
}

// The number behind a case comes out with `as int`, as it does for an enum of
// your own. This prints 0 and 1.
echo Core\Arr::Order::Asc as int, "\n";
echo Core\Arr::Order::Desc as int, "\n";
```

```output
3
2
1
1
2
3
0
1
```

## Example 02: rounding a shared bill

## Example 03: a direction that arrives as text

```nvs
<?nvs
// Shows a `Core` enum used the way your own enums are used. A class turns the
// text a visitor sent into a case, and the case then chooses the sort order.

class Listing
{
    // Returns the order the text names. Returns `Core\Arr::Order::Asc` for any other
    // text, so a visitor cannot send something the sort has no answer for.
    public static function order(string $wanted): Core\Arr::Order
    {
        return match ($wanted) {
            'desc' => Core\Arr::Order::Desc,
            default => Core\Arr::Order::Asc,
        };
    }
}

array<int> $prices = [30, 10, 20];
Core\Arr::Order $order = Listing::order('desc');

// This prints 30, 20 and 10.
foreach (Core\Arr::sort($prices, { order: $order }) as int $p) {
    echo $p, "\n";
}

// A case of a `Core` enum is compared with `==`. This prints `largest first`.
echo $order == Core\Arr::Order::Desc ? 'largest first' : 'smallest first', "\n";
```

```output
30
20
10
largest first
```
