# Every binding has a type

Every variable in a program has a type, and the type never changes.

The short way to declare a local variable is `var`. `var $count = 3;` gives `$count` the type of its
first value, `int`. In a `foreach` loop, `var` gives the value the type of the array's values, and
the key is a `string`.

You can also write the type yourself, as in `float $weight = 1;`. Write it when the value comes
later, when the variable needs a wider type, or when the type helps the reader. Parameters, return
values, properties and the variable in `catch` always have a written type.

A value of another type does not compile, and neither does reading a variable before it has a value.

**Good to know:** a variable belongs to the whole function, not only to its block. So you can read a
loop counter after the loop.

**The examples below** show `var` and then a written type, a loop counter read after its loop, and an
order where every value has a type. The last two do not compile: one assigns a string to an `int`,
and one gives `var` an array with two element types.

A variable is declared once. Every later `$count = …` is an assignment and has no type. A value
of another type does not compile: `$count = "two";` after `var $count = 1;` is the error `E0401`.
The message points to the line that gave `$count` its type.

`int $i = null;` and `uint $u = -1;` are the error `E0401` too. The only conversion without `as` is
widening, such as an `int` value in a `float` variable.

Assigning to a variable that was never declared is the error `E0301`. Reading a variable before
every path has given it a value is also the error `E0301`.

`var` needs a value whose type it can see. `var $xs = [];` does not compile, because an empty array
has no element type. `var $xs = [1, "a"];` does not compile either, because the elements have two
types. Both are the error `E0414`, and the message shows the type to write, such as
`array<int|string> $xs = [1, "a"];`.

The variable of a `catch` clause is a declaration too. Two `catch` clauses in one function may use
the same name when they catch the same type.

## Example 01: var or a written type

```nvs
<?nvs
// Shows the two ways to declare a variable: with `var`, or with a written type.

// `var` gives the variable the type of its first value.
// `$count` is an `int` and `$label` is a `string`. The types never change.
var $count = 3;
var $label = 'boxes';
$count = $count + 1;

// A written type is needed when the variable gets its value later.
string $unit;
$unit = 'kg';

// A written type can also be wider than the first value.
// With `var $weight = 1;` the type is `int`, so the next line would not compile.
float $weight = 1;
$weight = $weight * 2.5;

// This prints `4 boxes, 2.5 kg each`.
echo $count, ' ', $label, ', ', $weight, ' ', $unit, " each\n";
```

```output
4 boxes, 2.5 kg each
```

## Example 02: a loop counter outlives the loop

```nvs
<?nvs
// A variable belongs to the whole function, not only to the block where it is declared.
// So you can read the loop counter `$i` after the loop ends.

var $entries = ['12', 'nine', '30'];
var $total = 0;

// `var $i = 0` makes the counter an `int`.
for (var $i = 0; $i < Core\Arr::count($entries); $i = $i + 1) {
    try {
        $total = $total + ($entries[$i] as int);
    } catch (Throwable $e) {
        // The variable in `catch` always has a written type.
        echo 'skipped ', $entries[$i], ': ', $e->message, "\n";
    }
}

// This prints `read 3 entries, total 42`.
echo 'read ', $i, ' entries, total ', $total, "\n";
```

```output
skipped nine: cannot convert string "nine" to `int`
read 3 entries, total 42
```

## Example 03: price up an order

```nvs
<?nvs
// Prices an order the way a small shop does. Every value has a type: the constant,
// the property, the method's parameter and return value, and each variable.

class Order
{
    public const int TAX_PERCENT = 20;

    public string $customer;

    public function constructor(string $customer)
    {
        $this->customer = $customer;
    }

    public function net(array<decimal> $lines): decimal
    {
        decimal $sum = 0;
        // In a `foreach`, `var $amount` gets the type of the array's values, `decimal`.
        // `var $item` gets the key's type, `string`.
        foreach ($lines as var $item => var $amount) {
            echo $item, ': ', $amount, "\n";
            $sum = $sum + $amount;
        }
        return $sum;
    }
}

var $order = new Order('Blog Press');

// The type is written here because `var` would make these prices `float`.
// A `decimal` keeps exact cents, so `120.00` prints with both zeros.
array<decimal> $lines = ['print run' => 120.00, 'delivery' => 15.50];

// `var $net` gets the type `decimal` from the value that `net` returns.
var $net = $order->net($lines);
decimal $gross = $net + $net * Order::TAX_PERCENT / 100;

echo $order->customer, ' owes ', $gross, ' (', $net, " plus tax)\n";
```

```output
print run: 120.00
delivery: 15.50
Blog Press owes 162.60 (135.50 plus tax)
```

# Numbers: `bool`, `int`, `uint`, `float`, `decimal`

Novis has one true-or-false type and four number types.

- `bool` is `true` or `false`. You cannot use it in arithmetic.
- `int` is a whole number that can be negative.
- `uint` is a whole number that cannot be negative. It can count twice as high as an `int`.
- `float` is a fast number with a fraction. It is not always exact, so use it for a weight or a
  ratio.
- `decimal` is an exact number with up to 28 decimal places. Use it for money.

A number written in the code gets its type from where you put it. `float $weight = 3;` makes `3` a
`float`, and `decimal $price = 1.10;` makes `1.10` a `decimal`.

If a whole number gets too big or too small for its type, the program throws an `ArithmeticError`.
`int` and `uint` cannot be used in one sum. `decimal` and `float` cannot be used in one sum either.
Convert one side with `as`.

**The examples below** show whole numbers that are too big, money and a measurement, and a parcel
priced at a shop counter. The last one adds a `decimal` and a `float`, so it does not compile.

An `int` is a 64-bit signed whole number. A `uint` is a 64-bit unsigned whole number, from `0` to
`18446744073709551615`. A result outside that range throws an `ArithmeticError`, such as
`Integer addition overflowed`. Below zero, a `uint` throws `Integer subtraction overflowed`.

`-1` is never a `uint`, because the `-` is an operator. `uint $u = -1;` is the error `E0401`.
Beside a `uint` variable, a plain number is a `uint` too, so `$u + 1` compiles.

`$i + $u` with an `int` and a `uint` is the error `E0407`. An `int` variable does not assign to a
`uint` variable either: that is the error `E0401`. Convert one side with `as int` or `as uint`.

When one side of a sum is a `float`, the other side is converted to `float`. A `decimal` and a
`float` in one sum is the error `E0455`. A `decimal` and an `int` or a `uint` give a `decimal`.

A `float` prints without a trailing `.0`, so `2.0` prints `2`. `0.1 + 0.2` prints `0.3`, but it is
not equal to `0.3`.

A `decimal` keeps its decimal places: `1.10 * 3` is `3.30`. Division rounds at the 28th place, so
`1 as decimal / 3` is `0.3333333333333333333333333333`.

`bool` has no arithmetic: `$b + 1` is the error `E0716`. A `bool` converts only to `string` and to
`bool`. `true as int` is the error `E0708`, so write `$b ? 1 : 0`. `true as string` is `"1"` and
`false as string` is `""`.

`true` and `false` are also types of their own, with one value each.

## Example 01: whole numbers that never wrap

```nvs
<?nvs
// Whole numbers have two types. An `int` can be negative. A `uint` cannot be negative,
// and it can count twice as high. If a result is too big for its type,
// the program throws an `ArithmeticError`. The number does not wrap around to a small value.

int $balance = -250;
uint $stock = 18446744073709551615;

echo $balance + 100, "\n";
echo $stock, "\n";

try {
    echo $stock + 1, "\n";
} catch (ArithmeticError $e) {
    echo 'out of room: ', $e->message, "\n";
}

bool $owing = $balance < 0;
echo $owing ? 'owing' : 'clear', "\n";
```

```output
owing
```

# Text: `string` and `bytes`

Text is a `string`. Data that may not be text is `bytes`. They are two separate types, and you
convert between them with `as`.

A `string` is always valid text. Its length is the number of characters a person counts. An accented
letter, an emoji or a flag is one character, even when it needs several bytes. There is no
`$name[0]` syntax. `Core\Str::at` returns one character, and `Core\Str::slice` returns several.

`bytes` is for the content of a file, a reply from a network connection or a hash. Its length is the
number of bytes. `Core\Bytes::slice` takes a part of it by byte position.

**Good to know:** `$text as bytes` always works. `$data as string` checks the data first. If the
data is not valid text, it throws a `RuntimeError`.

**The examples below** show a name measured in characters and in bytes, the first character and a
short preview of a title, and uploads sorted into pictures and notes. The last one converts text to
bytes and back, and shows the error for data that is not text.

A `string` is always valid UTF-8. Its length counts graphemes (what a person counts as one
character). `"e\u{301}"` is an `e` with a combining accent: it has one grapheme and three bytes.

`$s[0]` does not compile for a `string` or for `bytes`: it is the error `E0482`. Use
`Core\Str::slice($s, $i, 1)` for a character, or `Core\Bytes::slice` for a byte position.

You cannot write a `bytes` value directly in the code. `"nvs" as bytes` gives the UTF-8 bytes of a
string. `Core\Encoding::fromHex` and `Core\Encoding::fromBase64` give any bytes you need.

`bytes` has no string form of its own. `echo $b` is the error `E0707`, so write `echo $b as string`.
If the bytes are not valid UTF-8, `$b as string` throws a `RuntimeError`. `$b as ?string` gives
`null` instead.

`==` tests whether two strings are equal. `"a" < "b"` is the error `E0715`, so use
`Core\Str::compare` to put strings in order. Text has no arithmetic: `"3" * 2` is the error
`E0716`. Join two strings with `.`, or convert a string to a number with `as int` or `as float`.

## Example 01: check a name against two different limits

```nvs
<?nvs
// A display name is limited by what a reader sees; a database column is
// limited by what it stores. Those are two different numbers for the same
// name, so each one is measured with the type that owns it.

array<string> $names = ['Ann', 'Grüße', "Rene\u{301}e", 'Łukasz Szymański'];

foreach ($names as string $name) {
    uint $characters = Core\Str::length($name);
    uint $stored = Core\Bytes::length($name as bytes);
    echo $name, ': ', $characters, ' characters, ', $stored, " bytes\n";
}
```

```output
Ann: 3 characters, 3 bytes
Grüße: 5 characters, 7 bytes
Renée: 5 characters, 7 bytes
Łukasz Szymański: 16 characters, 18 bytes
```

## Example 03: sort uploads into pictures notes and neither

```nvs
<?nvs
// Files are often sent base64 encoded inside a JSON field.
// `Core\Encoding::fromBase64` returns `bytes`, because the data may not be text.
// The first bytes show if the file is a PNG picture.
// The data becomes a `string` only if it is valid text.

bytes $pngSignature = Core\Encoding::fromHex('89504e47');

array<string> $uploads = [
    'iVBORw0KGgo=',          // the first bytes of a PNG
    'SGVsbG8sIHdvcmxkIQ==',  // a short note
    'SGVsbG8s/w==',          // a note with one byte that is not text
];

foreach ($uploads as string $encoded) {
    bytes $data = Core\Encoding::fromBase64($encoded);
    // `as ?string` converts the bytes to a string if they are valid text.
    // If they are not, the result is `null`.
    ?string $text = $data as ?string;
    if (Core\Bytes::startsWith($data, $pngSignature)) {
        echo 'picture, ', Core\Bytes::length($data), " bytes\n";
    } elseif ($text != null) {
        echo 'note: ', $text, "\n";
    } else {
        echo "neither a picture nor text\n";
    }
}
```

```output
picture, 8 bytes
note: Hello, world!
neither a picture nor text
```

# `array<T>`

A list, or a lookup table, whose values all have the same type.

`var $ids = [1, 2];` creates an `array<int>`. The keys are not part of the type. Every value you add
later must have that type. Write the type yourself, as in `array<float> $weights = [2, 1];`, when the
array starts empty, when its values mix types, or when you will add values of a wider type later.

Keys are always strings: `$row[3]` and `$row["3"]` are the same entry. Entries keep the order you
added them in. An array of arrays is how you build a table or a grouped report.

An array is a value. When you pass it to a function, the function gets its own copy.

**Good to know:** reading a key that does not exist throws an error. Check first when a key may be
missing.

**The examples below** show a list made with `var` and one with a written type, then a lookup table,
then a grouped report that starts from an empty array. The last one shows how keys are numbered,
and that an assigned array is a copy.

An `array<T>` is an ordered table with `string` keys and values of the type `T`. Arrays can contain
arrays to any depth, such as `array<array<int>>`. `array<mixed>` can contain values of any type.

An `int` key is the same key as its digits written as a string, so `$a[1]` and `$a["1"]` read one
entry. The key variable of a `foreach` loop is always a `string`.

`$a[] = 60;` adds a value at the end. Its key is one more than the largest whole-number key, so after
`$a[5] = 50;` the next key is `6`.

Every value must have the type `T`. `array<int> $a = [1, "two"];` is the error `E0401`, and so is
`$a[] = "x";`. Reading a key that does not exist throws a `RuntimeError`: `undefined array key`.

Assigning an array to another variable copies it, the same as passing it to a function. A change through one variable is never seen
through the other.

An array has no string form: `echo $a` is the error `E0707`. `Core\Json::encode($a)` gives its text.
`$a + $b` with two arrays is the error `E0467`. `Core\Arr::underlay($a, $b)` combines them and keeps
the value of `$a` where both have a key.

## Example 01: add up a list of prices

```nvs
<?nvs
// A basket of prices, shown one line at a time and then added up.

// Every value in this list is an `int`, so `var` gives `$prices` the type `array<int>`.
// Every value you add later must be an `int` too.
var $prices = [1299, 450];
$prices[] = 780;

var $total = 0;
foreach ($prices as var $price) {
    echo $price, "\n";
    $total = $total + $price;
}

echo 'total ', $total, ' over ', Core\Arr::count($prices), " items\n";

// A weight can have a fraction, so this list has the written type `array<float>`.
// With `var`, the list would be `array<int>`, and adding `0.5` would not compile.
array<float> $weights = [2, 1];
$weights[] = 0.5;

// This prints `weight 3.5 kg`.
echo 'weight ', Core\Arr::sum($weights), " kg\n";
```

```output
1299
450
780
total 2529 over 3 items
weight 3.5 kg
```


## Example 03: total a days orders per department

```nvs
<?nvs
// Totals a day's orders per department and prints the totals as JSON.
// `withServiceFee` gets a copy of `$totals` and changes only that copy.
// So the first line of output shows the original totals.

class Report
{
    public static function withServiceFee(array<int> $totals): array<int>
    {
        foreach ($totals as var $department => var $cents) {
            $totals[$department] = $cents + 250;
        }
        return $totals;
    }
}

// An array of arrays suits a grouped report.
// `var` gives `$lines` the type `array<array<int>>`.

    'produce' => [1299, 450],
    'bakery' => [780],
];

// An empty array needs a written type. `var $totals = [];` does not compile,
// because the array has no value to take the type from.
array<int> $totals = [];
foreach ($lines as var $department => var $amounts) {
    $totals[$department] = Core\Arr::sum($amounts) as int;
}

var $billed = Report::withServiceFee($totals);

echo Core\Json::encode($totals), "\n";
echo Core\Json::encode($billed), "\n";
```

```output

{"produce":1999,"bakery":1030}
```

```nvs
<?nvs
// Shows how keys are numbered, and that assigning an array copies it.

array<int> $a = [10, 20];

```


# `callable`, classes, `object`, shapes

The types for things that are not plain values: a function you can pass around, a class, any
object, and an object described by the fields it has.

A `callable` is an anonymous function written with `fn`, or a method reference such as
`Core\Str::length(...)`. A class, interface or enum name is a type, and `object` is the type every
instance fits. A shape describes an object by its fields. `as Point` checks that a value has those
fields and throws an error if not. `is Point` gives `true` or `false`.

To pick a class while the program runs, convert its name with `as class<T>`. A name from a setting
is checked when it runs, and `as ?class<T>` gives `null` for a wrong name.

**Good to know:** a call through a `callable` returns a `mixed` value, so convert the result where
you use it: `$f(4) as int`.

**The examples below** pass a pricing rule around, check a value against a shape, and pick a
report class from a name in quotes and from a setting. The last two get the class of an `object`
back, and show a shape without a name as a compile error.

A string is never a `callable`. `callable $f = "strlen";` is the error `E0418`. Write a method
reference such as `Core\Str::length(...)` instead.

Any class instance can be assigned to an `object` variable. You can read a property through it by
name, and the result is `mixed`. A property the object does not have throws a `RuntimeError`.
`$o is Cell` tests the class, and `$o as Cell` converts to it. If the object is another class, `as`
throws a `RuntimeError`. `as ?Cell` is the error `E0473`, so use `is` to test first.

A `class<T>` variable contains a class, not an instance. `T` is a class or an interface, and every
class in the variable is `T` or extends or implements it. A `class<Dog>` can be assigned to a
`class<Animal>`. Two class references are equal when they are the same class.

`as class<T>` is the only way to get a class reference. A class name in quotes is checked when the
program compiles, and a name outside the hierarchy of `T` is the error `E0708`. A name in a variable
is checked when the program runs. A wrong name throws a `RuntimeError`, and `as ?class<T>` gives
`null` for it. `$cls as string` gives the class name.

Only three places take a class reference: `new $cls()`, `$cls::f()` and `$x is $cls`. A `string` in
any of the three is the error `E0496`. `Dog::class` is a `string`, the class name. Comparing a
`string` with a `class<T>` is the error `E0466`.

A shape cannot be written in front of a variable, because a `{` at the start of a statement opens a
block. `{ x: int } $p = …;` is the error `E0134`. Name the shape with `type` first.

A value assigned to a shape needs every field the shape names, with the type it gives. A missing
field or a field of another type is the error `E0401`. You can assign a new value to an existing
field of an anonymous object. Adding a field it does not have throws a `RuntimeError`.

`as Point` checks the type of each field too. `{ x: 5, y: "six" } as Point` throws a `RuntimeError`,
and `as ?Point` gives `null` for it.

# `mixed`

`mixed` is the one type Novis does not check. A `mixed` variable can contain a value of any type.

Input from outside the program has the type `mixed`: a query string, a form post, decoded JSON.
Convert each value to the type you need with `as`. If that is not possible, `as` throws an error.
`is` tests what the value is and does not convert it.

A `mixed` value is never converted to a narrower type for you. Passing one to a `string` parameter
does not compile until you write `as string`.

**Good to know:** an operation on a `mixed` value is slower than on a declared type. Convert the
value once, close to where it arrives.

**The examples below** read a page number from a query string, describe each field of a decoded
payload, and convert an order line. The last two use a `mixed` value directly and show the compile
error.

You can use a `mixed` value in arithmetic, as a condition, with `[]`, with `->`, with `.` and with
`is` or `as`. Each operation checks the value while the program runs. If the value has the wrong
type, it throws an error.

Arithmetic needs a number. `"abc" + 1` throws a `RuntimeError`, and so does `"5" + 1`. Convert text
first: `($m as int) + 1`. An `int` and a `float` add as they do without `mixed`: `5 + 1.5` is `6.5`.

`==` never converts a value. A `mixed` `"5"` is not equal to `5`.

`.` joins a number or a string. An array with `.` throws a `RuntimeError`. `[]` on a value that is
not an array throws a `RuntimeError`, and so does `->` for a field the object does not have.
Calling a method on a value that is not an object throws a `LogicError`.

A `mixed` value is never assigned to a narrower type without `as`. `int $i = $m;` is the error
`E0401`, and so is a `mixed` argument for a `string` parameter.

## Example 01: read a page number out of a query string

# Nullable, union, single-value and enum-case types

A nullable type `?T` is the type `T` or `null`. A variable can be `null` only when its type allows
it. A union `A|B` is either of the two types. Test which one a value is with `is` before you use it
as one of them.

A single-value type is one value written as a type, such as `"asc"` or `3`. A union of them is a
list of allowed values. A setting that may only be one of three words has a type that names those
three words. Any other word is not accepted. An enum case is a type in the same way, so a function
can accept two cases of an enum and not the third.

**The examples below** show a setting that may be missing, a sort order limited to three words, and
a handler that converts an untrusted request into the values it accepts. The last three show each
kind of type at once, and two compile errors.

`null` is a type of its own, and `null $n = null;` compiles. `int $i = null;` is the error `E0401`.
A `?int` value is not used in arithmetic before it is tested. `$maybe + 1` is the error `E0716`.
Test it with `!= null` first, or give a default with `??`.

A union may mix any types, such as `object|int`. Inside `if ($id is int)`, `$id` is an `int`.

A value written in the code is checked against a single-value type when the program compiles.
`$mode = "delete";` for a `"read"|"write"` variable is the error `E0401`. A value converted with
`as` is checked when the program runs. If it is not in the list, `as` throws a `RuntimeError`.
A single-value type can be assigned to its wider type: a `1|2|3` value to an `int`.

An enum is a list of named whole numbers. `enum Mode { Read, Write }` numbers its cases from `0`.
`enum Mode: int { Read = 1 }` gives each case its number. `$m as int` gives the number of a case.
`1 as Mode` gives the case with that number. If no case has it, `as` throws a `RuntimeError`, and
`as ?Mode` gives `null`. `Mode::Read as string` is the error `E0708`.

`iterable` and an intersection `A&B` can be written for a parameter or a return type. No value can
be assigned to either of them. `iterable $i = $xs;` is the error `E0401`.

# A member every class of a union declares

A variable of a union of classes, such as `Box|Circle`, is an object of one of those classes. You
can read a property or call a method of it when every class has that member with the same type. A
method needs the same parameters and return type. The member must also be visible where you use it.

Use `?->` on a union that may be `null`, such as `?Box|Circle`. A write compiles when no class makes
the property `readonly` and every class has the same `set` visibility. `isinit` does not compile on
a property of a union.

If one class does not have the member, the program does not compile. The same is true when the
types differ, or when the member is not visible in one class. The error is `E0881`, and its message
names the class. An interface is not allowed in such a union.

**The examples below** read a property of two shipping classes and call a method of two payment
classes. The last one is a compile error.

## Example 01: a property both classes declare

```nvs
<?nvs
// Shows how to read a property that every class of a union declares.

final class Courier
{
    public string $label = 'Courier, next day';
    public function constructor(public int $weight)
    { }
}

final class Pickup
{
    public string $label = 'Pickup at the shop';
    public function constructor(public int $weight)
    { }
}

final class Order
{
    // Small parcels go by courier. Heavy parcels are picked up at the shop.
    public static function shipping(int $weight): Courier|Pickup
    {
        if ($weight > 20) {
            return new Pickup($weight);
        }
        return new Courier($weight);
    }
}

// Both classes declare `string $label` and `int $weight`.
// So `$ship->label` compiles without a test of the class.
array<int> $weights = [3, 25];
foreach ($weights as int $weight) {
    Courier|Pickup $ship = Order::shipping($weight);
    echo $ship->weight, ' kg: ', $ship->label, "\n";
}

// `?->` reads a property of a union that may be `null`.
// Here the variable is `null`, so `??` prints `not chosen`.
?Courier|Pickup $later = null;
echo $later?->label ?? 'not chosen', "\n";

// A write works too, because `$label` has the same type in both classes.
Courier|Pickup $gift = new Courier(1);
$gift->label = 'Courier, gift wrapped';
echo $gift->label, "\n";
```

```output
3 kg: Courier, next day
25 kg: Pickup at the shop
not chosen
Courier, gift wrapped
```

# `void`, `never`, `self`, `static`

Four return types say something an ordinary type cannot.

`void` means the method returns no value. You call it as a statement of its own. You cannot print
the result, store it in a variable or pass it to another method.

`never` means the method does not return to its caller. It always throws an error or ends the
program.

`self` and `static` both name a class. `self` is the class the method is written in. `static` is the
class the call names. So a method in a base class can return an instance of the child class it was
called on, and the caller gets that child class.

The examples show a method called only for what it does, a chain of calls on one object, and a base
class that creates an instance of whichever child class the call names. Example 04 shows that a
`void` result cannot be printed. Example 05 shows that a call to a `never` method ends the caller's
path.

`void` and `never` are allowed only as a return type. A parameter or a variable of type `void` or
`never` is the error `E0742`. `var $x = Helper::nothing();` is `E0742` too, because the
call returns `void`.

A `void` result is not a value. `echo Helper::nothing();` is the error `E0707`. Passing it to an
`int` parameter is `E0401`. A `void` method that returns a value is `E0403`.

A `never` method must not reach the end of its body. That is the error `E0739`. A `return;` in it is
`E0822`. Every path must throw, call `exit` or call another `never` method.

A call to a `never` method ends the caller's path. The caller needs no `return` after it. This is
true for a static method and for a method no child class overrides. A call to an overridden method
does not end the path, so the caller still needs a `return` there. Otherwise it is `E0739`.

`self` and `static` are only allowed inside a class. Outside one, `self` is `E0303`. `self` also
works as a parameter type and inside another type, such as `array<self>` or `?static`. `static` is
not allowed as a parameter type.

A method that returns `static` must return `$this` or `new static(...)`. `return new self();` is
`E0741`, because a child class may be the class the call names.

`self` and `static` are not values. `return self;` is the error `E0321`. To use a member of the
class, write `self::` and the member's name.

# `type` aliases

A `type` alias gives a type a short name. After `type UserId = uint;`, `UserId` and `uint` are the
same type. A value of one is a value of the other, so you never convert between them.

You write an alias at the top level of a file, or inside a class, interface or enum. An alias
inside a class belongs to that class. Outside the class, you write the class name first:
`Basket::Lines`.

An alias cannot be a second name for one class, because a class already has a name. Use an alias
for a type that is long to write: a union, a nested array, or the fields of an object a method
returns.

An alias exists only while the program compiles. It has no cost while the program runs.

Example 04 names a nullable class and a union. Example 05 shows that an alias of one class does not
compile.

An alias name is written in PascalCase. `type user_id = uint;` is the error `E0110`.

An alias at the top level of a file can be used anywhere in that file, also above its declaration.
An alias inside a method body or a block, such as an `if`, is the error `E0233`.

An alias inside a class, interface or enum has no visibility. `public type Lines = …;` is the error
`E0133`. Inside its class you write the short name. Everywhere else you write `Owner::Name`.

A child class does not inherit an alias. `Lines` in a child class of `Basket` is the error `E0303`.
Write `Basket::Lines` there.

An alias of a single class, interface or enum is the error `E0307`. `?Foo`, a union, an object
shape and `array<Foo>` are allowed.

An alias may use another alias, such as `type Ids = array<Id>;`. An alias that contains itself is
the error `E0310`, such as `type Tree = array<Tree>;`. Use a class for a type that contains itself.

Two declarations with the same name are the error `E0304`. This is also true for an alias and a
class with the same name.

# Values written in the code

You can write a value directly in your program: a number, a string, `true`, `false` or `null`.

A number can have underscores between its digits, and it can be written in base 16, base 2 or
base 8. A leading zero has no special meaning, so `017` is seventeen. A number followed by a unit,
such as `30s` or `1h30m`, is a duration (a length of time).

A string in single quotes keeps every character as you typed it. A string in double quotes inserts
the values of your variables and reads escapes such as `\n`. A heredoc is a string that covers
several lines.

An html template, written ``html`...` ``, is a piece of a web page. Its type is `Core\Html\Markup`.
Every value you insert into it is escaped, so a value cannot add a tag.

**The examples below** show the ways to write a number, the two kinds of quotes, a message built
from a template, a page fragment with inserted values, the escapes of a double-quoted string,
durations, and a program that joins markup with `.` and does not compile.

A float can also be written `1E-2` or `1_000.5`. The keywords `true`, `false` and `null` are values
too.

A single-quoted string has two escapes: `\\` is one backslash and `\'` is a quote. Every other
backslash is printed as it is, so `'a\nb'` prints `a\nb`.

A double-quoted string has the escapes `\\`, `\"`, `\$`, `\n`, `\t`, `\r`, `\v` and `\f`. It also
has an octal escape from `\0` to `\777`, `\xHH` and `\u{HHHH}`. An octal or `\x` escape writes one
byte. The bytes of the string must form valid UTF-8, so `"\xff"` is the error `E0431`. An escape the
language does not know keeps its backslash, so `"\q"` prints `\q`.

A string cannot contain the `ESC` character. This is the error `E0011`. It is the same for the raw
byte and for `\e`, `\x1b`, `\033` and `\u{1b}`. To style text in a terminal, use `Core\Cli\Text`.

In a double-quoted string, `$name[key]` and `$name[0]` read one array element. A second `[...]`
after it is text, so `"$s[0][1]"` prints the element and then `[1]`. For more, use braces. The
expression in braces must start with a variable, and then it can be any expression, such as
`{$a + $b}`. A `{` with no `$` after it is text. `"${name}"` prints `${name}`.

A value in a string is converted the way `echo` converts it. A number, a `bool`, a `string` and
`null` work. `bytes`, an array and an enum case are the error `E0707`. An object of a class that
does not implement `Stringable` is the error `E0412`.

In a heredoc, every line must start with the same spaces as the closing marker. Those spaces are
removed. A line with less indentation is the error `E0433`.

A duration has the units `ns`, `us`, `ms`, `s`, `m`, `h`, `d` and `w`. A duration is an object, so
`==` checks whether two variables are the same object. `1h == 1h` is `false`. To compare two
durations, use `compareTo`, which returns `0` when they are equal.

An anonymous object at the start of a statement must be in parentheses: `({ x: 1 });`. Without them
it is the error `E0117`. The same is true for the body of an arrow function.

An html template keeps every byte between the backticks, also the spaces and line breaks. Write a
backtick in it as `` \` ``. Write `\{` for a `{` that opens no hole. A variable after it is still
filled in, so `\{$n}` prints `{`, the value and `}`.

A brace that is not followed by `$` is text. `{Page::TITLE}` prints as it is written, and the
compiler gives the warning `W1012`. Write `<?= Page::TITLE ?>` for a constant or a method call.

`<?= ... ?>` in an html template takes any expression. Spaces around it are allowed. A `}` inside it
is an ordinary brace. The first `?>` that is not inside a string or a template closes it. A `<?nvs`
block inside a template is the error `E0010`. A template is one expression. To repeat markup in a
loop, build the fragments in code and join them.

A `string` in a hole is escaped, also when it is tainted. A `Core\Html\Markup` in a hole is written
as it is. A secret value in a hole is the error `E0790`. A value with no string form is the error
`E0707`.

`+` joins two `Core\Html\Markup` values. `Core\Html::join($parts, $separator)` joins a list of
them. `.` with a `Core\Html\Markup` is the error `E0710`. The text it would make is escaped a second
time when it is printed.

`html"..."` with double quotes does not compile. The error `E0319` says to write it with backticks.

`"<p>x</p>" as Core\Html\Markup` converts a string that is written directly in the code. Any other
string is the error `E0417`. To turn a computed string into markup, use `Core\Html::escape` or
`Core\Html::sanitize`.

# Widening without `as`

Some values are converted to a wider type without `as`. This happens when you assign a value, pass
an argument, return a value or put an element in an array.

An `int` or a `uint` is converted to a `float`. A value is converted to a nullable type, to a union
that contains its type, and to `mixed`. An object is converted to a parent class, to an interface its
class implements, and to `object`. A single-value type such as `"read"` is converted to `string`.

Only the conversion to `float` changes the value. It is checked while the program runs. A number
above 2^53 cannot be stored exactly in a `float`, so the program throws an `ArithmeticError`.

No other conversion happens without `as`. A `string` to a number, a number to a `string`, and an
`int` to a `uint` each need `as`.

**The examples below** show a whole number used as a `float`, the wider types, a price list with
both kinds of number, an anonymous object at a shape, and a program that assigns an `int` to a `uint`
and does not compile.

A number written in the code without a type takes the type of the place it goes to. It can be an
`int`, a `uint`, a `float` or a `decimal`. `decimal $d = 3;` and `array<float> $xs = [1, 2];` both
compile.

An `int` or a `uint` above 9007199254740992 (2^53) throws an `ArithmeticError` when it is converted
to a `float`. This is also true for a number that a `float` could store exactly, such as
9007199254740994.

A single-value type is converted to its base type. A `"read"|"write"` value is converted to `string`,
and a `true` value to `bool`.

These assignments each need `as` or a test that narrows the type. Without it, each is the error
`E0401`:

- an `int` to a `uint`, and a `uint` to an `int`
- a number to a `string`, and a `string` to a number
- a `float` to an `int`
- a `mixed` value to any other type
- a `?int` to an `int`. The help suggests `$value ?? 0`.

An anonymous object written at a shape type has its fields converted too. `{ x: 2 }` at `{ x: float }`
stores `2.0`. A shape value that already exists is not converted. A `{ x: int }` value at
`{ x: float }` is the error `E0401`. Build a new value instead: `{ x: $old->x }`.

# The conversion operator `as`

Changing a value into another type is written one way in Novis: `as`, followed by the type you want.

A conversion gives a value of that type, or it throws an error. It never rounds, never drops a
fraction, and never uses a zero or an empty string instead. With `as ?int`, the result is `null` where the plain form would throw. Add `??` to
use a default value instead.

`as` also checks an object against a shape, such as `as Point`, and turns a class name into a class
reference with `as class<T>`.

**Good to know:** `as` converts only the value directly before it, so `$a + $b as float` converts
`$b` alone.

**The examples below** read numbers out of text from outside the program, add up an order total, and
skip a row that throws an error. Then they show which error each conversion throws and choose a class
by its name. The last two do not compile.

`as` can be written more than once: `$m as int as string` converts to `int` and then to `string`.

A conversion that fails while the program runs throws one of two errors. A number that does not fit
throws an `ArithmeticError`. These conversions throw it:

- a `float` or a `decimal` with a fraction to `int`
- a negative number to `uint`
- an `int` above 2^53 to `float`

Every other failure throws a `RuntimeError`.

Text converts to a number only when the whole text is one number. `" 42"`, `"42 "`, `""`, `"0x1A"`,
`"1_000"` and `"12.0"` all throw when converted to `int`. `"+5" as int` is `5`. `"1e3" as float` is
`1000`, and `".5"` and `"5."` are also valid `float` values. `"inf"` and `"NAN"` throw.

A `float` converts to `decimal` at the value it prints as. `0.1 as decimal` is `0.1`, not a long
binary fraction. A string converts to `decimal` the same way: `"1e3" as decimal` is `1000`.

`true as string` is `"1"`. `false as string` and `null as string` are `""`. A `bool` does not convert
to a number. `$b as int` is the error `E0708`, so write `$b ? 1 : 0`. Any value converts to `bool`
by the truthiness table: `"0"`, `""`, `0.0` and `null` are `false`.

`string as bytes` always works. `bytes as string` throws a `RuntimeError` when the bytes are not
valid UTF-8.

An enum case converts to `int` or `uint` and gives its number. `5 as Rank` throws a `RuntimeError`
when no case of `Rank` has the number `5`. An enum case does not convert to `string`.

A conversion between two types that has no rule is the error `E0708`, and the message names both
types. An `array`, `bytes` and an enum case to `string` are three of them.

A `mixed` value converts by the type of the value it contains. Text from a `mixed` value is
tainted: `$value as string` gives a `tainted string`.

`array<T> as array<U>` checks each element. An element must already be a `U`, or be a number that
widens to one, such as an `int` in an `array<float>`. The elements are not converted from text:
`["1", "2"] as array<int>` throws a `RuntimeError`.

`?int as int` throws a `RuntimeError` when the value is `null`. `$object as Foo` throws a
`RuntimeError` when the object is not a `Foo`.

A value converts to a set of allowed values, such as `"read"|"write"`, only when it equals one of
them. Otherwise it throws a `RuntimeError` that lists the allowed values.

`as ?T` is not allowed where `as T` cannot fail. `$i as ?int` on an `int` is the error `E0709`. A
class is not allowed either: `$o as ?Foo` is the error `E0473`, so use `$o is Foo`.

`as class<T>` checks a class name written in the code while the program compiles. That is
`Foo::class` or a string literal such as `'Shop\Dog'`. A name that is not a class is the error
`E0303`, and a class that is not a `T` is `E0708`. This is the same with `as ?class<T>`. Every
other string, including a class constant, is checked while the program runs. `as class<T>` then
throws a `RuntimeError`, and `as ?class<T>` gives `null`.

A class name in a string is always the full name with its namespace. No `namespace` and no `use`
applies to it. Inside `namespace Shop`, `"Dog" as ?class<Animal>` is `null`, and
`"Shop\Dog"` finds the class.

A `class<Dog>` converts to `class<Animal>` without a check when `Dog` extends `Animal`. Back from
`class<Animal>` to `class<Dog>`, the class it contains is checked, and the conversion throws a
`RuntimeError` when that class is not a `Dog`.

## Example 03: an order total read from a form

```nvs
<?nvs
// An order is sent as rows of text: a quantity and a price.
// `as uint` converts the quantity to a whole number that is not negative.
// `as decimal` converts the price to an exact amount of money.
// If a conversion fails, it throws an error. The program prints the row and skips it.

class Order
{
    public static function lineTotal(array<string> $row): decimal
    {
        uint $quantity = $row[0] as uint;
        decimal $price = $row[1] as decimal;

        // `as decimal` converts only `$quantity`, the value directly before it.

    try {
        $total = $total + Order::lineTotal($row);

    }
}
```


# Property keys

A property key is a value that names one public property of a class.

You use a key when the name of a property is known only while the program runs, such as a sort
column in a web address. The type `property<User>` contains the names of the public properties of
`User`, and inherited ones. `as` converts a string to a key, and throws an error if the string
does not name a public property. `as ?property<User>` gives `null` instead. `$user->$key` reads or
writes the named property.

**Good to know:** a `private` or `protected` property never converts to a key. A write through a key
does not compile when the class has a public `readonly` property.

**The examples below** sort a table by a column from the web address and update the properties a list of
changes names. Then they show a write of the wrong
type and a key of a parent class used on a child class.

In `property<T>`, `T` must be a class with at least one public property. An interface, an enum or a
type such as `int` is the error `E0799`.

A name written directly in the code is checked while compiling. `"emial" as property<User>` is the
error `E0405`. A string literal at a parameter typed `property<User>` or `?property<User>` is
converted to a key while compiling. It needs no `as`, and a wrong name is also `E0405`. In a
variable, a return value or an array, a string literal stays a `string`.

`as` gives the same `RuntimeError` for an unknown name and for a `private` or `protected` property.
The message lists the public properties of the class.

`$obj->$key` and `$obj->{$expr}` read or write the property that the key names. With a variable of
type `string` there, the program does not compile (`E0235`).

A read through a key has the type of every property the key can name, as a union. For a class with
a `string` property and an `int` property, the type is `string|int`.

A write through a key is checked twice. While compiling, the value must have the type of at least
one property. `true` written through a key of a class with only `string` properties is `E0401`.
While the program runs, the value must have the type of the property the key names. If it does not,
the write throws a `RuntimeError`. A `tainted` or `secret` value must fit every property the key can
name. If one property is a plain `string`, writing a `tainted string` is `E0401`.

If the class has a public `readonly` property, a write through a key does not compile (`E0782`). A
`private readonly` property does not stop the write.

A `property<Animal>` key works on a `Dog` when `Dog` extends `Animal`. You can also store it in a
variable of type `property<Dog>`. A `property<Dog>` key on an `Animal` is the error `E0235`.

`$key as string` gives the property name. Two keys are equal when they name the same property. A
key written in the code and a key converted from a variable are equal when the name is the same.

# Property paths

A property path is a value that names a property across related objects, such as `customer.address.city`.

The type `propertyPath<Order>` contains paths that start at the class `Order`. Each name in a path is a
public property of the class that the name before it reaches. That property can be an object, a
nullable object or an array of objects. A string written in a call to a `propertyPath<Order>`
parameter is checked when the program compiles. `as` checks any other string while the program runs,
and throws an error if a name is wrong. `as ?propertyPath<Order>` gives `null` instead.

**Good to know:** a `private` or `protected` property is never part of a path. A path can come back to
the same class, such as `parent.parent.name`.

**The examples below** go from an order to its customer, address and lines, and sort a list by a
property that the web address names. Then they show the errors for a wrong path.

Every name in a path but the last must be a property whose type is a class `C`, a `?C` or an
`array<C>`. The next name is a property of `C`. The last name can be any public property.

A path written directly in the code is checked while compiling, one name at a time. This is true
for `"customer.nme" as propertyPath<Order>` and for a string literal at a parameter typed
`propertyPath<Order>`. A wrong name is the error `E0405`, and the error points at that name. A path
that continues after a property that is not an object, such as `total.x`, is also `E0405`.

`as` checks any other string while the program runs. If the path is wrong, it throws a
`RuntimeError`. The message names the class and the part that is wrong. The empty string and a path
that ends with `.` throw too, because they have an empty part.

A path is not used to read a value. `$order->$path` does not compile (`E0235`). Use a
`property<T>` key to read or write one property.

`$path as string` gives the text. Two paths are equal when their text is equal. A path written in
the code and a path converted from a variable are equal when the text is the same.

# Strings with holes

A string with holes is a string that contains names between `{` and `}`, such as
`"{total} > 100 AND {customer.email} LIKE ?"`.

The type is written `string<K>`. It is one string, not a collection like `array<K>`. `K` says what a
hole may contain: `property<T>`, `propertyPath<T>`, or a set of strings such as `'name'|'count'`. A
string written in a call to a `string<K>` parameter is checked when the program compiles. `as` checks
any other string while the program runs, and throws an error if a hole is wrong.

**Good to know:** `{{` is one `{` and `}}` is one `}`. Only the holes are checked. A tainted string
(text from outside the program) stays tainted after `as string<K>`, so a condition from a request
cannot be the text of a database query. `Core\Str::parts` splits the string into its text and holes.

**The examples below** check the property paths in a query condition, fill a message template, check a
condition built while the program runs, and show a wrong hole that does not compile.

`K` is `property<T>`, `propertyPath<T>` or a set of strings, such as `'asc'|'desc'`. Any other `K`,
such as `string<int>`, does not compile (`E0860`).

A hole is everything between `{` and `}`, spaces included. `{ total }` is not the hole `{total}`.
An empty hole `{}`, a `{` with no `}` and a `}` with no `{` do not compile (`E0861`).

A string written directly in the code is checked while compiling, one hole at a time. This is true
for a string literal at a parameter typed `string<K>`, and for `"{total}" as string<property<Order>>`.
A hole that is not a property of the class is the error `E0405`. A hole that is not in a set of
strings is the error `E0861`. The error points at the wrong hole.

Only a parameter takes a string literal with no `as`. A local variable typed `string<K>` needs `as`
for a literal too, or the program does not compile (`E0401`).

`as` checks any other string while the program runs. If a hole is wrong, it throws a
`RuntimeError`, and the message names the hole and what is wrong with it. `as ?string<K>` gives
`null` instead.

`as string<K>` keeps `tainted`. A `tainted string` converts to a `tainted string<K>`. A parameter
typed `string<K>` does not take it (`E0401`).

`$text as string` gives the text as written, so `{{` stays `{{`. Two values are equal when their
text is equal. A string written in the code and a string converted from a variable are equal when
the text is the same.

```nvs
{
```

```nvs
    public static function fill(string<'name'|'count'> $template, string $name, int $count): string
```

# Narrowing

A test that proves what a value is lets you use it as that thing, in the code the test guards.

The shortest form is one expression: `$user != null ? $user->name : "guest"`. The right side of `&&`
runs only when the left side is true, so `$user != null && $user->active` works too. An `if` block
or a `match (true)` arm does the same for more code. You can test for `null`, test the kind of
object with `is`, or compare with a fixed word.

**Good to know:** a test works only for a variable or a `readonly` property, and only until you
write to the variable. Copy any other property, such as `$job->mode`, to a variable first.

**The examples below** use a value that might be `null`, check the kind of an object, and act on a
job's settings. The last two check two values in one test, and show a method call that does not
compile.

Four tests narrow a variable:

- `$x == null` and `$x != null` on a `?T`. Each narrows on the branch where the value is not `null`.
  `!` swaps the two branches, so `if (!($x == null))` narrows its block.
- `$x is C` on a `?C`, a union, `object` or `mixed`. Only the branch where the test is true narrows.
  After `if ($pet is Cat) { return …; }`, `$pet` is still `Dog|Cat`, and `$pet->speak()` does not
  compile (`E0477`).
- `$x == "read"` or `$x == Mode::Read` on a set of allowed values or a union of enum cases. The right
  side must be a value written in the code or an enum case. A comparison with a variable narrows
  nothing. The branch where the test is false keeps the full type. It is not narrowed to the
  values that are left.
- Each arm of `match (true)` and each `case` of `switch (true)` narrows its own code when its label
  is one of the tests above. `default` narrows nothing.

A ternary's two arms and the right side of `&&` and `||` are narrowed like the branches of an `if`.
What a test proves ends with the expression. After `$d != null ? $d->speak() : "none"`, `$d` is a
`?Dog` again.

The block of `if ($a != null && $b != null)` sees both variables narrowed. After
`if ($a == null || $b == null) { return …; }`, the code below also sees both narrowed. The `else`
of an `&&` and the block of an `||` narrow nothing, because only one of the two tests is known
there.

A write to the variable inside the branch ends the narrowing. An assignment narrows nothing. After
`$box = new Box();` on a `?Box` variable, `$box->count` is still `E0459`. A property is narrowed when it is
`readonly`, and so is every property before it in the path, such as `$app->config->parent`. Any
other property, such as `$d->friend`, is never narrowed, because a call can change it between the
test and the read. Copy it to a local variable first. A `->` on a `?C` that is not narrowed does not
compile (`E0459`). `$d?->speak()` needs no test: when `$d` is `null`, the result is `null`.

## Example 01: a value that might be missing

```nvs
<?nvs
// Shows how to use a value that might be `null` once you have checked it.

class Account
{
    // In `$nickname != null ? A : B`, the value is a `string` inside `A`.
    // So `A` can use it like any other string.
    public static function greeting(?string $nickname): string
    {
        return $nickname != null ? 'hello, ' . Core\Str::upperFirst($nickname) : 'hello, stranger';
    }

    // The right side of `&&` runs only when the left side is true.
    // So on the right side, `$email` is a `string`.
    public static function canReceiveMail(?string $email): bool
    {
        return $email != null && Core\Str::contains($email, '@');
    }

    // The right side of `||` runs only when the left side is false.
    // So on the right side, `$coupon` is a `string`.
    public static function paysFullPrice(?string $coupon): bool
    {
        return $coupon == null || Core\Str::startsWith($coupon, 'EXPIRED-');
    }

    // An `if` block does the same for several lines of code.
    // After the `return`, the rest of the method uses `$nickname` as a `string`.
    public static function badge(?string $nickname): string
    {
        if ($nickname == null) {
            return 'no badge';
        }

        string $initial = Core\Str::upper(Core\Str::slice($nickname, 0, 1));
        return $initial . ' for ' . $nickname;
    }
}

echo Account::greeting('ada'), "\n";
echo Account::greeting(null), "\n";
echo Account::canReceiveMail('ada@example.com') ? 'send mail' : 'no mail', "\n";
echo Account::canReceiveMail(null) ? 'send mail' : 'no mail', "\n";
echo Account::paysFullPrice(null) ? 'full price' : 'discount', "\n";
echo Account::paysFullPrice('SPRING10') ? 'full price' : 'discount', "\n";
echo Account::badge('ada'), "\n";
echo Account::badge(null), "\n";
```

## Example 02: one of several kinds of thing

```nvs
<?nvs
// Shows how to check which kind of object a value is, and then use it as that kind.

class Card
{
    public function constructor(public bool $contactless)
    {}

    public function pay(): string
    {
        return 'paid by card';
    }
}

class Cash
{
    public function count(): string
    {
        return 'counted out';
    }
}

class Till
{
    // On the right side of `&&`, `$payment` is a `Card`.
    // So the right side can read the `contactless` property.
    public static function canTap(Card|Cash $payment): bool
    {
        return $payment is Card && $payment->contactless;
    }

    // Inside the `if` block, `$payment` is a `Card`. After it, the type is still `Card|Cash`.
    // `as Cash` converts it to `Cash`, and throws an error if it is not `Cash`.
    public static function take(Card|Cash $payment): string
    {
        if ($payment is Card) {
            return $payment->pay();
        }

        return ($payment as Cash)->count();
    }

    // Each arm of `match (true)` uses the value as the kind that arm checked.
    public static function describe(mixed $thing): tainted string
    {
        return match (true) {
            $thing is Card => 'a card, ' . $thing->pay(),
            $thing is Cash => 'cash, ' . $thing->count(),
            $thing is string => 'a note that says ' . $thing,
            default => 'something else',
        };
    }
}

echo Till::canTap(new Cash()) ? 'tap to pay' : 'insert the card', "\n";
echo Till::take(new Card(false)), "\n";
echo Till::take(new Cash()), "\n";
echo Till::describe(new Cash()), "\n";
echo Till::describe('keep the change'), "\n";
echo Till::describe(7), "\n";
```

## Example 03: a jobs settings read once and acted on

```nvs

            // assigned to a variable of type "admin".
```

# Truthiness

A condition can test a value of any type. The value is either truthy or falsy.

The conditions are the test of an `if`, a `while` and the middle part of a `for`. The test of a
ternary `? :` and of `?:` is a condition too, and so are the values beside `&&`, `||` and `!`.
These values are falsy: `false`, `0`, `0.0`, `""`, `"0"`, an empty array, an empty `bytes` and
`null`. Every other value is truthy. This includes `"0.0"`, `" "` and every object.

**Good to know:** only a condition tests a value this way. A `bool` variable, a `bool` parameter and
a `bool` return value need `as bool`, which uses the same table. `empty($x)` is `true` when `$x` is
falsy. `isset($x)` is `true` when `$x` is not `null`.

**The examples below** test the fields of a form, show each kind of condition, build the header of
an email from settings that may be empty, and convert values with `as bool`.

Every enum case is truthy, also a case whose value is `0`. A value of type `mixed` is tested by the
type of the value it has while the program runs. `-0.0` is falsy, like `0.0`. An array that
contains one `0` is truthy, because it is not empty.

`x as bool` gives `false` for every falsy value and `true` for every other value.

`empty($x)` gives `true` for a falsy value, so `empty("0")` is `true`. `isset($x)` tests only for
`null`, so `isset("0")` is `true`.

A label of `match (true)` is compared with `true` using `==`. It is not tested for truthiness. A
label of type `int` does not compile, because an `int` is never equal to `true` (`E0466`).

A value that is not a `bool` does not compile in a `bool` variable, a `bool` parameter or a `bool`
return value (`E0401` or `E0403`). Write `as bool` there.

## Example 01: what counts as nothing

```nvs
foreach ($answers as string $answer) {
    echo "\"", $answer, "\" ", $answer ? 'is truthy' : 'is falsy', "\n";
```

# Parameters

A method lists the values it needs as parameters, and the call says which value goes to which.

Each parameter has a type and a name. A parameter with a default can be left out by the caller. The
default can be a value, a class constant, or an enum case. The last parameter can be
variadic: it collects the remaining arguments into a list. At the call, you can write an argument
with its parameter's name in front of it, as in `book(day: "Friday")`. Then you can skip the
defaults you do not need. Arguments without a name come first.

A parameter written `inout` changes the caller's own variable when the method returns. The call
writes `inout` in front of that argument too, so you can see the change at the call.

**Good to know:** parameter names are part of what a method promises, so a caller may rely on them.

**The examples below** show defaults and a variadic parameter, then named arguments with an enum
case as a default, then an `inout` stock count. The last one leaves out `inout` at the call, so it
does not compile.

A default must be a constant of the parameter's type: a value written in the code, a class constant,
an enum case or `null`. A call such as `Core\Math::abs(-1)` is not allowed (`E0451`). Only the last
parameter can be variadic, with `...`. Inside the method, a variadic `int ...$rest` is an
`array<int>`, and it is empty when the call gives no more arguments.

A call with too few or too many arguments does not compile (`E0402`). `...$list` at the call passes
the values of an array as separate arguments.

A named argument must come after every argument without a name. A positional argument after a
`name:` or `...` argument does not compile (`E0488`). A name that no parameter has is `E0486`, and a
parameter given two arguments is `E0487`.

An `inout` argument must be a variable or a property of an object, such as `$box->count`. An array
element and a static property do not compile (`E0439`). A property with hooks, a property named by
a key and `$obj?->count` do not compile either. Neither does the result of a call or a value written
in the code. The argument's type
must be exactly the parameter's type. An `int` variable at an `inout float` parameter does not
compile (`E0440`). A call that leaves out `inout` before the argument does not compile (`E0713`).

`&` before a parameter does not compile (`E0237`). An anonymous function written with `fn` cannot
have an `inout` parameter (`E0493`).

## Example 01: defaults and what is left over

```nvs
<?nvs
// A parameter can have a default value, so a caller can leave it out.
// The last parameter can collect all the remaining arguments into a list.

class Basket
{
    public const int USUAL_PRICE = 5;

    // A default can be a value or a class constant. `$each` uses the constant `USUAL_PRICE`.
    public static function total(int $items, int $each = Basket::USUAL_PRICE, int ...$surcharges): int
    {
        var $sum = $items * $each;

        foreach ($surcharges as var $surcharge) {
            $sum = $sum + $surcharge;
        }

        return $sum;
    }
}

echo 'three at the usual price: ', Basket::total(3), "\n";
echo 'three at four each: ', Basket::total(3, 4), "\n";
echo 'three at four each, plus two surcharges: ', Basket::total(3, 4, 2, 7), "\n";

// `...` passes the values of an array you already have as separate arguments.
var $surcharges = [2, 7];
echo 'the same two, out of a list: ', Basket::total(3, 4, ...$surcharges), "\n";
```

```output

three at four each: 12
three at four each, plus two surcharges: 21
the same two, out of a list: 21
```

# Properties and constants

A property is a variable that belongs to an object. A class constant is a value that belongs to the
class and never changes.

You write a property as `visibility [static] type $name`, with an optional default value:
`public int $size = 8;`. Each object has its own copy of every property that is not `static`.
A property must have a value before a program reads it. So the constructor must set every property
that has no default, on every path. If it does not, the program does not compile.

You write a constant as `visibility const type NAME = value;`, for example
`public const uint WIDTH = 5;`. Reading `Limits::WIDTH` gives a value of the type you wrote, here
a `uint`.

**Good to know:** the compiler works out a default value once, before the program runs. So it must
be a value written directly in the code, `[]`, an enum case or a class constant. Code that computes
a value belongs in the constructor.

The examples show defaults and a constructor, constants and a `static` property, and a small retry
policy. Example 04 shows a default that is computed, which does not compile.

A property needs a type. `public $x = 1;` is a syntax error (`E0101`).

A default must be a constant of the property's type. That is a value written in the code, also with
a minus sign such as `-3`. It can also be `[]`, an enum case, or a class constant such as
`Limits::ATTEMPTS` or `self::ATTEMPTS`. A union type takes any value one of its members takes:
`?string $label = null`, `?string $label = "plain"` and `"read"|"write" $mode = "read"` all compile.
Any other default does not compile (`E0472`). That includes a call, `null` for a `string` property,
and `"delete"` for a `"read"|"write"` property.

A property with no default must be set on every path out of the constructor. A constructor that sets
it only inside an `if` does not compile (`E0409`). A `static` property has no constructor to set it.
It needs a default or a nullable type, and a nullable one starts as `null`. Without either, it is
`E0409` too.

A constant needs a type. `public const W = 5;` does not compile (`E0246`). Reading a constant gives
its declared type exactly. With `public const uint WIDTH = 5;`, `int $i = Limits::WIDTH;` does not
compile (`E0401`).

The compiler copies a constant's value into every place that reads it. So the value must be a
number, a string, a `bool`, or an array of them. A constant whose value is another class's
constant, an enum case, `self::B + 1` or `"a" . "b"` compiles, but every read of it does not
compile (`E0792`).

# Qualifiers: `tainted` and `secret`

`tainted` and `secret` are two words you can write before `string` or `bytes`. `tainted string` is
text from outside your program, such as a form field or a command-line argument. `secret string` is
a confidential value, such as a password or an API key.

A value is tainted or secret only where a declaration says so. A string built from it with `.` or
interpolation is tainted or secret too. The compiler checks both words before the program runs, so
they do not make the program slower.

A tainted string cannot be a regular expression, a format template or a date pattern. It cannot be
assigned to a plain `string` either. A secret value does not compile with `echo`, in an error
message, in a debug dump or in `Core\Json::encode`.

**Good to know:** a conversion such as `as int` gives a plain value, because the result is a number.
`Core\Secret::reveal` is the only method that gives a plain string from a secret one. You give it the
reason as its second argument.

Examples 04 to 07 show each kind of mistake, and none of them compiles.

You can write `tainted`, `secret` or both, in the order `secret tainted string`. They go only before
`string` and `bytes`. `tainted int` and `tainted secret string` are syntax errors (`E0102`). You can
use them on a parameter, a local variable, a property and a return type.

A tainted string stays tainted through `.` and interpolation. It also stays tainted through every
`Core` method that returns text built from it, such as `Core\Str::upper`, `trim` and `split`. A method that
returns a count or a `bool`, such as `Core\Str::length` or `contains`, returns a plain value. A
parameter that is an instruction does not take a tainted string. That is a regular expression, a
`Core\Str::format` template, a `Core\Bytes::pack` format and a date pattern. Neither does a `Core`
parameter of type `string` that is not listed as taking one. Each of these is `E0401`, and so is
`string $plain = $input;` for a tainted `$input`.

`as int`, `as uint`, `as float`, `as bool` and `as` an enum give a plain value. `as string` and
`as bytes` keep `tainted` and `secret`, so `string $s = $input as string;` is `E0401`. Two methods
give a plain string that is safe for one use: `Core\Regex::quote` for a pattern and
`Core\Uri::encodeComponent` for a link.

A secret string stays secret through `.` and interpolation, separately from `tainted`. These do not
compile with a secret value. `echo` and `print` are `E0790`, also for `echo "Bearer {$token}"`.
An error message is `E0422`. `Core\Debug::dump` and `Core\Debug::render` are `E0724`, and
`Core\Json::encode` is `E0791`. Every `Core` parameter of type `string` or `bytes` is `E0401`. That
includes the parameters that take a tainted string, so `Core\Str::length($token)` does not compile.

`==` between two secrets, or between a secret and a plain string, compiles and gives a plain `bool`.
A declared `array<secret string>` keeps `secret`, so `Core\Json::encode` of it is `E0791`. An array
written in the code is an `array<mixed>`, and it has no `secret` elements. So
`Core\Json::encode([$token])` compiles and prints the value.

`Core\Secret::reveal($value, $reason)` gives a plain string, and `Core\Secret::revealBytes` gives
plain `bytes`. It removes only `secret`. For a `secret tainted string`, the result is a
`tainted string`.


## Example 03: a search term somebody else typed

```nvs
<?nvs
// Shows a tainted search term in a pattern and in a link, and a secret API key in a header.

class Orders
{
    public static function search(tainted string $term, secret string $apiKey): void
    {
        array<string> $labels = [
            'Order 1042, coffee beans',
            'Order 1043, filter papers',
            'Order 1044, coffee grinder',
        ];

        // `Core\Regex::quote` returns a plain pattern that matches the exact text.
        // So the search for "c.ffee" matches no order, because no label has a dot.
        Core\Regex\Pattern $pattern = Core\Regex::compile(Core\Regex::quote($term));
        uint $hits = 0;
        foreach ($labels as string $label) {
            if (Core\Regex::matches($label, $pattern)) {
                $hits = $hits + 1;
            }
        }

        // `Core\Uri::encodeComponent` returns a plain string that is safe in a link.
        string $link = 'https://example.test/orders?q=' . Core\Uri::encodeComponent($term);

        string $authorization = 'Bearer ' . Core\Secret::reveal($apiKey, 'sending it to the orders service');

        echo $link, "\n";
        echo 'the authorization header is ', Core\Str::length($authorization), " characters long\n";
    }
}
```

# What does not exist

This page lists PHP syntax that Novis does not have, and what to write instead.

There are no casts such as `(int)$x`. Write `$x as int`. The conversion is checked. If the value
does not fit, `as int` throws an error, and `as ?int` gives `null`.

There are no free functions, such as `intval`, `gettype` or `is_int`. To test what a `mixed` value
is, use `is` for a class, `== null` for `null`, and `($x as ?int) != null` for a number.

A string is not an array of characters. `$s[0]` does not compile, so use `Core\Str::at` or
`Core\Str::slice`. A string is never part of arithmetic, and `<` does not compare two strings. Use
`Core\Str::compare` to order them.

To take an array apart, write `[int $a, int $b] = $pair;`, with a type for each variable.

Each of these mistakes is a compile error, so you see them all before the program runs.

`(int)$x`, `(string)$x`, `(float)$x`, `(bool)$x` and `(array)$x` do not compile (`E0225`). The help
text names the `as` conversion to write, such as `$x as int`.

A call to a free function such as `intval`, `is_int` or `gettype` does not compile (`E0320`). Every
function in Novis is a method of a class, and the built-in ones are under `Core`. `settype` does not
compile either (`E0208`). A variable's type never changes, so you convert into a new variable with
`as`.

`$s[0]` on a string does not compile (`E0482`). `Core\Str::slice($s, $i, 1)` gives one character, and
`Core\Bytes::slice` works with a byte offset.

A string with an arithmetic operator does not compile. `"3" * 2` is `E0716`. `"a" < "b"` is `E0715`,
because `<` does not compare strings. `"3" == 3` is `E0466`, because a `string` is never equal to an
`int`.

`list($a, $b) = $pair;` does not compile (`E0230`). Write `[int $a, int $b] = $pair;`.

A string is never a `callable`, so `callable $c = "strlen";` is `E0418`. A `callable` is an
anonymous function such as `fn (int $n) => $n + 1`, or a method reference such as `Foo::bar(...)`. A
handle, such as an open file or a database connection, is a `Core` object.

A conversion never cuts off a fraction. `3.9 as int` throws an `ArithmeticError`, and `3.9 as ?int`
is `null`.

## Example 01: converting without a cast

```nvs
<?nvs
// Shows how to convert a value with `as`, and what happens when the value does not fit.

mixed $answer = '42';

// `as` converts a value to the type after it. Text from a `mixed` value is tainted.
int $count = $answer as int;
tainted string $label = $answer as string;

// `as ?int` converts a value to a whole number. 3.9 is not a whole number,
// so the result is `null`.

?int $whole = $price as ?int;

echo $label, ' ', $share, "\n";
echo $whole == null ? '3.9 is not a whole number' : 'converted', "\n";
```


## Example 02: asking what a value holds

```nvs
<?nvs
// Shows how to test what a `mixed` value is, with `== null`, `is` and `as`.

class Describe
{
    public static function of(mixed $value): string
    {
        // `== null` tests for `null`.
        if ($value == null) {
            return 'nothing';
        }

        // `is` tests whether the value is an object of that class.
        if ($value is Core\Regex\Pattern) {
            return 'a compiled pattern';
        }

        // `as ?int` gives `null` when the value is not a whole number.
        ?int $whole = $value as ?int;
        if ($whole != null) {
            return 'a whole number';
        }
        ?float $fraction = $value as ?float;
        if ($fraction != null) {
            return 'a number with a fraction';
        }

        return 'something else';
    }
}

echo Describe::of(null), "\n";
echo Describe::of(7), "\n";
echo Describe::of(2.5), "\n";
echo Describe::of('hello'), "\n";
echo Describe::of(Core\Regex::compile('a+')), "\n";
```

```output
nothing
a whole number
a number with a fraction
something else
a compiled pattern
```

## Example 03: reading a price list the novis way

```nvs
<?nvs
// Shows a program that reads a price list with `as`, `Core\Str::split` and `Core\Str::compare`.

class PriceList
{
    public static function summarise(array<string> $lines): string
    {
        int $total = 0;
        string $firstName = '';

        foreach ($lines as string $line) {
            // This takes the array apart. Each variable has its own type.
            [string $name, string $amount] = Core\Str::split($line, ',');

            // For text that is not a number, the result is `null`.
            // So the line "plums,not a price" is skipped.
            ?int $price = $amount as ?int;
            if ($price == null) {
                continue;
            }
            $total = $total + $price;

            // `Core\Str::compare` orders two strings. It is less than 0 when `$name` comes first.
            if ($firstName == '' || Core\Str::compare($name, $firstName) < 0) {
                $firstName = $name;
            }
        }

        return 'total ' . ($total as string) . ', first name ' . $firstName;
    }
}

echo PriceList::summarise(['pears,220', 'apples,150', 'plums,not a price']), "\n";
```

```output
total 370, first name apples
```
