```nvs
Core\Request::route(): ?Router\Match;                                   // the match the server made
Core\Router::match(Http\Method $method, tainted string $path): ?Router\Match;
Core\Router::methodsFor(tainted string $path): array<Http\Method>;      // [] ⇒ 404, else 405 + Allow:
Core\Router::url(string $name, array<string, mixed> $params): string;         // launder (URL path)
Core\Router::urlAbsolute(string $name, array<string, mixed> $params): string; // launder (URL)
Core\Router\Match::name(): ?string;
Core\Router\Match::params(): array<tainted string|int|uint|decimal|Core\Uuid|Parses>;
Core\Router\Match::param(string $name): ?(tainted string|int|uint|decimal|Core\Uuid|Parses);
Core\Router\Match::method(): Http\Method;
Core\Router\Match::access(): ?string;                                   // the resolved name of `allow:`
Core\Router\Match::accessAs<E>(): ?E;                                   // `allow:` as a case of enum E
```

The server matches a request once, before any application code, and `Core\Request::route()` is that
match; `match` asks the same table about a verb and a path the program chose. Either answers a name,
typed captures, the declared verb and the access decision, and **nothing invocable** — no `->invoke()`,
no callable, no class-and-method strings. Any route in the table may have matched, so a capture's type
is one union and a read is guarded by `name`: one `switch`, written by the program or generated by its
framework, in which the program states the type a capture already is with `as`. The access decision
rides on the match uninterpreted (`rule:security/access-is-checked-for-presence-not-meaning`), so a
dispatcher checks it once above that `switch` and the check covers every arm. `accessAs<E>()` answers
it as a case of the enum `E` the call site writes, and `null` when it is not one of `E`'s cases;
`access()` answers the resolved name of the constant `allow:` wrote, which is the only reading of a
class constant.

What the router deliberately does not do, because each is a framework opinion: **no dispatch** —
nothing calls the annotated method; **no controller convention** — no base class, naming rule or
directory layout; **no return-value-to-response rule** — what a handler returns is between it and
whoever called it; **no middleware, filters, groups or route-level rate limit**
(`rule:core-classes/ratelimit-two-members` declines the last for the same reason); **no
`HEAD`-implies-`GET`, no automatic `OPTIONS`, no trailing-slash normalisation** — each is somebody's
wrong default, and the server decides them above the table, visibly. A framework can build dispatch
on top, use `url` alone, or ignore all of it, and none of those choices is penalised.

Typed `callable` would not move this line: routes share no signature and handlers no return type, so
routing is not a case that forces `rule:types/grammar`'s deferral. Signing a route's identity is
`rule:core-classes/router-signed-url`.
