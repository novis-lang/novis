An `accept` that fails with `EMFILE`/`ENFILE` returns immediately and will fail again immediately, which turns descriptor exhaustion into a core pinned at full utilisation for as long as the condition lasts — and, because the log is written per iteration, into a disk filled at the speed of the loop.

**The loop applies a bounded backoff on a descriptor-exhaustion error and logs once per window**, not once per attempt: the wait doubles to a ceiling and a successful accept puts it back. No other accept failure is waited out, because no other one is a condition that will clear on its own. Descriptors are already charged to a request under `rule:errors/multipart-part-count`'s per-request accounting, so the condition is bounded from the other side too; this closes the behaviour when it happens anyway.
