`upload_total` is enforced by the server, not by each consumer. A request whose `Content-Length` already exceeds it is answered `413` **before dispatch** — before a mount is selected, before an isolate exists and before any application code runs — so the honest oversized client never reaches a program. A chunked body with no declared length is counted as bytes arrive, and when the total is crossed the iterator throws at the part being read and the connection is closed rather than left half-consumed.

Enforcing in the server rather than at every `readAll` and `content()` is what keeps the streaming path bounded now that it is the only path (`rule:http-server/an-upload-is-received-only-through-files`): the parts an application drains without reading are still the server's to count, and a bound placed in the parser would miss exactly the bytes it never sees. The number is load-bearing twice, because `rule:http-server/admission-is-arithmetic-not-a-number` multiplies it by the in-flight ceiling to get what the machine must hold.
