`rule:errors/stack-depth` bounds recursion through Novis frames, where every user call is a real machine frame and the check is emitted at function entry. The same request data recurses through *engine* frames — a nested document handed to a decoder, a nested expression handed to the parser — where that check does not reach, because a decoder's recursion has no Novis frames in it at all.

**Every engine-side recursive descent over request data carries an explicit depth counter and refuses past its limit**, and the refusal reaches the caller as an ordinary catchable failure — a `413`-class condition for a body, a diagnostic for source. The limit is one per decoder rather than one shared number, because the depth reasonable for a JSON body is not the depth reasonable for a source file; each is an `nvs.toml` directive under `rule:config/the-file-is-nvs-toml-and-it-is-toml`'s format.

The default for `Core\Json` is **512**, the depth JSON decoders commonly default to, chosen as a convention rather than for any property of the number: a document a real program sends is far shallower. A document deeper than that is refused with the catchable failure above, at the level that crosses the limit.
