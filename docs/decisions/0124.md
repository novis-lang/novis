# ADR 0124 — PHP 8.6 lands as four compile-time refusals and one session rule

- **Scope:** what Novis does about each item PHP 8.6 announces — partial function application, defaults on
  `readonly` properties, the `Io\Poll` API, `clamp`, `Time\Duration`, the reflection and session changes,
  and the deprecation list. Explicitly *not*: the `Core\Session` storage design
  ([0012](0012.md) *Revisiting*, due M8, though § 6 here fixes one point of it), the
  `Core\Reflect` class roster ([0019](0019.md), due M8), and
  the migration table's unaudited domains (`docs/spec/02-php-migration.md`
  owns those rows).

> **In short:** most of PHP 8.6 asks nothing of Novis — `clamp` and a `Duration` type already exist, the
> polling API is closed by the concurrency model, and nearly every deprecation names surface Novis never
> shipped. What is left lands now, as compile-time refusals rather than runtime warnings: **a `return`
> never leaves a `finally` block, a constructor's `return` carries no value, `let` and `is` are reserved
> spellings, and a `readonly` property declares no default.** Partial function application is not adopted —
> `fn` already spells it. And a session id the store did not issue is always rejected, with no toggle.

## Context

- PHP 8.6 (expected December 2026; the announced set is summarized at
  <https://stitcher.io/blog/new-in-php-86>) adds partial function application (`f(?, $x)` produces a
  closure), defaults on `readonly` properties, an I/O polling API (`Io\Poll\Context`), `clamp`, a
  `Time\Duration` class, `ReflectionProperty::isReadable`/`isWriteable`, a `SortDirection` enum, and
  stricter session ini defaults. It deprecates, aimed at removal in PHP 9: `return` inside `finally`,
  value-returning `return` in constructors, `let`/`is` as identifiers, `readonly` as a function name, `_`
  as a constant, the alias family (`is_double`, `is_integer`, `is_long`, `doubleval`), `strcoll`,
  `SORT_LOCALE_STRING`, `metaphone`, case-insensitive `define`, most of `ArrayIterator`'s mutation
  surface, `spl_object_hash`, `spl_classes`, `SplFileObject`'s CSV methods, `mysqli::stmt_init` and
  `mysqli::get_charset`, cross-class `ReflectionProperty` writes, and session handlers missing
  `create_sid`/`validateId`.
- Novis compiles. A change PHP must phase in over a major version with a deprecation channel is, here, a
  refusal at the line it is written — the posture [0034](0034.md),
  [0045](0045.md) and [0050](0050.md)
  already take for legacy spellings. Observable-behaviour parity (the priority ordering's #2) is owed to
  programs PHP 9 will still run, not to spellings PHP itself is removing.
- Most of the list is already settled elsewhere, and this ADR changes none of it: `clamp` is
  `Core\Math::clamp` and generic over any naturally ordered type; `Time\Duration` is `Core\Time\Duration`
  with [0070](0070.md)'s literals on top; `Io\Poll` has no landing spot because
  readiness is runtime-internal ([0115](0115.md))
  and user code gets structured concurrency instead; enum `__debugInfo` is closed with every magic method
  ([0028](0028.md)); the cookie defaults PHP is tightening have been
  Novis's defaults from the start ([0074](0074.md) § 3); and the
  aliases, `strcoll`, `metaphone`, SPL, `mysqli` and case-insensitive `define` are already `dropped`,
  rerouted, or impossible by construction. `ReflectionProperty::isReadable`/`isWriteable` and
  `SortDirection` are noted for the M8 roster and for whichever options shape first sorts — decisions that
  belong to those designs, not here.

## Decision

**The five PHP 8.6 items that land on undecided ground are decided as follows, the first four as
compile-time refusals in the front end.** Their diagnostic codes are declared next to their siblings in
`crates/nvs-diagnostics` when the front-end slice lands ([docs/plan/m1.md](../plan/m1.md) item 6 schedules
it); each refusal below states what its diagnostic names.

### 1. A `return` does not leave a `finally` block

`return` inside `finally` does not compile. It would replace whatever the region was leaving with —
including a throw in flight, which would be discarded with no `catch` anywhere in the program — and it is
the only construct in PHP where an unhandled exception vanishes without a handler. PHP 8.6 deprecates the
spelling for removal on exactly that argument. The diagnostic names the two rewrites: change the result in
a `catch`, or after the region. `break` and `continue` whose target lies outside the `finally` are refused
on the same grounds; a loop wholly inside the `finally` block keeps both.

### 2. A constructor's `return` carries no value

`return $value;` inside a `constructor` does not compile; the object under construction is the result and
nothing else can be. A bare `return;` remains legal as an early exit, provided every property is
definitely assigned on that path ([0022](0022.md) is unchanged and keeps
checking it). PHP 8.6 deprecates the value-returning form on the same "never made sense" argument.

### 3. `let` and `is` are reserved spellings

Both join the reserved set in `crates/nvs-syntax/src/token.rs`, in the family whose construct does not
exist — `eval`, `goto`, `list` — so the spelling stays available and nothing a user wrote ever has to be
renamed out from under a future decision. PHP 8.6 deprecates both as identifiers to reserve them for
future use; Novis, with no published corpus, reserves them outright. The diagnostics name the living
spellings: `var` declares an inferred local ([0037](0037.md)), `instanceof` tests
and `as` converts ([0066](0066.md)).

### 4. A `readonly` property declares no default

`readonly` with an initializer is refused where it is written. `readonly`'s contract is one assignment,
during construction, in the declaring class's own `constructor` — a property whose single assignment is
its own declaration-site default is a per-instance constant, and Novis already has a spelling for a value
known at the declaration: `const`. The diagnostic names it, and names dropping `readonly` as the other
fix. PHP 8.6 allows the combination (chiefly for hooks in interfaces); if its final semantics make the
form idiomatic in code `nvs convert` must carry, *Revisiting* reopens this — not before.

### 5. Partial function application is not adopted

`f(?, $x)` and `f(...)`-style application-with-holes do not parse. The value it would produce is exactly
the callable machinery [0027](0027.md) and
[0031](0031.md) reduced to one shape, and the closure literal already
spells every partial application: `fn($a) => f($a, $x)`. `nvs convert` (M11) rewrites a PHP 8.6 `?`
placeholder into that wrapper mechanically — each `?` becomes a fresh parameter, in order. The pipeline
operator is unaffected: [0098](0098.md)'s `$_` is a
parse-time substitution, not an application, and its `E0129` note already teaches the difference.

### 6. A session id the store did not issue is rejected, always

`Core\Session::start()` accepts a presented id only if its own store issued it and it is still live; an
unknown, expired or attacker-minted id is discarded and a fresh id is issued in its place. There is no
toggle, no ini, no option — PHP 8.6 flips `session.use_strict_mode` to `1` by default; Novis has no off
position, on the priority ordering's #1. Consequently the storage backend [0012](0012.md)
defers to M8 must be able to answer "did I issue this id" — the same demand PHP 8.6 makes of session
handlers by deprecating those without `create_sid`/`validateId`.

## Consequences

**Positive**

- Programs Novis accepts stay accepted by the PHP 9 direction of travel; none of the four refusals can
  produce a program PHP 9 runs and Novis refuses for a *different* answer — refusal is at compile time,
  so nothing diverges at run time.
- All four refusals are front-end checks with zero run-time cost, no new run-time state, and no memory
  spent anywhere.
- Session fixation resistance is a property of the language, not a deployment's ini hygiene.

**Negative**

- Converted PHP 8.x code using `return` in `finally` has no mechanical rewrite — a human decides whether
  the override was a bug (usually) or intent; `nvs convert` can only point at the line. The other three
  refusals rewrite mechanically: drop the value, rename the identifier, move the default to the
  constructor or a `const`.
- `let` and `is` are two more names PHP code may use freely that a converted program must rename.

The reference states § 1 in [70-errors.md](../reference/lang/70-errors.md) and §§ 2/4 in
[50-classes.md](../reference/lang/50-classes.md); the divergence rows are in
[divergences.md](../divergences.md); the migration table gains its `clamp` row. The checks themselves are
[docs/plan/m1.md](../plan/m1.md) item 6, scheduled after the current loop goal because they block nothing
and no fixture writes the code they refuse.

## Alternatives rejected

- **Mirror PHP 8.6 exactly: allow with a runtime deprecation warning.** Rejected — Novis has no
  deprecation channel and would be building one to permit, temporarily, code it can refuse statically at
  the exact line.
- **Adopt partial function application.** Rejected — it reintroduces a second closure-producing spelling
  where [0031](0031.md) just finished reducing to one, for no capability
  `fn` lacks.
- **Allow a `readonly` default as the one assignment.** Rejected — it makes a property spell what `const`
  spells, two names for one thing, the pattern [0015](0015.md) refuses.
- **Reserve only `is`, leave `let` free.** Rejected — the cost of reserving both now is identical and
  near zero; the cost of taking either back later is a breaking rename.
- **A strict-mode option on sessions.** Rejected — an off switch for fixation resistance is a security
  default traded for nothing, the direction the priority ordering forbids.

## Revisiting

- **§ 4** reopens if PHP 8.6's final readonly-default semantics (with hooks in interfaces) become
  idiomatic in the corpora `nvs convert` targets — the trigger is conversion pressure, not the RFC
  landing.
- **§ 5** reopens only on the same trigger: widespread `?` placeholders in real conversion targets, at
  which point the mechanical wrapper either suffices (stay) or measurably bloats output (reconsider).
- The rest is settled independent of what PHP 8.6 ships as; a changed final feature set changes the
  Context list, not the decision.

## Verification

- **Front end (plan item M1 § 6):** an `--EXPECTF-ERROR--` conformance case per refusal — `return` in
  `finally`, `return $v;` in a constructor, `readonly int $n = 1;`, and `let`/`is` written as an
  identifier each naming its diagnostic — plus a passing case for bare `return;` in a constructor and for
  a loop wholly inside a `finally`.
- **M8:** the session storage design's acceptance test includes presenting a fabricated id and asserting
  a fresh one comes back; the `Core\Reflect` roster decision records what became of
  `isReadable`/`isWriteable`.
- **M11:** `nvs convert` emits the `fn` wrapper for a `?` placeholder and points, without rewriting, at a
  `return` inside `finally`.
