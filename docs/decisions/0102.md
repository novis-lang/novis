# ADR 0102 — A request is matched once, and the route table completes without crossing into dispatch

- **Scope:** where the match happens and who may read it; telling a missing path from a refused verb;
  binding a query parameter; an absent trailing segment; the closed set a capture may narrow to; building
  an absolute link; reading the mount a request arrived through; which layer enforces `#[Access]`; and the
  correction that routing is not a forcing case for typed `callable`. **Not in scope:** dispatch, a
  controller convention, middleware and a return-value-to-response rule, all of which
  [0077](0077.md) § 4 refuses and this ADR upholds; the framework layer that does
  build them ([0082](0082.md) § 3); what an access *name* means
  ([0096](0096.md) § 2); the mount table's own
  grammar ([0097](0097.md) § 3); and typed `callable` itself, which
  § 9 hands back to [0007](0007.md) § 3 with a corrected count.

> **In short:** `rule:routing/routes-are-compiled-not-registered` stopped at matching and was right to. What it left
> was not a boundary problem but a set of holes an application falls into on its first week: the match
> happened in no defined place, a wrong verb answered `404`, a query parameter had no binding at all
> although [0085](0085.md) already promised to document one,
> `/posts` and `/posts/{page}` could not share a name, a `{lang}` could not say it means three values, an
> emailed link could not be absolute, and a host-mounted tenant could not learn which tenant it was. Nine
> decisions close them **without moving the boundary one line**. The load-bearing one: **the server matches
> once, before the handler, and `Core\Request::route()` is that match** — which is what
> [0096](0096.md) § 4's CSRF check and
> [0076](0076.md) § 1's `route` label were already written against and what
> [0097](0097.md) § 7 mistakenly denied them. Measured, that
> **removes** a match rather than adding one: a match is **32.7 ns** and most requests were about to make
> two.

## Context

- **Three of these are bugs in the tree, not new features.** Two accepted ADRs contradict each other about
  whether the server holds the route table; [0085](0085.md) § 1
  documents a query binding no ADR defines; and
  [0096](0096.md) introduces a
  compiler-recognized `#[Access]` without adding it to [0071](0071.md) § 1's closed list, so
  as written the attribute cannot be matched nominally and a userland `type Access = {...};` satisfies the
  requirement — which defeats that ADR's whole purpose. Each is repaired here rather than reconciled in a
  reader's head, per this repository's one-home rule.
- **The rest are the gaps a real application finds first.** They were not overlooked;
  [0077](0077.md) deliberately shipped a minimum and named several of them in its own
  *Revisiting*. What has changed is that [0082](0082.md) committed Novis to
  shipping a framework and [0085](0085.md) committed it to
  generating an API contract — and both of those consume the route table, so a hole in it is now a hole in
  two shipped promises rather than an inconvenience to one application.
- **The boundary is not what was wrong.** Every decision below was checked against
  [0077](0077.md) § 4's refusal list before being taken, and none of them dispatches,
  invokes, wraps a handler, or decides what a handler returns. § 1 comes closest and is the one that had to
  be argued hardest: a server that *matches* is not a server that *dispatches*, and the distinction is
  exactly the one [0086](0086.md) already draws in the other direction when it
  lets `Core\Command` dispatch because a CLI has one entry point and no middleware question.
- **The cost was measured rather than asserted**, because § 1 spends work on every request and
  `rule:programs/memory-priority` puts request-path latency above simplicity. The numbers are in
  § 1 and they decided the section.

## Decision

### 1. The match happens once, before the handler, and it travels on the request

```php
Core\Request::route(): ?Router\Match          // the match the server already made
Core\Router::match(Http\Method, tainted string): ?Router\Match   // unchanged: match some other path
```

The server matches the incoming request against the compiled table **once**, before any application code
runs, and records the result on the request. `Core\Request::route()` returns it. `null` means nothing
matched — the program may still serve the request however it likes, because nothing here dispatches.

**This is what three existing rules were already written against.**
[0096](0096.md) § 4's CSRF check needs to know
which handler a `POST` is for; [0076](0076.md) § 1's `route` label needs the matched
route's declared name; and § 8 below gives the access decision somewhere to ride. Each of the three was
specified against a route table that [0097](0097.md) § 7 said the
server did not have. **That sentence was true of one thing only and is now scoped to it**: a CORS preflight
is answered from `[http.cors]` *before any application code and therefore before the compiled unit is
loaded*, so it genuinely has no table to ask. Everything else in the request's life happens after the unit
is in hand, and the unit carries the table.

**Matching is not dispatching.** The server computes a name and typed parameters and stops there — it never
calls the annotated method, never decides what a return value means, and never wraps anything.
[0077](0077.md) § 4's refusal list is untouched, and § 9 below records why the
remaining temptation to cross it does not become available even when its stated blocker is removed.

**The cost, measured**, on a 60-route table in a release build with LTO — the trie
[0077](0077.md) § 2 specifies, via `matchit`, the crate that ADR names as its model:

| | ns/op |
|---|---:|
| static hit (`/health`) | 13.2 |
| deep static hit (`/api/v1/products`) | 19.6 |
| **one capture converted to `uint` — the typical route** | **32.7** |
| two captures, both converted | 59.0 |
| four captures, deepest route | 48.2 |
| a literal beating a capture (`/users/new`) | 47.4 |
| catch-all (`/files/a/b/c.png`) | 27.1 |
| **miss** | **8.1** |
| failed conversion → no match | 29.5 |
| *anchor:* parse the request line and ten headers | 135.9 |
| *anchor:* one `format!` of a 32-character string | 89.5 |

A match is **a quarter of the header parse the server performs unconditionally**, and this is an upper
bound: `matchit` returns captures through a map, where a compiled table writes into the fixed shape slots
it knows at compile time. **This section removes a match for most requests rather than adding one** — a
request that emits the `route` label or runs the CSRF check was already going to match, and the application
matching again for itself made two. The one case that pays is a program that has a route table, has metrics
off, is on a safe method, and never reads its own route; it pays 32.7 ns, and
[0096](0096.md)'s mandatory `#[Access]` makes
that close to an empty set. **A program with no route table still builds none and matches nothing**, exactly
[0077](0077.md) § 5's opt-in rule.

### 2. A missing path and a refused verb are different answers

```php
Core\Router::methodsFor(tainted string $path): array<Http\Method>
```

Empty means no route claims that path at all — `404`. Non-empty means the path exists under other verbs —
`405`, with the returned list spelling the `Allow:` header RFC 9110 requires alongside it.

It is called **only after `match` has already returned `null`**, so a served request pays nothing for it,
and the walk it performs is the 8.1 ns miss path measured above. `match` itself is unchanged: adding a
third state to its return would put a verb list on the success path where it is never read, and would make
every caller destructure three cases to use one.

This also answers the question [0097](0097.md) § 7 had to pass on. A
plain `OPTIONS` was passed through because "answering it means emitting `Allow:` for that path, and in entry
dispatch the server has no route table to ask" — § 1 gives it the table and this member gives it the list,
so a plain `OPTIONS` is now answerable by an application that wants to answer it. The server still does not
answer one on the application's behalf; that would be a convention, and
[0097](0097.md) § 7's reason for refusing to pick one stands.

**Where `{name?}` (§ 4) makes a node terminal, both forms are reported.** `methodsFor("/posts")` on a table
declaring `/posts/{page?}` returns that route's verbs, so the shorter form cannot `404` while the longer one
`405`s.

### 3. A query parameter is bound and laundered like a capture, and fails differently

```php
#[Route(path: "/orders", method: Http\Method::Get, name: "orders.index")]
#[Access(allow: Role::User)]
public function index(
    #[Query] uint $page = 1,
    #[Query] "asc"|"desc" $sort = "asc",
): Response { … }
```

`#[Query]` binds one method parameter from the request's query string. It takes **the same type list as a
path capture** (§ 5), converts the same way, and launders the same way — a bound `uint $page` arrives
unqualified for exactly [0024](0024.md) § 2's reason, and a bound
`string` stays `tainted`. A parameter **default makes it optional**; a parameter with no default whose key
is absent is a `400`.

**A failed conversion is a `400`, not a `404`** — and this is the one place this ADR deliberately diverges
from § 5's path rule. A path capture that fails to convert means *this route is not the one*, so matching
continues. A query value cannot select a route, so there is nothing to continue to: the route matched and
the input is bad, which is what `400` means. The divergence is the point rather than an inconsistency, and
it is why query binding is safe to add at all — **a query value can never reintroduce the declaration-order
dependence [0077](0077.md) § 2 exists to prevent**, because it takes no part in
choosing between two routes.

`Core\Query` joins [0071](0071.md) § 1's closed list of compiler-recognized attributes,
matched nominally, exactly as `Core\Route` and `Core\Access` are. **That list is now long enough to be the
risk that ADR named**, and § 9 records what is done about it.

This closes [0085](0085.md) § 1's "Query parameters | parameters
bound from the query string, by declared type" row, which had been a forward reference to a mechanism no ADR
defined. It now names this section.

### 4. A trailing segment may be absent, and its parameter is what says so

**`{name?}` captures one segment or none.** It is permitted **only in the last position**, at most once, and
never in the same path as a `{name...}`. **The method parameter it binds must have a default**, which is
what makes the absent case well-typed rather than nullable by accident. A `{name?}` whose parameter has no
default is a compile error naming both.

```php
#[Route(path: "/posts/{page?}", method: Http\Method::Get, name: "posts.index")]
#[Access(allow: Audience::Public)]
public function index(uint $page = 1): Response { … }
```

Precedence slots it below `{name}` and above `{name...}`, so § 2's structural rule extends with no ordering
to remember. **`/posts/` does not match it.** An empty final segment is not an absent one, and repairing the
difference is what [0095](0095.md) refuses generally and
[0097](0097.md) § 7 refuses for the trailing slash specifically.

What this replaces is a real papercut rather than a missing convenience: the two-attribute spelling is
already legal, because `#[Route]` is repeatable — but the two forms carry different paths, so
[0110](0110.md) § 1's shared name is not
available to them, one of the two loses reverse-URL generation, and
[0076](0076.md) § 1 sees one endpoint as two series.
In the trie, `{name?}` is one node marked terminal, so it costs the 13.2 ns static-hit path and not a
second walk.

### 5. A capture narrows to a closed set with a type, never with a regex

[0077](0077.md) § 3's list of types a capture may convert to gains two entries from
[0047](0047.md): a **union of string or int literal types**, and a **subset of
an enum's cases**. Everything else about that section is unchanged.

```php
#[Route(path: "/{lang}/docs/{page}", method: Http\Method::Get, name: "docs.show")]
#[Access(allow: Audience::Public)]
public function show("en"|"de"|"fr" $lang, string $page): Response { … }
```

`/fr/docs/intro` matches; `/xx/docs/intro` does not, and falls through to a `404` by § 3's existing
failed-conversion rule rather than reaching the handler. No grammar changes: the constraint is written where
the type is written, which is [0077](0077.md) § 3's whole thesis — *"the `\d+`
requirement everybody writes is a type"* — applied to a set that is not numeric.
[0085](0085.md) § 1's *Enumerations* row already names
[0047](0047.md), so the generated document emits `enum: [en, de, fr]` with no
further work.

**The inline `{id:uint}` grammar room [0077](0077.md) § 2 reserved is deliberately not
taken.** It would state the same fact twice, in two places that can disagree, and buy no capability.

**A regex constraint is refused outright, and this is a security decision rather than a taste one.** Laravel,
Symfony and Rails all accept an application-authored regex into the router. That regex then runs **on the
request path, before any rate limiting** ([0075](0075.md) is above the handler, not above the
match), which makes a catastrophically backtracking pattern a denial-of-service vector reachable by any
unauthenticated client. All three ecosystems have had the CVE. Under
`rule:programs/memory-priority`'s ordering that is priority 1 spent to buy priority 4, which the
ordering forbids in that direction. A shape a type cannot express — a slug matching `[a-z0-9-]+` — stays a
`Core\Validate` check inside the handler, which answers `400` and is the correct answer for it anyway.

### 6. A link is built through the launderer, absolute or not

```php
Core\Router::url(string $name, array<string, mixed> $params): string;           // launder (URL path)
Core\Router::urlAbsolute(string $name, array<string, mixed> $params): string;   // launder (URL)
```

**Keys that are not captures become a percent-encoded query string.** A missing capture stays the compile
error [0077](0077.md) § 4 already makes it, and **a literal key that is neither a
capture nor one of the route's declared `#[Query]` parameters (§ 3) is a compile error too** — the same
shape as that ADR's existing unknown-`url()`-name error. Without this rule the moment an application needs
`?page=2` it writes `url(…) . "?page=" . $n`, which is exactly the concatenation the launderer exists to
prevent and which re-taints the result; with it, a typo cannot silently become a query parameter.

**`urlAbsolute` prepends a configured origin, never a sniffed one.**
[0097](0097.md) § 6's refusal to read `X-Forwarded-Host`, or to derive
an origin from `Host`, is untouched and is the reason this member exists as configuration rather than as
inference — deriving one from a header is host-header injection, and an emailed password-reset link is where
it lands.

The origin is **per mount**, declared on [0097](0097.md) § 3's block,
falling back to `[app] origin`:

```toml
[app]
origin = "https://app.example.com"        # fallback

[[server.mount]]
scan   = "*/public/index.nvs"
host   = "{1}.example.com"
origin = "https://{1}.example.com"        # one line, every tenant
```

A single global origin would be **wrong** for a host-mounted deployment, which
[0097](0097.md) § 3 already supports: one binary serving
`tenant1.example.com` and `tenant2.example.com` would emit one tenant's origin in the other's email. The
same `{1}` that selects the mount builds the origin, so onboarding a tenant stays zero new configuration.

`origin` is **`System`** in [0005](0005.md)'s classification — a request may not set
it, because a value a request can choose is a value an attacker can influence and this one ends up in mail —
and **`Reload`** in [0078](0078.md)'s orthogonal field, so a new tenant
needs no restart. **The check that an origin resolves runs at mount expansion**, per resolved mount, and
re-runs on reload alongside the expansion [0097](0097.md) § 3 already
re-runs: a mount whose unit contains a literal `urlAbsolute` call and resolves no origin is a **boot error**,
so the failure is at deploy time rather than in a sent message.

### 7. A mount's captures are how one table serves many tenants

```php
Core\Request::mount(): Request\Mount
Core\Request\Mount::prefix(): string
Core\Request\Mount::captures(): array<tainted string>
```

**This replaces `mountPrefix`**, which stated half of it; two members for one fact is what this repository's
one-home rule forbids, and nothing is built, so nothing migrates. `prefix` is what
[0097](0097.md) § 3 strips from the path, and `captures` are that
section's glob captures — `{1}` is `captures[0]`. They are `tainted string` because they came off the wire,
so feeding one to a query launders normally.

**The pair is a class, not the shape literal it reads as.** A shape has no return-position spelling:
`nvs_stdlib::registry`'s `CoreTy::Shape` is a parameter-only variant with no runtime representation, and
`nvs_ir::lower_checked_ty` erases a `Ty::Shape` value to `Ty::Object` — which would take the `tainted` above
with it, so the shape spelling loses the one thing this section is for. § 1's `Router\Match` is the same
pair-of-answers shape one member along and is already a class, so this costs a reader nothing new.
**`mount()` is not nullable**, where § 1's `route()` is: nothing matching the route table is an ordinary
served request, but every request that reached a program reached it *through* a mount, and a door that
strips nothing answers `""` and an empty array rather than an absence.

**`#[Route]` gains no `host` field.** Host matching already exists one layer down, and putting a hostname in the
compiled table would destroy the property [0097](0097.md) § 3 bought:
*"the same compiled route table serves at `/ModuleA`, at `/ModuleB` or at `/`, with no recompile."* It is
also the same lifetime argument [0077](0077.md) already used to keep routes out of
`nvs.toml`, read in the other direction — **a path is source state and a hostname is deployment state**, so
each belongs where it changes. It would additionally force the duplicate-route compile error to grow a host
dimension, weakening one of the three checks that ADR exists for.

### 8. CSRF is the server's; the access decision is the dispatcher's

[0096](0096.md) § 2 left interpretation to "the
M7 server, **or** `Web\Auth`". That "or" is resolved: **the server enforces CSRF and nothing else.** The
declared access name rides on § 1's match, uninterpreted, and whoever dispatches — `Web\Auth`
([0082](0082.md) § 3), or an application's own `switch` — reads and enforces it.

Two enforcement points is how a route ends up checked twice in development and not at all in production. One
point, and it is the one that knows what a role means: the server would need a session, a user model and a
role source to interpret `Role::Admin`, all three of which
[0096](0096.md) § 2 and
[0082](0082.md) § 4 put outside the binary on purpose.

**The limit this leaves is stated plainly rather than implied: the compiler guarantees the decision was
*written*, not that it was *honoured*.** An application that hand-rolls dispatch and never reads
`route()->access` gets no enforcement. Closing that would require the compiler to recognise a dispatch site,
which is precisely the opinion [0077](0077.md) § 4 refuses to hold, and is
unimplementable against a dispatch table the compiler cannot follow.

**`Core\Access` joins [0071](0071.md) § 1's closed list**, which
[0096](0096.md) always owed and never wrote. Its
*Amends* line said "Amends: nothing". Because that ADR relies on the attribute being matched **nominally**,
and 0071 § 1 says "nothing else is ever matched by name", the omission meant a userland
`type Access = {...};` would satisfy the mandatory-sibling check and the compile error would pass on a
decision nobody made — defeating the ADR's purpose. This is a repair, not a new rule.

### 9. Routing is not a forcing case for typed `callable`, and the attribute count gets one home

A `Match` carrying a callable reference would need typed `callable` signatures
([0077](0077.md) § 4), which invites reading routing as a case that forces
[0007](0007.md) § 3's deferral. **It is not one.** Typed `callable` would not remove
the `switch`, for three independent reasons:

- **Routes do not share a signature.** `show(uint $id)`, `index()` and `blog(uint $y, uint $m, string $slug)`
  cannot inhabit one `handler` field. The only way around it is pre-binding the converted parameters into a
  zero-argument closure — and pre-binding is dispatch.
- **[0077](0077.md) § 4 rejects an invocable `Match` on two grounds, and typed
  `callable` removes only one.** *"Invoking would be dispatch, which is § 4's whole boundary; **and** a
  first-class reference would need `callable` to carry a signature."* The boundary ground survives intact,
  and § 8 above has just re-affirmed it.
- **Handlers have no common return type.** [0077](0077.md) § 4: *"What a handler
  returns is between it and whoever called it."* A `callable(): Response` would force one, which is a
  framework opinion `Core` refuses to hold.

So a future ADR re-arguing the deferral argues it on the cases
[0007](0007.md)'s *Revisiting* lists, plus the per-element dynamic-call cost in
`Core\Arr` — not on routing.

**The ergonomic cost is paid where [0082](0082.md) already put the layer.**
`Web\Controller` generates the dispatch `switch` from the route table **while compiling**, so an application
using the framework never writes one and receives typed, laundered parameters directly. An application that
declines the framework writes the `switch` itself — permanently, and typed `callable` was never going to
change that.

**[0071](0071.md) § 1 is the one home for the closed list of compiler-recognized
attributes, and no ADR states its size.** Every ADR adding one says its attribute "joins the closed list"
and stops there. A total restated in each amending ADR is a total that goes stale, which is what happened
to this one before the rule was written down.

## Consequences

**Positive**

- **Three contradictions leave the tree.** The server-holds-the-table disagreement, the query-binding
  forward reference, and `#[Access]`'s missing closed-list entry were each wrong before this ADR and are
  each repaired by a section of it. The last was security-relevant.
- **The match is made once and is cheaper than what it replaces**, measured at 32.7 ns against a 135.9 ns
  header parse the server performs regardless — and most requests were about to make two matches.
- **The boundary held under nine decisions.** Nothing here dispatches, and § 9 shows the one remaining
  temptation does not become available even when its stated blocker is removed. A framework can still use
  all of this, half of it, or none.
- **The generated OpenAPI document becomes complete.** § 3 makes query parameters real and § 5 makes a
  closed set expressible, which are between them most of what an API contract says beyond a path.
- **`url()` covers the cases that were driving people out of it.** Query strings and absolute links were
  both reachable only by concatenation, which re-taints and which a reviewer cannot see is wrong.
- **Multi-tenancy works without touching the route table**, so a module stays relocatable.

**Negative**

- **The closed list of compiler-recognized attributes reaches seven names.**
  [0071](0071.md)'s *Consequences* warned that "cheap to add" is how an attribute set becomes
  a second, undocumented language surface, and this ADR adds two in one sitting. § 9's deletion of the
  running count makes the list maintainable but does not make it shorter, and `#[Query]` is the entry that
  should have been held to the highest bar.
- **The server does work for a program that may not want it.** A route table with metrics off, on a safe
  method, never reading its own route, pays 32.7 ns for a match nothing reads.
- **`#[Access]` is guaranteed written, never guaranteed honoured.** § 8 states the limit; it does not close
  it, and an application that hand-rolls dispatch can still ship an unenforced route.
- **`{name?}` is a third thing in the path grammar**, and the grammar was previously two things and a rule
  about position.
- **A query parameter fails `400` where a path capture fails `404`.** Defensible and argued in § 3, but it
  is one more thing a reader must hold, and the two spellings sit on adjacent lines of the same signature.
- **`origin` is a new configuration key that a deployment can forget**, caught at boot only for a unit that
  actually calls `urlAbsolute`.

## Alternatives rejected

- **Leaving the match to the application** ([0077](0077.md) § 4 as written). Rejected
  in § 1: it leaves the 0096/0097 contradiction unresolved, means two matches for most requests, and lets
  the application's match and the server's disagree about the same request.
- **A three-state `match` return** instead of § 2's separate member. Rejected: it puts a verb list on the
  success path where it is never read and makes every caller destructure three cases to use one.
- **Answering `404` for a refused verb.** Rejected in § 2: it breaks RFC 9110, and the information-hiding
  argument for it is weak because a `GET` already reveals the path exists.
- **Deleting [0085](0085.md)'s query row** instead of § 3's
  binding. Rejected: it leaves every endpoint hand-validating its own query and the generated contract
  silently missing most of its parameters, which for [0080](0080.md)'s
  audience is most of the document's value.
- **A `query:` field on `#[Route]`** rather than a sibling attribute. Rejected: it puts a binding list at a
  distance from the parameters it names, and
  [0096](0096.md) already set the precedent that
  a sibling attribute is how `#[Route]` is extended without reopening § 4.
- **Two `#[Route]`s with a relaxed duplicate-`name` rule** instead of § 4's `{name?}`. Rejected: it weakens
  one of the three compile errors 0077 exists for, and turns `url()` from a table lookup into a best-fit
  search.
- **Inline `{id:uint}` constraints.** Rejected in § 5: the same fact in two places that can disagree, for no
  new capability.
- **Regex constraints**, as Laravel, Symfony and Rails all allow. Rejected in § 5 on
  `rule:programs/memory-priority`'s ordering: an unbounded application-authored regex over the
  request path, before rate limiting, is a denial-of-service surface, and all three ecosystems have the CVE
  to show for it.
- **Rejecting extra `url()` keys** rather than § 6's query string. Rejected: it leaves no laundered spelling
  for a link with a query string, so every paginated link falls back to concatenation.
- **One `url()` whose absoluteness depends on config.** Rejected in § 6: the same call site would mean two
  different things depending on a file the reader is not looking at, and it breaks
  [0097](0097.md) § 3's relocatability.
- **A single global `[app] origin` with no per-mount override.** Rejected in § 6: it is silently wrong for
  every tenant but one in a host-mounted deployment the server already supports.
- **Making `origin` `Runtime`-class**, settable per request. Rejected in § 6: a value a request can choose
  is one an attacker can influence, and this one is emailed. `tainted` blocks the naive spelling but not one
  laundered through a database round-trip.
- **A `host` field on `#[Route]`**, as 0077's *Revisiting* proposed and Symfony supports. Rejected in § 7:
  it bakes deployment state into the compiled table, destroys relocatability, and forces the duplicate-route
  error to grow a host dimension.
- **The server enforcing `#[Access]`.** Rejected in § 8: it would drag a session, a user model and a role
  source into the binary and cross 0077 § 4's boundary.
- **A compile error at the dispatch site** for an unread access decision. Rejected in § 8: it requires the
  compiler to recognise dispatch, and is unimplementable against a dispatch table it cannot follow.
- **Blocking this ADR on typed `callable`.** Rejected in § 9: it would be waiting for a fix that does not
  arrive, since two of the three obstacles survive it.

## Revisiting

- **`#[Query]` is the entry that makes the closed list long.** If an eighth compiler-recognized attribute is
  ever proposed, the question to ask first is whether the list should become a documented language surface
  with its own reference page rather than a roster inside [0071](0071.md) § 1.
- **Typed `callable`** ([0007](0007.md) § 3) is now owed its own ADR, argued on three
  forcing cases and the `Core\Arr` dispatch cost. § 9 removes routing from that argument; it does not weaken
  the rest of it.
- **`#[Access]` being written but not honoured** (§ 8) is the one gap this ADR names and does not close. If
  the corpus imported in [M11](../implementation-plan.md) shows applications hand-rolling dispatch and
  dropping the check, the answer is a lint in `Web\Controller`'s generator rather than a compiler rule.
- **A shape constraint a type cannot express** — the `[a-z0-9-]+` slug — stays a handler-side
  `Core\Validate` check. If it turns out to be the common case rather than the rare one, the answer is a
  named, non-backtracking matcher in `Core\Validate` that the router may call, never an
  application-authored regex on the request path.

## Verification

- **M4S:** `#[Query]` is matched nominally, like `#[Route]` — a userland `type Query = {...};` binds
  nothing, and `#[Core\Query]` and a `use`d `#[Query]` are one attribute. A `#[Query]` parameter whose type
  is not one of § 5's is a compile error at the parameter.
- **M4S:** `{name?}` not in the last position, two of them in one path, one beside a `{name...}`, and one
  whose parameter has no default are each a compile error naming both sites.
- **M4S:** a literal-union capture type and an enum-case-subset capture type each compile; the generated
  OpenAPI carries the union's members as `enum`.
- **M4S:** `url("posts.index", {page: 3, sort: "desc"})` folds to `/posts/3?sort=desc` where `sort` is a
  declared `#[Query]` parameter, and is a compile error where it is not — alongside the existing
  unknown-name and missing-capture errors.
- **M7:** `Core\Request::route()` is the same match [0096](0096.md)
  § 4's CSRF check and [0076](0076.md) § 1's `route` label read — asserted by a fixture
  that observes one match for a request that does all three.
- **M7:** a program with no route table gets `route()` returning `null`, performs no scan and emits the
  request series with no `route` label — [0077](0077.md) § 5's opt-in rule, unchanged.
- **M7:** `methodsFor` returns the declared verbs for a path claimed under another method and an empty array
  for an unclaimed one; `/posts` and `/posts/{page?}` report the same verbs, so the short form does not
  `404` while the long one `405`s.
- **M7:** `/posts` matches `{page?}` with the parameter's default, `/posts/3` matches with `3`, and
  `/posts/` matches neither.
- **M7:** `/fr/docs/x` matches a `"en"|"de"|"fr"` capture and `/xx/docs/x` falls through to a `404` rather
  than reaching the handler.
- **M7:** a `#[Query]` conversion failure is a `400` while a path-capture conversion failure is a `404`,
  asserted side by side on one route so the divergence is pinned rather than assumed.
- **M7:** `urlAbsolute` under two host mounts of one compiled table yields two different origins, and
  `mount().captures[0]` is the host glob's `{1}` and is `tainted` — checked by a fixture that would not
  compile if the qualifier were wrong.
- **Boot:** a mount whose unit contains a literal `urlAbsolute` call and resolves no `origin` is a boot
  error, and the check re-runs on a configuration reload with a newly scanned mount.
