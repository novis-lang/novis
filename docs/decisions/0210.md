# ADR 0210 — A property inside an `interface` body is refused where it is written

- **Scope:** what a property declaration inside an `interface` body does. Interface methods,
  constants and delegation are unchanged and are other records' ([0043](0043.md)).
- **Depends on:** [0043](0043.md), [0126](0126.md).
- **Validated by:** `tests/conformance/reject/an-interface-declares-no-property.nvst` and
  `crates/nvs-syntax/src/parser/tests/decl.rs`'s
  `an_interface_property_is_refused_and_the_rest_of_the_body_parses`.

> **In short:** an interface body is parsed by the class-body grammar, so a property inside one
> parsed, resolved and type-checked, and only the layout pass dropped it — silently, because
> [0043](0043.md) had already decided interfaces declare no state. A read through the interface
> then failed in codegen behind a clean `nvs check`. The property is now refused at the
> declaration as `E0254`, whose help names what replaces it: a bodiless method, or a typed
> constant the implementor overrides and a default method reads as `static::NAME`. Admitting the
> property was declined: it would need a run-time name lookup on every read through an
> interface-typed receiver and a conformance check per implementor, to buy a spelling the
> constant already gives.

## Context

### 1. A clean check and a codegen failure

A framework declared a page's path as `public string $path;` on the interface every page
implements, gave each page `public string $path = '/';`, and read `$v->path` through the
interface. `nvs check` reported nothing. `nvs run` stopped in `nvs-codegen`, which found no slot
for `View::path`: `nvs_types::layout` writes an empty property list for every interface, so the
IR class carried no field and the `FieldGet` the interface label named had nothing to resolve to.

### 2. The rule already existed and nothing enforced it

[0043](0043.md) decided interfaces carry behaviour and no state, and
`rule:classes/interface-private-methods` says so in one sentence. [0126](0126.md) named a
declared interface property as the one thing that would reopen a row of its own. No diagnostic
carried the rule: the parser reuses `parse_class_body` for a class, an interface and a rejected
`trait` alike, and every later pass treated the property as any class's.

## Options considered

### 3. Lower the property

A property read is a constant slot offset keyed on the receiver's static class. Through an
interface-typed receiver the concrete class is unknown until run time, so the read would need the
name-keyed lookup the erased-receiver path already pays, plus a conformance check that every
implementor declares the property at a compatible type, plus a decision on hooks and `readonly`
across the contract. PHP 8.4 admits only a hooked property in an interface, so the plain form is
not a PHP construct being refused either.

### 4. Refuse it at the declaration

One loop over the parsed body in `finish_interface_decl`, one code, one help line naming the
replacements. The enum body already refuses a method the same way.

## Decision

### 5. Refuse

Option 4. The value such a property was written for has two homes the interface already offers:
a bodiless method every implementor writes, and a typed constant the implementor overrides, which
a default method reads as `static::NAME` now that
`rule:statements/static-is-a-member-modifier` binds a constant late ([0211](0211.md)).

## Diagnostics

### 6. `E0254`

`an interface declares no property`, primary on the member's whole span, help naming the method,
the constant read as `static::NAME`, and `implements I by $field;` for shared state.

## Consequences

### 7. What changes for a program

A program that declared a property in an interface never ran, so nothing that runs changes.
`nvs check` now reports the declaration instead of accepting it.

## Alternatives rejected

### 8. Refusing in the checker instead of the parser

The checker sees the same declaration one pass later with nothing more to say about it, and the
parser is where the enum body's sibling refusal lives.

## Revisiting

### 9. If declared interface properties are admitted

That is the row [0126](0126.md) § 3 names. It reopens this record and `E0254` retires with it.

## Verification

### 10. Guards

The reject case pins the code and its position. The parser test pins that the refusal is a
diagnostic on an accepted body: the members beside the property still parse, and a body with none
draws nothing.
