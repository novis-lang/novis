# ADR 0143 — A push runs the lane its diff needs; the nightly and the release run all of it

- **Scope:** which jobs in [ci.yml](../../.github/workflows/ci.yml) run on a push to `main` and on a
  pull request, which are deferred to the nightly run and the release gate, and what escalates a
  deferred one back onto a push. It does **not** decide what any job *contains* — the suite is
  unchanged and every job still exists — nor what a release does once the suite is green
  ([docs/release.md](../release.md)), nor what `tools/verify.py` runs before a commit
  ([docs/agent/commands.md](../agent/commands.md)).

> **In short:** CI had one lane — sixteen runners, every one of them on every commit, and
> `release.yml` reaching for the same workflow, so a release and a typo in an ADR bought exactly the
> same twenty-odd minutes. Now there are three, out of **one** file. **Always:** the Python document
> checks, which cost seconds. **When the diff can break it:** build, test, conformance and lint —
> **on all three platforms, every time any code changes**; ASAN and the release-profile cost guards
> when the runtime, the backend, the library or the probes changed; `cargo deny` and the attribution
> diff when the dependency set changed; the reference check when the binary or its chapters changed.
> **Nightly at 03:00 UTC and again at release:** all of that unconditionally, plus Miri, the fuzz
> smoke runs and the unsafe audit. One workflow still holds every job — `release.yml` calls it with
> `full: true`, so the release gate is the same definition every push already runs a slice of, and
> cannot drift from it. **No lane is ever narrowed by platform**, because this is a public repository
> and which host a contributor pushes from is not knowable; what a push skips is work whose answer
> its own diff cannot change. The trade is one sentence long: anything only Miri or the fuzzers see
> is now found within a day rather than within ten minutes.

## Context

- **Sixteen runners fired on every commit**, and the loop's commits are not uniform: a large share of
  them are docs, a plan status block or an ADR, and those paid for three platform builds, a Wasmtime
  build, a nightly Miri run, a sanitizer rebuild and two `cargo install`s that can change nothing they
  could observe.
- **`release.yml` does not have a suite of its own.** Its `verify` job is
  `uses: ./.github/workflows/ci.yml`, on purpose: one home for what must be green. That is the right
  structure and it is why the fast lane could not be bought by deleting jobs — deleting a job from
  `ci.yml` deletes it from the release gate in the same edit.
- **One job gated nothing at all.** `unsafe-audit` is `continue-on-error: true` and appends
  `cargo geiger` output to the run summary; it cost a `cargo install cargo-geiger` per push for a
  number nobody was blocked by.
- **`fuzz-smoke` re-derived the same shallow findings every run.** 60s per target against a corpus
  that starts empty each time is not sixty seconds of new coverage; it is the same sixty seconds
  repeated, because nothing persisted what the last run found.

## Decision

### 1. Three lanes, one workflow

`ci.yml` gains a `schedule:` trigger and a `full` boolean on its `workflow_call`. Nothing else about
the file's structure changes: the jobs are the jobs.

- **The push lane** — `push` to `main`/`master`, and every `pull_request`. Jobs run under an `if:`.
- **The deep lane** — the nightly `schedule`, any `workflow_dispatch`, and `release.yml` passing
  `full: true`. Every gate is forced true, so every job runs.

A job is never defined twice. A second copy of a suite drifts, and it drifts silently because nothing
compares the copies — the reason `release.yml` calls this workflow rather than restating it.

### 2. The gates

The first job, `changes`, runs `python tools/ci-changes.py`, which compares the push's or the pull
request's base against `HEAD` and emits one boolean per lane. Every other job's `if:` is a single
comparison against one of them.

| Job | Runs when |
|---|---|
| `docs`, `migration-table` | always — Python only, seconds, and they catch the stale generated file a docs session produces |
| `test` (**all three platforms**), `lint` | `code` — any build input: `crates/`, `benches/`, `tests/`, `examples/`, `fuzz/`, `tools/`, the manifests, the toolchain pin, the workflows |
| the cost-guard step inside `test`, `asan` | `native` — `nvs-runtime`, `nvs-codegen`, `nvs-stdlib`, `nvs-host`, `benches/abi-probe` |
| `extension-sandbox` | `probe` — `benches/abi-probe/`, which is where `wasmtime` enters the tree |
| `supply-chain`, `attribution` | `deps` — the manifests, `deny.toml`, `THIRD-PARTY-LICENSES.txt`, the generator |
| `reference` | `refdoc` — `crates/`, `docs/reference/`, `docs/novis.md`, `tools/reference.py` |
| `miri`, `fuzz-smoke`, `unsafe-audit` | `deep` — the nightly and the release only |

**The platform matrix is not one of the gates.** Whenever `code` is true, all three legs run, exactly
as before this ADR; the matrix in `ci.yml` is untouched and static. Novis is a public repository and
nothing here may assume which host a contributor develops or pushes from, so no platform's coverage
is ever traded away by a path rule. `native` narrows two things only, and neither is a platform: ASAN,
which is a Linux job either way, and the cost-guard step, which is a second compile of the workspace
in release profile and whose baselines can only move if a measured crate moved.

**The lane table is a table in one Python file**, not a set of `paths:` filters spread over the
workflow and not a third-party action. It is the policy's only home, it is readable by anyone who can
read a dictionary, and `python tools/ci-changes.py --base HEAD~1` answers "what would CI have run for
this commit" without pushing anything.

### 3. Unknown base means everything

A first push to a branch, a force-push and a shallow clone all leave `ci-changes.py` without a base
commit it can diff against. Every such case resolves to **every lane true**. The failure mode of
guessing wrong in the other direction is a merged commit nothing checked, and there is no version of
this that is worth one of those.

### 4. A deferred job is skipped, never absent

Every gate is a job-level `if:`, never a workflow-level `paths-ignore:`. The difference matters
exactly once and then permanently: a job skipped by `if:` reports success to a required status check,
while a workflow filtered out by `paths-ignore:` never reports at all and a required check on it waits
forever. The second is a branch that cannot be merged, discovered by whoever turns branch protection
on months from now.

### 5. What moves into the nightly, and what it gains there

`miri`, `fuzz-smoke` and `unsafe-audit` leave the push lane entirely.

`fuzz-smoke` gets what it was missing: its corpus is cached between runs and its budget rises from 60s
to 300s per target. A nightly run that starts from what every previous night found is strictly more
coverage than a per-push run that starts from nothing, and it costs the push lane nothing at all.

### 6. Consecutive pushes each get a verdict

`cancel-in-progress` becomes true for pull requests only. A run on `main` is no longer cancelled by
the next commit, so every commit on the default branch carries its own result — which is what a bisect
reads, and the loop commits a slice at a time. The concurrency group gains `github.event_name`, so a
25-minute nightly never sits in front of an 8-minute push.

## Consequences

- **The push lane is the two always-on Python jobs plus whatever the diff touched.** A docs-only
  commit — an ADR, a plan status block, a playbook bullet — runs those two and nothing else, which is
  a large share of what this repository commits. A commit in `nvs-syntax` runs build, test and
  conformance on all three platforms, plus lint and the reference check. A commit in `nvs-runtime`
  adds ASAN and the cost guards.
- **Coverage latency, stated:** anything only Miri sees, and anything the fuzzers would have reached,
  is now found by the nightly rather than by the push — up to 24 hours, against a day of commits, on
  signals that have not fired once. **Nothing platform-specific is deferred**: a divergence between
  Linux, Windows and macOS is still caught by the push that introduced it.
- **Nothing left the suite.** Every job still exists and the release gate still runs all of them —
  which is the whole reason the trade is affordable. If the nightly ever finds something the push lane
  should have, the fix is one entry in the lane table.
- **Priority ordering (`rule:programs/memory-priority`):** this spends nothing from
  priorities 1–3. `cargo deny` still gates every change that can alter the dependency set, and ASAN
  still gates every change to a crate holding unsafe. What it spends is a little of priority 4: there
  is now a table to consult before adding a job.

## Alternatives rejected

- **A second workflow holding the heavy jobs.** Two files, two copies of the toolchain and cache
  setup, and the release gate assembled from both. The drift argument that put `uses:` in `release.yml`
  applies unchanged.
- **`dorny/paths-filter`.** A third-party action on the critical path of every run, pinned by SHA and
  audited by whoever updates it, to compute a `git diff` this repository can already spell in Python.
  Supply chain is priority 1 and `tools/` is where this repo puts its logic.
- **Workflow-level `paths-ignore:`.** Fewer lines, and it breaks required status checks — § 4.
- **Deleting the deferred jobs.** They are the memory-safety and fuzz evidence a JIT-compiled runtime
  is obliged to keep producing. The question was never whether to run them, only how often.
- **Narrowing the platform matrix by path** — a push building Linux alone unless the diff looked
  native, with the other two legs deferred to the nightly. It is the largest saving on offer and it
  was rejected outright. It can only be argued for by assuming something about who is developing on
  what, and no such assumption is available in a public repository: the contributor who never sees a
  Windows failure until the nightly is precisely the one who cannot reproduce it. It also rests on a
  claim nothing enforces — that a change outside the native crates cannot change per-platform
  behaviour — which is false the moment a front-end change alters what gets compiled, or a CLI change
  touches a path, a line ending or a file mode.

## Verification

- `python tools/ci-changes.py --base <sha>` prints the lanes for any range, so the table is checkable
  against real commits without a push.
- The release gate is `uses: ./.github/workflows/ci.yml` with `full: true`; a job that stopped running
  there would be a job removed from this file, which is a visible edit.
