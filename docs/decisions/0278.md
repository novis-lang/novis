# ADR 0278 — `Core\Ldap` is a native LDAPv3 client that binds only by simple bind over TLS, takes filters as values and reads Active Directory's attributes as typed values

- **Scope:** the whole surface of `Core\Ldap`: its classes, members and options shapes, the
  `[ldap.<name>]` block and the three `ldap.*` grants, how a connection binds and when it may bind
  without TLS, the pool and `authenticate`'s own connection, the search options and the four Active
  Directory extras, the filter builder and `Ldap\Dn`, the type table, writes and passwords, and the
  error kinds. Not in scope: which sans-IO codec crate `crates/nvs-ldap` borrows, which Stage 3 of the
  goal picks under `rule:core-classes/db-crate-boundary`; and the tier, which [0051](0051.md) § 3
  already placed.
- **Depends on:** [0051](0051.md) § 3 (the Native placement and the escaper in `Core`),
  [0067](0067.md) (`Core\Db`, whose block, grants, pool and reset this mirrors), [0024](0024.md)
  (`tainted` and its sink-named launderers), [0063](0063.md) (one paradigm per operation, the options
  bag), [0088](0088.md) (the sink predicate).
- **Validated by:** the `ldap` goal's stage checks: `crates/nvs-ldap/tests/` against the `samba-ad`
  test server, and the `tests/conformance/core/ldap-*.nvst` cases and `tests/hostile/core/Ldap*/`
  attacks as each stage lands them.

> **In short:** `Core\Ldap` is a general LDAPv3 client, Native like `Core\Db` and in every binary,
> whose wire is `crates/nvs-ldap` over the runtime's own TCP and TLS streams. `Ldap::connect('<block>')`
> and `Ldap::open(Ldap\Settings)` return a pooled `Ldap\Connection` bound as the block's identity; the
> only bind is a simple bind, over LDAPS or StartTLS unless the operator lists the host under
> `[capabilities.ldap] cleartext` and the block says `tls = "none"`. Kerberos, NTLM and every SASL
> mechanism are declined for good. A filter is an immutable `Ldap\Filter` value encoded straight to
> BER, so a `tainted` value can never change its structure and no escaper exists; `Ldap\Dn` is the one
> launderer for the DN sink. Attributes are read through typed readers driven by the server's schema
> plus a fixed table of Active Directory names, so a GUID is a `Core\Uuid`, a SID an `Ldap\Sid`, a
> FILETIME an `Instant` and `userAccountControl` a readonly flag object. `authenticate` binds on a
> connection of its own and names AD's reasons, with an unknown user and a wrong password as one kind.

## Context

[0051](0051.md) § 3 placed `ldap` as *Native but unscheduled*: Native by test 1, because a bound
directory session is state across calls, and with its injection answer in `Core` by test 2. The `ldap`
goal schedules it. The audience is the one 0051 named — applications that sign people in against
Active Directory and read group membership from it — and the server they meet is almost always AD, so
the client is general LDAPv3 with AD's conveniences under `Ldap\Ad`.

PHP's `ext/ldap` is the comparison every reader brings. Its surface is a C binding to OpenLDAP's
`libldap`: process-wide options, `false` plus `ldap_errno`, a `count`-keyed array with lowercased keys,
`ldap_escape` as the only injection answer, referral chasing with a rebind callback, and TLS settings
read from `ldap.conf` and `LDAPTLS_*`. php-src issue #17776 is the shape of the risk: a TLS option set
for one request's connection leaked into the next request's, so a "do not verify" meant for a test
server applied to production.

## Investigation

**The wire cannot be `ldap3`.** The Rust client most projects reach for runs on tokio, which
`crates/nvs-runtime/tests/manifest_policy.rs` keeps out of the graph (`rule:concurrency/one-scheduler`).
`rule:core-classes/db-crate-boundary`'s rule applies unchanged: BER and the LDAP message grammar are a
codec, identical for everyone and borrowed sans-IO; the sequencing — bind, StartTLS, the paging cookie,
when a connection is reusable — is written here, over `nvs_host::net::NvsTcp` and `nvs_host::tls::NvsTls`,
with StartTLS as the extended operation followed by the same in-place upgrade `Core\Mail` uses.

**Samba AD answers what the design depends on.** `smblds/smblds` (Samba 4.23) was run by hand without
`--privileged`. Over LDAPS it returned `objectGUID` and `objectSid` as binary, `pwdLastSet` as a
FILETIME and `whenCreated` as GeneralizedTime; it answered an empty-password simple bind with
`data 52e`, a simple bind on port 389 with `strongerAuthRequired`, and evaluated the nested-group
matching rule. AD itself answers an empty-password simple bind as a *successful anonymous bind*
(RFC 4513 § 5.1.2's unauthenticated bind), which is the classic login bypass, so the refusal has to be
the client's. Samba lacks the `.2253` DN-form control and returns nothing from the nested-group rule
when an object in the chain is unreadable; both are named in the tests rather than worked around.

**AD's flag fields are split.** Lockout and an expired password are not stored in
`userAccountControl`; they are computed into `msDS-User-Account-Control-Computed`. A reader of the
stored attribute alone reports a locked account as active.

## Options considered

1. **A binding to `libldap`, as PHP has.** Brings OpenLDAP's process-wide options, its own TLS stack
   beside `rustls` (`rule:security/one-tls-client`), `ldap.conf` and the environment, and SASL through
   `libsasl2`. Rejected on security and request isolation.
2. **`ldap3` over a private tokio runtime.** A second scheduler per core, refused by
   `rule:concurrency/one-scheduler` before any LDAP question is asked.
3. **A sans-IO codec under our own state machine, with a minimal surface** — bind, search, raw entries
   — leaving AD's types to a package. A package cannot be a launderer
   (`rule:security/launderers-are-sink-named`), and a GUID read with the wrong byte order is a bug
   every caller writes once.
4. **A sans-IO codec under our own state machine, general LDAPv3 with AD's types and extras.** Taken.

## Decision

### 1. The roster

One operation, one spelling (`rule:core-api/one-paradigm-per-operation`); every optional knob is one
trailing options bag (`rule:core-api/options-bag`).

| Class | Kind | Members |
|---|---|---|
| `Core\Ldap` | static | `connect(string $block): Connection`, `open(Settings $s): Connection` |
| `Ldap\Connection` | object | `search(Filter, ?SearchOptions): Entries`, `read(Dn\|string, ?{select}): ?Entry`, `changes(Filter, ?ChangesOptions): Changes`, `add(Dn\|string, array<string, mixed>)`, `modify(Dn\|string, array<Change>)`, `delete(Dn\|string)`, `rename(Dn\|string $from, Dn\|string $to)`, `compare(Dn\|string, string $attribute, mixed $value): bool`, `whoami(): string`, `setPassword(Dn\|string, secret tainted string)`, `changePassword(Dn\|string, secret tainted string $old, secret tainted string $new)`, `authenticate(tainted string $login, secret tainted string $password)` |
| `Ldap\Entries` | object, iterable of `Entry` | `total(): ?int`, `references(): array<string>` |
| `Ldap\Changes` | object, iterable of `Entry` | `cookie(): bytes` |
| `Ldap\Entry` | object | `dn(): Dn`, `has`, `string`, `strings`, `bytes`, `int`, `bool`, `instant`, `duration`, `uuid`, `sid`, `sids`, `accountFlags(): Ad\AccountFlags`, `groupType(): Ad\GroupType`, `accountType(): Ad\AccountType`, `isDeleted(): bool`, `toArray()` |
| `Ldap\Filter` | value | `equals`, `startsWith`, `endsWith`, `contains`, `present`, `atLeast`, `atMost`, `approx`, `all`, `any`, `not`, `parse`; `toString(): tainted string` |
| `Ldap\Dn` | value | `parse(string)`, `of(string $attribute, tainted string $value)`; `child(string $attribute, tainted string $value): Dn`, `parent(): ?Dn`, `rdn(): {attribute, value}`, `isWithin(Dn): bool`, `toString(): string` |
| `Ldap\Change` | value | `add(string, mixed)`, `remove(string, mixed)`, `removeAll(string)`, `replace(string, mixed)` |
| `Ldap\Sid` | value | `parse(string)`, `toString()`, `bytes()`, `domain(): Sid`, `rid(): int` |
| `Ldap\Ad` | static | `memberOf(Dn\|string, ?{nested: bool}): Filter`, `enabled(): Filter`, `disabled(): Filter`, `bitAnd(string, int): Filter`, `bitOr(string, int): Filter` |
| `Ldap\Ad\AccountFlags`, `Ldap\Ad\GroupType` | readonly value | one `bool` property per flag, `with({...})`, `bits(): int` |
| `Ldap\Ad\AccountType`, `Ldap\Scope`, `Ldap\Tls`, `Ldap\ErrorKind` | enum | § 8, § 5, § 2, § 10 |
| `Ldap\Settings` | shape | § 2 |
| `Ldap\LdapError` | error | `$kind: ErrorKind`, `$code: int` |

`SearchOptions` is `{base?: Dn|string, scope?: Scope, select?: array<string>, pageSize?: int,
sizeLimit?: int, timeLimit?: Duration, sort?: string, descending?: bool, window?: {offset: int,
count: int}, showDeleted?: bool}`. `ChangesOptions` is `{base?: Dn|string, select?: array<string>,
cookie?: bytes}`. Every reader on `Entry` takes the attribute name and returns `null` where the entry
has no value; `strings` and `sids` return the whole multi-valued list.

There is no `bind` member, no raw-control member, no raw-extended-operation member and no `escape`.
A control is a named search option; an extended operation is the member that needs it (`whoami` is
RFC 4532, StartTLS is the block's `tls`).

### 2. The block, `Settings` and the grants

`[ldap.<name>]` follows `[db.<name>]`: `url` (one URL or a list, `ldaps://` or `ldap://`), `base`,
`user`, `password` or `password_file` (a config secret,
`rule:config/a-secret-is-a-file-whose-content-is-the-value`), `tls` (`"required"`, the default, or
`"none"`), `tls_ca_file`, `timeout` and `pool`. Every table refuses an unknown key. A block with no
`user` binds anonymously; a block with a `user` and an empty password is a configuration error.
`Ldap\Settings` is the same fields as a shape: `url` is a sink with no launderer, as
`rule:core-classes/db-capabilities` makes `Settings.host`; `base` is `Dn|string`; `user` accepts
`tainted`, being a length-framed protocol field; `password` is `secret tainted string`; `tls` is the
enum `Ldap\Tls` with cases `Required` and `None`.

**The URL list fails over in order.** The first server that completes the TLS handshake and the bind
is used; a server that answers and refuses the credentials stops the walk, because a second server
would refuse them too and the walk would only multiply lockout counts.

Three deny-by-default grants under `[capabilities.ldap]`, in `db.*`'s shape: `connect` names blocks
and is pre-approved against the outbound address policy, because the operator wrote the address;
`open` names hosts, takes `*.` at a label boundary, and stays subject to
`rule:security/net-address-policy` in full; `cleartext` is § 3's host list. A timeout has a default and
no spelling for unlimited. Nothing is read from `ldap.conf`, `LDAPTLS_*` or any other environment, and
TLS trust is relaxed only where `rule:security/tls-trust-is-relaxed-only-under-a-host-grant` already
allows it per host.

### 3. Binding

**Simple bind is the only bind.** Kerberos, NTLM and every SASL mechanism — `EXTERNAL` included — are
declined for good, and no later session proposes them. Kerberos needs a C GSSAPI library, a keytab or a
credential cache found through the environment, and clock and DNS state outside the request; NTLM is
a broken challenge-response over MD4. Both are credential handling on the priority-one surface, for an
audience whose directories all accept a simple bind over TLS.

**A simple bind is encrypted unless two parties agree** (`rule:security/ldap-cleartext-bind-is-granted-per-host`):
`ldaps://` handshakes first and `ldap://` runs StartTLS before the bind. A bind over plain `ldap://`
needs the block or `Settings` to say `tls = "none"` *and* the host to be on `[capabilities.ldap]
cleartext`, and the client checks both before the password is written. The cost is stated where the
grant is: the password and every answer cross the network readable and changeable. A controller that
refuses a cleartext bind answers `strongerAuthRequired`, which is the kind `EncryptionRequired`.

**An empty password is refused before a byte is sent** (`rule:security/ldap-empty-password-is-refused`),
as `InvalidCredentials`, so a login form's empty field is a wrong password and never AD's anonymous
success.

### 4. The pool, and `authenticate`'s own connection

`rule:security/ldap-pool-is-bound-as-its-block` is the rule. The pool follows
`rule:security/db-pool-reset-is-a-boundary`: per core, keyed by every URL, the user, a digest of the
password, the TLS mode and CA file, and the configuration generation. **A pooled connection is bound as
its block's identity for its whole life**, because no member rebinds it: `authenticate` dials a fresh
connection over the same URL list and TLS, binds as the login, and closes it, success or failure. An
LDAP session keeps no other per-session state a program can set — controls are per operation — so the
reset is the property that the last operation finished: a connection released with a search still
paging, or an operation still outstanding, is closed rather than returned.

The bind name `authenticate` takes may be a DN, `user@upn-suffix` or `DOMAIN\user`, sent as given. It
accepts `tainted`: it is a framed octet string the server looks up, not an instruction it parses
(`rule:security/sink-predicate`). `authenticate` pays one TCP and TLS handshake per login; that is the
price of a pool that never changes identity.

### 5. Search

`search` sends the paged-results control (RFC 2696) on every request, `pageSize` 1000 by default, and
`Entries` fetches the next page as the loop reaches it, so a search holds one page and the current
entry. **A size or time limit the server hit throws** (`SizeLimitExceeded`, `TimeLimitExceeded`); a
partial result is never returned as if it were complete. `read` is a base-scope search for one entry
and returns `null` for `noSuchObject`.

**Referrals are never followed.** A continuation reference in a search is data, readable from
`Entries::references()` once the loop has finished; a referral answering any other operation throws
the kind `Referral`. There is no rebind callback.

**Ranged attributes are merged.** AD returns a long `member` as `member;range=0-1499`; the client
fetches the remaining ranges and returns the whole list under the plain name. The list counts against
the request's memory cap like any other value.

### 6. The filter builder is `Core`

`rule:core-classes/ldap-filter-is-a-value` is the rule. An LDAP filter on the wire is a BER structure,
not text: RFC 4515's string form is a client-side convenience that a client parses and then encodes.
A builder that encodes straight to BER is therefore the protocol's own shape, the way a bound parameter
is the SQL protocol's own shape, and it is the only form in which a filter carries a `tainted` value
without an escaper. `rule:core-classes/db-one-api` excludes *query builders* from `Core` because SQL
has a text form the server executes and a builder there is a second spelling of it; LDAP has no such
form on the wire, so the builder here is the one spelling, and that rule is about SQL and is not
edited.

Filters are immutable values made by static functions and combined with `all`, `any` and `not`; there
is no fluent chain and no operator overload. `atLeast` and `atMost` are RFC 4511's `>=` and `<=`, and
there is no `<` or `>` because the protocol has none. **A value is data and accepts `tainted`; an
attribute name is a sink** and is checked against RFC 4512's attribute-description grammar, throwing
`LogicError` on anything else. A value may be a string, bytes, an `int`, a `bool`, a `Core\Uuid`, an
`Ldap\Sid` or an `Instant`, and is encoded at search time by the same table § 8 reads with, so a GUID
filter matches AD's byte order. `Filter::parse` takes RFC 4515 text for filters an operator wrote; its
parameter refuses `tainted` (`rule:security/unclassified-parameter-refuses-tainted`), so request input
never reaches it. `toString` renders the RFC 4515 form for a log and is `tainted`, because the values
inside may be.

`Ldap\Ad` adds the AD matching rules as filters: `memberOf` with `nested: true` uses
`1.2.840.113556.1.4.1941`, `bitAnd` and `bitOr` use `.803` and `.804`, and `enabled` and `disabled`
test `userAccountControl`'s disabled bit.

### 7. `Dn` is the launderer for the DN sink

`rule:core-classes/ldap-dn-is-the-launderer` is the rule. A DN is parsed by the server into a path in
the tree, so a DN parameter is a sink by `rule:security/sink-predicate`. `Ldap\Dn` is built from parts:
`Dn::of` and `child` take an attribute type, checked as a filter's is, and a value that may be
`tainted`, and escape the value per RFC 4514. Every member that takes a DN takes `Dn|string`, and its
`string` arm refuses `tainted`; `Dn::parse` is the same refusal for text an operator wrote. The
launderer returns a carrier rather than a string (`rule:security/launderer-answers-a-carrier`), so a
value laundered for a DN reaches only a DN parameter. A DN the server returns comes back as a `Dn`.

### 8. The type table

`rule:core-classes/ldap-value-types` is the rule, and `rule:core-classes/db-column-types` is its
principle: each attribute has one natural type, a typed reader converts only where nothing is lost,
and anything else throws. Text and bytes are `tainted`. The schema gives the base type — AD's
`attributeSyntax`/`oMSyntax`, or the subschema's `SYNTAX` OID elsewhere — read lazily, once per pool,
and immutable after. A fixed table of names gives what the schema cannot say:

| Attribute | Natural type |
|---|---|
| `objectGUID` and every GUID-valued AD attribute | `Core\Uuid`, the first three groups byte-swapped from AD's mixed-endian form |
| `objectSid`, `tokenGroups`, `sIDHistory` | `Ldap\Sid` |
| FILETIME integers (`pwdLastSet`, `lastLogonTimestamp`, `accountExpires`, `lockoutTime`, …) | `?Instant`; `0` and `0x7FFFFFFFFFFFFFFF` are `null` |
| negative intervals (`maxPwdAge`, `lockoutDuration`, …) | `Duration` |
| GeneralizedTime | `Instant` |
| `TRUE`/`FALSE` | `bool` |
| `userAccountControl` with `msDS-User-Account-Control-Computed` | `Ad\AccountFlags` |
| `groupType` | `Ad\GroupType` |
| `sAMAccountType` | `Ad\AccountType` |

**A flag field is a readonly object with one `bool` per flag** and an immutable `with`; no general
flag-set type is added to `Core`. Bits the object does not name are kept, so a write never drops them.
`AccountFlags` reads lockout and an expired password from the computed attribute, which `search`
requests whenever `userAccountControl` is selected; those two are read-only and `with` cannot set them.
`pwdLastSet = 0` reads as `null` from `instant`, and `AccountFlags::$mustChangePassword` says it.

### 9. Writes and passwords

`modify` sends one Modify request whose changes apply atomically and in order: `Change::add`,
`remove`, `removeAll`, `replace`. A typed value is written in the form it is read, so a `Uuid`, a
`Sid`, an `Instant` and a flag object round-trip. `rename` derives the new RDN and, where it moved, the
new superior from `$to`. `compare` returns `bool` and throws on an error, never `-1`.

A password is AD's `unicodePwd`: the quoted string, UTF-16LE. `setPassword` is a `replace`, an
administrator's reset; `changePassword` is `remove` of the old plus `add` of the new in one Modify, the
user's own change, which AD checks against history. Both take `secret` strings
(`rule:security/secret-qualifier`) and run only over TLS, whatever the cleartext grant says. RFC 3062's
Password Modify is not used, because AD does not implement it. AD's policy refusal is the kind
`PasswordPolicy`.

### 10. Errors

Every failure is `Ldap\LdapError`, with `$kind` for the condition a program branches on and `$code`
for the LDAP result code. The kinds: `InvalidCredentials`, `AccountDisabled` (AD `data 533`),
`AccountLocked` (775), `PasswordExpired` (532), `MustChangePassword` (773), `AccountExpired` (701),
`NotAllowedNow` (530, 531), `EncryptionRequired`, `PasswordPolicy`, `NoSuchObject`, `AlreadyExists`,
`InsufficientAccess`, `ConstraintViolation`, `SizeLimitExceeded`, `TimeLimitExceeded`, `Referral`,
`ReadOnly`, `Unsupported`, `Unavailable`, `Timeout` and `Protocol`. **525 (no such user) and 52e (wrong
password) are both `InvalidCredentials`**, so a program cannot tell an attacker which accounts exist.
The message never carries a password or a value of the filter. A malformed attribute name or DN text
is `LogicError`, the program's own mistake.

### 11. The Active Directory extras

All four are in, each a named option or member and never a raw control.

- **Sort and VLV.** `sort` (one attribute, `.473`; AD sorts on one key) with `descending`, and
  `window` (`2.16.840.1.113730.3.4.9`), which needs `sort`, replaces paging for that search, and fills
  `Entries::total()` with the server's count.
- **Deleted objects.** `showDeleted` (`.417`) includes tombstones, and `Entry::isDeleted` says which.
- **Incremental sync.** `changes` is DirSync (`.841`): it returns the entries changed since the
  `cookie` the program stored, and `Changes::cookie()` is the next one. **`uSNChanged` polling pinned
  to one controller's `invocationId` is left out**: it is a second form of the same job, correct only
  while every call reaches the same controller, which the URL list's failover does not promise. On a
  server without DirSync, `changes` throws `Unsupported`.
- **The Global Catalog** is a block whose URL uses port 3268 or 3269. It is read-only: a write throws
  `ReadOnly` before a byte is sent.

### 12. What is taken from PHP's `ext/ldap`, and what is not

Taken: the atomic multi-change modify (`ldap_modify_batch`), `whoami`, a URL list for failover, and
controls attached to the operation they change. Not taken: process-wide TLS options, any "do not
verify" switch, an empty password as an anonymous bind, referral chasing and `ldap_set_rebind_proc`,
unlimited timeouts, `false` plus `ldap_errno`, the `count`-keyed array with lowercased keys (an
attribute name here matches without case and keeps the server's case), `ldap_escape`, `ldap_sort`,
T.61, the Oracle wallet, the `_ext` twins, and reading `ldap.conf` or `LDAPTLS_*`.

## Consequences

- **Performance:** one round trip per page of up to 1000 entries; the filter is encoded once per
  search with no text step; `authenticate` pays one TCP and TLS handshake per login.
- **Memory:** one page and the current entry per search, per request. The schema cache is per pool,
  O(endpoints) and not O(requests). A merged `member` list is the whole list, under the request's cap.
- **Usability:** AD values arrive as `Uuid`, `Sid`, `Instant`, `Duration` and flag objects; filters
  and DNs cannot be injected; the login reasons are named.
- **Simplicity:** one new Native subsystem in every binary, with no Cargo feature; a filter builder in
  `Core`, with § 6 as its reason; no second spelling of anything. The cost is compile time and binary
  size, as `rule:core-classes/db-crate-boundary` already spends for `Core\Db`.
- A deployment whose directory accepts only Kerberos or NTLM cannot use `Core\Ldap`. That is accepted.

## Alternatives rejected

- **`Filter::escape` beside text filters.** A second, weaker answer to a question the value builder
  settles; `rule:security/launderers-are-sink-named` forbids a catch-all, and an escaper over filter
  text is one for exactly this reason.
- **A fluent filter chain.** Two spellings of the same tree (`->and()` beside `all`), and order
  sensitivity a reader has to simulate.
- **A general bit-flag type in `Core`.** Three AD fields need it; a readonly object per field names
  every flag and costs nothing anywhere else.
- **Rebinding a pooled connection for `authenticate`.** Saves a handshake per login and makes the
  pool's identity something a request can change, which `rule:security/db-pool-reset-is-a-boundary`
  exists to prevent.
- **Distinct kinds for 525 and 52e.** A user-enumeration oracle handed to every login form.

## Revisiting

If a directory product the audience uses stops accepting a simple bind over TLS, the binding question
reopens; Kerberos is still declined, and the trigger is a mechanism that needs no ambient state.

## Verification

The `ldap` goal's stage checks hold each section: the Samba AD service in `tests/db/compose.yaml`
answers the wire, bind, search, writes, `authenticate` and the extras; the conformance cases pin the
grants, the empty-password refusal, the filter and DN sink splits and the type table; the attacks under
`tests/hostile/core/Ldap*/` try filter and DN injection, an empty password, an ungranted cleartext
bind, an unbounded search, an endless range and a continuation reference to another host. A run
against Windows Server is a person's check, and a gap it finds is a backlog item.
