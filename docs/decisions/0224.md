# ADR 0224 — the build keys read Rust source off the syntax tree `syn` parses, and the `card` tier leaves out a class's link to its card

- **Scope:** how `bun nv`'s build keys and the perf ledger's `impl_hash` read a `.rs` file: which
  program reads it, and what the `shipped` and `card` tiers leave out. It does not change which tier a
  check keys on, or what the partitions are.
- **Depends on:** [0221](0221.md) for `bun nv` as the one tool program, [0220](0220.md) for the perf
  currency the `card` tier also decides.
- **Validated by:** `tools/nv/test/keys.test.ts`, which also checks the scanner's card types against the
  registry's.

> **In short:** `tools/nv-scan` is a small Rust program, outside the workspace, that parses a `.rs` file
> with `syn` and prints one digest per tier. `bun nv` builds it when its sources change and runs it once
> for every batch of files. It replaces a lexer written with regular expressions. The `shipped` tier
> now leaves out any item, impl or trait member or statement whose `#[cfg(...)]` is false without
> `test`. The `card` tier leaves out every constant of a card type, reads `doc: Some(&CARD)` as
> `doc: None` when `CARD` is such a constant of the same file, and leaves card types out of `use`
> lists.

## Context

A session that gave `Core\Math` its class card changed three lines of code in `math.rs`: the new
constant's declaration, `ClassDoc` in a `use` list, and `doc: None` becoming `doc: Some(&CARD)`. The
`card` tier blanked only a card constant's initialiser, so those three lines moved the digest of
`nvs-stdlib`, and with it the key of every check that runs the `nvs` binary. The acceptance sweep that
followed ran nearly the whole floor, although nothing a program can do had changed.

## Investigation

Put back those three lines, and the same file, with ninety other lines of card text and tests changed,
kept its old `card` digest. The digest moved on the class-card link alone. Making the regular
expressions follow a `doc:` field and a `use` list would have added the kind of matching that is
already the tier's weak point. A wrong match there does not fail loudly. It gives two different
programs one key, and a check that should run is skipped.

## Options considered

1. More regular expressions over the lexed text.
2. A parser: `syn`, the one every Rust tool uses, already in the workspace's lock file.

## Decision

Option 2. Each tier is read off `syn`'s tree and hashed from the tokens it prints back, tagged and
length-prefixed. The card types are listed by name, and a test holds that list equal to the registry's
`pub struct *Doc` set. A file `syn` cannot parse is its text in every tier. The lexer stays only in
`keys/escape.ts`, which judges whether a test binary reads outside its package, and is not a tier.

## Consequences

- A first scan of the tree costs about three seconds, and the memo keeps later runs to the files that
  changed. Building the scanner costs a release build of `syn` once per change to its sources.
- Every key and every perf record's `impl_hash` changed once. The ledger was carried over: a record
  current under the old digest was given the new digest of the same file, and a stale one was left
  alone, so no record changed whether it is current.
- Only what prints a card reads whether a class has one, and those checks key on `shipped`.

## Revisiting

If a check that keys on `card` ever prints a card, the tier's premise is wrong for that check, and it
keys on `shipped` instead.
