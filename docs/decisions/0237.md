# ADR 0237 — `$x as Shape` tests the shape's fields the way `$x is Shape` does, and throws where the test fails

- **Scope:** `as` into a shape target, from any operand `is` gives a run-time answer for. `as ?Shape`,
  the nullable form, is left as it is.
- **Depends on:** [0036](0036.md) (shape types), [0150](0150.md) (`is` and its shape walk),
  [0236](0236.md) (an existing `int` field does not satisfy a `float` one).
- **Validated by:** `tests/conformance/lang/an-as-conversion-to-a-shape-tests-its-fields-and-throws-where-is-answers-false.nvst`
  and `tests/conformance/reject/an-as-conversion-to-a-shape-no-value-of-the-operand-could-satisfy-does-not-compile.nvst`.

> **In short:** `$x as Shape` is a checked conversion. It runs the field walk `$x is Shape` runs: the
> value must be an object, and every field the shape names must be there at the named type. Where the
> walk holds, the result is the value at the shape; where it fails, `as` throws the `RuntimeError` a
> failed `as ClassName` throws, with a message naming the shape by its fields. An operand that already
> satisfies the shape at compile time is the free row it was. An operand that can hold no object is
> `E0708`, and a shape whose fields carry a `tainted` or `secret` qualifier keeps `E0711`.

## Context

`$x is {top: float, left: float}` already answered at run time by walking the object's fields by name.
`$x as` the same shape was `E0711`: a shape names no class, so the conversion had no descriptor to
test against, and the refusal's help told the reader to name a class instead. A function taking
`float|Pad` therefore had no way to get a `Pad` out of the union except an `is` guard around a second
binding, while the same function taking `float|Box` could write `$p as Box`.

An operand already typed as an object was the free row for every target the refusal covered,
shapes included. `Whole $w; $w as {w: float}` over a class whose `$w` is an `int` was accepted and
ran nothing. It handed an object whose `w` is an `int` to code that reads `w` as a `float`, which is
the mismatch [0236](0236.md) refuses at compile time.

## Decision

### 1. The test is the `is` walk

A shape target is a checked conversion. The test is exactly the walk `rule:types/type-test`'s shape
row lowers: the object tag first, then one presence probe and one tagged read per field the shape
names, each field held to its own row. No second walk exists. An `int` field fails a `float` one,
because the walk compares the tag the slot holds, which is the [0236](0236.md) rule at run time.

### 2. Which operands take the test

The test runs wherever `is` would give a run-time answer: `mixed`, `object`, a `?Shape`, a union
containing the shape or an object type, and a class whose fields do not statically satisfy the shape.
An operand that `is` would fold to `true` converts for free. An operand that `is` would fold to
`false` shares no value with the shape and is `E0708`, the refusal a class target gets for the same
pair.

### 3. What the failure throws

A failed test throws `RuntimeError` with `cannot convert a value of another type to `{left: float,
top: float}``, the class and the message form a failed `as ClassName` uses. The shape is named by its
fields, because an alias is a name for the type and not a part of it.

### 4. A field typed `mixed`

A shape field typed `mixed` passes whenever the key is there. `is` had no row for it and stopped the
compiler, and `as` reaches the same walk, so both are fixed together.

## Diagnostics

`E0711` keeps `object`, `callable`, a `Core` namespace class and a shape with a qualified field, and its
help and card now name a shape as one of the checked ways out of `mixed`. A shape from an operand that
holds no object is `E0708` with a help line of its own.

## Consequences

Performance: one field walk per conversion that needs one, the same O(fields) cost `is` pays, and
nothing allocated. Memory: none. Usability: `as` works for shapes the way it does for classes. Simplicity:
one more row in `rule:types/conversion`, and no new mechanism. A class-typed operand that does not
satisfy the shape now runs the walk where it ran nothing before, which is the soundness fix
§ *Context* describes.

## Verification

The `lang` case asserts agreement: over six values, `as` succeeds exactly where `is` answers `true`.
It also pins the `int`-into-`float` field failing for an object literal and for a class instance.
`crates/nvs-types/tests/classes.rs`'s
`a_shape_target_records_its_field_walk_only_where_the_operand_needs_one` pins which operands record
the walk.
