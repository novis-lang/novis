# ADR 0090 — `==` is the only equality operator, and comparing two disjoint types does not compile

- **Scope:** the spelling of equality and inequality; what equality *means* for every Novis type, including
  the three PHP compares two ways (strings, arrays, objects); what happens when the two operands' static
  types cannot both hold the same value; what a `mixed` or union operand does at runtime; and the
  comparison `switch` and `match` arms perform. Not in scope: ordering `< <= > >= <=>`, which
  [0013](0013.md) owns and this ADR does not touch; truthiness, which
  [0035](0035.md) owns; converting between types, which is `as`
  ([0034](0034.md), [0066](0066.md)); and the
  natural ordering `Arr::sort`/`Math::min` use, which `crates/nvs-stdlib/src/ordering.rs` owns.

> **In short:** Novis has **one** equality operator, `==`, and its negation `!=`. `===` and `!==` do not
> parse. There is nothing for a second spelling to distinguish, because Novis has no loose comparison to
> escape from: `==` never converts either operand, and the two operands must have types that can both hold
> the same value — `"1" == 1` is a **compile error**, not `true` and not `false`. Where PHP's two
> operators genuinely disagreed at the same type, Novis takes the strict answer in each case: two strings
> compare as text and never as numbers (`"1" == "01"` is false), two arrays compare element by element in
> order, and two objects compare by **identity**. Comparing content rather than identity is a named
> method, never an operator — there is no `__equals` hook, for the reason
> [0014](0014.md) and [0028](0028.md) give for every
> other magic method. A `mixed` or union operand is the one case resolved at runtime, and there a
> mismatched runtime type is `false` rather than a throw.

## Context

- **PHP has two operators because it has juggling.** `===` exists to escape `==`, and `==` exists because
  PHP 4 had no types. Novis has neither problem: `rule:types/declaration` makes every
  binding declare a type, and `rule:types/no-legacy-cast` makes `as` the only
  conversion spelling. Carrying both operators forward would carry the scar without the wound.
- **This repository already refuses redundant spellings on exactly this reasoning.**
  `rule:expressions/no-keyword-logical-operators` deleted `and`/`or`/`xor` because `&&`/`||`
  already say it; `rule:expressions/bracket-destructuring` deleted `list(…)`;
  `rule:statements/nvs-is-the-only-open-tag` refuses a second open tag and a second
  termination keyword; `rule:statements/nothing-gets-a-second-name` is the general rule. Two operators that
  compile to one instruction is the same finding.
- **Loose comparison is already named as a hazard by two security ADRs.**
  [0060](0060.md) § 4 requires verification to return claims or throw,
  precisely so no falsy value can pass a loose test, and [0056](0056.md) § 1 cites
  `preg_match`'s return for the same reason. Priority 1 is not traded, and the cheapest way to close a
  hazard family is to remove the construct that carries it.
- **The standard library already chose strict, twice, before this ADR existed.**
  `Arr::contains` is always strict where `in_array` defaulted to loose, and `Arr::min`/`max` go through a
  natural ordering that *throws* on a cross-tag pair rather than coercing
  (`crates/nvs-stdlib/src/ordering.rs`). Leaving the operator undecided while the library decided for
  itself is the two-homes-for-one-fact bug AGENTS.md exists to prevent.
- **The compiler had already collapsed them by accident.** `nvs-ir` lowers `==` and `===` to the same
  instruction, its own comment noting the collapse holds only while no non-scalar operand exists. That is
  a gap waiting to be filled with a decision, not a decision.

## Decision

### 1. `===` and `!==` do not parse

The lexer does not produce them. A source file containing either is a **hard compile error** whose
diagnostic names the fix — delete the third character — in the shape
[0034](0034.md) and [0045](0045.md)
already use for a rejected PHP spelling. There is no suppression and no dialect flag, for the reason
[0029](0029.md) gives: a construct that parses in one project and not another
is two languages.

`==` and `!=` are the whole set. `!=` is exactly `!( … == … )`; there is no third relation. PHP's `<>` is that
same relation under a second spelling, and it does not parse either — the diagnostic names `!=`.

### 2. Both operands must have types that can hold the same value

A comparison whose two static types are **disjoint** — no single value inhabits both — is a compile error,
because the compiler already knows the answer and the author did not mean to write it.

```
string $s = "1";
int $n = 1;
if ($s == $n) { }        // E0xxx: `string` and `int` are disjoint; this comparison is always false
if ($s == ($n as string)) { }   // convert once, deliberately, then compare
```

Disjointness, not identity of types, is the test — so every shape that ordinary code writes still compiles:

| the two operands' static types | verdict |
|---|---|
| the same type | compares |
| `int`, `uint`, `float`, `decimal` in any pairing | compares — **the numeric types are one domain**, mathematically exact over the full range of both, which is [0007](0007.md) § 4's and [0054](0054.md) § 3's existing rows unchanged |
| `?T` against `null`, or `?T` against `T` | compares — this is the null test, and it narrows ([0007](0007.md) § 6) |
| a union against any type one of its members can hold | compares, and narrows on the branch where it held |
| a literal or enum-case type against its base type ([0047](0047.md)) | compares |
| `mixed` against anything | compares — see *5* |
| a class against the same class or an ancestor of it | compares |
| a non-nullable type against `null` | **compile error** — the diagnostic says the type cannot hold `null`, so the test is always false |
| `string` against `bytes` | **compile error** — [0009](0009.md) makes these different types on purpose; convert one side |
| an enum against its underlying integer | **compile error** — write `$e as int`, which is what [0010](0010.md) § 3 already makes cheap |
| two unrelated classes | **compile error** — no instance is both |
| anything else disjoint | **compile error** |

This is the rule Rust and Go apply, and the one PHP could not: it turns the entire class of comparisons
that silently answered `false` — or, worse, silently answered `true` in PHP 7 and `false` in PHP 8 — into
a diagnostic at the site that wrote it.

### 3. What equality means, one row per type

Nothing here converts. Each row is the strict reading; where PHP's two operators disagreed, the column
names which one Novis took.

| type | two values are equal when | note |
|---|---|---|
| `null` | always | one value |
| `bool` | the same | |
| `int`, `uint`, `float`, `decimal` | mathematically equal across the whole domain | `1 == 1.0` is true; `decimal` ignores scale, so `1.10 == 1.1000` is true ([0054](0054.md) § 5) |
| `float` edge cases | IEEE 754: `NAN == NAN` is **false**, `0.0 == -0.0` is **true** | the natural *ordering* uses `total_cmp` instead and says why; the two questions are separate |
| `string` | the same sequence of Unicode scalar values | **PHP's `===`.** Never numeric — `"1" == "01"` and `"1e3" == "1000"` are both false. No normalization either: two strings that render identically but differ in code points are not equal, and `Core\Str` owns the member that normalizes |
| `bytes` | the same bytes | |
| `array<T>` | the same length, the same keys in the same order, and every value equal by this table, recursively | **PHP's `===`.** [0007](0007.md) § 5 keeps the ordered hash and iteration order is observable, so order is part of the value |
| class instance | **the same object** | **PHP's `===`.** See *4* |
| enum case | the underlying integers are equal ([0010](0010.md) § 5) | |
| `callable` | the same closure | closures are values ([0031](0031.md)); two `fn` literals with identical bodies are two closures |
| `mixed`, a union | resolved at runtime — see *5* | |

The recursion in the array row terminates because an Novis array cannot contain itself: an array is a
copy-on-write value, not a reference, so there is no cycle to walk. An array holding **objects** compares
those objects by identity per the class row, which bounds that walk too.

### 4. Objects compare by identity; content comparison is a method

`$a == $b` on two class instances asks whether they are the same object. It never walks properties.

That is the same refusal `rule:classes/comparable` makes for ordering, for the same reason
stated there: an ambient, undeclared property walk has unbounded cost in the object graph's size and no
way for a class to opt out. It is also why there is **no `__equals`, no `equals()` protocol and no
`Equatable` interface** — a per-class equality hook would make `==` mean something different in every file,
which is exactly the property [0014](0014.md) and
[0028](0028.md) removed from every other magic method.

Two named ways to ask the other question, both of which already exist:

- **`$a->compareTo($b) == 0`**, when the class implements `Comparable` ([0013](0013.md)).
  A class that has a meaningful notion of "same value" almost always has a meaningful order too, and this
  gets both from one declaration.
- **`Core\Test::assertEqualsDeep`** in a test, which walks properties, arrays and shapes and produces a
  diff ([0079](0079.md) § 4). It is a test member on purpose: a structural
  walk is a debugging affordance, not something a request path should reach for by accident.

A class needing content equality in production and not wanting an order writes an ordinary named method.
That reads worse than `==` by exactly one call, and it is visible at the call site, which is the point.

### 5. A `mixed` or union operand resolves at runtime, and a mismatch is `false`

`rule:types/unions-and-mixed` makes `mixed` unchecked by design — every operation on it is
allowed and resolved dynamically. Equality is no exception: `$a == $b` where either side is `mixed` or a
union compiles, dispatches on the runtime tags, and applies *3*'s table to the row they land in.

**When the two runtime tags belong to different rows, the answer is `false`.** It does not throw, and it
does not convert.

That is not a second, looser rule sneaking back in. `false` *is* the strict answer — a `string` and an
`int` are not the same value — and it is what Python, Rust and JavaScript's `===` all say. The static case
in *2* is a compile error rather than `false` for a different reason: there the compiler can prove the
answer before the program runs, which makes it dead code rather than a question.

The asymmetry is deliberate and worth stating plainly: **`mixed` is where you pay for not declaring a
type**, here as everywhere else in `rule:types/declaration`. A comparison against `mixed` silently answers `false` where a
typed one would have refused to compile.

### 6. `switch` and `match` use this rule, and only this rule

PHP's `switch` compared loosely and its `match` compared identically. With one operator there is one
comparison: a label or arm is compared against the subject by *3*'s table, and a label whose type is
disjoint from the subject's is *2*'s compile error. `match (true) { … }` is unchanged — each arm is a
`bool`, tested against `true`.

### 7. Porting

`tooling/convert-one-table-two-modes`'s `==` rule keeps its destination spelling
and re-tiers against this table:

- **Tier E** — both operands proven the same non-`string` scalar type, or proven numeric. PHP's two
  operators agreed there, and so does Novis's one.
- **Tier D** — two `string` operands. PHP's `==` compared two numeric strings *numerically*; Novis's
  compares them as text. The rewrite compiles and answers differently on numeric-string input, which is
  exactly a `TODO(convert:…)` and not a blocker.
- **Tier D** — two arrays (PHP's `==` ignored key order) or two objects (PHP's `==` walked properties).
  The `TODO` names which reading Novis took.
- **Not emitted as code** — a cross-type comparison, which is *2*'s compile error. The converter emits the
  commented-out original plus the idiomatic shape, `$id == ($raw as int)`. This is the branch that most
  earns the treatment: it is where PHP 8.0 itself changed the answer, so the original source was already
  ambiguous about which language it was written for.

## Consequences

**Positive**

- **One operator, one meaning.** Nothing to remember, nothing to review for, and no reader has to work out
  which of two nearly identical spellings a line used.
- **A whole bug family becomes a diagnostic.** `$row['id'] == 1` against a string column, `$s == 0`
  against a non-numeric string, `strpos(…) == false` — each is now either a compile error or the strict
  answer, at the site that wrote it. [0067](0067.md) § 8's driver-returns-strings hazard and
  [0063](0063.md) R5's absence-is-`?T` rule both stop depending on the reader's care.
- **The compiler gets simpler, not more complex.** One `BinaryOp`, one lowering path, one narrowing
  spelling. `nvs_types::locals` currently narrows on `===`/`!==` while explicitly refusing to read
  anything from `==`; that carve-out disappears.
- **`==` is what every language without juggling spells it** — C, Java, Go, Rust, Python. The one
  operator Novis keeps is the one a reader arriving from anywhere but PHP already knows.

**Negative**

- **`==` is in every line of real PHP, and some of it meant something we deleted.** This is the largest
  single porting cost of any rejected-spelling ADR, larger than `(int)$x` or `and`/`or`, simply by
  frequency. § 7 is why it is survivable: the dangerous branch does not compile, and the two divergent
  branches are annotated rather than silent.
- **The numeric-string row is the one that ports silently.** `"1" == "01"` was true in PHP and is false
  here, and nothing in the compiled program flags it — only the converter does. It is named here so that
  the converter's rule table is the thing kept honest.
- **A `mixed` comparison answers where a typed one refuses.** Someone will discover that widening a
  parameter to `mixed` makes a diagnostic go away, and get `false` instead of a fix. This is `rule:types/declaration`'s
  standing trade rather than a new one, but equality is where it is easiest to reach for by accident.
- **Object identity will surprise someone porting a value class.** PHP's `==` compared two `Money`
  objects by their properties; Novis's says they are different objects. § 4's answer costs one method call
  and a `Comparable` declaration.
- **`$x == null` on a non-nullable type is now an error rather than a folded constant.** Defensive
  null checks copied from PHP stop compiling. That is the intended reading — the check was always dead —
  but it is a diagnostic per site, not a global rewrite.

## Alternatives rejected

- **Keep both operators with PHP's semantics.** Rejected on priority 1: it reintroduces the hazard family
  two security ADRs already work around, and on [0015](0015.md), since with Novis's type
  system the two spellings agree everywhere except three rows nobody would choose the loose reading for.
- **Keep both, with `==` defined as strict — two spellings for one operation.** Rejected on
  [0045](0045.md)'s exact reasoning. Worse than either alternative:
  a PHP reader seeing `==` would assume juggling that is not there, so the familiar spelling would be
  actively misleading.
- **Keep `===` and drop `==` instead.** The safer-looking spelling, and rejected anyway: `===` exists in
  PHP and JavaScript *only* as an escape from `==`. With nothing to escape, it is three characters saying
  what two say everywhere else, and every reader arriving from a language without juggling would have to
  learn a local dialect for no gain.
- **Make a statically disjoint comparison `false` rather than an error**, matching the runtime rule in *5*.
  Rejected: the compiler can prove it, and code whose answer is knowable at compile time is a mistake
  worth naming. This is the same argument [0022](0022.md) makes for
  definite assignment.
- **Structural object equality, PHP's `==` reading.** Rejected on [0013](0013.md)'s
  reasoning, which this ADR does not want to re-litigate for a second operator: unbounded cost in the
  graph's size, ambient and undeclarable, and no way to opt out.
- **An `Equatable` interface or an `__equals` hook.** Rejected: it makes `==` mean something different per
  class, which is the property removed from every magic method by
  [0028](0028.md). § 4's two named spellings cover the need without
  changing what an operator does.
- **A separate identity operator for objects, so `==` could be structural.** Rejected as the two-operator
  problem in a new costume, and unnecessary: identity is the reading a reference type wants by default,
  and content comparison is the one that benefits from being visible.

## Revisiting

- **A named content-equality member in `Core`**, if § 4's `compareTo(…) == 0` turns out to be what every
  value class writes. It would be a member under [0063](0063.md)'s conventions, not
  an operator and not an interface, and the evidence for it is repetition in real programs rather than
  argument.
- **Whether `mixed == mixed` should throw** on a cross-row pair rather than answering `false`, matching
  what `crates/nvs-stdlib/src/ordering.rs` already does for `Arr::min`. Deliberately not taken now, because
  ordering has no correct answer for a mismatched pair while equality does; revisit if the silent `false`
  in *5* turns out to hide real bugs.

## Verification

- **Grammar.** A fixture per rejected spelling — `$a === $b` and `$a !== $b` — each a compile error whose
  message names `==`/`!=`. `crates/nvs-syntax`'s corpus parse over the local `php-src` checkout will now
  report these as errors rather than parsing them, which is itself the check that the lexer rule fires.
- **Disjointness.** One `.nvst` case per error row in *2*'s table, and one per compiling row, asserting the
  diagnostic code in the first set and the answer in the second. The `?T`-against-`null` row must still
  narrow, which `crates/nvs-types/tests` already covers under the old spelling.
- **The table in *3*.** A conformance fixture per row, with the three PHP-divergent rows written as
  explicit non-equalities: `"1" == "01"` is false, two arrays differing only in key order are not equal,
  and two distinct instances with identical properties are not equal. The differential leg is expected to
  **disagree** with the PHP oracle on exactly those three, which is what pins them.
- **The runtime path.** A `mixed`-against-`mixed` fixture per tag pairing, asserting `false` across rows
  and never a throw — the one place a wrong answer would be silent.
- **Nothing to measure.** No number here needs a guard test in `benches/abi-probe`: the typed path is the
  instruction it already was, and the `mixed` path is the tag dispatch `rule:types/unions-and-mixed` already priced.
