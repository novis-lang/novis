# ADR 0149 — Writing a `///` run is the editor's job: the configuration continues one, and a paste provider prefixes one

- **Scope:** the editor affordances for *writing* a doc comment in Novis source, and which of them
  contribute a frozen name. Not in scope: what marks a doc comment and what may appear inside one, which
  is [0137](0137.md) and is unchanged; the rest of `language-configuration.json`, which is
  [0099](0099.md).
- **Depends on:** [0137](0137.md), [0099](0099.md)

> **In short:** the one real cost of [0137](0137.md)'s line-oriented doc comment is that a multi-line one
> is typed `///` by `///`, and **both halves of that cost belong to the editor rather than to the
> grammar**. `language-configuration.json`'s `onEnterRules` continues a `///` run on Enter — the entry
> there today continues a `/** */` block, which is a PHP inheritance and documents nothing in Novis — and
> pasting multi-line text into a run is a `DocumentPasteEditProvider` offering *Paste as doc comment*,
> which prefixes each line. **Neither contributes a setting or a command id**, so
> `rule:ide/contributions-are-frozen-and-only-ever-added`'s roster and its test do not move.

## Context

- [0137](0137.md) § 1 makes a doc comment a run of line comments, and the per-line marker is the whole
  reason nothing inside the body can end it. That property is what a block form spends, and it is worth
  more than the four characters it costs.
- What it costs is *authoring*. A multi-paragraph doc comment is typed one `///` at a time, and pasting a
  Markdown table or a fenced block means prefixing every line by hand. VS Code's toggle-line-comment
  inserts `//`, not `///`, so the built-in shortcut does not answer either; multi-cursor is the current
  answer and it is the reason the objection keeps being raised.
- `rule:ide/language-configuration-is-content` promises `onEnterRules` continuing a `/** */` block. In
  Novis `/* */` is an ordinary comment and `/** */` documents nothing ([0137](0137.md) § 1), so that entry
  continues a comment nobody writes while leaving the one that is written uncontinued. It is a fragment
  borrowed from a PHP extension in the same way the `wordPattern` was, and it is wrong for the same
  reason.

## Options considered

1. **Change the language** — give the doc comment a block form so the prefix is written once. Rejected
   below, and it is the reason this record exists rather than an amendment to [0137](0137.md).
2. **Leave it** — `///` per line, multi-cursor for a paste. Honest, and what happens by default, but it
   leaves a rule fragment stating something untrue about `onEnterRules`.
3. **Answer it in the editor.** Taken: two affordances, no grammar change, no frozen name.

## Decision

### 1. `onEnterRules` continues a `///` run

Enter on a line whose text opens with `///` starts the next line with `///` at the same indentation. This
replaces the `/** */` entry rather than joining it — a block comment in Novis is trivia nothing reads, so
continuing one is a courtesy to a shape the language does not use.

The run continues until the author deletes the inserted marker, which is what Rust and C# do and what a
reader arriving from either already expects. No rule tries to guess where a doc comment ends.

### 2. Pasting is a paste provider, not a command

A `DocumentPasteEditProvider` registered for `nvs` offers **Paste as doc comment** when multi-line text is
pasted with the cursor in a `///` run: every line takes the run's own indentation and marker, and an empty
line becomes a bare `///`. The ordinary paste is unchanged and the alternative costs one keystroke in VS
Code's own paste widget.

That widget is why this is not a command. `rule:ide/the-extension-builds-no-ui-the-editor-already-has`
applies directly: the editor already surfaces paste alternatives, so no command, keybinding or menu item
is added to surface this one. Prefixing lines with a marker is also not language logic — no parse, no type
table — so `rule:ide/dependencies-are-allowlisted`'s allowlist is unchanged.

### 3. The frozen roster does not move

Neither affordance contributes a setting or a command, so
`rule:ide/contributions-are-frozen-and-only-ever-added`'s roster is unchanged and its contributions test
still asserts the same list. The one identifier created here is the paste edit's **kind id**, which
reaches a user's `editor.pasteAs.preferences` and is therefore public API on that rule's own terms:
frozen on first contribution, added to, never renamed.

## Consequences

**Positive**

- **The standing objection to `///` is answered where answering it is free.** The grammar does not move,
  so nothing [0137](0137.md) verified moves either — no lexer change, no output change, no `.nvst` case
  affected.
- **A wrong fragment becomes right.** `onEnterRules` continuing `/** */` was a promise to continue a
  comment Novis does not document with.
- **No new frozen name**, so the roster, its test and every user's `settings.json` are untouched.

**Negative**

- **Each client owns its own copy.** `rule:ide/one-server-two-thin-clients` puts editing affordances in
  the client, not the server, so the PhpStorm plugin gets neither of these for free and either writes both
  again or goes without. That is the standing cost of a thin-client design, charged here for the first
  time on an editing feature.
- **The continuation over-runs.** An `onEnterRules` marker keeps arriving until the author deletes it,
  which is the familiar nuisance in every `///` language and is not worth a heuristic that guesses wrong
  in the other direction.
- **The paste provider's output is unchecked.** It is client-side text manipulation with no server
  round-trip, so nothing validates that the result reads well — though prefixing cannot produce anything
  that is not a comment, so the worst case is a badly worded one.
- Memory and latency: none. Both affordances are editor-side and touch no compile and no request path.

## Alternatives rejected

- **A `///`-delimited block — `///` alone opening, an un-prefixed body, `///` alone closing.** Two
  delimiter lines to save a four-character prefix, and they spend the property that makes the line form
  safe. The terminator is a bare `///` line, which is exactly what a code sample of a documented member
  contains, so a doc comment could never show one — and the only fix is a lexer that tracks Markdown
  fences to find where a comment ends, which puts the body's grammar inside the language's. It also makes
  the body's indentation content: four leading spaces are a CommonMark code block, so the renderer must
  dedent, while `rule:tooling/fmt-quotes` forbids the formatter from ever re-aligning a comment. An
  unterminated block turns the rest of the file into prose where the line form costs one line.
- **`/** */`, the PHPDoc shape.** [0137](0137.md)'s own rejection stands, and the lexer adds a second
  reason: block comments do not nest and end at the first `*/`, so a glob or a regex in a Markdown body
  would terminate the comment.
- **A command and a keybinding**, `nvs.pasteAsDocComment`. Adds a frozen id and a key to learn for
  something the paste widget already offers on the ordinary paste.
- **A snippet that expands to a doc comment.**
  `rule:ide/a-code-action-writes-only-what-is-already-determined` refuses snippets, and the reason
  transfers unchanged: a snippet body is a second copy of a syntactic shape.
- **Making `nvs fmt` insert the prefix.** `rule:tooling/fmt-quotes` leaves every comment byte-for-byte
  untouched, and a formatter cannot know which un-prefixed lines were meant to be documentation.

## Revisiting

- **An authoring aid that needs to understand the prose** — reflowing a doc comment's Markdown, say, or
  renumbering a list in one — is the first thing in this area that would want language logic in the
  client, and `rule:ide/dependencies-are-allowlisted` is what it would have to answer. Nothing needs it.

## Verification

- **The contributions test is unchanged** — `package.json` declares the same settings and commands as
  before, which is the claim that makes this record additive.
- **The configuration entry is asserted headlessly**, with the rest of `language-configuration.json`:
  Enter after a `///` line continues the run, and after a `//`, `#` or `/* */` line it does not.
- **The paste edit is asserted in the extension-host run**, which is where
  `rule:ide/headless-gates-the-loop-the-host-run-gates-the-milestone` puts an interaction that needs a
  real editor: multi-line text pasted into a `///` run comes back prefixed at the run's indentation, with
  an empty line as a bare `///`, and the ordinary paste is unaffected.
