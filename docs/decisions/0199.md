# ADR 0199 — A match answers its route's access decision and its verb, and its captures stay one union

- **Scope:** what `Core\Router\Match` lets a program read. Who dispatches, what the server enforces and
  what a match may never carry are [0102](0102.md)'s and [0077](0077.md)'s and unchanged.
- **Depends on:** [0102](0102.md), [0077](0077.md).
- **Validated by:** `tests/conformance/core/one-access-check-above-the-dispatch-switch-covers-every-route.nvst`,
  `tests/conformance/core/a-match-answers-the-access-decision-as-the-name-its-route-resolved.nvst`,
  `tests/conformance/core/a-match-answers-the-verb-that-matched-where-one-method-serves-two.nvst`, and
  `a_match_crosses_its_verb_and_its_access_decision_and_a_missing_one_is_null` in
  `crates/nvs-stdlib/src/router.rs`.

> **In short:** the rule said a match carries `name`, `params`, `method` and `access`, with `params` a
> shape typed per route; the class shipped with `name()`, `params()` and `param()`, the captures as one
> union, and a comment saying the verb and the access decision stay off it on purpose. The class gains
> `method()` and `access()`, because a dispatcher that cannot read the decision off the match has to read
> it once per `switch` arm and an arm that forgets is an unguarded route. The captures stay the union,
> and the rule now says so.

## Context

A user's report asked the server to call the matched route method. That is declined by
[0102](0102.md) and stays declined, and the answer to the report is a `switch` the program writes until
`nvs/web` generates it. Writing that `switch` against the shipped class showed the disagreement above.

`rule:security/access-is-checked-for-presence-not-meaning` says the declared name "rides on the match
the server made", and that the application's own dispatch reads and enforces it. Nothing on the class
answered it. The one way left was `Core\Attributes::get<{allow: …}>(Users::show(...))`, which needs the
method named and so can only be written inside the arm that already knows which route matched.

## Options considered

1. **Add `access()` and `method()`, keep the captures as the union.** Chosen.
2. **Build the rule as written**, including `params` as a shape narrowed by a comparison on `name`. That
   is a discriminated narrowing the checker does not have, for a cast the union already lets a program
   write in one word, and `nvs/web`'s generated `switch` binds typed parameters without it.
3. **Make the rule match the class** and leave the decision readable through `Core\Attributes::get`.
   One check per arm is how a route ends up unguarded by omission, and nothing reports the omission:
   the compiler guarantees the decision was written, never that it was read.

## Decision

### 1. `Core\Router\Match::access(): ?string`

The resolved name of the constant the route's `#[Access(allow: …)]` wrote — `Core\Audience::Public`,
`App\Role::Admin` — which is the whole of what the compiled row carries. It is a plain `string`,
because it is the unit's own text. `null` is reachable only from a table built by hand, since a route
with no decision does not compile, and a dispatcher reads `null` as denied.

A name and not the constant's value: the compiler checks that the name resolves and promises nothing
about what it means, so the name is the one thing it can answer without interpreting.

### 2. `Core\Router\Match::method(): Core\Http\Method`

The verb the matched row declares. Two `#[Route]`s on one method may share a `name` when they share a
path, so the name does not tell a `Get` match from a `Post` match and the verb does.

### 3. The captures stay `tainted string|int|uint|decimal|Core\Uuid|Parses`

`params()` and `param()` are unchanged. A value the matcher converted is already that type at run time,
and the program states which with `as`.

### 4. The handler label still does not cross

`Class::method` is the one field of the row a program could turn into a call.

## Consequences

- A dispatcher checks access once, above its `switch`, and the check covers a route added later whose
  arm never mentions access.
- **Spends**, per read of `Core\Request::route()` or `Core\Router::match`: one `string` the length of
  the decision's name, and one integer. O(in-flight), and nothing for a program that never reads a match.
- The access comparison is against text, so a renamed enum case breaks it silently. `nvs/web`'s
  `Web\Auth` is where that comparison is written once.

## Verification

The three cases and the unit test above. `Core\Router\Match::access` printed `Core\Audience::Public`,
`App\Role::Admin` and `App\Policy::STAFF` for the three spellings `rule:attributes/access-payload`
admits, and the constant's value did not cross.
