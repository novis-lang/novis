# ADR 0249 — `Core\Path::thisFile` and `thisDir` are folded while compiling to the file that wrote the call, and `thisDir` joins only a relative literal

- **Scope:** Two `Core\Path` members that name the source file containing the call and its folder,
  how the checker folds them, and what `thisDir`'s join accepts. How a path literal at a path
  parameter resolves is unchanged.
- **Depends on:** [0241](0241.md) (a relative path literal resolves from the file that wrote it, and
  a `__DIR__` constant was rejected), [0021](0021.md) (`require` resolves against the requiring
  file).
- **Validated by:** the Stage 5 checks of goal `path-literals-follow-up`: `nvs-types`' tests in
  `crates/nvs-types/tests/paths.rs`, `nvs-ir`'s `this_file_and_this_dir_lower_to_a_string_constant`,
  and the two `.nvst` cases named under *Verification*.

> **In short:** `Core\Path::thisFile()` is the absolute path of the source file that contains the
> call, and `Core\Path::thisDir(?string $join = null)` is its folder, with a relative literal
> `$join` added. The checker replaces each call with that path while compiling, from the same folder
> a path literal is joined to, so a bundle answers the folder beside the executable. The program
> runs a string constant and no call. A `$join` that is not a relative string literal does not
> compile (`E0837`), and the help names `Core\Path::join`. Magic constants stay `E0319`.

## Context

[0241](0241.md) made a relative literal at a path parameter resolve from the file that wrote it, so
`Core\IO::read('data/x.json')` needs no folder written in front of it. A program still wants the
folder as a value in three places that are not a path parameter: to build a path from parts it
computes (`Core\Path::join($dir, $name)`), to hand a folder to a library, and to print where it
runs from. Before this, the only way to get the folder was `Core\Path::dirname` of a path literal
passed through a `#[Core\Path]` parameter of the program's own.

## Decision

### 1. Two members, and their answers

`thisFile(): string` is the absolute path of the file that contains the call. `thisDir(?string $join
= null): string` is that file's folder, and with `$join` the folder joined to it, with `.` and `..`
removed. The folder is `nvs_types::paths`' `base_dir`, the one a path literal is joined to, so the
two never disagree, and a file reached through `require` names itself and not the entry file.

### 2. Folded while compiling

`nvs_types::paths::fold_this` records the answer under the call's span in the table a path literal
uses (`ExprTypeTable::path_literal`), and `nvs-ir` lowers the call to a string constant. The
registry rows keep a symbol each, reached only by a source handed to the compiler as text, which
has no file; the symbol throws a `RuntimeError` that says so.

### 3. `$join` is a relative string literal

The join happens while compiling, so its argument must be known then. A variable, a constant, a
concatenation, an empty string and an absolute path do not compile. A literal `null` is the same as
no argument. A path the program builds keeps `Core\Path::join(Core\Path::thisDir(), $part)`, which
the diagnostic names, so the fold never falls back to a run-time call quietly.

### 4. Why this is not 0241's rejected `__DIR__`

0241 rejected a `__DIR__` constant because every call site would have had to write the join, and a
forgotten one would still have resolved against the working directory. Neither holds here. A path
parameter still resolves its literal from its file, so `Core\IO::read('data/x.json')` needs no
`thisDir`. `thisDir` is written only where a program wants the folder as a value, and a relative
path it builds from that value is absolute already. Nothing resolves against the working directory
implicitly, with or without these members.

### 5. Tradeoffs

- **Performance:** nothing on the request path. Each call is one join while compiling, and a string
  constant at run time.
- **Memory:** nothing. The constant is the same instruction a string literal lowers to.
- **Usability:** a program names its own file and folder the same way from every folder it is
  started in, and a PHP user's `__DIR__` has a direct replacement.
- **Simplicity:** two members and one diagnostic more. No new syntax and no magic constant.

## Diagnostics

- `E0837` `E_PATH_THIS_DIR_JOIN_NOT_A_RELATIVE_LITERAL`: a `$join` that is not a relative string
  literal. The help names `Core\Path::join(Core\Path::thisDir(), $part)`.
- `E0319` for `__FILE__` and `__DIR__` now names the two members in its help.
- Run time: `RuntimeError` from either member in a source with no file.

## Consequences

- A call taken as a first-class callable, `Core\Path::thisDir(...)`, is not folded, and calling the
  closure throws as a source with no file does.
- An editor shows the folded path of a `thisDir` call as a link, as it does for a path literal,
  because both are in the same table.

## Alternatives rejected

- **A `__DIR__` constant.** 0241's reasons, and a magic constant is syntax a `Core` member does not
  need.
- **`thisDir` accepting any string and joining at run time.** It would be `Core\Path::join` under a
  second name, and the call could not be folded.
- **Answering the entry file's folder.** A library could not name a file beside its own code, which
  is 0241's reason for joining to the file that wrote the literal.
