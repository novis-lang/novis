# ADR 0270 — a `readonly` property is written once, by its own constructor through `$this`, so a null test of it narrows a later read

- **Scope:** what `readonly` guarantees, where each half of the guarantee is enforced, and the
  narrowing it buys. Which spellings narrow, and on which edges, stay `rule:types/narrowing`'s.
- **Depends on:** [0038](0038.md), [0192](0192.md).
- **Validated by:** `tests/conformance/reject/readonly-is-written-once.nvst`,
  `tests/conformance/class/an-erased-write-to-a-readonly-property-throws.nvst` and
  `tests/conformance/class/a-null-test-narrows-a-readonly-property.nvst`.

> **In short:** a `readonly` property is written by its class's own constructor, through `$this`, at
> most once on each path, and never in a loop or through a hook. The checker refuses every other write
> it can see (E0782, E0843); a write through a receiver it cannot see — an erased `object`, or
> `Core\Reflect\ClassInfo::set` — throws a `RuntimeError` at run time. Because the value cannot change
> once construction ends, the four narrowing spellings narrow a path of `readonly` properties, and the
> narrowed read keeps one null check so a write the checker missed is an error rather than a `null`
> read as an object.

## Context

### 1. `readonly` promised write-once and did not hold it

`rule:classes/lateinit-restrictions` described `readonly` as "assigned exactly once, during
construction", but no rule stated it and the checker enforced only part of it: a constructor could
write the property twice, in a loop, or through another instance of its class, and an erased write
reached the slot unchecked. Narrowing a property needs the promise to be true, so it had to be made
true first.

### 2. Programs copy a tested property into a local

`if ($this->node != null) { $this->node->label(); }` did not compile, because the subject of a test
was a binding alone. Every such program wrote `var $n = $this->node;` first, for properties whose
value could never change after construction.

## Decision

### 3. The compile-time half

E0782 refuses a write to a `readonly` property anywhere but the declaring class's `constructor`,
through `$this`. Inside that constructor it also refuses a second write on one path (a promoted
parameter counts as the first), a write inside a loop, and an element write after the property is
written, since that writes the property again. E0843 refuses a `get` or `set` hook on a `readonly`
property, because a hook runs code at every access and the value read would no longer be the value
written.

### 4. The run-time half

A write whose receiver the checker cannot resolve — through `object` or `mixed`, or through
`Core\Reflect\ClassInfo::set` — reaches `write_erased_property` in `nvs-runtime`, which throws a
`RuntimeError` naming the property when the slot is `readonly`. The constructor's own writes and the
graph decoder store slots directly and never come there.

### 5. What it buys

With both halves in place, `rule:types/narrowing` admits a path of `readonly` properties as a subject.
The narrowed read keeps one compare and branch: a write neither half saw throws a `LogicError` naming
the property instead of reading `null` as an object. A narrowed binding keeps no check, because every
write to a binding is visible to the checker.

## Consequences

A constructor that writes a `readonly` property twice, in a loop, or through another instance stops
compiling. Speed: one compare and branch per narrowed property read, replacing the copy into a local.
Memory: none. A mutable property is still never narrowed, and E0459's help on one shows the local copy
and `?->`.

## Alternatives rejected

### 6. Checking write-once only at run time

PHP admits the first write from any method of the class and throws on the second. That makes the
property write-once by bookkeeping, and a test of it could not narrow at compile time, because the
checker could not know whether the first write had happened yet.
