# ADR 0169 — markup is written as a literal whose segments are trusted and whose holes escape

- **Scope:** how a `Core\Html\Markup` is *written* in expression position, and why the terminal carrier
  gets no matching form. It does not touch what the HTML sink escapes with, which is
  [0024 § 5](0024.md)'s and *Revisiting*'s.
- **Depends on:** [0024](0024.md) for the sink and the carrier, [0133](0133.md) for the predicate that
  made `escape` answer one.
- **Validated by** goal `markup-literal`'s acceptance list, which is where this record's *Verification*
  becomes checks.

> **In short:** `Core\Html\Markup` is composed today by lifting a literal with `as Core\Html\Markup`
> and joining with `+`, which is ceremony imposed on the one thing a developer writes most — markup
> is *syntax*, and the carrier made them express it through a value API. So markup gets a literal:
> `` html`<p>hello {$name}</p>` `` is a `Markup` whose segments are trusted because the author wrote
> them and whose `{$…}` holes are escaped and spliced. That is one rule, it is the rule `<?= ?>`
> already follows, and it introduces no way to make a `Markup` out of computed text. Backticks
> delimit it because HTML is full of `"`. `Core\Html::join` composes a list of them. The terminal
> carrier gets no such form and never will, by the predicate in § 6.

## Context

- [0024 § 5](0024.md) makes `echo` under an HTTP request an escaping sink accepting only
  `Core\Html\Markup`, and gives three ways to obtain one: `as Core\Html\Markup` on a source literal,
  `Markup + Markup`, and the sink's own escape-and-lift. [0133](0133.md) added `Core\Html::escape`'s
  answer as a fourth and `Core\Html::sanitize` as a fifth.
- Every one of those is right, and together they price the common case badly. Writing a fragment of
  markup around a value reads:

  ```nvs
  echo ('<span>posted by </span>' as Core\Html\Markup) + Core\Html::escape($row->get("name"));
  ```

  Two constructs and an operator, to say what `<span>posted by </span><?= $name ?>` says with neither.
- **The asymmetry is the diagnosis.** Inline HTML costs nothing because it is *syntactic*: its segments
  are trusted by being source, its holes escape, and no operator appears. Expression position pays
  `as` and `+` for exactly the same two facts, because the carrier is a value and markup is not.
- `Core\Cli\Text` looks like it shares the problem —
  `rule:tooling/styling-is-a-value-not-a-grammar`'s own example is
  `Cli::write(Cli\Text::styled(…) + Cli\Text::plain($path))` — and § 6 shows it does not.
- The `+` is also read as arbitrary by a developer arriving from PHP, where `.` concatenates. The
  operator is correct — `.` answers a `string`, which is what a carrier must not decay to — but that
  is an argument for why `.` cannot work, not for why anyone should be writing an operator here.

## Investigation

- **The escape body is already tuned for this shape.** `Core\Html::escape` scans for the five characters
  and for unterminated bidi controls before allocating, and on the no-escape path — "most of a page",
  in its own words — it takes one more reference to the argument's bytes rather than copying them
  (`crates/nvs-stdlib/src/html.rs:410-446`). What it spends unconditionally is **one object allocation
  per call**, and `as Core\Html\Markup` spends the same on every lift
  (`crates/nvs-stdlib/src/html.rs:483-485`). So today's spelling of the example above allocates twice
  per row of a table.
- **A typed literal folds.** `rule:types/duration-literal` is the precedent: `1h30m` is one token whose
  suffix *is* its type, "folded to a single nanosecond count and emitted into the constant pool, so
  `{timeout: 30s}` allocates nothing at run time". A hole-free markup literal is the same shape, and it
  replaces a per-execution allocation with a constant.
- **The sink's lowering already branches on static type.** `Lowering::lower_echo` hands a `Ty::Object`
  or `Ty::Tagged` operand to `Helper::EchoValue` unconverted and everything else to `Helper::EchoStr`
  (`crates/nvs-ir/src/lower/expr.rs:577-583`), so a literal whose holes are known at compile time can
  lower to a run of writes with no carrier materialised at all.
- **`Markup` is not a heavy object.** It is memberless with one slot
  (`crates/nvs-stdlib/src/html.rs:216-222`); the cost is the `ObjHeader` — refcount, class pointer and
  the two live-list links (`crates/nvs-runtime/src/object.rs:1501`) — and the slot. There is no dispatch
  to remove, only allocations.
- **PHP's own template surface is the shape being copied**, not invented: `{$…}` already interpolates in
  a double-quoted string, and a `{` not followed by `$` is already literal text there. Reusing that
  grammar means a markup literal needs no second interpolation parser and no new escape for the braces
  in a `<style>` block.

## Options considered

1. **A markup literal whose holes escape.** Taken.
2. **A markup literal that also refuses holes it cannot escape correctly** — unquoted attributes, URL
   attributes, `on*` handlers, `<script>`/`<style>` bodies, tag and attribute names, comment bodies.
   Rejected in *Alternatives rejected*.
3. **Overload `.` so `Markup . string` escapes and lifts.** Rejected there too.
4. **Implicitly lift a bare source literal in a sink position**, removing `as Core\Html\Markup` with no
   new syntax. Rejected there too.
5. **Nothing; the framework's template files are the answer.** Rejected: `Web\Response::view` renders a
   `.nvs` file (`rule:programs/first-party-framework`), which serves a page. A function returning a
   fragment — a table row, a component — is expression position, and it is where the ceremony lands.

## Decision

### 1. The literal

`` html`…` `` is an expression whose type is `Core\Html\Markup`. Its **segments are trusted**, because
they are source the author wrote — the trust level `as Core\Html\Markup` already grants a literal token
and for the identical reason. Every **hole is escaped**: the value is passed through
`Core\Html::escape` and spliced. A hole already holding a `Markup` is spliced raw, which is
`Markup + Markup` written in interpolation syntax.

That is the whole rule, and it is deliberately the rule `<?= ?>` already follows. Nothing here can turn
computed text into trusted markup: a segment is always source, a hole is always escaped, and the two
cannot trade places.

### 2. Backticks delimit it

`` html`…` `` and not `html"…"`. HTML is full of `"`, and a double-quoted form would put a backslash in
front of every attribute in every template — worse than the ceremony being removed. The backtick is
free: Novis has no shell-execution form at all (`rule:core-classes/process-is-argv-only`), and PHP's
`` `cmd` `` is a converter mapping (the `Core\Process::run` row in `docs/rules/php-migration.md`) rather than a
token this lexer holds. A literal backtick inside the body is `` \` ``.

The prefix is a **name** rather than a bare delimiter because § 6's predicate admits a second carrier
one day, and a nameless template literal could not say which sink it meant.

### 3. A hole is `{$`, and every other brace is text

The hole grammar **is** the interpolation grammar of a double-quoted string, both halves of it, reusing
the lexer frames that already exist rather than adding a second interpolation parser:

- `{$` opens a hole, and what follows is a **full expression**. The lexer consumes only the `{` and
  hands `$` on as the next code token, opening an ordinary `Mode::Code` frame that counts brace depth,
  so a closure body inside a hole does not close it early
  (`crates/nvs-syntax/src/lexer.rs:1260-1264`, `:1064-1090`) and the parser runs `parse_expr`
  (`crates/nvs-syntax/src/parser/expr.rs:2517-2521`). `{$u->fullName()}`, `{$row["name"]}` and
  `{$a + $b}` are all holes.
- A bare `$name` interpolates too, in PHP's simple syntax — `$name`, `$name->prop` one level deep, or
  `$name[offset]` (`crates/nvs-syntax/src/parser/expr.rs:2529-2533`).
- **A hole must begin with `$`.** `{Money::format($c)}` is literal text, exactly as it is in a
  double-quoted string; a static call reaches a hole through a local or a closure. That is PHP's
  limitation, kept rather than repaired, because the alternative is a second interpolation grammar that
  differs from the one every `.nvs` file already contains.

A `{` not followed by `$` is therefore literal text, which is also already true — so a `<style>` block's
braces need no escape, and `\{` is available for the one case that wants a literal `{$`.

Consequences that follow from § 1 rather than being decided here: a `secret` value in a hole is refused
by `rule:security/secret-sinks-refuse` as at any other sink, and a `tainted` one is accepted, because
the sink "never distinguishes tainted from untainted".

### 4. What it lowers to

- **No holes:** a compile-time constant. The `Markup` is built once and emitted into the constant pool,
  as `rule:types/duration-literal` does with a nanosecond count, so a literal in a loop allocates
  nothing per iteration.
- **Holes, in a sink position:** a run of writes — segment, escaped hole, segment — straight into the
  output buffer, with no `Markup` materialised. The carrier is a checker fact here; a value born and
  consumed at the same sink is unobservable, which is the same erasure `rule:security/tainted-qualifier`
  already performs for the qualifier.
- **Holes, in value position** — assigned, returned, put in an `array<Core\Html\Markup>`: one `Markup`
  holding the joined bytes, because the value genuinely escapes the sink.

The compiler needs **no HTML knowledge** for any of this. Segments are opaque bytes; only `{$` and the
closing delimiter are scanned for. There is no tag tracking, no balance requirement, and therefore no
rule about where a literal may begin or end — `` html`<table>` `` and `` html`</table>` `` are both
ordinary literals, which is what lets a page be composed from fragments.

### 5. `Core\Html::join`

`Core\Html::join(array<Core\Html\Markup> $parts, Core\Html\Markup $separator): Core\Html\Markup`. Every
element is already a carrier, so the member neither escapes nor trusts anything — it concatenates. It
exists because the list-of-fragments shape is what a real page is, and without it that shape is a
`foreach` around an `echo` in the one place a value was wanted.

### 6. No ``text`…` `` peer, and the predicate that says why

> A carrier earns a literal form when its content is **authored as text**.

HTML markup is: `<span>` is bytes a developer types. Terminal styling is not, and that is decided rather
than incidental — `rule:tooling/styling-is-a-value-not-a-grammar` refuses both a raw `"\e[31m"` and a
`"<red>…</red>"` markup string as a fifth grammar. A ``text`…` `` literal's segments could therefore only
ever be plain text, which needs no trust: `rule:tooling/terminal-output-is-a-sink` neutralizes every
value "regardless of qualifier", and `Core\Cli::write` already accepts a bare string beside its carrier
(`crates/nvs-stdlib/src/cli.rs:443`). There is no `as Cli\Text` to remove because plain text never needed
lifting. The feature would have nothing to trust and nothing to escape.

The ceremony in that rule's own example is `Core\Cli::write` taking exactly one value
(`crates/nvs-stdlib/src/cli.rs:189-196`), which forces composition before the call; `echo` is variadic
and lifts per operand, so `echo Cli\Text::styled("deleting ", $warn), $path` needs neither `plain` nor
`+`.

The predicate is written down so a third carrier is measured against it rather than against the count.

### 7. What does not change

`as Core\Html\Markup` on a literal, `Markup + Markup`, `Core\Html::escape`, `Core\Html::sanitize` and
`Core\Html::toSource` all keep their present meaning and their present types. The literal is a fifth way
to obtain a `Markup` and it displaces none of them: `as` stays the spelling for a literal already held in
a variable's initializer, `+` stays composition for two computed carriers, and `escape` stays the
launderer a hole is defined in terms of.

## Diagnostics

**None.** An unterminated markup literal is `E0002` (`E_UNTERMINATED`), the code that already covers an
unterminated string, heredoc and `{$…}` interpolation — a markup literal is one more `Mode` arm in the
lexer's existing report (`crates/nvs-syntax/src/lexer.rs:210-232`), not a second way to be unterminated.
A hole's operand faces exactly the checks an interpolation already faces, and the refusals a hole can
meet — a `secret` value, a type with no conversion to text — are existing codes issued by existing
rules. A decision that adds no diagnostic is the honest outcome here, and it is a consequence of § 3
reusing the grammar rather than inventing one.

## Consequences

**Positive**

- The common case loses two constructs and an operator, and gains nothing to learn: one sentence covers
  the literal, and it is a sentence a PHP developer already knows from `<?= ?>`.
- **It is cheaper than what it replaces.** A hole-free literal allocates nothing per execution against
  one object per lift today; a holed one in a sink position allocates nothing at all against two per
  fragment today.
- **`nvs convert` gains a mechanical rewrite where [0133](0133.md) had to record a human gap.**
  `'<b>' . htmlspecialchars($x) . '</b>'` has a faithful target — `` html`<b>{$x}</b>` `` — where under
  the carrier alone it had none, and that ADR's *Consequences, Negative* booked exactly that as the cost
  of the carrier.
- The compiler learns no HTML, so the whole class of "which attributes are URL attributes" questions is
  not opened.

**Negative**

- **One more literal form in the language**, with a `nvs fmt` layout, an editor region and a converter
  row behind it. Priority 4 pays for priority 3 and for migration ergonomics; AGENTS.md asks that a
  feature say what it spends, and this is it.
- **Two ways to write markup**, this and inline HTML. They serve different positions — a file that is a
  template, and an expression that returns a fragment — but a reader still meets both.
- **It makes the sink's existing blind spots easier to write into.** `` html`<a href="{$url}">` `` is
  accepted and `javascript:` still reaches the document. That hazard is not new and not changed —
  `<a href="<?= $url ?>">` does the same today — but convenience raises its frequency, which is why
  *Revisiting* names it rather than leaving it implied.

## Alternatives rejected

- **A literal that refuses the holes it cannot escape correctly** — a closed list of positions
  (unquoted attribute, URL attribute, `on*` handler, `<script>`/`<style>` body, tag name, attribute
  name, comment body) diagnosed at compile time. Rejected on two grounds. It would make the literal
  **stricter than `<?= ?>`**, so the same hazard in the same document would be a compile error in the
  newer, more convenient syntax and legal in the older one — the incentive pointing exactly backwards.
  And it is a list of special cases where this rulebook's own habit is a predicate
  (`rule:core-classes/db-column-types`: "One rule settles what would otherwise be a list of special
  cases"), requiring the compiler to hold an HTML position model that § 4 otherwise does not need. The
  hazard is real; it belongs to the sink, where it applies to both spellings at once, and *Revisiting*
  is where it is filed.
- **Overloading `.` so `Markup . string` escapes and lifts.** [0133](0133.md) rejected this as an
  operator escaping silently; the argument that survives is different and stronger — `.` would answer
  `string` or `Markup` depending on its operands, so a reader could no longer tell what `$a . $b` is
  without knowing both types.
- **Implicitly lifting a bare source literal in a sink position.** It removes `as Core\Html\Markup`
  without new syntax, but then `echo '<b>' . $x` and `echo '<b>', $x` produce different documents with
  nothing visible to explain why, and it leaves `+` exactly as it was.
- **A ``text`…` `` peer for `Core\Cli\Text`,** for symmetry. Rejected in § 6, by the predicate rather
  than by taste.

## Revisiting

- **Whether the HTML sink needs context-aware escaping** — an attribute-context escaper, a URL-valued
  attribute that refuses a bare `string`, a refusal inside `<script>` and `<style>`. This is a question
  about the *sink*, so whatever it decides applies to `<?= ?>` and to this literal identically, and
  neither spelling is where it gets decided. [0024](0024.md)'s own *Revisiting* already carries the
  first half of it ("a matching attribute-context escaper", still unrostered). It is a pre-existing gap
  that this record neither widens nor closes.
- **Whether `Core\Html::join` wants a no-separator form**, once real templates exist to count. The
  two-argument shape is the honest default; a defaulted `$separator` is a change to one row.

## Verification

In the order it becomes possible:

- **M1**: the lexer takes `` html`…` `` as one token with its holes, `` \` `` and `\{` escape, an
  unterminated literal is `E0133` naming this rule, and the token round-trips through an `nvs ast`
  snapshot as `rule:ide/ast-json-schema-is-frozen` requires of a new node.
- **M2**: `nvs check` gives the literal type `Core\Html\Markup`, a hole accepts what an interpolation
  accepts, a `secret` hole is refused by its own existing code, and a hole holding a `Markup` type-checks
  without conversion.
- **M8**: the conformance cases — segments trusted and holes escaped in one document, a hole-free literal
  identical to `as Core\Html\Markup` over the same bytes, a `Markup` hole spliced rather than double
  escaped, a `{` before a non-`$` left as text, and `Core\Html::join` over a list built in a loop.
- **M8**: `nvs fmt` leaves a literal's bytes byte-identical and lays out only its surroundings, proven by
  the idempotence run the formatter already carries.
- **M10**: `nvs/regions` reports a markup literal's body beside an inline-HTML region, and
  `editor.formatOnSave` still runs `nvs fmt` alone.
- **M11**: `nvs convert` rewrites a concatenation of literal markup and `htmlspecialchars` calls into one
  literal, and says so on the site it could not.
