# ADR 0267 — A line break the author writes decides whether a list, a call chain or an operator chain is one line or one part per line, and `nvs fmt` lays out the rest

- **Scope:** which line breaks `nvs fmt` reads as the author's choice, the one-line and
  one-part-per-line layouts of a list, a `->` call chain and an `&&`, `||`, `??` or `.` chain, a broken
  control-structure condition, and the two editor actions that add or remove those breaks. Not `match`
  arms, enum cases or the `use` block, whose layouts their own rules keep; not an html template body, a
  heredoc body or a template region, which `nvs fmt` never touches.
- **Depends on:** [0039](0039.md), [0259](0259.md), [0004](0004.md).
- **Validated by:** `crates/nvs-fmt/tests/list_layout.rs`, `crates/nvs-fmt/tests/chain_layout.rs` and
  the split and join cases under `tests/lsp/actions/`, as side goal `fmt-layout-from-breaks` lands them.

> **In short:** there is still no line width. A list, a `->` call chain and an operator chain each have
> two layouts: all on one line, or one part per line. One line break the author wrote at the
> construct's own level — after its opener, between two parts, or before its closer — selects the
> second, and `nvs fmt` then writes every part on its own line, indented once, with a trailing comma
> in a list and the operator first in an operator chain. A break inside a nested part never counts for
> the construct around it. `nvs fmt` never splits a line because it is long and never joins a broken
> one; two editor actions, *Put on separate lines* and *Join onto one line*, add or remove the breaks.

## Context

ADR 0039 settled that `nvs fmt` never reflows to a width, and kept every byte inside an expression the
author's. The user's experience with PER and php-cs-fixer is that width-driven wrapping breaks at
places nobody would choose and packs as much onto a line as fits, so the result is often less readable
than the input. Keeping the interior untouched avoids that but gives the author no help: a list wrapped
two items to a line, or with its closer on the last item's line, stays exactly as typed, and
continuation lines keep whatever indentation they were written with
(`crates/nvs-fmt/src/indent.rs:24-32`).

## Options considered

1. **Width-fitting printer** (Prettier, php-cs-fixer, rustfmt): the tool chooses every break. Rejected
   by the user, for the reason above.
2. **Keep ADR 0039 unchanged:** no help with a badly wrapped list.
3. **A trailing comma as the signal** (Black, dart format): the author must type a comma to keep a list
   broken, which is a second, less visible way to say what a line break already says.
4. **Any line break the author wrote at the construct's own level as the signal**, two fixed layouts,
   no width. Chosen.

## Decision

### 1. A list is one line or one item per line

A list is a call's arguments, including `new`'s; a function's, method's or anonymous function's
parameter list; an array literal; an anonymous object; a shape type. It is **broken** when its own
level holds a line break the author wrote: after the opener, between two items, or before the closer.
A break inside an item — a function body, a nested array, a nested call, a heredoc — belongs to that
item and is not the list's.

A list that is not broken is written on one line however long it is. A broken list is written with the
opener ending its line, each item on a line of its own one level in, a trailing comma after the last
item, and the closer at the indentation of the line the opener is on. An item that spans several lines
moves in with its first line and keeps its own layout, decided by its own rules.

```nvs
$order = Shop::place($customer,
    $basket, $address);
```

```nvs
$order = Shop::place(
    $customer,
    $basket,
    $address,
);
```

```nvs
array<string> $names = Core\Arr::map($users, fn(User $user) {
    return Core\Str::upper($user->name);
});
```

The last one is not broken: its breaks are inside the function body, so it keeps its layout.

### 2. A broken call chain is one call per line

A chain of two or more `->` or `?->` calls is broken when a line break the author wrote sits before
any of its arrows. A broken chain keeps its receiver on the first line and starts every arrow on a
line of its own, one level in from the line the chain starts on. A chain that is not broken stays on
one line. The arguments of each call are a list under § 1, judged on their own.

### 3. A broken operator chain is one operand per line, with the operator first

An operator chain is a run of one of `&&`, `||`, `??` or `.`. It is broken when a line break the
author wrote sits between two of its operands. A broken chain keeps its first operand where it was and
starts every following operand on a line of its own, one level in, with the operator first. When the
run mixes operators of different precedence, the chain is the run at the lowest precedence, and each
higher-precedence operand is judged on its own.

A broken condition of `if`, `elseif`, `while` or `do … while` takes one more step: the `(` ends its
line, each operand of the top-level chain starts a line one level in, and the `)` starts its own line,
followed by ` {` for a block. A condition is broken by a line break after the `(`, between two
operands of its top-level chain, or before the `)`; a break inside one operand, such as inside a
call's arguments, is that operand's.

```nvs
if (
    $user->isActive()
    && $user->hasRole('admin')
    && $request->isSecure()
) {
    Audit::log($user);
}
```

### 4. What `nvs fmt` never does

It never splits a line because it is long, never joins a broken construct onto one line, and never
places two items, two calls or two operands of a broken construct on one line. A comment inside a
broken construct stays with the part it follows on that part's line, or opens its own line when it
was written on one. A line comment makes the construct broken, because a line break follows it.

### 5. Two editor actions add and remove the breaks

With the cursor in a list, a call chain or an operator chain, the server offers **Put on separate
lines** when the construct is on one line, and **Join onto one line** when it is broken. Each writes
the layout `nvs fmt` would write after the break is added or removed, so applying it and then
formatting changes nothing more. Join is not offered when the construct holds a line comment, which
joining would turn into code. Both are computed from the tree under the cursor alone, are filed under
`refactor.rewrite`, and are never under `source.fixAll.nvs` or `quickfix`: whether a list is broken is
the author's choice, never a fix.

## Consequences

- **Tradeoffs.** Runtime performance and memory: none, because nothing in `nvs` or the server changes.
  `nvs fmt` stays one walk over the lossless tree with no width measurement. Developers get one rule for
  every list-shaped construct, a predictable layout from one keystroke, and no surprising breaks. A file
  formatted before this changes: a list wrapped several items to a line becomes one item per line, and
  a continuation line is re-indented. That is a one-time diff, the cost `rule:tooling/fmt-is-one-canonical-style`
  names for changing a style rule.
- **Determinism.** Output is still a pure function of the input bytes. Two files that differ only in
  where a broken list was wrapped now format to the same bytes; two that differ in whether it was
  broken still do not (`rule:tooling/fmt-is-idempotent`).
- **The trailing comma** follows the layout: a broken list's closer always opens its own line, so the
  case in `rule:tooling/fmt-trailing-commas` where a multi-line list ends on its last item's line no
  longer comes out of `nvs fmt`.

## Alternatives rejected

- **A line-length limit that only reports**, never wraps. It is a diagnostic about layout, which
  `rule:tooling/fmt-is-never-a-diagnostic` excludes, and the editor's own ruler already shows a column.
- **Keeping several items per line in a broken list.** That is the packing the user asked to remove,
  and it gives a list a third layout.

## Verification

Side goal `fmt-layout-from-breaks` names each test, and its checks are the list of what holds this
record.
