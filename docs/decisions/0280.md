# ADR 0280 — outside keys and an object's outside fields are `tainted`, and only an array converts to an array

- **Scope:** three ways text from outside the program still reached a plain `string` after
  [0279](0279.md): a `foreach` key, a shape target filled from an object's fields, and a nullable or
  union operand converted to an array. Not in scope: a key qualifier written on an array type, and a
  map nested in a `queryAs`/`postAs`/`jsonAs` target (see *Revisiting*).
- **Depends on:** [0279](0279.md) § 1 and § 3 — text out of `mixed` is `tainted`, and a written type
  says so itself; [0053](0053.md) — what a `foreach` binds; [0007](0007.md) — the conversion table.
- **Validated by:** `tests/conformance/reject/a-foreach-key-from-outside-the-program-must-be-written-tainted.nvst`,
  `tests/conformance/reject/a-shape-filled-from-a-mixed-or-tainted-field-must-be-written-tainted.nvst`,
  `tests/conformance/reject/a-nullable-or-union-operand-with-no-array-member-does-not-convert-to-an-array.nvst`
  and `crates/nvs-types/tests/tainted.rs`.

> **In short:** a `foreach` key over `mixed`, or over an array whose element type carries `tainted` or
> `mixed`, is `tainted string`: `var $k` takes it, and a written `string $k` is `E0851`. A shape target
> of `as` or `is` over an object takes each text field from the object's field of that name, so a
> `mixed`, `object`, tainted or undeclared field needs `tainted {…}` (`E0851`). A union operand converts
> to an `array<T>` only when one of its members is an array or `mixed`, so `?string as array<string>`
> is `E0708` where it is written. All three are decided while checking.

## Context

0279 closed every way text left `mixed` through a value, and three paths stayed open.
`foreach (Core\Request::json() as string $k => mixed $v)` bound a key the client chose as a plain
`string`, and so did a key over `queryArray("filter")`, whose keys are the brackets of
`filter[color]=red`. `class Bag { public mixed $data; }` then `$bag as {data: string}` read the
`mixed` field into a plain text field, because 0279's shape check asked about the operand's own type
and a class is neither `mixed` nor `object`. And `?string as array<string>` compiled and threw when it
ran, because a union operand is a "wide" kind the conversion table never refuses.

## Options considered

### A. A key qualifier on the array type

`array<tainted string => T>` or similar, set by the accessors that fill an array from outside. It is
exact, but it adds a type parameter to every array, a second axis to assignability, and a spelling
nobody has written yet. Rejected for now under the simplicity priority.

### B. The element type is the evidence (chosen)

An array's type records nothing about its keys, but an array whose elements carry `tainted` or `mixed`
was filled from outside in every member that answers one: `queryArray`, `postArray`, `headers()`,
`Env::all()`, an LDAP entry, an XML element's attributes, a decoded document. Reading the key's
qualifier off the element type covers all of them and every member not written yet. An array the
program fills with tainted values under its own literal keys over-taints, which is the safe direction.

## Decision

### 1. A `foreach` key from outside is `tainted string`

Over a `mixed` or `iterable` subject, and over an `array<T>` whose `T` carries `tainted` or `mixed`
anywhere, the key binding's type is `tainted string`. A `var` key takes it; a written `tainted string`
key is admitted over every array; a written `string` key there is `E0851`, the refusal a value binding
over `mixed` already gets, because the binding is a type the program wrote.

### 2. A shape's text field reads the object's field of the same name

For a class, a shape or a union of them, each text field of the target shape written without `tainted`
is checked against the source's field of that name: `mixed`, `object` or anything carrying `mixed` or
`tainted` is outside text, and so is a field the class does not declare, since only a subclass could
fill it and its type is unknown. A nested shape field is asked again one level down. `is tainted {…}`
is admitted over such a subject, as it is over `mixed`.

### 3. Only an array converts to an array

A union operand converted to an `array<T>`, under `as T` and `as ?T` alike, is read member by member:
it has a row when one member is an array or a type the table does not model, such as `mixed`, and is
`E0708` otherwise.

## Diagnostics

- **`E0851`**, reused: "this key can come from outside the program, so it must be `tainted string`" for
  a key, and the existing "`{data: string}` gets its text from `Bag`, so it must be `tainted {…}`" for
  a shape. The code's card names both new sources.
- **`E0708`**, reused: "`string|null` cannot be converted to `array<string>`".

## Consequences

- **Cost.** Memory: none. Latency: none — every part is decided while checking and the qualifier is
  erased before codegen. Compile time: one walk of the subject's element type per `foreach` with a key,
  and one property lookup per text field of a shape target over an object.
- **Over-tainting.** A key of a program-built `array<mixed>` or of an array of tainted values is
  tainted. The fix is to write `tainted string $k`, and to bind or escape the key where it reaches a
  sink.

## Revisiting

A map nested in a decoded target — `postAs<Form>` where `Form` has an `array<int>` field — is keyed by
the peer and has clean elements, so § 1 cannot see it. A key qualifier (option A) is the fix if that
shape turns up in practice.
