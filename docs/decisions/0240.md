# ADR 0240 — A `require` or `autoload` literal, an `as class<T>` string and a string argument at a path or class-name parameter complete, link and hover as the path or name the compiler reads, and a directory link reveals it in the Explorer

- **Scope:** Completion, links, hover and go-to-definition inside the literals of `require` and
  `autoload`, inside the string operand of `as class<T>` and inside a string argument at a parameter
  marked as a path or a class name, the trigger characters that open those lists, and what the VS
  Code client does with a link to a directory. Any other string is not decided here.
- **Depends on:** [0099](0099.md) (the request set, and `documentLink` as a projection of the walk),
  [0193](0193.md) (trigger characters answered only where a spelling ends), [0241](0241.md) (the
  path and class-name marks, and the checker's resolved path literals).
- **Validated by:** `tests/lsp/completion/a-require-literal-offers-the-directories-and-nvs-files-its-text-reaches.lspt`,
  `tests/lsp/links/an-autoload-root-links-to-the-directory-it-names.lspt`,
  `tests/lsp/completion/an-autoload-prefix-offers-the-namespaces-the-workspace-declares.lspt`,
  `tests/lsp/completion/a-class-reference-literal-offers-the-classes-that-are-its-type.lspt`,
  `tests/lsp/hover/an-autoload-prefix-answers-its-namespace-and-its-roots.lspt`,
  `tests/lsp/completion/a-path-argument-offers-the-files-and-directories-its-text-reaches.lspt`,
  `tests/lsp/links/a-path-argument-links-to-the-file-or-directory-it-names.lspt`,
  `tests/lsp/completion/an-expected-error-argument-offers-only-error-classes.lspt`,
  `crates/nvs-lsp/tests/completion.rs`, `crates/nvs-lsp/tests/completion_edits.rs`,
  `crates/nvs-lsp/tests/navigation.rs`, `crates/nvs-lsp/tests/autoload.rs` and
  `editors/vscode/test/client/links.test.ts`.

> **In short:** inside the literal of a `require`, of an `autoload` root or of an `autoload discover`
> glob, completion offers the entries of the directory the text before the cursor reaches, resolved
> against the declaring file's directory: directories with a `/` after them, and `.nvs` files inside
> a `require` only. The listing is `nvs_hir::autoload::entries_of`, the one the compiler resolves a
> glob with. `'`, `"` and `/` become trigger characters, answered only inside such a literal. Each
> `autoload` root and each glob gets a `documentLink` to the directory it names, resolved by
> `nvs_hir::autoload::Site::directories` out of the literal spans the walk now keeps; a missing root
> and a malformed glob get none. A directory link is a `file:` URI ending in `/`, and the VS Code
> client turns it into a `revealInExplorer` command.
>
> An `autoload` prefix completes as the namespaces the workspace declares, hovers as the namespace it
> maps (a `{..}` segment replaced by its directory name) and the roots in probe order, and links to
> the first root that exists. The string operand of `as class<T>` completes as the classes the program
> declares that are a `T`, and hovers and jumps as the class whose whole name it is.
>
> A string argument at a path parameter (`CoreTy::Path`, `#[Core\Path]`, or a `Core` shape field with
> the same mark) completes as every file and directory of the directory its text reaches, links to the
> file or directory the checker resolved it to, and hovers as that absolute path and whether anything
> is there. A string argument at a class-name parameter (`CoreTy::ClassName`) completes as the classes
> the program declares, only the `Throwable` ones for `Core\Test::assertThrows`, and hovers and jumps
> as `as class<T>`'s string does.

## Context

`documentLink` already promised "the resolved path literal of a `require` or `autoload`", and only the
`require` half existed: `nvs_hir::autoload::Site` kept the whole declaration's span and no span per
literal, so there was no literal-to-directory edge to read, and deriving one in the language server
would have been a second copy of the resolution rule. Writing a path in a `require` or an `autoload`
had no help at all: completion answered nothing inside a string.

## Decision

### 1. The walk keeps each literal's span, and hir resolves it

`SiteKind::Prefix` carries each root with its literal's span, and `SiteKind::Discover` the glob's.
`Site::directories` pairs each literal with the directory it names, through the functions
`AutoloadMap::build` resolves with (`canonical` for a root, `glob_base` for a glob), and keeps only a
literal whose directory exists. Nothing calls it while compiling. The language server keeps the entry
document's own sites and asks them when a link request arrives.

### 2. Completion lists one directory through the compiler's listing

The text between the opening quote and the cursor is split at its last separator. The part before it
is joined to the declaring file's directory, which is the base `require` and `autoload` both resolve
against, and listed through `nvs_hir::autoload::entries_of`. Names are offered as the disk spells them
(`rule:programs/path-case`), names starting with `.` are hidden, and each item's text edit replaces
only the segment after the last separator. A directory item writes a `/` and runs the editor's
suggest command. Nothing is offered once the directory part holds a `*`.

`completion.rs` itself reads no filesystem, which is what
`rule:ide/completion-offers-only-what-the-compiler-derived`'s guard test checks. The listing is the
compiler's, so a name offered is one resolution would find.

### 3. Three more trigger characters, each answered only inside a path literal

A client offers nothing inside a string unless asked, so without a trigger the list would need
Ctrl+Space every time. `'` and `"` open a path literal and `/` extends one. Each is far more often
something else, so `continues_a_trigger` answers them only where the cursor is inside a `require` or
`autoload` path literal, an `autoload` prefix, or the string operand of `as class<T>`.

### 4. A directory link is a URI ending in `/`, and VS Code reveals it

A directory cannot open in an editor tab. The server stays on the standard protocol and marks a
directory the way a URI does, with a trailing `/`. The VS Code client's `provideDocumentLinks`
middleware rewrites such a target into `command:revealInExplorer?<the directory>`. No trust setting is
added: `isTrusted` is a field of a `MarkdownString`, and a `DocumentLink` has no such field.

### 5. An `autoload` prefix is a namespace, and links to its first root

`SiteKind::Prefix` keeps the prefix literal's span too. `Site::namespace` reads the prefix with
`prefix_segments`, the function `AutoloadMap::build` reads it with, so a `{..}` segment is shown as the
directory name the map uses. `Site::roots` gives every root in probe order, a missing one included,
printed the way `nvs check --autoload-map` prints it.

- **Completion** offers every namespace a declaration in the workspace index or the analysis is
  written in or under, `Core` excluded. A prefix usually maps code nothing loads yet, so the index,
  and not only the program, is the source.
- **Hover** shows the namespace and the roots, and marks a root that does not exist. A cursor on a
  `{..}` segment is told the directory name it is replaced by.
- **Ctrl-click** is a `documentLink` to the first root that exists, the first directory a name under
  the prefix is probed in. A namespace has no declaration, so `definition` has nothing to answer, and
  a link reveals the directory in the Explorer the way a root's link does.

### 6. The string operand of `as class<T>` is a class's whole name

`rule:types/class-reference`'s run-time conversion compares the string with the whole names of the
classes the program declares that are a `T`, and resolves no `use` and no namespace. The editor
matches that. Completion offers each class and interface in the analysis that
`nvs_hir::hierarchy::implements_interface` says is a `T`, `T` included. A class only an autoload root
could load is not offered, because the conversion cannot find it either. Hover and `definition`
answer the class whose whole name the text is, exactly as written, so `'\App\User'` and a short name
answer nothing.

### 7. A name is offered whole

Both name literals offer whole names that replace all the text after the opening quote. A `\` typed
just before the closing quote is an escaped quote (`'App\'`), so the literal does not end there and
no list can be answered at that keystroke. A whole name never needs that keystroke.

### 8. A string argument is a path or a name when its parameter says so

[ADR 0241](0241.md) marks a parameter whose text is a path (`CoreTy::Path`, and `#[Core\Path]` on a
user parameter) or a class name (`CoreTy::ClassName`), and a `Core` shape field carries the same mark
(`CoreShapeField::text`). The checker now keeps the parameters' marks on the call it resolved
(`ResolvedCall::param_text`), because the language server holds call sites and no signature table.
`crate::arguments` finds the call that holds a string literal, counts the argument from the call's own
`(` the way `signatureHelp` does, maps it to its parameter through `ResolvedCall::arg_slots`, and reads
the mark. A literal in a `{...}` argument is looked up by its key in the parameter's shape, every arm
of a union of shapes included, as `Db\Settings` is. A literal at an unmarked parameter is ordinary
text, and nothing here changes what it is offered.

- **Completion** is § 2's listing, with every file offered, since a path parameter takes a file of
  any kind. An absolute text replaces the document's directory, so it lists the directory it names.
- **The link** reads the checker's own join, `ExprTypeTable::path_literal`, for a relative literal,
  and the text itself for an absolute one. A relative literal the checker left alone (a first segment
  holding a `:`) has no link. A path that names nothing on disk has none either: the program may be
  about to create the file. Whether the target is a directory is asked of the disk when the link is
  made, because nothing was loaded through this edge.
- **Hover** shows the same absolute path and says whether a file, a directory or nothing is there.
  A `.lspt` case cannot freeze an absolute path, so a Rust test holds it.

### 9. A class-name argument is § 6's string, with its own set of classes

A class-name parameter looks a class up by its whole name at run time, and resolves no `use`, so its
completion, hover and `definition` are § 6's. The set offered is every class the program declares,
because the parameter names no `T`. `Core\Test::assertThrows` is the one member whose class-name
parameter expects an error, so its list holds only the classes that are a `Throwable`, the error
classes the language declares included. That member is named in a one-row table in
`crate::arguments`, since the mark says only that the text is a class name.

## Consequences

What this spends: one span per `autoload` literal per compile, kept in `Site`. A `PathBuf` and one
existence test per literal per link request, in the server only. One directory listing per completion
request inside a path literal. One more span per prefix declaration per compile. In the server, one
walk of the index and the symbol table per completion request inside a name literal, and one
existence test per root per hover. One `Vec` of parameter marks per resolved call per compile, empty
and not allocated for every method that marks nothing. In the server, one walk of the entry document
per link request, and one existence test per path argument per link or hover request. Nothing on the
request path at run time.

Another client receives a directory link as an ordinary `file:` URI and opens it however it opens a
directory.

## Alternatives rejected

- **Resolving the root in `crates/nvs-lsp`.** A second copy of the resolution rule, which is what the
  links module refused before this record.
- **A `std::fs` listing in `completion.rs`.** It would bypass the guard that keeps every completion
  source on a table the compiler builds, and could disagree with what resolution finds.
- **Marking a directory link in `data` or `tooltip`.** Both are free-form fields a client has to know
  about. A trailing `/` is what a URI already means by a directory.
- **Turning on `editor.quickSuggestions` for strings in the extension.** It opens the editor's
  word list inside every string in the file, not only in path literals.
- **`definition` on a prefix, to its first root.** A `Location` names a file and a range, and a
  directory is neither. The link already gives the same ctrl-click.
- **Resolving an `as class<T>` string through the file's `use` lines.** The conversion does not, so
  the editor would jump to a class the program then fails to find.
- **Offering every workspace class for `as class<T>`.** A class the program never loads is one the
  conversion throws for.
- **Joining a path argument's text in the language server.** A second copy of
  `rule:programs/path-literals-resolve-from-their-file`'s join, which could disagree with the path the
  program opens.
- **A bound in the class-name mark, so `assertThrows` would carry `Throwable` in the registry.** One
  member needs it, and a new mark field would be read by nothing but the editor.
