# ADR 0221 — the repository's tools are one Bun program over JSON records under `data/`, and a file rendered from the records is committed, marked and never edited

- **Scope:** the repository's own tooling: what runs it, where a fact a tool reads is kept, how a record is
  written, and what a file rendered from the records is. It does not decide the perf currency, which
  [0220](0220.md) owns, and it changes nothing a Novis program or the `nvs` binary does.
- **Depends on:** [0220](0220.md).
- **Validated by:** `bun nv audit python`, `bun nv check`, `bun nv render --check` and `bun nv rules --render --check`,
  the last three in CI's `docs` job; `tools/nv/test/records.test.ts` for the writer's one text per value.

> **In short:** the tools are one Bun + TypeScript program, `bun nv <command>`, whose only runtime
> dependency is `smol-toml`, for the TOML files the tree still has. A fact a tool reads is a JSON record under
> `data/`, one entity per file, its type declared once in `tools/nv/schema/` and its text written only
> by `tools/nv/lib/store.ts`. Prose stays under `docs/` at its path. A file written from the records is
> committed, opens with a marker naming the command that writes it, is `linguist-generated` in
> `.gitattributes`, and a conflict in one is resolved by rendering it again.

## Context

The repository was run by about fifty Python scripts. Each parsed its own slice of Markdown, TOML
front matter and positional numbering, and each shape had a checker of its own. A fact such as a
goal's place in the chain was written in several files, and the checkers existed to keep the copies
agreeing. Goal `tooling-overhaul` replaced the scripts, and the user's standing decisions for it fix
the runtime, the record format and the rule for generated files. This record writes those decisions
down as rules, so they outlive the goal's prose.

## Decision

### 1. One program, one runtime

The tools are `bun nv <command>`, one entry point at `tools/nv/main.ts`. A subcommand keeps the name
of the script it replaced. The runtime is Bun, pinned by `engines` in `package.json`. The one runtime
dependency is `smol-toml`, which reads the TOML files the tree still has, such as `Cargo.toml`.
`Bun.TOML` is never used, so every TOML file is read by one parser. No record is TOML. The dev
dependencies are `typescript` and `@types/bun`. Any other dependency is a new decision.

### 2. A fact a tool reads is a record

A record is one JSON file under `data/`, holding one entity: a goal, a rule's structure, a decision's
fields, a gap, a playbook bullet, a plan field. Its type is declared once in `tools/nv/schema/`, and
that declaration gives the static type, the runtime check and a JSON Schema. `tools/nv/lib/store.ts`
is the only code that writes one: keys in schema order, two-space indent, LF, one trailing newline.
So a value has one text, loading and writing a record changes nothing, and git merges two edits to
one record line by line. An id is a slug or a number and never changes. A reference is an id, and
`bun nv check` holds every reference to a record that exists.

### 3. Prose stays where it is

A rule fragment, a decision record, a goal's prose, a milestone file, a reference chapter and an
`about.md` keep their paths under `docs/`, so every `rule:` token and every `NNNN § N` citation still
resolves. A fact a tool reads has its home in a record. Where a prose file still repeats one, as a
decision record's YAML block does, the record is the authority and a check compares the copy to it.

### 4. A rendered file is committed and never edited

A file a tool writes from the records is committed, so GitHub and a reader without Bun see it. It
opens with a marker naming the command that writes it, and `.gitattributes` gives it
`linguist-generated`, so a review collapses it. The command has a `--check` form that writes nothing
and fails when the file no longer matches the records. After a merge conflict in a rendered file,
the file is rendered again from the merged records. It is never merged by hand.

## Consequences

- Every developer and every CI job needs Bun, one binary on Windows, macOS and Linux.
- A shape that had a checker of its own is now a schema, and `bun nv check` is the one audit of them.
- A generated file shows in a diff beside the record change that caused it, and review tools fold it.
- The data model has no runtime cost to a Novis program. It touches no request path.

## Alternatives rejected

- **Keep Python.** Fifty scripts each carried a parser for a shape another script also parsed, and
  two readers of one shape drifted apart.
- **TOML records.** A second writer cannot reproduce a TOML file's text from its value without a
  formatting library, and JSON is what the website and the editors already read.
- **Render on demand and commit nothing generated.** GitHub would show no rulebook, and a reader
  would need Bun to read the rules.
- **More runtime dependencies**, such as a schema or a CLI library. Each one is a supply-chain input
  to every contributor's machine, and the schema builder is a few hundred lines.
