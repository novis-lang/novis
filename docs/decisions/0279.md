# ADR 0279 — text out of `mixed` is `tainted`, however it is taken out

- **Scope:** what a value pulled out of `mixed` carries on the `tainted` axis: every conversion, `.`,
  interpolation, `is` narrowing, shape target and `foreach` binding that reads text out of `mixed`, and
  the typed readers of a database row. Not in scope: typed request accessors (`query`/`post` answering
  `?tainted string`), which are the follow-up step; and the `secret` axis, whose union reach is unchanged.
- **Depends on:** [0024](0024.md) § 1 — the qualifier, its sources and the "structured input stays
  `array<mixed>`" boundary; [0157](0157.md) § 3–4 — `tainted {…}` over a shape, and `tainted mixed`
  refused; [0067](0067.md) — the row's column map, which already promised `tainted` text.
- **Validated by:** the `tests/conformance/reject/mixed-text-*.nvst`,
  `tests/conformance/lang/mixed-text-*.nvst` and
  `tests/conformance/reject/db-row-text-readers-answer-tainted-text.nvst` cases, and
  `crates/nvs-types/tests/tainted.rs`.

> **In short:** `mixed` is where request input lands, and the qualifier cannot be written on it, so
> until now text pulled out of it was a plain `string`: `$db->query("… " . Core\Request::query("id"))`
> and `string $a = Core\Request::query("id") as string` both compiled. Now every way text leaves
> `mixed` yields the tainted form — `as string`, `as ?string`, `as bytes`, `as array<string>`, `as secret
> string` (as `secret tainted string`), `.`, interpolation and `is string`. A conversion to `int`,
> `float`, `bool`, `decimal`, an enum or a set of allowed values stays clean. Where the text would land in
> a type the program wrote — a shape, a `foreach` binding — the program writes `tainted` itself
> (`E0851`). It is decided while checking, with nothing at run time.

## Context

0157's *Consequences* named the gap this closes: "a program that reads a request body as `mixed` and
pulls a `string` out of it holds an unqualified string, because the container was never qualified".
The members that answer `mixed` are not a corner: `Core\Request::query`, `post` and `json`,
`Core\Script::args`, `Core\Session::get`, `Core\Json::decode`, `Core\Cache::get`, `Core\Db\Rows::value`,
`Core\Db\Row::get`, `Core\Serialize::decode`, `Core\Uri::queryParameter` and a socket's or event
stream's `value`. The site promises that text from a request cannot reach SQL, HTML or a shell command
until it is checked, and every one of those was a way round it.

Separately, `Core\Db\Row::string` declared `?string` and `Row::bytes` `?bytes`, against
`rule:core-classes/db-column-types`'s "every value a row yields is `tainted`": a stored-injection path.

## Investigation

Every way text leaves `mixed` in the checker, probed against the release build before the change:
`as string`/`?string`/`bytes`/`array<string>`/`secret string`, `.` and interpolation with a `mixed`
operand, `$m is string` and `$m is {name: string}` narrowing, `$m as {name: string}` and
`$o as {name: string}` over an `object`, and `foreach ($m as string $v)` over a `mixed` or `iterable`
subject — all produced a plain `string`. Assignment, a `string` parameter and destructuring already
refuse `mixed`. The same probe found `?tainted string as string` and `array<tainted string> as
array<string>` laundering, because the conversion rule read the qualifier off the top atom only.

## Options considered

### A. Typed request accessors only

`query`/`post` answer `?tainted string`. Rejected as the sole fix: it leaves `json()`,
`Script::args`, `Session::get`, `Cache::get` and the database's `get` open, and every future member
answering `mixed` would reopen it. It is still worth doing, for ergonomics and for latency (no `mixed`
box on the hot read), and it is planned as the follow-up step.

### B. Text out of `mixed` is `tainted` (chosen)

One rule at the boundary every `mixed` source shares. It is compile-time only, and it covers members
not yet written.

### C. A hidden, source-marked `mixed`

`mixed` carrying an invisible "came from outside" bit. Rejected: it is lost at the first `mixed`
parameter or property, it cannot be written in a declaration, and `tainted mixed` is refused by 0157
§ 4 for the same reason.

## Decision

### 1. Every way text leaves `mixed` adds `tainted`

An operand that is `mixed`, an `array<mixed>` or a union with a `mixed` member is *unchecked*. A
conversion out of one answers the target with `tainted` set wherever the target can carry it — the
atom, an array's element, every union member — so `as ?string` is `?tainted string` and `as
array<string>` is `array<tainted string>`. `secret` stays in front: `as secret string` is `secret
tainted string`. A `.` or an interpolation with an unchecked operand is tainted. `$m is T` over an
unchecked subject narrows to the same tainted form of `T`.

### 2. Non-text targets stay clean

`int`, `uint`, `float`, `bool`, `decimal`, an enum, a set of allowed values, a class: the existing
laundering argument holds unchanged, because a value that survived the check has had its shape proven.

### 3. A written type is never tainted for the program

A shape target of `as` or `is` over a `mixed` or `object` operand, and a `foreach` value binding over a
`mixed` or `iterable` subject, are types the program wrote. Tainting them silently would make the
declaration understate the value, which is what 0157 rejected for a hydrated shape. A text field or
binding written without `tainted` is `E0851`, and the fix is one word: `as tainted {…}`,
`is tainted {…}`, `tainted string $v`. `object` is included for shapes because its fields are as untyped
as `mixed`'s, and `$m as object` must not be a step round the rule. To make `tainted {…}` usable there,
a shape target whose qualified fields are all `tainted` is admitted by `as`, and over an unchecked subject
by `is`; it is tested with the qualifier erased. A `secret` field stays refused.

### 4. A conversion reads `tainted` through a union and an array

`?tainted string as string` and `array<tainted string> as array<string>` keep the qualifier. The
conversion rule now reads the operand with `carries_tainted`'s reach. `secret` is still read off the
atom alone.

### 5. A row's typed text readers answer the tainted form

`Core\Db\Row::string` is `?tainted string` and `Row::bytes` is `?tainted bytes`, as
`rule:core-classes/db-column-types` already said.

## Diagnostics

- **`E0851`** (`E_UNCHECKED_TEXT_NOT_TAINTED`) — "`{name: string}` gets its text from `mixed`, so it
  must be `tainted {…}`", and for a binding "`string` gets its text from `mixed`, so it must be `tainted
  string`". The help names both fixes and says to check or escape the text before a query, a page or a
  command uses it.
- `E0813` is no longer reported for a `tainted` atom tested over a `mixed` or `object` subject.
- A sink handed text out of `mixed` reports the existing `E0401` "expected `string`, found `tainted
  string`".

## Consequences

- **Cost.** Memory: none. Latency: none — the qualifier is erased before codegen, as
  `rule:security/tainted-qualifier` already promises. Compile time: one walk of the operand's type per
  conversion, `.`, interpolation and type test.
- **Over-tainting.** A literal that was stored in `mixed` comes back out tainted, and so does the text of
  a `Stringable` object pulled out of one. The way out is the one every other tainted value has:
  `Core\Taint::assertTrusted(…, reason)` (`rule:security/assert-trusted`) for a value that really is
  trusted, or the sink's own launderer — a bound parameter, an escaper.
- **Existing programs** that bound text out of `mixed` as `string` stop compiling. Each fix writes
  `tainted string` and then binds or escapes the value where it reaches a sink.

## Alternatives rejected

- **Auto-tainting a shape target** instead of `E0851`: rejected for 0157's reason — a declaration that
  understates the value is worse than a long one.
- **Refusing `as string` out of `mixed` outright**: it would leave no way to read text from a request
  at all, and the tainted result is exactly what a sink needs to see.

## Verification

The conformance cases named under *Validated by* pin each conversion form, the sink refusal, `E0851` for
a shape, a binding and an `object` operand, `as tainted {…}` and `is tainted {…}` accepted, the
numeric, `bool` and enum conversions clean, and `Row::string` tainted against an in-memory SQLite
database.
