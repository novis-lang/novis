# ADR 0215 — an `autoload` prefix may take one segment from a directory name, every segment is checked, and an autoloaded file declares the name the map finds it by

- **Scope:** the prefix of an explicit `autoload` declaration — a `{..}` segment read off the disk,
  and the shape every segment must have — the namespace an autoloaded file must declare, and the
  `missing` section of `nvs check --autoload-map`. It does not change `autoload discover`, how a
  root is probed, or that a root which does not exist is allowed.
- **Depends on:** [0061](0061.md) for the map and the one-declaration rule, [0062](0062.md) for the
  exact on-disk spelling.
- **Validated by:** `tests/conformance/lang/a-directory-segment-names-the-prefix-after-a-directory.nvst`,
  `tests/conformance/lang/an-autoload-prefix-that-can-never-match-does-not-compile.nvst`,
  `tests/conformance/lang/an-autoloaded-file-declaring-another-namespace-does-not-compile.nvst`, and
  `crates/nvs-hir/src/requires.rs`'s `the_rendered_map_names_what_was_skipped_and_what_was_shadowed`.

> **In short:** `autoload 'Framework\{..}' from '../src';` maps `Framework\Blog` when the file sits in
> `Blog/public/` and `Framework\Shop` when it sits in `Shop/public/`, so many modules share one entry
> file byte for byte and each maps only its own root. The braces hold `.` and `..` steps, resolved
> like a root, read as the directory the disk spells, one per prefix. Every prefix segment — written
> or read — must be a `PascalCase` namespace segment, or the declaration is `E0327`. A file reached
> through a root must declare the full name the map derived for it, namespace included, or it is
> `E0317`. A root that does not exist stays legal and is listed under `missing` by `--autoload-map`.

## Context

### 1. One entry file per module, each naming its module

An application with many modules, each mounted with its own entry file, could not give them one
shared entry file, so that a new module is a copied directory: each entry had to write its own
namespace in its `autoload` line. `autoload discover` names a prefix after a directory, but it maps *every* matching
directory into the program, so every module's `#[Route]` table and `implementing<T>()` answer held
every other module's classes, and two modules both declaring `/` was `E0748`. Isolation by which roots
a program declares is what the project relied on.

### 2. Two ways the map accepted a mistake in silence

A prefix was parsed as a name and never checked. `'App\*'` — the PSR-4 spelling — and `'App\{..}'`
were accepted and printed by `--autoload-map` verbatim, and failed only as an `E0303` on the first
class they were meant to find.

`check_file_shape` compared only the declared short name with the file name. A root mapped as
`Nonsense` holding a file that declares `App\Blog\View\Index` passed; with the `implementing` scan the
class then existed in the program, and without the scan it was `E0303`. Whether a name exists
depended on whether something enumerated a root — the order dependence the one-declaration rule was
written to rule out, reached through the namespace instead of through a second declaration.

## Decision

### 1. A `{..}` segment

One whole segment of an explicit prefix may be `{` + a path of `.` and `..` steps + `}`. It is replaced
by the last component of that path, resolved against the declaring file's directory and canonicalized,
so `{.}` is that directory's own name and `{..}` its parent's, spelled as the disk spells it. It is
resolved while the map is built, so the map, `implementing` and `--autoload-map` see only the result.
At most one segment of a prefix may be braced.

### 2. Every prefix segment is a namespace segment

A written segment, and the name a braced segment reads, must pass the same `PascalCase` test
`discover` applies to a directory. A prefix failing it is `E0327`, `E_AUTOLOAD_PREFIX_SHAPE`, at the
declaration. A borrowed site reports nothing, as for every other borrowed diagnostic.

### 3. An autoloaded file declares the name the map finds it by

`check_file_shape` receives the full name the probe or the scan derived — prefix, directories, file
stem — and compares it with the declaration's name under the namespace in force where it stands. A
short-name difference keeps its message; a namespace difference says which name the file declares and
which name the map finds it as. Both are `E0317`.

### 4. A missing root is listed

A root that does not exist remains legal: a deployment leaves a module out by not shipping its
directory (`rule:programs/no-runtime-autoload`). `--autoload-map` gains a counted `missing` section
listing each prefix and root that is not a directory, and a missing root is made canonical as far as
the disk allows so it prints beside the others. A whole path loses Windows' `\\?\` prefix when printed.

## Consequences

- Performance and memory: one canonicalization per braced segment while compiling, and nothing at run
  time. The compile cache already keys a unit on its entry's path, so identical entry files in two
  directories never share a unit.
- Security: path traversal stays impossible. A braced segment produces a namespace segment that
  passes the same test as any other, never a path, and probing still builds suffixes only from
  namespace segments.
- A program's meaning now depends on a directory's name where it writes `{..}`. Renaming the directory
  renames the namespace, and every class under it then fails `E0317` loudly. `discover` already had
  this property.
- A program that relied on a file declaring a namespace other than its map path no longer compiles.
  Every such file was reachable only by accident.

## Alternatives rejected

- **A PSR-4 wildcard, `'App\*' from '../../*/src'`.** It maps every module into every program, which
  is § 1's problem, and needs a second feature — roots that resolve by name but are not enumerated —
  before it is usable. It would still need a way to name the current module.
- **`discover` taking a prefix.** Same problem: it maps every directory the glob matches.
- **`*` instead of `{..}` inside a prefix.** A reader coming from PSR-4 reads `*` as a wildcard, which
  is the meaning this form does not have.
- **A missing root as an error.** It reverses the rule that a deployment omits a module by omitting
  its directory.
- **The scan skipping a file with the wrong namespace.** The mistake would stay invisible.
