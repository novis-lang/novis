# ADR 0273 — Coverage reports carry functions, branches and per-test lines, and `nvs test` writes Cobertura beside lcov and Clover

- **Scope:** what a coverage report holds beyond lines: function coverage, branch coverage from a probe on
  every conditional edge, a third format under `--coverage-cobertura <FILE>`, the lines each test reached
  in the `--format json` document, and the VS Code coverage profile that reads the lcov file. Choosing
  which files a report covers, an HTML report and merging the reports of several runs are not decided
  here.
- **Depends on:** [0235](0235.md) (line coverage, the shared table and how a file is named), [0018](0018.md)
  and [0041](0041.md) (the probe sites and the one flag word they check).
- **Validated by:** `crates/nvs-cli/tests/test_coverage.rs`, `crates/nvs-codegen/tests/probes.rs` and
  `editors/vscode/test/surfaces/tests.test.ts`.

> **In short:** lcov and Clover gain function coverage, read from the statement counts: a function is an
> `nvs_ir::Function`, named `Class::method`, at the line of its first statement and with that
> statement's count. `--coverage-cobertura <FILE>` writes the same table as Cobertura XML. Codegen emits
> `rule:testing/debug-probes`'s second site on both edges of every `Terminator::Branch`, numbered across
> the program by a per-function base as statements are, and counted under `DebugFlags::BRANCH` into a
> second table beside `StmtHits`; every coverage flag turns both bits on, and all three formats carry the
> branches. Under a coverage flag the `--format json` document is `schemaVersion: 3`, and each test record
> lists the lines that test reached. The VS Code extension adds a Coverage run profile that reads the lcov
> file into the editor's own coverage view. A run without a coverage flag allocates nothing, and its
> compiled code differs from today's only by the edge probe's load and branch.

## Context

ADR 0235 shipped line coverage in lcov and Clover and left four things to a later decision: branches,
per-test lines, a third format and the editor. CI services read more than lines. GitLab and Azure DevOps
read Cobertura, reviewers ask which side of a condition no test took, and lcov's and Clover's function
records are what most coverage dashboards summarise first. The IR already names both edges of a
conditional branch (`then_edge`, `else_edge` on `Terminator::Branch`) and `DebugFlags::BRANCH` was
reserved for them, but codegen emitted nothing on an edge.

## Options considered

1. **Function counts from a probe of their own at entry.** Rejected: a function's first statement is
   already probed, and runs exactly when the function does unless the function has no statement. A
   second site would cost every call a load and a branch for a number the table already has.
2. **Function counts from the first statement's count.** Chosen. A function with no statement has no
   probe, so it is not listed, which is the same rule a line follows.
3. **Branches from the statement counts**, as the difference between a condition's count and the count
   of the first statement of each side. Rejected: a side with no statement of its own, such as an `if`
   with no `else`, has nothing to subtract, and the result would be a guess.
4. **A probe on every conditional edge.** Chosen. It is the site `rule:testing/debug-probes` already
   names, using the edge identity the IR carries, so every count is an edge's.
5. **Per-test lines from a table per test.** Rejected for now: the runner runs one test at a time, so the
   shared table's counts after a test minus its counts before name exactly that test's lines, at the
   cost of one copy of the table per test. A parallel runner changes this, and gives each test a table
   of its own.

## Decision

### 1. Functions

The function table comes from the same walk over `Program::functions` as `Program::stmt_spans`, read
before the program is dropped. Each entry is a function's name, the line of its first statement and
that statement's number. lcov writes `FN`, `FNDA`, `FNF` and `FNH`. Clover writes `<line type="method">`
and the `methods` and `coveredmethods` metrics.

### 2. Cobertura

`--coverage-cobertura <FILE>` writes one `<package>` per directory, one `<class>` per file and one
`<line number hits>` per line, with `line-rate` at every level. The table that feeds lcov and Clover
feeds it, so the three files cannot disagree about a count. It follows ADR 0235 § 4: it writes a file,
works beside a machine `--format`, and is refused beside a `.nvst` tree and `--list`.

### 3. The edge probe

Each edge of a `Terminator::Branch` gets one load of the flag word and one predicted-not-taken branch,
and calls an out-of-line `nvs_probe_edge(ctx, edge)` under `DebugFlags::BRANCH`. Edge numbers get a
per-function base as statement numbers do, and `Program::edge_spans` lists them in that order. The
counts go into a second table of atomic counters beside `StmtHits`, handed down to every child context
the same way. Novis code cannot read it.

### 4. Branches in the reports

A branch is one `Terminator::Branch`, and its two edges are its two sides. lcov writes
`BRDA:<line>,<block>,<side>,<count>`, with `-` for a side whose branch never ran, and `BRF` and `BRH`.
Clover writes `<line type="cond" truecount falsecount>` and the `conditionals` metrics. Cobertura writes
`branch="true"` and `condition-coverage` on the line, and `branch-rate`. Every coverage flag turns both
bits on; there is no flag for lines without branches.

### 5. Per-test lines

Only under a coverage flag, the `--format json` document is `schemaVersion: 3`, and each `tests[]` record
gains `coverage`: each file name mapped to the sorted list of lines that test reached at least once in any
attempt. A run without a coverage flag writes the version 2 document unchanged.

### 6. The editor

The VS Code extension adds a run profile of kind `Coverage` beside its Run profile. It runs the same
command with `--coverage-lcov` pointing into the extension's storage directory and adds one
`FileCoverage` per `SF` record, with its statement, branch and function counts. It draws nothing of its
own (`rule:ide/the-extension-builds-no-ui-the-editor-already-has`).

## Consequences

- **Performance:** one more load and predicted-not-taken branch per conditional edge in every compiled
  unit, whether or not a run asks for coverage. Under the flag, one relaxed atomic add per edge taken.
  The statement probe's bench pins the no-flag cost.
- **Memory:** per run that asks, one `u64` per edge in the program beside the statement table, and one
  copy of the statement table per test while a JSON document is being written. Nothing for a run that
  does not ask.
- **Usability:** Cobertura is the format GitLab and Azure DevOps read, branches are what reviewers ask
  for, and the editor shows the result in its own view.
- **Simplicity:** one more flag and one more probe site. The JSON document has a third version, written
  only under a flag.

## Verification

`crates/nvs-cli/tests/test_coverage.rs` pins each format's function, branch and line records and the
JSON document's per-test lines. `crates/nvs-codegen/tests/probes.rs` counts both edges of an `if`, a
`while`'s exit and re-entry and a `match` arm, and asserts a run without the flag calls `nvs_probe_edge`
zero times. `editors/vscode/test/surfaces/tests.test.ts` feeds a fixed lcov file through the reader.
