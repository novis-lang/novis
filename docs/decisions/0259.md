# ADR 0259 — A string or a `.` chain converts to an html literal through one refactor the language server computes, and no fix-all applies it

- **Scope:** one editor code action, its kind, the VS Code command that applies it, and the boundary that every
  other code action is a diagnostic's suggestion. The html literal's grammar and every program's behaviour are
  unchanged.
- **Depends on:** [0099](0099.md), [0040](0040.md).
- **Validated by:** the unit tests in `crates/nvs-lsp/src/html_literal.rs`,
  `the_html_literal_refactor_has_its_own_kind_and_is_never_in_a_fix_all` in `crates/nvs-lsp/tests/actions.rs`,
  and the `.lspt` cases under `tests/lsp/actions/` that name `rule:ide/a-string-converts-to-an-html-template`.

> **In short:** a cursor on a string, or on an operand of a `.` chain with a string in it, is offered
> **Convert to html literal**, kind `refactor.rewrite.htmlLiteral`. The server computes the literal
> from the expression alone, parses it back to check that it prints the same text with the same holes,
> and offers nothing when it cannot. It is the one code action with no diagnostic behind it, and it is
> never under `source.fixAll.nvs`, because applying it changes what the line prints. The VS Code
> command `nvs.convertToHtmlLiteral` only asks the editor to apply that kind.

## Context

The html literal (`rule:core-classes/html-template`) is how markup is marked as markup, and code
arriving from PHP writes the same markup as strings: `"<b>" . $name . "</b>"`, or a double-quoted
string with `$name` in it. Converting one by hand means re-escaping every `"`, `$` and backtick, and
turning each concatenated value into a hole. That is mechanical, and a mistake in it changes the
page.

`rule:ide/a-code-action-ships-only-a-fix-a-diagnostic-already-knows` admitted a code action only
where a diagnostic already carries its replacement text, and left anything the server would compute
to M10. M10's acceptance asks that refactorings arrive as LSP code actions with no logic duplicated
in a client, which PhpStorm, talking to the same server, depends on. This conversion is pulled
forward from M10 by the project owner's decision; nothing else is.

## Investigation

The html literal's segment grammar is the double-quoted one plus two escapes, `` \` `` and `\{`
(`nvs_syntax::string_lit`'s `MARKUP_ESCAPES`). Its holes are the double-quoted string's `{$…}` and
simple `$name`, scanned by the same lexer code, and `<?= … ?>`. So a double-quoted string's text runs,
escapes and holes carry over almost unchanged. The differences are few: `\"` is not needed; a
`` \` `` or `\{`, which a double-quoted string prints as two characters, is one character in the
literal; a raw backtick closes the literal; a raw `<?=`, `<?nvs` or `<?php` opens a tag; and a raw
`{Name::X}` draws `W1012`. Each has a spelling that keeps it text: `\\`, `` \` ``, `\{`, and `\x3C`
for the `<`, since `\xHH` is in the shared grammar.

A single-quoted string has no holes, so each `$` that would start one is written `\$`, which the
shared grammar reads as `$`. A heredoc or nowdoc is dedented by the indentation of its closing label
(`nvs_syntax::string_lit::dedent_heredoc_run`), and the literal has no such rule, so converting one
would mean re-indenting its body.

## Options considered

### 1. A code action the server computes

The server finds the string or chain at the cursor through `SyntaxIndex`
(`rule:ide/the-index-answers-the-cursor`), parses that expression on its own, writes the literal, and
answers it as a code action. Every client gets the same edit.

### 2. A command in the VS Code extension

The extension rewrites the selected text with its own TypeScript. It would need its own copy of the
lexer's escape and hole rules, and PhpStorm would need a third.

## Decision

Option 1.

### 1. What converts, and what does not

A double-quoted or single-quoted string converts, on its own or as an operand of a `.` chain. In a
chain, a variable or a property or offset read on one becomes a `{$…}` hole, and any other operand a
`<?= … ?>` hole. A bare `$name` hole at the end of a string that another operand follows is braced, so
it does not run on into that operand's text. A heredoc and a nowdoc are not offered. Neither is an html
literal, a string in a template region or an attribute payload, which `SyntaxIndex` holds no node for,
or a string at an array key, a subscript, a `case` label, a `match` condition, a constant's value or a
`require`, `use` or `autoload` path. A chain with a comment between operands is not offered, since the
rewrite would drop it. The result is not type-checked: the preview is the review.

### 2. The literal is checked by parsing it back

The literal written is parsed with the real parser. Its segments, cooked by the literal's own
cooker, must equal the original's cooked text, and its holes must be the original expressions, in
order. A string the escaper gets wrong is therefore offered nothing rather than an edit that prints
something else, and a later change to either grammar is checked here without this code learning it.

### 3. Its own kind, and never a fix-all

The action is filed under `refactor.rewrite.htmlLiteral`, a sub-kind narrow enough that a client
asking for it gets this action alone, and the server advertises it in `codeActionKinds`. It is
offered beside the quick fixes and never under `source.fixAll.nvs` or `quickfix`. A plain string
echoed is escaped as text, and a literal's segments are markup, so applying it changes the output.
That is why it is a refactor a person chooses, and not a fix a save may apply.

### 4. The VS Code command applies the server's action

`nvs.convertToHtmlLiteral`, "Convert to html literal", in the command palette and the editor context
menu for Novis files, runs `editor.action.codeAction` with the kind above, `preferred: false` and
`apply: "ifSingle"`. It holds no conversion logic.

## Consequences

- No runtime cost: the action edits source and nothing it writes is new to the compiler.
- Per code-action request on a string: one parse of the expression under the cursor for each `.`
  above it, one of the literal written, and one per enclosing array or `match` checked for a key
  position, each the size of that expression and dropped with the answer.
- `rule:ide/a-code-action-ships-only-a-fix-a-diagnostic-already-knows` now admits exactly one
  computed action. Any further one is still M10's and needs its own record.

## Alternatives rejected

- **Offering only the literal under the cursor inside a chain.** The result is a `Markup`
  concatenated with a string, which is not what anybody converting a chain wants.
- **Re-encoding each string from its cooked value.** It is simpler, and it turns every `\n` into a
  real line break and every `\x41` into its character, so the source changes more than the conversion
  needs.
- **Converting a heredoc by re-indenting its body.** The dedent and the escapes interact, and the
  case is rare next to strings and chains; it can be added under this record's rule if it is wanted.
