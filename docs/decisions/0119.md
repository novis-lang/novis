# ADR 0119 — An expression-level `catch` is a typed arm on one guarded expression, and it lowers to the block form

- **Scope:** the expression form `expr catch (Class $e) => expr`, its grammar, precedence, result type,
  the rule for what an arm may hold, the two diagnostics that keep it honest, and what it lowers to. Not
  in scope: the block form `try { … } catch (…) { … } finally { … }`, which is unchanged in every
  particular and stays the only home of `finally` ([docs/reference/lang/40-statements.md](../reference/lang/40-statements.md)
  § *try, catch, finally*); the exception hierarchy and what a `catch` may name, which
  [0020](0020.md) § 0 owns; and the non-throwing conversion `as ?T`, which
  [0066](0066.md) owns and this form does not replace.
- **Depends on:** [0002](0002.md) — the landing pad and the checked-return ABI this
  form reuses without adding to; [0020](0020.md) — a limit report is not a
  `Throwable`, so it is no more catchable here than in the block form.

> **In short:** `var $cfg = Core\Json::parse($raw) catch (ParseError) => [];` guards one expression and
> supplies a value where it threw. An arm is `catch (Class [$var]) => expression`, the class is
> mandatory, and arms chain — `f() catch (IOError) => 0 catch (ParseError $e) => throw new
> LogicError("bad", {previous: $e})` — tried in order exactly like the block form's clauses. **The arm's
> body is an expression, and that one word is the whole rule for what it may hold**: `throw` is already
> an expression in Novis, so wrapping a failure and rethrowing it is one line, while `return`, `break`
> and `continue` are statements and are refused by name. The result type is the union of the guarded
> expression's type and every arm's, a `throw` arm contributing nothing — the rule `match` already has.
> There is no `finally` and no run-time mechanism of its own: the form lowers to the same landing pad,
> the same `instanceof` dispatch and the same re-raise `try` lowers to, with the value in a temporary.

## Context

- **Novis throws where PHP warned, and every throw is a `try` block.** [0007](0007.md)
  § 7 makes a failed conversion and an absent array key throw; [0063](0063.md) R4
  makes every `Core` failure throw; arithmetic overflow and division by zero throw. Each of those is
  right, and each costs the caller a five-line block to supply a fallback. The repository's own Novis
  code has 1037 `try` blocks, 557 of which are one statement in the `try` and one in the `catch`.
- **The two most common cases are already value-shaped, and this form sits beside them, not over
  them.** `$s as ?int ?? 1` ([0066](0066.md)) is the conversion, and
  `$a["k"] ?? $d` ([0007](0007.md) § 7 row 11) is the absent key. Neither reaches
  a `Core` call that fails, an arithmetic throw, or a user class's own exception, and this ADR exists
  for those.
- **Definite assignment prices the block form higher than it looks.** A local assigned inside `try` is
  readable after the block only when every `catch` also assigns it, so the common shape is a bare
  declaration, a two-branch assignment and the read — three places to keep in step. An expression
  assigns on every path it completes, so the declaration and the fallback are one line and the
  checker has nothing to track.
- **The shapes the industry has tried.** Go has no shorthand at all — `v, err := f(); if err != nil`
  costs three lines per call and is the language's most-cited complaint; its `try()` proposal was
  abandoned in 2019. Rust's `?` needs a `Result` type Novis has not got. Swift's `try? expr` yields an optional
  and catches *everything* untyped. Zig's infix `catch` guards one expression with a fallback, and is
  the shape taken here, with `match`'s `=>` supplying the arm spelling Zig lacks.

## Decision

**A `catch` arm is a postfix on an expression. It names one class, optionally binds the thrown object,
and supplies an expression whose value stands in where the guarded expression threw. Arms chain, and
the whole thing lowers to the block form.**

### 1. The grammar

```
CatchExpr := Ternary ( "catch" "(" Type Variable? ")" "=>" Ternary )*
```

`Type` is one class or interface under `Throwable`, resolved and checked exactly as the block form's
`catch (T $e)` is — the same `E0` codes for a name that is not a class, a class that is not a
`Throwable`, and [0020](0020.md) § 0's limit report. A union (`A | B`) is
refused with the block form's own wording, *write two arms*. The variable is optional, as in the block
form, and where bound it is a local of the enclosing function under the block form's rule
(`crates/nvs-types/src/locals.rs`'s `catch` binding), so an arm's `$e` is the same kind of name a
clause's `$e` is.

Arms are **clauses of one guard, not guards of each other**: `f() catch (A) => x catch (B) => y` tries
`A` then `B` against what `f()` threw, and `x` is not guarded by the `B` arm. This is the block form's
"any number, tried in order; the first whose class matches runs", and it is the reading a chain of
clauses already has. A supertype written first shadows the arms after it, as in the block form.

### 2. Precedence

`catch` sits **between assignment and the ternary**: `parse_assignment` → `parse_catch` →
`parse_ternary` in [`nvs_syntax::parser::expr`](../../crates/nvs-syntax/src/parser/expr.rs)'s chain. The
guarded expression is everything the ternary level parses, so one arm covers a whole `??` chain or a
whole `?:`, which is what a reader expects of a guard; the arm body is parsed at the same level, so a
following `catch` starts the next arm of the same guard rather than nesting under the fallback.

| written | groups as |
|---|---|
| `$x = $a / $b catch (ArithmeticError) => 0` | `$x = (($a / $b) catch … => 0)` |
| `$x = $m["k"] ?? f() catch (IOError) => ""` | `$x = (($m["k"] ?? f()) catch … => "")` |
| `f() catch (A) => $y ?: 1 catch (B) => 2` | `f() catch (A) => ($y ?: 1) catch (B) => 2` |
| `f() catch (A $e) => throw new B({previous: $e})` | the `throw` takes everything to its right, PHP's own rule for `throw`, so a `throw` arm is written last or parenthesised |

An assignment inside an arm is parenthesised, as it is inside a ternary arm. Two parses this rules out
by construction: `try` never appears in the expression form (the guard starts at the expression, not at
a keyword), and `catch` after an expression can only be this form, because the block form's `catch`
follows a `}` the statement parser is already inside.

### 3. An arm holds an expression — which admits `throw` and refuses `return`

The arm body is parsed as an expression and that is the entire rule. Two consequences follow without a
word of their own:

- **`throw` is allowed**, because `throw expr` is already an expression
  ([docs/reference/lang/30-expressions.md](../reference/lang/30-expressions.md): *"it sits on the right
  of `??`, `||` or a ternary arm"*). `f() catch (IOError $e) => throw new IOError("count failed",
  {previous: $e})` wraps and rethrows in one line, and the variable on the left is never assigned —
  the same answer `$x = $y ?? throw new …` already gives. `nvs_types` types a `throw` as `never`, so
  the arm contributes nothing to *4*'s union.
- **`return`, `break` and `continue` are refused**, because they are statements. The parser names them
  rather than reporting a generic expected-expression: **`E0126`**, *an arm is an expression — `throw`
  is one, `return` is not; for an early return write the block form*. The refusal is deliberate and
  not a gap to fill later: a `return null` on an `IOError` hides a failure, and the block form's five
  lines are the right price for that choice.

### 4. The result type is the union of the sides — `match`'s rule

The expression's type is the union of the guarded expression's type and every arm's, computed by the
same `make_union` that types a `match` (`crates/nvs-types/src/expr/mod.rs`, the `ExprKind::Match`
arm). `int $rows = $db->count($q) catch (IOError) => 0;` is `int`; `catch (IOError) => null` makes it
`?int`, and the declaration on the left refuses that with the mismatch diagnostic it already has. No
new rule, no new code: the arm is checked against nothing but the position the whole expression sits in.

An arm is checked from the **pre-guard** definite-assignment state, as a block clause is
(`crates/nvs-types/src/locals.rs`, the `StmtKind::Try` arm): a local the guarded expression assigned
cannot be assumed assigned inside the arm, because the arm runs precisely when the guard did not
complete.

### 5. `catch (Throwable) => value` with no binding warns

**`W1006`**, a warning under `nvs check` — in the `W1xxx` band, where every warning the compiler has
lives: an arm naming `Throwable` **and binding no variable** whose
body is not a `throw`. In the block form a `catch (Throwable)` has a body with room to log or
re-raise; in the expression form the body is the value, so an unbound `Throwable` arm is by
construction *discard every failure, including the ones not anticipated* — PHP's `@` operator, which
[0007](0007.md) § 7 removed, regrown as a one-liner. The warning names the two
honest spellings: name the class the site expects, or bind `$e` and carry it. It is a warning and not
an error for the reason [0066](0066.md) § 6 gives for its own: the
hazard is a habit, not a type error, and `nvs check` is where habits are named.

### 6. Lowering is the block form's, with the value in a temporary

There is no run-time representation of the expression form. `nvs_ir::lower::Lowering::lower_try`
(`crates/nvs-ir/src/lower/exception.rs`) already does everything the form needs — push the protected
region, lower a body, take the thrown reference in the handler block, dispatch by `instanceof` chain,
re-raise what no arm matched, join — and the expression form differs in exactly one way: the body and
each arm produce a value, which is written to one temporary and joined by a phi, the way `lower_match`
joins its arms (`crates/nvs-ir/src/lower/expr.rs`). Nothing in `nvs-runtime` or `nvs-codegen` changes,
[0002](0002.md)'s landing pad is the one already emitted, and the cost of a guarded
expression that does not throw is the cost of the block form's: zero on the happy path.

### 7. What this does not change

- **The block form**, in every particular, and it remains the only spelling with `finally`. Resource
  cleanup stays there; this ADR gives it no one-line twin.
- **`as ?T` and `?? $d`** — [0066](0066.md) and [0007](0007.md)
  § 7 row 11 stay the spellings for a conversion and an absent key. `$s as int catch (…) => null` is
  legal and pointless, and `nvs check` may say so later; it is not a diagnostic here.
- **What may be caught.** [0020](0020.md) § 0's rule that a limit report is not
  a `Throwable` holds unchanged, and the type checker refuses it in an arm with the same code it uses
  for a clause.

## Consequences

- **Priority 4, the language surface**, is where this is paid and earned: one more expression form, in
  exchange for the five-line block that today follows every failable call whose caller has a fallback.
  Priorities 1–3 are untouched: the same landing pad, the same dispatch, the same re-raise, and nothing
  a program could previously catch or fail to catch changes.
- **Zero memory cost.** The temporary is a value slot the block form's assignment already needs.
- **The checker gains one arm and one warning**, and no new typing rule — *4* is `match`'s union, *3*'s
  `never` is `throw`'s existing type, and the class check is the clause's.
- **The reference chapter gains one section** beside the block form's, generated by `python
  tools/reference.py` and proved by its examples like every other.
- **Every consumer of the AST that walks `ExprKind::Match` walks the new node too** — `nvs-syntax`'s
  casing pass, `nvs-hir`'s member and require walkers, `nvs-types`, `nvs-ir`'s two walkers — which is
  the whole file set of the change and why it is one loop stage rather than a scattering.
- **`nvs convert` (M11)** has nothing to map onto this: PHP has no expression `catch`, so no PHP program
  contains one, and no converted program gains one. It is not a row in `docs/divergences.md`
  for the same reason.

## Alternatives rejected

- **Extending `??` to swallow any throw.** PHP's `@` with a nicer face: untyped, discards the object,
  reads as a null check. Every reason [0007](0007.md) § 7 throws on garbage
  evaporates the moment the fix is one `??` away.
- **Swift's `try? expr` yielding `?T`.** Untyped, so it catches everything; it conflates *threw* with
  *returned `null`*, a trade [0066](0066.md) § 2 accepted for `as ?T`
  only because the developer wrote the `?? 1` beside it; and it lands every result in the `?T`-in-a-
  condition trap [0066](0066.md) § 6 lints. Redundant with `as ?T` for the
  case it does best.
- **Admitting `return` in an arm**, as Zig does (`catch return err`). The arm would then hold either a
  value or a departure with nothing in the spelling to say which, and the first example ever written
  for this ADR was misread that way by its own reviewer. *3*'s expression rule keeps the one departure
  that is already an expression and refuses the rest by name.
- **A bare fallback with no `=>`** — `f() catch (IOError) 0`. The value dangles after the parenthesis
  with nothing to say it is the result; `match` already owns the `condition => value` spelling and
  the reader already knows it.
- **A braced multi-arm form** — `f() catch { IOError => 0, ParseError $e => throw … }`. Unnecessary once
  arms chain under *1*, and it is a second spelling of the same thing.
- **Go's comma-ok.** Needs a tuple return Novis has not got, and it is the shape Go is criticised for.
- **A `Result` type and Rust's `?`.** A sum type is a language-scale decision;
  [0066](0066.md) rejected it for conversions and the reasoning is the same
  here.
- **A `try` keyword opening the guard** — `try f() catch …`. A token that carries no information: the
  guard starts where the expression does, and an unguarded throw already propagates without a keyword,
  which is the only thing Zig's `try` adds.

## Revisiting

- **A lint on `$s as int catch (…) => null`** naming `as ?int`, once `nvs check` has a habit pass
  that can see both spellings; *7* leaves it out rather than guessing at its wording.

## Verification

- **M1 (parser):** `crates/nvs-syntax/src/parser/tests/expr.rs` — one arm and a chain parse as arms on
  the one guarded expression; the guard covers a `??` chain and a ternary; an arm body covers a ternary;
  a `return` at the head of an arm is `E0126` naming the block form; a union type in an arm is refused
  with the block form's wording.
- **M2 (checker):** a `nvs-types` fixture typing `f() catch (E) => 0` as `int` when `f(): int`, `=>
  null` as `?int`, and a `throw` arm as the guard's own type; an arm reading a local the guard assigned
  is a read-before-assignment; a class that is not a `Throwable` and [0020](0020.md)
  § 0's limit report are refused with the clause's own codes; `catch (Throwable) => 0` warns `W1006`
  and `catch (Throwable $e) => throw new …` does not.
- **M3 (lowering) and the corpus:** `tests/conformance/lang/` cases for the value where the guard
  threw and the guard's own value where it did not; arms tried in order with a supertype first
  shadowing; what no arm matched leaving the frame carrying the same object; a `throw` arm leaving
  through an enclosing block form's `finally`; and `tests/conformance/reject/` for `E0126`.
- **The reference:** [docs/reference/lang/40-statements.md](../reference/lang/40-statements.md) gains a
  section beside the block form's whose examples `python tools/reference.py` runs.
