# ADR 0196 — `nvs.exe` carries the logo as its icon and the manifest's facts as its version information, written by the build script itself

- **Scope:** what the Windows binary says about itself to the operating system — its icon, its version
  information, which build gets which — and how that is compiled in. An application manifest, a code
  signature, and an icon of an author's own on a `nvs build --compile` bundle are not decided here.
- **Depends on:** [0065](0065.md), [0151](0151.md).
- **Validated by:** `crates/nvs-cli/tests/windows_resource.rs`, and the reading under *Verification*.

> **In short:** on a Windows MSVC target `build.rs` writes a compiled resource file by hand and links
> it. A release build carries the logo, a debug build the test file's mark and the words
> `(debug build)`. The version information is filled from the workspace manifest, `LICENSE` and the
> commit, so nothing is stated a second time, and the build gains no dependency and runs no tool.

## Context

`nvs.exe` had no resources. In Explorer it drew the generic program icon, *Properties → Details* was
empty, and Task Manager and the firewall prompt `nvs serve` raises named it by file name. `php.exe` is
the comparison a Novis user brings: it carries a product name, a version, a company and a copyright.
The developer also asked for the debug binary to be told apart from the release one at a glance, since
both are named `nvs.exe` and both sit on a contributor's machine.

Every fact such a block states is already in the tree: `[workspace.package]` has the version, authors,
license, description and homepage, `LICENSE` has the copyright line, and `build.rs` already captures
the commit for `nvs info`.

## Options considered

1. **A build dependency that drives the resource compiler** — `winresource` or `embed-resource`. They
   find and run `rc.exe` from the Windows SDK, or `windres`. It is the common answer, and it adds a
   crate to a build script whose own module doc declines a TOML parser on supply-chain grounds, plus a
   tool lookup that can fail a build.
2. **A checked-in `.rc` file compiled by hand into a checked-in `.res`.** No build-time tool, but the
   version and the commit are then frozen in a binary blob nobody regenerates.
3. **`build.rs` writes the `.res` file itself.** The format is an entry header and two payload layouts,
   `GRPICONDIR` and `VS_VERSIONINFO`, and the MSVC linker accepts the file as an input.

## Decision

### 1. `build.rs` writes the resource and links it

Option 3. `crates/nvs-cli/build/winres.rs` builds the file from an `.ico` and a list of strings, and
`build.rs` passes it with `cargo:rustc-link-arg-bins`. It runs when the target is Windows with the MSVC
environment, which is both targets `release.yml` builds. Every length is written through a checked
conversion, and an input that does not fit links nothing and warns; the build script's rule that it
never fails a build holds.

### 2. The debug build has its own icon and says so

The profile picks the file: `assets/nvs.ico` from `website/media/novis-logo.png` for release,
`assets/nvs-debug.ico` from `novis-logo-file-icon-light-theme-nvst.svg` for debug. The debug build's
`FileDescription` is `Novis (debug build)` and its fixed flags carry `VS_FF_DEBUG`. The description is
the string Task Manager and the firewall prompt show, which is why it is the product's name and not a
sentence about it.

### 3. The icons are committed, and a script cuts them

A build must not need ImageMagick, so the two `.ico` files are committed. `tools/exe-icons.py` cuts
them the way `website/README.md` cuts the favicon — trimmed, one resize per size, each sharpened for
its size — at the sizes Windows picks from between 100% and 250% scaling.

### 4. The strings come from where they already live

The rule's table is the mapping. The commit rides in `ProductVersion` as semver build metadata. No
date field is set, which keeps [0065](0065.md)'s reproducible build.

## Consequences

- A bundle from `nvs build --compile` is a copy of the host and so carries Novis's icon and version
  information. Before this it carried none. An author who wants their own needs a resource editor
  until a record gives the bundler an `--icon`.
- The binary grows by the icon's bytes, read by nothing on a request path.
- A GNU-targeted Windows build has no resource. Nothing ships from one.
- The test binary of the `nvs` target is linked with the same resource, which costs nothing.

## Alternatives rejected

- **An application manifest in the same file.** The linker already embeds its default manifest, a
  second one is a duplicate-resource error without `/MANIFEST:NO`, and what a manifest would change —
  the active code page, long paths — is behaviour and deserves its own record.
- **The release icon on both builds.** The debug binary is the one a contributor runs by accident when
  measuring, and an icon is the cheapest place to say so.

## Verification

`(Get-Item target\debug\nvs.exe).VersionInfo` in PowerShell, which asks the operating system's own
parser, returns every string and `IsDebug : True`, and
`[System.Drawing.Icon]::ExtractAssociatedIcon` returns the debug mark. The test walks the linked
binary's resource directory with the `object` crate, which shares no code with the writer.
