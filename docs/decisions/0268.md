# ADR 0268 — a file that declares one type shows its kind beside its name, as the editor's own file decoration fed by `nvs/fileKinds`

- **Scope:** how an editor's file list tells a class file from an interface, enum or `type` alias file,
  and the seventh request of Novis's own that answers it. What shape an autoloaded file must have
  stays `rule:programs/one-declaration-per-autoloaded-file`'s.
- **Depends on:** [0099](0099.md), [0101](0101.md), [0201](0201.md).
- **Validated by:** `crates/nvs-lsp/tests/autoload.rs`'s `a_file_that_declares_one_type_is_listed_with_its_kind`
  and `editors/vscode/test/client/kinds.test.ts`.

> **In short:** an autoloaded file declares exactly one class, interface, enum or `type` alias, so a
> directory of them is a directory of types whose kind the file list cannot show: every `.nvs` file has
> the same icon. The server now answers `nvs/fileKinds` with every indexed file of that shape and its
> kind, read once per file where the index already reads it, and the VS Code client draws the answer as
> a file decoration — a letter beside the name and the theme's own colour for that kind of symbol.

## Context

### 1. The icon cannot say it

VS Code chooses a file's icon from its extension, its name or its language, and never from what the
file contains; an icon theme has the same three inputs. Every `.nvs` file therefore has one icon,
whatever it declares. The one per-file surface that reads anything else is a file decoration
(`FileDecorationProvider`): a badge of one or two characters, a tooltip and a colour, drawn in the
Explorer, on the editor tab and in Open Editors. The colour applies to the name and the badge, and
the icon is left as it is.

### 2. The client may not decide it

`rule:ide/one-server-two-thin-clients` keeps every judgement about the language in the server, so the
client cannot find the kind by matching `class` or `enum` in the text. The server's index already reads
every file the workspace pass or an open document reaches, which is the test
`rule:ide/the-request-set-is-closed` sets a new request: the structure the milestone builds is the
answer.

## Decision

### 1. The shape is the autoload shape, scanned once

A file is listed when it has the shape `rule:programs/one-declaration-per-autoloaded-file` holds an
autoloaded file to: one class, interface, enum or `type` alias, and nothing else but `namespace` and
`use`. `nvs_hir::autoload::sole_declaration` is that test, and it is the scan the shape check itself
runs, so the shape the editor shows and the shape the compiler accepts cannot disagree. A file reached
by `require` with the same shape is listed too: it declares one thing just as plainly, and asking how a
file was reached would need an edge the loaded file does not keep.

### 2. `nvs/fileKinds` answers the whole list

The request takes no parameters and answers `[{uri, kind}]`, `kind` being `class`, `interface`, `enum`
or `type`, for every file the index holds with that shape. The index records the kind when it reads the
file, so an answer is one pass over its file map and no analysis. The server does not watch `.nvs` files
on disk, so the list follows what the index holds: the client asks when a server starts answering,
after `nvs.checkWorkspace`, and when a Novis document is opened or saved, and several asks close
together are one.

### 3. The colour is the theme's

`rule:ide/novis-ships-names-not-colours` gives colour to the user's theme, and the manifest contributes
no `colors`. The decoration's colour is a `ThemeColor` the editor already defines for the same kind of
symbol in the Outline and in completion — `symbolIcon.classForeground`,
`symbolIcon.interfaceForeground`, `symbolIcon.enumeratorForeground` and
`symbolIcon.typeParameterForeground` — so a theme that colours a class one way colours a class file the
same way. A theme that gives two kinds one colour still shows two letters.

### 4. A sixth reader of the one index

`rule:ide/five-features-are-one-reference-index` counts the index's readers, and this is one more. It
is not a reference feature: it asks what a file declares, not where a name is used. It reads the index
rather than walking the front end, which is what that rule exists to hold, so the rule names it beside
the five rather than the request building a second structure.

## Consequences

The server holds one more field per indexed file and answers one more request; no analysis is added.
The badge shares the decoration slot with source control, so a modified class file may show the
source-control badge and colour in place of its kind. A file changed outside the editor keeps the kind the index
last read until it is opened or a workspace pass runs, the same staleness every index reader has. No
setting is added: a user who wants another colour sets the theme colour, which also changes the Outline.
