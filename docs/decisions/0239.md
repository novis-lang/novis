# ADR 0239 — A union that holds `float` is a `float` position for an `int` or `uint` value whose type the union does not name

- **Scope:** How an `int` or `uint` value is stored where the declared type is a union holding `float`:
  `?float`, `float|string`, `float|Shape`. A plain `float` target already converted, and an existing
  array or shape value is [0238](0238.md) and [0236](0236.md).
- **Depends on:** [0007](0007.md) and [0054](0054.md) (the `int` → `float` widening is the one implicit
  conversion), [0238](0238.md) (the element of an array literal is placed at its element type).
- **Validated by:** `tests/conformance/lang/an-integer-stored-at-a-union-holding-float-becomes-a-float.nvst`
  and `nvs_ir`'s `an_int_at_a_union_holding_float_converts_before_it_is_tagged`.

> **In short:** where a value is stored at a union that names `float` and not the value's own integer
> type, an `int` or `uint` is converted to `float` exactly as at a plain `float` position, throwing above
> 2^53. A union value such as a `?int` is converted by its run-time tag: an integer tag becomes a float,
> every other value is stored unchanged. A union that names `int`, such as `int|float`, keeps the `int`.

## Context

The checker accepted `?float $x = 3;` through the `int` → `float` row inside the union, and the same at
an argument, a property, a return, a shape field, an array element and every other storing position. A
union erases to a tagged value, and the lowering tagged the `int` as an `int`. A read after narrowing
loaded the integer's bits as a float, so `3` printed `1.4821969375237E-323`, and `$x is float` was
false while `$x is int` was true. A plain `float` target converted, because its erased type is `float`.

## Options considered

1. **Convert where the value is stored.** The checker marks each value it accepted only through the
   widening inside a union, and the lowering converts the marked value before it is tagged.
2. **Refuse it, and require `as ?float`.** Code that relies on the widening stops compiling.

The user chose option 1.

## Decision

`nvs_types::expr::assign::note_float_widening` marks the value's span in the expression table
(`ExprTypeTable::widens_to_float`) when the target is a union holding `float`, and the value is an
`int` or `uint` the union does not name, or a union with an integer member the target does not name.
Every storing position calls it after accepting the value: `check_expr` with an expected type covers
arguments, declarations, assignments and literal elements, and `check_return`, a shape literal's
fields, a `??=`, a `foreach` value binding and a destructuring leaf call it too.

`nvs_ir::lower::Lowering::lower_expr` reads the mark for every expression. A static `int` or `uint`
takes `Helper::IntToFloat` or `Helper::UintToFloat`, the row a plain `float` position uses. A tagged
value takes the new `Helper::TaggedWidenToFloat`, which converts an integer tag the same way and
returns any other value as it is, with the same reference. A `foreach` binding and a destructuring leaf
have no expression, and read the mark at the binding's span.

## Consequences

Performance: a static integer pays the conversion a plain `float` position already pays. A union value
pays one tag test per store, at the marked positions only. Memory: one span per marked value in the
compile's expression table, nothing per request. Usability: `?float` and the other unions behave as
`float` does for whole numbers, and the wrong values are gone. Simplicity: one rule for every position
that holds `float`. A union source whose integer members the target names in part, such as `int|uint`
into `int|float`, is not marked, because the run-time conversion applies to both tags.

## Alternatives rejected

A compile error that requires `as ?float` was rejected because it is inconsistent with the rest of the
language: an `int` into `float` converts with nothing written, and so does an `int|float` value into
`float`. Adding `?` to the declared type should not change which values are accepted.

## Verification

The `.nvst` case covers every storing position, a `uint`, a union source, a value that is not a number,
a union that names `int`, and the throw above 2^53 for a literal and a `?int` value. The unit test pins
that the conversion comes before the tag and carries the error edge.
