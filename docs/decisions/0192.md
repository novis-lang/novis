# ADR 0192 — `is` is the one type test, `instanceof` is a refused spelling, and neither keyword is compared with PHP again

- **Scope:** which spelling asks whether a value holds a type, what the right-hand side of `is` may be,
  what happens to `instanceof`, and how far PHP's Pattern Matching RFC constrains any of it. It does
  not design pattern syntax of any kind, does not build the converter that rewrites a PHP source file
  (M11's), does not take false-edge narrowing, and changes nothing about `as`.
- **Depends on:** [0150](0150.md) (`is` as the general type test, and the rule this one deletes),
  [0124](0124.md) (`let` and `is` reserved as identifiers), [0125](0125.md) and [0126](0126.md) (the
  three sites a `class<T>` is accepted at, and `E0496` as their one refusal), [0007](0007.md) (a
  declared type answers before the program runs).
- **Validated by:** `tests/conformance/reject/instanceof-is-spelled-is.nvst`,
  `tests/conformance/lang/an-is-test-against-a-class-reference-is-the-dynamic-class-test.nvst`, and the
  absence gate `git grep -i -w instanceof` over `crates/`, `tests/`, `docs/reference/`, `docs/spec/`,
  `docs/rules/` and `docs/agent/playbook.md`.

> **In short:** Novis has one type test. `$x is T` asks whether a value holds a `T` for every type a
> value can inhabit, `$x is Request` is the class test, and `$x is $cls` against a `class<T>` value is
> the dynamic class test and narrows its subject to `T` on the true edge. A test whose answer the
> subject's declaration already settles — `int $n; $n is Request` — compiles and folds to `false`, as
> every other settled test does. The spelling `instanceof` is refused where it is written, naming `is`
> in the rewrite; the descriptor walk it used to lower to keeps running under a name that is not the
> keyword. This is a deliberate divergence from PHP, taken for good: `is` is judged the more
> understandable operator, and **no session compares either keyword with PHP again** — the Pattern
> Matching RFC was read once, its reading is frozen in § 1 below, and it is not read again.

## Context

### 1. What was read once, and is frozen here

PHP's *Pattern Matching* RFC, version 0.9, **in discussion** and not voted. Its type pattern spells
the class test `$foo is Request` and gives it as the equivalent of `$foo instanceof Request`; the two
operators coexist there rather than one replacing the other. Binding is permitted only *inside* an
object or array pattern — a bare variable is not a whole pattern, and the RFC refuses it as one.
Pinning is spelled `^$var` and compares with `===`. Nothing in the RFC addresses a **dynamic class
name** on the right of `is`: the question Novis answers below is one PHP has not asked.

PHP 8.6's *Deprecations for PHP 8.6* RFC, passed, deprecates `is` as an identifier, and its stated
motivation is the pattern-matching RFC above and nothing else. That is a claim on the spelling, not
on a meaning.

**These two paragraphs are the whole of what this project knows about either document, and they are
not refreshed.** A later Novis session that wants a row of pattern syntax is designing a Novis
feature from Novis's priorities, not tracking a vote — § 9.

### 2. Two spellings split one question, and the seam was where the cost was

The tree carried `is` for types and `instanceof` for classes, and the seam between them showed up
four times over. `$x is $cls` was refused (`E0812`) and `$x instanceof $cls` was the dynamic class
test, so a class reference and a written class name — the same question about the same value — were
asked with different words. `instanceof` refused a subject that could hold no object (`E0497`) while
`is` answered the same question with `false`, so a mechanical rewrite between them was not
answer-preserving. `rule:types/narrowing` had to state that two of its five spellings narrow
identically. And every rule touching either one carried a paragraph explaining why the other existed.

Nothing about that seam is PHP compatibility: `instanceof` in Novis had already diverged from PHP's
at both of the places it mattered — the refusal at `E0497`, and a `string` right-hand side reported as
`E0496` rather than resolved as a class name.

## Options considered

### 3. The three shapes the seam could take

**Keep both**, and pay the seam: two operators, one of them a special case of the other, with the
dynamic form reachable only through the narrower one. **One test, `is`, with the dynamic form behind
a `Core` call** — `Core\Reflect::isInstance($x, $cls)` — which removes the keyword but moves a
language question into the library. **One test, `is`, with the dynamic form as the value arm of its
own grammar.** The third is taken; the other two are § 10 and § 11.

## Decision

### 4. One operator, four sentences

`$x is T` is Novis's only type test, and it asks every question the two operators used to split:

- `$x is Request` is the class test, and `is` keeps every other row `rule:types/type-test` lists.
- `$x is $cls`, where `$cls` is a `class<T>`, is the **dynamic class test**: it tests the class the
  value holds against the descriptor the reference carries, and narrows its subject to `T` on the true
  edge. The value arm starts with `$` and nothing else does — a call or a constant on the right of
  `is` is a type, and a program wanting a computed class reference binds it to a local first.
- `int $n; $n is Request` compiles and folds to `false`, like every other test whose answer the
  subject's declaration settles. There is no inapplicable subject left to refuse, because `is` is
  applicable to every value.
- **`instanceof` is refused where it is written**, with a diagnostic naming the rewrite. The
  descriptor walk it lowered to is untouched and keeps running under a name that is not the keyword.

Narrowing the value arm to `T` is sound: a `class<T>` holds `T` or an implementor, so a subject that
answers `true` is a `T`. False-edge narrowing stays untaken for every spelling, exactly as before.

### 5. `$x is $cls` is a divergence, and it is the one PHP has not ruled on

PHP's RFC refuses a bare variable as a whole pattern (§ 1), so PHP has no dynamic class test through
`is` and no plan for one. Novis gives the spelling the dynamic meaning because it has no binding
patterns to collide with, and because the alternative is keeping a keyword alive for one form. The
divergence is stated once, in `rule:php-migration/one-type-test`, which this record creates as the
home for every sentence about either keyword and PHP.

### 6. The rule the RFC shaped is deleted, not amended

`php-migration/is-takes-pattern-matchings-type-patterns` existed to hold the relationship with a
document this project no longer reads, and two of its sentences are now false — that a bare variable
is a top-level capture in PHP, and that `$x is $cls` must stay refused to protect the spelling. A
rule that is wrong about its own subject is deleted rather than rewritten: its fragment and its
`php-migration.json` entry go, and every `seeAlso` naming it is swept. The `changes:` block has no key
for a removal, so this sentence is where it is recorded. [0150](0150.md) stays `accepted` — it also
created `types/type-test`, which this record modifies rather than removes.

The shapes that rule listed as reserved — object and array patterns, comparison patterns, pinning,
`match ($x) is {…}` — keep refusing, as syntax Novis does not have. No diagnostic names an RFC.

## Diagnostics

### 7. One new code, two retired, one rewritten

`E0253` is the refusal of the spelling: *`instanceof` is not a Novis operator; the type test is `is`*,
with help *write `$x is Request`; a class reference on the right is `$x is $cls`*. It is reported
where a binary operator may stand and consumes its right operand, so the site costs one diagnostic
rather than a cascade. The token stays in the lexer for exactly this.

`E0497` — `instanceof` on a subject that can hold no object — and `E0812` — a value on the right of
`is` — are **retired**: both are now accepted sites, their constants and doc comments are deleted, and
neither number is ever reassigned.

`E0496` is unchanged and is the one report for a value that is not a `class<T>` at any of its sites,
`is` included. Its help names `as class<T>`, which is the fix for a `string` right-hand side — the
shape a converted PHP program arrives in.

## Consequences

### 8. What moves, and what it spends

**It spends nothing.** The same instruction is emitted, the same runtime call is made and the same
descriptor walk runs; `rule:programs/memory-priority` has no figure to record here. What changes is
which spelling reaches them.

The runtime primitive is **renamed** rather than kept under the keyword's name, because the gate this
decision is held to is that the word names nothing in `crates/` but the refusal: the instruction is
what `is C`, `is $cls`, `is callable`, `is iterable` and the `catch` chain all emit, so it is named for
the question it asks rather than for one of its callers.

`rule:types/narrowing` counts **four** spellings, `rule:types/class-reference-sites`'s third row is
spelled `$x is $cls`, and `rule:php-migration/a-declared-type-answers-before-the-program-runs` reduces
to its `->` half — the `instanceof` half of it is not a refusal any more.

Migration is mechanical and belongs to M11: the converter rewrites `$x instanceof C` to `$x is C`, and
leaves PHP's string and object right-hand sides to `E0496`'s help. Nothing about the converter is
built here. A PHP program's `instanceof` never silently means something else in Novis — it does not
compile.

## Alternatives rejected

### 9. Deferring to PHP's eventual vote

Waiting would mean tracking an in-discussion RFC indefinitely and shaping a language surface around a
document whose contested rows are the ones most likely to move. The cost of that tracking is paid by
every future session; the cost of diverging is paid once, here, and read by a converter that already
has to rewrite a keyword. Novis diverges and stops looking.

### 10. `Core\Reflect::isInstance($x, $cls)` for the dynamic test

Rejected. It answers the same question as `$x is Request` in a different vocabulary, cannot narrow —
a checker does not read a library call's result as a type refinement — and puts a language operation
behind a capability-shaped surface. It would also leave the tree with two ways to ask, which is the
thing this record removes.

### 11. Keeping `instanceof` for the dynamic form alone

Rejected. It keeps a keyword, a parser production, an AST node, an `ExprInfo` variant, a lowering path
and an LSP arm alive for one form, and it keeps the seam of § 2 in place while making it narrower and
therefore harder to remember. It also preserves the worst property of the pair: two spellings whose
answers differ for a subject that can hold no object.

## Revisiting

### 12. One trigger, and it is not PHP's

This is revisited if **Novis wants pattern syntax of its own** — binding, destructuring, sequence
patterns — because that is where the right-hand side of `is` would have to grow a grammar beyond a
type. That is a Novis design question, opened by a record of its own and decided on Novis's
priorities.

There is **no PHP trigger**. PHP passing, amending or abandoning its Pattern Matching RFC does not
reopen this, and neither does anything PHP does with `instanceof`.

## Verification

### 13. The gate is an absence

`git grep -i -w instanceof` over `crates/`, `tests/`, `docs/reference/`, `docs/spec/`, `docs/rules/`
and `docs/agent/playbook.md` finds nothing, with exactly these homes excluded because each *has* to
spell it: the token table and the parser site that refuse it, the diagnostics crate's doc comment for
`E0253`, the parser test and the conformance case that pin it, and the `php-migration` chapter that
states the divergence. `docs/decisions/` is frozen history and is outside the sweep.

The behaviour itself is held by the two conformance cases named above, by the narrowing case that
proves the value arm refines its subject to `T`, and by the settled-answer case that proves a class
test over a scalar subject folds rather than reports.
