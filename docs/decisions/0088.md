# ADR 0088 — A sink is a parameter that becomes an instruction, and an unclassified one refuses

- **Scope:** the predicate that decides whether a `Core` parameter is an `rule:security/tainted-qualifier`
  sink; the fail-closed default for a `string`/`bytes` parameter nobody classified, and where that
  classification is declared; which sink `echo` writes to in every execution context Novis has; the typed
  `Core\Response` body members that replace `write`; and the carrier type a captured sink yields. Not in
  scope: what the HTML and terminal sinks *do* once reached, which stay
  [0024](0024.md) § 5 and [0086](0086.md)
  § 1; the `secret` axis's own roster, which is [0033](0033.md)
  § 4 and is unchanged here; and the extension-manifest declaration syntax, which is
  [0055](0055.md) and is confirmed rather than amended (§ 6).

> **In short:** `rule:security/sink-predicate` lists five sinks, and a list is a
> deny-list wearing a type system's clothes: a `Core` member nobody thought about accepts tainted data
> silently. That is not hypothetical — `Core\Str::format`'s `$template` is unmarked today, so a tainted
> `printf` template compiles, while `Core\Regex`'s pattern one section away is correctly a sink. This ADR
> replaces the list with a predicate — **a parameter is a sink when its content becomes an instruction
> something executes, rather than data something returns** — and flips the default for an unclassified
> `string`/`bytes` parameter from *contagious* to *refuses*. Userland is already fail-closed, because a
> plain `string` parameter rejects a tainted argument today; `Core`'s own signature table was the only
> fail-open surface in the language, and it is one table. The same fail-closed reflex settles `echo`: every
> execution context has a sink, and the **default sink is the terminal**, so a scheduled script, a job
> worker and a test all neutralize control bytes rather than writing raw. The HTML sink is attached by one
> thing only — an HTTP request — which is why a JSON body is now `Response::json` rather than an `echo` the
> § 5 sink would HTML-escape into corruption.

## Context

- **§ 4 of [0024](0024.md) is an enumeration.** It names HTML output,
  SQL text, process argv, header values and filesystem paths, and [0086](0086.md)
  added terminal output as a sixth. Every one is right. The problem is the shape: the
  [spec's](../spec/01-core-library.md) Q column says every member carries a mark, but the *absent* mark
  means **contagious** — accepts tainted, returns tainted — so a member whose classification nobody
  performed is a member that accepts.
- **The gap is live.** `Core\Str::format(string $template, mixed ...$arguments)` carries a blank Q mark. A
  tainted template hands an attacker positional specifiers — `%2$s` prints an argument the call site never
  meant to print — and unbounded padding, `%999999999d`. It is the printf-grammar twin of
  `Core\Regex`'s pattern, which [0056](0056.md) correctly made a sink, and it sits
  eleven sections earlier in the same file.
- **Only `Core` is fail-open.** [`assign.rs`](../../crates/nvs-types/src/expr/assign.rs) already refuses a
  tainted argument at a plain `string` parameter, so every user-authored function in every Novis program is
  fail-closed by construction, and so is every function a package ships under
  [0081](0081.md). The whole exposure is one table in
  `nvs-stdlib`, which is what makes flipping the default a bounded pass rather than a language change.
- **`echo` has two meanings and no stated binding.** In a request it is
  [0024](0024.md) § 5's auto-escaping HTML sink; in a CLI program it is
  [0086](0086.md) § 1's substituting terminal sink. Both are decided; neither
  ADR says which applies where, and neither covers a scheduled `spawn script`
  ([0073](0073.md)), a job worker ([0084](0084.md)) or a
  `#[Test]` method ([0079](0079.md)) — contexts with neither a response nor a
  tty.
- **The JSON body is a trap the current rules build.** `echo Core\Json::encode($row)` over a tainted row
  yields a tainted string, which the § 5 sink dutifully HTML-escapes into `&quot;`-riddled invalid JSON.
  The only spelling that avoids it today is `Core\Taint::assertTrusted`, which trains the escape hatch on
  the single most common shape of handler an API writes — precisely the reflex
  [0024](0024.md) § 3 exists to prevent.

## Decision

### 1. The predicate: a sink takes an instruction, not data

> **A `string`/`bytes` parameter is a `tainted` sink when its content becomes an instruction that a parser
> executes. It is not a sink when its content is data that a parser returns, or that a serializer or a
> protocol frames.**

That one line derives every entry [0024](0024.md) § 4 lists and every
carve-out it grants, which is the test of whether it is the right predicate rather than a restatement:

| Position | Instruction or data | Consequence |
|---|---|---|
| `Core\Db`'s query text | instruction — the server executes it | **sink** |
| `Core\Db`'s bound parameters | data — the wire protocol frames each value | tainted-friendly |
| `Core\Process`'s argv element | data, *because* there is no shell to execute it ([0044](0044.md)) — but the executable path is an instruction | **sink** on the path |
| an HTTP header value | instruction — `CR`/`LF` re-frames the message | **sink** |
| an HTTP request or response **body** | data — `Content-Length` frames it | tainted-friendly |
| a filesystem path component | instruction — `..` and separators direct the resolver | **sink** |
| a file's **contents** | data | tainted-friendly |
| a `Core\Log` field | data — [0020](0020.md)'s JSON-Lines writer frames it | tainted-friendly, and *desirable* |
| `Core\Json::decode`'s input | data — the parse returns a value to the program | tainted-friendly, result tainted |
| `Core\Regex`'s pattern | instruction — it compiles to something that runs | **sink** |
| `Core\Regex`'s subject | data | tainted-friendly |

**One corollary settles a whole class at once.** `rule:core-api/shape-rules` R11 fixes the
library's grammar count at exactly four — a regex pattern, a `printf` template, a CLDR date pattern, and a
`Core\Bytes::pack` format. Every one of the four is an instruction by this predicate, so **every R11
grammar is a sink**, and R11's count doubles as the roster. `Core\Regex` already was; the other three are
brought in line by § 6.

### 2. An unclassified `string`/`bytes` parameter refuses `tainted`

The default flips. A `Core` member whose `string`/`bytes` parameter carries no classification **rejects a
tainted argument**, and *contagious* becomes a thing an author writes rather than a thing an author gets by
forgetting.

- **The classification lives once, in `nvs-stdlib`'s member registry** — beside `params`, `defaults` and
  `return_ty` in the `CoreMethod` row, which the five edits in
  [docs/agent/conventions.md](../agent/conventions.md) already make the one place a member is declared.
  The [spec's](../spec/01-core-library.md) Q column is that table rendered for a reader, not a second home
  for the fact.
- **A member with an unclassified `string`/`bytes` parameter fails `nvs-stdlib`'s own test suite**, not
  merely a review. The default is what a *program* sees; the test is what stops a member from shipping
  unclassified at all, and the two together are why forgetting is no longer a security event.
- **The four marks are unchanged** — *contagious*, *sink*, *launder*, *neutral*
  ([spec § *How to read an entry*](../spec/01-core-library.md)). Only the meaning of their absence changes.
- **A mark that admits `tainted` admits a union carrying it, arm by arm** — and the contagion is read back
  out with at least that reach. `Core\Env::get` answers `?tainted string`, so `$name ?? "default"` is a
  `string|tainted string`, and that is the shape *every* environment read arrives in rather than a corner:
  a launderer that took only the atom would be refusing the one spelling its own door produces. The
  admission does not weaken, because each arm is narrowed and then compared, so a union is admitted only
  where every arm of it is — one tainted arm at a *sink* still refuses the whole union. **The two
  directions are deliberately not symmetric**: the answer that decides whether to *set* the qualifier on a
  result reaches further than the narrowing that decides whether to *admit* an argument, because reaching
  too far over-taints in the first and leaks in the second.

The cost is one pass over the existing table, marking the overwhelming majority *contagious* — the
overwhelming majority genuinely is. The benefit is that the pass never has to happen again: the next
`Core` member added, by anyone, in any milestone, is safe until its author says otherwise.

### 3. `echo` always has a sink, and the default sink is the terminal

| Context | `echo` writes to | Carrier, and the rule it obeys |
|---|---|---|
| an HTTP request | the response body | `Core\Html\Markup`, auto-escaping ([0024](0024.md) § 5) |
| a CLI program — a `#[Command]` method or a script's main task | stdout | `Cli\Text`, substituting ([0086](0086.md) § 1) |
| a `spawn script` isolate ([0006](0006.md)) | its own output buffer, or the parent's stream under `output: 'inherit'` | the parent's carrier |
| a scheduled script ([0073](0073.md)), a job worker ([0084](0084.md)), a `#[Test]` method ([0079](0079.md)) | that run's captured output | `Cli\Text` |

**The same table selects a rendering.** [0092](0092.md) § 3 adds a
column to it: the sink in force decides not only where a `Core\Log` record, a `Core\Debug::dump`, a
`Throwable` trace, a test result or a compiler diagnostic goes, but whether it is drawn as plaintext, JSON
or HTML — so no call site ever names a format. Nothing else about this table changes.

**The terminal sink is the default; the HTML sink is attached by an HTTP request and by nothing else.**
That direction is the fail-closed one, and [0086](0086.md) § 1's own reasoning
is why: its substitution is uniform rather than tty-dependent precisely because *a CI log is written to a
pipe and read by a human later*, which is exactly what a scheduled run's and a job worker's output is. A
context with no attached sink does not exist, so `echo` never has an undefined meaning — and where the
meaning had to be chosen, it was chosen to neutralize.

`echo` inside a `spawn script` isolate therefore **works**, while every `Core\Cli` *member* inside one
still throws under [0086](0086.md) § 8. The two are consistent: that rule is
about who owns the *tty*, and an isolate's `echo` never reaches one — it reaches a buffer its parent owns.

### 4. A response body is written by one typed member, and `echo` means HTML

`Core\Response::write` is replaced by five members, each owning one body shape and setting its own
`Content-Type`:

| Member | Body | Qualifier |
|---|---|---|
| `html(Core\Html\Markup $body)` | `text/html` | takes the carrier, so nothing to refuse |
| `json(mixed $value)` | `application/json` | **contagious** — it serializes the value itself |
| `text(string $body)` | `text/plain` | **contagious** |
| `bytes(bytes $body, string $contentType)` | as given | **contagious** body, **sink** content type |
| `sendFile(…)` | as resolved | path is a **sink** (§ 1) |

- **`json` takes `mixed` and accepts tainted freely**, by § 1's predicate and by the same argument
  [0024](0024.md) § 4 already makes for `Core\Log` fields and `Core\Db`
  bound parameters: the framing belongs to the serializer, never to concatenation. A tainted string
  becomes a JSON string value and cannot escape it.
- **`text` accepts tainted, and it is [0074](0074.md) that makes this
  true.** `X-Content-Type-Options: nosniff` is on by default with nothing configured, so `text/plain` is
  not re-parsed as HTML by a browser. Without that default this member would have to refuse; the
  dependency is stated so that removing the default is visibly a change to *two* ADRs.
- **`echo` and a typed writer on the same response is a compile error.** They disagree about the body's
  type and its `Content-Type`, and silently letting the last one win is how a JSON endpoint acquires an
  HTML prelude.
- **`echo` in a request implies `text/html`**, which is what makes the inline-HTML page shape from
  [0049](0049.md)'s dual-mode lexer work with no ceremony.

### 5. Capturing a sink yields the sink's carrier

`Core\Out::capture` returns **the carrier of the sink in force**, not a plain `string` — `Core\Html\Markup`
in a request, `Cli\Text` everywhere else per § 3. The reason is not symmetry: the captured bytes have
*already* been through the sink, so returning them as a `string` and re-emitting them with
`echo Out::capture(…)` — which the [spec](../spec/01-core-library.md) § 12 names as the way to re-emit —
would escape them a second time and corrupt the page.

The same rule gives [0006](0006.md)'s `output: 'capture'` result its type, by the
same argument and with the same fix. `output: 'inherit'` needs no rule: the child's carrier is the
parent's, so appending composes the way `Markup + Markup` already does.

### 6. The three grammars that were not yet sinks

| Member | Parameter | Now |
|---|---|---|
| `Core\Str::format` | `$template` | **sink**; the arguments stay contagious |
| `DateTime::format`, `Date::format`, `TimeOfDay::format` | `$pattern` | **sink** |
| `Core\Bytes::pack` | `$format` | **sink** |

No launderer is added for any of them, deliberately. A grammar is written by the program, not received by
it, so the fix at a failing call site is to use a literal — which
[0057](0057.md) already folds at compile time for all three — or, for a genuinely
dynamic template drawn from a translation catalogue, `Core\Taint::assertTrusted` with its written reason.
`Core\Regex::quote` remains the one exception, because a regex is the one grammar that routinely needs a
runtime value *inside* it rather than *as* it.

### 7. What this deliberately does not change

- **[0055](0055.md) § 1's contagion-by-default for extensions stands.** An
  extension is a wasm component with no ambient authority ([0003](0003.md)), so it cannot
  itself be a sink: everything it does to the world outside travels through a `Core` member, and that
  member is classified under § 2. Fail-open at the extension boundary would be a real hole only if the
  boundary reached anything, and it does not. `.nvsx` manifests keep the tighten-only rule unchanged.
- **`Core\Log` is still not a sink**, for the reason [0024](0024.md) § 4
  already gives and § 1's table now derives: a structured field is data.
- **`Core\Json::decode` is not a sink.** Parsing attacker-controlled JSON is the point of the member; its
  result is `tainted` and the risk is bounded by the `maxDepth` cap the [spec](../spec/01-core-library.md)
  § 6 already sets. `Core\Serialize::decode` remains a sink for the separate reason
  [0023](0023.md) gives — it reconstructs a live object graph.
- **The `secret` axis is untouched.** [0033](0033.md) § 4's
  roster is about confidentiality, not structure, so § 1's predicate does not govern it: `secret` is
  refused at HTML output, terminal output, `Core\Log`, dumps, `Throwable` messages, serialization and a
  job payload, and each of those is an *output* rather than an instruction.

## Consequences

- **The failure direction inverts, which is the whole point.** Before: a member nobody classified accepted
  tainted data at run time in production. After: a member nobody classified fails `nvs-stdlib`'s test suite
  before it lands, and a member that slipped through refuses at `nvs check` in a developer's editor.
- **A one-time pass over the `Core` registry**, marking a large majority *contagious*. It is real work at
  M4S/M8 scale and it is the only work the flip costs; § 2's test is what keeps it from recurring.
- **`Str::format` with a dynamic template becomes a compile error**, and a translation catalogue is the
  legitimate case that hits it. `Core\Taint::assertTrusted` covers it at the cost of one written reason, and
  a catalogue read from the application's own files is exactly the false positive
  [0024](0024.md)'s *Consequences* already names as the accepted
  direction.
- **`Core\Response` grows from six members to ten and loses `write`.** A priority-4 cost, paid to remove a
  case where the safe spelling and the correct spelling disagreed. `nvs convert` gains a mapping rather than
  a gap: PHP's `echo json_encode($x)` becomes `Response::json($x)` mechanically.
- **Nothing changes at run time.** Every rule here is checked by `nvs check` and erased before codegen, so
  [0024](0024.md) § 1's zero-cost claim is unweakened — no representation,
  no branch, nothing on the request path.
- **`echo` becomes explainable in one table** rather than reconstructed from two ADRs and three milestones,
  which is the form the [spec](../spec/01-core-library.md) and `nvs-lsp`'s hover text can both use.

## Alternatives rejected

- **Keep contagious as the default and state the predicate as guidance.** Cheapest, and it is what produced
  `Str::format`: the predicate was derivable from § 4's list and the member was added
  anyway. A rule enforced by attention is the thing
  [0019](0019.md) already rejected for reflection and
  [0024](0024.md) already rejected for a bolt-on analysis pass.
- **Deny at the process boundary — `tainted` may never leave except through a typed carrier.** Strictly
  stronger and wrong: it refuses `Fs::write`'s contents, an outbound request body, a `Core\Db` bound
  parameter and a `Core\Log` field, every one of which is safe and common. The predicate that separates
  them is § 1, so a boundary rule would be § 1 with the useful half deleted.
- **Key the response body's rule on `Content-Type`** rather than on which member wrote it. The header can be
  set after the first byte of the body is written, so the rule would depend on a fact that is not yet
  decided at the point it must be enforced.
- **Keep one `Response::write` and require `Markup` for every body.** One rule instead of five members, and
  it makes `Taint::assertTrusted` the ordinary spelling for an API handler — the exact training effect
  [0024](0024.md) § 3 exists to avoid.
- **Route `echo` to `Core\Log` in a context with no response and no tty.** Sounds tidy and is not: it
  silently reshapes free text into [0020](0020.md)'s structured writer, and a
  scheduled script's output is read by an operator in a terminal often enough that
  [0086](0086.md)'s neutralization is the property that actually matters there.
- **Make `echo` in a sinkless context a compile error.** Considered, and rejected once § 3's default made
  "sinkless" an empty set — an error for a construct that has a safe, obvious meaning is friction with no
  security purchase.

## Verification

- **§ 1/§ 2** — a `nvs-stdlib` test walks the whole member registry and fails on any `string`/`bytes`
  parameter with no classification. This is the check that makes the default a guarantee rather than a
  default, and it is the one test whose absence would silently restore the status quo.
- **§ 2** — a `.nvst` compile-error case passing a tainted value to a deliberately unclassified fixture
  member, asserting the diagnostic names both the qualifier and the parameter.
- **§ 3** — one fixture `echo`ing the same string containing `ESC` and `<script>` from each of the four
  contexts, asserting the response body is HTML-escaped and the other three carry `␛`. The CLI and request
  rows are already covered by [0086](0086.md) and
  [0024](0024.md)'s own cases; the isolate and scheduled rows are new and
  are the ones that would fail silently.
- **§ 4** — `Response::json` over a tainted row produces byte-valid JSON with no HTML entities, asserted
  against the decoded value rather than the text; `echo` followed by any typed writer is a compile error;
  a response written only by `echo` carries `Content-Type: text/html`.
- **§ 5** — `echo Out::capture(fn() => echo $tainted)` in a request produces singly-escaped output. A case
  asserting *double* escaping would have passed before this ADR, which is what makes it worth pinning.
- **§ 6** — compile-error cases for a tainted `Str::format` template, a tainted CLDR pattern and a tainted
  `pack` format, plus a case asserting the *arguments* to `format` stay contagious.
- **§ 7** — a case asserting a tainted value still reaches `Core\Log`, `Core\Json::decode` and a `Core\Db`
  bound parameter without a diagnostic, which is what pins the predicate's data half against an
  over-eager future tightening.
