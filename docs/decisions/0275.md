# ADR 0275 — A deprecated declaration names its replacement as a checked Novis expression, every use warns with that rewrite as its fix, and a `// TODO:` comment is a list the tools print

- **Scope:** the compiler-recognized `#[Core\Deprecated]` attribute, its attach sites, its `replace`
  template and the checks the template meets where it is declared; `W1003` at every use and the rewrite
  it carries as a `safe` suggestion; the `// TODO:` comment form; `nvs check --deny`, `--fix` and
  `--todos`; and the `[errors] deprecated` setting with `Core\DeprecatedError`. The spelling of each new
  diagnostic, and the exact text of `W1003`'s message, are left to the stages that write them.
- **Depends on:** [0046](0046.md) (attributes, which left `#[Deprecated]` to its own record),
  [0068](0068.md) (a forced break is announced by a warning naming its replacement), [0099](0099.md) (a
  quick fix is a diagnostic's suggestion), [0137](0137.md) (no `@deprecated` tag), [0064](0064.md) (the
  block roster).
- **Validated by:** `tests/conformance/reject/a-deprecation-template-that-does-not-fit-does-not-compile.nvst`,
  and the goal `deprecated-and-todo`'s acceptance checks: every fixture the rewrite tests fix is checked
  again with no `W1003` and no error, and a program that uses nothing deprecated compiles to the same code.

> **In short:** `#[Core\Deprecated(since:, note:, replace:)]` joins the closed `Core` roster of
> compiler-recognized attributes, every field optional. `replace` is **one Novis expression**, with the
> declaration's own parameters and `$this` as its placeholders, and it is compiled where it is declared:
> it must fit the member's type, name nothing less visible than the member and nothing deprecated, or the
> declaring code does not compile. Every use of a deprecated declaration is warning `W1003`, never an
> error, and the warning carries the template filled in at that use as a `safe` suggestion, so the
> editor's quick fix and `nvs check --fix` apply it unchanged. An argument whose side effect the template
> would repeat, skip or reorder moves to a `var` line in front of the statement; where that line would
> change when the code runs, there is no fix. `// TODO: text` is a comment and only a comment: the tools
> list it and nothing fails on it unless `nvs check --deny todo` asks. `[errors] deprecated` (`"ignore"`,
> the default in every mode, `"log"` or `"throw"`) lets a developer make a deprecated use visible while
> the program runs.

## Context

[0046](0046.md) built attributes and left `#[Deprecated]` to a record of its own; none was written.
`W1003` was declared and nothing raised it, and [0137](0137.md) refused a `@deprecated` doc tag with the
sentence "deprecation is an attribute", which was true of nothing. [0068](0068.md) already requires that
a forced break survive one minor release as a warning that names its replacement, and had no mechanism
to name one. The user asked for a way for a library author to retire a member and hand every caller the
rewrite, and for a todo marker the tools know.

Almost all of it stands on code that exists: the attribute roster and the `#[Core\Path]` precedent for
an attribute a use site reads back, the `Suggestion` every diagnostic can carry and the language
server's translation of it into a code action ([0099](0099.md)), the trivia the lexer keeps for every
`//` comment, and the per-request word codegen already branches on for debug probes.

## Options considered

1. **A replacement as prose** — `note: "use find() instead"`, as PHP, Java and C# do. Nothing can be
   applied, and nothing checks the prose against the code it names.
2. **A replacement as a name** — `replace: "find"`. Mechanical only when the two members take the same
   arguments in the same order, which is the case a rename tool already handles.
3. **A replacement as a template in a syntax of its own** — `"find({0}, limit: {1})"`. Mechanical, but a
   second language inside a string, with its own escaping and its own errors.
4. **A replacement as a Novis expression over the declaration's own variables** — chosen. The parser and
   the checker already read it, so the template is checked where it is written, and the fix is a
   substitution on a tree.

## Decision

### 1. The attribute

`#[Core\Deprecated]` is a plain name on the closed `Core` roster of
`rule:attributes/attach-sites-and-forms`, naming no shape. Its payload is `since`, `note` and `replace`,
every one a string and every one optional, plus `construct`, a string allowed only on a class. A field
outside that list is refused. It attaches to a class, an interface, an enum, an enum case, a method, a
constructor, a property, a class constant and a parameter. A type alias carries no attributes, so it
cannot be deprecated.

### 2. The template

`replace` is one Novis expression, or one type name on a class, an interface or an enum. It is compiled
once, in the scope of the declaration, with the member's parameters and, on an instance member, `$this`
bound. **The placeholders are the parameters**: there is no `{0}`, no `$1` and no other template syntax.
The template is refused where it is declared, each with its own code from the `E08xx` band, when it:

- does not parse as one expression, or one type name where a type is due;
- does not compile in that scope;
- has a type that is not assignable to the method's return type, the property's type or the constant's
  type; a parameter's template is a named argument whose value fits that parameter;
- names something less visible than the deprecated member;
- names something deprecated, so every fix is one step and never produces code with a second warning.

A class's replacement declares every public member the class declares, with an assignable signature,
and `construct` is a template over the constructor's parameters for a `new`. A broken template fails the
build of the code that declares it, never the fix somebody applies.

### 3. The warning

Every use of a deprecated declaration is `W1003`: a call, a `new`, a property read or write, a class
constant, an enum case, a passed deprecated parameter, and a type position naming a deprecated class.
An override or implementation of a deprecated member warns at the override, with no fix. Nothing warns
inside a deprecated declaration or inside a member of a deprecated class, so a library's own old code is
quiet. The message names the member, then `since` when written, then `note`, then the replacement as it
would be written at that use. **A deprecation is never an error**: only `nvs check --deny deprecated`
turns it into a failure. A construct the compiler refuses outright stays refused and is not a
deprecation; this decision is about what a program's author retires.

### 4. The fix

The checker fills the template in at each use. A parameter is the argument's source text, matched by
position or by name; a parameter left out is its default as written at the declaration; `$this` is the
receiver as written; a static member's class is the class as the use wrote it. A substituted expression
is parenthesized only where its precedence is lower than its place. A name in the template is resolved
at the declaration and written at the use as the shortest name that resolves to the same declaration,
with an import added by the computation `E0303`'s fix already uses, and never an alias
(`rule:ide/no-refactoring-introduces-an-alias`).

An argument or receiver is pure when it contains no call, `new`, assignment, increment or decrement. A
pure one is copied wherever the template uses it, and so is an impure one used exactly once and in the
order the use wrote it. Every other impure one moves to a `var` line in front of the statement, in the
order the use evaluated it, under a fresh name made from its parameter's. **There is no fix where that
line would change when the code runs** — on the right of `&&`, `||`, `??` or `?:`, in a loop's condition
or step, in an arrow function or a `match` arm, in a default value or a property initializer — nor for a
`...$args` spread into a template parameter. The warning is raised as before and its help shows the
template.

Every fix is `safe`: the rewrite keeps the order and the count of every side effect by construction,
and what the replacement does is the declaring author's claim, which § 2's type check bounds. It is the
fourth fix admitted by `rule:ide/a-code-action-ships-only-a-fix-a-diagnostic-already-knows`, because
the checker computes it where it raises the warning and the server translates it unchanged.

### 5. The todo

A `//` line comment whose text, after the slashes and spaces, starts with `TODO:` in capitals is a todo,
and the rest of the line is its text. A `///` doc comment, `todo:`, `TODO` without the colon and a
`/* */` comment are not. It is read from the trivia the lexer keeps, so the parser does not change. A
todo is a comment and only a comment: an attribute would say the same thing a second way, and there are
no statement attributes. It is not a diagnostic and `Severity` gains no variant. The editor shows each
at `Information` level, `nvs check --todos` lists them, and nothing fails on one unless `--deny todo`
asks.

### 6. `nvs check`

`--deny <kind>` is repeatable over the closed list `deprecated` and `todo`, and exits with failure when
one is found in a file outside `vendor/`, after printing everything it would have printed. `--fix`
applies every `safe` suggestion of every diagnostic in every file of the checked program outside
`vendor/`, checks again, and repeats until a pass applies nothing; the casing and legacy-cast fixes come
along. `--todos` prints `path:line: text` in path and line order, and `--json` gains a `todos` array.

### 7. The setting

`[errors] deprecated` is a new top-level block: `"ignore"`, `"log"` or `"throw"`, default `"ignore"` in
every mode, `Runtime`-class, so a test or a single request may set it with `Core\Config::set`. Deprecated
code still works in production, and only a developer turns this on. `"log"` writes one `warning` record
per use site per request, naming the member, the use's file and line, and the replacement; the request
remembers the sites it logged in a set freed with it. `"throw"` throws `Core\DeprecatedError`, a
`LogicError` whose message is `W1003`'s text, fixed at compile time. A deprecated method or constructor
checks on entry, so a call through an interface or a dynamic call is caught; a property, constant or enum
case, a `new` and a passed parameter check at the use; a type position checks nothing, because it runs
nothing.

## Diagnostics

`W1003` is the warning at every use, and its card says what the message carries. The template refusals
of § 2 are new codes from the `E08xx` band, one per check, declared by the stage that raises them. No
other code is added.

## Consequences

- **Performance.** A program that uses no deprecated code compiles to the same code as before: no check
  is emitted anywhere a deprecated declaration is not used. A use of deprecated code costs one load of a
  word in the request context and one branch, every time it runs, whatever the setting.
- **Memory.** The template and the message, once per declaration in the compiled unit. Under `"log"`,
  the set of sites a request logged, per request, O(distinct deprecated sites the request reaches), and
  freed with it.
- **Usability.** A library retires a member and its callers migrate with one click or one
  `nvs check --fix`. `rule:packaging/a-forced-break-is-announced-before-it-lands` has its warning.
- **Simplicity.** One attribute, one comment form, one setting, two flags on `nvs check` beside
  `--todos`. The rewrite's side-effect handling is the large part, and it is the checker's alone.

## Alternatives rejected

- **A `TODO` attribute or statement attribute.** A second way to write what a comment already says, and
  attributes attach to declarations only.
- **`TODO(owner):` and `FIXME:`.** Not now: one form keeps the list one list.
- **Deprecating a type alias.** It carries no attributes.
- **An error-level deprecation.** Retiring a member would break every caller on the day it lands, which
  is what [0068](0068.md) exists to prevent.
- **A workspace-wide fix in the editor.** `workspace/executeCommand` is not implemented;
  `nvs check --fix` is the workspace-wide form.
- **`--deny warnings`, or any kind beyond the two.** The list is closed until a kind is argued for.

## Verification

The template refusals are pinned one per check by
`tests/conformance/reject/a-deprecation-template-that-does-not-fit-does-not-compile.nvst`. Every
fixture the rewrite's Rust tests fix is checked again and has no `W1003` and no error, and applying the
fix a second time changes nothing. A request that sets `"throw"` leaves the next request on `"ignore"`.
