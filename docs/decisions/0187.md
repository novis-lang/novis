# ADR 0187 — Every driver parks its stream's read on the connection, `serverVersion` answers what the handshake already said, a unique key's nulls are distinct on all five backends, and a job keeps every attempt's error on its own row

- **Scope:** the four answers the database and queue halves owe that no rule states — the read state
  `stream` leaves between steps on MySQL, MariaDB, SQL Server and SQLite; what `serverVersion` answers
  on each driver; the null semantics of the schema vocabulary's unique key and the DDL SQL Server needs
  for them; and where a job's earlier attempts' errors live. Not in scope: `streamAs<T>`'s hydration,
  which is `rule:core-classes/derive-attribute`'s and `queryAs`'s shape repeated at a written type; the
  queue's SQL Server statement texts, which are a dialect rather than a decision; the rest of the schema
  vocabulary's v1 exclusions, which `rule:core-classes/schema-vocabulary-is-closed` keeps.
- **Depends on:** [0004](0004.md) for the ordering all four are argued under; [0067](0067.md) for
  `Core\Db`'s shape and its statement members; [0132](0132.md) for the busy state a parked read is read
  off; [0145](0145.md) for the plan grades the new DDL is graded under; [0084](0084.md) for the queue
  tables the `errors` column joins.
- **Validated by:** the streaming, `serverVersion`, schema and queue stages of goal `m8-db-queue` —
  a scripted-server proof per wire driver, a `.nvst` case over SQLite's `:memory:` block, and the
  five-driver matrix `python tools/db-matrix.py --all` runs.

> **In short:** a stream's read state is **split from the borrow and parked on the connection**, the way
> `PgCursor` already is, on every driver — the MySQL and MariaDB result-set walk, TDS's token walk to
> `DONE`, and a SQLite statement stepped on one pinned pool thread for the life of the walk. No driver
> takes a refusal; the refusal stays written down as the fallback for a protocol that turns out unable
> to park a read, and it is a `RuntimeError` naming the driver and `query`, never a buffer.
> `serverVersion` answers **what the handshake already delivered**, kept on the connection and costing
> no round trip: PostgreSQL's `server_version` `ParameterStatus`, the MySQL and MariaDB banner verbatim,
> `major.minor.build` from TDS's `LOGINACK` where the server sent numbers rather than a string, and
> SQLite's library version. A unique key **reads nulls as distinct on all five backends**, which four
> give for nothing and SQL Server gets from a filtered unique index its emitter writes. And a job's
> `errors` array is **accumulated on the jobs row** as each attempt fails, so the dead-letter move
> carries every attempt rather than the last one.

## Context

Four questions sit in front of goal `m8-db-queue`'s code, each one already scoped by a rule that
deliberately stops short of answering it.

`rule:core-classes/db-streaming` specifies what `stream` does — constant memory, the connection held
until drained, a second statement refused — and then records that it lands on PostgreSQL alone,
because "the read needs the portal left open with its state parked off the borrow, and the other four
drivers have no such state". That is a statement about this repository's code rather than about the
four protocols, and nothing has asked the protocols.

`serverVersion` is a `Core\Db\Connection` member with no rule at all. Every driver parses the server's
version during its handshake and then drops it: PostgreSQL discards every `ParameterStatus`
(`crates/nvs-db/src/pg.rs:1153-1157`, whose comment says nothing is read off them), MySQL and MariaDB
keep only a parsed `(u16, u16, u16)` for a collation-width decision
(`crates/nvs-db/src/mysql.rs:814`, `:866`, `:1042`), and TDS answers its `LoginAck` rather than keeping
it (`crates/nvs-db/src/tds/stream.rs:658-660`). The member can therefore be built from what is already
on the wire, or it can be built from a `SELECT version()` round trip, and nothing says which.

`rule:core-classes/queue-storage-is-a-table` enforces at most one pending job per dedupe key with a
plain nullable column under a plain unique key, which works because four backends read two nulls as
distinct. It then records that SQL Server reads them as equal, that the queue has no SQL Server
statements today, and that the day it gains them "the vocabulary grows before the queue does". This
goal is that day.

`rule:concurrency/attempts-are-finite-and-a-dead-letter-is-kept` says a dead-lettered job carries
"every attempt's error". It does not: `crates/nvs-cli/src/worker.rs:93-101` records the gap, because
§ 2's jobs table has nowhere to keep what an earlier attempt threw, and
`crates/nvs-stdlib/src/queue.rs:871` builds a one-entry array at the move. The rule and the code
disagree, and the rule is the one worth keeping.

## Investigation

**What each driver would have to park.** `crates/nvs-db/src/pg.rs:2555-2583` is the worked example and
the shape the other four are measured against: `PgCursor` is the statement's read state — the column
descriptions, what ended the statement, the `lastId` seen on the way past, and the trace span — held
*beside* the borrow for the buffered members and *on the connection* for `stream`, because a borrow
cannot span a call that returns to the program. `State::Streaming` is what refuses the second
statement in the parked case, which is `rule:core-classes/db-connection-busy-state` read off a cell
rather than off a lifetime.

Read that way, none of the four remaining drivers lacks the state — each lacks the *split*:

- **MySQL and MariaDB** frame a result set as a column-count packet, one column definition per column,
  then one packet per row until a terminating packet, over `crate::mysql`'s `Wire`. Everything the
  walk needs between two rows is the column definitions and the wire's own sequence position, and both
  are values.
- **SQL Server** is a token walk: `COLMETADATA` describes the columns and `ROW` tokens follow until
  `DONE` (`crates/nvs-db/src/tds/rows.rs`). The metadata is the parked value, exactly as the column
  descriptions are on PostgreSQL.
- **SQLite** is the one real obstacle, and it is a borrow rather than a protocol:
  `crates/nvs-db/src/sqlite.rs:33-40` records that `rusqlite`'s `Rows` borrows the statement, the
  statement borrows the connection, and the handle is an `Arc<Mutex<Connection>>` used from a pool
  thread. Nothing can be parked off that borrow, so the borrow has to be given a thread of its own.

**What each server says about its version.** PostgreSQL sends `server_version` as a `ParameterStatus`
during startup, a string the server chose. MySQL and MariaDB send the banner as the greeting's own
field, which `crates/nvs-db/src/mysql.rs:866` parses to a triple and throws the text away —
MariaDB's banner is where a MariaDB server identifies itself as one. TDS sends no string:
`crates/nvs-db/src/tds/stream.rs:208-226` reads `LOGINACK`'s `program` name and a `(major, minor,
build)` triple of numbers. SQLite has no server and no handshake; the only version that exists is the
library's own. So three drivers have a string and two do not, and the spelling for those two is the
whole of what needs deciding.

**What SQL Server needs for a nullable unique key.** `ALTER TABLE … ADD CONSTRAINT … UNIQUE`, which
`crates/nvs-db/src/ddl.rs:660-665` emits for every dialect but SQLite, has T-SQL's null semantics:
two nulls collide. `CREATE UNIQUE INDEX … WHERE <column> IS NOT NULL` does not — the rows that would
collide are not in the index at all, which is precisely the standard's behaviour and the other four
backends'. It is one index per key rather than a second column or a second statement, and SQL Server
records the predicate in its own catalog, so it can be read back and matched to the key that asked for
it.

**What an accumulated `errors` array costs.** `crates/nvs-stdlib/src/queue.rs:871-885`'s `dead_errors`
already fixes an entry's shape — `at`, `class`, `message`, built through `serde_json` rather than
formatted — and `:326-328` already declares `errors` on the dead-letter table as unbounded payload
text rather than an indexed column. The jobs table gaining the same column is the same kind of column
in the same schema value, and `:303-308` records what that costs to converge: a nullable column with
no default is a catalog write, and therefore a `Safe` step, on all four dialects.

## Options considered

For the parked read: park per driver as PostgreSQL does; buffer the result set and hand rows out of
the buffer; refuse `stream` on the drivers that have no portal; give `stream` a `{chunk}` option and
buffer a chunk at a time.

For `serverVersion`: answer what the handshake delivered; issue `SELECT version()` (or
`@@VERSION`/`sqlite_version()`) on the first call; answer a normalised `(major, minor, patch)` triple
on every driver; answer `null` where the server sent no string.

For the unique key: a filtered unique index on SQL Server; a `not null` column carrying a generated
token per released row; a computed column that maps null to a unique value; leaving SQL Server's
queue with the weaker guarantee and documenting it.

For the errors array: accumulate on the jobs row; a third table of attempts; keep only the last error
as the code does today; write earlier attempts to the log alone.

## Decision

### 1. A stream's read state is parked on the connection, on every driver

`stream` on MySQL, MariaDB and SQL Server parks the same kind of value `PgCursor` is — what the result
set described, what will end it, and the trace event it is timed by — on the connection, split from
any borrow, and advances it one row per call. `State::Streaming` refuses a second statement in every
case (`rule:core-classes/db-connection-busy-state`), and the buffered members keep the borrow-held
form, so the two paths share one row reader per driver and cannot disagree about what ends a stream.

**SQLite streams on one pinned thread per open walk.** The statement is prepared and stepped on a
thread taken from `nvs-host`'s blocking pool, each row is handed across, and the thread is released
when the walk is drained, dropped, or its task ends. That is the borrow `crates/nvs-db/src/sqlite.rs`
cannot split, kept alive on a thread instead of in a value. It costs one pooled thread per open
stream, which is O(open streams) and never O(requests served), and it is the price of the member
answering uniformly rather than one backend answering `RuntimeError`.

**Buffering is refused outright**, on every driver, in every disguise. It breaks the one promise the
member makes — constant memory — and it makes the memory a request holds a function of a result set's
size, which is the unbounded-by-input shape `rule:core-classes/output-that-scales-with-its-input-bounds-the-input`
refuses everywhere else. A chunk option is refused for the reason
`rule:core-classes/db-streaming` already gives.

**The refusal stays written down, as the fallback it now is.** A driver whose protocol cannot be
parked — none of the five, as read above, but a sixth is possible — throws a `RuntimeError` naming the
driver and naming `query` as the member to use instead. It is never a silent buffer and never a
partial read.

**An abandoned stream drains rather than poisons, on all five.** MySQL, MariaDB and SQL Server each
frame their remaining rows self-describingly to a terminating packet or `DONE` token, so the read back
to a message boundary is deterministic and the connection returns to `Idle` and to the pool, which is
the per-driver choice `rule:core-classes/db-connection-busy-state` leaves to the driver. The drain is
bounded by the result set the caller itself asked for. Closing instead would spend a full connection
handshake — and a TLS one — on what is ordinarily a program taking the first row of a sorted query.
A read that *fails* mid-message is `Poisoned` and closed, unchanged by this record.

### 2. `serverVersion` is what the server said during the handshake

Each connection keeps the version its handshake already delivered, and `serverVersion` answers it from
memory. **No driver issues a statement for it**, ever: a member that looks like a field read but costs
a round trip is a latency trap on the request path (priority 3), and a server that has just told us
its version is not a thing to ask again.

| Driver | What is answered | Where it comes from |
|---|---|---|
| PostgreSQL | the `server_version` string verbatim | the `ParameterStatus` at startup |
| MySQL | the greeting's banner verbatim | the handshake packet's own version field |
| MariaDB | the greeting's banner verbatim, which is how a MariaDB server says it is one | the same field |
| SQL Server | `major.minor.build`, decimal, no padding — `16.0.4125` | `LOGINACK`'s numeric triple |
| SQLite | the library version, as `sqlite3_libversion` reports it | the linked library, not a server |

A server's own string is answered **unchanged**, including any suffix it chose to put there, because
the value's whole purpose is to say what is on the other end and a driver that tidies it is a driver
that hides the thing being asked about. Where the server sent numbers, the triple is spelled the one
way this table fixes, so a program comparing versions across drivers is comparing one shape. The
member never answers `null`: every one of the five has an answer.

`serverVersion` is also what `rule:core-classes/schema-plan` grades against, and that is the second
reason it is a field rather than a query — a grader that has to open a connection and ask cannot grade
a plan built offline.

### 3. A unique key reads nulls as distinct on every backend

The schema vocabulary's unique key means *the standard's* unique key: rows whose key columns are all
non-null must be distinct, and a row with a null in any key column collides with nothing. Four
backends give that directly. **SQL Server's emitter writes a filtered unique index** for a key over
any nullable column:

```sql
CREATE UNIQUE INDEX <key> ON <table> (<columns>) WHERE <column> IS NOT NULL;
```

with one `IS NOT NULL` conjunct per nullable key column, and the plain
`ADD CONSTRAINT … UNIQUE` where every key column is `not null`, unchanged.

**This is a spelling, not a vocabulary growth.** A `Core\Db\Schema` still declares a unique key over
columns and nothing else; `WHERE` is a thing the SQL Server emitter writes, the way SQLite's emitter
already writes `CREATE UNIQUE INDEX` where the others write a constraint
(`crates/nvs-db/src/ddl.rs:645-659`). `rule:core-classes/schema-vocabulary-is-closed` keeps partial
indexes out of v1 as something a *program* may express, and that stays true.

The catalog reader matches the index back to the key that asked for it, predicate and all, so a second
`plan` over a converged database is empty — the property the whole schema half rests on. **The safe
fallback, where a filtered index cannot be read back as the same key, is to refuse `plan` on a SQL
Server table holding a nullable unique column**, naming the table and the key. A refusal costs an
operator a manual step; DDL that will not converge re-proposes itself on every deployment, and an
operator who has seen a plan lie once cannot use the tool again.

A build of this index over an existing table is `Locking` under `rule:core-classes/schema-plan` — an
index build over rows that are already there, exactly as a plain unique index is. Inside a
`CREATE TABLE` it is `Safe`.

The alternative `rule:core-classes/queue-storage-is-a-table` refuses stays refused, and its reason
outlives SQL Server: a `not null` column carrying a generated token per released row cannot be added
to a table that already holds rows, so it describes a schema no existing deployment can converge to.
A computed column is the same objection with an extra vocabulary entry attached.

This is priority 2 read as correctness of the one API `rule:core-classes/db-one-api` promises: a
program's own schema gets the same unique-key semantics on SQL Server as everywhere else, which is the
fix, not a side effect of making the queue work.

### 4. A job's errors accumulate on its own row

The jobs table gains **`errors`**, a nullable JSON document in the same unbounded payload-text form the
dead-letter table's column already has. Each failed attempt appends `dead_errors`'s entry — `at`,
`class`, `message` — and the dead-letter move copies the accumulated array with the final attempt's
entry appended, so the row carries every attempt as
`rule:concurrency/attempts-are-finite-and-a-dead-letter-is-kept` has always said it does. A job that
has never failed carries `null`.

**Bounded by construction, twice over.** Attempts are finite with nothing configured, and an entry's
`message` is truncated on a character boundary at a fixed cap when it is written, so a row's `errors`
is at most attempts × (cap + the two short fields). A thrown message is arbitrary text under the
program's control, so the cap is what keeps a job row from being a place to store a megabyte.

A third table of attempts was rejected: it is a second write per failure on the table `claim` already
contends over, a second thing `purge` has to delete, and a join to answer a question whose only reader
is a person looking at one dead job.

Converging costs one `Safe` step — a nullable column with no default, which is a catalog write on all
four dialects, for the reason `crates/nvs-stdlib/src/queue.rs:303-308` records for `tag`. No index, no
rewrite, no backfill.

## Diagnostics

No new diagnostic codes. Every refusal this record fixes is a run-time one with an existing shape:
`State::Streaming`'s `LogicError` for a second statement, the fallback `RuntimeError` naming a driver
and `query` for a protocol that cannot park a read, and the `plan` refusal naming a SQL Server table
and key whose filtered index does not read back. `queryAs`'s last compile-time refusal is `E0806`,
which is already allocated and is not this record's to spend.

## Consequences

- `stream` and `streamAs<T>` answer on all five drivers, so the large-read path stops being "use
  PostgreSQL or buffer". On the four drivers that buffer today, a large read's memory drops from the
  whole result set to one row plus the column descriptions — a reduction, not a spend.
- Each open SQLite stream holds one pooled thread. A program that opens many and drains none can
  exhaust that pool; it is the same shape as holding many connections, and it is bounded by the pool
  the host already sizes.
- `serverVersion` costs one short string per open connection and no round trip. The grader can use it
  without a connection of its own.
- A SQL Server deployment's existing nullable unique keys change meaning when the plan is applied:
  rows the old constraint rejected become legal. That is the correction, and the plan shows the index
  drop and create as ordinary steps rather than doing it quietly.
- The queue runs its statements on all five backends, and `no_dialect` loses its last live arm.
- A failing job's row grows by one capped entry per attempt and is released when the row is deleted or
  purged; the dead-letter row carries the same array. Both are O(in-flight work), never O(jobs run).

## Alternatives rejected

- **Buffering a result set behind `stream`.** It is the member's one promise broken, and it would make
  a request's memory a function of a table's size.
- **Refusing `stream` on the drivers without a portal.** It is what the tree does today, and it turns
  `rule:core-classes/db-one-api`'s single API into four APIs with a footnote. The reading above found
  no protocol that needs it.
- **A `SELECT version()` on first use.** A round trip on the request path to learn something the
  connection was told at startup, and on SQLite it would answer the same string a function call gives
  for nothing.
- **Normalising every driver's version to a triple.** It throws away what a server chose to say about
  itself — the build, the vendor suffix, the distribution's patch marker — which is most of why anyone
  reads the member.
- **A `not null` dedupe column with a generated token per released row.** Cannot be added to a
  populated table, so no existing deployment could converge to it.
- **Leaving SQL Server's queue with at most one released row per key.** A silent correctness
  difference between backends is the thing the one-API promise exists to prevent.
- **Keeping only the last error.** It is the current gap, and it makes the common failure — a job that
  failed differently on each attempt — unreadable from the row.

## Revisiting

The parked read is reopened by a driver whose protocol genuinely cannot be advanced between calls; the
fallback refusal in § 1 is what that driver takes, and it is written into the rule so a future session
does not reach for a buffer instead. SQLite's pinned thread is reopened if a `rusqlite` release offers
a stepped statement that does not borrow its connection, which would make the thread unnecessary.

The filtered index is reopened if SQL Server's catalog turns out not to report the predicate in a form
the introspector can match back — the § 3 fallback is what holds until then, and the answer is a
refusal rather than a divergent schema.

## Verification

- A stream over each of the five drivers reads a result set larger than any buffer the driver holds,
  with the process's memory flat across the walk, and a second statement on the streaming connection
  throws `LogicError` on every one of them.
- An abandoned stream leaves the connection usable for the next statement on MySQL, MariaDB, SQL
  Server and SQLite, and the connection is pooled rather than closed.
- A SQLite stream's pinned thread is returned when the walk is drained, when it is dropped, and when
  its task ends, proved in a `.nvst` case over a `:memory:` block.
- `serverVersion` answers a non-empty string on every driver, matches the server's own reported
  version where the server has one, and issues no statement — asserted against a scripted server for
  the wire drivers.
- A unique key over a nullable column admits two rows whose key value is null on all five backends,
  and refuses two rows sharing a non-null value on all five.
- A second `plan` over a SQL Server database converged from the first is empty, including for a table
  whose unique key is filtered.
- A job that fails every attempt lands in the dead-letter table with one `errors` entry per attempt,
  in order, each carrying the class and message that attempt threw, with an over-long message
  truncated at the cap.
