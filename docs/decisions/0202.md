# ADR 0202 — a markup literal takes `<?= expr ?>` as a hole for any expression

- **Scope:** the second hole a markup literal has, what it accepts, and what a `<?nvs` tag inside a
  literal is. It does not touch double-quoted strings or heredocs, whose `{$…}` grammar stays PHP's,
  and it does not change what a hole's value goes through at the sink, which is [0169](0169.md)'s.
- **Depends on:** [0169](0169.md) for the literal and its `{$…}` holes.
- **Validated by:** `tests/conformance/core/a-markup-literal-takes-an-output-tag-hole-for-any-expression.nvst`
  and the reject cases beside it.

> **In short:** a hole in a markup literal had to begin with `$`, because the literal borrowed a
> double-quoted string's grammar whole. Novis has no free functions and no global constants, so
> every constant and every call a page wants is `Name::` shaped and was text — `{App::VERSION}`
> shipped as those twelve characters. The fix is the output tag a page already has:
> `<?= App::VERSION ?>` inside a literal is a hole that takes any expression, and the value goes
> through exactly the rules a `{$…}` hole's does. One spelling for "output this" in a page and in a
> literal, no second grammar to learn, and nothing in HTML, CSS or JavaScript ever contains `<?=`,
> so no page text has to be escaped to make room for it.

## Context

### 1. Every constant and call in a page was text

[0169](0169.md) made the literal's hole grammar a double-quoted string's: `{$` opens, anything else is
text. In PHP that rule costs nothing, because a page interpolates variables and a static call is rare.
In Novis it costs the common case. There are no free functions and no global constants
(`rule:classes/no-free-functions-or-constants`), so a version number, a money formatter and a
fragment-returning view are all `Name::…`, and none of them could reach a page without a local
bound above the literal. A reader who wrote `{App::VERSION}` got no diagnostic and a page with the
brace in it, because inert text always compiles.

### 2. The workaround was real duplicated work

`string $v = App::VERSION;` above every literal that wants one is a line per value, in the one
place a developer writes most. That is the ceremony 0169 removed for markup, put back for constants.

## Options considered

### 3. `{Name::…}` opens a hole

The narrowest change: a `{` followed by a class-name-shaped token and `::` opens a hole. It covers a
constant and a static call and nothing else — `{new App()}`, `{"lit"}` and `{1 + 2}` stay text — and
it adds a clause to the string grammar that a string does not have.

### 4. A second brace opener: `{= …}`, `{> …}`, `{{ … }}`

Short, and each collides with a template language a page may embed: `{{` is Vue, Twig and
Handlebars, `{>` is a Handlebars partial, `{=` is Mustache's set-delimiter tag. Each would force
`\{` escapes into client-side templates served from a literal, and each is a spelling with no
precedent in the language.

### 5. The output tag: `<?= expr ?>`

The tag a page already uses for "output this expression", inside the literal, closing on `?>`. Any
expression, spaces allowed, nested literals allowed. `<?=` occurs in no HTML, CSS or JavaScript, so it
collides with nothing a page contains. It was also the spelling the report's author tried before
knowing the literal existed.

## Decision

### 6. `<?= expr ?>` is a hole in a markup literal

Inside ``html`…` ``, `<?=` opens a hole that takes one expression and closes on the first `?>`
outside a nested string or literal. The value goes through the same rules as a `{$…}` hole: a
`string` is escaped, a `Markup` is written raw, a `secret` is refused, a value with no string form is
refused. A `}` inside the hole is an ordinary brace, so a closure with a body is written as anywhere
else.

### 7. `{$…}` is unchanged, and a string gets nothing

`{$…}` and bare `$name` keep their meaning in the literal, and a `{` followed by anything else is
still text, so a `<style>` block and a client-side template need no escape. A double-quoted string
and a heredoc do not take `<?=`: a string is not a page, PHP prints `"<?="` as text, and a code
generator that writes PHP into a string would be broken by the change. That keeps the rule one
sentence: `{$…}` interpolates everywhere, and in a markup literal `<?= expr ?>` outputs anything.

### 8. A `<?nvs` tag inside a literal is `E0010`

A literal is one expression. A code block inside it would need output captured from statements into
a value, which is a new mechanism, and a loop or a condition around markup is what code mode
outside the literal already is. The tag is reported once, at the tag, with the two replacements
named, and is then text.

### 9. The scan, and what it costs

The lexer's body scan gains one three-byte test, in the markup mode only, beside the two-byte test
for `{$`. A tag hole is a code frame that closes on `?>` instead of a depth-zero `}`. The parser
sees the same part a brace hole produces, so the checker, the lowering and the formatter — which
keeps a literal verbatim — change nothing. A hole that is a constant is still escaped per
execution, as every hole is; folding it is left to a later decision.

## Diagnostics

### 10.

| Written | Result |
|---|---|
| `<?= $secret ?>` | `E0790`, as in a `{$…}` hole |
| `<?= $array ?>` | `E0707`, no string form |
| `<?nvs … ?>` inside a literal | `E0010`, naming `<?= expr ?>` and composition |
| `<?= $s` with no `?>` | `E0002`, the unterminated hole and the unterminated literal |

## Alternatives rejected

### 11. A warning on `{Name::…}` left as text

Proposed with the report. Not taken: with a hole that takes any expression, the case a reader wants
has a spelling, and a warning keyed on the shape of text inside a literal is a heuristic over bytes
the compiler has decided not to read.

## Verification

### 12.

`a-markup-literal-takes-an-output-tag-hole-for-any-expression.nvst` runs a constant, a static call
returning a `string`, one returning a `Markup`, a `tainted` value, a nested literal in a ternary, a
closure with a brace body, and a `?>` inside a string in a hole, and asserts `{Name::…}` is still
text. The reject cases assert a `secret` in a tag hole, a `<?nvs` inside a literal and an
unterminated tag hole. The lexer's own tests pin the token stream.
