# ADR 0211 — `static::NAME` reads the called class's constant at run time

- **Scope:** what a `static::` class-constant read answers, and the four refusals that make the
  run-time read sound. `self::`, `parent::` and named-class constant reads stay inlined and are
  unchanged; `static::` on a method, on `::class` and in `new static()` are [0144](0144.md)'s.
- **Depends on:** [0008](0008.md), [0144](0144.md).
- **Validated by:** `tests/conformance/class/a-static-constant-read-answers-the-called-class.nvst`
  and the four reject cases
  named in the rule's `guardedBy`.

> **In short:** `static::PATH` inside a method answered the declaring class's `PATH` — exactly
> what `self::PATH` answers — because the checker resolved `static` to the enclosing class and
> inlined the value. The rule had promised PHP's meaning, under which the read is bound to the
> class the call was made on, and a subclass or implementor overriding the constant was silently
> ignored. The read is now late-bound: the frame's called class, which every method already holds
> for `static::class`, is asked for the name at run time through its own constant table, which
> the runtime already carried for reflection. A redeclaration at an incompatible type is refused
> so the typed load stays sound; `static::` in a constant expression, on a non-scalar constant,
> and inside a closure body are refused rather than left to fold wrongly or panic.

## Context

### 1. The override was reached by name and by nothing else

A template-method shape — an interface with a default body reading `static::PATH`, an implementor
declaring `public const string PATH = '/'` — printed the interface's value. Through ordinary
`extends` it did the same, in instance and static methods alike. `Index::PATH` written out
answered the override, so the override was there and only `static::` could not see it.

### 2. One arm collapsed two keywords

`nvs_types::expr::members::resolve_class_expr` mapped `self` and `static` to the enclosing class
in one arm, and `infer_class_const` inlined whatever the ancestor walk found from there. The
sibling `defaults` fold already special-cased `static::class` with the exact reasoning this
constant read lacked. Nothing tested a `static::` constant, and `E0499` had refused
`static::$prop` for the identical hazard while the constant spelling stayed silent.

### 3. Everything a late read needs was already built

A method's frame holds its called class as a `Ty::ClassDesc` — parameter 0 in a `static`
method, `$this`'s descriptor in an instance one — cached by `Lowering::lsb` and read for
`static::class` and `new static()`. The runtime `ClassDesc` carries a flattened, own-first
constant table, filled from the layout pass, that only `Core\Reflect` read.

## Options considered

### 4. Refuse `static::NAME`

`E0499`'s answer for the property: a diagnostic saying `static::` on a constant means nothing
different. Sound, and honest, and it drops a PHP meaning the rule names as kept and that the
template-method shape depends on.

### 5. Bind it late through the descriptor

One new IR helper taking the frame's descriptor and the name, answering from the table by name.
The read stays typed at the declaring class's declaration, so a redeclaration has to keep an
assignable type. A constant with no scalar value cannot be answered from the table, and a
constant expression has no frame to read a descriptor from; both are refused rather than folded.

## Decision

### 6. Bind late

Option 5. The cost is paid only by code that writes `static::` on a constant: one scan of a
per-class table the size a declaration wrote, and for a `string` constant one allocation per
read, charged to the isolate — the cost `static::class` already pays, and for the same reason
the process-wide table's strings are not shared across isolates. `self::NAME` and `Class::NAME`
still inline. The name is emitted as a fresh string per read and released with the call; a
per-unit interned name would remove that allocation and is left for a measured need.

### 7. What is refused, so the late read stays sound

- **`E0833`** — a class or interface redeclaring an inherited constant at a type not assignable
  to the ancestor's. The late read is a typed load, so a subclass answering another
  representation would be read wrongly, `secret` bit included. Checked for every declaration
  kind, `abstract` and interface too, since a read can be made through any of them. PHP 8.3
  makes the same demand of a typed constant override.
- **`E0831`** — `static::NAME` in a property or parameter default or an attribute payload, which
  is folded once with no call. It folded as `self::` before.
- **`E0832`** — `static::NAME` where the value is an `array`, an object, `null` or an integer
  outside `int`: the table carries the four scalars and nothing else.
- **`E0834`** — `static::` in any form inside a closure body. The closure's frame carries neither
  a receiver nor a called class; before this, `static::method()` and `static::class` there
  panicked in lowering, and `static::NAME` folded as `self::`. The playbook bullet that recorded
  the panic is retired with it.

## Consequences

### 8. A program that printed the wrong string prints the right one

Every `static::NAME` read whose called class overrides the constant changes its answer to the
override, which is the PHP answer. A read whose called class does not override it answers as
before. A redeclaration at another type, which was accepted and never read through `static::`,
is now an error.

## Alternatives rejected

### 9. Specializing the read per called class at compile time

The called class of a body is not a finite set the checker holds — a class in an autoload root
nobody has named yet is still a caller — so there is nothing to specialize over.

### 10. Answering an `array` constant late

The descriptor's table stores a folded scalar; an array would have to be rebuilt per read from
its constant form, which is a second constant materializer beside `nvs-ir`'s. Refused instead,
with `self::` named as the spelling that still inlines it.

## Revisiting

### 11. If a `static::` read shows in a profile

The name allocation per read is the first thing to remove — a string interned once per unit
would do — and the table scan the second.

## Verification

### 12. Guards

The conformance case reads through `extends`, an interface default, and a `static` method, and
holds `self::` beside each. The differential case pins the same against PHP. One reject case
per refusal pins its code, and the `E0833` case redeclares in both a class and an interface.
