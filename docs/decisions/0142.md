# ADR 0142 — A store an operator configured is authorized by the configuring, and may be a Unix socket

- **Scope:** what authorizes an outbound connection to a store named in root-owned configuration, and
  how such a store is reached over a Unix domain socket. Covers the grant `Core\Cache::shared()` and
  `Core\RateLimit::consume` ask, the spelling a socket takes in `[cache.shared] url` and in
  `[db.<name>] host`, what a platform without `AF_UNIX` does with one, and how a Postgres socket path
  is read. Not in scope: the address policy itself, which is [0058](0058.md)
  § 3's and is only *narrowed in reach* here; the two tiers and why the local one is a cache rather
  than a store, which is [0059](0059.md) § 1's; the transport, which
  `crates/nvs-host/src/net.rs` owns and already carries.
- **Depends on:** [0058](0058.md), whose § 3 already decided that an endpoint
  an operator wrote is not attacker-influenceable, and [0059](0059.md),
  which decides there is a coherent tier to reach at all.
- **Validated by:** `crates/nvs-stdlib/src/cache.rs`'s `a_configured_store_needs_no_address_grant` and
  `a_program_supplied_socket_path_is_never_a_target`.

> **In short:** an endpoint an operator wrote into root-owned configuration is authorized **by that
> writing**, so the grant over it names the *store* and not a host: `Core\Cache::shared()` and
> `Core\RateLimit::consume` ask `cache.shared`, unscoped, exactly as `Core\Db::connect` asks
> `db.connect` by name. Asking `net.connect` at a host scope was the wrong question, and its cost was
> that a loopback Redis needed `net.internal` to except the very range every ordinary deployment puts
> its store in. Once the question is not "which address" the answer may have no address at all, and a
> **Unix socket** falls out: `unix:/run/redis.sock` in `[cache.shared] url`, a bare absolute path in
> `[db.<name>] host`, admitted **only where an operator wrote it** — a program-supplied socket path is
> refused, because the local machine is precisely what § 3's denied ranges exist to keep a
> program-supplied endpoint away from, and a path has no address for that table to read.

## Context

Three things were true at once and only two of them fit together.

[0058](0058.md) § 3 carries an address policy on `net.connect` and denies
loopback, private and link-local ranges by default, because a hostname a program supplies can resolve
into any of them. It then carves out one class: an endpoint an operator wrote into root-owned
configuration and granted by name — a `[db.<name>]` block — on the reasoning that such an address "was
written by the same authority that grants the capability", and that applying the policy there "would
deny every ordinary deployment, since a database lives at `10/8`, a container network or `127.0.0.1`,
which is precisely the denied set".

[0059](0059.md) § 1 gave `Core\Cache::shared()` the other treatment:
`net.connect` under 0058's policy in full. But `[cache.shared] url` is the same kind of key as a
`[db.<name>]` block — `System`-class, `Boot`-apply, root-owned, written by the operator — and a shared
store lives in the same address space a database does. The result is that the ordinary deployment,
a Redis on loopback, has to write both halves of a grant to reach a store nobody but the operator
named:

```toml
[app.capabilities.net]
connect  = ["127.0.0.1"]
internal = ["127.0.0.1"]   # loopback is denied by default
```

That is the outcome § 3's carve-out exists to prevent, arrived at because the carve-out named one block
and a second block of the same kind was written later.

The third thing is the transport. `crates/nvs-host/src/net.rs` already carries `NvsUnix` — a Unix-domain
socket on the same parking reactor as `NvsTcp`, with the same four functions — and
[0097](0097.md) § 5 already admits a socket path on the *listening*
side, where it is what makes FastCGI unnecessary. Nothing outbound can reach it, and the obstacle was
never the transport: `nvs_runtime::capability::pin_host` asks `net.connect` at a **host** and then pins
the address that host resolves to, and a socket path has neither. So "add a scheme to the URL parser"
was never the whole of it, and the question of what authorizes such a connection had no answer.

Answering it for the *cache* answers it for the socket, which is why one ADR decides both.

## Decision

### 1. `cache.shared` is the grant, it is unscoped, and it replaces the address question

`Core\Cache::shared()` asks `Cap::CacheShared` at `Scope::Unscoped`. So does
`Core\RateLimit::consume`, which reaches the same store through the same door — `open_configured` in
`crates/nvs-stdlib/src/cache.rs`, whose two callers differ only in the sentence each appends to a
refusal. Neither asks `net.connect`, and neither consults § 3's denied-range table.

This is `Cap::MailSend`'s shape and `Cap::DbConnect`'s reasoning, which
`crates/nvs-config/src/capability.rs` already states for both: *the endpoint an operator wrote into
root-owned configuration carries the authority that granted this capability, so it is pre-approved and
is not additionally asked about `rule:security/net-address-policy`'s denied ranges.* A third key of the same kind gets the
same treatment rather than a fourth rule.

**Unscoped, because there is nothing to scope on.** A deployment has one shared store —
`crates/nvs-stdlib/src/ratelimit.rs`'s module doc already says so, which is why the limiter opens the
store itself rather than requiring `shared()` to have been called first. `db.connect` is scoped by
`Name` because a deployment has many `[db.<name>]` blocks and a program may be entitled to one and not
another; `cache.shared` has no such choice to express, and a scope with one possible value is a scope
that reads as a decision nobody made.

What the grant means is "this program may reach the coherent tier", and **where** that tier is stays
the operator's answer rather than a fact the program restates. That is the property being bought: the
application's `nvs.toml` stops naming an address that only the deployment knows, so moving a store
between a container, a loopback daemon and a socket is a change to one block and not to every app's
grant list.

### 2. A Unix socket is admitted where an operator wrote the endpoint, and nowhere else

`[cache.shared] url` and `[db.<name>] host` may name a Unix domain socket. `Core\Net::connect`,
`Core\Db::open`'s program-supplied `Db\Settings` and `Core\Http\Client` may not, and a path reaching
any of them is refused as a target this deployment has no way to authorize.

**The asymmetry is § 3's own, read for what it is about.** The denied-range table is not a list of
unpleasant networks; it is the mechanism that keeps a *program-supplied* endpoint off the local machine,
which is why loopback heads it. A program-supplied socket path is a way onto the local machine that the
table cannot see — there is no address to match, and the reachable set on an ordinary host is worse than
loopback's, since it includes a container daemon's socket, a database's local socket and whatever else a
distribution puts in `/run`. Admitting one would hand a program the exact capability § 3 spends a resolution and a pin to
deny it.

An operator-written endpoint is the case § 3 already distinguishes and for the reason it already gives:
it was written by the authority that grants the capability, so there is nothing for an attacker to
influence and nothing for a table to check.

**A deny-list of socket paths is not the alternative.** The address table works because the ranges are
few, closed and named by a standard; the set of sockets on a host is open, distribution-specific and
grows when anything is installed. A check that must enumerate what to refuse is a check that is wrong on
the machine nobody tested.

### 3. `unix:` where the key is a URL, a bare path where the key is a host

```toml
[cache.shared]
url = "unix:/run/redis.sock"          # or redis://host[:port]

[db.main]
driver = "postgres"
host   = "/var/run/postgresql"        # a socket directory; § 5
```

Two spellings because the two keys are two different things, and each takes the one that reads as
itself. `[cache.shared] url` holds a URL and its parser already dispatches on scheme — it strips
`redis://` and refuses `rediss://` and a database index with a sentence apiece — so a `unix:` scheme is
one more arm on machinery that exists, and the value stays a URL as the key's name promises.
`[db.<name>] host` is not a URL and never was, so it takes the overload
[0097](0097.md) § 5 established on the listening side: a value
beginning with a path separator is a socket, and no `host:port` can be spelled that way.

The `unix:` scheme names no protocol, and does not need to: `[cache.shared]` speaks RESP and nothing
else, so the scheme's whole job is to say *which transport*, which is the one thing the block does not
already know.

### 4. A platform with no `AF_UNIX` transport refuses at boot

A Unix spelling on a platform this build has no Unix transport for is **`E0627`**, refused where the key
was written, with a note naming the platform and pointing at loopback TCP.

`NvsUnix` is `#[cfg(unix)]` and `crates/nvs-host/src/net.rs` states why there is no Windows fallback:
`AF_UNIX` exists on Windows but `mio` does not carry it, so a caller gets `NvsTcp` on loopback rather
than a type that compiles and cannot be polled. That reasoning survives up here unchanged, and its
consequence is a refusal rather than a translation.

**At boot rather than at run time**, which is the opposite of the answer
[0139](0139.md) gives `backend = "db"`, and the difference is
what each is waiting for. `db` names a store the roster admits whose *second half is unwritten*, so
refusing it where it is written would claim the decision was wrong rather than that the build has not
caught up; it becomes reachable with no config change the day the half lands. A Unix socket on a
platform with no `AF_UNIX` is not waiting for this project — the deployment has to be spelled
differently, and every request until someone notices is one a boot refusal would have prevented. That
puts it with `backend = "local"`'s `E0626`: refused where it is written, so a deployment cannot run
believing it has a store it will never reach.

**Silently reading it as loopback TCP is refused** for the reason `rediss://` is refused rather than
half-served: a configuration that reads as one transport and runs as another is worse than one that does
not run, because the difference is invisible in exactly the review that would have caught it.

### 5. A Postgres socket path is the directory, and the engine's own name is derived

For `driver = "postgres"`, `[db.<name>] host` names the **directory** and the socket is
`<host>/.s.PGSQL.<port>`. `/var/run/postgresql` with `port = 5432` is
`/var/run/postgresql/.s.PGSQL.5432`.

This is what libpq, `psql`, PDO and every Postgres tool take, so a migrating deployment carries the
string it already has rather than learning a spelling that exists only here — which is
[0067](0067.md)'s standing direction for the driver surface. The cost is one piece of protocol
trivia encoded in `crates/nvs-db/src/pg.rs`, which is where Postgres trivia belongs, and it is trivia
that has not changed in the lifetime of the protocol.

MySQL and MariaDB take the socket **file** — `/var/run/mysqld/mysqld.sock` — because their socket has no
naming convention to derive one from, and that too is the string those deployments already hold.

**MSSQL refuses a path.** TDS has no `AF_UNIX` transport, so `crates/nvs-db/src/tds/mod.rs` reports it as a
target this driver does not speak rather than as a file it could not open. SQLite has no socket at all
and is untouched: its path is the database.

### 6. `net.local` is what a program-supplied path would need, and it is not written

When `Core\Net` lands — [docs/spec/01-core-library.md](../spec/01-core-library.md) § 15 lists it as
TCP/UDP/Unix over the runtime's own reactor — a program will want to connect to a socket path directly,
and § 2's restriction has to give. The shape that answers it is a **separate** capability,
`net.local`, asked at `Scope::Path` under § 4's canonicalise-then-prefix rule, whose entries are
absolute paths or directory prefixes and which carries no address policy because there is no address:

```toml
[app.capabilities.net]
local = ["/run/redis.sock", "/var/run/mysqld/"]
```

It is named here and **not added to the roster**, because `crates/nvs-config/src/capability.rs` states
the roster is closed on purpose and a capability with no caller is a row that cannot be exercised.
Naming it costs nothing and buys the thing an unwritten decision usually fails to buy: whoever writes
`Core\Net` finds the answer rather than the question.

**It is deliberately not `net.connect` widened to admit paths.** That grant's whole documented character
is that it carries an address policy, and entries of two kinds under one name — hosts governed by a
table, paths governed by nothing — is one name covering two guarantees, which
[0059](0059.md) § 1 split `local()` from `shared()` to avoid and
[0024](0024.md) § 3 refused a generic `sanitize()` over.

## Consequences

- **`net.connect` is no longer the grant for a store an operator configured**, so a deployment that
  granted it for its Redis host boots with `cache.shared` ungranted and would throw on the first
  `shared()` or `consume()`. That is knowable at boot — a `[cache.shared] url` set with no
  `cache.shared` grant is a pair the configuration holds — and is reported there as a `Warn` naming both
  keys, rather than discovered on a request.
- **The denied-range table governs strictly less than it did.** One more door stops consulting it. This
  is the point rather than a side effect, and the bound on it is § 2: the table's reach shrinks only over
  endpoints an operator wrote, and every program-supplied one — `Core\Http\Client`, `Core\Net`,
  `Core\Db::open` — is governed exactly as before.
- **A loopback store stops needing `net.internal`.** The two-key grant in *Context* becomes
  `cache.shared = true`, and `net.internal` returns to what § 3 wrote it for: excepting an internal
  address a program's own code reaches.
- **An application's `nvs.toml` stops naming its store's address.** A grant that says "may reach the
  coherent tier" is portable across deployments that put the tier in different places, which a
  host-scoped grant was not.
- **Sessions and rate limits over a socket cost no round trip on the network at all.** `rule:http-server/a-session-store-answers-four-operations`'s "one
  round trip on a read and two on a write" becomes a local one where a deployment is single-machine,
  which is priority 3 recovered without spending any of priority 1 — the local *cache* tier is still
  refused a session by [0059](0059.md) § 4, and for the reason it always
  was: a socket is coherent across cores and a per-core map is not.
- **Windows deployments cannot use any of it.** `mio` carries no `AF_UNIX`, so § 4 refuses the spelling
  and those deployments stay on loopback TCP. The gap closes if `mio` gains the transport, with no
  decision here to revisit.
- **`crates/nvs-db` gains an `AF_UNIX` connect path in three drivers.** MySQL, MariaDB and Postgres each
  speak their existing protocol over the new transport; none of them gains a second wire.

## Alternatives rejected

- **Keep `net.connect` and carve `[cache.shared]` out of the address table only.** Fixes the loopback
  double grant with a one-line amendment and leaves the grant roster closed. Rejected because it answers
  half the question: the app still names a host it has no business knowing, and a socket path still has
  nothing to put in `connect`, so § 2 would need its own unrelated answer. The two problems have one
  cause — the grant asks about an address — and one fix.
- **Gate a socket on `fs.write` over its path.** No new capability, and `Scope::Path` with
  canonicalise-then-prefix already exists. Rejected: it makes one grant mean both "may write files here"
  and "may talk to whatever daemon listens here", so `fs.write = ["/run/"]` — written to let an
  application reach Redis — also permits overwriting every socket and pidfile in `/run`. Two guarantees,
  one name.
- **Admit a program-supplied socket path now, with `net.local`.** Settles `Core\Net`'s case in the same
  pass. Rejected on § 6: the member does not exist, so the grant would ship unexercised, and § 2's
  restriction is the conservative half of a decision that is cheap to loosen later and expensive to
  tighten.
- **A bare path in `[cache.shared] url`**, on the listening side's overload. Uniform with
  `[db.<name>] host` and with [0097](0097.md) § 5. Rejected on § 3:
  the key is named `url`, its parser already dispatches on scheme, and a non-URL in a key called `url` is
  a thing to re-litigate rather than a thing to read.
- **Fall back to loopback TCP where `AF_UNIX` is absent**, so one configuration serves every platform.
  Rejected in § 4: it is the `rediss://`-served-as-`redis://` failure from the other direction.
- **A full socket path for Postgres**, uniform with MySQL's. Rejected on § 5: no existing Postgres
  connection string is written that way, so uniformity here is paid for by every migrating deployment.

## Verification

- A program granted `cache.shared` and **no** `net.connect` reaches a store at `redis://127.0.0.1:6379`
  with no `net.internal` entry — `a_configured_store_needs_no_address_grant`. The contrast is the test:
  the same program without `cache.shared` is refused, so the grant is shown to be doing the work rather
  than nothing being checked.
- A socket path handed to `Core\Net::connect`, to `Core\Db::open`'s settings and to
  `Core\Http\Client` is refused in all three, and refused as a target rather than as a file that could
  not be opened — `a_program_supplied_socket_path_is_never_a_target`. Asserted over all three doors,
  because § 2's rule is about the class of endpoint and a rule proven at one door is a rule the next door
  can be written without.
- `[cache.shared] url = "unix:/run/redis.sock"` on a build with no Unix transport is `E0627` at boot,
  its note naming the platform and the file the key was written in. On a build that has one, a record
  written through the socket is read back through it.
- `[db.main] host = "/var/run/postgresql"` with `port = 5432` opens `.s.PGSQL.5432` under that directory,
  asserted against the path the driver actually connects to rather than against a successful connection,
  so the derivation is what is under test.
- The `nvs-db` matrix gains a socket leg for MySQL, MariaDB and Postgres, running the same case list the
  TCP legs run — the drivers are asserted to agree across transports, which is the property a second
  transport has to have. MSSQL refuses a path, asserted by the diagnostic and not by a failure to
  connect.
- A `[cache.shared] url` set with no `cache.shared` grant produces the boot `Warn` *Consequences* names,
  so the migration is reported where it can be acted on.
