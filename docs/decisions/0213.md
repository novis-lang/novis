# ADR 0213 — Two habits the compiler accepted and did nothing with are warned about where they are written: a `/** … */` block above a declaration, and `{Class::…}` inside a markup literal

- **Scope:** two advisory diagnostics, `W1011` and `W1012`, and the reference headings that make
  `///` and the `<?= … ?>` hole reachable through `nvs agent find`. What a doc comment is, and
  what a markup literal's holes admit, are unchanged and stay with [0137](0137.md) and
  [0202](0202.md).
- **Depends on:** [0137](0137.md), [0202](0202.md), [0169](0169.md).
- **Validated by:** `crates/nvs-syntax/tests/doc_comments.rs` and
  `crates/nvs-syntax/tests/markup_literal.rs`.

> **In short:** a framework built by a coding agent through `nvs agent` and `nvs check` documented
> every class, method and constant with `/** … */`, and every one of those blocks was an ordinary
> comment nothing read; the same program printed `{Page::TITLE}` into a page as literal text. Both programs
> passed `nvs check` with `no errors`, which a reader takes as the answer to "is this allowed?".
> Neither shape is ever what was meant, both are the habit of the language most readers arrive
> from, and both are cheap to name at the character where they go wrong. Each is a warning and not
> a refusal, because the program is correct: what is wrong is that its documentation is dropped,
> or its page prints the wrong string, without a word.

## Context

### 1. What was reported

A report written after building a framework entirely through `nvs agent`, `nvs check` and the
reference found four things the compiler accepted and did nothing with. Two — a property
inside an `interface` body, and `static::CONST` reading the declaring scope — were already
refusals or fixes by the time the report landed. The two here are the ones that produce a clean
program with a silent defect:

| Written | What happened | `nvs check` |
|---|---|---|
| `/** … */` on every declaration | dropped; invisible to `nvs meta`, `nvs doc` and the editor | `no errors` |
| `{Class::CONST}` in an `html` literal | printed into the page as text | `no errors` |

The first was found only when a person said "Novis has `///`". The reference's `# Comments`
section did not mention it, `nvs agent find doc` did not reach it, and the attributes chapter's
own example used a `/** */` block until the same week.

### 2. The pattern behind both

`rule:tooling/doc-comment-is-three-slashes` already says a `/**` block is an ordinary comment, and
`rule:core-classes/html-literal` already says a brace hole begins with `$`. Both rules are right
and both are silent at the one place a reader is looking: the diagnostic output of `nvs check`.
A rule a reader can only learn by reading the rulebook is, for an agent that reads `find` fifty
times and the primer once, a rule that does not exist.

## Options considered

### 3. Say nothing, document better

Adding `///` to the comments section and a heading for the tag hole is done here regardless, and
it is not enough: the report's authors had the documentation of the literal in front of them and
still shipped `{Page::TITLE}`, because nothing in the output of the program said the brace was
text. A heading fixes discovery; it does not fix the program that was already written.

### 4. Refuse both

Refusing a `/**` block above a declaration would refuse a comment, which no other rule does, and
would turn every converted PHP file into a wall of errors before a single `///` was written.
Refusing `{Class::…}` would grow the hole grammar by a negative — a brace that is text unless it
looks like this — which is the second interpolation grammar 0202 declined. Both programs are
correct; a refusal would say otherwise.

### 5. Warn, narrowly

A warning at the block, and a warning at the brace, each with the one-token fix in its help. The
trigger for the first is a block that opens with `/**` and has a body, across no blank line from
the declaration or from the `///` run above it — so a divider block, a block above a statement
and `/**/` stay silent. The trigger for the second is `{` directly followed by a name and `::`
inside a markup literal — so a CSS block, `{not a hole}`, `\{` and the same text in a
double-quoted string, where the habit is PHP's own, stay silent.

## Decision

### 6. `W1011`: a `/** … */` block directly above a declaration documents nothing

The lexer keeps a `/**`-opening block comment on the compile path, as it already keeps a `///`,
and the parser checks for one at the point where a declaration takes its doc run. The check reads
the source text between the block and the declaration, as attachment does, so the compile path
and the trivia path answer identically. Reported once per block.

### 7. `W1012`: a brace before a class path in a markup literal is text

The lexer reports it while scanning a markup literal's text segment, at the brace, covering
through the `}` that closes it on the same line; the help rewrites that text as `<?= … ?>`. The
bytes stay text, and a `$name` inside them still interpolates as it did.

### 8. The headings

The programs chapter gains `# Doc comments: ///`; the types chapter gains `## inout` and
`### <?= expr ?>` under the markup section; the tools reference gains a server chapter, since
`Core\Request::mount()`, the mount table and the request lifecycle had no heading at all. An
empty `nvs agent find` now says that a keyword may sit under a heading that does not name it.

## Diagnostics

### 9. The two codes

- `W1011` — *this `/** … */` block documents nothing*, at the block; help: *`/** … */` is an
  ordinary comment; write `///` for a doc comment*.
- `W1012` — *this brace opens no hole*, at the brace through its `}`; help: *a brace hole begins
  with `$`; write `<?= Page::TITLE ?>` for any expression, or `\{` for a brace that is meant to
  stay*.

## Consequences

### 10. What a compile spends

One `starts_with("/**")` per block comment in the lexer, and one byte test per `{` inside a markup
literal's text. Nothing on any request path, and no program output moves: both are advisories.

### 11. What a reader gets

A converted PHP file with docblocks on every declaration prints one warning per block on its
first `nvs check`, which is the moment the author learns the marker. A page that prints
`{Page::TITLE}` is caught before it ships.

## Alternatives rejected

### 12. Warning on `{Class::…}` inside a double-quoted string

Declined. The string's grammar is PHP's own, its limitation is one every PHP programmer already
knows, and a string is not a page: the defect the warning exists for is a wrong string reaching a
reader.

### 13. A guard test over every lexer keyword

Declined as written. The keyword table carries every spelling Novis refuses too — `and`, `goto`,
`global` — and a heading per refused word is the wrong shape. The guard is a fixed list of the
syntactic forms Novis has, each of which `find` must reach through a heading.

## Verification

### 14. What holds it

`doc_comments.rs` holds the four declaration kinds warned about, the five shapes that are silent,
and a block above an attached `///` run. `markup_literal.rs` holds the span, the help's rewrite,
the unclosed brace and six silent braces. `crates/nvs-cli/tests/agent.rs` holds the list of
syntactic forms each reachable through a heading.
