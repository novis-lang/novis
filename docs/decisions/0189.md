# ADR 0189 — What the checker prepares reaches the member as a leading constant of the call, and it is a fact rather than an object

- **Scope:** the channel from `nvs-types`' intrinsic pass to the running member — where a prepared
  answer is filed, how it is addressed, what it may be, and which members take one. It does not decide
  what any grammar prepares; a row's own answer is [ADR 0057](0057.md)'s.
- **Depends on:** [0057](0057.md) (the intrinsic roster and preparation), [0063](0063.md) (a call's
  arguments are addressed by parameter), [0018](0018.md) (the artifact's identity).
- **Validated by:** `crates/nvs-ir/tests/prepared_patterns.rs`.

> **In short:** the checker files what it prepared under the **call's** span; the lowering reads it
> there and emits it as argument 0 of that call, for a closed roster of members
> (`nvs_stdlib::registry::PREPARED_MEMBERS`); the word rides in the unit's own code, so the artifact
> carries it with nothing serialized beside it. What crosses is the durable *fact* a preparation
> settled — the engine tier of a regex literal — and never a live object, because a compiled automaton
> belongs to the core that built it.

## Context

### 1. Validation paid for itself; preparation had nowhere to go

`rule:expressions/intrinsic-list-is-closed`'s pass reads a written literal against its member's
grammar while the program is checked, and that read has two effects. The first is a refusal, and it
needs no machinery: a malformed pattern is a diagnostic and the program does not run. The second is
the answer the read *produced* — which engine a pattern routes to, what a format template expands to,
which placeholders a statement binds — and that half had no way out of the checker at all. The roster
named what each row prepares and nothing carried it, so every member derived its own answer again at
the first call.

`rule:expressions/preparation-preserves-behaviour` already promised the second half ("the compiler
calls the same pattern compiler … and stores the output"), which made the gap a divergence between a
rule and its implementation rather than an unbuilt idea.

## Investigation

### 2. Three things the channel had to survive

**A compiled pattern cannot be stored.** `nvs_stdlib::regex`'s cache holds an `Rc<Compiled>` on one
core, deliberately: the runtime is thread-per-core and shared-nothing, and a compiled program is
derived from the text, so a per-core cache needs no lock and cannot become cross-request state. An
artifact cannot hold one either — the `.nvsc` payload is an object file, and an automaton is a graph
of allocations. So "store the prepared pattern" could never have meant the automaton, whatever the
roster's own wording suggested.

**The literal's span is not an address the lowering holds.** The pass records against the span it
underlines a refusal at, which is the literal's. `nvs-ir` lowers a *call*, and what it holds is the
call's span — the same key every other resolved fact about that call is filed under. A channel keyed
on the literal would have made the consumer re-derive which argument filled the row's parameter, which
is exactly the mapping `rule:core-api/parameters-are-callable-by-name` put in the checker so that
nothing below it has to hold `MethodSig::param_names`.

**A slot that is sometimes absent is a slot read past.** A member's helper reads a fixed argument
list. If the constant were emitted only where something was prepared, the same member called with a
computed pattern would read its first argument out of the caller's next slot.

## Decision

### 3. The record names the literal and is filed under the call

`nvs_types::expr_table::Prepared` carries both spans' worth of answer: `fact` is what the read
produced, `literal` is where the text was written. The table is keyed on the **call's** span, so the
lowering's lookup is the one address it already has, and a reader that wants to *name* the pattern —
a test, the tier record — slices the source at `literal`.

### 4. A closed roster, one leading constant, and the zero word

`nvs_stdlib::registry::PREPARED_MEMBERS` is the roster of members whose helper takes the prepared word
as **argument 0**, ahead of everything including a receiver. It is a roster and not a field on every
registry row for `WRITTEN_CLASS_MEMBERS`' reason: a handful of members against two hundred rows, where
a field would be empty on nearly all of them. A member on it is handed
`nvs_stdlib::regex::PREPARED_NONE` where its argument was not a literal, so the slot is written at
every call site and the helper reads one ABI.

### 5. What may cross is a fact, and the encoding lives beside the decoder

`nvs_ir::ir::Prepared` is the closed set of facts a word can be, and `nvs_ir::ir::prepared_code` turns
one — or the absence of one — into the word. The numbers themselves live in `nvs_stdlib::regex`,
beside the helper that decodes them, and reach the compiler through `nvs-types`' re-exports: two ends
of an ABI spelling the same constant twice is the failure this shape rules out.

The first passenger is `Core\Regex::compile`, carrying the tier its pattern settled in. The runtime
still compiles — that is the bound § 2 states — but it no longer offers a backtracking pattern to the
linear engine's parser first in order to be told what the compiler already knew.

### 6. What is not decided here

Every other roster row prepares by validating alone. A parsed CLDR pattern, a `printf` plan and a
bound SQL statement are all facts that could travel this channel, and each is a member joining the
roster plus a fact variant — not a second mechanism. Nothing here forecloses that and nothing here
schedules it.

## Consequences

**What it spends.** One `iconst` per call site on a roster member, and one machine word in the
argument list of members that take it — no allocation, no data section, nothing per request. A member
off the roster is unchanged instruction for instruction.

**What it buys.** The first compile of a backtracking literal in a process skips the linear engine's
parse. That is a small win by itself; what it makes possible is the rest of § 6, where the answer not
derived again is a parse at every call rather than once per process.

**A word this build does not know is read as "nothing was prepared."** The alternative — a helper that
refused an unrecognized word — would turn a compiler-version skew into a failed request, and
`rule:packaging/an-artifact-is-one-immutable-content-addressed-file` already puts the compiler build
in the artifact's address, so a cached unit cannot hand a process a word another compiler minted.

## Alternatives rejected

**A table on `ir::Program`, interned and pointed at**, the way an inline shape's wire contract is. It
is the right shape for a prepared *plan* and the wrong one for a fact that fits in the slot: a table
would buy an indirection and an entry per distinct pattern to carry two bits. The variant that needs
it can add it, and § 5's encoding is what would make that a second `InstKind` rather than a change to
this one.

**Seeding the per-core pattern cache at unit load.** It needs no ABI at all, which is its whole appeal,
and it fails on the two things this design is for: a unit is loaded once and cores are many, so the
seeding is either cross-thread or repeated per core; and it can only ever pre-fill a cache keyed by
text, which is a mechanism `Core\Regex` happens to have and no other grammar does.

**Keying the checker's record on the literal's span** and having the lowering find it by walking the
call's written arguments. It re-derives the parameter-to-argument mapping in a crate that deliberately
does not hold the signature names, and it gets `name:` and `...` wrong in exactly the ways § 2's third
paragraph describes.

## Verification

`crates/nvs-ir/tests/prepared_patterns.rs` lowers the three shapes a roster member's argument takes —
a linear literal, a backtracking literal, a computed pattern — and asserts the facts arrive in written
order, that the word is the call's argument 0, and that a member off the roster grew no slot.
`crates/nvs-types/tests/intrinsics.rs` remains the home of *which* tier a pattern settles in, over
every pattern the conformance suite writes.
