# ADR 0197 — A mount capture may be written in lower case, a brace that is not a reference is refused, and no part of a URL takes its case rule from the filesystem

- **Scope:** how case is treated along a URL as the mount table sees it — what a capture expands
  to, what a brace in `prefix`, `host` or `origin` means, how a host is held, and what steps 3 and 4
  do with a remainder the disk holds in another case. Case-insensitive prefix matching and a redirect
  to a canonical case are considered and declined. Route matching is not touched.
- **Depends on:** [0097](0097.md), [0104](0104.md).
- **Validated by:** `crates/nvs-config/tests/mount.rs` and the `mount` tests in
  `crates/nvs-server/src/mount.rs`.

> **In short:** `{n:lower}` expands to the capture in ASCII lower case, and `lower` is the whole
> transform set. Any other brace in `prefix`, `host` or `origin` is `E0621`. A host is held in lower
> case, so the duplicate check and the override agree with the request-time comparison. A remainder
> that differs from the file on disk only in case does not select it, on any operating system.

## Context

A deployment of ninety modules mounted by one glob reported that it could not keep all three of: a
directory named for the namespace it holds, the lower-case URL its users have bookmarked, and a
configuration with no per-module block. `autoload` compares a path's case exactly
(`rule:programs/path-case`), so the directory is `CMB`; the capture expands verbatim and a prefix is
matched exactly, so the URL is `/fw/CMB.dev`. A proxy in front cannot change a path's case without
naming every module.

The same report found that `{1:lower}`, `{x}` and `{}` all pass `nvs config check`, boot, and produce
a mount nothing reaches. It cost the reporter an afternoon believing a transform existed.

## Investigation

Reading the two matchers beside each other found the URL treated four ways:

| Part | Case | Where |
|---|---|---|
| `host`, against a request | folded | `nvs-server`'s step 1 |
| `host`, in the duplicate check and the override | exact | `nvs-config`'s `expand` |
| `prefix` and a route's literal segments | exact | step 1, `rule:routing/path-grammar` |
| the remainder, in steps 3 and 4 | the filesystem's | a bare `metadata` call |

The second row is a defect: `host = "A.example.com"` and `host = "a.example.com"` passed the
duplicate check as two keys and then both matched every request for that name, and an explicit
`entry` written in one case did not override a scanned mount expanded in another. The fourth row
means `/STYLE.CSS` serves `style.css` on Windows and macOS and is the entry's `404` on Linux.

The literal-brace reading was deliberate and tested. It does not survive its own premise: a brace
is not a character a host name carries, a URL path carries one only percent-encoded, and step 1
compares a prefix with the path as it was sent.

## Options considered

1. **A transform in the reference**, `{1:lower}`. Boot-time only; the table still holds one literal
   prefix per mount.
2. **A key on the block**, `case = "lower"`. Reopens `rule:http-server/a-mount-carries-no-policy`'s
   closed key set, and cannot say "lower in the prefix, verbatim in the origin's path".
3. **Case-insensitive prefix matching.** One resource gains many URLs, and every request pays a fold.
4. **A redirect to the canonical case.** Still does not let an operator choose the canonical
   spelling.

## Decision

### 1. `{n:lower}` is the capture in ASCII lower case

A reference is `{n}` or `{n:lower}`. The transform belongs to the reference, so one template may
hold both. The set is closed at `lower`: `upper` has no deployment asking for it, and a closed set
is one line to extend. `Mounted::captures`, and so `Core\Request::mount()`, keeps the directory's
own spelling. Two captures a transform folds onto one key are the existing duplicate refusal.

### 2. Any other brace in `prefix`, `host` or `origin` is `E0621`

Braces around anything else, a `{` nothing closes, a `}` nothing opened, and a `{` inside a
reference. A reference is digits only, so `{+1}` is not one.

### 3. A host is held in ASCII lower case

`expand` lower-cases the substituted host. The request-time comparison still folds, so a table
built by hand behaves the same.

### 4. A remainder in another case is a file that is not there

Steps 3 and 4 compare the canonical path the disk returned with the path the remainder spelled. A
difference that is only case declines the step, and the request falls to step 5.

## Diagnostics

`E0621`, three messages: the existing out-of-range one, "writes `{…}`, which is not a capture
reference", and "has a `{` that pairs with nothing".

## Consequences

- Nothing is added to a request in production. § 3 removes nothing from step 1 and adds nothing;
  § 4 is two path comparisons in steps that production does not run, and allocates only when the
  paths already differ.
- A configuration with a stray brace stops booting. Its mount was unreachable, so nothing that
  worked stops working.
- A development URL that was mis-cased and worked on Windows or macOS now reaches the entry, which
  is what it did in production on Linux.
- A symlink whose own name is its target's in another case is declined with the rest: nothing at
  hand can tell it from the filesystem folding the name.
- Windows' other aliases for a name — a trailing dot or space, an 8.3 short name — are not case
  differences and are not decided here.

## Alternatives rejected

Options 2 to 4 above. Lower-casing every capture in a prefix unasked was also rejected: it would
move every existing mixed-case deployment's URLs.
