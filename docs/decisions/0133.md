# ADR 0133 — A launderer answers its sink's carrier, and only an idempotent escape answers a `string`

- **Scope:** what the *return type* of a laundering `Core` member is, and the predicate that decides it;
  `Core\Html::escape` answering `Core\Html\Markup`; `Core\Html::toSource` as the one reasoned way back to a
  `string`; the return type `Core\Html::sanitize` will have when it lands. Not in scope: what makes a
  parameter a sink, which is [0088 § 1](0088.md); the
  `tainted` qualifier, its sources and its propagation, which are
  [0024](0024.md); the terminal's substitution table, which is
  [0086 § 1](0086.md); the HTML parser `sanitize` waits on, which is
  [0122](0122.md).
- **Depends on:** [0024](0024.md) — § 3 is the rule this refines and
  § 5 is the sink that makes the refinement necessary.

> **In short:** `rule:security/launderers-are-sink-named` says a launderer answers the
> plain unqualified type. That is right for every sink a developer invokes by hand and wrong for the one
> sink that launders on its own: HTML. An escaped value returned as a `string` is indistinguishable from
> text nobody has escaped, so § 2's concatenation rule re-poisons it and § 5's escape-and-lift escapes it a
> second time — `&` becomes `&amp;amp;` with no diagnostic anywhere. The fix is a **predicate, not a list**:
> a launderer answers its sink's carrier type when its sink launders automatically **and** its transform is
> not idempotent. Exactly one member on today's roster meets both, so `Core\Html::escape` answers
> `Core\Html\Markup` and everything else keeps its `string`. `Core\Html\Markup` composes with `+` and
> refuses `.`, which is already built, so the double escape stops being a runtime surprise and becomes a
> compile error. `Core\Html::toSource(Markup, string $reason): string` is the one way back, modeled on this
> project's `unsafe` policy: rare, greppable, and carrying a written reason.

## Context

- `rule:core-classes/html-auto-escape` makes HTML the one sink that launders *for*
  you: `echo` under an HTTP request accepts only `Core\Html\Markup`, and every non-`Markup` interpolation is
  escaped and lifted with no call in the source. § 3, written for the sinks that refuse rather than
  transform, makes `Core\Html::escape` answer a plain `string`.
- Those two do not compose. A `string` carries one bit of state where the domain has three — *untrusted*,
  *plain text nobody has escaped*, and *already escaped for this sink* — and the second and third are the
  same type. So:

  ```nvs
  tainted string $name = Core\Request::query("name");   // Tom & Jerry
  string $safe = Core\Html::escape($name);              // Tom &amp; Jerry
  tainted string $line = "Hello " . $safe;              // § 2 re-poisons it, correctly
  echo $line;                                           // Hello Tom &amp;amp; Jerry
  ```

  Every step is the rule working as specified. The bug is that `$safe`'s type forgot what had been done to
  it, and the sink cannot ask.
- **The hazard needs two things at once**, which is why it is not everywhere: a transform that is not
  idempotent, *and* a sink that applies it without being asked. `Core\Db::quoteIdentifier`,
  `Core\Uri::encodeComponent` and `Core\Regex::quote` are all non-idempotent, and all three are safe,
  because breaking one takes a visible second call in the source. `Core\Cli::escape` sits under an
  auto-substituting sink and is safe the other way, because `␛` contains no `ESC`
  ([0086 § 1](0086.md)).
- **This repository had already reached the conclusion twice without generalising it.**
  [`Core\Http::allowUrl`](../../crates/nvs-stdlib/src/http.rs) answers a `Core\Http\Target`, and its row
  says a `Qual::Launder` that returned a `string` "would have removed the qualifier and left the rebinding
  gap open". [`Core\Out::capture`](../reference/core/Out.md) answers the carrier of the sink in force,
  "never a plain `string`, so re-emitting it is one more `echo` and it is not escaped a second time". Both
  are § 1's rule, stated for one member each.

## Decision

### 1. The predicate: when a launderer answers a carrier

A `Core` member that removes the `tainted` qualifier answers its sink's **carrier type** rather than the
plain unqualified type when **both** hold:

1. **its sink launders automatically** — a value reaches that sink and is transformed with no call written
   at the site, and
2. **its transform is not idempotent** — applying it to its own output changes the output.

Otherwise it answers the plain unqualified type, exactly as
[0024 § 3](0024.md) already says.

The two conditions are one question asked twice: *a second application the source does not show, of a
transform a second application changes.* Neither alone is a hazard, which is why this is a predicate and
not a preference for carriers.

| Sink | Launders on its own | Idempotent | Its launderer answers |
|---|---|---|---|
| HTML output ([0024 § 5](0024.md)) | yes | no — `&` → `&amp;` → `&amp;amp;` | `Core\Html\Markup` |
| Terminal ([0086 § 1](0086.md)) | yes | yes — `␛` holds no `ESC` | `string` |
| SQL query text ([0067 § 5](0067.md)) | no | no | `string` |
| URI component, form value | no | no — `%` → `%25` | `string` |
| Regex pattern ([0056](0056.md)) | no | no — `\` → `\\` | `string` |

A launderer written for a *new* sink is measured against the two conditions, not against this table. A
sink that acquires an automatic launder later reclassifies its own member on the day it does.

### 2. `Core\Html::escape` answers `Core\Html\Markup`

`Core\Html::escape(tainted string $text): Core\Html\Markup` — the one member on today's roster that meets
both conditions. The bytes it produces are unchanged; only the wrapper is new.

The composition half is already built and already correct.
[`Markup + Markup` is `Markup`](../../crates/nvs-types/src/expr/operators.rs), `.` has no row for a
carrier, and a mixed `$markup + "x"` is refused rather than escaped — `+` is not a sink, and an operator
that escaped silently would be the same surprise this ADR removes. So the *Context* program now reads:

```nvs
tainted string $name = Core\Request::query("name");

echo "Hello ", $name;                                       // the sink escapes once
echo ("Hello " as Markup) + Core\Html::escape($name);       // the same output, said explicitly

Core\Html\Markup $m = Core\Html::escape($name);
tainted string $line = "Hello " . $m;                       // refused: `.` has no row for `Markup`
```

**The eager-escape habit stops compiling**, which is the point. A developer arriving from
`htmlspecialchars()` is corrected at the call site instead of shipping `&amp;amp;`, and for most code the
correction is to delete the escape call: the sink was always going to do it.

### 3. `Core\Html::toSource` is the one way back to a `string`

`Core\Html::toSource(Core\Html\Markup $markup, string $reason): string` hands back the markup's source
text. There is **no `Markup as string` conversion**, because one would reopen the hole in a keystroke:
`Core\Html::escape($x) as string . $tainted` is the *Context* bug with an extra word in it.

This is modeled on `Core\Taint::assertTrusted` and, behind it, on this project's own `unsafe` policy: an
escape hatch that is rare, greppable, and carries a written reason at the site rather than a silent cast.
`$reason` is a source literal and an empty one is refused — a reason that can be computed is a reason
nobody wrote.

Its legitimate callers are the ones that need the bytes and not the guarantee: caching a rendered fragment,
storing one in a column, writing one to a file, handing one to a sink that is not this one.

The name follows [0063 § 1](0063.md): `to…` is R5's conversion verb, `source` is a
full word under R7, and it is deliberately neither `raw` — which in every template language means the
opposite direction — nor `unescape`, which R6 reserves for the operation that actually inverts `escape`
and which this is not.

### 4. `Core\Html::sanitize` answers `Markup`

[ADR 0051 § 3](0051.md) owes `Core\Html` a sanitizer and
`rule:core-classes/html-parsing`'s tree is what it waits
on. Its return type is fixed here rather than there, while it costs a sentence: it answers
`Core\Html\Markup`.

That makes it [0024 § 5](0024.md)'s **fourth** way to obtain a `Markup`,
and the only one that takes a runtime-computed string — which is exactly why it must be a parser that
rebuilds the document from a known-good grammar, and never a filter that deletes what looks dangerous. A
filter answering a carrier would be the generic `sanitize()` § 3 refuses, wearing a type.

### 5. What does not change

`Core\Db::quoteIdentifier`, `Core\Uri::encodeComponent`, `Core\Uri::encodeFormValue`, `Core\Regex::quote`
and `Core\Cli::escape` keep their plain `string`, by § 1 rather than by exemption. Their results are
legitimately concatenated into a larger string, and a carrier would force a builder API onto four classes
to close a hazard whose second call is already visible in the source.

## Consequences

**Positive**

- The double escape moves from a silent runtime corruption to a compile error, at the site that caused it.
- The three-state domain gets three types. `tainted string` is untrusted, `string` is text the sink will
  escape, `Core\Html\Markup` is HTML that is finished — and no operator moves a value backwards between
  them.
- Order stops mattering. Under the *Context* bug the answer depended on where in a concatenation the
  escaped fragment sat; under § 2 every ordering is either correct or refused.
- It costs nothing at runtime that was not already spent: the escape-and-lift path allocates a `Markup`
  already, so this removes the second escape rather than adding a wrapper.
- Three members that had each argued the rule alone — `Core\Http::allowUrl`, `Core\Out::capture`, and now
  `escape` — read as one rule with three instances.

**Negative**

- **`nvs convert` gains a second non-mechanical HTML gap**, beside the one
  [0024](0024.md) already carries. `htmlspecialchars($x)` used in a
  string-building position now needs a human: either the escape is deleted and the sink does it, or the
  concatenation becomes `+` over `Markup`.
- **Escaped HTML cannot be stored or logged as text without `Core\Html::toSource` and a written reason.**
  That is usually the bug rather than the use case — escaped markup in a database is a classic one — but it
  is a real restriction with a real per-call-site cost.
- One more thing a laundering member's author must decide. § 1 makes it a two-question check rather than a
  judgement, and *Verification*'s registry test makes forgetting it fail rather than ship.

## Alternatives rejected

- **Have the HTML sink detect already-escaped text and skip it** — PHP's `htmlspecialchars($s, …, $double)`
  parameter. Rejected: `rule:errors/ambiguous-input-refused` refuses exactly this
  repair, and `Core\Html`'s own module doc already argues it out of existence — `&amp;` in the input is
  text that said `&amp;`, and it must come back as `&amp;amp;`. A sink that guesses is a sink an attacker
  can aim.
- **A third qualifier, `escaped string`.** Rejected: new grammar, a new keyword and a third axis in the
  checker, to express what a class that already exists expresses for free.
- **`Markup . string` escapes and lifts the other operand instead of refusing.** Rejected: `.` produces a
  `string`, so composing two carriers through it would lose exactly what a carrier carries, and an operator
  that escaped silently would reintroduce the invisible second transform.
- **`Markup as string`, freely.** Rejected: one keystroke back to the *Context* bug, with the type system
  no longer able to say anything about it.
- **A carrier for every non-idempotent launderer**, with `Core\Uri\Component`, `Core\Db\Identifier` and
  `Core\Regex\Pattern`. Rejected under § 5: one uniform rule with no exemption list, bought by forcing a
  builder API onto four classes whose values are normally assembled by concatenation, against a hazard that
  takes a visible second call to reach.

## Verification

- **`nvs check` corpus**, beside [0024](0024.md)'s own entries:
  `Core\Html::escape($t) . "x"` is a diagnostic naming the carrier and the two fixes; `Core\Html::escape($t)
  + ("x" as Markup)` type-checks as `Core\Html\Markup`; `Core\Html::escape(Core\Html::escape($t))` is
  refused at the parameter rather than accepted as text.
- **A registry guard test**, in the shape of `nvs-stdlib`'s
  `validate_launders_only_what_it_actually_validated`: every `Qual::Launder` member either answers a
  carrier or appears on a named list with the § 1 condition it fails. A launderer added for an
  auto-laundering sink fails on the day it lands, in whichever class it is added to.
- **A `.nvst` case for the whole of *Context***: the tainted value, the source literal and the escaped
  fragment, rendered once through each of § 2's two spellings, both producing `Tom &amp; Jerry` exactly
  once.
- **`Core\Html::toSource`'s reason is checked, not merely declared**: a non-literal or empty `$reason` is a
  diagnostic, and the member's call sites are greppable by name — the same property
  [0033](0033.md) § 3's reveal roster relies on.
