# ADR 0137 — A doc comment is `///`, and its only tags are `@see` and `@example`

- **Scope:** what marks a comment in *Novis source* as documentation, what may appear inside one, which
  tools consume it, and when an undocumented public member is reported. Not in scope: where an
  implemented `Core` member's documentation lives, which is
  [0117](0117.md) and is unchanged — a
  `Core` member is Rust and documents itself in the registry, so it never carries a `///`; the trivia
  layer's losslessness property and the `SyntaxIndex`, which are
  [0099](0099.md) § 1; the LSP's request set, which is
  [0099](0099.md) § 5 and M4B; the website's rendering, which
  [website/README.md](../../website/README.md) owns; and Rust's own `///`/`//!` in `crates/`, which is a
  different language's mechanism entirely.
- **Depends on:** [0099](0099.md), [0117](0117.md)

> **In short:** a doc comment is **`///`**, lexed as `TriviaKind::DocComment`; `////` and longer runs
> are ordinary comments, as in Rust. Its content is **prose in Markdown plus exactly two tags** —
> `@see`, naming a member, and `@example`, naming a file — and **any other `@tag` is a diagnostic**,
> which is what makes the set closed rather than merely recommended. There is deliberately no `@param`,
> `@return`, `@throws`, `@var` or `@deprecated`: the first two are the signature, which cannot drift
> from itself; `@throws` is [0117](0117.md)'s
> registry field for `Core` and a sentence in the prose for user code; every binding is annotated so
> `@var` has nothing to say; and deprecation is an attribute
> ([0046](0046.md)). **`nvs meta --json` is the one consumer**, gaining
> an optional program argument so it emits a program's own declarations beside the `Core` registry it
> already emits — so `tools/reference.py`, the website's `sync:core` and `nvs doc` are renderers over
> one JSON rather than three sources of truth. `nvs doc` renders that JSON to Markdown from inside the
> binary, for a project that does not have this repository's tools. **Nothing requires a doc comment by
> default**: `nvs check --strict-docs` reports a public member without one, and publishing a package
> turns that on — a check that can never be satisfied by an autofix, because with no `@param` or
> `@return` to fill in, a generated `///` would be empty.

## Context

- [0099](0099.md) § 5's hover row already promises "for a
  declaration, its own doc comment out of the trivia layer." Nothing defines which trivium that is, so
  the promise cannot currently be kept. **This ADR exists to close a hole, not to add a feature.**
- [0117](0117.md) settled the same question
  for `Core` and its reasoning transfers: documentation belongs next to the thing it documents, in a
  machine-readable form, so that a contributor changing behaviour does not have to remember to update
  prose somewhere they will never otherwise look. For a `Core` member that place is the registry
  declaration. For a Novis declaration it is the source file, and there is nowhere else it could be.
- **Almost nothing PHPDoc carried survives into Novis, and this is the whole reason the tag set is
  empty.** `array<T>`, unions, literal types, inline `{name: T}` shapes and — since
  [0136](0136.md) — a callable's signature are all *types*
  ([0007](0007.md) § 3). `#[Deprecated]`-style metadata is attributes
  ([0046](0046.md)). "This touches the filesystem" is a declared
  capability ([0118](0118.md)). What is left for a
  comment is genuinely prose: units, ordering guarantees, the surprising edge, and why.
- **The pipeline for this already exists and has two renderers on it.**
  `tools/reference.py` builds `docs/novis.md` from `nvs meta --json`, and the
  website's `sync:core` builds `src/data/core.json` from the same command
  ([website/README.md](../../website/README.md)). Neither re-derives anything from source. A third
  source of truth for user declarations would be the duplication that pipeline's shape exists to avoid.
- **`///` is already being written by hand, informally.** Seven Novis files in the tree carry `///`
  above a declaration — sessions writing Rust habit into Novis — and they read as documentation. One
  file also carries a `//// ____` divider, which is why the run length matters below.

## Decision

### 1. `///` is the marker; `////` is not

`Lexer::skip_trivia` ([lexer.rs:357](../../crates/nvs-syntax/src/lexer.rs)) classifies a line comment
opened by **exactly three** `/` as `TriviaKind::DocComment`. Four or more is `LineComment`, which is
Rust's rule and exists for the same reason: a divider line of slashes is not documentation.

```php
/// The price in cents. Money is `decimal`, never `float`.
/// A negative amount throws; zero is allowed and is a no-op.
public function charge(uint $cents): void { … }

// An ordinary comment. Nothing reads it.
//// ─────────────────────────────  also ordinary
```

`#` comments are never doc comments whatever their length: `#[` already opens an attribute, and a
second doc spelling is what [0015](0015.md) refuses. A `DocComment` run is
**attached to the next declaration** — consecutive `///` lines with only whitespace between them are
one comment; a `///` followed by a blank line and then a declaration is not attached, and a `///`
attached to nothing is a diagnostic.

### 2. Prose plus two tags, and a third is a diagnostic

The body is Markdown. Two tags, each on its own line, in a trailing block:

```php
/// The price in cents, never a float.
///
/// @see Core\Money::fromCents
/// @example examples/charge.nvs
```

- **`@see <member>`** names a class, member, enum or constant. It must resolve, or it is a diagnostic —
  the same standard `tools/check-links.py` already holds 282 markdown files
  to.
- **`@example <path>`** names a file that must exist **and must be inside a directory the test corpus
  walks**, so an example that stops compiling fails the build rather than rotting in a page. `examples/`
  is such a directory today.
- **Any other `@tag` at the start of a line in a doc comment is a diagnostic.** This bullet is the
  entire difference between a closed set and a convention: an unenforced set grows, and the growth is
  how PHPDoc arrived at documenting a signature twice. `@` anywhere else in the prose is just a
  character.

**There is no `@param`, `@return`, `@throws`, `@var`, `@deprecated`, `@since` or `@internal`**, and the
*Context* above is the one home for why each is unnecessary rather than merely discouraged. A parameter
that needs explaining is explained in a sentence that names it — "the timeout is in **milliseconds**" —
which no schema improves on for an audience that is reading the file.

### 3. One JSON, several renderers

`nvs meta --json` stays the single machine-readable source, and every renderer consumes it:

```
                      ┌─ tools/reference.py  → docs/novis.md
nvs meta --json ──────┼─ website sync:core    → core.json → MDX
                      └─ nvs doc              → Markdown pages
```

Nothing re-derives documentation from source, and no renderer is authoritative for content. This is
[0117](0117.md)'s shape extended by one
input rather than a second pipeline beside it.

### 4. `nvs meta --json` gains an optional program argument

Today the command takes none and prints the `Core` registry, a static compile-time table
(`crates/nvs-cli/src/main.rs:509`). It gains an optional entry path:

```
nvs meta --json                 # the Core registry, exactly as today
nvs meta --json app.nvs         # the Core registry, plus that program's own declarations
```

The second form is **program-dependent** — it parses and resolves the program — which is a materially
different command wearing the same name, so it is stated here rather than discovered. The emitted shape
for a user declaration mirrors the registry's own: name, signature, the doc comment's prose, its `@see`
list and its `@example` list. [0117](0117.md)
§ 2 owns the `Core` half of that shape and is unchanged; this ADR owns the user half.

### 5. `nvs doc` renders, and decides nothing

`nvs doc <entry>` writes one Markdown page per class from the JSON of § 4. It ships in the binary
because a user's project does not have `tools/reference.py`, and it is deliberately the least
interesting part of this decision: a renderer with no source of truth of its own, so replacing it
later costs nothing.

### 6. Nothing requires a doc comment by default

`nvs check` is silent about documentation. `nvs check --strict-docs` reports a **public** member with no
attached doc comment; publishing a package turns it on unconditionally, which parks against the package
manager exactly as [0007](0007.md) § *Revisiting* parks its own measured test.

Why this cannot become the failure mode it is modelled against: an editor that demands a docblock is
answered with a generated one, and a generated docblock is noise. Here there is **nothing to generate** —
with no `@param` and no `@return`, a synthesized `///` would be empty, so no autofix is possible and the
only way to satisfy the check is to write a sentence. A private helper is never reported, and neither is
an application, at any setting, unless it asks.

### 7. The bidi boundary is the existing one

A `///` rendered to HTML crosses exactly the boundary
[0087](0087.md) exists for — "a comment that renders as
code" is that ADR's own wording. The lexer already bidi-checks every comment span, and a doc comment
**reuses that check rather than growing a second one**; `nvs doc` and `nvs meta --json` emit text the
lexer has already accepted, so neither needs a check of its own.

## Diagnostics

Bands rather than numbers, because a code is claimed by creating it and `python tools/brief.py` prints
the next free one in each band:

- **Parser band (`E01xx`)** — an unknown `@tag` at the start of a line in a doc comment; a `///`
  attached to no declaration.
- **Name-resolution band (`E03xx`)** — an `@see` that does not resolve; an `@example` naming a file that
  does not exist or that no test directory walks; and `--strict-docs`' undocumented public member.

Wording, in each case naming what to do instead:

- unknown tag → *`@returns` is not a documentation tag; a `callable`'s and a member's return type are in
  the signature. The only tags are `@see` and `@example`.*
- `@param` specifically → *`@param` is not a documentation tag; name the parameter in a sentence
  instead — its type is in the signature.*
- `@throws` specifically → *`@throws` is not a documentation tag; say in prose what the member throws
  and when.*
- unattached `///` → *this doc comment is attached to nothing; a doc comment documents the declaration
  it precedes.*

## Consequences

**Positive**

- **[0099](0099.md) § 5's hover row becomes keepable.** It is
  the only promise in this area and it currently has no referent.
- **The PHPDoc outcome is unreachable by construction, not by advice.** There is no tag for an editor to
  autocomplete and none for a linter to demand, so the specific failure this decision was prompted by —
  a generated block of `@throws` lines nobody reads and everybody deletes — cannot occur.
- **Zero migration.** No `Core` member gains a `///` (they are Rust and use the registry), no Rust file
  changes, and no existing Novis file is required to change: the 187 `.nvs` and 1,694 `.nvst` files in
  the tree are examples, fixtures and cases, and § 6 is silent by default. The seven files already
  carrying `///` are reclassified and read correctly as-is.
- **No frozen output can move.** A trivium's classification never reaches the checker, and
  [0099](0099.md) § 1's losslessness is a property over
  `tokens ⊕ trivia`, so retaining more says nothing about what a program prints.
- **One source of truth gains one input** rather than the tree gaining a second documentation pipeline.

**Negative**

- **`nvs meta --json` becomes two commands under one name** (§ 4) — a static dump with no argument, a
  program analysis with one. Named rather than discovered, but it is a real seam.
- **`nvs doc` is a renderer this repository does not itself need**, since `tools/reference.py` and the
  website already cover every in-tree consumer. It is built for a user's own project and for the package
  ecosystem that does not exist yet; § 5 keeps it cheap to replace for exactly that reason.
- **The strict check has no trigger yet.** "Publishing turns it on" parks against the package manager,
  so until then `--strict-docs` is opt-in only and nothing fires it automatically.
- **A closed tag set is a standing refusal**, and every future request to widen it will look small.
  § 2's diagnostic is what makes refusing cheap; the *Revisiting* entry below is where a case would have
  to be made.
- Memory and latency: the trivia vector is
  [0099](0099.md) § 1's cost, already accepted there and not
  re-charged here. What this ADR adds to a compile is **one variant test per line comment** in
  `skip_trivia`, and nothing on any request path.

## Alternatives rejected

- **`/** */`, the PHPDoc shape.** Immediately familiar, and that is the objection: it is the exact form
  every PHPDoc tutorial teaches and every IDE autocompletes tags into. A habit is harder to refuse than
  a grammar.
- **Adjacency — any comment run above a declaration is its documentation.** Needs no new syntax and
  starts working on every file already written, including converted PHP. But a note-to-self and a
  document become the same token, and only the author knew which was meant. Converted PHP arrives full
  of the first kind.
- **No tags at all, prose only.** Nearly taken. `@see` and `@example` survive because each buys a
  *check* rather than a formatting convention: a cross-reference that must resolve, and an example that
  must still compile. A Markdown link and a fenced block buy neither.
- **An open, unvalidated tag syntax** like PHPDoc's, where tools ignore what they do not know. This is
  the state the decision exists to prevent; recorded so the refusal has a home.
- **An attribute, `#[Doc("…")]`.** Consistent with
  [0046](0046.md) and structurally retrievable, but an attribute
  payload is a compile-time constant expression, which makes multi-paragraph Markdown prose miserable to
  write and worse to read in place.
- **A diagnostic for an undocumented public member in every project.** The pressure would be answered
  by `/// Charges the card.` above `chargeTheCard()` — noise a human typed, which will outlive the
  method's behaviour.
- **A second doc-comment spelling for module-level docs** (`//!`, as Rust has). A Novis file's
  declarations are its surface; there is no module object to document, and
  [0011](0011.md) makes the class the unit. Reconsider only if
  a package's own landing page turns out to need a home in source.

## Revisiting

- **A third tag** — the case has to name a *check* the tag makes possible, not a rendering it would
  improve, since that is the standard `@see` and `@example` met. Prose plus Markdown is the answer until
  then, and § 2's diagnostic is what keeps the question from being decided by accretion.
- **`--strict-docs` at publish** becomes real when the package manager does. If publishing turns out to
  want more than "a public member has a comment" — a minimum length, a required first sentence — that is
  a lint's design and belongs with the publisher, not here.
- **Per-parameter structured documentation**, as `ParamDoc` gives a `Core` member. Parked against the
  same package-manager trigger: `Core` needs it because it renders to a website for readers who never
  see the source, and a third-party package is the first user declaration in the same position. If it
  lands, it lands as a registry-shaped field in the JSON of § 4, never as an `@param` tag.

## Verification

- **The lexer** — `///` lexes as `DocComment`, `//` and `////` as `LineComment`, `#` always as
  `LineComment`; the seven files in the tree already using `///` reclassify with no other change, and
  the `//// ____` divider in
  `tests/conformance/core/encoding-every-encoder-agrees-with-its-own-decoder-over-a-table.nvst` stays an
  ordinary comment.
- **Losslessness is unaffected** — `tokens ⊕ trivia` still reproduces every file in `examples/`,
  `tests/` and the vendored `php-src` checkout byte-for-byte, which is
  [0099](0099.md) § 1's own test with one more variant flowing
  through it.
- **Attachment** — a `///` run attaches to the next declaration across blank-free whitespace, does not
  attach across a blank line, and is a diagnostic when it attaches to nothing.
- **The closed set** — `@see`/`@example` parse; `@param`, `@return`, `@throws`, `@var` and an invented
  `@nonsense` each report, and the first three report the wording that names what to do instead.
- **The checks bite** — an `@see` naming no member fails, and an `@example` naming a file outside every
  test directory fails, both in `nvs check` at default settings.
- **`nvs meta --json app.nvs`** emits a declaration's prose, `@see` list and `@example` list beside the
  `Core` registry, and `nvs meta --json` with no argument emits byte-identical output to today's.
- **No output moves** — the whole `.nvst` corpus and every `examples/` fixture produce byte-identical
  output before and after, which is the claim that makes this ADR additive.
