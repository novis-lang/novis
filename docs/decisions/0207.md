# ADR 0207 — A file a program requires borrows that program's `autoload` map too

- **Scope:** which files a lender lends its map to, which files the survey walks, and what an edit to a
  required file re-walks. The map itself, the borrowed half's silence and `nvs check` stay
  [0198](0198.md)'s.
- **Depends on:** [0198](0198.md), [0099](0099.md).
- **Validated by:** `a_required_file_borrows_the_map_of_the_program_that_requires_it` and
  `a_require_added_to_a_required_file_lends_the_map_onward` in `crates/nvs-lsp/tests/autoload.rs`, and
  `the_declaring_file_is_analysed_as_it_always_was` there for the entry a lender never lends to.

> **In short:** [0198](0198.md) lent a map to a file lying under an autoload root, and to nothing else.
> A test file a test program requires by hand lies under no root, and the entry that requires it
> declares nothing itself, so the survey never walked the program and the editor reported every `use`
> in the test file as unresolved while `nvs test` ran it clean. A lender now records every file its walk
> read and lends to those too, the survey walks a file whose text holds `require` as well as one holding
> `autoload`, and a lender never borrows.

## Context

A developer laid out a test program the way the testing reference describes it: an entry file that
requires each test file and then the application's bootstrap file, which declares
`autoload 'Framework' from '../../Framework/src';` and `autoload 'Blog' from '../src';`. `nvs test` on
the entry ran clean. The editor put `E0306` on every `use Framework\…;` in the test file.

Two things in [0198](0198.md) leave that file out. Its § 2 lends only to a file under a root one of the
lender's declarations names, and `tests/` is not one. Its § 1 walks only a file whose text holds
`autoload`, and the test entry holds `require` alone: the declaring file *is* walked, as its own
program, and that program never reads the test file.

## Options considered

1. **Lend to the files a lender's walk read, and walk a file holding `require` too.** Chosen.
2. **Make the test file's own `require` the link.** A test file requires nothing; the entry requires
   it, and the edge points the wrong way for a walk that starts at the open document.
3. **Have the reference recommend a layout the editor already handles.** The layout is the one the
   reference prescribes, and a test file that uses a class is the ordinary case.

## Decision

### 1. A lender records what its walk read

Beside the declaring files, a lender keeps every other file its `require` chain loaded, under the same
canonical key. The set is the walk's `loaded` list minus its entry, so it costs nothing the walk did not
already pay.

### 2. A file the walk read borrows, and a lender never borrows

`Documents::lender_for` matches a file that a lender read before it tests the roots, and still takes the
first lender in entry-path order. A file that is itself a lender's entry borrows from nobody: it wrote a
declaration, so it has a map of its own, and `nvs check` analyses it through exactly that one. This
replaces [0198](0198.md) § 2's narrower "a lender never lends to its own entry point", which the new edge
would otherwise defeat — the bootstrap file is read by the test program's walk, and would have borrowed
copies of its own declarations from it.

### 3. The survey walks a file holding `require`

A program whose declarations sit in a file it requires holds no `autoload` itself, so the keyword search
that gates the walk now accepts either keyword. A file holding `require` whose chain declares nothing is
walked once and kept as nothing.

### 4. An edit to a required file re-walks its lender when the text holds `require`

Only a `require` can change what a walk reads, so `Documents::resurvey` repeats a lender's walk for an
edit to a file it read when the edited text holds that keyword, and for no other such edit. The
declaring files are unchanged as staleness keys. A file that stops holding the keyword leaves the read set
stale until the lender's next walk, which lends a map to a file no longer required and nothing else.

## Consequences

- **Performance:** at startup, one walk per file holding `require` in addition to one per file holding
  `autoload`, each reading the program that file starts; in an autoload-based application that is the
  bootstrap and the test entries. Per edit, one more keyword search of the changed text, and a repeated
  walk when a required file is edited while holding `require`. Per analysis, one membership test per
  lender before the prefix test. Nothing is on a request path of the runtime.
- **Memory:** one more path list per lender, the length of the program's `require` chain, held for the
  session.
- **Usability:** a test file laid out as the reference prescribes is analysed as the build sees it. A
  bootstrap file that sits under another program's root and uses a name only that program declares is
  now reported as `nvs check` reports it, where before it borrowed the outer map.
- **Simplicity:** one field on the lender, one branch in the lookup, one keyword in the gate. The rule
  keeps one named exception to an open document being its own entry point.

## Alternatives rejected

- **Keying a lender's staleness on every file its walk read**, which [0198](0198.md) rejected and § 4
  narrows to the edits that can change the read set.
- **Walking every file as a program.** The two-keyword gate refuses every plain class file for the cost
  of the read the index makes anyway.

## Verification

The suite pins the required test file resolving both roots' classes after a survey, its entry borrowing
nothing, and a `require` added to a required buffer reaching the file it names through the repeated
walk. The bootstrap file, now read by two programs, is still analysed with nothing lent.
