# ADR 0232 — An attribute's name may be `Owner::Name`, resolved as the type `Owner::Name` is, and a malformed attribute is one error

- **Scope:** the name of a named attribute, and how the parser recovers from a malformed `#[...]` group. What an
  attribute name must resolve to stays [0046](0046.md)'s shape-typed alias, and retrieval stays
  structural.
- **Depends on:** [0046](0046.md) (a named attribute's name is a shape-typed `type` alias),
  [0190](0190.md) (a `type` alias is also a member of a class, interface or enum).
- **Validated by:** `tests/conformance/lang/an-attribute-names-a-type-alias-declared-in-an-interface-or-class.nvst` and
  `tests/conformance/reject/a-malformed-attribute-is-one-error.nvst`.

> **In short:** a `type` alias can be a member of an interface or class and is reached as `Owner::Name`
> in a type ([0190](0190.md)), but an attribute's name was a plain name only, so `#[Page::Meta(...)]`
> did not parse. It now does, and the name is resolved by lowering it as the type atom `Owner::Name`,
> so an attribute and a type can never resolve one spelling two ways. A compiler-recognized name such as
> `Core\Route` is a plain name and never matches the member form. A malformed group is reported once
> and skipped to its own `]`, where it used to leave the parser in the middle of the attribute and
> cascade into a score of follow-on errors.

## Context

[0190](0190.md) made an alias a member of a class, interface or enum body, and an interface is the
natural home for the shape every implementor's attribute satisfies. An attribute could not name it:
the parser read `Page` as the whole name, stopped at `::`, reported "expected `]`" without consuming
anything, and the class body then restarted at `::`. A program had to repeat the alias at file scope
under a second name to use it as an attribute, which is the second name for one type that
`rule:statements/nothing-gets-a-second-name` exists to avoid.

## Decision

### 1. The member form

The named form's name is either a plain name or `Owner::Name`. The AST keeps the owner in
`Attribute::name` and the alias in `Attribute::member`, the pair the type grammar's
`TypeAtom::Member` already holds. The checker builds that atom and lowers it, so the member alias, its
owner's namespace and imports, an alias standing left of `::`, and every diagnostic for a name that
resolves to nothing are the type position's own. A member that lowers to anything but a shape, an
enum case or a class constant's literal type, is `E0726`, as a plain name is.

The autoload harvest needs nothing new: the owner is the attribute's `name`, and every attribute name
was already harvested, so the owner's file is loaded.

### 2. The compiler-recognized roster

The recognized names are all plain names. The member form skips the roster test entirely, and
`derive::attribute_is` answers no for it, so `#[Core\Route::Meta]` is an alias lookup that fails
rather than a route.

### 3. Recovery

A group that does not end at its `]` reports "expected `]`" only if nothing inside the group was
reported yet, then skips to the group's own `]`, counting brackets, parentheses and braces. Outside
every bracket, a `;`, an unmatched closing bracket or a keyword that begins a declaration also ends
the skip without being consumed, so a group missing its `]` loses only its own tokens. A `::` with no
name after it is one error, and that attribute is kept as the bare form, so the checker says nothing
more about it.

## Consequences

Retrieval is unchanged, because it never read the name ([0046](0046.md)): `implementingWith<I,
Page::Meta>` and `implementingWith<I, {title: string}>` find the same payloads. `ClassInfo::attributes`
reports the name as written, `Page::Meta`. Nothing changes per request; the member form costs one type
lowering per attribute at compile time, which the plain form already paid through the alias table.

## Alternatives rejected

- **A lookup of its own in the attribute checker**, reading the member alias table directly. It would
  be a second resolver for one spelling, and the type position's handling of an alias left of `::` and
  its diagnostics would have to be copied into it.
- **Matching `Owner::Name` against the recognized roster.** No recognized attribute is a member of
  anything, so the only effect would be a second spelling of a name the compiler acts on.
