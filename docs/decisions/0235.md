# ADR 0235 — `nvs test` writes line coverage as lcov and Clover, counted into one table every context of the run shares

- **Scope:** the first coverage report `nvs test` writes: line coverage of a `#[Test]` run, its two
  formats and the two flags that ask for them, how the statement probe numbers a statement across a
  whole program, and how the counts reach the runner from every context the run makes. Branch
  coverage, per-test coverage, a third format and the editor's coverage view are left to a later goal.
- **Depends on:** [0018](0018.md) and [0041](0041.md) (the statement probe is compiled into every unit
  and checks one flag word), [0079](0079.md) (every test runs in an isolate of its own).
- **Validated by:** `crates/nvs-cli/tests/test_coverage.rs`, `crates/nvs-codegen/tests/probes.rs` and
  the `StmtHits` cases in `crates/nvs-runtime/src/ctx/trace.rs`.

> **In short:** `nvs test --coverage-lcov <FILE>` and `--coverage-clover <FILE>` write which lines a
> `#[Test]` run reached. Codegen numbers every statement across the whole program by adding a
> per-function base to the IR's per-function `StmtId`, and `nvs_ir::Program::stmt_spans` is the table of
> where each number is written. The runner gives the suite's context one `StmtHits` table of atomic
> counters and turns `DebugFlags::COVERAGE` on; every child context copies the handle with the flag,
> and a `server: true` test's request program installs it itself. A line's count is the largest count
> of a statement starting on it. A run that does not ask allocates nothing and runs the code it ran
> before.

## Context

The statement probe was in every compiled unit, and the runtime counted a hit per statement into a
vector on the context. Nothing turned it into a report. Users integrating Novis into CI asked for a
coverage file their CI service can read. Two things stood between the probe and a report:
`nvs_ir::StmtId` numbers from zero in each function, so two functions wrote into the same counter, and
each test runs in an isolate of its own whose context, with its vector, is gone when the test ends.

## Options considered

1. **Program-wide statement numbers in the IR.** Rejected: `nvs_ir::ids` keeps ids per function so an
   edit in one function does not renumber every other one, and nothing outside a coverage run needs a
   program-wide number.
2. **A base per function, added by codegen.** Chosen. The IR is unchanged, the probe passes `base +
   StmtId` as the constant it already passed, and the table of spans is the same walk over
   `Program::functions` in the same order.
3. **Copy each isolate's counts back to the parent when it ends**, as the verdict crosses. Rejected: a
   request a `server: true` test sends runs in a context no test owns, and a placed isolate ends on
   another core. Each path would need its own copy step.
4. **One shared table, handed down with the flag.** Chosen. A child already copies the flag word, so
   the handle travels the same way, and the parent reads every count from one place.

## Decision

### 1. Statement numbers

`UnitBuilder::compile_all` gives each function the count of statements in every function before it
in `program.functions` as its base, and the probe adds it. `nvs_ir::Program::stmt_spans` concatenates
every function's `stmt_spans` in that order. A unit loaded from the compile cache was compiled by the
same walk, so the runner computes the table from the lowered program and does not need the compile.

### 2. One table for the run

`nvs_runtime::StmtHits` is a fixed slice of `AtomicU64`, sized from `stmt_spans`. `Ctx::isolate`,
`Ctx::child` and `Ctx::placed_isolate` copy the handle beside `debug`. A connection the server accepts
starts from a fresh context, so the runner's request program sets the table and the flag on the
request's context itself. Novis code cannot read the table, so sharing it across isolates gives the
program nothing it could observe. A context with the flag and no table counts nothing.

### 3. Lines

lcov and Clover count lines. A line's count is the largest of the statements that start on it, so a
`while` and the block it opens are not counted twice. Every function is compiled, so a statement no
test reached is listed with `0`. A file not on disk, such as the entry a directory run generates, is
left out. A file is named relative to the directory the run started in, with `/` between parts.

### 4. Flags

`--coverage-lcov <FILE>` and `--coverage-clover <FILE>`, after PHPUnit's `--coverage-clover <file>`,
which most of the people moving to Novis already type. Each writes a file, so both work beside
`--format json` and `junit`, whose document stays the only thing on stdout. They are refused beside a
`.nvst` tree, whose cases run as processes of their own, and beside `--list`, which runs nothing.

## Consequences

- **Spends:** per run that asks, one `u64` per statement in the program and one file and line pair per
  statement for the report. Nothing for a run that does not.
- **Costs with coverage on:** one relaxed atomic add per statement executed, beside the call the
  probe already made.
- A file's own top-level statements do not run under `nvs test`, so they are listed with `0`.

## Verification

`crates/nvs-cli/tests/test_coverage.rs` pins the lcov file of a program with an untaken branch and an
uncalled method, the Clover totals, a `server: true` request's lines, a directory run's file names, and
both refusals. `crates/nvs-codegen/tests/probes.rs` pins that two functions count into separate parts
of the table.
