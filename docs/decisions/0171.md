# ADR 0171 — One workspace index with five readers, eight more requests in the closed set, and inlay hints for the two idioms that stopped moving

- **Scope:** what M10's editor layer adds to `nvs-lsp` on top of M4B's slice — the symbol
  index's shape and its one construction site, the requests admitted beyond the nine, the
  completion arms that answer a namespace separator and a bare name, and the reversal of
  [0099](0099.md) § 3's inlay-hint deferral. It decides nothing about `nvs fmt`, `nvs dap`, the
  profiler, the inline-HTML `nvs/regions` request or `nvs ext`: each is still staged behind a
  piece that does not exist, per `rule:ide/every-feature-is-staged-behind-its-dependency`.
- **Depends on:** [0099](0099.md) (the M4B request set and the test a tenth request has to pass),
  [0108](0108.md) (five features are one reference index; `nvs.check.scope`), [0111](0111.md) (the
  PHP-name completion layer), [0040](0040.md) (the staged editor catalog).
- **Validated by:** `crates/nvs-lsp/tests/index.rs`'s
  `the_crate_has_exactly_one_symbol_index_construction_site` and `all_five_readers_query_the_one_index`,
  `crates/nvs-lsp/tests/coverage.rs`'s `every_request_answers_every_construct`,
  `crates/nvs-lsp/tests/completion.rs`'s `every_completion_source_names_a_compiler_table`, and
  `crates/nvs-lsp/tests/navigation.rs`'s `declaration_is_not_answered_because_it_would_answer_identically`.

> **In short:** `nvs-lsp` builds **one** workspace symbol index, keyed by the fully-qualified name
> the checker resolved, at one construction site, and five features are five queries against it.
> Eight standard requests join M4B's nine on [0099](0099.md) § 3's own test — the data structure
> the milestone already builds *is* the answer — and `textDocument/declaration` is refused rather
> than deferred, because Novis has no declaration that is not the definition. Completion gains two
> arms that read a namespace separator and a bare name, and both read tables the compiler builds
> for another reason. Inlay hints are admitted for exactly two idioms, which is where
> [0099](0099.md) § 3's deferral is reversed and no further.

## Context

M4B shipped the minimal server: nine standard requests, two code actions and `nvs/redactions`,
each answerable from a single document's analysis. Everything that needed a view of more than one
file at a time — find-references, rename, CodeLens, type hierarchy, unused-member dimming — was
left to M10 behind one dependency, the workspace symbol index, and
`rule:ide/five-features-are-one-reference-index` had already decided that the five are queries
against one index rather than five walks.

What was not decided was the index's own shape, and three questions in it are the kind that are
cheap to answer once and expensive to answer twice: what a symbol is keyed by, which analysis owns
a file that several `require` graphs reach, and what a keystroke invalidates. A wrong answer to the
third is not a correctness bug — it is an editor that goes quiet for a second on every character,
which reads to a developer as the language being slow.

The request set was a separate question with the same shape. [0099](0099.md) § 3 closed M4B's list
and left a test rather than a list for what comes after it, and the whole risk at M10 is that
"M10's catalog" is read as permission to add anything in it.

## Decision

### 1. The index is one workspace-scoped construction site, keyed by the name the checker resolved

A symbol is a **string** — `App\User`, `App\User::greet`, `App\User::$name`, the fully-qualified
name the checker resolved with the member as its own source writes it, `$` included so a property
is told from a method of the same name. Both sides of the index are read back out of the checker,
and `crate::definition::target_of` is already the function that turns a recorded expression into
the name it resolved to, so an id would be that same string keyed twice with a table in between.
`crates/nvs-lsp/src/index.rs`'s module doc is the current text of all three choices.

One entry per file, owned by **whichever analysis reached it first** in sorted path order, so a
file in three graphs is indexed once and the winner does not depend on a hash map's iteration.
Invalidation follows the **read** edge, not the `require` edge: an entry records every file the
analysis that produced it read, so a `didChange` drops the changed file and every entry produced by
an analysis that read it, and nothing else. The `require` edge would need a second graph, kept by
hand, saying the same thing.

The index is **workspace-scoped from the first slice** and the scope is chosen per query, not per
index. `nvs.check.scope` therefore selects the tree a query runs over and never the construction
site, which is what lets unused-member dimming — correct only at workspace scope — be *silent*
under the default rather than wrong.

### 2. Eight standard requests join the nine, and `textDocument/declaration` does not

Each passes [0099](0099.md) § 3's test, and the data structure each one reads is named here so the
test is checkable rather than asserted: `references` and `documentHighlight` are the index's read
side, whole-workspace and narrowed to the open file; `codeLens` counts the index's uses and walks
its extends edge; `typeHierarchy` — `prepare`, `supertypes` and `subtypes`, one request in three
methods — walks that same edge both ways. `signatureHelp`, `typeDefinition` and `implementation`
read what `hover` and `definition` already resolve. `inlayHint` is § 4.

Four of the eight carry `.lspt` vocabulary — `codeLens`, `references`, `documentHighlight` and
`inlayHint` are in `Request::ALL` and so are rows in the coverage matrix
`every_request_answers_every_construct` gates. The other four are answered on the wire and have a
Rust test rather than a case, because `signatureHelp`, `typeDefinition`, `implementation` and
`typeHierarchy` each answer a *shape* the canonical rendering in `nvs_lsp::render` has no spelling
for, and inventing one is what `rule:ide/an-lsp-answer-is-frozen-as-an-lspt-case` forbids a case to
do. A later slice that gives one of them a rendering makes it a case; nothing about the answer
changes when it does.

`textDocument/declaration` is **refused, not deferred.** Novis has no declaration that is not the
definition, so the request would answer identically to `textDocument/definition` — two capabilities
for one answer, and an editor that shows a developer two menu entries that always agree. The crate
names neither spelling, and a test asserts it.

### 3. A separator and a bare name are two more readings of tables the compiler already builds

Completion answers a namespace separator from the `Core` registry and the index, and a bare name
from the imports in force, the declarations the index holds, the keywords the position allows, the
variables in scope, and — under `nvs.completion.phpNames` — the PHP inventory, whose item shape is
`ide/three-of-four-item-shapes-insert-nothing`'s four-row table and whose insert side is
gated on a destination the registry actually holds.

This is `rule:ide/completion-offers-only-what-the-compiler-derived` applied, not extended: every
source names a table the compiler builds for another reason, and a test enumerates the sources and
fails one that reads a directory layout, an annotation dialect or the network. The PHP inventory is
the one source that is not a compiler table, and it is admitted as a source of *names* only —
`php-migration/every-php-builtin-is-a-completion-candidate` is why, and the registry gate is
what keeps a name from becoming text in a file.

### 4. Inlay hints are admitted for two idioms, and that is the whole reversal

[0099](0099.md) § 3 deferred inlay hints past M4B for two stated reasons: they want a settings story
and they encode idioms still moving through M5–M9. Both halves have settled — the settings roster
is frozen and the two idioms below stopped moving — so the deferral is reversed for exactly two
shapes and no others: a `var` declaration with no annotation gets `: T` after the name, and a call
argument written as a bare literal gets `name:` before it.

Both are read out of what `nvs_types::check_program` already recorded — the declaration's binding
in `ExprTypeTable::local_scopes`, the parameter name through `ResolvedCall::param_names` and that
call's `arg_slots` — and a site the table holds nothing for gets **no hint**. That is the module's
whole failure mode: a hint is text an editor draws as if the source said it, so a re-derived one is
a confident lie. Narrowing to the range an editor can show is `crate::server`'s, not the answer's
shape, so a case may ask the request of a whole document.

A third shape — a `foreach` binding, a chained call's intermediate type, a closure's return — is a
**decision**, on the same terms a tenth request is: it is either already written in the source or a
claim about an idiom M5–M9 is still moving.

## Consequences

The index holds one entry per file the workspace's analyses reached, for the life of the server
process. That is memory spent to buy latency (priority 3 over priority 5, per `AGENTS.md`) and it
is spent in the **editor** process, never on the request path: nothing in this record runs in a web
request, so the footprint rule's O(in-flight) bound has no subject here. It is bounded by the tree
`nvs.check.scope` selects and released by the same invalidation a keystroke triggers.

Five features that a naive implementation gives five walks cost one walk between them, and the
warm-index path is what makes references and highlight answer inside the same bound a full
re-analysis has to stay under (`rule:ide/a-full-reanalysis-stays-under-a-bound`).

For a developer using the language, the visible trade is that CodeLens is a request per visible
declaration and is therefore a setting, defaulting on; and that unused-member dimming says nothing
at all under the default scope rather than reporting a symbol as unused because the other tab was
closed.

## Alternatives rejected

- **A graph-scoped index.** Four of the five readers would work; unused-member dimming, the one
  that is only correct at workspace scope, would not — and it would have made `nvs.check.scope` a
  property of the index rather than of the query, so the fifth reader would have needed a second
  construction site. Rejected before the first slice.
- **Call hierarchy as a sixth reader.** `textDocument/callHierarchy` needs call-site edges kept
  incrementally, which is a different index, and nothing else reads it.
  `rule:ide/five-features-are-one-reference-index` names five and excludes this one with a reason;
  a sixth query is a decision, not an addition.
- **`textDocument/declaration`.** See § 2: identical answers, two capabilities.
- **A convention scan or an annotation dialect behind the new completion arms.** Refused outright
  as a second, unchecked description of the program's shape, which is the same failure
  `rule:routing/api-document-is-generated-from-the-route-table` refuses for API documents.
- **Inlay hints for everything an editor could annotate.** The deferral's stated reason was moving
  idioms, so reversing it wholesale would reverse it for the cases the reason still covers.

## Revisiting

If `a_full_reanalysis_of_a_thousand_lines_stays_under_the_bound` or
`a_warm_index_answers_within_the_reanalysis_bound` ever fails, the answer is item-level caching over
the `SyntaxIndex` and then a decision with a number in hand — never a larger number in the test.
A sixth reader for the index, or a third inlay-hint shape, reopens this record rather than being
added under it.

## Verification

`the_crate_has_exactly_one_symbol_index_construction_site` and `all_five_readers_query_the_one_index`
hold § 1 structurally, with `a_change_invalidates_the_file_and_its_readers_and_nothing_else` and
`check_scope_selects_the_tree_and_never_the_construction_site` holding its two behaviours, and
`call_hierarchy_is_not_answered` holding the exclusion. § 2's four case-carrying requests are frozen
as `.lspt` cases under `tests/lsp/`, each one a row
`every_request_answers_every_construct` requires at every construct the corpus reaches; its four
wire-only requests are held by `signature_help_names_the_active_parameter_of_the_enclosing_call`,
`signature_help_renders_a_core_row_and_a_declared_list_the_same_way` and
`type_definition_and_implementation_resolve_through_the_graph`, and the refusal by
`declaration_is_not_answered_because_it_would_answer_identically`. § 3 is held by
`a_namespace_segment_offers_the_registry_and_the_index_and_no_keywords`,
`a_bare_name_offers_the_imports_in_force_and_the_declarations_in_the_index`,
`every_completion_source_names_a_compiler_table` and
`no_completion_source_reads_a_directory_layout_or_the_network`. § 4 is held by
`crates/nvs-lsp/tests/hints.rs` — including
`no_hint_is_produced_from_anything_the_type_phase_did_not_record` — and by the `.lspt` cases under
`tests/lsp/hints/`.
