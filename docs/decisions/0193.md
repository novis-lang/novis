# ADR 0193 — A bare name completes to every type the server holds, a list opens only where a spelling ends, and the index covers the workspace by default

- **Scope:** what `textDocument/completion` offers at a bare position, in markup and after a trigger
  character, and the default of `nvs.check.scope`. Member lists after `->` and `::`, the namespace list
  after `\` and the PHP-name layer are unchanged.
- **Depends on:** [0099](0099.md), [0108](0108.md), [0111](0111.md).
- **Validated by:** `crates/nvs-lsp/tests/completion_edits.rs`, and the cases under
  `tests/lsp/completion/` that cite the three rules this creates.

> **In short:** typing `C` on an empty line offers `Core`'s classes beside the workspace's own, by short
> name, and accepting one writes its `use` line. The list is ranked by what the file already reaches.
> Reserved words are offered only where they compile. A trigger character opens a list only where it
> finished `->`, `::`, `\`, `$` or `<?`, and `<?` in markup offers the two open tags and nothing else. The
> symbol index is built over the workspace unless a developer narrows it.

## Context

A developer used the reference client for a day and reported six things, each of which reproduced against
the server with a scratch `.lspt` case before anything was changed.

1. `<?` in a run of markup listed HTML tags. The server answered nothing there; the list was the HTML
   service the client forwards to, and nothing offered `<?nvs` or `<?=`.
2. `C` on the first line of a file offered reserved words and no `Core` class. The registry was read only
   after a `\` had been written.
3. `cs` did not find `Core\Str`, for the same reason: the editor's own matching reads across a separator,
   and the item was never in the list to be matched.
4. The order of the list was the editor's alone, because no item carried a `sortText`.
5. `Core\Str:` opened the whole statement list. `:` is a trigger character, a single colon matched no arm,
   and the position's list was the fallback. `$a -` and `$a >` did the same.
6. A variable was not offered after `$`. Two causes: a lone `$` is no word to the client and was no trigger
   character, so no request was sent; and a cursor at the last byte of a file with no trailing newline is
   outside the half-open span of the script frame, so the server found no body and no variable. The second
   is why `if ($f` worked and `$f` alone did not — the auto-closed `)` moved the cursor off the end.

The same session showed every reserved word offered on the right-hand side of a declaration, `abstract`,
`namespace` and `break` among them.

## Options considered

**What accepting an unimported type inserts.** The qualified name, which edits nothing else and is what the
workspace's own types already did; or the short name plus a `use` line, which is what the developer would
have written by hand. The developer chose the second.

**Where the `<?` decision lives.** In the client, as a one-line test on the text before the cursor; or on
the server, as a hole in the region list. The first is a second reading of the lexer's open tags in a
package that holds no language logic (`rule:ide/one-server-two-thin-clients`).

**How a triggered request is gated.** On the client's `triggerCharacter`, or on the text before the cursor.
The text is what says whether `:` finished `::`, and it is the same for every client.

## Decision

### 1. A bare position offers the registry and the index, by short name, importing on accept

`rule:ide/a-bare-name-reaches-every-type-and-imports-the-one-accepted`. The registry is a table the
compiler resolves `Core\Str::` against, so `rule:ide/completion-offers-only-what-the-compiler-derived`
admits it; the `use` line is an `additionalTextEdit` placed above the cursor, so it never overlaps the text
the item replaces. Fuzzy matching stays the client's, and the ranking tiers are the server's.

### 2. A list opens where a spelling ends

`rule:ide/completion-is-asked-where-a-spelling-ends`. `$` and `?` join the trigger characters and `-`
leaves them. The half-written open tag is cut out of its HTML region together with the character after it,
because a client reads a region as half-open and the cursor that matters is the one at the hole's end.

### 3. A reserved word is offered where it compiles

`rule:ide/keywords-are-offered-where-the-compiler-accepts-them`. The token before the name decides
statement or expression, and the ancestor list decides the rest.

### 4. `nvs.check.scope` defaults to `"workspace"`

`rule:ide/check-scope-defaults-to-the-workspace`, renamed for what it now says. Completion out of an index
of the open documents offers a developer only the classes already on screen, which is the opposite of what
a list of types is for.

## Consequences

- **Performance.** A bare-position request builds a few hundred more items and lexes the document once
  more; both are dropped with the answer. Workspace scope reads every `.nvs` file under the root at
  startup, which a large tree pays for once per session and `"open"` avoids.
- **Memory.** Per session and not per request: one declaration and occurrence list per file under the
  root, where the old default held them for open documents alone.
- **Usability.** Accepting a type edits a second place in the file. Diagnostics and unused-member dimming
  now cover files nobody opened.
- **Simplicity.** The client is unchanged; every decision is the server's.

## Alternatives rejected

- **A `CompletionList` with `isIncomplete`**, re-asking on every keystroke so the server could match
  fuzzily itself. The editor already matches across a separator, and a round trip per character is latency
  spent to duplicate it.
- **Offering namespaces as items.** Typing `Core` already lists every `Core` type, and the separator arm
  takes over at the `\`.

## Revisiting

If startup on a large workspace is measured as slow, the default returns to `"open"` and completion reads a
declaration-only index of the workspace instead; the setting's two values do not change.

## Verification

`crates/nvs-lsp/tests/completion_edits.rs` holds the `use` edit and where it lands, the qualified fallback,
the replaced `$`, the tiers, the trigger gate and the region hole. The cases under `tests/lsp/completion/`
hold what is offered at each cursor. `tests/handshake.rs` holds the default scope, and the extension's
contributions suite holds the manifest's.
