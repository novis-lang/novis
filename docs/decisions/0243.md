# ADR 0243 — A completion file's value may name where it is defined and what replaces it, an attachment may depend on another argument and may ask for a check, a list may be completed a segment at a time, and a parameter typed as a union of string literals completes its members

- **Scope:** Six additions to the completion files of [0242](0242.md): a value's source location, read
  by hover and go-to-definition; an attachment that applies only when another argument has a given
  value; a list of values completed one segment at a time; an opt-in check of the string literals at a
  parameter; a replacement for a deprecated value, offered as a quick fix; and completion of a
  parameter whose declared type is a union of string literal types, which the compiler derives without
  a file. Whether `nvs check` reports the opt-in check is left to a later record.
- **Depends on:** [0242](0242.md) (the completion file, its loaded table and the guarantee that an item
  changes only the string the cursor is in), [0240](0240.md) (a string argument mapped to its parameter
  through `crate::arguments`, which also finds the argument a `when` names).

> **In short:** a value in a completion file may carry a `location`, a file and a line, and hover on a
> string literal equal to it shows its `title` and `documentation` while ctrl+click goes to the
> location. An attachment may carry `when`, naming another parameter and the string literals its
> argument must equal for the attachment to apply. A list of values may be written as an object with a
> `separator` of `.`, `/` or `:`, and completion then offers the next segment after the text already
> typed, replacing only that segment; `.` becomes a trigger character inside such a string. An
> attachment with `"strict": true` makes the language server warn on a string literal at that
> parameter whose text is not one of its values. A deprecated value may name a `replacement`, and a
> literal equal to it gets a hint with the Deprecated tag and a quick fix that rewrites only the
> string. Separately from any file, a string argument at a parameter whose declared type is a union
> of string literal types completes those literals, because the compiler derives them.

## Context

[0242](0242.md) gave a project a way to list the values a string parameter takes, and there are four
things a project needs that the list cannot say. A translation key is defined in a file of its own, and a
developer who reads `'shop.cart.title'` wants to see the text and open the line that defines it. One
method's keys depend on another argument: the keys of the `shop` domain are not the keys of the `blog`
domain, and a list that merges both offers mostly wrong keys. Keys written as paths, with hundreds of
entries under a few prefixes, are easier to choose one segment at a time. And a value that was renamed
should say what replaced it.

[0242](0242.md) refused to check a program's string literals against the values, because the data can
change after the file is written and a stale file would raise a false warning. That reason holds for a
file nobody keeps current, and it does not hold for one a build step regenerates from the data itself.
The person who writes the file knows which kind it is, so the check is theirs to ask for.

A parameter whose declared type is a union of string literals (`rule:types/literal-types`), such as
`'paid'|'shipped'`, already names its values in the program, and the checker records each parameter's
type on the call it resolves (`crates/nvs-types/src/expr_table.rs:102`, `ResolvedCall::param_tys`).
Nothing under `crates/nvs-lsp/src/` reads a literal type today, so such a parameter completes nothing.

## Decision

### 1. A value may name the place that defines it

A value object gains an optional `location`, `{ "file": "<path>", "line": <n> }`. `file` is relative
to the folder of the completion file that declares the value, and `line` is 1-based. Inside a string
argument at a parameter some attachment names, a literal whose text equals a value answers two more
requests. `textDocument/hover` shows the value's `title` and `documentation`, as the completion popup
does. `textDocument/definition` answers the location, at the start of that line. A value without a
`location` answers hover and leaves definition with no answer. Both only read the loaded table, and
neither opens the named file.

### 2. An attachment may apply only when another argument has a given value

An attachment gains an optional `when`:

```json
{
  "method": "App\\I18n\\Text::translate",
  "parameter": "key",
  "set": "shop-keys",
  "when": { "parameter": "domain", "equals": "shop" }
}
```

`parameter` names another parameter of the same method, and `equals` is a string or a list of
strings. The attachment applies at a call only when that call's argument for the named parameter is a
string literal whose text equals one of them. The argument is found the way the completed one is,
through `crate::arguments`, so a named argument and a positional one are read alike. When that
argument is not a string literal, or is left out, an attachment with `when` does not apply, and the
attachments without `when` still do. `Text::translate('shop', '')` therefore offers the shop's keys
and the keys every domain shares.

### 3. A list may be completed one segment at a time

Wherever a list of values may be written, in a set or in an attachment's `values`, it may instead be
an object, `{ "separator": ".", "values": [...] }`. The separator is one of `.`, `/` and `:`. The
values are still whole keys, `shop.cart.title`, and are still what the strict check and hover compare
against. Completion splits them on the separator and offers the distinct segments that follow the text
already typed: after `shop.` it offers `cart` and `checkout`. An item's one edit replaces only the
segment being typed, from the last separator before the cursor to the end of that segment, so the
edit stays inside the string ([0242](0242.md) § 6). A segment that ends a value carries that value's
fields; a segment that only leads to longer values carries its text and nothing else.

`/` and `:` are trigger characters already, and `.` becomes one. A request any of the three raised is
answered only inside a string argument at a parameter where an applying list has that separator, so
`$a.` and `Name:` open nothing they did not open before
(`rule:ide/completion-is-asked-where-a-spelling-ends`).

### 4. An attachment may ask for its literals to be checked

An attachment gains an optional `"strict": true`. A parameter is strict when any attachment for it
says so. At a strict parameter, the language server warns on a string literal argument, in a `.nvs`
file, whose text is not one of the values of the attachments that apply at that call. A value built at
run time is not checked, and neither is a literal at a call where an attachment's `when` cannot be
decided, because its argument is not a literal. Only the language server reports it: `nvs check` and
the compiler do not read completion files.

### 5. A deprecated value may name its replacement

A value with `"deprecated": true` gains an optional `"replacement": "<value>"`. A string literal at an
attached parameter whose text equals a deprecated value gets a hint diagnostic with the `Deprecated`
tag, which an editor shows as a strikethrough. When the value names a replacement, the diagnostic
carries it as its own suggestion, and the code action offered on it replaces the literal's text with
the replacement, escaped for the literal's quote style. It changes only the string, as an item does
([0242](0242.md) § 6), and it is a fix the diagnostic already knows
(`rule:ide/a-code-action-ships-only-a-fix-a-diagnostic-already-knows`).

### 6. A parameter typed as a union of string literals completes its members

A string argument at a parameter whose declared type is made only of string literal types, with or
without `null`, completes each literal as an item of kind `value`. Its one edit replaces the literal's
text with the member, escaped for the quote style, and `'` and `"` open the list there. The arm reads
the parameter's type from the call the checker resolved, `ResolvedCall::param_tys`, and the literals
from the checker's own type table, so it is inside
`rule:ide/completion-offers-only-what-the-compiler-derived` as that rule stands: the compiler derives
these values to check the call. A parameter that also has a completion file is offered both lists,
merged by value. No warning is added for a literal outside the union, because the checker already
rejects one (`rule:types/literal-types`).

## Diagnostics

The new kinds are in the `W1xxx` band, and the goal that implements this claims the numbers.

On the completion file's own URI, never for a file under `vendor/`:

- **A `location` whose file does not exist.** A warning; the value keeps everything else.
- **A `when` naming a parameter the method does not have.** It joins [0242](0242.md)'s kind for an
  attachment whose parameter the method does not have, and that attachment contributes nothing.
- **A `replacement` on a value that is not deprecated.** A warning; the replacement is ignored.
- A `separator` other than `.`, `/` and `:` is a field of the wrong form, so the file contributes
  nothing, as [0242](0242.md) decides for every such field.

On a `.nvs` file, phase-gated like every diagnostic (`rule:ide/diagnostics-are-phase-gated`):

- **A string literal at a strict parameter that is not one of its values.** A warning.
- **A string literal equal to a deprecated value.** A hint with the `Deprecated` tag, carrying the
  replacement as its suggestion when the value has one.

## Consequences

What this spends: nothing at run time, and nothing in the language, since a program compiles the same
with or without the files. The server holds a little more per value that has a `location` or a
`replacement`, in proportion to what the files hold. Every hover, definition and code-action request
inside a string argument pays one lookup in the loaded table. A strict parameter costs one set lookup
per string literal argument at it, each time a document is analysed.

The rules that list what hover, definition, completion and code actions answer, and which characters
open a list, gain these answers in the goal that implements this, in the session that lands each one.

## Alternatives rejected

- **Values attached to a method's return value or to a property.** A return type or a property type
  that is a union of string literals already says this in the program, and the checker holds it.
- **A file that overrides a method's return type**, as PhpStorm's `override()` does. The editor's
  types would then disagree with the compiler's: the second description of the program's shape that
  `rule:ide/completion-offers-only-what-the-compiler-derived` refuses.
- **The check on by default.** [0242](0242.md)'s reason stands for a file nobody regenerates: a stale
  file would turn into false warnings. The person who writes the file says when it is current.
