# ADR 0231 — `self::m()` and `parent::m()` inside a closure call the class the closure is written in

- **Scope:** the called class of a `self::m()` or `parent::m()` call, or `(...)` reference, written inside a
  closure body. `static::` in a closure stays refused ([0211](0211.md)'s `E0834`), and the same calls in
  a method body still forward the method's called class.
- **Depends on:** [0008](0008.md) (`static` marks a class member and keeps its PHP meanings),
  [0144](0144.md) (`static::class` is a run-time read of the called class a frame holds),
  [0211](0211.md) (`static::` in a closure is refused).
- **Validated by:** `tests/conformance/callables/self-and-parent-in-an-anonymous-function-call-the-class-the-function-is-written-in.nvst`.

> **In short:** `fn($n) => self::label($n)` inside a method passed the checker and crashed the compiler,
> because a static call through `self::` forwards the frame's called class and a closure's frame holds
> none. Such a call now sets the called class to the class the closure is written in, the way a written
> class name does, so `static` inside the method it reaches is that class. `parent::m()` does the same.
> An instance method reached through either is called on the closure's `$this`, which the call now
> captures. PHP forwards the enclosing method's called class into the closure instead.

## Context

A static method's called class travels in its receiver slot, and an instance method reads it off
`$this`. `self::m()` and `parent::m()` forward whichever one the calling frame holds. A closure is
compiled as a function of its own whose receiver slot holds the closure object, so it holds no called
class, and a closure that never names `$this` captures no receiver either. `static::` was refused inside a
closure for that reason ([0211](0211.md)), but `self::m()` and `parent::m()` were not, and lowering
panicked on both. A `self::m()` call to an instance method panicked a second way: the checker accepted it
because a receiver was in scope, and the closure never captured it.

## Options considered

1. **Carry the called class into the closure.** The closure object would store the enclosing frame's
   called class as a hidden capture, and `self::`, `parent::` and `static::` would forward it, as PHP
   does. This needs a field slot that holds a class descriptor, which closures do not have today, and it
   lifts `E0834` too, so it is a larger change to the closure layout.
2. **Refuse `self::m()` and `parent::m()` in a closure,** as `static::` is. Every closure that calls a
   private static helper would have to be rewritten through a written class name.
3. **Set the called class to the lexical class.** `self::` already means that class for constants and
   `::class`, and a `self::m(...)` reference already binds a class at the site where it is written.
   Nothing new is stored.

## Decision

Option 3. In a closure body, `self::m()` and `parent::m()` record the class the closure is written in as
the class the call sets, exactly as a written class name records itself. For `parent::` that is still the
lexical class, not the parent: the parent is where the method is looked up, not the class the call is
made on. An instance target reads `$this`, so the call captures it like any other read of `$this`, and
the closure's frame then has a receiver to call on and to read a class from.

## Consequences

- A static method reached from a closure sees the lexical class as `static`, even when the enclosing
  method was called on a subclass. PHP sees the subclass. The rule's `divergesFromPhp` says so.
- A static method that is abstract in the lexical class has no body to call there. A closure that calls
  one through `self::` stops with the same run-time error a written `Page::title()` call gives.
- No memory or time cost: the called class is a constant descriptor at the call site, and only a closure
  that calls an instance method this way captures `$this`.

## Revisiting

Option 1 becomes the better answer if closures gain a slot for a class descriptor. It would bring
`static::` into closures as well, and remove both the divergence and the abstract-method case above.
