# ADR 0256 — `nvs agent init` updates every file it wrote that nobody has edited since, told apart by a fingerprint in the file's own marker

- **Scope:** what a re-run of `nvs agent init` does to the files an earlier run wrote, how a project and an
  agent learn that those files are older than the installed binary, and which harnesses get an
  adapter. What a pointer may say is [0167](0167.md)'s and unchanged.
- **Depends on:** [0167](0167.md).
- **Validated by:** `crates/nvs-cli/tests/agent.rs` — the `init_*` cases, `every_unit_carries_a_fingerprint_in_its_marker`
  and `the_primer_notes_a_harness_whose_pointer_is_missing_and_nothing_else`.

> **In short:** every unit `init` writes — the `AGENTS.md` stanza and each adapter — carries a marker
> with a fingerprint of the text it wrote. A re-run replaces a unit that still matches its fingerprint
> and refuses one that does not, unless `--force`. `--check` writes nothing and fails while any unit is
> missing, outdated or edited, and `nvs agent primer` puts one line on standard error while the
> working directory holds an outdated one. Cursor and GitHub Copilot get adapters beside the Claude
> Code skill.

## Context

[0167](0167.md) had a re-run refuse any stanza or adapter that did not read exactly as the installed
binary writes it, because from the file alone an upgrade and an edit look the same. The cost of that
is every project that ran `init` once: the next release that changes the pointer's text makes the
project's copy differ, the re-run refuses it, and the only way out is to delete the block by hand. The
pointer text itself was already stale — it said `index` lists only standard library members, while
`index`, `find` and `show` also cover reference headings, configuration keys, commands, flags and
error codes, and it did not name `nvs check --json`.

## Decision

The user's calls: the files `init` created stay in sync when Novis adds things, the install gives
the best experience an agent can have, and the pointers name `nvs check --json`. The orchestrating
session's calls, implementing those: §§ 1–5 below. The implementing session's call: § 2's note also
fires for a missing adapter of a harness the project shows, once the project carries the stanza.

### 1. A fingerprint in the marker tells an upgrade from an edit

Each unit carries a marker `<!-- nvs agent: written by `nvs agent init`, fingerprint 1a2b3c4d -->`:
the stanza opens on it, and an adapter carries it on the line under its front matter, as an HTML
comment rather than a front-matter key a harness might reject. The fingerprint is the first eight hex
digits of BLAKE3 over the unit's text without the marker line, with `\r\n` read as `\n`. BLAKE3 is
fixed by its specification and already in the binary for the code cache, so the fingerprint is the
same on every platform and from every build.

A re-run judges every unit before it writes any. A unit that reads as this binary writes it is
current. One whose text still matches its fingerprint was not edited, so it is replaced and `init`
prints `updated <path>`. Anything else was edited: `init` refuses, names the file, exits non-zero and
writes nothing, unless `--force`, which replaces it.

The units the `init` before fingerprints wrote carry the old marker, or none. Their text is known, so
its fingerprint is a constant in the binary and those units are judged against it; the old text
itself is not kept.

### 2. Staleness reaches the agent with nobody in between

`nvs agent primer` is the command every pointer tells an agent to run first. When the working
directory holds a unit that is outdated, or carries the stanza and lacks the adapter of a harness it
shows, the primer prints one line on standard error naming `nvs agent init`. It reads only
`AGENTS.md` and the adapter paths. An edited unit gets no note: it is the project's own text.

### 3. `--check` is the same judgement with nothing written

`nvs agent init --check` prints `missing`, `outdated` or `edited` and the path for each unit that is
not current and exits non-zero, or prints `up to date` and succeeds. A project runs it in CI.

### 4. More harnesses, each a header over the same protocol

Cursor gets `.cursor/rules/novis.mdc` when `.cursor/` exists, with `description`, `globs: **/*.nvs`
unquoted as Cursor's documentation writes it, and `alwaysApply: false`. GitHub Copilot gets
`.github/instructions/novis.instructions.md`, with `applyTo: "**/*.nvs"`, when
`.github/copilot-instructions.md` or `.github/instructions/` exists — never for `.github/` alone, which
most projects have whatever they use.

### 5. The protocol names the whole surface

The text every pointer carries says that `index`, `find` and `show` cover reference headings,
configuration keys, commands, flags and error codes as well as members, names `nvs check --json` and
`nvs test`, and says that `init` updates the text. It still states no language fact.

## Consequences

A project that ran `init` follows the installed binary by running `init` again, and its agents are
told when to. A person's edit is never overwritten without `--force`. An edit that keeps the text and
the fingerprint consistent — a marker rewritten by hand — reads as untouched and is updated; that is
somebody imitating `init`, and is accepted.

## Alternatives rejected

- **A version number in the marker.** It says which binary wrote the unit, not whether somebody edited
  it since, which is the one thing the re-run has to know.
- **Keeping every old text in the binary.** It grows with every release; a fingerprint per old text is
  eight characters, and only the pre-fingerprint text needs one.
- **Detecting Copilot by `.github/`.** Almost every repository on GitHub has one.
