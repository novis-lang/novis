# ADR 0151 — The CLI inherits no flag from PHP, and `nvs --help` opens with which build is answering

- **Scope:** which short flags `nvs` declares and where each one comes from; the removal of `nvs -i`;
  and the two-line banner that replaces the one-line `about` string. Not in scope: what `nvs info`
  reports, which is [0065](0065.md)'s and unchanged; and not the subcommand set, which each command's
  own record owns.
- **Depends on:** [0065](0065.md), which created `nvs info` and the `-i` alias this record retires.
- **Validated by:** `crates/nvs-cli/src/main.rs`'s argument definitions — two short flags in the whole
  top-level surface, both generated by clap — and `nvs info`'s own snapshot of the build facts.

> **In short:** Novis copies PHP's *semantics* on purpose and its *command line* not at all. `nvs -i`
> was the one flag inherited from PHP, kept because it is the spelling a PHP developer tries first; it
> is removed, and with it the global `--licenses` that hung off it and the hand-written check for a
> collision clap cannot express. `nvs info` is now spelled one way. In the same surface, the one-line
> `about` string becomes two lines: the README's own title, then the version, commit and date of the
> build that is answering — the **commit's** date, which is derived from the commit and so leaves two
> builds of one commit byte-identical.

## Context

- [0065](0065.md) § 3 carried `nvs -i` beside the `nvs info` subcommand deliberately, and the rule it
  created said so in as many words: the one place in Novis where an operation is reachable two ways.
  The argument was familiarity — nobody should have to hunt for the command that says what the binary
  is.
- That alias is not free. It costs a global `info: bool`, a second global `--licenses` carrying
  `requires = "info"` so it cannot be typed alone, and an explicit `if cli.info && cli.command.is_some()`
  in `main` because a subcommand is not an argument clap can name in a `conflicts_with`. Three
  mechanisms for one spelling.
- Deriving the flag also produced a spelling nobody chose. `#[arg(short = 'i', long)]` gives `--info`
  as well, which is neither the subcommand nor PHP's spelling, appeared in no rule, no test and no
  document, and was reachable only by reading the source or the error message that named it.
- The banner had drifted from the project's own description. `about` read "The Novis compiler and CLI"
  while [README.md](../../README.md)'s H1 read "Novis — The Web-Native Programming Language", which is
  two homes for one fact.
- A bug report needs the build that produced the behaviour, and a reporter does not think to run a
  second command to get it. The facts were already compiled in — `build.rs` emits the commit for
  `nvs info` — and were simply not on the first screen anyone sees.

## Decision

### 1. No flag on `nvs` exists because PHP spells it that way

`nvs -i`, the derived `--info`, and the global `--licenses` are removed. `nvs info` and
`nvs info --licenses` are the whole of it.

The distinction that makes this narrow: PHP compatibility is about *observable program semantics*, and
argv is not that. A PHP developer's muscle memory is worth something for the first five minutes and is
charged to every reader of `--help` thereafter.

`-h`/`--help` and `-V`/`--version` are untouched and are not exceptions to this. They come from clap,
not from PHP, and `-V` is uppercase because the GNU convention reserves `-v` for verbosity — PHP's own
version flag is the lowercase `-v`, so adopting it would be the single change that moved *toward* PHP.
A short flag and its long form are one flag with two spellings, which is the getopt convention and not
an operation reachable two ways.

`-o`/`--output` on `nvs build --compile` survives as the only short flag Novis declares for itself. It
is not PHP's — `php` has no such flag — and it meets the bar a short flag has to meet: a long name typed
often enough to hurt.

### 2. `rule:core-api/one-paradigm-per-operation` stops needing a CLI carve-out

The rule 0065 created had to state that "nothing is reachable two ways" governs `Core` and not the CLI,
because the CLI had one exception. With the exception gone the carve-out is deleted rather than
reworded: the `Core` shape rules never had anything to say about argv, and saying so was only ever
necessary to excuse `-i`.

### 3. `nvs --help` opens with two lines

```
Novis — The Web-Native Programming Language
version: 0.0.1 · commit: 9c62ae176 · 2026-09-07
```

Line one is [README.md](../../README.md)'s H1 verbatim, so the binary and the repository state the
project's identity in one place and one wording. `Novis` is underlined through `anstyle`, which clap
writes via `anstream`; a redirected or piped `--help` gets plain text and `NO_COLOR` is honoured
without the code that builds the string testing for a terminal.

### 4. The date on line two is the commit's, never the build's

`build.rs` gains `NVS_COMMIT_DATE` from `git log -1 --format=%cs HEAD`, with `NVS_BUILD_COMMIT_DATE` as
the tarball escape hatch `NVS_BUILD_COMMIT` already is for the hash, and `unknown` when neither is
available.

A wall-clock build timestamp was asked for and is refused, because
`rule:packaging/a-build-records-no-timestamp` exists to keep two builds of one commit byte-identical
and a timestamp is exactly what breaks that. The committer date costs the property nothing — it is read
off the commit, so every rebuild of one commit emits the same string — and answers the one question the
hash does not, which is how old the binary is. That rule is amended to record the distinction rather
than overturned.

## Consequences

- A PHP developer typing `nvs -i` gets clap's unknown-argument error naming `nvs info`, which is one
  extra keystroke discovered once.
- `main` loses a branch and two fields; `Cli` has one global left, `--config`.
- `nvs info` grows a `commit date` row, because every fact `build.rs` records reaches that report.
- `--help` is two lines longer and now changes with every commit, which is the point of it.

## Alternatives rejected

- **Keep `-i`, drop only the underived `--info`.** Halves the surface but keeps all three mechanisms,
  since the flag is what carries them; the spelling was never the expensive half.
- **Bake a real build timestamp.** What was originally asked. It overturns
  `rule:packaging/a-build-records-no-timestamp` for a cosmetic field and makes every `cargo build`
  produce a different binary from identical source.
- **Move `-V` to `-v` to match PHP.** Rejected twice over: it contradicts § 1's own principle, and it
  spends the flag every future `--verbose` will want.

## Verification

`nvs -i`, `nvs --info` and a top-level `nvs --licenses` are all unknown arguments. `nvs info` and
`nvs info --licenses` print what 0065 § 3 specifies, with a `commit date` row added. `nvs --help` opens
with the two lines above; `nvs --help | cat` carries no escape sequence, and neither does a run with
`NO_COLOR` set. Two builds of one commit, in separate checkouts, emit the same banner.
