# ADR 0260 — `nvs agent init` installs for the agent found in the environment, and adds a check-on-edit hook where the agent's tool runs a plain command after an edit

- **Scope:** which agents `nvs agent init` knows and how it finds the one that runs it, what each one
  gets beside the `AGENTS.md` stanza, the hooks it merges into Claude Code's and Cursor's settings, and
  `nvs agent hook`, the command those hooks run. What a pointer may say is [0167](0167.md)'s, and how a
  re-run tells an upgrade from an edit is [0256](0256.md)'s; both are unchanged.
- **Depends on:** [0167](0167.md), [0256](0256.md), [0257](0257.md).
- **Validated by:** `crates/nvs-cli/tests/agent.rs` — the `init_*` cases,
  `no_hooks_removes_each_hook_and_check_names_a_missing_one` and the five `the_hook_*`,
  `the_claude_code_hook_*` and `the_cursor_hook_*` cases.

> **In short:** `init` always writes the `AGENTS.md` stanza, and beside it exactly what the agent
> running it needs, found by an environment variable that agent sets, or named with `--agent`. Five
> agents are known: Claude Code (a skill and a hook), Cursor (a hook), Codex and OpenCode (nothing),
> GitHub Copilot (an instructions file). The hook runs `nvs agent hook <agent>` after each edit, which
> checks an edited `.nvs` file as `nvs check` does and gives the first five errors back in the JSON the
> tool reads. This amends [0256](0256.md) § 4, which chose a harness by the directories in the tree.

## Context

[0256](0256.md) § 4 wrote an adapter for a harness whose directory the tree showed: `.cursor/` for
Cursor, `.github/instructions/` for Copilot. A directory says that somebody on the project once used
the tool, not that the agent running `init` now is it. One person's run wrote files for another
person's tool, and an agent whose tool left no directory got nothing it needed. An agent also wrote
Novis code and learned of its mistakes only when it thought to run `nvs check`.

## Decision

The user's calls:

- `init` always writes the `AGENTS.md` stanza, and installs exactly what the running agent needs.
  Nothing agent-specific is written for a person who runs another agent.
- The supported agents are Claude Code, Cursor, Codex, GitHub Copilot and OpenCode.
- A check-on-edit hook is wanted. `nvs check` is fast enough to run after every edit: about 1.4 s on a
  program of 216k lines, and about 0.45 s for one class file in a project of 84k lines.
- Where an agent's tool has no hook that runs a plain command, it gets no hook: no wrapper script and
  no plugin.

The orchestrating session's and the implementing session's calls, implementing those:

### 1. The agent is found by an environment variable, never by the tree

Each agent sets a variable in the commands its own tools run, so the variable says which agent runs
`init` now. The tree says only which agents somebody used. `--agent <name>` replaces detection and may
be given more than once; `--all` installs for every agent and conflicts with `--agent`. A run that
finds none writes the stanza alone and says how to name one.

Claude Code's `CLAUDECODE` is not used: an editor's integrated terminal started from Claude Code also
sets it, so a person typing `nvs agent init` there would be taken for the agent.

### 2. What each agent gets

| Agent | Found by | Beside `AGENTS.md` | Hook | Sources |
|---|---|---|---|---|
| Claude Code | `CLAUDE_CODE_CHILD_SESSION` | the skill `.claude/skills/novis/SKILL.md`, because it reads `AGENTS.md` only in a project with no `CLAUDE.md` | `hooks.PostToolUse` in `.claude/settings.json` | https://code.claude.com/docs/en/env-vars , https://code.claude.com/docs/en/memory , https://code.claude.com/docs/en/hooks |
| Cursor | `CURSOR_AGENT`, documented on its agent terminal page | nothing: it reads `AGENTS.md` | `hooks.postToolUse` in `.cursor/hooks.json` | https://cursor.com/docs/agent/terminal , https://cursor.com/docs/context/rules , https://cursor.com/docs/agent/hooks , https://cursor.com/docs/reference/third-party-hooks |
| Codex | `CODEX_THREAD_ID` | nothing: it reads `AGENTS.md` | none: its hooks are experimental and give the patch text, not the edited file's path | `codex-rs/core/src/exec_env.rs` in the Codex repository |
| GitHub Copilot | `COPILOT_AGENT=1` or `AI_AGENT=github_copilot_vscode_agent` (the VS Code agent's terminal), `COPILOT_AGENT_SESSION_ID` (Copilot CLI), `GITHUB_COPILOT_API_TOKEN` (the cloud agent) | `.github/instructions/novis.instructions.md`, because which Copilot surface reads `AGENTS.md` is not documented | none: its hooks are a preview with two payload formats, and the fields naming an edited file are not documented | — |
| OpenCode | `OPENCODE=1` | nothing: it reads `AGENTS.md` | none: code after an edit runs only as a JavaScript or TypeScript plugin | — |

The Cursor rule [0256](0256.md) wrote, `.cursor/rules/novis.mdc`, is retired: a re-run deletes an
untouched copy and leaves an edited one with a note. A file an earlier run wrote is kept current
whichever agent runs `init` now, so every person on a team keeps the same files.

### 3. The hook entries, and how they are merged

Claude Code's entry, under `hooks.PostToolUse` in `.claude/settings.json`:
`{"matcher": "Write|Edit|MultiEdit", "hooks": [{"type": "command", "command": "nvs agent hook claude-code"}]}`.
Cursor's, under `hooks.postToolUse` in `.cursor/hooks.json`, a new file of which starts as
`{"version": 1}`: `{"command": "nvs agent hook cursor", "matcher": "Write"}`.
`.claude/settings.local.json` is each person's own and is never read or written.

An entry is found again by its exact command, so a project may change the matcher. A missing entry is
added at the end of the event's array for a chosen agent, and an entry that is there is left whoever
runs `init`. `--no-hooks` adds none and removes the entry wherever it is; a file left with nothing but
the skeleton `init` creates is deleted. `--check` names a missing hook as `missing hook <path>`, and
with `--no-hooks` it reads no hook file.

The workspace's `serde_json` sorts object keys, and turning on `preserve_order` would reorder every
other document the workspace writes. So the merge reads the file into an order-keeping document type
of its own, and writes every key and entry back in the order it found them; only the indentation is
normalised to two spaces. A file that is not valid JSON, not an object, or whose `hooks` or event
value has the wrong type refuses the whole run, and `--force` does not override that: the file holds
the project's other settings, and a file `init` cannot read is one it cannot rewrite without losing
them.

### 4. `nvs agent hook` checks the edited file and gives back its errors

The verb reads the tool's JSON payload on standard input and takes the path from the first of
`file_path`, `path`, `target_file` and `filePath` in `tool_input`, else from a top-level `file_path`.
Claude Code documents `tool_input.file_path`. Cursor documents no field of its `Write` tool's input, so
the other names are the ones its tools are known to use, and a `tool_input` sent as a JSON string is
read as well. Anything that goes wrong before the check — a payload that is not JSON, no path, a path
not ending in `.nvs` — ends it silently with status 0, because a hook must never break the agent. It
runs in the payload's `cwd`, or in the first of Cursor's `workspace_roots` when there is no `cwd`: a
hook the tool started in another directory starts itself again there, because the process never
changes its own working directory (`nv verify`'s test step counts a binary that does as one that can
read any file). It checks the file in-process exactly as `nvs check <file>` does there, so the
configuration and the program that
lends a class file its `autoload` map ([0257](0257.md)) are found as they would be. It never writes a
default `nvs.toml`: a hook runs after every edit, and the project did not ask for one.

Only errors are given back. A warning that stands would be repeated after every edit until the agent
learned to pass over the report; `nvs check` shows warnings when asked. The first five errors are
rendered by position without colour, then a line with the number of the others and the
`nvs check <path>` that shows them all, then the line naming `nvs agent show` when an error has a
code. The whole-run rendering is not
used, because its "aborting due to N errors" would misstate a capped list. A clean file prints
nothing.

Claude Code gets `{"decision": "block", "reason": …}` on standard output with status 0: after
PostToolUse, `block` does not undo the edit, and Claude Code gives the reason to the agent as feedback
to act on. `hookSpecificOutput.additionalContext` was rejected, because it is the field for context
that is not an error. Cursor gets `{"additional_context": …}`, the only text its postToolUse output
has. Exit status 2 with the report on standard error was rejected: Cursor treats status 2 as a
denial. Cursor's third-party hooks page says a `decision: "block"` with a `reason` from a Claude Code
hook becomes an automatic follow-up there too.

### 5. A Cursor session hears about an edit once

Cursor loads Claude Code's hooks from `.claude/settings.json` by default. So `nvs agent hook
claude-code` prints nothing when it runs under Cursor and `.cursor/hooks.json` in the working
directory carries Cursor's own entry. It runs under Cursor when the payload carries `cursor_version`
or one of `CURSOR_PROJECT_DIR`, `CURSOR_VERSION` and `CURSOR_AGENT` is set. Cursor's hooks page
documents the field and the first two variables for a hook's process; `CURSOR_AGENT` is documented
only on its agent terminal page, for the commands the agent runs. Without Cursor's entry the Claude
Code hook reports as usual, and Cursor reads its report.

## Consequences

A person running `init` by hand writes the stanza and nothing for any one tool, and an agent running
it gets its own files without a flag. An agent that edits a `.nvs` file sees its errors in the same
turn. The hook costs one front-end run of the edited file after every edit of a `.nvs` file, and a
process start and a JSON parse after every other edit. A tool that starts the hook outside the
payload's directory costs a second process start for each `.nvs` edit. A project whose settings file is broken
cannot run `init` until it is fixed.

Not checked: no live Claude Code or Cursor session ran the hook. Which field of Cursor's `Write`
tool input names the edited file is not documented, and neither is whether that input arrives as an
object or as a JSON string; § 4 lists what the hook accepts.

## Alternatives rejected

- **Tree markers, as [0256](0256.md) chose.** They name the tools somebody used, not the one running.
- **Enabling `serde_json`'s `preserve_order`.** It changes every JSON document in the workspace.
- **A wrapper script or a plugin for Codex, Copilot and OpenCode.** The user's call: where the tool has
  no plain command hook, there is no hook.
- **Warnings in the report.** See § 4.
