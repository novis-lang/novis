# ADR 0204 — A hosted service's console is the platform log, and `--log-file` is gone

- **Scope:** where a service's stdout and stderr go on Windows, what the installer no longer asks
  for, and how an event-log record is rendered. The reload, the drain and the identity of the service
  stay [0093](0093.md)'s.
- **Depends on:** [0093](0093.md), [0196](0196.md).
- **Validated by:** `tools/service-live.ps1` against the real service control manager, and
  `crates/nvs-cli/tests/windows_resource.rs`'s message-table case.

> **In short:** `nvs service install --log-file` promised a destination nothing ever wrote to on
> any platform, and the installer refused an install that named none (`E0632`). Both are removed.
> Under the SCM the dispatcher redirects the process's stdout and stderr into the event log, one
> record per line, which is what the journal does for a unit under systemd; the four lifecycle
> records go beside them, and `nvs.exe` carries a message table so every record renders as its text.

## Context

### 1. The option was a promise nothing kept

[0093](0093.md) § 2 and § 4 reasoned that a service has no console, so stderr goes nowhere and a
refused compile would leave no trace; the installer therefore insisted on a destination, either its
own `--log-file` or a `[log] target` in the named configuration, and refused otherwise. The
installer did insist. But the path went nowhere: the systemd unit renderer never wrote a
`StandardError=` line for it, the Windows registration stored nothing but the argv
(`rule:packaging/the-argv-lives-in-imagepath`), and `nvs serve` had no way to learn the path. What
`--log-file` did was grant its directory to the service account and satisfy the refusal. The first
live run of the dispatcher ([0093](0093.md)'s missing half, landed the same day) confirmed it: a
service installed with `--log-file` served and stopped without the file ever appearing.

### 2. A `[log] target` was never the answer either

The refusal accepted a `file:` or `syslog` target as a destination. That is where `Core\Log` goes.
It is not where a refused configuration's diagnostic goes, nor a boot warning, nor a `FATAL`: those
are written to stderr by the process, and a `[log] target` says nothing about stderr. The row's own
reason, "a refused compile leaves no trace", was not met by the row.

## Decision

### 3. Under the SCM, stdout and stderr are the event log

`crate::dispatch` (the SCM dispatcher) replaces the process's standard output and standard error
handles with anonymous pipes before the server runs, and a thread per pipe writes each line as one
event-log record under the service's source — information for stdout, warning for stderr. `std`
asks the platform for the standard handle on every write, so the redirect holds for the process's
life without any code above it knowing. This is the SCM's spelling of what systemd already does:
the journal takes a unit's stderr, and a Linux service needs nothing for it.

A pipe that cannot be made leaves the handle as it was. The records are how a failure is read, and
a start refused for want of them would be the failure with no way to read it.

### 4. `--log-file` and `E0632` are removed

The installer's `--log-file` option is gone from `nvs service install` and `nvs service unit`, and
so is the refusal `E_SERVICE_OUTPUT_GOES_NOWHERE` (`E0632`) with the host fact behind it. The
directory grant survives for the one path that is real: the file a `[log] target` of `file:` names,
which the service opens and must be able to rotate. The codes `E0630`, `E0631`, `E0633` and `E0634`
keep their numbers; nothing takes `E0632`'s place.

### 5. The binary carries a message table

Every event-log record the service writes is rendered as its one insertion string, and
`build/winres.rs` links a `RT_MESSAGETABLE` resource with ids 1 to 6, each `%1`, beside the icon and
version information [0196](0196.md) put there. The source's `EventMessageFile` was already the
binary; without the table Event Viewer heads each record with "the description for event id …
cannot be found" and PowerShell's `Get-WinEvent` shows an empty `Message`. The ids are: 1 started,
2 stopped, 3 failed to start, 4 reload applied, 5 a line of stdout, 6 a line of stderr.

## Consequences

- A refused configuration under the SCM is readable in Event Viewer as a warning record carrying
  the diagnostic, beside the "failed to start" error record; before, it was lost.
- A `[log] target = "stderr"` is a working destination for a hosted service: every `Core\Log`
  record becomes an event-log record. That is the operator's choice and its volume is theirs, as it
  is under the journal.
- What it spends, per `rule:programs/memory-priority`: two pipes and two threads for the life of a
  hosted process, and one event-log write per line the server prints. Nothing per request unless the
  operator sends `Core\Log` to stderr.
- A line written in the last instant before exit can be lost with the process: the reader threads
  are not joined. The lifecycle records are written directly and are not affected.

## Alternatives rejected

- **Make `--log-file` real: store the path under the service's `Parameters` key and have the
  dispatcher redirect to that file.** It would hold [0093](0093.md) § 3's "nothing but the argv is
  stored" to a second exception, and it answers a question the platform already answers: an
  administrator looks in the event log first, and a file nobody was told about is the second place.
- **Keep the refusal and accept `stderr` as a destination.** The refusal's only reason was that
  stderr went nowhere; with stderr captured, a row that refuses an install for naming no destination
  refuses nothing real.

## Verification

- `tools/service-live.ps1`: install without `--log-file`, start, request, stop, uninstall, and the
  event log holding the "listening on" line as a stdout record beside the lifecycle records.
- `crates/nvs-cli/tests/windows_resource.rs`: the message table covers ids 1 to 6 with `%1` each.
- `crates/nvs-cli/src/service.rs`'s refusal cases no longer name `E0632`, and `nvs service install
  --log-file` is a usage error.
