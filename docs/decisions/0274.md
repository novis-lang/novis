# ADR 0274 — Nothing in Novis is tested against PHP or translated from it, and correctness leaves the priority ordering

- **Scope:** the end of PHP as a reference for Novis: the priority ordering loses its correctness item and
  is cited by name; the PHP oracle, `nvs test --php` and the differential tree go; `nvs convert`, M11 and
  every list that maps a PHP name or construct to a Novis one go, with the editor's PHP-name completion
  and E0320's PHP clause; the `php-migration/` rule topic and the divergence catalogue go; and the three
  stdlib gaps parked on M11 are decided by Novis's own rules. What stays naming PHP is listed in § 5.
  The wording of the one concept page, and which Novis rule each moved `php-migration/` rule lands in,
  are left to the goal's stages and the rules they write.
- **Depends on:** [0004](0004.md) (the ordering this record shortens), [0007](0007.md) (the divergence
  list), [0079](0079.md) (`.nvst` and its differential comparison), [0089](0089.md) and [0111](0111.md)
  (the converter and the PHP-name completion layer this record ends), [0099](0099.md) (the case-file
  grammar).
- **Validated by:** the goal `php-oracle-retired`'s acceptance checks: no `--ORACLE--` section and no
  `php` spawn remain under `crates/nvs-test/src/`, `tests/differential/` is gone, and `AGENTS.md` and
  `rule:programs/memory-priority` list four priorities.

> **In short:** PHP was the oracle that let the language be prototyped fast, and that era is over. Every
> behaviour Novis has is stated by its own rule and pinned by its own conformance case, so **no test and
> no check runs PHP to judge Novis**: the `--ORACLE--` and `--ORACLE-DIVERGES--` sections,
> `nvs test --php` and `tests/differential/` are removed, for users too. **Priority 2, "correctness of
> language semantics — PHP-compatible observable behaviour", is deleted, not reworded**: the ordering is
> security, latency, simplicity, memory, and it is cited by name from now on. **There is no mechanical
> migration from PHP**, planned or shipped: M11 and `nvs convert` leave the plan, and no list maps a PHP
> function or construct to a Novis one, in a document, in data or in a feature. A program is ported by
> rethinking it, by hand or with an agent and `nvs agent`. One concept page stays, and PHP is named only
> where a page compares the two, in the PHP benchmarks, and in the diagnostics for a PHP habit.

## Context

The differential tree ran a case under both engines, and a difference was either a bug or a recorded
divergence. That made PHP normative in three places: the second item of [0004](0004.md)'s ordering, the
divergence list of [0007](0007.md), and the oracle sections [0079](0079.md) built `.nvst` around. Novis
has since diverged a long way — keys are strings, every binding is typed, casts are gone, `is` is the
one type test — and each divergence is already a rule of its own. The oracle now mostly confirms that
PHP still differs where a rule says it does.

Priority 2 also contradicted `rule:programs/no-compatibility-promise`, which forbids "PHP compatible" in
any document, while `AGENTS.md` printed the phrase as the second thing a contributor weighs.

The converter ([0089](0089.md)) and the PHP-name completion layer ([0111](0111.md)) rest on the same
premise from the other direction: that a program moves to Novis name by name. A mechanical port carries
the PHP shape over and misses what Novis does that PHP cannot — tainted values, isolates, uncoloured
suspension — which are the three claims of `rule:programs/three-claims`.

## Decision

### 1. The user's calls, first set: PHP stops judging Novis

No test and no check runs PHP to judge Novis. `nvs test --php`, the `--ORACLE--` and
`--ORACLE-DIVERGES--` sections and `tests/differential/` are removed, for users as well as for this
repository. Correctness is the job of the rules and the conformance cases. The sentence "This replaces
PHP's `x`." leaves `about.md` and the registry text. **The PHP benchmarks stay**: `benches/userland`'s
PHP engine, `bun nv bench --serve-vs-fpm` and `benches/proxied`'s php-fpm arm, with their ledgers and
rules. PHP is needed only to run them.

### 2. Priority 2 is deleted, and a priority is cited by its name

"Correctness of language semantics — PHP-compatible observable behaviour" leaves the ordering and is
not replaced. What a program observably does is stated by the rules and pinned by the conformance
cases, and the ordering does not repeat it. It decides between the four things left in it:

| Before | After |
|---|---|
| 1. Security and request isolation | 1. Security and request isolation |
| 2. Correctness of language semantics | — deleted |
| 3. Latency and throughput on the request path | 2. Latency and throughput on the request path |
| 4. Simplicity | 3. Simplicity |
| 5. Memory footprint | 4. Memory footprint |

A frozen record that says "priority 3" means latency, and "priority 5" means memory footprint; this
table is how it is still read. Every live citation names the priority it means instead — "latency",
"memory footprint" — because a number shifts when the list changes and a name does not. Frozen records
keep their numbers.

### 3. The user's calls, second set: no mechanical migration

There is no mechanical migration help from PHP to Novis, planned or shipped. M11 is scratched, and
with it `nvs convert` and the `.phpt` importer. **No list maps PHP functions or constructs to Novis
ones** — not `docs/spec/02-php-migration.md`, not `tools/data/php-builtins.txt`, not the `Replaces`
column, not `nvs_stdlib::php_names`. The features that read such a list go with it: the editor's
PHP-name completion with its `nvs.completion.phpNames` setting, and E0320's PHP clause. A program is
ported by rethinking it, by hand or with an AI agent and `nvs agent`.

The divergence catalogue goes too: `docs/divergences.md` and the rule field `divergesFromPhp`. A
divergence is a relation to PHP, and once PHP is not the reference there is nothing to diverge from;
each behaviour is stated by its own rule. The language rules filed under `php-migration/` move to the
topics that own their subject, and the topic is dissolved.

### 4. The records whose decisions this ends, and the rules it removes

[0089](0089.md) is behind every `tooling/convert-*` rule, and [0111](0111.md) is behind the PHP-name
completion layer. Both end here, and each turns `retired` in the commit that removes the last rule it
created. The `changes:` block has no key for a removal, so this section records them:

- the eight converter rules: `tooling/convert-one-table-two-modes`, `tooling/convert-three-tables`,
  `tooling/convert-equivalent-is-proven`, `tooling/convert-is-deterministic`,
  `tooling/convert-drops-nothing`, `tooling/convert-annotations-and-report`,
  `tooling/convert-php-front-end` and `tooling/convert-never-does`;
- `php-migration/a-trait-converts-to-an-interface-or-a-delegate` and
  `php-migration/a-shell-call-converts-to-process-under-review`;
- the five PHP-name completion rules: `php-migration/every-php-builtin-is-a-completion-candidate`,
  `php-migration/the-php-name-layer-is-joined-at-build-time`,
  `php-migration/an-item-inserts-only-a-registered-member`,
  `php-migration/a-php-name-sorts-below-every-novis-symbol` and
  `php-migration/completion-php-names-setting`;
- every other `php-migration/` rule either moves to the topic that owns its subject, keeping its
  `because`, or is deleted when its whole content is a relation to PHP. Then the topic's record and
  chapter are deleted.

A live citation of a removed rule is rewritten. A frozen record that cites one keeps the id in
backticks and loses the `rule:` prefix, the edit commit 3759c8451 made to [0150](0150.md). A citation
of a moved rule takes the new id.

### 5. Where PHP is still named

Origins stay honest, not prominent. One line on the home page and in `README.md` says Novis grew out of
PHP's ideas. Elsewhere PHP is named only on the one concept page — the php-differences chapter cut down
to how Novis thinks differently, what it can do that PHP cannot, and how to port by rethinking — with its
examples and attacks; on `why-novis` and the claims pages that compare the languages; in the PHP
benchmarks; and in the diagnostics for a PHP habit: E0229 for `<?php`, W1004, and the superglobals and
PHP-constant reference cards. Those diagnostics stay because each is help for one error a person
meets, not a table to translate from. That last call is the agent's, not the user's.

Names stay: the `php-differences` id and paths, the `E_PHP_*` constants, the Cargo keyword, and a
conformance case whose file name mentions PHP.

### 6. The three gaps M11 was holding follow Novis's own rules

Each was parked as "a decision on PHP compatibility", waiting for the converter to say what PHP needs.
Nothing does now. These three are the agent's calls, not the user's:

- **A `Core\Str` search matches only on grapheme boundaries**, across the whole search family, because
  every position in a `string` is a grapheme (`rule:types/string-is-utf8`).
- **A `Core\Arr` member that calls back into Novis code holds its subject for the whole walk**, as
  `foreach` does, so a callback that writes to the subject writes to a copy.
- **`Core\BigInt::powMod` returns the least non-negative residue**, which is what every use of modular
  exponentiation wants.

## Consequences

### 7. What it spends, and what it buys

- **Performance.** `nv verify` runs one tree fewer and spawns no PHP. The stdlib build loses the join
  that built the PHP-name table. A `Core\Str` search checks a grapheme boundary for each candidate
  match, and a callback-taking `Core\Arr` member pays one refcount pair per call.
- **Memory.** The binary loses the PHP-name table.
- **Usability.** Somebody porting a program loses side-by-side `--ORACLE--` tests, PHP-name completion,
  E0320's PHP clause and the construct tables. They gain one page that says how Novis thinks and how to
  port by rethinking, and the `nvs agent` topics stay.
- **Simplicity.** One runner mode, two case sections, one flag and one embedded editor grammar fewer;
  about 280 cases and about 30 playbook entries fewer; one milestone, about fifteen rules and a whole
  rule topic fewer; a 1,788-line list, a 1,430-line inventory, an editor layer and its setting fewer;
  and one field fewer on about 593 rule records.

`rule:testing/nvst-is-separate` loses the differential comparison, and
`rule:ide/case-files-have-their-own-grammar` loses PHP inside `--ORACLE--`. Each fragment is rewritten
when the oracle is removed, so neither states a removal before the tree holds it.

## Alternatives rejected

### 8. Rewording priority 2

"Correctness of language semantics", without the PHP clause, was the obvious edit. It was rejected by the
user: correctness is not something the ordering trades against latency or memory, so an item for it
decides nothing, and the rules and the conformance cases already own it.

### 9. Keeping the oracle as an optional mode

`nvs test --php` for users, or the differential tree as an unrun archive, would keep a second reference
that disagrees with the rules wherever they diverge, and a reader could not tell which one is normative.
Removing it leaves one.

## Verification

### 10. The gate is an absence

The goal's stage checks hold it: no `php` spawn and no oracle section under `crates/nvs-test/src/`, no
`tests/differential/`, four priorities in `AGENTS.md` and `rule:programs/memory-priority` and none cited
by number outside frozen records, no `tooling/convert-*` rule and no `php-migration/` topic, and no
`divergesFromPhp` field. `bun nv records --check` holds the `changes:` block against the four rules'
`because` lists.
