# ADR 0255 — A match answers its access decision as a case of the enum its call site writes

- **Scope:** how a program compares `Core\Router\Match`'s access decision. What the compiler checks about
  `allow:`, who dispatches and what the server enforces are [0102](0102.md)'s and [0199](0199.md)'s and
  unchanged; `access()` stays as [0199](0199.md) § 1 shipped it.
- **Depends on:** [0199](0199.md), [0102](0102.md).
- **Validated by:** `tests/conformance/core/a-match-answers-the-access-decision-as-a-case-of-the-written-enum.nvst`,
  `tests/conformance/core/access-as-answers-a-uint-backed-case-that-a-match-arm-compares.nvst`,
  `tests/conformance/reject/access-as-needs-an-enum-as-its-type-argument.nvst`,
  `tests/hostile/core/Router-Match/accessAs/01-an-admin-route-tries-to-pass-as-public.nvs`, and
  `access_as_names_a_case_only_for_a_decision_of_the_written_enum` in `crates/nvs-stdlib/src/router.rs`.

> **In short:** `Core\Router\Match::accessAs<E>(): ?E` answers the route's `allow:` as a case of the
> enum `E` its call site writes, and `null` when the decision is not one of `E`'s cases. A dispatcher
> compares that case with `==`, so a renamed case is a compile error at the comparison and a case of
> another enum never reads as one of `E`'s. A type argument that is not an enum is `E0841`.
> `access()` keeps answering the name as text, for a log line and for a class constant.

## Context

A route declares `#[Core\Access(allow: Core\Audience::Public)]` with an enum case, and the dispatcher
read it back through `access(): ?string` as `"Core\Audience::Public"`. Comparing that with the case the
attribute was written with is `E0466`, because a `?string` and an enum are disjoint, so the only
comparison that compiled was against the text. [0199](0199.md)'s *Consequences* named the cost: a
renamed enum case breaks it silently. In a dispatcher that is a security failure and not a style one.
`$rule == "App\Role::Admin"` guarding an admin check keeps compiling after `Admin` is renamed, never
matches again, and the route is served unguarded.

## Investigation

The first remedy considered was `access(): mixed` answering the constant's value. It is unsafe.
A case is its backing integer at run time and a value in `mixed` does not say which enum it came from
(`rule:enums/representation`), so `Core\Audience::Public` and `App\Role::Admin` are both `0` there. A
`match` over a `mixed` decision would take the `Public` arm for the admin route.

What the typed member needs already exists in two halves. A `Core` member may declare a type variable
its call site writes (`CoreTy::Written`, which `Core\Json::decodeAs<T>` uses), and the runtime describes
every enum of the unit by name (`ClassTable::enum_desc`, which `Core\Reflect\EnumInfo::of` reads). What
did not exist is the bridge: a written type argument reached a native member only as a class
descriptor, and an enum has none.

## Options considered

1. **`accessAs<E>(): ?E`, beside `access()`.** Chosen.
2. **`access(): mixed` answering the value.** Refused for the collision above.
3. **`access(Class::class): ?E`, typed from a string argument.** Needs the checker to type a result from
   an argument's value, a special case no other member has, for the same answer option 1 gives with
   machinery that already exists.
4. **Keep the text and teach the comparison.** Leaves the silent rename in place, which is the bug.

## Decision

### 1. `Core\Router\Match::accessAs<E>(): ?E`

The case of `E` that the route's `allow:` names. `null` for a decision of another enum, for a class
constant and for a row with no decision, and a dispatcher reads `null` as denied. One application
mixes `Core\Audience::Public` with its own roles, so a dispatcher asks once per enum:
`accessAs<Core\Audience>() == Core\Audience::Public`, then `accessAs<App\Role>()`.

### 2. A roster for members whose type argument is an enum

`nvs_stdlib::registry::WRITTEN_ENUM_MEMBERS` lists the members that take one. The checker records the
written enum on the call (`ResolvedCall::written_enum`) at both call paths and both callable-reference
paths, and `nvs-ir` hands the native member the enum's name as a `string` in argument 0, ahead of the
receiver. The helper compares the row's `Enum::Case` against that name and only then looks the case up.

### 3. `E0841` for a type argument that is not an enum

A class, a shape and a scalar are refused. A route whose `allow:` names a class constant has no enum,
and `access()` is its reading.

### 4. `access()` is unchanged

The name stays the reading for a log line and for a class constant. Its card and examples now point a
dispatcher at `accessAs`.

## Diagnostics

`E0841` — `` `Core\Router\Match::accessAs` returns a case of an enum, and `App\Policy` is not an enum ``.

## Consequences

- A comparison of the decision is typed. A renamed case is a compile error where it is compared, and
  an enum mix-up answers `null`, which is denied.
- **Spends**, per call: no allocation, because the enum's name is an immortal string constant of the
  unit. The work is one comparison of the row's enum name against the written one, and, when they are
  equal, a linear search of the unit's enums by name. Nothing per request beyond the call, and nothing
  for a program that never calls it.
- `Core\Router\Match` has one more member, and the access examples now show `accessAs` for checks and
  `access` for names.

## Verification

The three conformance cases, the attack and the unit test above. The attack reads an admin route whose
case is `0`, like `Core\Audience::Public`, as public one million times and counts `0`.
