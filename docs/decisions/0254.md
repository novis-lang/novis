# ADR 0254 — `??=` reads its target the way `??` does and is typed as the value it wrote, and `??+=`, `??-=` and `??.=` start from the zero of the target's type

- **Scope:** what `??=` reads, what it writes and what its value's type is, and three new assignment
  operators built on the same read. The plain `=`, narrowing after a write and every other compound
  operator are unchanged and stay with their own records.
- **Depends on:** [0007](0007.md).
- **Validated by:** the conformance and reject cases the two rules' `guardedBy` names, and the
  hooked-property test in `crates/nvs-ir/src/lower/tests.rs`.

> **In short:** `??=` was `$a = $a ?? $v` with an ordinary read of `$a`, so it threw on the absent
> key PHP writes its default into, and its value had the target's type, so
> `return $this->posts ??= Post::findActive();` did not compile against a non-null return type. The
> read a `??=` makes of its own target is now the guarded read `??` makes, at every level, and the
> expression's type is the target's with `null` removed when the written value cannot be `null`.
> On that same read, `$a ??+= $v`, `$a ??-= $v` and `$a ??.= $v` mean `$a = ($a ?? d) op $v` with
> `$a` evaluated once and `d` the zero of the target's own type. No syntax writes another default.

## Context

### 1. Both shapes PHP code writes `??=` for failed

Ported PHP uses `??=` in two places. A memoising getter, `return $this->posts ??= Post::findActive();`,
was `E0403` against a return type of `array<Post>`, because the compound-assignment check answered the
target's type, `?array<Post>`, for every operator. An array default, `$options["theme"] ??= "light"`,
threw `undefined array key` when the key was absent, because the rewrite `$a["k"] = $a["k"] ?? $v`
read the target as an ordinary read, and [0007](0007.md) makes an ordinary read of an absent key
throw. The reference already said `??=` works as PHP's does.

### 2. `??` is already the guarded read

[0007](0007.md) names `$a["k"] ?? $d` as the one read of an absent key that yields rather than
throws, and `isset` and `empty` share that read. `??=` is spelled as that `??`, and a program that
writes it means the same "absent or `null`".

### 3. A count throws on its first new key

`$counts[$word] += 1` throws on the first word not yet counted, and `$lines[$day] .= $entry` on the
first day. So a Novis program writes `$counts[$word] = ($counts[$word] ?? 0) + 1`, which names the
target twice. PHP accepts `$counts[$word]++` there only because it reads the absent key as `null`
and warns, which [0007](0007.md) refuses.

## Options considered

### 4. For the absent key

Keep the throw and document `$a[$k] = $a[$k] ?? $v`; or make the read `??=` makes of its target the
guarded one.

### 5. For the result type

Keep the target's type; or type the expression as the value it has afterwards.

### 6. For the default

Do nothing and keep the written-out form; let `+=`, `-=` and `.=` read an absent target as zero; add
operators whose default is written at the use, `($a ?? 100) -= 1`; or add operators whose default is
fixed by the target's type.

## Decision

### 7. `??=` reads its target guarded

The read `??=` makes of its own target is the read `??` makes of its left operand: an absent key at
any level of the target, and a `null` level under it, give `null` and do not throw, so the right side
is written there. `$g["k"]["j"] ??= 5` with no `"k"` creates the row, as `$g["k"]["j"] = 5` does. An
absent key and a stored `null` in an `array<?T>` both take the right side. A present value that is
not `null` is left alone, and the right side does not run.

The mark is one the **read** consults and the **write** does not. The two share one typed entry per
span, and a write through a guarded row would lose the `null` the write path checks for, so
`array<?array<int>> $g; $g["0"]["1"] ??= 5;` stays `E0482` and never reaches the lowering.

### 8. `??=` is typed as the value it wrote

The value of `$a ??= $v` is the value `$a` has afterwards. Its type is the target's type with `null`
removed when `$v`'s type has no `null`, and the target's type when it does. The value is the one
written, never a second read of the target, so a hooked property runs its `get` hook once and its
`set` hook once. The target's declared type does not change, and nothing is narrowed on the next
line: `?int $n = null; $n ??= 1;` leaves `$n` a `?int`, as every write does
(`rule:types/narrowing`). Every other compound operator and the plain `=` keep the target's type.

### 9. Three operators with a default

`$a ??+= $v`, `$a ??-= $v` and `$a ??.= $v` are `$a = ($a ?? d) op $v` with `$a` evaluated once, and
that sentence answers every question about them. Which operand types are accepted, what overflows,
what a qualifier does and what the expression's type is are what the written-out form does, and a
written-out form that is refused refuses the operator with the same code.

`d` is the zero of the target's own type, never an `int` by default: `0` for `int` and `uint`, `0.0`
for `float`, the zero `decimal`, and `""` for `string`. `?uint $n = null; $n ??+= 1;` gives a `uint`.
For a `mixed` or union target the default is the `int` `0` for `??+=` and `??-=` and the `string` `""`
for `??.=`, and the operator is answered from the runtime tag as `rule:types/arithmetic` says. A
target whose type without `null` has no zero (an object, an array, a `bool`) reaches the refusal the
plain operator already makes there.

A target that can never be `null` or absent compiles, and the operator is then the plain `+=`, `-=`
or `.=`, as `??` and `??=` already compile on such a value. `tainted` and `secret` do through `??.=`
what they do through `.=`, and the default carries neither.

### 10. These three and no others

There is no `??*=`, no `??/=` and none for the bitwise operators: a product or a quotient that starts
from zero stays zero. The bare `??+` and `??-` are not operators, because `$a ??-1` already means
`$a ?? -1`, and a token needs its `=`.

## Diagnostics

### 11. No new code

`($a ?? 100) -= 1` stays `E0105`, the code for an assignment target that is not a place. `??+=` on a
`string` is what `+=` on a `string` is, and `??.=` into an `int` is what `.=` into an `int` is. A
nullsafe target, an append target and a target whose row may be `null` are each refused with the code
the plain compound assignment already uses.

## Consequences

### 12. Cost

Performance: one `null`-or-absent test more than `+=`, and the same one read and one write of the
target. `??.=` copies the accumulated string on each append, as `.=` on an element or a property
already does. Memory: nothing. Usability: a count, a running total and a grouped string are one line,
and ported `??=` code compiles and runs. Simplicity: three operators PHP does not have, whose default
is not visible where they are written.

### 13. Existing programs

Every `??` and `??=` that compiled keeps its output: a present target that is not `null` is read and
left alone exactly as before. Programs that write `$a[$k] = ($a[$k] ?? 0) + 1` keep it, and neither
form is preferred.

## Alternatives rejected

### 14. Reading an absent target as zero under `+=`, `-=` and `.=`

That is PHP's behaviour without its warning, and it is the hole [0007](0007.md) closes: a misspelled
key would count from zero silently. The new operators say where a default is wanted.

### 15. A default written at the use

`($primary ?? $backup) += 1` reads as "add to whichever exists", and making `($a ?? 100) -= 1` mean
"start from 100" would give the same syntax two meanings. `$a = ($a ?? 100) - 1` is that program, and
it already works.

### 16. Narrowing the target after `??=`

It would make one write narrow where no other write does. It is a question for every write at once,
not for this operator.

## Verification

### 17. Guards

An accept case with a memoising getter called twice, an absent key, a nested absent key, a stored
`null` and a present value whose right side must not run; a reject case for `??=` through a nullable
row; an accept case for the three operators over a word count, a stock count that goes negative,
grouped lines, `?int` and `?string` targets, `float` and `decimal` targets, a nested absent row and a
key with a side effect that runs once; a reject case with one diagnostic per refusal in § 11; a lexer
test that `$a ??-1` is still a `??` and a signed literal; and the hooked-property test of § 8.
