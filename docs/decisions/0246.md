# ADR 0246 — An extension crosses typed WIT values, runs on its request's core under that request's budget, and holds only what its entry, its manifest and its caller all grant

- **Scope:** everything [0003](0003.md) left open about Tier 1: how a value is typed at the boundary,
  what the `nvs:ext@1.0.0` world imports and exports, what the manifest and the `.nvsx` file carry,
  what loading checks, how a call runs on a core and under which limits, what a failure looks like to
  the program, which I/O a guest may be granted and by whom, and what `nvs ext` does. The two
  first-party components and how they ship are [0247](0247.md); the intl component's API is the
  record goal `ext-intl` opens; the WIT text itself is written by goal `ext-design` against this
  record.
- **Depends on:** [0003](0003.md) (the three tiers and the sandbox), [0055](0055.md) (the qualifier
  axis at the boundary), [0078](0078.md) (reload and `env_hash`), [0120](0120.md) (the image
  component's entry points), [0051](0051.md) (tier placement).
- **Validated by:** the acceptance checks of the M9 goals `ext-host`, `ext-compiler`, `ext-grants`
  and `ext-tooling`, and `benches/abi-probe`'s `wasm-probe` guards.

> **In short:** a parameter or return of an extension crosses as the WIT type a fixed table gives
> its Novis type — `int` is `s64`, `bytes` is `list<u8>`, a shape is a `record`, `?T` is `option<T>` —
> copied whole, and only `mixed` still crosses as the `value` handle 0003 described. A `.nvsx` is one
> component with two custom sections, `nvs.manifest` (JSON) and `nvs.source` (the Novis source that
> builds on it), and both are covered by one `sha256` pin that every `[[extension]]` entry must now
> carry. A request gets one instance per extension it calls; the call is a wasmtime async call
> polled by the request's coroutine on the request's own core, it yields to the core's other tasks
> every epoch tick, and its CPU time and linear memory count against the request's own caps. A guest's
> error result throws the class the world maps it to, a trap throws a new `ExtensionError`, and only
> a CPU or memory limit is a `FATAL`. A guest links WASI with an empty context — no files, no network,
> no environment — and gains filesystem roots and outbound HTTP only where the `[[extension]]`
> entry's grant, the manifest's request and the calling code's own grant all agree. `nvs ext` builds,
> inspects, tests and pins a component, with Rust and C templates.

## Context

[0003](0003.md) chose the sandbox and measured its boundary, and M9 is the milestone that builds it.
Walking M9's plan against the records before any code exists found eight questions that 0003 either
left open or answered in a way a later record contradicts:

- **How a value is typed.** 0003 says every value crosses as an opaque `value` handle read through
  accessor calls. [0120](0120.md) § 3 then specifies the image component as eight typed exports —
  `run(Source, Plan): bytes` — that carry whole records and lists. The two shapes cannot both be the
  rule.
- **Whether the async claim holds.** 0003 says wasmtime's async support "is the same stack switching
  the scheduler already uses, so there is no async colouring". The mechanisms are alike, but wasmtime
  keeps a per-thread chain of active wasm calls in thread-local state and requires it to unwind in
  order. A Novis coroutine that parked with wasm frames on its stack would let a second coroutine on
  the same thread enter wasm and break that order. The composition has to be designed, not assumed.
- **What a guest may reach.** 0003 says WASI is "available as an opt-in world whose preopens are
  derived from the capability grants" and stops there: whose grants, which interfaces, and what a
  C or Go toolchain that links WASI for its own libc gets when nothing is granted.
- **Where the Novis half of a two-payload extension comes from.** `rule:packaging/an-extension-package-carries-two-payloads` has `nvs/image`'s builder resolved
  "exactly as a source package's is", but packages are M15, behind M9.
- **What a pin is.** The `[[extension]]` entry's `path` and `sha256` are both optional today, and
  the configuration reader accepts `sha256 = "abc"` (`crates/nvs-config/tests/tree.rs:44`).
- **What a crash is.** `rule:packaging/a-guest-runs-under-the-requests-budget` makes a trapped guest
  a resource-limit failure. A codec that panics on a crafted file has not exceeded a limit.
- **Whose memory a guest spends.** `rule:core-classes/image-pixel-cap` sizes "the extension's own
  memory cap" from the pixel cap, beside the request's cap rather than inside it.
- **How the compiler learns an extension's classes.** `Core` classes are a `const` slice
  (`crates/nvs-stdlib/src/registry.rs:1685`) seeded into the signature table at
  `crates/nvs-types/src/core_lib.rs:44`. Nothing registers a class whose existence depends on
  configuration.

## Investigation

What exists today, read from the tree: wasmtime 48 is a workspace dependency used only by
`benches/abi-probe`'s `wasm-probe` feature, which proves the pooling allocator, epoch interruption and
a host import (`benches/abi-probe/src/wasm.rs:95-171`). `wit-component` and `wit-parser` 0.254 are in
`Cargo.lock` through that crate; `wit-bindgen` is not. The `[[extension]]` block parses into
`Extension { path, sha256 }` (`crates/nvs-config/src/tree.rs:416-424`), is a `System`/`Reload`
directive (`crates/nvs-config/src/directive.rs:261`), and its pins fold into `env_hash`
(`crates/nvs-config/src/cache.rs:629-650`). Nothing loads, verifies or instantiates anything.

The per-request CPU cap is a watchdog sweep that raises a safepoint flag
(`crates/nvs-host/src/watchdog.rs:641-668`, `crates/nvs-runtime/src/ctx/safepoint.rs:516`), and the
memory cap is the accounting allocator (`crates/nvs-runtime/src/budget.rs:810`). A pooling-allocator
linear memory is mapped by wasmtime, not allocated through the global allocator, so neither cap
sees a guest today.

## Options considered

Each was decided with the user, one question at a time; the rejected halves are under *Alternatives
rejected*.

- Typed WIT values against handles everywhere, or both at the author's choice.
- WASI with an empty context, WASI plus grants, or Novis's own imports only.
- The entry's grant alone, the caller's authority, or the intersection of entry, manifest and caller.
- Files and outbound HTTP, files only, or files and raw sockets.
- A guest call on its core yielding, on a compute pool, or on the pool only when an export says so.
- The Novis source inside the `.nvsx`, in a folder beside it, or a minimal package system pulled
  forward from M15.
- A required pin without signatures, a required pin with ed25519 signatures, or an optional pin.
- A crash as a catchable exception, as a `FATAL`, or as a `FATAL` that runs `onLimit`.

## Decision

### 1. A value crosses as its WIT type

Every parameter and return of an exported function has a Novis type, and one fixed table gives its
WIT type. The table is closed: a Novis type not in it cannot appear in an extension signature, and a
manifest naming one does not load.

| Novis | WIT | Notes |
|---|---|---|
| `bool` | `bool` | |
| `int` | `s64` | |
| `uint` | `u64` | no conversion, as M8's parametric signatures promised |
| `float` | `f64` | |
| `string` | `string` | UTF-8 both ways; a guest returning invalid UTF-8 traps in the canonical ABI |
| `bytes` | `list<u8>` | one bulk copy each way |
| `array<T>` (a list) | `list<T>` | |
| `array<K, V>` | `list<tuple<K, V>>` | order kept |
| a shape `{a: T, b?: U}` | `record { a: T, b: option<U> }` | an optional field is an `option` |
| an enum | `enum` | case names in kebab-case on the WIT side |
| `?T` | `option<T>` | |
| a closed union of shapes | `variant` | one case per shape |
| a `Core` value class | the record the world's `types` interface defines for it | the list is closed and walked by goal `ext-design` |
| `resource` | a WIT `resource` the extension exports | lives until the request ends, never past it |
| `mixed` | `borrow<value>` | the 0003 handle, read through accessor imports |

A value is **copied whole** in each direction by the canonical ABI. That is what a coarse API wants —
0003 measured a bulk copy at about 12 ns per KiB — and it gives every author native types from
`wit-bindgen` with no marshalling code. The handle survives for `mixed` only, where the guest
genuinely cannot know the shape in advance. `throws` is not a column: every export returns
`result<T, error>` on the WIT side, and § 6 maps the error.

### 2. The `nvs:ext@1.0.0` world

The package `nvs:ext@1.0.0` defines the **imports** every extension may use and the **types** they
share. An extension's **exports** are its own: one interface, named by the manifest, whose functions
become the static methods of the class the manifest declares.

- `nvs:ext/types` — `error` (§ 6), the records the `Core` value classes cross as, and the `value`
  resource with its accessor functions (kind, scalar reads, string and bytes bulk copy, array length
  and element, shape field).
- `nvs:ext/log` — `write(level, message)`, into the calling request's log with the extension's name
  as the channel.
- `nvs:ext/settings` — `get(key) -> option<setting>`, reading the extension's own settings block
  from the request's configuration snapshot (§ 9).
- WASI 0.2 — `wasi:cli` (stdin empty, stdout and stderr to the request log at `debug`, no arguments,
  no environment, `exit` traps), `wasi:clocks` (the request's clock, so a test clock reaches the
  guest), `wasi:random` (`Core\Random`'s generator), `wasi:filesystem` and `wasi:http`'s outgoing
  handler under § 7's grants, and nothing else from WASI.

A component importing anything outside this list **does not load**, and the refusal names the
import. That is what makes "an extension attempting access it was not granted fails" a load-time
fact for every interface that is not offered at all, and a call-time refusal for the two that are.

The world is versioned by semver. A host implementing `1.y` loads a component built against `1.x`
for any `x ≤ y`; a component built against a newer minor or another major is refused, naming both
versions. A minor version may only add imports and types.

### 3. The `.nvsx` file: one component, two sections, one pin

A `.nvsx` is a WebAssembly component with two custom sections:

- **`nvs.manifest`** — JSON, `{"manifest": 1, ...}`: the class name, the exported interface it maps,
  for each export its Novis signature (parameter names, types, defaults, the trailing options shape)
  and its qualifier declarations (`rule:security/extension-declares-sink-or-source`), the class's
  `const` members, the settings block it reads (§ 9), the I/O it requests (§ 7), the largest linear
  memory it needs, and the help text each method shows (`rule:testing/feature-proofs`' Help proof).
- **`nvs.source`** — the Novis source files that build on the class, as a flat list of
  `(relative path, bytes)`, every file declaring a namespace under the extension's own.

At load the host checks the manifest against the component's actual WIT exports through § 1's table.
A signature the exports do not match, a Novis type the table does not hold, or a source file outside
the extension's namespace refuses the load.

The source half closes the M15 gap: loading the extension makes its namespace's source resolvable by
`autoload` with no line the program writes, compiled like any other file and holding the authority of
its own namespace — which is no grant at all unless the operator writes one. One file means one pin
that covers both the component and the code above it, so the source cannot be edited under a pinned
binary. `nvs ext inspect --source` prints it. When packages arrive, a package may carry a `.nvsx`;
nothing here has to change for that.

### 4. Loading: a pin is required

An `[[extension]]` entry needs `path` and `sha256`, and the pin is 64 hexadecimal digits. Boot and
reload refuse an entry without one, naming its file and line, and `nvs ext pin <file>` prints the
entry ready to paste. Load then refuses, each naming the entry: a file whose digest differs from its
pin, a component that does not validate, a manifest that is malformed or does not match its exports,
an import outside § 2, a class under `Core\` (`rule:core-api/core-means-always-present`) or `Novis\`
(reserved for the components [0247](0247.md) builds in), and a class name another loaded extension
already declares. Reload keeps 0078's shape: everything is verified first and the swap is refused
whole if one entry fails.

**Signatures are not part of M9.** A pin of the exact bytes, written by root, is stronger than a
signature for a file already on the disk; a signature earns its place when new bytes arrive from
somewhere else, which is the registry, and the registry, its keys and its transparency log are M15.

### 5. A call runs on its request's core, as an async call, and yields

A request gets **one instance per extension it calls**, created at its first call and dropped when
the request ends (`rule:packaging/a-fresh-instance-per-request`). A component cannot be re-entered,
so a second task of the same request calling the same extension waits until the first call returns.

Every call is a wasmtime **async** call. The request's coroutine polls the call's future on its own
core; a pending future parks the coroutine exactly as a socket wait does, and the waker is the core's
`RemoteWake`. wasmtime's own fiber holds the wasm frames and saves its thread-local call chain when
it suspends, which is what makes the composition sound where 0003's "it is the same mechanism" was
not enough.

A host import that waits — a file read on the blocking pool, an HTTP call through `Core`'s client —
returns a pending future, and the guest suspends with it. Computation suspends too: an epoch ticker
advances the engine's epoch about once a millisecond, and at every tick the guest's deadline callback
checks the request's CPU deadline. Past it, the call traps as a CPU limit; before it, the call yields
so the other tasks on that core run. A long encode slows its neighbours fairly and never freezes the
core, and a call pays no thread handoff.

The compiled module is shared by every core and cached in the artifact cache
(`rule:packaging/a-wasm-module-cache-reuses-the-artifact-cache`).

### 6. Failures: an error throws its class, a trap throws `ExtensionError`, a limit is `FATAL`

`nvs:ext/types` defines `variant error { invalid(string), parse(string), runtime(string) }`. An export
returning `err` throws `LogicError`, `ParseError` or `RuntimeError` with that message.

A **trap** that is not a limit — a panic, `unreachable`, an out-of-bounds access inside the guest's
own memory, invalid UTF-8 — throws **`ExtensionError`**, a new global class extending `RuntimeError`,
whose message names the extension, the export and the trap. The sandbox contains the trap, so host
state is intact; the instance is discarded, and the next call in the same request gets a fresh one.
A handler can answer a crafted upload that crashed a decoder with a `422`.

The request's CPU limit and memory limit reached inside a guest stay a resource-limit `FATAL`, which
reaches `onLimit` (`rule:errors/on-limit`) and is not a `Throwable`
(`rule:errors/throwable-hierarchy`).

### 7. Authority: an empty WASI, and grants that only intersect

Every component links WASI with an **empty context**: no preopened directory, no network, no
environment, no arguments. A toolchain that links WASI for its libc — wasi-sdk, TinyGo, Zig — gets a
working libc with no authority.

Two kinds of I/O can be granted, and no other:

- **Files** — `wasi:filesystem` preopens. Each root is a directory the effective `fs.read` set holds,
  opened read-only, or one the effective `fs.write` set holds, opened read-write. Paths are
  canonicalised and prefix-checked as every `Core\IO` door does
  (`rule:security/path-scope-canonicalise-then-prefix`).
- **Outbound HTTP** — `wasi:http`'s outgoing handler, implemented by `Core\Http\Client`, so the
  `net.connect` grant, the address policy, TLS trust and the outbound proxy apply exactly as they
  apply to Novis code. Raw sockets, listening, process spawn and every other WASI interface stay
  unlinked.

The **effective set** for a call is the intersection of three sets
(`rule:security/extension-grants-are-an-intersection`): what the operator grants on the extension's
own entry, what the manifest declares it needs, and what the calling code's namespace holds at the
call. Each only narrows:

```toml
[[extension]]
path   = "geo.nvsx"
sha256 = "…"
grants = { read = ["data/geo/"], connect = ["tiles.example.com"] }
```

An entry with no `grants` holds no I/O, whatever its manifest requests. An extension never acts with
more authority than the code that called it, and a request narrowed by an isolate stays narrowed
through the extension. The preopens are computed per instance, so they come from the request's own
configuration snapshot (`rule:security/capability-question-is-grant-and-scope`).

The qualifier rules are unchanged and enforced at the call site by the same code path as a `Core`
call (`rule:security/extension-manifest-only-tightens`). Bytes read through a granted file or a
granted HTTP call are tainted by contagion only when an argument was, so a manifest whose export
reads the outside world declares its return a source.

### 8. The compiler: a registration layer over the signature table

The signature table gains a layer the loaded set writes: each manifest's class becomes a
`ClassSignature` whose methods carry the manifest's parameter qualifiers through the same `MethodSig`
fields `Core` members use (`crates/nvs-types/src/core_lib.rs:135`), so `admits_tainted_argument` and
`tainted_result` read them with no extension-specific branch. Codegen emits a direct call to a
per-export trampoline that converts arguments by § 1's table; the set is in `env_hash`, so an
artifact never outlives the trampolines it calls (`rule:config/the-extension-set-is-in-every-unit-key`).
`nvs check`, `nvs test` and the language server read the manifests of the resolved configuration's
set and never instantiate a component.

### 9. Settings

A manifest may declare one settings block, `[ext.<name>]`, with each key's type (`bool`, `int`,
`uint`, `float`, `string`, a list of strings) and default. The block is a `System`/`Reload` block
in the configuration, an unknown key in it is refused at boot like any other, and the guest reads
it through `nvs:ext/settings`. A block that only narrows a cap the component enforces — as
`[image] max_pixels` does — is the pattern; a setting cannot grant anything, because § 7 is the only
place I/O is granted.

### 10. `nvs ext`, and a bundle

`nvs ext new --lang rust|c` writes a project that builds a component; `nvs ext build` takes the
author's built wasm module or component, componentizes it with `wit-component`, writes the manifest
from the project's `nvsx.toml`, embeds the Novis source, and checks the result loads;
`nvs ext inspect` prints the manifest, the requested I/O and, with `--source`, the source;
`nvs ext test` runs the project's `.nvs` tests with the built file loaded and no `nvs.toml`;
`nvs ext verify` runs every load check on a file; `nvs ext pin` prints its entry. Rust and C are the
two templates because they are the two languages the M9 components prove; `nvs ext build` takes a
module from any toolchain, so Zig and Go work by hand and get templates later.

`nvs build --compile` embeds each `.nvsx` the build's configuration lists, with its pin, and the
bundle loads them exactly as the entries would
(`rule:packaging/a-nvsx-dependency-embeds-in-the-same-payload`).

## Diagnostics

Every load refusal in §§ 3–4 is a configuration error carrying the entry's file and line, at boot and
at reload, with codes taken from the configuration band's next free numbers when they land. A
`secret` argument to an extension, a `tainted` argument to a parameter the manifest declares a sink,
and an extension class used with the set not loaded are compile errors. `ExtensionError` is a
runtime throw.

## Consequences

- **Authors write ordinary code.** A Rust author's export is `fn run(source: Source, plan: Plan) ->
  Result<Vec<u8>, Error>`; nothing reads a handle.
- **Copying is the cost of typed values.** A guest that needs one field of a large array still
  receives the array. Coarse APIs are the rule already (`rule:packaging/the-boundary-is-the-cost`),
  and `mixed` keeps the pull-only path for the case that needs it.
- **Performance:** an extension call stays about 11 ns plus the copy; an epoch tick costs a check per
  millisecond of guest time; a request's first call to an extension costs about 8–23 µs of
  instantiation. Nothing is paid by a request that calls no extension.
- **Memory:** a guest's linear memory is charged to the calling request as it grows and freed with
  the request — O(in-flight), under the request's own cap. The pooling allocator reserves address
  space per slot, not committed memory.
- **Simplicity:** one world, one table, one pin, and two kinds of I/O. Three additions an author
  meets: the manifest, `ExtensionError`, and the `grants` key.
- **The async bridge is the riskiest piece**, and goal `ext-design` proves it in `benches/abi-probe`
  before goal `ext-host` builds on it.

## Alternatives rejected

- **Handles for every value.** Nothing is copied that the guest does not read, but every author
  writes marshalling code and a record of ten fields costs ten crossings. Rejected for the author's
  sake and for the latency of the common, coarse call.
- **Typed values and handles at the author's choice.** Two ways to pass one argument.
- **Novis imports only, no WASI.** The smallest surface, but C, Go and Zig toolchains need a shim to
  build, which breaks the "any language" claim and the libwebp leg.
- **The caller's authority.** A malicious extension would hold everything the application holds.
- **The entry's grant alone.** A narrowed request would widen through the extension.
- **Raw sockets.** A WASI socket connects to an address, so a grant written as a host name needs the
  host to remember which addresses came from which lookups; it is a second copy of the outbound
  policy, and TLS becomes the guest's own code.
- **A compute pool for every call.** A thread handoff per call, separate CPU accounting, and a new
  knob, for computation the core can share fairly by yielding.
- **The source in a folder beside the `.nvsx`, or a minimal package system now.** The first leaves
  the source outside the pin; the second designs half of M15 before M15.
- **Signatures in M9.** Key formats, rotation and where a signature section sits are M15's subject.
- **A crash as `FATAL`.** A crafted upload that crashes a codec would end the request with no answer
  the application can write, though nothing in the host was harmed.

## Revisiting

Reopen § 5 if goal `ext-design`'s spike cannot poll a wasmtime async call from a Novis coroutine
soundly; the fallback is a guest call run on a pinned blocking-pool thread, at the cost of a handoff
per call. Reopen 0003's tier argument, not this record, if M9's committed benchmark puts in-guest
compute far below native for the image workload.

## Verification

- **`ext-design`:** the async spike in `benches/abi-probe` polls a guest call from a coroutine, parks
  on a host import, resumes, yields at an epoch tick while another coroutine on the thread runs wasm,
  and traps at a CPU deadline, with the thread-local call chain intact after each.
- **`ext-host`:** an entry without a pin, with a malformed pin and with a wrong digest each refuse,
  naming the line; a component importing an unoffered interface refuses, naming it; a guest's state
  is gone on the next request; an infinite loop stops at the request's CPU cap; a growing memory stops
  at the request's memory cap; a panic throws `ExtensionError` and the next call succeeds; an `err`
  throws its mapped class; two coroutines of one request calling one extension both finish.
- **`ext-compiler`:** a call with the wrong argument type does not compile; a tainted argument to a
  declared sink does not compile; a `secret` argument does not compile; the result of a call with a
  tainted argument is tainted; the source section's class resolves with no `autoload` line.
- **`ext-grants`:** a file read outside the intersection fails, each of the three narrowing the set in
  turn; an HTTP call to an ungranted host fails, and one to a private address fails under the address
  policy; a granted read and a granted call succeed.
- **`ext-tooling`:** both templates build, load and pass `nvs ext test` on all three platforms; a
  bundle carrying a `.nvsx` runs it.
