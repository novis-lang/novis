# ADR 0186 — An enum capture is spelled by a written backing value or else by its case name, an exporter brings no second registry, runtime or client, the drain is bounded by `[server] drain_timeout`, and `sendFile` takes the path alone

- **Scope:** the four calls M7's server surface reaches that no rule currently states — which text an
  enum capture matches on, what an exporter may take off the shelf, what bounds the drain, and
  `Core\Response::sendFile`'s parameter list. Not in scope: the trace push's own wire choices beyond the
  transport it may not bring, which is the export stage's; `Core\Metrics`'s member roster, which is
  `rule:observability/metrics-three-members`'s; the control endpoint's operations, which
  `rule:config/one-local-control-socket` already fixes.
- **Depends on:** [0004](0004.md) for the ordering all four are argued under; [0077](0077.md) and
  [0102](0102.md) for the closed set an enum capture narrows to; [0076](0076.md), which put the
  exporters behind crate names; [0088](0088.md) for the typed body members `sendFile` is one of.
- **Validated by:** the acceptance cases the routing, metrics-export and trace-push stages add — a
  segment that names an admitted case, one that names a value outside the subset and falls to `404`,
  a scrape served off the server's own accept loop, and a stop that finishes inside the bound.

> **In short:** an enum capture matches on its case's **written** backing value, and on the **case
> name** when the value was counted rather than written, because a counted value is an accident of
> declaration order that a later insertion silently repoints every URL through. Neither
> `metrics-exporter-prometheus` nor `opentelemetry-otlp` can be taken: the first is separable from a
> transport but not from a second metrics registry, and the second cannot be reached at all without
> either a second HTTP client or `opentelemetry_sdk`'s executor. What may be taken is a crate that is
> only an encoder. The drain gets `[server] drain_timeout`, `"30s"` with nothing configured, because
> `rule:concurrency/a-drain-closes-a-connection-cleanly` names a period that nothing sets. And
> `sendFile` takes the path alone.

## Context

M7's remaining surface reaches four questions that every rule currently declines to answer, each one
small enough that a record of its own would be four records arguing the same ordering.

`rule:routing/a-capture-narrows-to-a-closed-set` admits a subset of an enum's cases as a capture type
and then stops: its last sentence records that the conversion is not done at match time "because a
case's segment spelling is still undecided". Everything downstream waits on that sentence — the match
itself, `Core\Router::url`'s link for every member of the set, and the generated document's
`enum: [...]`, which cannot be emitted without knowing what it lists.

`rule:observability/the-exporters-are-crates` names three crates and calls the OTLP and Prometheus
paths "taken as dependencies". It was written from the shape of the problem — a wire format is
somebody else's specification — rather than from the crates' manifests, and no session had opened
them.

`rule:concurrency/a-drain-closes-a-connection-cleanly` says a connection is closed "after a drain
period" and that the period starts when the connection first sees the drain. Nothing in
`crates/nvs-config/src/default.toml`'s `[server]` block (lines 379-416) sets that period, and
`crates/nvs-runtime/src/drain.rs` holds a bit and no duration, so the period is currently unbounded —
which `rule:http-server/an-unsafe-or-unbounded-default-is-a-defect` refuses.

`docs/spec/01-core-library.md` § 15 lists the body member as `sendFile(…)`, the one member of the seven
whose parameters were never written down.

## Investigation

**The two exporter crates, read from their published manifests** (crates.io metadata for
`metrics-exporter-prometheus` 0.18.3 and `opentelemetry-otlp` 0.32.0; neither crate is in `Cargo.lock`
and neither is in this machine's registry cache, so the manifests were fetched rather than read from
disk).

`metrics-exporter-prometheus`'s default feature set is `["http-listener", "push-gateway"]`, and between
them they pull `tokio` with `rt`, `net`, `time` and `rt-multi-thread`; `hyper` with `server` *and*
`client`; `hyper-util` with `tokio`, `client-legacy` and `http1`; and `hyper-rustls` with the
`aws-lc-rs` provider. Each of those is a thing this workspace already has exactly one of and has
argued for: the root `Cargo.toml:130-132` records that `tokio` is in the lock file with `sync` alone
because `hyper` 1.11 needs one `oneshot`, and is not a runtime; `hyper` is taken at
`Cargo.toml:147` as `default-features = false, features = ["http1", "server"]`; the TLS provider is
fixed at `Cargo.toml:233`.

With `default-features = false` that all goes away, and what is left is the required set: `base64`,
`evmap`, `indexmap`, `metrics` ^0.24.5, `metrics-util` ^0.20 with `recency`, `registry` and `storage`,
`quanta`, `thiserror`. No runtime and no transport — so the crate passes the test the goal set. It
fails a different one. `metrics` plus `metrics-util`'s `registry` and `storage` **is** a metrics
registry, with its own recency policy and its own clock in `quanta`, and the renderer renders *that*
registry. This workspace already has one, per core, at `crates/nvs-server/src/metrics.rs`, fixed by
`rule:observability/a-registry-is-per-core-and-nothing-reads-it` and bounded by
`rule:observability/past-max-series-a-new-series-is-refused`. Taking the crate means either keeping two
registries and copying between them at every scrape, or replacing ours — and ours is the one the
per-core merge and the `max_series` refusal are written against.

`opentelemetry-otlp` fails earlier. Its default set is
`["http-proto", "reqwest-blocking-client", "trace", "metrics", "logs", "internal-logs"]`, and
`reqwest` is a second HTTP client with its own TLS stack. Every other transport feature is also a
client: `grpc-tonic` is `tonic` plus `tokio`, `hyper-client` is `opentelemetry-http/hyper` with
`hyper`'s client half, and the `reqwest-*` family is `reqwest` again. Turning all of them off does not
leave an encoder, because `opentelemetry_sdk` is a **required** dependency — not optional — and it
requires `futures-channel`, `futures-executor`, `futures-util` and `portable-atomic`. `futures-executor`
is an executor. `opentelemetry-proto`, the crate that is genuinely only the generated message types,
requires `opentelemetry_sdk` too, so there is no door into the OTLP encoding through this family that
does not open on somebody else's execution model.

What *does* pass both tests is a protobuf encoder. `prost` with no default features is code generation
and byte encoding: no runtime, no socket, no TLS. It is not in `Cargo.lock` today, and taking it is the
export stage's call under the predicate this record sets, not this record's.

**The drain's arithmetic.** `[server]`'s four waits are each idle rather than total and each finite
with nothing configured — `header_timeout` 10s, `body_idle_timeout` 30s, `write_idle_timeout` 30s,
`keepalive_timeout` 60s (`crates/nvs-config/src/default.toml:411-416`). If a drain merely set a bit and
left each connection to notice it at its own next wait, a connection parked in a keep-alive idle wait
would not see it for 60s and would then be given the whole drain period on top. The generated unit sets
no `TimeoutStopSec` (`crates/nvs-cli/src/service.rs:503-512`), so systemd's default — 90s unless the
distribution lowered it — is what would `SIGKILL` the process, and a 60s notice plus any drain period
at all runs into it.

**`sendFile`.** `rule:security/response-body-is-one-typed-member` already classifies the file member's
path as a sink, and `setHeader` already admits `Content-Disposition`, so the only open question was
whether a second parameter carried a filename or a media type. Both already have homes: the disposition
is a header, and the media type is the static-file policy's table.

## Options considered

For the enum capture: the case name always; the backing value always; the written value where there is
one and the case name otherwise; a per-enum attribute naming the spelling.

For the exporters: take both crates as `rule:observability/the-exporters-are-crates` reads today; take
`metrics-exporter-prometheus` with `default-features = false` and write the OTLP half; write both
formats and take a crate only for an encoder; write both formats and take nothing.

For the drain: a fixed constant in `nvs-server`; a new `[server] drain_timeout`; reuse
`keepalive_timeout` as the period.

## Decision

### 1. An enum capture matches on a written backing value, and on the case name when the value was counted

A Novis enum is backed by exactly one integer type and nothing else (`rule:enums/one-backing-type`), so
PHP's split between a backed enum and a pure one has no spelling here — every case has an integer. What
it maps to is whether that integer was **written**:

- If every case in the capture's admitted subset has its value written in the enum body, the segment is
  that integer, parsed as the enum's backing type.
- If any admitted case's value was counted on from the one before it
  (`rule:enums/declaration`), the whole subset is spelled by **case name**, compared byte for byte and
  case-sensitively, as a literal segment already is (`rule:classes/names-resolve-case-sensitively`).

The rule is per subset rather than per case because a subset that mixed the two would put an integer
and a name in the same position, and a case named `7` — legal, since a case name is an identifier and
nothing stops one that looks like a number — would then be two admitted values at once.

Written-versus-counted is the line because a counted value is not an identifier. `enum Status { Active,
Banned }` gives `Active` the value `0` because it is written first, and inserting `Draft` ahead of it
repoints `/0` from `Active` to `Draft` — a silently changed meaning for every link already in the
world, from an edit that looks local. A written value was chosen, and the author who writes
`Active = 1` is stating a number they intend to keep. This is priority 2 read as what a URL means
rather than as what PHP does, and priority 4 declines the alternative: an attribute naming the spelling
is a third place the same fact could be written, which is the objection
`rule:routing/path-grammar` already makes to the inline `{id:uint}` form.

Two cases may carry the same value (`rule:enums/declaration`), and a subset admitting two of them under
the written-value spelling has no single answer for what `/1` converts to. That is a **compile error**
naming both cases, not a silent first-wins — `rule:errors/ambiguous-input-refused`'s direction. Under
the case-name spelling an alias is fine, because the names are still distinct.

A segment naming no admitted case is not a match, and falls through to a `404` by
`rule:security/route-capture-is-laundered-by-its-type`, exactly as a failed `int` conversion does. The
same spelling is what `Core\Router::url` writes into a link and refuses outside the set
(`rule:routing/link-name-and-params-are-checked`), what the generated document lists in `enum: [...]`,
and what a `#[Query]` parameter of the same type matches on
(`rule:routing/a-query-parameter-is-declared-like-a-capture`) — one spelling in every position, so a
route and its link and its document cannot disagree.

### 2. An exporter brings no second registry, no second scheduler and no second client

A crate is taken for a half that needs none of those — an encoder — and never for a half that carries
its own execution or its own socket. Concretely, under § *Investigation*'s reading:

- **The Prometheus exposition format is written here.** It is a line-oriented text format over series
  this process already holds, and the crate that renders it renders its own registry rather than ours.
- **The OTLP encoding is written here**, against the specification, from a protobuf encoder if one is
  taken. `opentelemetry-otlp` is not takeable at all without an executor or a client.
- **The scrape endpoint is this server's own accept loop**, on the listener `[metrics] listen` names —
  one more listening socket driven by the same loop as every other, never a second HTTP server.
- **A push goes out over `nvs-host`'s parking stream and the one TLS client this workspace has**,
  under `Core\Http\Client`'s own bounds, never over a client a telemetry crate brought.

`rule:observability/the-exporters-are-crates` keeps what it got right — these are somebody else's
specification, and the wiring and the registry are ours — and loses the claim that the paths are taken
as dependencies, which its own crates' manifests do not support.

The ordering: this is priority 4 and priority 1 both, and they agree. A second scheduler in a
thread-per-core runtime is the objection `rule:concurrency/one-scheduler` already makes; a second TLS
provider is a second set of certificate-verification defaults to keep in step, and `aws-lc-rs` is also
a C dependency, which `rule:packaging/a-c-dependency-answers-two-questions` prices separately. What it
costs is that two wire formats are ours to keep correct as they version, which is the trade this
record makes deliberately and § *Revisiting* is the condition for reopening.

### 3. The drain is bounded by `[server] drain_timeout`, `"30s"` with nothing configured

`[server] drain_timeout` joins the four waits, spelled the same way — a bare number is seconds, so
`"30s"` and `30` are the same period — and is `Boot`-class with the rest of the block
(`rule:http-server/the-server-block-is-boot-class`). Nothing configured is `"30s"`, never unbounded and
never zero.

The drain **wakes** every parked wait rather than leaving a connection to discover it when its own idle
timer expires. Without that, the bound composes with `keepalive_timeout` and the stop takes 60s before
the drain period even starts; with it, a stopping process is bounded by `drain_timeout` plus the write
of whatever response was in flight, which `write_idle_timeout` already bounds. That keeps the worst
case at 60s against systemd's 90s default, with room for a distribution that lowered it. Waking a
parked connection is not closing it from outside: the close is still the connection's own, taken at its
next wait, which is `rule:concurrency/a-drain-closes-a-connection-cleanly`'s requirement and the reason
a dropped descriptor is not an option.

Reusing `keepalive_timeout` was rejected: it is an idle bound on a connection that is doing nothing,
and a drain bound is a ceiling on connections that are doing something. One directive answering both
means an operator who lengthens keep-alive lengthens every restart.

### 4. `Core\Response::sendFile(string $path)`

The path alone, and it is a `Qual::Sink` (`rule:security/response-body-is-one-typed-member`). No
filename parameter — a download name is `Content-Disposition`, which `setHeader` already admits — and
no content-type parameter, because the static-file policy's media-type table is the one home for what a
path's bytes are called, and a second spelling would let a response declare one type while the policy's
`Range` and conditional handling served another. `rule:core-api/verb-lexicon` admits `sendFile`: the
verb is `send`, and the member is the one of the seven whose body is a file.

## Diagnostics

One new code, in the band the route diagnostics continue into
(`crates/nvs-diagnostics/src/lib.rs:2742-2767` is where their `E07xx` run sits, and that band is full
at `E0799`):

- **`E0819`** — an enum capture's admitted subset contains two cases that share a backing value, under
  the written-value spelling. The message names the capture, both cases and the value, and the fix is
  to admit one of them or to give them distinct values.

A subset that mixes written and counted values needs no diagnostic: it is well-formed and spells by
case name, which § 1 decides rather than refuses.

## Consequences

- `Core\Router::url` can build a link for an enum capture, and `nvs build --openapi` can emit its
  `enum: [...]`, both of which were blocked on this spelling.
- Inserting a case ahead of a counted one still changes that case's integer, and under the case-name
  spelling no URL moves. Under the written-value spelling nothing moves either, because the values are
  written. There is no arrangement left in which a URL changes silently.
- `[metrics] endpoint` and `[trace] endpoint` are commented in
  `crates/nvs-config/src/default.toml:727-740` as `http://127.0.0.1:4317`, which is OTLP's **gRPC**
  port. A push over this workspace's one HTTP/1.1 client is OTLP/HTTP with a protobuf body, whose
  collector port is 4318, so those two comment lines change when the push lands.
- The Prometheus text format and the OTLP protobuf schema are ours to track across their versions.
  Both are versioned specifications with stability guarantees, which is why they were worth taking as
  specifications rather than as crates.
- A stop is bounded at `drain_timeout` plus one response write. An operator whose requests legitimately
  run longer than 30s raises the directive rather than discovering a `SIGKILL`.
- `sendFile` holds one open file handle and one chunk buffer per response in flight, which is
  O(in-flight) and is what the goal's § *Standing decisions* already books against priority 5.

## Alternatives rejected

- **The case name always.** Simple, but it makes a written backing value decorative — an author who
  wrote `Active = 1` to pin a public number gets `Active` in the URL anyway — and it puts an
  identifier from the source into the URL surface whether or not the author meant it to be public.
- **The backing value always.** Every counted value is then a public identifier that an insertion
  moves, which is § 1's whole objection.
- **An attribute naming the spelling per enum.** A third place the fact can be written, disagreeing
  with the other two, which is the objection `rule:routing/path-grammar` makes to `{id:uint}`.
- **Taking `metrics-exporter-prometheus` with `default-features = false`.** It passes the runtime and
  transport test and fails on the registry: keeping two means copying every series at every scrape,
  and replacing ours means rewriting the per-core merge and the `max_series` refusal against a crate's
  policy instead of the rule's.
- **Taking `opentelemetry-otlp` with every transport feature off.** Not available: `opentelemetry_sdk`
  is a required dependency and brings `futures-executor`.
- **A fixed drain constant in `nvs-server`.** Bounded, but an operator cannot raise it for a
  deployment whose requests are legitimately long, and the answer to that would be a directive.

## Revisiting

The exporter half is reopened if either crate publishes a release whose encoder is separable — a
`metrics-exporter-prometheus` that renders a caller's own series, or an `opentelemetry-otlp` whose
message types do not require `opentelemetry_sdk`. Read the manifests again before concluding either
way; this record's reading is of `metrics-exporter-prometheus` 0.18.3 and `opentelemetry-otlp` 0.32.0.

The drain's default is reopened by a deployment that is `SIGKILL`ed inside it, which would mean the
wake is not reaching some parked wait — a defect rather than a tuning question.

## Verification

- A route whose capture admits a subset of an enum with written values matches the integer and not the
  name; one whose subset has a counted value matches the name and not the integer; a segment outside
  the subset is a `404` and not a `400`.
- Two admitted cases sharing a value under the written-value spelling is `E0819`, and the same two
  cases under the case-name spelling compile.
- `Core\Router::url` round-trips every member of the set through the route it names, in both
  spellings.
- A scrape of `[metrics] listen` is answered while the server is serving requests, and `Cargo.lock`
  contains no crate that brings an executor, an HTTP client or a TLS provider this workspace did not
  already have.
- A stop under load finishes inside `drain_timeout` plus one response write, with a connection parked
  in a keep-alive wait closing cleanly rather than after `keepalive_timeout`.
