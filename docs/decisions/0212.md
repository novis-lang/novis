# ADR 0212 — `Core\Program::implementingWith<I, T>($member)` joins the enumeration with one attribute per class

- **Scope:** one compiler-owned member joining `rule:programs/implementing`'s enumeration with
  `rule:attributes/structural-retrieval`'s retrieval. What a retrieval target may be, and what the
  enumeration answers, are unchanged and stay with their own records.
- **Depends on:** [0061](0061.md), [0046](0046.md).
- **Validated by:** the four cases and the checker test the rule's `guardedBy` names.

> **In short:** a framework enumerates its pages with `implementing<View>()` and routes them with
> `#[Core\Route]`, and it could not read the route back off the classes it enumerated: a retrieval
> names its target where it is written, and inside the loop the variable is the interface. So every
> page wrote its path twice, once in the attribute and once in a method, with nothing to check the
> two. `implementingWith<I, T>($member)` expands to the same array with each class's one matching
> attribute beside its instance, as `array<{instance: I, attribute: ?T}>`, folded per class by the
> retrieval the compiler already runs. Letting a retrieval take an instance was impossible, a route
> listing would answer routes only, and an interface requiring an attribute would have checked the
> duplication rather than removed it.

## Context

### 1. Enumerate, or read attributes, not both

`Core\Program::implementing<I>()` expands to `new C()` per implementing class, typed as `I`.
`Core\Attributes::get<T>(C::m(...))` folds to the one payload satisfying `T`, and its target is read
syntactically. A framework that has both cannot compose them: inside `foreach
(implementing<View>() as View $v)` there is no class name to write, and `$v->render(...)` is
`E0730`. The framework's page therefore carried its path in the attribute for the server and again
in a method for the dispatcher, and tested the two against each other behaviourally.

### 2. Both lists exist at one moment in the checker

The expansion is a list of classes with their constructors, recorded against the call. The
retrieval is a fold over the attach sites of one class's member. The checker holds the class list
and the attach table at the same time, so joining them is one fold per class and nothing new about
either.

## Options considered

### 3. A retrieval taking an instance

`Core\Attributes::get<T>($view, 'render')`, accepted when the receiver's static type is one of the
enumerated classes. Inside the loop it is not: the variable is typed as the interface, so no call
site of that shape could ever be accepted.

### 4. A sibling of the enumeration

`implementingWith<I, T>($member)` answering `array<{instance: I, attribute: ?T}>`. One expansion,
one row shape, the compiler doing the join it is positioned to do. It generalizes past routes to
every attribute a framework reads off classes it discovered.

### 5. A route listing

`Core\Router::routes()` answering the compiled rows would remove the duplication for routes alone,
with a new class and several members for it, and leave every other attribute where it was.

### 6. An interface requiring an attribute

The compiler would check that every implementor's method carries the attribute, and the path
would still be written twice.

## Decision

### 7. The sibling

Option 4. The member name is the reporter's; `$member` addresses a class's own declaration the
way the retrieval's `$target` plus `$member` does, collapsed to one string: the class itself for
an empty name, a method for a method name, a property or constructor parameter otherwise. The
row is a shape rather than a pair of parallel arrays because the loop body reads one class's two
facts together.

### 8. The registry row spells a shape a helper never answers

`a_shape_is_only_ever_a_whole_parameter` refuses a shape in a return type because no helper has a
runtime representation to answer with. This row is expanded by the checker, which builds each row
itself and answers the call's type from the two written arguments, so the row spells the shape
for the one reason a return type is written there: the card, `nvs meta` and `nvs agent` print
what the call answers. The guard exempts the one member and says so.

## Diagnostics

### 9. The retrieval's, naming the class

`E0798` for a `$member` some implementor does not declare, `E0728` for two matches on one class,
`E0729` for a `T` that is not a shape, each naming the class the fold was made on; the
enumeration's `E0743` and `E0744` unchanged.

## Consequences

### 10. Cost

The same allocations `implementing` makes plus one row object per class and one payload object
per matched attribute, where the call stands, per evaluation. Nothing runs that did not run before;
the join is paid while checking.

## Alternatives rejected

### 11. A route listing

Option 5, for routes only; the reporter's side complaint that nothing lists a program's routes
outside a request is left open and is a routing question.

## Verification

### 12. Guards

Two accept cases: the join in the enumeration's order with `null` where nothing matches, and the
empty name and a property name selecting the class's and the constructor's rosters. Two reject
cases: a member no implementor declares, and two matches on one class. The checker test pins the
recorded entry's payload per class.
