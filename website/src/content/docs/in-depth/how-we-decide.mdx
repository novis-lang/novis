Most design questions have two good answers. Novis chooses with four priorities. They are always
used in the same order. Novis gives up a lower priority to get a higher one. It never gives up a higher priority to get
a lower one.

1. **Security, and requests that cannot affect each other.** Novis never gives this up for any other priority.
2. **Speed of each request.** A request starts fast and finishes fast.
3. **Simplicity.** The language you write must be simple. After that, the code of Novis itself.
4. **Low memory use.** This comes last.

What a program does is not one of the priorities. The language rules say what it does, and tests
check every rule.

## What the order means for you

A check that keeps your server safe stays on, even when it costs a little speed. An example is the
check on [tainted input](/in-depth/concepts/tainted-input/).

Novis chooses a faster design over a simpler one. Novis compiles your code to machine code for this reason,
although an interpreter would be simpler to build.

Novis chooses a simpler language over one that uses less memory. When you change an array, Novis changes a
copy if another variable still uses it. So a change to one variable never changes another variable. The
copy uses memory.

## Memory use is allowed, and it is still limited

Memory is last, but it is never unlimited. Every request has a memory limit that you set. The
memory a server uses grows with the requests it runs at the same time. It does not grow with the
number of requests it has served in total. Growth of that kind is a bug.
