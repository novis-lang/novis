These pages explain why Novis works the way it does. You do not need them to write Novis code.
Read them when you want to know the reasons behind a design.

Each page is about one question:

- [What Novis is for](/in-depth/what-for/): the programs Novis is made to run.
- [What Novis will never be](/in-depth/never/): the things Novis does not do, and will not add.
- [How we decide](/in-depth/how-we-decide/): the four priorities, in the order we use them.
- [How Novis is written](/in-depth/how-novis-is-written/): how coding agents write Novis, and the rules and tests that check their work.
- [Design principles](/in-depth/design-principles/): four ideas that are in every part of the language.
- [Concepts](/in-depth/concepts/): six ideas explained one at a time, such as tainted input and limits.
- [Where Novis is weaker](/in-depth/falls-behind/): the costs of these choices, stated plainly.
- [Novis, PHP, Bun and Go compared](/in-depth/compare/): the same programs in four languages, measured on one machine.
- [All questions](/in-depth/questions/): every question the search knows, with the page that has the answer.
- [Roadmap](/in-depth/roadmap/): what is built, and what comes next.
- [What changed](/in-depth/what-changed/): the changes in each release of Novis.

Some pages link to a rule on GitHub. A rule gives the full reasoning behind one design choice. It is
written for people who work on Novis, so it uses more technical words.
