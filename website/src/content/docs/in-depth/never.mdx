Some features make a language easier for one program and less safe for every other program. Novis
leaves these features out. This page lists them, so you know before you start.

## A way to load native code

Your program cannot load a C library into the running process. One bad write in native code can
damage the memory of every request on the server. One crash in native code stops all of them.

Extensions will run as sandboxed WebAssembly. An extension has its own memory, and it
reaches only what you allow. <a href={decisionRecord('0003')}>Read the full reasoning.</a>

## Global state

Novis has no global variables and no `global` keyword. There is no global time zone and no global
locale. A function that needs a time zone or a language gets it as an argument.

With global state, one part of a program can change the result of another part. Nothing in the code
shows this. On a
server, it can also carry a value from one request into the next.
<a href={decisionRecord('0012')}>Read the full reasoning.</a>

## PHP that runs unchanged

Novis does not run PHP files. Its syntax is close, but it removes the parts that cause bugs, such
as the `(int)` cast. A Novis program uses `as int` for that, and the
conversion is checked. [Start here](/syntax/start-here/) lists the differences.

## A runtime that uses as little memory as possible

Novis uses memory to make requests safe and fast. Each request has its own memory, and compiled
code stays in memory. A Novis server can use more memory than a server written in another language. Every
request still has a memory limit that you set. <a href={decisionRecord('0004')}>Read the full reasoning.</a>

## A language with many ways to do one thing

Novis gives each job one way to write it. There is one way to convert a value, one way to query a
database and one way to receive an uploaded file. A second way would mean a second thing to learn,
test and keep safe.
