Some objects stop being valid while the program runs. A row that was deleted from the database is
one example. A class that implements `Revocable` can mark such an object as revoked. After that,
the program cannot use the object by mistake.

<FeatureSection examples="lang/classes/revocable-objects" heading="Revocable objects" id="revocable-objects" />

## What happens after revoke()

| You write | The result |
|---|---|
| `$post->revoke()` | the object is removed from every `Core\ObjectMap`, `Core\ObjectSet` and `Core\Heap` |
| `$post->isRevoked()` | `true` |
| `$post->title`, `$post->title = 'x'` | throws `RevokedObjectError` |
| `$post->publish()` | throws `RevokedObjectError` |
| `clone $post`, `Core\Json::encode($post)` | throws `RevokedObjectError` |
| `$post == $other`, `$post is Post`, `$post::class` | works as before, no error |
| `$post->revoke()` again | nothing happens |

A plain array, a property or a variable still contains the object. Only the three `Core`
collections remove it. `RevokedObjectError` is a `LogicError`. The page
[Error types](/syntax/errors/error-types/) lists it with the other error classes.

## Do and don't

- Do write `implements Revocable` on the class with no parent class. Its subclasses get it too.
- Do keep objects that can be deleted in a `Core\ObjectMap` or a `Core\ObjectSet`, so a deleted one
  leaves at once.
- Do call `isRevoked()` when an object may already be revoked. It never throws.
- Don't declare `revoke()` or `isRevoked()` in your class. `Revocable` provides both.
- Don't expect a plain array to remove a revoked object. Remove it yourself, or use a `Core` collection.
