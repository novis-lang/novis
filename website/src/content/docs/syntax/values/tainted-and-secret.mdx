`tainted` and `secret` are words you write before `string` or `bytes`. The compiler checks them. They do
not make the program slower.

`tainted` means the value comes from outside the program, such as a form or a command-line argument.

<Snippet src="syntax/tainted-and-secret/01-tainted.nvs" />

- A string built from a tainted string is tainted too. That includes `.`, interpolation and methods
  such as `Core\Str::upper`.
- A method that returns a count or a `bool`, such as `Core\Str::length`, returns a plain value.
- A tainted string cannot be a pattern or a template, such as the pattern of `Core\Regex::compile`.
- `as int`, `as float`, `as bool` and `as` an enum give a plain value.
- `string $plain = $input;` does not compile when `$input` is tainted.

## Use this when a value must never be printed

`secret` is for passwords, tokens and keys.

<Snippet src="syntax/tainted-and-secret/02-secret.nvs" />

These do not compile with a secret value: `echo`, the message of an error, `Core\Debug::dump`,
`Core\Json::encode`, and every `Core` parameter of type `string`.

`Core\Secret::reveal` is the only method that gives a plain string. A value that was also tainted
stays tainted.

## Do and don't

- Do declare request input as `tainted string`.
- Do convert tainted input with `as int` or an enum when you can.
- Do declare passwords and API tokens as `secret string`.
- Don't call `Core\Secret::reveal` only to print a value. Write a reason that says why it must be
  shown.
