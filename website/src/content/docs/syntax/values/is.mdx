`$value is Cat` is `true` when `$value` is a `Cat` object. Inside the branch where the test is true,
the variable has the type `Cat`.

<Snippet src="syntax/is/01-is.nvs" />

The new type applies only inside the branch. After `if ($pet is Cat) { return ...; }`, `$pet` is still
a `Dog|Cat`, so the last line converts it with `as Dog`.

These tests change the type in the same way:

- `$x == null` and `$x != null` on a `?T`
- `$x == "read"` on a type that lists exact values, and `$x == Mode::Read` on an enum
- the right side of `&&` and `||`, and the two sides of `? :`
- both tests of `if (A && B)`, inside its block
- both tests of `if ($a == null || $b == null) { return; }`, in the code after it. There, `$a` and
  `$b` are not `null`.

## Use this when there are many types to test

`match (true)` runs the first arm whose test is true. Inside each arm, the variable has the type that the arm's test checked.

<Snippet src="syntax/is/02-match-true.nvs" />

To test whether a `mixed` value is a number, convert it: `($value as ?int) != null`. There is no
`is int`.

If you assign a new value to the variable inside the branch, the variable has its declared type again.

## Do and don't

- Do test with `is` before you call a method that only one class has.
- Do use `match (true)` for three or more tests.
- Don't convert with `as Cat` when the value may be another class. `as` throws an error then.
