A route connects a URL path and an HTTP method to a method of your class. You declare it with
`#[Core\Route]`. Every route also needs `#[Core\Access]`, which says who may use it. The compiler
collects all routes of the program into one table. `Core\Router` reads that table.

<FeatureSection examples="lang/attributes/core-route-and-core-access-the-route-table" heading="Core\Route and Core\Access" id="core-route-and-core-access" />

A few facts the examples do not show:

- `Core\Router::urlAbsolute` puts the origin in front, such as `https://example.com`. The origin is
  the `origin` setting under `[[app]]` in `nvs.toml`.
- `Post`, `Put`, `Patch` and `Delete` requests are checked for CSRF (a request sent from another
  site). A `Get` request that opens a WebSocket from another site is not allowed.
- `csrf: false` turns both checks off for one method. You write it in `#[Core\Access]`, as in
  `#[Core\Access(allow: Core\Audience::Public, csrf: false)]`. On `#[Core\Route]`, it does not compile.
- Use `csrf: false` only on a route that does not use the session cookie. A webhook that another
  server signs is one example. Without the check, another site can send a form with your visitor's
  cookie. The [webhook example](/reference/types/audience/) shows such a route.

## Handling a request

`nvs serve` finds the route for each request before your program runs. `Core\Router::dispatch`
then calls the method of that route. You give `dispatch` a gate. A gate is an object of your own
class that implements `Core\Router\Gate`.

<Snippet src="syntax/routes/02-dispatch.nvs" />

- `failed` also runs when the program uses too much memory or time. The status is `500`.
- A capture or a `#[Core\Query]` value that cannot be converted gives `Refusal::BadCapture` and the
  status `400`. A missing required query key and a repeated one give the same.
- A route method is `static`, or its class has a constructor without parameters.
- A route method can return a value, such as its page. When the gate implements
  `Core\Router\Responder`, `dispatch` gives that value to the gate's `respond` method. A plain gate
  does not use the value, and `nvs check` gives a warning for it.
- A request that the server stopped, for example in the CSRF check, never reaches a route method.
  `dispatch` calls `refused` for it.

The [reference page of `Core\Router::dispatch`](/reference/core/router/dispatch/) has more examples.

When you call the route method yourself, `Core\Router::match` returns `null` for a path no route
has. `Core\Router::methodsFor($path)` returns the methods the path has. An empty array means `404`,
and any other array means `405`. The server does not check `accessAs`. Your program checks it
before it calls the method. Without `dispatch`, the CSRF check is the only check that runs for you.

The examples above do not print the document. This file is one more route with `#[Core\Api]`:

<Snippet src="syntax/routes/04-api.nvs" />

For this file, `nvs build --openapi main.nvs` prints a document with this operation:

```json
"/users/{id}": {
  "get": {
    "description": "Looks the user up by id.",
    "operationId": "Users::show",
    "parameters": [
      {"in": "path", "name": "id", "required": true, "schema": {"minimum": 0, "type": "integer"}}
    ],
    "responses": {
      "200": {"content": {"application/json": {"schema": {"type": "string"}}}, "description": "success"}
    },
    "summary": "Show one user.",
    "tags": ["users"]
  }
}
```

More facts about the document:

- Each name in `security:` needs a `#[Core\Api\Scheme]` on a class of your program, such as
  `#[Core\Api\Scheme(name: "bearer", type: Core\Api\SchemeType::Http, scheme: "bearer")]`.
  The document lists each scheme under `components.securitySchemes`. A name that no scheme declares
  does not compile.
- When the method returns a class with `#[Core\Json\Derive]`, the response schema lists the JSON
  fields of that class.
- When the method reads the body with `Core\Request::jsonAs<T>()` or `Core\Request::postAs<T>()`,
  the document describes that body with the schema of `T`. The call must be in the route method
  itself. A body that another method reads is not in the document.

## Do and don't

- Do give every route a `name:`, and build links with `Core\Router::url`.
- Do check `accessAs` once, before the `switch` that calls the methods.
- Do give a capture the type you need, such as `uint`. The conversion is then done for you.
- Don't write a path by hand in a link. A typo in a route name does not compile.
- Don't use `csrf: false` on a form that a browser sends.
