A test double replaces a real object in a test. Your code calls the double, and the double returns
the values you chose. The test then runs without a mail server, a network or a database.

## A double for an interface

`Core\Test::double` builds an object for an interface. You give an anonymous function for each method:

<Snippet src="guides/testing/test-doubles/test-doubles.nvs" />

`Core\Test::assertCalled` checks that a method was called, how many times, and with which
arguments. `Core\Test::assertNeverCalled` checks that a method was not called at all.

Your class must take the interface as a parameter for this to work. A class that creates its own
mailer inside a method cannot get a double.

## Other doubles

- `Core\Test::partial` wraps a real object and replaces only some of its methods.
- `Core\Test::answerHttp` gives a fixed response for a URL. `Core\Http\Client` then gets this
  response and sends nothing over the network. `Core\Test::sentHttp` lists the requests your code
  sent.

## The clock

A test with `#[Test(at: "2026-03-01T09:00:00Z")]` runs with the clock fixed at that time.
`Core\Time::now()` returns that time. `Core\Test::advance(1h)` moves the clock one hour forward.

Under `at:`, `Core\Time::sleep` does not wait. `Core\Time::sleep(1h)` ends at once, and the clock
is then one hour later. When two tasks sleep, the one with the shorter sleep wakes first. A timeout
of `Core\Task::all` uses the same clock. So a test of a retry, a wait or a timeout takes
microseconds.

The clock also ends a cache entry of `Core\Cache::memory` when its time to live has passed, and
makes a delayed queue job due. A test without `at:` uses the real clock, and a sleep really waits.

## Mail and logs

Under `nvs test`, `Core\Mail::send` sends nothing and opens no connection. It still checks the
addresses and the `[mail]` settings. `Core\Test::sentMail` returns the messages your code sent in
this test, in the order sent. Each one is a `Core\Test\SentMail` with `to()`, `subject()`, `text()`
and the other fields.

`Core\Test::logs` returns the log records written in this test. Each one is a
`Core\Test\LogRecord` with `level()`, `message()` and `fields()`. A record below the `[log] level`
setting is not written, so it is not in the list.

Both lists contain what the test wrote, and what each request and each run it started wrote. Each
test starts with two empty lists.

## Do and don't

- Do give a class its services as parameters, so a test can pass a double.
- Do check the calls that matter, such as the address a mail was sent to.
- Don't replace the class you are testing. Replace only what it talks to.

Read every method in [Reference: Core\Test](/reference/core/test/).
