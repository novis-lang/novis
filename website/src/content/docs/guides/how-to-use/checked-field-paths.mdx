`orderBy("customer.email")` names class properties in a string. A property is a variable that
belongs to a class, also called a field. In Novis, the editor completes these names, and a typo gets
a red underline.

This works because the string has its own type. `propertyPath<Order>` is a path of property names of
`Order`. A string with holes, `string<propertyPath<Order>>`, can have several paths in one
condition, such as `"{total} > ? AND {customer.city} = ?"`.

Your code can split these strings. `Core\Str::parts` gives the text and the holes of a condition.
`Core\Reflect::steps` gives one property for each name of a path. So you can build a query builder,
an ORM or any other library that takes class property names.

This page builds a small data mapper in six steps. Each step adds one thing, and each program runs.
The mapper writes SQL text. It does not connect to a database.

## One property

<Snippet src="guides/how-to-use/data-mapper/01-one-field.nvs" />

The parameter type `property<Order>` accepts the name of one public property of `Order`. The
compiler checks the string `"total"` in the call. If you write `"totl"`, the program does not
compile.

## A path

<Snippet src="guides/how-to-use/data-mapper/02-a-path.nvs" />

`propertyPath<Order>` accepts names joined with dots. `customer` is a `?Customer`, so the next name
is a property of `Customer`. A path can also go through an array of objects, such as
`array<Line>`.

The editor shows the names you can use. After the `"`, it lists the five properties of `Order`.
Each letter you type keeps only the names that match. After each `.`, it lists the properties of
the class the path has reached, here the four properties of `Customer`:

## A condition

<Snippet src="guides/how-to-use/data-mapper/03-a-condition.nvs" />

`string<propertyPath<Order>>` is a string with holes. Each `{...}` is a property path of `Order`,
and the compiler checks it. Write `{{` for a `{` that is not a hole, and `}}` for a `}`.

## One method for every class

<Snippet src="guides/how-to-use/data-mapper/04-static.nvs" />

In a parameter type, `static` is the class that the call names. So `Order::where` checks paths of
`Order`, and `Customer::where` checks paths of `Customer`. You write the method once, in the parent
class.

## From holes to SQL

<Snippet src="guides/how-to-use/data-mapper/05-holes-to-sql.nvs" />

`Core\Str::parts` gives the text and the holes of the condition in turn. `Core\Reflect::steps`
gives one property for each name of a path. The mapper adds a `JOIN` for each object on the path.
A step also has the property's type, so a library can see if it is an array or can be `null`.

Novis does not read the SQL text between the holes. A typo in a column name there is found when
the query runs. A name in a hole is checked when the program compiles.

## A sort field from a request

<Snippet src="guides/how-to-use/data-mapper/06-a-sort-field-from-a-request.nvs" />

A field name from a request is a `tainted string`. `as ?propertyPath<Order>` checks each name while
the program runs. `customer.passwordHash` names a private property, so the result is `null`. A path
with a wrong name or a brace also gives `null`.

A condition from a request stays `tainted` after `as string<K>`. Only its holes are checked. So it
cannot reach the text of a database query.

## Do and don't

- Do type a parameter `propertyPath<T>` when it takes a field name, so each call is checked.
- Do convert a field name from a request with `as ?propertyPath<T>`, and handle the `null`.
- Do pass values in a query as parameters, with `?`. Put only field names in the holes.
- Don't build a condition from request text. The result is `tainted`, and a query does not accept it.

Read more in [Concepts: field names the compiler checks](/in-depth/concepts/checked-field-names/).
