Novis uses exceptions for errors. A method throws an error, and the code that knows what to do
catches it. Throwing an error is fast, so you can use errors on a busy server too.

## Your own errors

that can happen in a correct program, such as a missing record:

## Two kinds of error

`RuntimeError` is for a problem the program cannot prevent: a missing file, a network failure or
bad input. `LogicError` is for a mistake in the code, such as a method called at the wrong time.
Catch a `RuntimeError` and handle it. A `LogicError` is a bug, so fix the code.

## Failures you cannot catch

A request that goes over a [limit](/guides/how-to-use/limits/) stops at once. This is not an
exception, so no `catch` block runs. The server writes the failure to its log, and the other
requests keep running. `Core\Fatal::onLimit` registers a handler that runs when this happens.

## Do and don't

- Do create one error class for each kind of failure that a caller handles in its own way.
- Do catch errors in one place for each request, and set the status there.
- Do pass the original error as `previous` when you throw a new error from a `catch` block.
- Don't catch an error only to ignore it. Use a `catch` expression with a clear default value.
- Don't show the message of an unexpected error to the client. Write it to the log.
