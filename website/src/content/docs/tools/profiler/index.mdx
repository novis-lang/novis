The profiler measures how long each function call takes. You do not change your program for this.
Add the `--profile` option to `nvs run` or `nvs test`. When the run ends, Novis writes the result to
a profile file.

There are two formats. `--profile=callgrind` writes a Callgrind file. `--profile=speedscope` writes a
speedscope file.

| Format | The file | Open it with |
|---|---|---|
| `callgrind` | `callgrind.out.<pid>` | KCachegrind or Webgrind |
| `speedscope` | `profile.<pid>.speedscope.json` | speedscope, or the *View Profile* command in VS Code |

`<pid>` is the process ID of the run. The file is written in the current folder.

## Name the file

`--profile-out <file>` writes the profile to the file you name. At the end, the run prints
`profile:` and the path of the file. It prints this line on standard error.

## Totals for each function: Callgrind

<Terminal src="tools/profiler/callgrind.term" />

A Callgrind file has two totals for each function. The first total is the time in the function
itself. The second total also includes the time of the functions it called. The file also lists who
called each function. Open it in KCachegrind or Webgrind.

## Profile your tests

`nvs test --profile=speedscope` gives each test its own timeline in the file. A program that your
code starts with `spawn` also gets its own timeline.

A Callgrind file adds the totals of all of them together. The time a program waits for a program it
started is also in that sum. So the total can be larger than the time the run took.

## Every call costs a little more

The profiler adds a small cost to every function call. In a speedscope profile, it is about 170
nanoseconds per call on a current desktop processor. Every call has the same extra cost. So code
that makes many small calls looks slower in a profile than it is without the profiler.

`--profile` cannot be used together with `--dump-ir`, `--dump-asm` or `--count`.

## Profile one part of a program

A program can also profile one part of itself. `Core\Debug::startProfile` starts the profile, and
`Core\Debug::stopProfile` stops it. Only the calls between them are in the profile. Novis writes
them to a speedscope file. Use this when you want to measure one step, such as one step of a nightly
job.

Your `nvs.toml` must allow this. `[debug] mode` must include `"profile"`. `[capabilities.debug]
profile` must list the folder of the profile file:

```toml
[debug]
mode = ["profile"]

# The program may write a profile file in this folder, and nowhere else.
[capabilities.debug]
profile = ["."]
```

A path in `[capabilities]` is relative to the `nvs.toml` file. `--profile` does not need these
settings. Only the person who runs the command can add that option.

Read more in [Reference: Profiling](/reference/cli/profiling/) and
[Reference: Core\Debug::startProfile](/reference/core/debug/startprofile/).
