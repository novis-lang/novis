A test is a method with the `#[Test]` attribute. It must be `public`, return `void` and belong to a
class. A test that checks nothing fails, so every test needs at least one assertion.

<Snippet src="tools/test-runner/prices.nvs" />

`nvs run prices.nvs` runs the program and skips the tests, so the output above is `1200`.
`nvs test prices.nvs` runs only the tests:

<Terminal src="tools/test-runner/prices.term" />

Each test has one line with its time. A skipped test has a `-` and the reason on the next line. The
last line counts the results.

## When a test fails

A failed assertion prints the value it got and the value it expected. In this file, the second test
expects `650`, but `withTax(500)` returns `600`:

<Terminal src="tools/test-runner/fail.term" />

When a test fails, `nvs test` exits with the status `1`. Your build stops there. A skipped test is
not a failure.

## Run every test in a project

`nvs test .` reads every `.nvs` file in the current folder, and in the folders under it. Novis
reads them as one program and runs every test in it. Run it from your project folder. Your entry
file is in that folder, so the tests can use your classes.

You can write the tests under `src/`, next to your classes. You can also keep them in a `tests`
folder with one `bootstrap.nvs` that requires your entry file. `nvs test .` runs both. The
editor and `nvs check tests/CartTest.nvs` use `tests/bootstrap.nvs` too, so a test file can
use your classes without a `require` of its own. Read
[Project layout](/guides/how-to-use/project-layout/) for both ways.

## Choose which tests run

This file has three tests for a cart. The last one has the tag `slow`:
`#[Test(tags: ['slow'])]`.

<Terminal src="tools/test-runner/options.term" />

- `--list` prints every test with its file and line. It runs none of them.
- `--filter itAdds` runs only the tests whose name contains `itAdds`. The name is `Class::method`.
- `--skip-tag slow` does not run the tests with the tag `slow`. `--tag slow` runs only those tests.

The summary counts the tests that did not run as `left out`.

A build server often needs a report file. `--format junit` prints the result as JUnit XML, and
`--format json` prints one JSON document:

```sh
nvs test . --format junit > report.xml
```

Other options stop at the first failure, run only the tests that failed last time, or run the tests
again when you save a file. Read every option in [Reference: nvs test](/reference/cli/nvs-test/).

## Test many generated inputs

A test with `#[Property]` runs 100 times. Each time, Novis generates new values for its parameters.
`gen:` gives the range of each value. When a call fails, Novis looks for the smallest input that
still fails.

This method has a bug. It should never return more than `10`, but it checks against `100`:

<Snippet src="tools/test-runner/property/volume.nvs" />

<Terminal src="tools/test-runner/property.term" />

The 8th call failed with the input `39`. The smallest input that still fails is `11`. The `seed: 7`
in the attribute makes every run use the same inputs, so you can run the failure again.

## Check your tests with mutation testing

`nvs test --mutate` checks whether your tests notice a small change in your code. It runs the tests
once. Then it changes the program in one place, for example `>=` to `>`. This changed program is
called a mutant. It runs the tests again, and a test should now fail.

<Snippet src="tools/test-runner/mutate/shipping.nvs" />

<Terminal src="tools/test-runner/mutate.term" />

The tests use the orders `2000` and `8000`, and they still pass when `>=` on line 10 changes to `>`.
So the mutant survived. A test with an order of exactly `5000` fails on that mutant. The mutation
score is the share of mutants that made a test fail. A survived mutant does not make the run fail, so
the exit status is `0`.

## Count the work of a bench

A method with `#[Bench]` is a bench. `nvs test --bench` runs every bench once, and runs no test. A
plain `nvs test` runs no bench.

<Snippet src="tools/test-runner/bench/slug.nvs" />

<Terminal src="tools/test-runner/bench.term" />

The `count:` line has the number of statements, calls, allocations, allocated bytes and garbage
collections. These numbers are the same on every run and on every computer, so a build server can
compare them with the last run. The time is marked `(advisory)`, because it changes on every run.

## Coverage

`nvs test` can also write a coverage report: which lines of your code the tests ran. Read
[Coverage reports](/tools/test-runner/coverage/).
