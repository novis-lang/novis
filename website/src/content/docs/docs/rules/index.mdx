Most languages are described by a specification and explained by a tutorial. Novis keeps a
third thing, and it is the one the project actually works from: a rulebook. Every rule
states one thing that is true right now — not what is planned, not how it got decided.
Where a rule departs from PHP, it says so and says why. Where the compiler or a test
already enforces it, it names the file.

A rule marked **shipped** is enforced by the toolchain today. One marked **designed** is
decided and written down, and the code has not caught up yet. Both are the language;
neither is a wish. The full reasoning behind any rule — the alternatives weighed, the
costs accepted — stays in the frozen decision records in the repository, which each rule
links to.
